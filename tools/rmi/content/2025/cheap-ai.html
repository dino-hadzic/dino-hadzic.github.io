Ti si malen, pod stresom mišić koji pokušava preživjeti sve brži uspon AI startupa. Konkurenti niču na sve strane i stjecanje tehnološke prednosti čini se gotovo nemogućim. U očajničkoj potrazi za prednošću naišao si na CheapAI™, startup s toliko malo sredstava da si čak i ti možeš priuštiti raditi ondje. Tvoja je prva misija izgraditi najjeftiniji tokenizer na svijetu.

Zaposlio te CheapAI™ i tvoja je prva misija izgraditi tokenizer. Nažalost, budžet je vrlo malen i, osim 26 slova engleske abecede, možeš si priuštiti samo jedan dodatni token duljine najviše $K$.

Zadan je niz znakova $S$ sastavljen od malih slova engleske abecede i broj $K$. Tvoj je cilj odabrati token (niz znakova) duljine najviše $K$ tako da, kad se pojavljivanja odabranog tokena koja se međusobno ne preklapaju zamijene posebnim znakom #, ukupna duljina dobivenog niza bude najmanja moguća.

Zadatak

Za zadani broj $K$ i niz $S$ sastavljen od malih slova engleske abecede odaberi neprazan niz (token) $t$, $1\le|t|\le K$, i zamijeni pojavljivanja niza $t$ u $S$ (odabrana tako da se ne preklapaju) posebnim znakom #, tako da konačni niz bude najmanje moguće duljine.

Odredi tu najmanju duljinu.

Implementacija

Trebaš implementirati sljedeću funkciju:

int solve(int K, std::string S);

Funkcija prima $K$ i $S$ kao parametre i mora odrediti (vratiti) najmanju duljinu niza dobivenog nakon što se pojavljivanja (koja se ne preklapaju) odabranog tokena, duljine najviše $K$, zamijene posebnim znakom #.

Ograničenja

  • $1\le K\le|S|\le200\,000$
  • $S$ se sastoji od malih slova engleske abecede.

Pregled zadatka

Neka je $N=|S|$. Biramo jedan niz $t$ duljine $l\le K$ i u $S$ označimo nekoliko njegovih pojavljivanja koja se međusobno ne preklapaju; svako označeno pojavljivanje zamjenjuje se jednim znakom #. Ako smo zamijenili $c$ pojavljivanja, svako je skratilo niz za $l-1$ znakova, pa je nova duljina

\[N-c\,(l-1).\] Primjer 1: oba pojavljivanja tokena aabaa zamijenjena su znakom #. Primjer 2: tri pojavljivanja tokena aaaaaa koja se ne preklapaju; ostaje jedno slovo a.

Za čvrsti token zato želimo što više pojavljivanja koja se ne preklapaju. Označimo

\[f(l)=\max_{|t|=l}\ (\text{najveći broj nepreklapajućih pojavljivanja niza } t \text{ u } S),\]

pa je odgovor

\[\min_{1\le l\le K}\ \bigl(N-(l-1)\,f(l)\bigr).\]

Cijeli zadatak svodi se na dva pitanja: kako za zadani token (ili za sve tokene iste duljine odjednom) naći najveći broj nepreklapajućih pojavljivanja i kako izbjeći da to radimo za svaku od $K$ duljina. Imajte na umu da dulji token nije nužno bolji: u drugom primjeru ($N=19$, sama slova a, $K=8$) vrijednosti su ove.

$l$12345678
$f(l)$199643322
$N-(l-1)f(l)$1910777475

Najbolja je duljina $6$, a ne najveća dopuštena $8$.

Pohlepni izbor pojavljivanja

Neka se token $t$ duljine $l$ pojavljuje u $S$ na pozicijama $p_1\lt p_2\lt\dots\lt p_m$ (pozicija = indeks prvog znaka). Dva se pojavljivanja ne preklapaju točno kad im se pozicije razlikuju za barem $l$.

Lema 1 (pohlepni izbor). Najveći broj nepreklapajućih pojavljivanja dobiva se ovako: idemo po pozicijama slijeva nadesno i uzmemo pojavljivanje kad god je njegova pozicija barem $l$ veća od pozicije zadnjeg uzetog.

(Dokaz.) Neka pohlepni postupak uzme pozicije $g_1\lt g_2\lt\dots\lt g_a$, a neko optimalno rješenje $o_1\lt o_2\lt\dots\lt o_b$. Indukcijom pokazujemo $g_i\le o_i$ za sve $i\le\min(a,b)$. Za $i=1$ pohlepni uzima najljevije pojavljivanje. Ako je $g_i\le o_i$, onda je $o_{i+1}\ge o_i+l\ge g_i+l$, dakle $o_{i+1}$ je pojavljivanje koje pohlepni smije uzeti nakon $g_i$; on uzima najljevije takvo, pa je $g_{i+1}\le o_{i+1}$. Kad bi bilo $b\gt a$, pojavljivanje $o_{a+1}\ge g_a+l$ pohlepni bi još uzeo — kontradikcija. Dakle $a=b$.

Token aba ($l=3$) pojavljuje se u nizu ababababa na pozicijama $0,2,4,6$. Pohlepni izbor uzima $0$, preskače $2$ (jer $2\lt0+3$), uzima $4$ i preskače $6$: najviše $2$ pojavljivanja, duljina $9-2\cdot2=5$.

Podzadatak 1 — sama slova a 5

Ako je $S$ niz od $N$ slova a, jedini tokeni duljine $l$ su nizovi od $l$ slova a. Takav se token pojavljuje na svakoj poziciji $0,1,\dots,N-l$, pa pohlepni izbor uzima pozicije $0,l,2l,\dots$, tj. $f(l)=\lfloor N/l\rfloor$. Odgovor je

\[\min_{1\le l\le K}\ \Bigl(N-(l-1)\Bigl\lfloor\frac Nl\Bigr\rfloor\Bigr),\]

što računamo jednom petljom u $O(K)$. Kao što pokazuje tablica gore, treba doista isprobati sve duljine, a ne samo $l=K$.

int solve(int K, std::string S) {
    int n = S.size(), best = n;
    for (int l = 1; l <= K; l++)                 // token = l slova 'a'
        best = std::min(best, n - (l - 1) * (n / l));
    return best;
}

Podzadatak 2 — $|S|\le100$ 7

Token koji se u $S$ uopće ne pojavljuje ništa ne skraćuje, pa je dovoljno isprobati podnizove niza $S$: sve parove (duljina $l\le K$, početak $p$). Za svaki takav token prolazimo nizom slijeva nadesno i primjenjujemo lemu 1: ako na poziciji $i$ počinje pojavljivanje, uzmemo ga i skočimo na $i+l$, inače idemo na $i+1$.

Tokena ima $O(N^2)$, a jedan prolaz s usporedbom podnizova stoji $O(N\cdot l)$, pa je složenost $O(N^4)$ u najgorem slučaju (s malom konstantom; za $N=100$ to je trenutačno).

int solve(int K, std::string S) {
    int n = S.size(), best = n;
    for (int l = 1; l <= K; l++)
        for (int p = 0; p + l <= n; p++) {       // token t = S[p .. p+l-1]
            int c = 0;
            for (int i = 0; i + l <= n; ) {
                if (S.compare(i, l, S, p, l) == 0) { c++; i += l; }  // najljevije pojavljivanje: uzmi ga
                else i++;
            }
            best = std::min(best, n - (l - 1) * c);
        }
    return best;
}

Podzadatak 3 — $|S|\le5000$ 12

Umjesto da svaki token obrađujemo posebno, za čvrstu duljinu $l$ obradimo sve tokene te duljine jednim prolazom. Pozicije $0,\dots,N-l$ podijelimo u klase: dvije su pozicije u istoj klasi ako na njima počinju jednaki podnizovi duljine $l$. Svaka klasa odgovara jednom tokenu, a njezini su članovi upravo pozicije njegovih pojavljivanja.

Sada prolazimo pozicijama $i=0,1,\dots,N-l$ i za svaku klasu pamtimo poziciju zadnjeg uzetog pojavljivanja (last) i broj uzetih (cnt). Poziciju $i$ uzimamo ako je $i\ge$ last $+\,l$ za njezinu klasu. Za svaku klasu to je točno postupak iz leme 1 (klase jedna drugoj ne smetaju jer biramo samo jedan token), pa je najveći cnt jednak $f(l)$. Prolaz je $O(N)$.

Ostaje odrediti klase. Kad duljine obrađujemo redom $l=1,2,\dots,K$, to je lako: podniz duljine $l$ na poziciji $i$ određen je parom (klasa podniza duljine $l-1$ na poziciji $i$, slovo $S_{i+l-1}$). Različitih parova ima najviše $26N$, pa im nove oznake dodjeljujemo tablicom veličine $26N$ — bez sažimanja (hashiranja) i bez sortiranja, $O(N)$ po duljini.

Ukupno $O(N\cdot K)$ vremena i $O(26N)$ memorije; za $N=5000$ to je najviše $2{,}5\cdot10^7$ koraka.

int solve(int K, string S) {
    int n = S.size(), best = n;
    // id[i] = oznaka klase podniza S[i .. i+l-1]; za l = 0 svi su jednaki
    vector<int> id(n, 0), last(n), cnt(n), slot(26 * (size_t)n + 26, -1), used;
    for (int l = 1; l <= K; l++) {
        int m = 0; used.clear();
        for (int i = 0; i + l <= n; i++) {       // nova klasa = (stara klasa, novo slovo)
            int key = id[i] * 26 + (S[i + l - 1] - 'a');
            if (slot[key] < 0) { slot[key] = m++; used.push_back(key); }
            id[i] = slot[key];
        }
        for (int key : used) slot[key] = -1;     // očisti tablicu za sljedeću duljinu
        for (int c = 0; c < m; c++) { last[c] = -n; cnt[c] = 0; }
        int f = 0;                               // f(l)
        for (int i = 0; i + l <= n; i++) {       // pohlepni izbor za sve klase odjednom
            int c = id[i];
            if (i >= last[c] + l) { last[c] = i; f = max(f, ++cnt[c]); }
        }
        best = min(best, n - (l - 1) * f);
    }
    return best;
}

Za $N=75\,000$ ovaj pristup više nije dovoljno brz: na službenim testovima četvrtog podzadatka daje točne odgovore, ali mu treba i više od 15 sekundi (ograničenje je 2 s).

Podzadatak 4 — $|S|\le75\,000$ 40

Da bismo bili brži od $O(NK)$, ne smijemo računati $f(l)$ za svaku duljinu. Trebaju nam tri sastojka: (1) način da $f(l)$ izračunamo u $O(N)$ za proizvoljnu duljinu $l$, a ne samo redom; (2) monotonost funkcije $f$; (3) činjenica da $f$ poprima malo različitih vrijednosti.

1. $f(l)$ za proizvoljni $l$ pomoću sufiksnog polja

Izgradimo sufiksno polje i LCP polje

Sufiksno polje niza $S$ je popis početnih pozicija svih sufiksa niza $S$, poredanih leksikografski po sufiksima: $sa_0, sa_1,\dots,sa_{N-1}$. Može se izgraditi udvostručavanjem: sufikse redom sortiramo po prvih $1,2,4,8,\dots$ znakova, pri čemu se poredak po $2k$ znakova dobiva iz rangova po $k$ znakova (par rangova na pozicijama $i$ i $i+k$). S običnim sortiranjem to je $O(N\log^2N)$, s brojećim sortiranjem $O(N\log N)$.

LCP polje za svaka dva susjedna sufiksa u tom poretku pamti duljinu njihova najduljeg zajedničkog prefiksa: $lcp_i=\mathrm{LCP}(sa_i,sa_{i+1})$. Kasaijev algoritam računa ga u $O(N)$: sufikse obrađuje redom po početnoj poziciji $i=0,1,\dots$ i koristi to da se pri prijelazu s $i$ na $i+1$ zajednički prefiks smanji najviše za 1.

Ključno svojstvo: najdulji zajednički prefiks sufiksa na mjestima $a\lt b$ sufiksnog polja jednak je $\min(lcp_a,\dots,lcp_{b-1})$. Zato svi sufiksi koji počinju istim nizom duljine $l$ čine uzastopan blok u sufiksnom polju, unutar kojeg su svi $lcp$-ovi barem $l$.

niza $S$. Dvije pozicije počinju istim podnizom duljine $l$ točno onda kad njihovi sufiksi imaju zajednički prefiks duljine barem $l$. U sufiksnom polju takvi sufiksi čine uzastopan blok, a granice blokova su upravo mjesta gdje je $lcp_i\lt l$. Dakle klase iz prethodnog podzadatka dobivamo jednim prolazom po LCP polju: nova grupa počinje svaki put kad je $lcp\lt l$.

Sufiksno polje niza abaababa. Za $l=2$ granice grupa su ondje gdje je LCP $\lt2$: dobivamo grupe aa $\{2\}$, ab $\{5,0,3\}$ i ba $\{6,1,4\}$ (sufiks a je kraći od $l$ i ne računa se). Pohlepni prolaz po pozicijama $0,1,\dots$ uzima za ab pozicije $0,3,5$, pa je $f(2)=3$. Za $l=3$ ostaje samo grupa aba $\{5,0,3\}$: uzimamo $0$ i $3$, a $5\lt3+3$ preskačemo, pa je $f(3)=2$.

Nakon toga radimo isti pohlepni prolaz po pozicijama kao u podzadatku 3. Jedno računanje $f(l)$ stoji $O(N)$, neovisno o $l$.

// sa[0..n-1] = sufiksno polje, lcp[i] = LCP sufiksa sa[i] i sa[i+1]
// f(l): najveći broj nepreklapajućih pojavljivanja nekog niza duljine l; O(n)
static int f(int l) {
    int g = 0; grp[sa[0]] = 0;
    for (int i = 1; i < n; i++) {                // nova grupa počinje gdje je LCP < l
        if (lcp[i - 1] < l) g++;
        grp[sa[i]] = g;
    }
    for (int i = 0; i <= g; i++) { lastp[i] = -n; cntg[i] = 0; }
    int best = 0;
    for (int i = 0; i + l <= n; i++) {           // pozicije slijeva nadesno
        int c = grp[i];
        if (i >= lastp[c] + l) { lastp[c] = i; best = max(best, ++cntg[c]); }
    }
    return best;
}

2. Monotonost

Lema 2. $f(1)\ge f(2)\ge\dots\ge f(N)\ge1$.

(Dokaz.) Neka token $t$ duljine $l+1$ ima $f(l+1)$ nepreklapajućih pojavljivanja. Njegov prefiks duljine $l$ pojavljuje se na istim pozicijama, a kraća se pojavljivanja na tim pozicijama pogotovo ne preklapaju. Zato je $f(l)\ge f(l+1)$. Niz $S$ sam je token duljine $N$ s jednim pojavljivanjem, pa je $f(N)=1$.

Posljedica: skup duljina na kojima $f$ ima istu vrijednost $v$ je interval (blok) $[a,b]$. Unutar bloka izraz $N-(l-1)\,v$ najmanji je za najveći $l$, dakle iz svakog bloka zanima nas samo desni kraj $b$ (odnosno $\min(b,K)$).

3. Malo različitih vrijednosti

Lema 3. $f(l)\le\lfloor N/l\rfloor$. Posebno, $f$ poprima najviše $2\sqrt N$ različitih vrijednosti.

(Dokaz.) $c$ nepreklapajućih pojavljivanja duljine $l$ zauzima $c\cdot l\le N$ znakova. Za $l\le\sqrt N$ ima najviše $\sqrt N$ duljina, pa i najviše toliko vrijednosti; za $l\gt\sqrt N$ vrijedi $f(l)\lt\sqrt N$, pa je i tu najviše $\sqrt N$ različitih vrijednosti.

Za niz od $N=40$ slova a vrijedi $f(l)=\lfloor40/l\rfloor$: funkcija je nerastuća i leži ispod krivulje $N/l$, pa za velike $l$ ima duge vodoravne „stepenice”. Svaku stepenicu dovoljno je obraditi jednom.

Algoritam: korijenska podjela i binarno pretraživanje

Odaberemo prag $B$.

  • Kratki tokeni, $l\le B$: izračunamo $f(l)$ za svaku duljinu posebno — $B$ računanja.
  • Dugi tokeni, $l\gt B$: ovdje je $f(l)\le N/B$, pa ima najviše $N/B$ blokova. Krenemo od $l=B+1$, izračunamo $v=f(l)$ i binarnim pretraživanjem (dopušteno zbog leme 2) nađemo najveći $r\le K$ s $f(r)\ge v$, tj. desni kraj bloka. Kandidat za odgovor je $N-(r-1)v$, a zatim nastavljamo od $l=r+1$. Svaki blok stoji $O(\log N)$ računanja.

Ukupan broj računanja funkcije $f$ je $B+O\bigl(\tfrac NB\log N\bigr)$, što je za $B=\sqrt{N\log N}$ jednako $O(\sqrt{N\log N})$. Složenost je

\[O\bigl(N\sqrt{N\log N}\bigr)\]

uz izgradnju sufiksnog polja ($O(N\log^2N)$ sa sortiranjem). Za $N=75\,000$ to je oko $2300$ računanja funkcije $f$.

int solve(int K, string S) {
    build(S);                                    // sufiksno polje + LCP
    int B = min<long long>(K, (long long)sqrt((double)n * max(1.0, log2((double)n))));
    int best = n;
    for (int l = 1; l <= B; l++)                 // kratki tokeni: svaka duljina posebno
        best = min(best, n - (l - 1) * f(l));
    for (int l = B + 1; l <= K; ) {              // dugi tokeni: blok po blok
        int v = f(l), lo = l, hi = K;            // tražimo najveći r s f(r) = v
        while (lo < hi) {
            int mid = (lo + hi + 1) / 2;
            if (f(mid) >= v) lo = mid; else hi = mid - 1;
        }
        best = min(best, n - (lo - 1) * v);      // u bloku je najbolji desni kraj
        l = lo + 1;
    }
    return best;
}

Na službenim testovima ovo rješenje prolazi četvrti podzadatak s velikom rezervom (najviše oko 0,35 s na našem računalu). Na testovima s $N=200\,000$ također daje točne odgovore, ali mu je trebalo do 1,8 s, što je tik uz ograničenje od 2 s — za zadnji podzadatak želimo nešto bolje.

Podzadatak 5 — $|S|\le200\,000$ 36

Službeno rješenje (cheapai_assertall.cpp) koristi iste sastojke — sufiksno polje, $f(l)$ u $O(N)$, monotonost — ali blokove ne traži binarnim pretraživanjem za svaki blok posebno, nego jednim „podijeli pa vladaj” po duljini uz pamćenje već izračunatih vrijednosti.

Postavimo stražare $f(0)=N+1$ i $f(K+1)=0$. Postupak divide(l, r) pretpostavlja da su $f(l)$ i $f(r)$ poznati:

  • ako je $r-l\le1$, nema se što računati;
  • ako je $f(l)=f(r)$, zbog monotonosti je $f$ konstantna na cijelom $[l,r]$ i sve duljine između preskačemo (od njih je ionako najbolja $r$, koja je već izračunata);
  • inače izračunamo $f(m)$ za $m=\lfloor(l+r)/2\rfloor$ i rekurzivno obradimo $[l,m]$ i $[m,r]$.

Na kraju uzmemo minimum izraza $N-(l-1)f(l)$ po svim izračunatim duljinama.

Tvrdnja 4 (točnost). Za svaki blok jednakih vrijednosti funkcije $f$ unutar $[1,K]$ njegov je desni kraj izračunat.

(Dokaz.) Neka je $b\le K$ desni kraj bloka, dakle $f(b)\gt f(b+1)$ (za $b=K$ to vrijedi zbog stražara $f(K+1)=0\lt1\le f(K)$). Promatrajmo najdublji poziv divide(l, r) za koji je $l\le b\lt r$; takav postoji jer početni poziv divide(0, K+1) to zadovoljava. U njemu je $f(l)\ge f(b)\gt f(b+1)\ge f(r)$, pa se ne zaustavlja zbog jednakih rubova. Ako je $r-l\le1$, onda je $l=b$ i $f(b)$ je već poznat. Inače se poziv dijeli u $m$ i jedan od potpoziva opet sadrži $b$ u $[l',r')$ — kontradikcija s izborom najdubljeg poziva. Budući da se preskaču samo unutrašnjosti intervala s jednakim rubovima, a ondje desni kraj bloka ne može biti, minimum po izračunatim duljinama jednak je traženom minimumu.

Rubne vrijednosti ne treba računati: $f(0)=N+1=20$ (stražar veći od svih pravih vrijednosti) i $f(K+1)=f(20)=0$. Poziv divide(0, 20). Dubina 1. Računamo sredine intervala kojima se rubovi razlikuju — $[0,20]$: $f(10)=1$. Dubina 2. Računamo sredine intervala kojima se rubovi razlikuju — $[0,10]$: $f(5)=3$; $[10,20]$: $f(15)=1$. Sada je $f(10)=f(15)=1$, pa je zbog monotonosti $f\equiv 1$ na cijelom $[10,15]$: duljine 11–14 ne računamo. Dubina 3. Računamo sredine intervala kojima se rubovi razlikuju — $[0,5]$: $f(2)=9$; $[5,10]$: $f(7)=2$; $[15,20]$: $f(17)=1$. Sada je $f(15)=f(17)=1$, pa je zbog monotonosti $f\equiv 1$ na cijelom $[15,17]$: duljinu 16 ne računamo. Dubina 4. Računamo sredine intervala kojima se rubovi razlikuju — $[0,2]$: $f(1)=19$; $[2,5]$: $f(3)=6$; $[5,7]$: $f(6)=3$; $[7,10]$: $f(8)=2$; $[17,20]$: $f(18)=1$. Dubina 5. Računamo sredine intervala kojima se rubovi razlikuju — $[3,5]$: $f(4)=4$; $[8,10]$: $f(9)=2$; $[18,20]$: $f(19)=1$. Kraj: izračunato je 14 od 19 vrijednosti (preskočene su 11–14 i 16). Odgovor je $\min_l\,N-(l-1)f(l)$ po izračunatim $l$; ovdje $l=19$ daje $19-18\cdot1=1$. Kod velikih $N$ ušteda je golema: za $N=K=200\,000$ i niz od samih slova a računa se samo $2178$ od $200\,000$ vrijednosti.

Koliko se puta računa $f$?

Tvrdnja 5. Postupak izračuna $f$ za $O(\sqrt N+\log K)$ duljina, pa je ukupna složenost $O(N\sqrt N)$ (uz izgradnju sufiksnog polja).

(Dokaz.) Nazovimo padom svaku duljinu $j$ s $f(j)\gt f(j+1)$. Poziv divide(l, r) računa novu vrijednost samo ako je $f(l)\ne f(r)$ i $r-l\ge2$; takav poziv zovimo aktivnim. Aktivan poziv sadrži barem jedan pad $j\in[l,r)$. Pozivi na istoj dubini rekurzije $d$ imaju disjunktne poluintervale $[l,r)$ i duljinu barem $L_d=\lfloor(K+1)/2^d\rfloor$.

Odaberimo neki $x\gt0$. Aktivnih poziva dubine $d$ s lijevim rubom $l\lt x$ ima najviše $x/L_d+1$ (disjunktni su i svaki je dug barem $L_d$). Svaki aktivni poziv s $l\ge x$ sadrži svoj pad $j\ge x$, a takvih padova ima najviše $f(x)\le N/x$, jer nakon $x$ funkcija može pasti najviše $f(x)$ puta. Za $x=\sqrt{N L_d}$ dobivamo da je aktivnih poziva dubine $d$ najviše

\[2\sqrt{N/L_d}+1.\]

Aktivan poziv ima duljinu barem $2$, pa na dubinama na kojima ih ima vrijedi $(K+1)/2^d\gt1$ i zato $L_d\ge(K+1)/2^{d+1}$. Slijedi $\sqrt{N/L_d}\le\sqrt{2N\cdot2^d/(K+1)}$: te ocjene rastu geometrijski s faktorom $\sqrt2$, a najveća je (za $2^d\lt K+1$) manja od $\sqrt{2N}$, pa je njihov zbroj $O(\sqrt N)$. Dubina ima $O(\log K)$, što daje još $O(\log K)$ od pribrojnika $+1$.

Mjerenje potvrđuje ocjenu: na svim službenim testovima naša implementacija ovog postupka izračuna najviše $2151$ vrijednost funkcije $f$ (test s $N=200\,000$ slova a), a za $N=K=200\,000$ slova a $2178\approx4{,}9\sqrt N$. Za usporedbu, rješenje iz podzadatka 4 na istom ulazu treba $3845$ računanja, a čisto „binarno pretraživanje po blokovima” bez praga $B$ čak $16\,345$.

static vector<int> F;                            // F[l] = f(l) ili -1 ako nije izračunato
static int get(int l) { if (F[l] < 0) F[l] = f(l); return F[l]; }

static void divide(int l, int r) {
    if (r - l <= 1 || get(l) == get(r)) return;  // f je konstantna na [l, r]
    int mid = (l + r) / 2;
    get(mid);
    divide(l, mid);
    divide(mid, r);
}

int solve(int K, string S) {
    build(S);                                    // sufiksno polje + LCP
    F.assign(K + 2, -1);
    F[0] = n + 1;                                // stražari: f(0) > f(1), f(K+1) = 0
    F[K + 1] = 0;
    divide(0, K + 1);
    int best = n;
    for (int l = 1; l <= K; l++)                 // desni kraj svakog bloka sigurno je izračunat
        if (F[l] >= 0) best = min(best, n - (l - 1) * F[l]);
    return best;
}

Službeno rješenje gradi sufiksno polje udvostručavanjem s brojećim sortiranjem ($O(N\log N)$) i LCP polje Kasaijevim algoritmom; funkcija koja računa $f(l)$ ista je kao gore. Na službenim testovima treba mu najviše oko 1,2 s (našoj inačici oko 0,7 s).

Sažetak

  • Zamjena $c$ nepreklapajućih pojavljivanja tokena duljine $l$ daje duljinu $N-c(l-1)$; za čvrsti token najveći $c$ daje pohlepni izbor slijeva nadesno.
  • $f(l)$ — najbolji $c$ po svim tokenima duljine $l$ — računa se u $O(N)$: pozicije se grupiraju po podnizu duljine $l$ (sufiksno polje + LCP), a pohlepni izbor radi se za sve grupe jednim prolazom.
  • $f$ je nerastuća i $f(l)\le N/l$, pa ima $O(\sqrt N)$ blokova jednakih vrijednosti; iz svakog bloka važan je samo desni kraj.
  • „Podijeli pa vladaj” po duljini, koji preskače intervale s jednakim rubovima, računa $f$ samo $O(\sqrt N+\log K)$ puta: ukupno $O(N\sqrt N)$.
