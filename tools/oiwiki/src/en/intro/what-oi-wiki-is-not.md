---
title: What OI Wiki is not
---

???+ warning "Note"
    As part of the project policy this page is very important; every contributor should make sure their contribution meets the following conditions.

## OI Wiki is not a place to publish original research

As a wiki, **OI Wiki** is not a place to publish [original research](https://en.wikipedia.org/wiki/Wikipedia:No_original_research) (such as **new theories and solutions**, **original opinions**, **self-coined definitions or terms**, etc.). For example:

-   if you discovered an unconventional approach to some problem and cannot show that the approach has already been applied to other problems, you **should not** create a separate page on **OI Wiki**;
-   if you proposed a new algorithm or data structure and cannot show that it has already been used to solve some class of problems in programming contests, you **should not** submit it to **OI Wiki**.

## OI Wiki is not a news collection

As a knowledge-integration site focused on programming-contest content, mainly in a Chinese-language context, **OI Wiki** emphasises information that is **well established and widely recognised**.

In other words, unless it is information released by an authoritative body (such as contest format updates published by the China Computer Federation), the content you contribute should be information that has been tested and settled, has gained wide recognition, and will not become outdated for some time. For example:

-   if you find that Dr. X has published a new algorithm somewhere and want to add it to **OI Wiki**, you should first observe whether it gains wide recognition (e.g. as a generally good solution in official contests) and whether it is sufficiently distinct from the algorithms already on **OI Wiki**;
-   if you find that some software or person mentioned on **OI Wiki** has become controversial, please follow the relevant announcements in the comments section etc. and do not open repeated issues about it. The purpose of **OI Wiki** is to record **information that lasts**, not **time-sensitive temporary information**.

## OI Wiki is not an archive

The main **OI Wiki** site does not collect **literature**, **slides**, **lecture notes**, **manuals** and similar materials; if you want to submit programming-contest materials, please go to [OI-wiki/libs](https://github.com/OI-wiki/libs).

## OI Wiki is not a promotional tool

**OI Wiki** is a knowledge-integration site; it is **not** a soapbox, a forum or a promotional tool. So when adding or modifying entries, please do not:

-   express opinions or comments: the content of **OI Wiki** must be **objective and neutral**. If you want to express opinions and comments related to **OI Wiki**, use the comments section or the issue page. If they are unrelated to **OI Wiki**, use a personal blog or forum;
-   engage in any form of promotion: for the sake of collecting knowledge, **OI Wiki** can accept introductions to "websites or software that are **already well known** in the programming-contest community". Beyond that, **OI Wiki** does not accept any promotional content not provided by sponsors.

## OI Wiki is not an authoritative body

As a community project relying mainly on user contributions, **OI Wiki** is not authoritative and neither should nor can act as an authoritative body. **OI Wiki** can serve as a reference for learning programming-contest knowledge, but it is not a standard textbook. As a community-maintained reference site, you should not treat **OI Wiki** as the final authoritative standard (e.g. as a contest "syllabus"), nor blindly trust everything on **OI Wiki**. **OI Wiki** is not responsible for any consequences arising from the use of its content.

## OI Wiki is not a personal blog

**OI Wiki** is based on the word "wiki" and is essentially a community that **edits content collaboratively**. This means the content you provide should **minimise personal colouring**, serve the whole wiki and pay attention to the structure of the entries you contribute to. Never treat entries in the wiki with the mindset of writing a personal blog post. For example:

-   you **should not** use **OI Wiki** as a navigation site for your personal blog;
-   you **should not** add entry history, personal rants, jokes or other irrelevant content to the description of an entry.

The opposites of these examples are common habits when writing a personal blog, and they are not welcome on **OI Wiki**, which advocates objectivity and neutrality.

## OI Wiki is not a translation standards committee

The target audience of **OI Wiki** is not historians or linguists, so when translating foreign terms **OI Wiki** prefers translations that are **already widely accepted** in the Chinese-language context, even if they may be flawed.

Once a translation is widely known and accepted, blindly changing it for the sake of "correctness" only causes more confusion and chaos, and the resulting word games hurt communication.

## OI Wiki is not an encyclopaedia

The content collected on **OI Wiki** should be limited to those parts of computer science, mathematics and related fields that "have already been applied in programming contests". Other fields or knowledge unrelated to programming contests are not suitable for **OI Wiki**.

For example, the following fields or knowledge are **not suitable** for **OI Wiki**:

-   history, art and other unrelated fields;
-   knowledge such as the [TBN matrix](https://learnopengl.com/Advanced-Lighting/Normal-Mapping) which belongs to a related field but currently cannot be applied in programming contests;
-   domain algorithms such as [PID control](https://en.wikipedia.org/wiki/PID_controller) or the [finite element method](https://en.wikipedia.org/wiki/Finite_element_method) which currently cannot be applied in programming contests;
-   general algorithms such as [deep learning](https://en.wikipedia.org/wiki/Deep_learning) or [reinforcement learning](https://en.wikipedia.org/wiki/Reinforcement_learning) which currently cannot be applied in programming contests.

## OI Wiki is not programming-language documentation or a language tutorial

The algorithms collected on **OI Wiki** should be more concerned with the algorithm itself than with the code implementation. A concrete implementation serves only as a more detailed understanding or an implementation hint, not as a convenience for learners of a specific language. If you want to learn a language, you should read its official documentation and similar materials.

For the sake of collecting knowledge, **OI Wiki** may include simple usage guides for the languages commonly used in programming contests. Beyond that, **OI Wiki** does not collect content such as "the implementation details of some function in some standard library of some language", which has little to do with programming contests and algorithms.
