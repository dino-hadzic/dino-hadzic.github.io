Poglavlje 5
Potpuno pretraživanje

Potpuno pretraživanje (complete search) općenita je metoda koja se može koristiti za rješavanje gotovo svakog algoritamskog problema. Ideja je generirati sva moguća rješenja problema metodom grube sile (brute force), a zatim odabrati najbolje rješenje ili prebrojati broj rješenja, ovisno o problemu.

Potpuno pretraživanje dobra je tehnika ako ima dovoljno vremena za prolazak kroz sva rješenja, jer je pretraživanje obično lako implementirati i uvijek daje točan odgovor. Ako je potpuno pretraživanje presporo, mogu biti potrebne druge tehnike, kao što su pohlepni algoritmi ili dinamičko programiranje.

Generiranje podskupova

Najprije razmatramo problem generiranja svih podskupova skupa od $n$ elemenata. Na primjer, podskupovi od $\{0,1,2\}$ su $\emptyset$, $\{0\}$, $\{1\}$, $\{2\}$, $\{0,1\}$, $\{0,2\}$, $\{1,2\}$ i $\{0,1,2\}$. Postoje dvije uobičajene metode za generiranje podskupova: možemo ili izvesti rekurzivno pretraživanje ili iskoristiti bitovnu reprezentaciju cijelih brojeva.

Metoda 1

Elegantan način za prolazak kroz sve podskupove skupa je korištenje rekurzije. Sljedeća funkcija search generira podskupove skupa $\{0,1,\dots,n-1\}$. Funkcija održava vektor subset koji će sadržavati elemente svakog podskupa. Pretraživanje započinje kada se funkcija pozove s parametrom 0.

void search(int k) {
    if (k == n) {
        // obrada podskupa
    } else {
        search(k + 1);
        subset.push_back(k);
        search(k + 1);
        subset.pop_back();
    }
}

Kada se funkcija search pozove s parametrom $k$, ona odlučuje hoće li uključiti element $k$ u podskup ili ne, te se u oba slučaja zatim poziva s parametrom $k+1$. Međutim, ako je $k=n$, funkcija primjećuje da su svi elementi obrađeni i da je podskup generiran.

Metoda 2

Drugi način generiranja podskupova temelji se na bitovnoj reprezentaciji cijelih brojeva. Svaki podskup skupa od $n$ elemenata može se prikazati kao niz od $n$ bitova, što odgovara cijelom broju između $0$ i $2^{n}-1$. Jedinice u bitovnom nizu označavaju koji su elementi uključeni u podskup. Uobičajena je konvencija da zadnji bit odgovara elementu 0, pretzadnji bit elementu 1 i tako dalje. Na primjer, bitovni prikaz broja 25 je 11001, što odgovara podskupu $\{0,3,4\}$.

Sljedeći kod prolazi kroz podskupove skupa od $n$ elemenata:

for (int b = 0; b < (1 << n); b++) {
    // obrada podskupa
}

Sljedeći kod pokazuje kako možemo pronaći elemente podskupa koji odgovaraju bitovnom nizu:

for (int b = 0; b < (1 << n); b++) {
    vector<int> subset;
    for (int i = 0; i < n; i++) {
        if (b & (1 << i)) subset.push_back(i);
    }
    // obrada podskupa
}

Generiranje permutacija

Zatim razmatramo problem generiranja svih permutacija skupa od $n$ elemenata. Na primjer, permutacije od $\{0,1,2\}$ su $(0,1,2)$, $(0,2,1)$, $(1,0,2)$, $(1,2,0)$, $(2,0,1)$ i $(2,1,0)$. Baš kao i za podskupove, postoje dva pristupa: možemo koristiti rekurziju ili funkcije standardne biblioteke.

Metoda 1

Elegantan način generiranja permutacija je korištenje rekurzije. Sljedeća funkcija search održava vektor permutation i polje chosen kako bi pratila koji su elementi već u permutaciji. Pretraživanje započinje kada se funkcija pozove.

void search() {
    if (permutation.size() == n) {
        // obrada permutacije
    } else {
        for (int i = 0; i < n; i++) {
            if (chosen[i]) continue;
            chosen[i] = true;
            permutation.push_back(i);
            search();
            chosen[i] = false;
            permutation.pop_back();
        }
    }
}

Metoda 2

Druga metoda za generiranje permutacija je započeti s permutacijom $\{0,1,\dots,n-1\}$ i opetovano koristiti funkciju koja konstruira sljedeću permutaciju u rastućem redoslijedu. Standardna C++ biblioteka sadrži funkciju next_permutation koja se može koristiti u tu svrhu:

vector<int> permutation;
for (int i = 0; i < n; i++) {
    permutation.push_back(i);
}
do {
    // obrada permutacije
} while (next_permutation(permutation.begin(), permutation.end()));

Vraćanje natrag (Backtracking)

Algoritam s vraćanjem natrag (backtracking) započinje s praznim rješenjem i proširuje ga korak po korak. Pretraživanje rekurzivno prolazi kroz sve različite načine na koje se rješenje može konstruirati.

Kao primjer, razmotrimo problem postavljanja $n$ kraljica na šahovsku ploču dimenzija $n \times n$ tako da nikoje dvije kraljice ne napadaju jedna drugu. Kod pretpostavlja da su redci i stupci ploče numerirani od $0$ do $n-1$. Kada se funkcija search pozove s parametrom $y$, ona postavlja kraljicu u redak $y$, a zatim poziva samu sebe s parametrom $y+1$. Zatim, ako je $y=n$, rješenje je pronađeno i varijabla count se povećava za jedan.

Polje column prati stupce koji sadrže kraljicu, a polja diag1 i diag2 prate dijagonale. Nije dopušteno dodati još jednu kraljicu u stupac ili dijagonalu koji već sadrže kraljicu.

void search(int y) {
    if (y == n) {
        count++;
        return;
    }
    for (int x = 0; x < n; x++) {
        if (column[x] || diag1[x + y] || diag2[x - y + n - 1]) continue;
        column[x] = diag1[x + y] = diag2[x - y + n - 1] = 1;
        search(y + 1);
        column[x] = diag1[x + y] = diag2[x - y + n - 1] = 0;
    }
}

Pretraživanje započinje pozivom search(0).

Obrezivanje pretraživanja

Često možemo optimizirati backtracking obrezivanjem stabla pretraživanja. Ideja je dodati provjere koje rano prekidaju pretraživanje ako je očito da se trenutno djelomično rješenje ne može proširiti do važećeg konačnog rješenja.

Usredotočit ćemo se na slučaj rešetke dimenzija $7 \times 7$, jer je njezina razina težine prikladna za naše potrebe. Započinjemo s jednostavnim algoritmom s vraćanjem natrag, a zatim ga optimiziramo korak po korak koristeći zapažanja o tome kako se pretraživanje može obrezati. Nakon svake optimizacije mjerimo vrijeme izvršavanja algoritma i broj rekurzivnih poziva, kako bismo jasno vidjeli učinak svake optimizacije na učinkovitost pretraživanja.

Osnovni algoritam: Prva verzija algoritma ne sadrži nikakve optimizacije. Jednostavno koristimo backtracking za generiranje svih mogućih putova od gornjeg lijevog kuta do donjeg desnog kuta i brojimo broj takvih putova.
Vrijeme izvršavanja: 483 sekunde
Broj rekurzivnih poziva: 76 milijardi

Optimizacija 1: Ako put stigne do donjeg desnog kuta prije nego što posjeti sve kvadrate, jasno je da više ne možemo posjetiti sve kvadrate, pa možemo prekinuti pretraživanje.

Optimizacija 2: Ako put udari u zid i ne može nastaviti naprijed, ali može skrenuti lijevo ili desno, rešetka se dijeli na dva dijela koji oba sadrže neposjećene kvadrate. Jasno je da više ne možemo posjetiti sve kvadrate, pa možemo prekinuti pretraživanje. Nakon ove optimizacije, pretraživanje je vrlo učinkovito:
Vrijeme izvršavanja: 0.6 sekundi
Broj rekurzivnih poziva: 69 milijuna

Sada je dobar trenutak da prestanemo s optimizacijom algoritma i vidimo što smo postigli. Vrijeme izvršavanja izvornog algoritma bilo je 483 sekunde, a sada je nakon optimizacija vrijeme izvršavanja samo 0.6 sekundi.

Sastanak u sredini (Meet in the middle)

Sastanak u sredini (meet in the middle) je tehnika u kojoj se prostor pretraživanja dijeli na dva dijela približno jednake veličine. Izvodi se zasebno pretraživanje za oba dijela, a na kraju se rezultati kombiniraju.

Korištenjem tehnike sastanka u sredini možemo postići učinkovitiji algoritam vremenske složenosti $O(2^{n/2})$. Primijetite da su $O(2^n)$ i $O(2^{n/2})$ različite složenosti jer je $2^{n/2}$ jednako $\sqrt{2^n}$.

Ideja je podijeliti popis na dva popisa $A$ i $B$ tako da oba sadrže otprilike polovicu brojeva. Prvo pretraživanje generira sve podskupove od $A$ i sprema njihove zbrojeve u popis $S_A$. Sukladno tome, drugo pretraživanje stvara popis $S_B$ iz $B$. Nakon toga, dovoljno je provjeriti je li moguće odabrati jedan element iz $S_A$ i drugi element iz $S_B$ tako da njihov zbroj bude $x$. To je moguće točno onda kada postoji način da se formira zbroj $x$ pomoću brojeva iz izvornog popisa.

Na primjer, pretpostavimo da je popis $[2,4,5,9]$ i $x=15$. Najprije podijelimo popis na $A=[2,4]$ i $B=[5,9]$. Nakon toga stvaramo popise $S_A=[0,2,4,6]$ i $S_B=[0,5,9,14]$. U ovom slučaju moguće je formirati zbroj $x=15$ jer $S_A$ sadrži zbroj 6, $S_B$ sadrži zbroj 9, a $6+9=15$. To odgovara rješenju $[2,4,9]$.
