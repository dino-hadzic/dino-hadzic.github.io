Pregled zadatka slajdovi 1–4

Podzadatak 0 — pregled zadatka

  • Zadano je stablo s $N$ vrhova.
  • Par vrhova $(s,g)$ zovemo dobrim parom ako zadovoljava sljedeći uvjet:
    • ako put u stablu od $s$ do $g$ zapišemo kao $(s=i_0,\ i_1,\ i_2,\ \dots,\ i_d=g)$, postoji $j$, $0\le j\le d$, takav da je $T_{i_j}\le j$, i pritom je $d\le D$.
  • Za svaki $s=1,2,\dots,N$ odredi broj vrhova $g$ takvih da je $(s,g)$ dobar par.

Ovo je samo preformulacija teksta zadatka: put između dva vrha stabla je jedinstven, JOI u vrh $i_j$ stiže točno u trenutku $j$ (svaki prelazak traje $1$ i troši $1$ izdržljivosti, a vraćanje u već posjećeni grad nije dopušteno), pa „rally iz $s$ može uspješno završiti u $g$” znači točno: duljina puta $d=\mathrm{dist}(s,g)$ nije veća od $D$ i na putu postoji grad $i_j$ u kojem je štand već postavljen u trenutku dolaska, $T_{i_j}\le j$. Posebno, $(s,s)$ je dobar par ako i samo ako je $T_s\le 0$, tj. $T_s=0$.

Ograničenja

  • $2\le N\le 400\,000$
  • $0\le D\le N-1$
  • $0\le T_i\le N$

Podzadatak 1 3 boda slajdovi 5–7

$D\le1$

  • Udaljenost vrhova $s$ i $g$ označimo s $\mathrm{dist}(s,g)$.
  • Kad je $D\le1$, parova $(s,g)$ za koje je $\mathrm{dist}(s,g)\le D$ ima $O(N)$:
    • parova s $\mathrm{dist}(s,g)=0$ ima koliko i vrhova;
    • parova s $\mathrm{dist}(s,g)=1$ ima dvostruko više nego bridova.
  • Za svaki od tih parova dovoljno je izravno (naivno) provjeriti je li dobar.
  • Složenost je $O(N)$.

Kod sa slajda 7:

int N, D; cin >> N >> D;
vector<int> T(N), ans(N);
for(int i = 0; i < N; i++) {
    cin >> T[i];
    if(T[i] == 0) ans[i] ++;
}
for(int i = 0; i < N-1; i++) {
    int u, v; cin >> u >> v;
    u--; v--;
    if(D == 1) {
        if(T[u] <= 0 || T[v] <= 1) ans[u] ++;
        if(T[v] <= 0 || T[u] <= 1) ans[v] ++;
    }
}
for(int i = 0; i < N; i++) cout << ans[i] << '\n';

Što kod provjerava: par $(i,i)$ je dobar ako je $T_i=0$ (pečat u trenutku $0$). Za brid $\{u,v\}$ i $D=1$ par $(u,v)$ je dobar ako je pečat moguć u $u$ u trenutku $0$ ($T_u\le0$) ili u $v$ u trenutku $1$ ($T_v\le1$); simetrično za $(v,u)$. Kad je $D=0$, moguć je samo $g=s$, pa petlja po bridovima ništa ne dodaje.

Podzadatak 2 7 bodova slajdovi 8–10

Put (path graph), $N\le3000$

  • Promatramo samo slučaj $s\lt g$.
    • Slučaj $s=g$ je jednostavan, a slučaj $s\gt g$ se zbog simetrije svodi na slučaj $s\lt g$.
  • Hodamo li od $s$ udesno, neka je $m$ prvi grad u kojem se može udariti pečat. Tada su vrhovi $g$ za koje je $(s,g)$ dobar par upravo $g=m,\ m+1,\ \dots,\ s+D$.
  • Za svaki $s$ smijemo potrošiti $O(N)$ vremena.
  • Složenost je $O(N^2)$.

Zašto je skup dobrih $g$ interval: ako je pečat udaren u gradu $m$ (u trenutku $m-s$, jer je $T_m\le m-s$), onda je svaki nastavak puta do bilo kojeg $g\ge m$ s $g-s\le D$ uspješan, a za $g\lt m$ na putu $s,\dots,g$ nema grada u kojem bi se pečat mogao udariti (jer je $m$ prvi takav). Ako takvog $m$ nema među gradovima $s,\dots,\min(s+D,N)$, dobrih $g\gt s$ nema.

Kod sa slajda 10 (gradovi su indeksirani od $0$):

for(int s = 0; s < N; s++) {
    int ans = 0;
    for(int i = 0; i <= D && s + i < N; i++) if(T[s + i] <= i) {
        ans += D - i + 1;
        break;
    }
    for(int i = 0; i <= D && s - i >= 0; i++) if(T[s - i] <= i) {
        ans += D - i + 1;
        break;
    }
    if(T[s] == 0) ans--;
    cout << ans << '\n';
}

Napomena uz kod sa slajda 10

Prva petlja traži $m=s+i$ (prvi grad udesno u kojem je $T_{s+i}\le i$) i broji $g=s+i,\dots,s+D$; druga petlja isto radi ulijevo. Par $(s,s)$ broji se u obje petlje (slučaj $i=0$) kad je $T_s=0$, zato se na kraju jednom oduzima: if(T[s] == 0) ans--;.

Kod sa slajda doslovno pribraja $D-i+1$ i ne vodi računa o rubu puta: ako je $s+D\gt N-1$ (odnosno $s-D\lt0$), prebrojava gradove kojih nema. Provjerili smo to stress-testom protiv izravnog DFS-rješenja sa slajda 13 — na slučajnim putovima s $N\le8$ odgovori se razlikuju u otprilike polovici testova (npr. $N=3$, $D=2$, $T=(0,2,0)$: ispravno je $3,2,3$, a kod daje $5,4,5$). Ispravan zbroj je $\min(s+D,\,N-1)-(s+i)+1$ u prvoj petlji i $(s-i)-\max(s-D,\,0)+1$ u drugoj; s tom izmjenom kod prolazi sve testove. Ideja sa slajda je točna, samo je kod skraćen.

Podzadatak 3 10 bodova slajdovi 11–13

$N\le3000$

  • Kao i u podzadatku 2, za svaki $s$ smijemo potrošiti $O(N)$ vremena.
    • Stablo obilazimo DFS-om.
    • Uz to pamtimo sljedeće podatke:
      • trenutačnu izdržljivost;
      • je li pečat već udaren (bool vrijednost).
  • Složenost je $O(N^2)$.

Kod sa slajda 13 (G je lista susjedstva; umjesto preostale izdržljivosti pamti se prijeđena udaljenost d, što je isto jer je preostala izdržljivost $D-d$):

for(int s = 0; s < N; ++s) {
    int ans = 0;
    auto dfs = [&](auto &&self, int i, int p, int d, bool stamped) -> void {
        if(T[i] <= d) stamped = true;
        if(stamped) ans ++;
        if(d < D) {
            for(int to : G[i]) if(to != p) self(self, to, i, d+1, stamped);
        }
    }; dfs(dfs, s, -1, 0, false);
    cout << ans << '\n';
}

Na slajdu iza dfs(dfs, s, -1, 0, false); stoji zalutalo „44” — očita tipfelerska greška pri lijepljenju koda, pa je ovdje izostavljena. Svaki vrh $i$ koji DFS posjeti s $d\le D$ odgovara točno jednom paru $(s,i)$ (put u stablu je jedinstven), a zastavica stamped kaže je li na putu $s\to i$ postojao grad s $T\le$ trenutak dolaska; zato se ans uvećava točno za broj dobrih parova s prvim članom $s$.

Podzadatak 4 11 bodova slajdovi 14–17

Put (path graph)

  • Promatramo samo slučaj $s\lt g$.
  • Od sada obrnuto: za svaki $g$ neka je $dp[g]$ najveći $s$ takav da se, hodajući od $s$ do $g$, pečat može udariti barem jednom.
    • Računa se kao $dp[g]=\max\big(g-T[g],\ dp[g-1]\big)$.

Zašto rekurzija za $dp[g]$ vrijedi

Pečat se na putu $s,\dots,g$ može udariti u samom $g$ ako i samo ako je $T_g\le g-s$, tj. $s\le g-T_g$; najveći takav $s$ je $g-T_g$. Inače se udara u nekom gradu $i\lt g$, a to je moguće za točno one $s$ koji su dobri za $g-1$ (put $s,\dots,g-1$ je početni dio puta $s,\dots,g$); najveći takav je $dp[g-1]$. Skup dobrih $s$ za fiksni $g$ zatvoren je prema dolje: ako je pečat moguć iz $s$, moguć je i iz svakog $s'\lt s$, jer se u svaki grad stiže kasnije (trenutak dolaska u $i$ je $i-s'\gt i-s$), a kasniji dolazak samo pomaže. Zato je dovoljno pamtiti najveći dobar $s$.

  • Fiksiramo li $g$, skup vrhova $s$ za koje je $(s,g)$ dobar par čini interval.
    • Konkretno, to su $g-D,\ g-D+1,\ \dots,\ dp[g]$.
    • Dovoljno je imos-metodom (razlikovnim poljem) na taj interval dodati $1$ u $\mathrm{ans}[s]$.
  • Isto napravimo i za $s\gt g$.
  • Složenost je $O(N)$.

Skica intervala (nije na slajdu)

Uvjet $d\le D$ daje $s\ge g-D$, a mogućnost pečata (zatvorena prema dolje) daje $s\le dp[g]$; presjek je interval $[\,g-D,\ dp[g]\,]$, prazan ako je $dp[g]\lt g-D$ ili ako pečat nije moguć ni iz jednog $s$.

Kod sa slajda 17:

vector<int> sol(int N, int D, const vector<int>& T) {
    vector<int> ans(N), dp(N, -1);
    if(T[0] == 0) dp[0] = 0;
    for(int g = 1; g < N; g++) dp[g] = max(dp[g-1], g - T[g]);
    for(int g = 0; g < N; g++) if(g - D <= dp[g]){
        ans[max(0, g - D)] ++;
        if(dp[g] + 1 < N) ans[dp[g] + 1] --;
    }
    for(int i = 1; i < N; ++i) ans[i] += ans[i-1];
    return ans;
}
int main() {
    int N, D; cin >> N >> D;
    vector<int> T(N);
    for(int i = 0; i < N; i++) cin >> T[i];
    vector<int> ans = sol(N, D, T);
    reverse(T.begin(), T.end());
    vector<int> ans2 = sol(N, D, T);
    reverse(ans2.begin(), ans2.end());
    reverse(T.begin(), T.end());
    for(int i = 0; i < N; ++i) {
        ans[i] += ans2[i];
        if(T[i] == 0) ans[i]--;
        cout << ans[i] << '\n';
    }
}

Detalji koda sa slajda 17

Vrijednost $-1$ u dp znači „ni iz jednog $s$ pečat nije moguć”; budući da je $dp[g]=\max(dp[g-1],\,g-T[g])$ i $dp[0]\ge-1$, uvijek je $dp[g]\ge-1$, pa je indeks dp[g] + 1 nenegativan. Kad je $dp[g]=-1$ i $g-D\le-1$, kod doda $1$ na ans[0] i odmah oduzme $1$ na ans[0] — ništa se ne mijenja, kako i treba. Interval $[\max(0,g-D),\,dp[g]]$ dodaje se razlikovnim poljem, a prefiksnim zbrojem dobiju se vrijednosti $\mathrm{ans}[s]$ za sve parove $s\le g$ (uključujući $s=g$, koji je dobar točno kad je $T_g=0$). Slučaj $s\gt g$ dobiva se pozivom iste funkcije na obrnutom nizu $T$ i obrtanjem rezultata; par $(s,s)$ time je prebrojan dvaput, pa se za $T_s=0$ jednom oduzima. Ovaj kod smo stress-testirali protiv izravnog rješenja sa slajda 13 — bez odstupanja.

Kako se iz triju podataka sa slajda 21 dobiva rješenje u $O(N)$ po komponenti

Slajdovi kažu što računati, ali ne i kako iz toga prebrojati parove bez dodatnog $\log$. Ovdje je potpuna izvedba; provjerili smo je implementacijom koja se poklapa s izravnim rješenjem sa slajda 13 na $1500$ slučajnih stabala i radi ispod $1$ s za $N=400\,000$.

Oznake. Neka je $c$ centroid tekuće komponente. Za vrh $v$ komponente stavimo $a(v)=\mathrm{dist}(v,c)$ (prvi podatak sa slajda) i promatrajmo put $v=u_0,u_1,\dots,u_{a}=c$ prema centroidu.

  • Pečat prije centroida. Krenemo li iz $v$ u trenutku $0$ prema $c$, u vrh $u$ s puta stižemo u trenutku $\mathrm{dist}(v,u)=a(v)-\mathrm{dist}(c,u)$, pa je pečat moguć ako i samo ako postoji $u$ na putu $[v,c]$ s $T_u\le a(v)-\mathrm{dist}(c,u)$, tj. \[ Q(v):=\min_{u\in[v,c]}\big(T_u+\mathrm{dist}(c,u)\big)\le a(v). \] Vrijednost $Q$ računa se DP-om od centroida prema dolje: $Q(c)=T_c$, a za dijete $w$ vrha $u$ (gledano iz $c$) $Q(w)=\min\big(Q(u),\,T_w+a(w)\big)$. Oznaka $P(v)$ označava istinitost uvjeta $Q(v)\le a(v)$ — to je drugi podatak sa slajda (bool).
  • Pečat poslije centroida. Krenemo li iz $c$ u trenutku $t$ prema $v$, u vrh $u$ na putu $[c,v]$ stižemo u trenutku $t+\mathrm{dist}(c,u)$, pa je pečat moguć ako i samo ako je $t\ge T_u-\mathrm{dist}(c,u)$ za neki $u$, tj. $t\ge m(v)$, gdje je \[ m(v):=\min_{u\in[c,v]}\big(T_u-\mathrm{dist}(c,u)\big). \] To je treći podatak sa slajda (najmanji dopušteni $t$; može biti negativan, što znači „uvijek moguće”), opet DP od centroida: $m(c)=T_c$, $m(w)=\min\big(m(u),\,T_w-a(w)\big)$.

Uvjet za par kroz centroid. Neka su $s$ i $g$ u različitim podstablima centroida (ili je jedan od njih jednak $c$), $a=a(s)$, $b=a(g)$. Put $s\to g$ je $s\to c\to g$ duljine $a+b$, u $c$ se stiže u trenutku $a$, pa je \[ (s,g)\ \text{dobar} \iff a+b\le D\ \text{ i }\ \big(P(s)\ \text{ ili }\ m(g)\le a\big). \] (Vrh $c$ pripada obama dijelovima puta, ali to ne smeta: uvjet je disjunkcija.)

Brojanje u $O(\text{veličina})$ — ključni trik. Fiksirajmo $g$. Skup svih $a$ za koje par s nekim $s$ na udaljenosti $a$ zadovoljava uvjet je interval:

  • ako vrijedi $P(s)$: $a\in[0,\ D-b(g)]$;
  • ako ne vrijedi $P(s)$: $a\in[\max(0,m(g)),\ D-b(g)]$.

Zato napravimo dva razlikovna polja indeksirana udaljenošću $a\in\{0,1,\dots,\text{veličina}\}$: $\mathrm{cnt}_P[a]$ = broj vrhova $g$ s $D-b(g)\ge a$ (svaki $g$ doda $1$ na $[0,\min(D-b(g),\text{veličina})]$) i $F[a]$ = broj vrhova $g$ s $\max(0,m(g))\le a\le D-b(g)$. Nakon prefiksnih zbrojeva za svaki $s$ dodamo $\mathrm{cnt}_P[a(s)]$ ako vrijedi $P(s)$, inače $F[a(s)]$. Sve je linearno; dvodimenzionalni uvjet „$b(g)\le D-a$ i $m(g)\le a$” riješen je bez Fenwickova stabla upravo zato što za fiksni $g$ dopušteni $a$ čine interval — to je „nepotrebni $\log$” o kojem govori slajd 22.

Izbacivanje parova iz istog podstabla. Gornje brojanje nad cijelom komponentom broji i parove $(s,g)$ s $s$ i $g$ u istom podstablu centroida, za koje put ne prolazi kroz $c$ i uvjet je kriv. Standardno: isti postupak provedemo zasebno za svako podstablo djeteta centroida (s istim vrijednostima $a$, $Q$, $m$, koje se i dalje mjere prema $c$) i rezultat oduzmemo. Ostaju točno parovi s $s$ i $g$ u različitim podstablima, parovi s $s=c$ ili $g=c$, te par $(c,c)$ — svi oni čiji je put kroz $c$. Takav par broji se na točno jednoj razini dekompozicije (na onoj gdje se $s$ i $g$ razdvoje), a par $(s,s)$ na razini gdje je $s$ centroid: $a=b=0$, $m(s)=T_s$, uvjet $T_s\le0$. Rubni slučajevi $s=c$ ($a=0$, $P(c)\iff T_c\le0$) i $g=c$ ($b=0$, $m(c)=T_c$) uklapaju se u iste formule bez posebne obrade.

Složenost. Po komponentni veličine $n$: dva DFS-a i nekoliko polja duljine $n+2$ (indekse ograničimo na $[0,n]$: $D-b(g)$ odrežemo na $n$, $m(g)$ na $\max(0,\cdot)$, a $D-b(g)\lt0$ znači da $g$ ne doprinosi). Zbroj veličina komponenata po svim razinama je $O(N\log N)$, dakle ukupno $O(N\log N)$ vremena i $O(N)$ memorije.

Skica implementacije (stress-testirana protiv koda sa slajda 13; $a$ = udaljenost od $c$, $q$ = $Q$, $m$ = $m$):

struct Info { int v, a, q, m; };   // a = dist(c,v), q = min(T_u + dist(c,u)) na [v,c], m = min(T_u - dist(c,u)) na [c,v]

void collect(int v, int p, int a, int q, int m, vector<Info>& out) {   // DP od centroida prema dolje
    q = min(q, T[v] + a);
    m = min(m, T[v] - a);
    out.push_back({v, a, q, m});
    for (int to : G[v]) if (to != p && !removed[to]) collect(to, v, a + 1, q, m, out);
}

// za svaki s iz 'group' doda sign * #{ g iz 'group' : a(s)+b(g) <= D i (P(s) ili m(g) <= a(s)) }
void account(const vector<Info>& group, int sign, int lim) {   // lim = velicina komponente
    vector<int> cntP(lim + 2, 0), F(lim + 2, 0);
    for (const Info& g : group) {
        int hi = D - g.a;                        // najveci dopusteni a (b(g) = g.a)
        if (hi < 0) continue;
        hi = min(hi, lim);
        cntP[hi]++;                              // sufiksni zbroj: cntP[a] = #g s D - b(g) >= a
        int lo = max(g.m, 0);
        if (lo <= hi) { F[lo]++; F[hi + 1]--; }  // razlikovno polje na intervalu [m(g), D - b(g)]
    }
    for (int i = lim - 1; i >= 0; --i) cntP[i] += cntP[i + 1];
    for (int i = 1; i <= lim; ++i) F[i] += F[i - 1];
    for (const Info& s : group) {
        bool P = s.q <= s.a;                     // pecat vec na dijelu s -> c
        ans[s.v] += sign * (P ? cntP[s.a] : F[s.a]);
    }
}

void solve(int root) {
    int total = calcSize(root, -1);
    int c = findCentroid(root, -1, total);
    vector<Info> all;
    collect(c, -1, 0, INT_MAX, INT_MAX, all);
    account(all, +1, total);                     // svi parovi u komponenti ...
    for (int to : G[c]) if (!removed[to]) {
        vector<Info> sub;
        collect(to, c, 1, T[c], T[c], sub);      // q i m vec sadrze doprinos centroida (T_c +- 0)
        account(sub, -1, total);                 // ... minus parovi unutar istog podstabla
    }
    removed[c] = true;
    for (int to : G[c]) if (!removed[to]) solve(to);
}

Funkcije calcSize i findCentroid su standardne (veličine podstabala uz zanemarivanje uklonjenih vrhova; spuštanje u dijete s više od pola vrhova komponente). Na primjeru iz teksta zadatka program daje $2,3,4,2,2$.

Sažetak

  • $(s,g)$ je dobar par $\iff$ $\mathrm{dist}(s,g)\le D$ i na putu postoji grad $i_j$ s $T_{i_j}\le j$; za $D\le1$ i $N\le3000$ dovoljna je izravna provjera (DFS iz svakog $s$), $O(N)$ odnosno $O(N^2)$.
  • Na putu: $dp[g]=\max(g-T_g,\,dp[g-1])$ je najveći $s$ iz kojeg se do $g$ udari pečat, dobri $s$ za fiksni $g$ čine interval $[g-D,\,dp[g]]$ → razlikovno polje, $O(N)$.
  • Općenito stablo: centroid dekompozicija; za svaki vrh udaljenost od centroida $a$, može li se pečat udariti na putu do centroida ($P$) i najmanji trenutak polaska iz centroida $m$ uz koji se pečat udari na putu od centroida.
  • Par kroz centroid je dobar $\iff a+b\le D$ i ($P(s)$ ili $m(g)\le a$); za fiksni $g$ dopušteni $a$ čine interval, pa se broji razlikovnim poljem bez dodatnog $\log$, uz oduzimanje parova iz istog podstabla: ukupno $O(N\log N)$.
  • Aljkavi detalji ili nepotreban $\log$ (npr. Fenwick za 2D uvjet) donose samo podzadatak 5.
