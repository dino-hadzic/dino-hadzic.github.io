U algoritamskim natjecanjima važan dio teorije brojeva čini modularna aritmetika (modular arithmetic), tj. izvođenje raznih cjelobrojnih operacija pri nekom modulu. Osim osnovnih četiriju računskih operacija i potenciranja, u njoj se mogu zgodno računati i logaritmi, korijeni raznih redova, faktorijeli, binomni koeficijenti i druge operacije.

Modularna aritmetika česta je u raznim vrstama zadataka, a ne samo u dijelu o teoriji brojeva. Stvarni odgovor mnogih zadataka može biti vrlo velik i premašiti raspon uobičajenih cjelobrojnih tipova. Tada, kako bi se izbjeglo uvođenje aritmetike velikih brojeva i ispis dugačkih brojeva, zadatak često traži da se ispiše odgovor modulo neki broj. To zahtijeva dobro vladanje raznim tehnikama modularne aritmetike.

Cjelobrojno dijeljenje i operacija modulo u C/C++-u

U C/C++-u cjelobrojno dijeljenje i operacija modulo ne poklapaju se s dijeljenjem i modulom uobičajenima u matematici.

Za sve standardne verzije C/C++-a propisano je da u cjelobrojnom dijeljenju:

  1. kad je djelitelj 0, ponašanje je nedefinirano;
  2. inače je rezultat izraza (a / b) * b + a % b jednak a.

Drugim riječima, predznak rezultata operacije modulo ovisi o tome kako se zaokružuje pri dijeljenju, a način zaokruživanja pri dijeljenju definiran je implementacijom (odlučuje prevoditelj).

Od verzija standarda C99 i C++11 propisano je da se kvocijent zaokružuje prema nuli (odbacuje se razlomljeni dio); predznak modula tada je jednak predznaku djeljenika. Otada su sljedeće tvrdnje zajamčeno istinite:

assert(5 % 3 == 2);
assert(5 % -3 == 2);
assert(-5 % 3 == -2);
assert(-5 % -3 == -2);

Klasa modularnih cijelih brojeva

Modularna aritmetika može se promatrati kao izvođenje raznih operacija nad klasama kongruencije pri nekom modulu. Ako se klasa kongruencije predstavi strukturom, a zbrajanje, oduzimanje, množenje i druge operacije među klasama kongruencije enkapsuliraju kao metode strukture ili preopterećeni operatori, modularna aritmetika prirodno se može implementirati kao klasa modularnih cijelih brojeva. U nastavku je jednostavan primjer koji podržava zbrajanje, oduzimanje, množenje i brzo potenciranje \(32\)-bitnih predznačenih cijelih brojeva pri modulu \(M < 2^{30}\):

Jednostavna klasa modularnih cijelih brojeva 
// A simple ModInt implementation.
template <int M>
struct ModInt {
  struct skip_mod {};

  ModInt(int v, skip_mod) : v(v) {}

  int v;

  ModInt() : v(0) {}

  // Initialization: find remainder.
  // Equivalent to: v = int((x % M + M) % M)
  ModInt(long long x) {
    x %= M;
    if (x < 0) x += M;
    v = int(x);
  }

  // Addition.
  // Equivalent to: ModInt((l.v + r.v) % M)
  friend ModInt operator+(ModInt l, ModInt r) {
    int res = l.v + r.v;
    if (res >= M) res -= M;
    return ModInt(res, skip_mod{});
  }

  // Subtraction.
  // Equivalent to: ModInt((l.v - r.v + M) % M)
  friend ModInt operator-(ModInt l, ModInt r) {
    int res = l.v - r.v;
    if (res < 0) res += M;
    return ModInt(res, skip_mod{});
  }

  // Multiplication.
  friend ModInt operator*(ModInt l, ModInt r) {
    return ModInt(1LL * l.v * r.v % M, skip_mod{});
  }

  // Exponentiation.
  ModInt pow(long long b) const {
    ModInt res{1}, po{*this};
    for (; b; b >>= 1) {
      if (b & 1) res = res * po;
      po = po * po;
    }
    return res;
  }
};

Ova implementacija namjerno smanjuje broj operacija modulo jer je operacija modulo obično znatno skuplja od običnog zbrajanja, oduzimanja, množenja ili usporedbe. U komentarima koda dane su ekvivalentne i izravnije implementacije. Glavna je ideja tih jednostavnih optimizacija da pri zbrajanju ili oduzimanju dvaju cijelih brojeva iz \([0,M)\) rezultat sigurno pada u interval \((-M,2M)\), pa se jednim zbrajanjem ili oduzimanjem može vratiti u interval \([0,M)\). Potenciranje u ovoj implementaciji koristi tehniku brzog potenciranja.

Osim tih osnovnih operacija, pri raznim modulima mogu se izvoditi i sljedeće operacije:

  • inverz
  • dijeljenje
  • faktorijel
  • binomni koeficijenti
  • kvadratni korijen
  • logaritam
  • korijen

Te su operacije obično lakše pri prostom modulu. Za složeni modul često su potrebne proširene verzije odgovarajućih algoritama i kineski teorem o ostatcima. Većina tih operacija u modularnom smislu može se promatrati kao rješavanje neke vrste kongruencije. Za opće metode rješavanja kongruencija može se pogledati stranica Kongruencije.

Srodni algoritmi

U ovom odjeljku predstavljamo nekoliko metoda za optimiranje operacija modulo, množenja i brzog potenciranja u modularnom smislu. Za veliku većinu zadataka jednostavna implementacija iz prethodnog teksta dovoljno je učinkovita. Međutim, kad zadatak postavlja stroge zahtjeve na konstantu algoritma, te optimizacije mogu doći do izražaja: smanjenjem nepotrebnih izračuna i operacija modulo dodatno snižavaju vremenski trošak algoritma.

Brzo množenje

Pri testiranju prostosti i faktorizaciji na proste faktore često se susreće množenje modulo modul u rasponu long long. Da bi se izbjegao problem cjelobrojnog prekoračenja u računu, u ovom odjeljku predstavljamo „brzo množenje” koje radi s modulom u rasponu long long, ne treba __int128 i ima složenost \(O(1)\). Ovaj algoritam zahtijeva da na sustavu za ocjenjivanje long double bude predstavljen barem kao \(80\)-bitni broj s pomičnim zarezom proširene preciznosti1.

Pretpostavimo da je \(0 \le a, b < m\) i da treba izračunati \(ab\bmod m\). Primijetimo:

\[ ab\bmod m=ab-\left\lfloor \dfrac{ab}m \right\rfloor m. \]

Iskoristimo prirodno prekoračenje tipa unsigned long long:

\[ ab\bmod m=ab-\left\lfloor \dfrac{ab}m \right\rfloor m=\left(ab-\left\lfloor \dfrac{ab}m \right\rfloor m\right)\bmod 2^{64}. \]

Čim možemo izračunati kvocijent \(\left\lfloor\dfrac{ab}m\right\rfloor\), množenje i oduzimanje u krajnje desnom izrazu mogu se izravno izračunati u unsigned long long.

Dalje treba razmotriti samo kako izračunati \(\left\lfloor\dfrac {ab}m\right\rfloor\). Rješenje je da se najprije u long double izračuna \(\dfrac am\) pa pomnoži s \(b\). Budući da koristimo long double, neizbježno dolazi do pogreške u preciznosti. Pretpostavimo da je long double predstavljen kao \(80\)-bitni broj s pomičnim zarezom proširene preciznosti (tj. predznak ima \(1\) bit, eksponent \(15\) bitova, a mantisa \(64\) bita); tada long double može točno predstaviti najviše \(64\) značajna bita2. Stoga \(\dfrac am\) u najgorem slučaju griješi počevši od \(65\). bita, a raspon pogreške3 je \(\left(-2^{-64},2^{-64}\right)\). Nakon množenja s \(b\), \(64\)-bitnim predznačenim cijelim brojem, raspon pogreške je \((-0.5,0.5)\). Radi pojednostavljenja daljnje rasprave možemo najprije dodati \(0.5\) pa zaokružiti na cijeli broj; konačni raspon pogreške je \(\{0,1\}\).

Naposljetku, pri uvrštavanju u gornju formulu treba pomnožiti s \(-m\), pa je konačni raspon pogreške \(\{0,-m\}\). Budući da je \(m\) u rasponu long long, kad je rezultat \(r\in[0,m)\), izravno vraćamo \(r\), a inače vraćamo \(r+m\).

Implementacija u kodu izgleda ovako:

Referentna implementacija 
long long mul(long long a, long long b, long long m) {
  long long c = (unsigned long long)a * b -
                (unsigned long long)((long double)a / m * b + 0.5L) * m;
  return c < 0 ? c + m : c;
}

Danas prevoditelji za C/C++ na velikoj većini sustava za ocjenjivanje već podržavaju tip __int1284, pa se tip množitelja može i izravno proširiti na __int128 i zatim računati modulo:

Referentna implementacija 
long long mul(long long a, long long b, long long m) {
  return (__int128)a * b % m;
}

Dakako, operacija modulo nad __int128 nije jeftina. Ako treba dodatno optimirati konstantu, mogu se razmotriti metode predstavljene u sljedeća dva odjeljka.

Barrettova redukcija

Već je spomenuto da su dijeljenje i operacija modulo obično skuplji od ostalih osnovnih računskih operacija. Kako bi se smanjio trošak operacija modulo, postoje algoritmi koji daju isti rezultat bez izravnog računanja modula. Algoritam Barrettove redukcije (Barrett reduction) koji predstavljamo u ovom odjeljku jedan je od njih.

Neka je \(m\) fiksni modul i pretpostavimo da za razne \(a > 0\) treba više puta izračunati \(a\bmod m\). Iz dijeljenja s ostatkom znamo

\[ z = a\bmod m = a - \left\lfloor\dfrac{a}{m}\right\rfloor m. \]

Ključ je u izračunu kvocijenta \(\left\lfloor\dfrac{a}{m}\right\rfloor\). Neka je \(R\) neka konstanta; tada vrijedi5

\[ \left\lfloor\dfrac{a}{m}\right\rfloor = \left\lfloor a\dfrac{R}{m} / R\right\rfloor \approx \left\lfloor a\left\lfloor\dfrac{R}{m}\right\rfloor/R\right\rfloor. \]

Ako odaberemo \(R = 2^k\), tada se \(\left\lfloor\dfrac{R}{m}\right\rfloor\) u desnom izrazu može unaprijed izračunati, a dijeljenje s \(R\) može se obaviti posmakom. Stoga izračun kvocijenta desnim izrazom zahtijeva samo jedno množenje i jedan posmak. Uvrštavanjem u izraz za \(a\bmod m\) dobivamo procjenu \(z'\) traženog ostatka.

Sada analizirajmo pogrešku takvog postupka. Funkcije pod i strop imaju svojstvo: za \(x > y > 0\) vrijedi \(\lfloor x\rfloor - \lfloor y\rfloor \le \lceil x - y\rceil\). Stoga je pogreška

\[ \begin{aligned} \Delta &= |z' - z| = m\left|\left\lfloor\dfrac{a}{m}\right\rfloor - \left\lfloor a\left\lfloor\dfrac{R}{m}\right\rfloor/R\right\rfloor\right|\\ &\le m\left\lceil a\left(\dfrac{R}{m} - \left\lfloor\dfrac{R}{m}\right\rfloor\right) /R\right\rceil \le m\left\lceil\dfrac{a}{R}\right\rceil. \end{aligned} \]

Čim je \(a \le R\), pogreška \(\Delta\) ne premašuje \(m\). Budući da je \(z' \ge z\), procjena \(z'\) može biti samo \(z\) ili \(z + m\). Dovoljno je nakon dobivanja procjene, kad je \(z' \ge m\), oduzeti suvišni \(m\) i odgovor je zajamčeno točan.

U postupku Barrettove redukcije cjelobrojni modul računa se samo s dva množenja, jednim posmakom i najviše dva oduzimanja. No povećanje učinkovitosti nije besplatno: zapravo su međuvarijable u Barrettovoj redukciji često dulje od ulaznih varijabli. Lako se vidi da je najdulja međuvarijabla u Barrettovoj redukciji \(a\left\lfloor\dfrac{R}{m}\right\rfloor\). Neka \(\ell(x)\) označava duljinu binarnog zapisa cijelog broja \(x\). Tada vrijedi

\[ \ell\left(a\left\lfloor\dfrac{R}{m}\right\rfloor\right) \approx \ell(a) + \ell(R) - \ell(m). \]

Budući da izbor \(R\) mora zadovoljavati uvjet \(a \le R\), ta je duljina barem \(2\ell(a) - \ell(m)\). No kad je potrebno računati modulo, obično je \(\ell(m)\le\ell(a)\), pa duljina te međuvarijable može biti veća od ulazne duljine \(\ell(a)\). Na primjer, ako treba \(64\)-bitni cijeli broj računati modulo \(32\)-bitni cijeli broj, međuvarijabla zapravo treba \(64 \times 2 - 32 = 96\)-bitni cijeli broj.

Jedna od primjena Barrettove redukcije jest izračun ostatka umnoška \(ab\bmod m\). Ako je jedan od množitelja fiksan, recimo \(b\), tada se pomoću

\[ ab\bmod m = ab - \left\lfloor a\left\lfloor\dfrac{bR}{m}\right\rfloor/R\right\rfloor m \]

može napraviti procjena slična gornjoj; dovoljno je unaprijed izračunati vrijednost \(\left\lfloor\dfrac{bR}{m}\right\rfloor\). Ovaj slučaj s fiksnim \(b\) ponekad se naziva i Shoupovo množenje6.

Češći je slučaj kad \(a, b\) nisu fiksni. Tada treba najprije izračunati vrijednost \(ab\), a zatim Barrettovom redukcijom dobiti \(ab\bmod m\). Na primjer, pri implementaciji množenja u modularnom smislu treba za \(0 \le a,b < m\) izračunati \(ab\bmod m\). Tada odabrani \(R\) mora zadovoljavati \(ab \le R\). Prema prethodnoj analizi, najdulja međuvarijabla u izračunu ima duljinu \(2\ell(ab)-\ell(m)\). Kad je \(\ell(a)\approx\ell(b)\approx\ell(m)\), ta duljina iznosi \(3\ell(m)\). Drugim riječima, ako se Barrettovom redukcijom želi implementirati modularno množenje \(32\)-bitnih cijelih brojeva, međuvarijable trebaju \(96\)-bitne cijele brojeve. To je jedno od ograničenja praktične primjene Barrettove redukcije u algoritamskim natjecanjima.

Kao primjer, referentna implementacija modularnog množenja \(32\)-bitnih predznačenih cijelih brojeva Barrettovom redukcijom izgleda ovako:

Referentna implementacija 
// Modular multiplication of int32_t using Barrett reduction.
class Barrett {
  int32_t m;
  uint64_t r;

 public:
  Barrett(int32_t m) : m(m), r((uint64_t)(-m) / m + 1) {}

  // Barrett reduction: a % m.
  int32_t reduce(int64_t a) const {
    int64_t q = (__int128)a * r >> 64;
    a -= q * m;
    return a >= m ? a - m : a;
  }

  // Modular multiplication: (a * b) % m;
  // Assume that 0 <= a, b < m.
  int32_t mul(int32_t a, int32_t b) const { return reduce((int64_t)a * b); }
};

U implementaciji su potrebni \(128\)-bitni cijeli brojevi4.

Montgomeryjevo množenje

Algoritam Montgomeryjeva množenja (Montgomery multiplication) po funkciji je vrlo sličan Barrettovu algoritmu: i on može smanjiti trošak operacija modulo pri računanju s modularnim cijelim brojevima. Za razliku od prethodna dva algoritma, koji približno računaju kvocijent, Montgomeryjevo množenje preslikava sve cijele brojeve u Montgomeryjev prostor, u kojem su operacije razmjerno jednostavne, čime se snižava ukupni trošak računanja.

Neka je modul \(m\) neparan i odaberimo \(R = 2^k > m\). Tada je Montgomeryjev oblik koji odgovara klasi kongruencije \(a \bmod m\)

\[ aR\bmod m. \]

Budući da je \(R\perp m\), između klase kongruencije \(a \bmod m\) i njezina Montgomeryjeva oblika \(aR\bmod m\) postoji bijekcija. Stoga se cijeli brojevi mogu pretvoriti u Montgomeryjev oblik, zatim se izvede niz operacija modulo \(m\), a dobiveni se Montgomeryjev oblik pretvori natrag u cijeli broj; rezultat je uvijek točan.

Montgomeryjev oblik omogućuje zgodno izvođenje mnogih operacija s modularnim cijelim brojevima. Upravo smo objasnili da je za usporedbu dviju klasa kongruencije dovoljno usporediti njihove Montgomeryjeve oblike. Nadalje, budući da je

\[ (a\pm b)R\bmod m = ((aR\bmod m)\pm(bR\bmod m)) \bmod{m}, \]

zbrajanje i oduzimanje klasa kongruencije odgovara zbrajanju i oduzimanju njihovih Montgomeryjevih oblika. Međutim, za množenje klasa kongruencije ne mogu se izravno pomnožiti dva Montgomeryjeva oblika. Budući da je

\[ (ab)R\bmod m = ((aR\bmod m)(bR\bmod m)R^{-1}) \bmod{m}, \]

pri množenju dvaju Montgomeryjevih oblika nad njihovim umnoškom \(x\) treba izvesti sljedeću operaciju Montgomeryjeve redukcije (Montgomery reduction):

\[ \operatorname{REDC}: x \mapsto xR^{-1}\bmod m. \]

Pomoću te operacije Montgomeryjev oblik umnoška \(ab\) jest \(\operatorname{REDC}((aR\bmod m)(bR\bmod m))\). Montgomeryjeva redukcija središnja je operacija Montgomeryjeva množenja:

  • Pretvorba \(a\) u njegov Montgomeryjev oblik jest \(\operatorname{REDC}((a\bmod m)(R^2\bmod m))\).
  • Pretvorba Montgomeryjeva oblika od \(a\) natrag u \(a\bmod m\) jest \(\operatorname{REDC}(aR\bmod m)\).
  • Montgomeryjev oblik koji odgovara modularnom inverzu \(a^{-1}\bmod m\) jest \(\operatorname{REDC}((aR\bmod m)^{-1}(R^3\bmod m))\).

Sada raspravimo kako implementirati operaciju Montgomeryjeve redukcije \(\operatorname{REDC}\). Pri izračunu \(\operatorname{REDC}(x)\) uvijek pretpostavljamo \(0 \le x < m^2\), što vrijedi u svim gornjim slučajevima. Budući da je \(R\perp m\), prema Bézoutovu teoremu postoje cijeli brojevi \(R^{-1},m'\) takvi da je

\[ RR^{-1} + mm' = 1. \]

Stoga, uz \(q=\lfloor xm' / R\rfloor\), vrijedi

\[ \begin{aligned} xR^{-1} &= x\dfrac{1 - mm'}{R} \equiv \dfrac{x-xmm' + qmR}{R} = \dfrac{x - m(xm'\bmod R)}{R} \pmod{m}. \end{aligned} \]

Budući da je \(0 \le x < m^2 < mR\) i \(0 \le xm'\bmod R < R\), vrijedi

\[ -m < \dfrac{x - m(xm'\bmod R)}{R} < m. \]

Drugim riječima, taj se kvocijent od \(xR^{-1}\bmod m\) razlikuje za najviše jedan \(m\). Dovoljno je, kad je kvocijent manji od nule, dodati \(m\) i dobiva se \(\operatorname{REDC}(x)\). Za izračun tog kvocijenta potrebna su samo dva cjelobrojna množenja, jedno cjelobrojno oduzimanje i dvije bitovne operacije (redom modulo \(R=2^k\) i dijeljenje s njim). Stoga se Montgomeryjeva redukcija može izvesti učinkovito.

Za izvođenje Montgomeryjeva množenja potrebno je unaprijed izračunati niz konstanti. Prvo, u Montgomeryjevoj redukciji koristi se \(m' = m^{-1}\bmod R\), koji se može izračunati Newton–Henselovom metodom predstavljenom u nastavku. Drugo, pri svođenju raznih operacija na Montgomeryjevu redukciju pojavljuju se i konstante poput \(R^2\bmod m\). Da bismo je dobili, treba jednom izračunati \(R\bmod m\), a zbrajanjem sa samim sobom dobiva se \(2R\bmod m\). Zatim, promatrajući to kao Montgomeryjev oblik broja \(2\) i izravno primjenjujući brzo potenciranje, dobiva se \(2^kR\bmod m = R^2\bmod m\).

Kao primjer, implementacija Montgomeryjeva množenja \(32\)-bitnih predznačenih cijelih brojeva izgleda ovako:

Referentna implementacija 
// Montgomery modular multiplication.
// The modulus m must be odd. The constant r is 2^32.
class Montgomery {
  int32_t m;
  uint32_t mm, r2;

 public:
  Montgomery(int32_t m) : m(m), mm(1), r2(-m) {
    // Compute mm as inv(m) mod r.
    for (int i = 0; i < 5; ++i) {
      mm *= 2 - mm * m;
    }
    // Compute r2 as r * r mod m.
    // If allowed to use modular operation for uint64_t, simply use:
    //   r2 = (uint64_t)(-m) % m;
    r2 %= m;
    r2 <<= 1;
    if (r2 >= (uint32_t)m) r2 -= m;
    for (int i = 0; i < 5; ++i) {
      r2 = mul(r2, r2);
    }
  }

  // Montgomery reduction: x * inv(r) % m.
  // Also used to transform x from Montgomery space to the normal space.
  int32_t reduce(int64_t x) {
    uint32_t u = (uint32_t)x * mm;
    int32_t ans = (x - (int64_t)m * u) >> 32;
    return ans < 0 ? ans + m : ans;
  }

  // Multiplication in Montgomery space: x * y * inv(r) % m.
  int32_t mul(int32_t x, int32_t y) { return reduce((int64_t)x * y); }

  // Transform x from the normal space to Montgomery space.
  int32_t init(int32_t x) { return mul(x, r2); }
};

U usporedbi s implementacijom modularnog množenja Barrettovom redukcijom, izračun Montgomeryjevim množenjem uključuje više koraka: pretvorbu, množenje Montgomeryjevih oblika, inverznu pretvorbu itd. Stoga se trošak pretvorbe i inverzne pretvorbe može amortizirati, a time postići visoka ukupna učinkovitost, samo kad je broj modularnih operacija između pretvorbe i inverzne pretvorbe dovoljno velik. Međutim, budući da implementacija Montgomeryjeva množenja uključuje samo međuvarijable duljine \(2\ell(m)\), implementacija je fleksibilnija. Na primjer, modularno množenje \(32\)-bitnih cijelih brojeva treba samo \(64\)-bitne međuvarijable. Stoga, ako treba implementirati klasu modularnih cijelih brojeva za razne teorijsko-brojevne izračune, Montgomeryjevo množenje prikladnije je.

Klasa cijelih brojeva modulo potencija broja 2

U ovom odjeljku raspravljamo o implementaciji klase modularnih cijelih brojeva kad je modul potencija broja \(2\). U tom posebnom slučaju dijeljenje i operacija modulo mogu se izvesti bitovnim operacijama, pa je računanje vrlo učinkovito. I Barrettova redukcija i Montgomeryjevo množenje iskorištavaju to svojstvo \(2^e\) kao djelitelja i modula kako bi ubrzali račun. Posebno, kad je modul upravo neki od posebnih brojeva poput \(2^{32}\) i \(2^{64}\), klasa modularnih cijelih brojeva može se implementirati pomoću nepredznačenih cijelih brojeva odgovarajuće duljine i prirodnog prekoračenja, bez ikakve eksplicitne operacije modulo. Čak i kad modul nije točno takav, može se svesti na slučaj tih posebnih modula. Na primjer, kad je modul \(2^{58}\), međuizračuni se mogu obaviti modulo \(2^{64}\), a na kraju se rezultat uzme modulo \(2^{58}\). Osim što je operacija modulo jednostavna, i druge operacije klase cijelih brojeva modulo \(2^e\) imaju mnoge posebne implementacije. U ovom se odjeljku usredotočujemo na implementaciju inverza i potenciranja.

Prvo inverz: za zadani neparni \(a\) i modul \(m=2^e~(e > 2)\) treba naći \(a^{-1}\bmod m\). Uobičajene metode za inverz uključuju prošireni Euklidov algoritam i metodu brzog potenciranja. Postupak proširenog Euklidova algoritma uključuje računanje modulo opći modul; obična metoda brzog potenciranja treba izračunati \(a^{\varphi(m)-1}\bmod{m}\), što zahtijeva \(\Theta(e)\) cjelobrojnih množenja. Učinkovitija je Newton–Henselova metoda. Konkretno, razmotrimo primjenu sljedećeg rezultata:7

\[ ax \equiv 1 \pmod{2^e} \implies ax(2 - ax) \equiv 1\pmod{2^{2e}}. \]

Prema tom izrazu, dovoljno je krenuti od \(x = 1\) i uzastopno primjenjivati \(x \gets x(2-ax)\); nakon \(\lceil\log_2 e\rceil\) iteracija dobiva se \(a^{-1}\bmod m\).

Kao primjer, referentna implementacija inverza cijelih brojeva modulo \(2^{32}\) izgleda ovako:

Referentna implementacija 
// Compute 1/v mod 2^32 for odd v.
uint32_t inv_mod_2_32(uint32_t v) {
  uint32_t x = 1;
  for (int i = 0; i != 5; ++i) {
    x *= 2 - v * x;
  }
  return x;
}

Zatim potenciranje: za zadane \(x,a,b\) i modul \(m=2^e~(e > 2)\) treba naći \(xa^b\bmod m\), pri čemu je \(a\) neparan. Prema analizi strukture množenja cijelih brojeva modulo \(2^e\) znamo da se \(a\) uvijek može zapisati u obliku \(\pm g^{\ell}\)8, pri čemu se negativni predznak pojavljuje točno onda kad je \(a\equiv 3\pmod 4\). U tom se slučaju \(a\) može zamijeniti s \(-a\), a konačni rezultat pomnožiti s \((-1)^b\). Stoga u nastavku bez smanjenja općenitosti pretpostavljamo da vrijedi \(a\equiv 1\pmod 4\). Tada je središnja ideja algoritma zapisati \(a\) u obliku \(g^{L(a)}\bmod m\) i zatim traženu potenciju izračunati kao \(xg^{bL(a)}\bmod m\).

Izračunati \(L(a)\) znači izračunati diskretni logaritam \(\operatorname{ind}_ga\). Primijetimo da se, čim je \(a\equiv 1\pmod 4\), \(a\) uvijek može zapisati u sljedećem obliku:

\[ a \equiv (2^{e_1}+1)(2^{e_2}+1)\cdots(2^{e_s}+1) \pmod{m}, \]

gdje je \(1 < e_1 < e_2 < \cdots < e_s < e\). Naime, izravnim razvojem tog umnoška vidi se da je drugi najniži bit binarnog zapisa od \(a\) koji je jednak \(1\) upravo \(e_1\). bit (indeksi počinju od \(0\)), pa se taj zapis može naći rekurzivno. Prema svojstvima diskretnog logaritma vrijedi

\[ 4L(a) \equiv 4L(2^{e_1}+1) + 4L(2^{e_2}+1) + \cdots + 4L(2^{e_s}+1) \pmod{m}. \]

Budući da je modul diskretnog logaritma jednak redu \(\delta_m(g)=2^{e-2}=m/4\), ovdje smo cijelu kongruenciju izravno pomnožili s \(4\) kako bi se račun mogao provoditi u klasama ostataka modulo \(m\). Stoga je dovoljno za \(1 < d < e\) unaprijed izračunati sve \(4L(2^d+1)\) i vrijednost \(4L(a)\) može se brzo izračunati.

Obratno, iz \(L(a)\) lako se dobiva vrijednost \(g^{L(a)}\bmod{m}\). Prema binomnom teoremu za \(1 < d < e\) vrijedi

\[ \begin{aligned} (2^d+1)^{2^{e-d}} \equiv 1 \pmod{m},\quad (2^d+1)^{2^{e-d-1}} \equiv 1 + 2^{e-1} \pmod{m}, \end{aligned} \]

pa je \(\delta_m(2^d+1) = 2^{e-d}\). Prema svojstvima reda vrijedi

\[ \delta_m(2^d+1) = \dfrac{\delta_m(g)}{\gcd(\delta_m(g), \operatorname{ind}_g(2^d+1))}. \]

Stoga je \(\gcd(\delta_m(g), \operatorname{ind}_g(2^d+1)) = 2^{d-2}\). To pokazuje da je \(L(2^d+1) = \operatorname{ind}_g(2^d+1) = 2^{d-2}r\), gdje je \(2\nmid r\). Dakle, najniži bit binarnog zapisa od \(4L(2^d+1)\) koji je jednak \(1\) upravo je \(d\). bit (indeksi počinju od \(0\)). Stoga se i \(4L(a)\) može rekurzivno, preko binarnog zapisa, rastaviti na zbroj članova oblika \(4L(2^d+1)\). Odatle se dobiva vrijednost \(a\).

U konkretnoj implementaciji postoji nekoliko točaka koje se mogu dodatno optimirati. Prvo, pri rastavljanju \(a\) u oblik umnoška i dalje je potrebno dijeljenje. Zgodnije je računati rastav od \(a^{-1}\), tj. tražiti \(1 < e_1 < e_2 < \cdots < e_s < e\) takve da vrijedi

\[ a(2^{e_1}+1)(2^{e_2}+1)\cdots(2^{e_s}+1) \equiv 1 \pmod{m} \]

I ovdje se \(e_1\) određuje traženjem drugog najnižeg bita jednakog \(1\), ali da bi se u \(a^{-1}\) poništio faktor \(2^{e_1}+1\), dovoljno je \(a\) pomnožiti s \(2^{e_1}+1\), što se može obaviti bitovnim operacijama. Nadalje, budući da je \(4L(a^{-1})=-4L(a)\), pri zbrajanju \(4L(a)\) treba umjesto zbrajanja koristiti oduzimanje. Drugo, za posebno odabranu bazu \(g\) iteracija ne mora ići do \(d = e-1\), nego je dovoljno ići do \(d = \lceil e/2\rceil - 1\). Za to treba odabrati \(g\) tako da je

\[ 4L(2^{\lceil e/2\rceil} + 1) = 2^{\lceil e/2\rceil}. \]

Za \(d \ge e / 2\) vrijedi

\[ (2^d+1)^2 = 2^{2d} + 2^{d+1} + 1 \equiv 2^{d+1} + 1 \pmod{m}. \]

Stoga indukcijom od \(d = \lceil e/2\rceil\) slijedi da \(4L(2^d+1)=2^d\) vrijedi za sve \(d \ge e/2\). Nadalje, čim je \(e/2 \le e_1 < e_2 < \cdots < e_s < e\), vrijedi

\[ (2^{e_1}+1)(2^{e_2}+1)\cdots(2^{e_s}+1) \equiv 1 + 2^{e_1} + 2^{e_2} + \cdots + 2^{e_s} \pmod{m} \]

te

\[ 4L((2^{e_1}+1)(2^{e_2}+1)\cdots(2^{e_s}+1)) = 2^{e_1} + 2^{e_2} + \cdots + 2^{e_s}. \]

Stoga se nakon obrade svih binarnih bitova s \(d < e/2\) diskretni logaritam preostalog dijela može dobiti izravno, bez računanja bit po bit. Uz prvu optimizaciju cijelo potenciranje treba samo \(O(e)\) zbrajanja, oduzimanja i bitovnih operacija te \(1\) množenje; uz drugu optimizaciju može se uštedjeti otprilike polovica zbrajanja, oduzimanja i bitovnih operacija, ali je potrebno dodatno \(1\) množenje.

Kao primjer, referentna implementacija potenciranja cijelih brojeva modulo \(2^{32}\) izgleda ovako:

Referentna implementacija 
// Store 4L(a) for a = 2^d + 1, where L(a) is disc. log. base 388251981.
// The first two values are never used and thus set to zero.
// The base is chosen such that 4L(2^16+1) = 2^16.
constexpr uint32_t log_table[16] = {
    0x00000000, 0x00000000, 0xbba0267c, 0x49b9d1e8, 0xf0026f90, 0xd6e17e20,
    0xe78bf840, 0x039fe080, 0xaf7f8100, 0x60fe0200, 0xd1f80400, 0x23e00800,
    0x47801000, 0x8e002000, 0x18004000, 0x20008000,
};

// Compute 4L(v).
uint32_t log_mod_2_32(uint32_t x, uint32_t v) {
  for (int i = 2; i != 16; ++i) {
    if ((v >> i) & 1) {
      v += v << i;
      x -= log_table[i];
    }
  }
  x += v ^ 1;
  return x;
}

// Compute x*a for 4L(a) = v.
uint32_t exp_mod_2_32(uint32_t x, uint32_t v) {
  for (int i = 2; i != 16; ++i) {
    if ((v >> i) & 1) {
      x += x << i;
      v -= log_table[i];
    }
  }
  x *= v ^ 1;
  return x;
}

// Compute x*a^b for odd a.
uint32_t pow_odd_mod_2_32(uint32_t a, uint32_t b, uint32_t x) {
  if (a & 2) {
    a = -a;
    if (b & 1) {
      x = -x;
    }
  }
  return exp_mod_2_32(x, log_mod_2_32(0, a) * b);
}

// Compute x*a^b mod 2^32.
uint32_t pow_mod_2_32(uint32_t a, uint32_t b, uint32_t x = 1) {
  if (!a) return b == 0 ? x : 0;
  auto d = __builtin_ctz(a);
  if ((uint64_t)d * b >= 32) return 0;
  return pow_odd_mod_2_32(a >> d, b, x) << (d * b);
}

Predračun diskretnih logaritama može se obaviti Pohlig–Hellmanovim algoritmom, a baza \(g\) može se odabrati kao

\[ 5^{\operatorname{ind}_5(2^{\lceil e/2\rceil}+1)/2^{\lceil e/2\rceil - 2}}\bmod{2^e}. \]

In algorithm competitions, an important component of number theory is modular arithmetic, that is, performing all kinds of integer operations under some modulus. Besides the basic four arithmetic operations and exponentiation, one can also conveniently take logarithms, extract roots of various orders, compute factorials and binomial coefficients, and so on.

Modular arithmetic appears in all kinds of problems, not only in the number theory part. The actual answer to many problems may be very large and exceed the range of common integer types. In that case, to avoid introducing big-integer arithmetic and printing long numbers, problems often require the answer to be printed modulo some number. This requires a solid command of all kinds of modular arithmetic techniques.

Integer division and modulo in C/C++

In C/C++, integer division and the modulo operation are inconsistent with the division and modulo customary in mathematics.

For all standard versions of C/C++, it is specified that in integer division:

  1. when the divisor is 0, the behavior is undefined;
  2. otherwise, the result of (a / b) * b + a % b equals a.

In other words, the sign of the modulo operation depends on how division rounds, and how division rounds is implementation-defined (decided by the compiler).

Starting from the C99 and C++11 versions of the standards, it is specified that the quotient is rounded toward zero (the fractional part is discarded); the sign of the modulo is then the same as that of the dividend. Since then, the following assertions are guaranteed to be true:

assert(5 % 3 == 2);
assert(5 % -3 == 2);
assert(-5 % 3 == -2);
assert(-5 % -3 == -2);

Modular integer class

Modular arithmetic can be viewed as performing all kinds of operations on the congruence classes under some modulus. If a struct is used to represent a congruence class, and addition, subtraction, multiplication and other operations between congruence classes are encapsulated as methods of the struct or as operator overloads, then modular arithmetic can be naturally implemented as a modular integer class. Below is a simple example that supports addition, subtraction, multiplication and binary exponentiation of \(32\)-bit signed integers under a modulus \(M < 2^{30}\):

A simple modular integer class 
// A simple ModInt implementation.
template <int M>
struct ModInt {
  struct skip_mod {};

  ModInt(int v, skip_mod) : v(v) {}

  int v;

  ModInt() : v(0) {}

  // Initialization: find remainder.
  // Equivalent to: v = int((x % M + M) % M)
  ModInt(long long x) {
    x %= M;
    if (x < 0) x += M;
    v = int(x);
  }

  // Addition.
  // Equivalent to: ModInt((l.v + r.v) % M)
  friend ModInt operator+(ModInt l, ModInt r) {
    int res = l.v + r.v;
    if (res >= M) res -= M;
    return ModInt(res, skip_mod{});
  }

  // Subtraction.
  // Equivalent to: ModInt((l.v - r.v + M) % M)
  friend ModInt operator-(ModInt l, ModInt r) {
    int res = l.v - r.v;
    if (res < 0) res += M;
    return ModInt(res, skip_mod{});
  }

  // Multiplication.
  friend ModInt operator*(ModInt l, ModInt r) {
    return ModInt(1LL * l.v * r.v % M, skip_mod{});
  }

  // Exponentiation.
  ModInt pow(long long b) const {
    ModInt res{1}, po{*this};
    for (; b; b >>= 1) {
      if (b & 1) res = res * po;
      po = po * po;
    }
    return res;
  }
};

This implementation deliberately reduces the number of modulo operations, because a modulo operation is usually much more expensive than an ordinary addition, subtraction, multiplication or comparison. The code comments provide equivalent and more direct implementations. The main idea of these simple optimizations is that when two integers in \([0,M)\) are added or subtracted, the result certainly falls in the interval \((-M,2M)\), so it can be adjusted back into the interval \([0,M)\) by one addition or subtraction. The exponentiation in this implementation uses the technique of binary exponentiation.

Besides these basic operations, the following operations can also be performed under various moduli:

  • inverse
  • division
  • factorial
  • binomial coefficients
  • square root
  • logarithm
  • roots

These operations are usually easier under a prime modulus. For a composite modulus, extended versions of the corresponding algorithms and the Chinese remainder theorem are often needed. Most of these modular operations can be viewed as solving some kind of congruence equation. For general methods of solving congruence equations, see the Congruence equations page.

Related algorithms

This section introduces several methods for optimizing modulo, multiplication and binary exponentiation in the modular setting. For the vast majority of problems, the simple implementation given above is efficient enough. However, when a problem has strict requirements on the constant factor of the algorithm, these optimizations can come into play and further reduce the running time of the algorithm by cutting unnecessary computations and modulo operations.

Fast multiplication

In primality testing and integer factorization, one often encounters modular multiplication with a modulus in the long long range. To avoid integer overflow during the computation, this section introduces a "fast multiplication" that handles a modulus in the long long range, does not need __int128, and has complexity \(O(1)\). This algorithm requires that, on the judge system, long double is represented as at least an \(80\)-bit extended-precision floating-point number1.

Suppose \(0 \le a, b < m\) and we want to compute \(ab\bmod m\). Notice that:

\[ ab\bmod m=ab-\left\lfloor \dfrac{ab}m \right\rfloor m. \]

Using the natural overflow of unsigned long long:

\[ ab\bmod m=ab-\left\lfloor \dfrac{ab}m \right\rfloor m=\left(ab-\left\lfloor \dfrac{ab}m \right\rfloor m\right)\bmod 2^{64}. \]

As long as we can compute the quotient \(\left\lfloor\dfrac{ab}m\right\rfloor\), the multiplication and subtraction in the rightmost expression can be computed directly with unsigned long long.

Next, we only need to consider how to compute \(\left\lfloor\dfrac {ab}m\right\rfloor\). The solution is to first compute \(\dfrac am\) with long double and then multiply by \(b\). Since long double is used, there will undoubtedly be precision errors. Suppose long double is represented as an \(80\)-bit extended-precision floating-point number (that is, \(1\) sign bit, \(15\) exponent bits and \(64\) mantissa bits); then long double can represent at most \(64\) significant bits exactly2. So in the worst case \(\dfrac am\) goes wrong starting from bit \(65\), and the error range3 is \(\left(-2^{-64},2^{-64}\right)\). After multiplying by \(b\), a \(64\)-bit signed integer, the error range is \((-0.5,0.5)\). To simplify the following discussion, we can first add \(0.5\) and then round down; the final error range is \(\{0,1\}\).

Finally, when substituting into the formula above, we need to multiply by \(-m\), so the final error range is \(\{0,-m\}\). Since \(m\) is in the long long range, when the result \(r\in[0,m)\) we return \(r\) directly, and otherwise we return \(r+m\).

The code implementation is as follows:

Reference implementation 
long long mul(long long a, long long b, long long m) {
  long long c = (unsigned long long)a * b -
                (unsigned long long)((long double)a / m * b + 0.5L) * m;
  return c < 0 ? c + m : c;
}

Nowadays, the C/C++ compilers on the vast majority of judge systems already support the __int128 type4, so one can also simply promote the type of the multiplicands to __int128 and then take the modulo:

Reference implementation 
long long mul(long long a, long long b, long long m) {
  return (__int128)a * b % m;
}

Of course, the modulo operation on __int128 is not cheap either. If the constant factor needs to be squeezed further, consider the methods introduced in the next two sections.

Barrett reduction

As mentioned above, division and modulo operations are usually more expensive than the other arithmetic operations. To reduce the cost of modulo operations, there are algorithms that obtain the same result without directly taking a modulo. The Barrett reduction algorithm introduced in this section is one of them.

Let \(m\) be a fixed modulus, and suppose we want to compute \(a\bmod m\) many times for different \(a > 0\). By division with remainder,

\[ z = a\bmod m = a - \left\lfloor\dfrac{a}{m}\right\rfloor m. \]

The key is the computation of the quotient \(\left\lfloor\dfrac{a}{m}\right\rfloor\). Let \(R\) be some constant; then5

\[ \left\lfloor\dfrac{a}{m}\right\rfloor = \left\lfloor a\dfrac{R}{m} / R\right\rfloor \approx \left\lfloor a\left\lfloor\dfrac{R}{m}\right\rfloor/R\right\rfloor. \]

If we choose \(R = 2^k\), then \(\left\lfloor\dfrac{R}{m}\right\rfloor\) in the right-hand expression can be precomputed, and the division by \(R\) can be done by a shift. So computing the quotient with the right-hand expression needs only one multiplication and one shift. Substituting into the expression for \(a\bmod m\), we get an estimate \(z'\) of the desired remainder.

Now we analyze the error of this approach. The floor function has the property that for \(x > y > 0\), \(\lfloor x\rfloor - \lfloor y\rfloor \le \lceil x - y\rceil\). Therefore, the error

\[ \begin{aligned} \Delta &= |z' - z| = m\left|\left\lfloor\dfrac{a}{m}\right\rfloor - \left\lfloor a\left\lfloor\dfrac{R}{m}\right\rfloor/R\right\rfloor\right|\\ &\le m\left\lceil a\left(\dfrac{R}{m} - \left\lfloor\dfrac{R}{m}\right\rfloor\right) /R\right\rceil \le m\left\lceil\dfrac{a}{R}\right\rceil. \end{aligned} \]

As long as \(a \le R\), the error \(\Delta\) does not exceed \(m\). Since \(z' \ge z\), the estimate \(z'\) can only be \(z\) or \(z + m\). After obtaining the estimate, it suffices to subtract the extra \(m\) when \(z' \ge m\) to guarantee a correct answer.

In the computation of Barrett reduction, only two multiplications, one shift and at most two subtractions are used to complete the integer modulo. But the efficiency gain is not free: in fact, the intermediate variables involved in Barrett reduction are often longer than the input variables. It is easy to see that the longest intermediate variable in Barrett reduction is \(a\left\lfloor\dfrac{R}{m}\right\rfloor\). Let \(\ell(x)\) be the length of the binary representation of the integer \(x\). Then

\[ \ell\left(a\left\lfloor\dfrac{R}{m}\right\rfloor\right) \approx \ell(a) + \ell(R) - \ell(m). \]

Since the choice of \(R\) must satisfy the condition \(a \le R\), this length is at least \(2\ell(a) - \ell(m)\). But when a modulo is needed, we generally have \(\ell(m)\le\ell(a)\), so the length of this intermediate variable may be greater than the input length \(\ell(a)\). For example, if a \(64\)-bit integer must be reduced modulo a \(32\)-bit integer, the intermediate variable actually needs a \(64 \times 2 - 32 = 96\)-bit integer.

One application of Barrett reduction is computing the remainder of a product, \(ab\bmod m\). If one of the factors is fixed, say \(b\), then

\[ ab\bmod m = ab - \left\lfloor a\left\lfloor\dfrac{bR}{m}\right\rfloor/R\right\rfloor m \]

gives an estimate similar to the one above, and it suffices to precompute the value of \(\left\lfloor\dfrac{bR}{m}\right\rfloor\). This case with fixed \(b\) is sometimes also called Shoup's modular multiplication6.

The more common case is that \(a, b\) are both not fixed. Then one must first compute the value of \(ab\) and then use Barrett reduction to get \(ab\bmod m\). For example, when implementing modular multiplication, we need to compute \(ab\bmod m\) for \(0 \le a,b < m\). Then the chosen \(R\) must satisfy \(ab \le R\). By the analysis above, the longest intermediate variable in the computation has length \(2\ell(ab)-\ell(m)\). When \(\ell(a)\approx\ell(b)\approx\ell(m)\), this length is \(3\ell(m)\). In other words, if Barrett reduction is used to implement modular multiplication of \(32\)-bit integers, the intermediate variables need \(96\)-bit integers. This is one limitation of Barrett reduction in practical use in algorithm competitions.

As an example, a reference implementation of modular multiplication of \(32\)-bit signed integers using Barrett reduction is as follows:

Reference implementation 
// Modular multiplication of int32_t using Barrett reduction.
class Barrett {
  int32_t m;
  uint64_t r;

 public:
  Barrett(int32_t m) : m(m), r((uint64_t)(-m) / m + 1) {}

  // Barrett reduction: a % m.
  int32_t reduce(int64_t a) const {
    int64_t q = (__int128)a * r >> 64;
    a -= q * m;
    return a >= m ? a - m : a;
  }

  // Modular multiplication: (a * b) % m;
  // Assume that 0 <= a, b < m.
  int32_t mul(int32_t a, int32_t b) const { return reduce((int64_t)a * b); }
};

The implementation needs \(128\)-bit integers4.

Montgomery multiplication

The function of the Montgomery multiplication algorithm is very similar to that of the Barrett algorithm: it can likewise reduce the cost of modulo operations in modular integer arithmetic. Unlike the previous two algorithms, which both approximate the quotient, Montgomery multiplication maps all integers into the Montgomery space, where operations are relatively easy, thereby lowering the overall computational cost.

Let the modulus \(m\) be odd, and choose \(R = 2^k > m\). Then the Montgomery form corresponding to the congruence class \(a \bmod m\) is

\[ aR\bmod m. \]

Since \(R\perp m\), there is a bijection between the congruence class \(a \bmod m\) and its Montgomery form \(aR\bmod m\). Therefore, we can convert integers into Montgomery form, perform a number of operations modulo \(m\), and then convert the resulting Montgomery form back into an integer; the result is always correct.

Many modular integer operations can be done conveniently using the Montgomery form. We have just explained that to compare whether two congruence classes are the same, it suffices to compare their Montgomery forms. Moreover, since

\[ (a\pm b)R\bmod m = ((aR\bmod m)\pm(bR\bmod m)) \bmod{m}, \]

addition and subtraction of congruence classes correspond to addition and subtraction of their Montgomery forms. However, to compute the product of congruence classes, one cannot directly multiply the two Montgomery forms. Since

\[ (ab)R\bmod m = ((aR\bmod m)(bR\bmod m)R^{-1}) \bmod{m}, \]

when multiplying two Montgomery forms, the following Montgomery reduction operation must be applied to their product \(x\):

\[ \operatorname{REDC}: x \mapsto xR^{-1}\bmod m. \]

Using this operation, the Montgomery form of the product \(ab\) is \(\operatorname{REDC}((aR\bmod m)(bR\bmod m))\). The Montgomery reduction operation is the core operation of Montgomery multiplication:

  • Converting \(a\) to its Montgomery form is \(\operatorname{REDC}((a\bmod m)(R^2\bmod m))\).
  • Converting the Montgomery form of \(a\) back to \(a\bmod m\) is \(\operatorname{REDC}(aR\bmod m)\).
  • The Montgomery form corresponding to the modular inverse \(a^{-1}\bmod m\) is \(\operatorname{REDC}((aR\bmod m)^{-1}(R^3\bmod m))\).

Now we discuss how to implement the Montgomery reduction operation \(\operatorname{REDC}\). When computing \(\operatorname{REDC}(x)\), we always assume \(0 \le x < m^2\), which holds in all the cases above. Since \(R\perp m\), by Bézout's identity there exist integers \(R^{-1},m'\) such that

\[ RR^{-1} + mm' = 1. \]

Therefore, letting \(q=\lfloor xm' / R\rfloor\), we have

\[ \begin{aligned} xR^{-1} &= x\dfrac{1 - mm'}{R} \equiv \dfrac{x-xmm' + qmR}{R} = \dfrac{x - m(xm'\bmod R)}{R} \pmod{m}. \end{aligned} \]

Since \(0 \le x < m^2 < mR\) and \(0 \le xm'\bmod R < R\), we have

\[ -m < \dfrac{x - m(xm'\bmod R)}{R} < m. \]

That is, this quotient differs from \(xR^{-1}\bmod m\) by at most one \(m\). It suffices to add \(m\) when the quotient is less than zero to obtain \(\operatorname{REDC}(x)\). Computing this quotient needs only two integer multiplications, one integer subtraction and two bit operations (taking the modulo and dividing by \(R=2^k\), respectively). Therefore, the Montgomery reduction operation can be performed efficiently.

To perform Montgomery multiplication, a series of constants must be precomputed. First, Montgomery reduction uses \(m' = m^{-1}\bmod R\), which can be computed with the Newton–Hensel method introduced below. Second, when reducing various operations to Montgomery reduction, constants such as \(R^2\bmod m\) are also involved. To obtain it, compute \(R\bmod m\) once, and adding it to itself gives \(2R\bmod m\). Then, treating that as the Montgomery form of \(2\) and directly applying binary exponentiation, we get \(2^kR\bmod m = R^2\bmod m\).

As an example, an implementation of Montgomery multiplication for \(32\)-bit signed integers is as follows:

Reference implementation 
// Montgomery modular multiplication.
// The modulus m must be odd. The constant r is 2^32.
class Montgomery {
  int32_t m;
  uint32_t mm, r2;

 public:
  Montgomery(int32_t m) : m(m), mm(1), r2(-m) {
    // Compute mm as inv(m) mod r.
    for (int i = 0; i < 5; ++i) {
      mm *= 2 - mm * m;
    }
    // Compute r2 as r * r mod m.
    // If allowed to use modular operation for uint64_t, simply use:
    //   r2 = (uint64_t)(-m) % m;
    r2 %= m;
    r2 <<= 1;
    if (r2 >= (uint32_t)m) r2 -= m;
    for (int i = 0; i < 5; ++i) {
      r2 = mul(r2, r2);
    }
  }

  // Montgomery reduction: x * inv(r) % m.
  // Also used to transform x from Montgomery space to the normal space.
  int32_t reduce(int64_t x) {
    uint32_t u = (uint32_t)x * mm;
    int32_t ans = (x - (int64_t)m * u) >> 32;
    return ans < 0 ? ans + m : ans;
  }

  // Multiplication in Montgomery space: x * y * inv(r) % m.
  int32_t mul(int32_t x, int32_t y) { return reduce((int64_t)x * y); }

  // Transform x from the normal space to Montgomery space.
  int32_t init(int32_t x) { return mul(x, r2); }
};

Compared with implementing modular multiplication via Barrett reduction, the computation of Montgomery multiplication involves several steps: conversion, multiplication of Montgomery forms, inverse conversion, and so on. Therefore, only when the number of modular operations between the conversion and the inverse conversion is large enough can the cost of conversion and inverse conversion be amortized, yielding high overall efficiency. However, since the implementation of Montgomery multiplication only involves intermediate variables of length \(2\ell(m)\), it is more flexible to implement. For example, modular multiplication of \(32\)-bit integers needs only \(64\)-bit intermediate variables. So if a modular integer class is needed for all kinds of number-theoretic computations, Montgomery multiplication is more suitable.

Integer class modulo a power of 2

This section discusses the implementation of a modular integer class when the modulus is a power of \(2\). In this special case, division and modulo operations can be implemented with bit operations and are very efficient. Both Barrett reduction and Montgomery multiplication exploit this property of \(2^e\) as divisor and modulus to speed up computation. In particular, when the modulus is exactly a special number such as \(2^{32}\) or \(2^{64}\), a modular integer class can be implemented using unsigned integers of the corresponding width together with natural overflow, without any explicit modulo operation. Even when the modulus is not exactly of this kind, it can be reduced to the case of these special moduli. For example, when the modulus is \(2^{58}\), the intermediate computations can be done modulo \(2^{64}\), and the result is finally reduced modulo \(2^{58}\). Besides the convenient modulo, the other operations of the integer class modulo \(2^e\) also have many special implementations. This section focuses on the implementation of the inverse and exponentiation operations.

First, the inverse: given an odd \(a\) and a modulus \(m=2^e~(e > 2)\), we need to find \(a^{-1}\bmod m\). Common methods for finding an inverse include the extended Euclidean algorithm and the binary exponentiation method. The extended Euclidean algorithm involves taking modulo with respect to a general modulus; the ordinary binary exponentiation method needs to compute \(a^{\varphi(m)-1}\bmod{m}\), which requires \(\Theta(e)\) integer multiplications. A more efficient method is the Newton–Hensel method. Concretely, consider applying the following result:7

\[ ax \equiv 1 \pmod{2^e} \implies ax(2 - ax) \equiv 1\pmod{2^{2e}}. \]

According to this expression, starting from \(x = 1\) and repeatedly applying \(x \gets x(2-ax)\), we obtain \(a^{-1}\bmod m\) after \(\lceil\log_2 e\rceil\) iterations.

As an example, a reference implementation of the inverse of integers modulo \(2^{32}\) is as follows:

Reference implementation 
// Compute 1/v mod 2^32 for odd v.
uint32_t inv_mod_2_32(uint32_t v) {
  uint32_t x = 1;
  for (int i = 0; i != 5; ++i) {
    x *= 2 - v * x;
  }
  return x;
}

Next, exponentiation: given \(x,a,b\) and a modulus \(m=2^e~(e > 2)\), we need to find \(xa^b\bmod m\), where \(a\) is odd. From the analysis of the multiplicative structure of integers modulo \(2^e\), we know that \(a\) can always be written in the form \(\pm g^{\ell}\)8, and the minus sign appears if and only if \(a\equiv 3\pmod 4\). In that case, we can replace \(a\) by \(-a\) and multiply the final result by \((-1)^b\). Therefore, in what follows we may assume that \(a\equiv 1\pmod 4\) holds. Then the core idea of the algorithm is to write \(a\) in the form \(g^{L(a)}\bmod m\) and then compute the desired power as \(xg^{bL(a)}\bmod m\).

Computing \(L(a)\) means computing the discrete logarithm \(\operatorname{ind}_ga\). Notice that as long as \(a\equiv 1\pmod 4\), \(a\) can always be written in the following form:

\[ a \equiv (2^{e_1}+1)(2^{e_2}+1)\cdots(2^{e_s}+1) \pmod{m}, \]

where \(1 < e_1 < e_2 < \cdots < e_s < e\). This is because, by directly expanding this product, one finds that the second-lowest bit equal to \(1\) in the binary representation of \(a\) is exactly bit \(e_1\) (indices start from \(0\)), and from this the representation can be found recursively. By the properties of the discrete logarithm, we have

\[ 4L(a) \equiv 4L(2^{e_1}+1) + 4L(2^{e_2}+1) + \cdots + 4L(2^{e_s}+1) \pmod{m}. \]

Since the modulus of the discrete logarithm equals the order \(\delta_m(g)=2^{e-2}=m/4\), here we directly multiply the whole congruence by \(4\) to ensure that the computation can be carried out in the residue classes modulo \(m\). Thus, it suffices to precompute all \(4L(2^d+1)\) for \(1 < d < e\), and then the value of \(4L(a)\) can be computed quickly.

Conversely, from \(L(a)\) it is easy to obtain the value of \(g^{L(a)}\bmod{m}\). By the binomial theorem, for \(1 < d < e\) we have

\[ \begin{aligned} (2^d+1)^{2^{e-d}} \equiv 1 \pmod{m},\quad (2^d+1)^{2^{e-d-1}} \equiv 1 + 2^{e-1} \pmod{m}, \end{aligned} \]

so \(\delta_m(2^d+1) = 2^{e-d}\). By the properties of the order,

\[ \delta_m(2^d+1) = \dfrac{\delta_m(g)}{\gcd(\delta_m(g), \operatorname{ind}_g(2^d+1))}. \]

Therefore, \(\gcd(\delta_m(g), \operatorname{ind}_g(2^d+1)) = 2^{d-2}\). This shows that \(L(2^d+1) = \operatorname{ind}_g(2^d+1) = 2^{d-2}r\), where \(2\nmid r\). So the lowest bit equal to \(1\) in the binary representation of \(4L(2^d+1)\) is exactly bit \(d\) (indices start from \(0\)). Therefore, \(4L(a)\) can likewise be decomposed recursively, via its binary representation, into a sum of terms of the form \(4L(2^d+1)\). From this, the value of \(a\) is obtained.

In a concrete implementation, there are some points that can be further optimized. First, decomposing \(a\) into product form still requires division. It is more convenient to compute the decomposition of \(a^{-1}\), i.e. to find \(1 < e_1 < e_2 < \cdots < e_s < e\) such that

\[ a(2^{e_1}+1)(2^{e_2}+1)\cdots(2^{e_s}+1) \equiv 1 \pmod{m} \]

holds. Again, \(e_1\) is determined by finding the second-lowest bit equal to \(1\), but to cancel the factor \(2^{e_1}+1\) in \(a^{-1}\), it suffices to multiply \(a\) by \(2^{e_1}+1\), which can be done with bit operations. Also, since \(4L(a^{-1})=-4L(a)\), when accumulating \(4L(a)\) we need to use subtraction instead of addition. Second, for a specially chosen base \(g\), the iteration need not proceed to \(d = e-1\); it suffices to proceed to \(d = \lceil e/2\rceil - 1\). For this, we need to choose \(g\) such that

\[ 4L(2^{\lceil e/2\rceil} + 1) = 2^{\lceil e/2\rceil}. \]

For \(d \ge e / 2\), we have

\[ (2^d+1)^2 = 2^{2d} + 2^{d+1} + 1 \equiv 2^{d+1} + 1 \pmod{m}. \]

So, by induction starting from \(d = \lceil e/2\rceil\), we see that \(4L(2^d+1)=2^d\) holds for all \(d \ge e/2\). Furthermore, as long as \(e/2 \le e_1 < e_2 < \cdots < e_s < e\), we have

\[ (2^{e_1}+1)(2^{e_2}+1)\cdots(2^{e_s}+1) \equiv 1 + 2^{e_1} + 2^{e_2} + \cdots + 2^{e_s} \pmod{m} \]

and

\[ 4L((2^{e_1}+1)(2^{e_2}+1)\cdots(2^{e_s}+1)) = 2^{e_1} + 2^{e_2} + \cdots + 2^{e_s}. \]

Therefore, after processing all binary bits with \(d < e/2\), the discrete logarithm of the remaining part can be obtained directly without bit-by-bit computation. With the first optimization, the whole exponentiation needs only \(O(e)\) additions, subtractions and bit operations plus \(1\) multiplication; with the second optimization, about half of the additions, subtractions and bit operations can be saved, but \(1\) extra multiplication is needed.

As an example, a reference implementation of exponentiation of integers modulo \(2^{32}\) is as follows:

Reference implementation 
// Store 4L(a) for a = 2^d + 1, where L(a) is disc. log. base 388251981.
// The first two values are never used and thus set to zero.
// The base is chosen such that 4L(2^16+1) = 2^16.
constexpr uint32_t log_table[16] = {
    0x00000000, 0x00000000, 0xbba0267c, 0x49b9d1e8, 0xf0026f90, 0xd6e17e20,
    0xe78bf840, 0x039fe080, 0xaf7f8100, 0x60fe0200, 0xd1f80400, 0x23e00800,
    0x47801000, 0x8e002000, 0x18004000, 0x20008000,
};

// Compute 4L(v).
uint32_t log_mod_2_32(uint32_t x, uint32_t v) {
  for (int i = 2; i != 16; ++i) {
    if ((v >> i) & 1) {
      v += v << i;
      x -= log_table[i];
    }
  }
  x += v ^ 1;
  return x;
}

// Compute x*a for 4L(a) = v.
uint32_t exp_mod_2_32(uint32_t x, uint32_t v) {
  for (int i = 2; i != 16; ++i) {
    if ((v >> i) & 1) {
      x += x << i;
      v -= log_table[i];
    }
  }
  x *= v ^ 1;
  return x;
}

// Compute x*a^b for odd a.
uint32_t pow_odd_mod_2_32(uint32_t a, uint32_t b, uint32_t x) {
  if (a & 2) {
    a = -a;
    if (b & 1) {
      x = -x;
    }
  }
  return exp_mod_2_32(x, log_mod_2_32(0, a) * b);
}

// Compute x*a^b mod 2^32.
uint32_t pow_mod_2_32(uint32_t a, uint32_t b, uint32_t x = 1) {
  if (!a) return b == 0 ? x : 0;
  auto d = __builtin_ctz(a);
  if ((uint64_t)d * b >= 32) return 0;
  return pow_odd_mod_2_32(a >> d, b, x) << (d * b);
}

The precomputation of the discrete logarithms can be done with the Pohlig–Hellman algorithm, and the base \(g\) can be chosen as

\[ 5^{\operatorname{ind}_5(2^{\lceil e/2\rceil}+1)/2^{\lceil e/2\rceil - 2}}\bmod{2^e}. \]
