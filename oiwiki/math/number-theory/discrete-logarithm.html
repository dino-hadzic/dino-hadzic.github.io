Definicija

Predznanje: Red elementa i primitivni korijen.

Diskretni logaritam definira se slično logaritmu. Uzmimo pozitivan cijeli modul \(m\) koji ima primitivni korijen i neka je \(g\) jedan njegov primitivni korijen. Za cijeli broj \(a\) takav da je \((a,m)=1\) znamo da nužno postoji jedinstven cijeli broj \(0\leq k<\varphi(m)\) takav da je

\[ g^k\equiv a\pmod m \]

Taj \(k\) nazivamo diskretnim logaritmom po bazi \(g\) modulo \(m\) i pišemo \(k=\operatorname{ind}_g a\); kad nema opasnosti od zabune, možemo pisati \(\operatorname{ind} a\).

Očito je \(\operatorname{ind}_g 1=0\), \(\operatorname{ind}_g g=1\).

Svojstva

I svojstva diskretnog logaritma u mnogočemu nalikuju svojstvima logaritma.

Svojstva

Neka je \(g\) primitivni korijen modulo \(m\) i \((a,m)=(b,m)=1\). Tada:

  1. \(\operatorname{ind}_g(ab)\equiv\operatorname{ind}_g a+\operatorname{ind}_g b\pmod{\varphi(m)}\)

    Nadalje, \((\forall n\in\mathbf{N}),~~\operatorname{ind}_g a^n\equiv n\operatorname{ind}_g a\pmod{\varphi(m)}\)

  2. Ako je i \(g_1\) primitivni korijen modulo \(m\), onda je \(\operatorname{ind}_g a\equiv\operatorname{ind}_{g_1}a \cdot \operatorname{ind}_g g_1\pmod{\varphi(m)}\)

  3. \(a\equiv b\pmod m\iff \operatorname{ind}_g a=\operatorname{ind}_g b\)
Dokaz
  1. \(g^{\operatorname{ind}_g(ab)}\equiv ab\equiv g^{\operatorname{ind}_g a}g^{\operatorname{ind}_g b}\equiv g^{\operatorname{ind}_g a+\operatorname{ind}_g b}\pmod m\)

  2. Neka je \(x=\operatorname{ind}_{g_1}a\); tada je \(a\equiv g_1^x\pmod m\). Neka je još \(y=\operatorname{ind}_g g_1\); tada je \(g_1\equiv g^y\pmod m\).

    Stoga je \(a\equiv g^{xy}\pmod m\), tj. \(\operatorname{ind}_g a\equiv xy\equiv\operatorname{ind}_{g_1}a \cdot \operatorname{ind}_g g_1\pmod{\varphi(m)}\)

  3. Uočimo da

    \[ \begin{aligned} \operatorname{ind}_g a=\operatorname{ind}_g b&\iff \operatorname{ind}_g a\equiv\operatorname{ind}_g b\pmod{\varphi(m)}\\ &\iff g^{\operatorname{ind}_g a}\equiv g^{\operatorname{ind}_g b}\pmod m\\ &\iff a\equiv b\pmod m \end{aligned} \]

Algoritam baby-step giant-step

Za problem diskretnog logaritma još ne postoji klasični algoritam polinomnog vremena (veličina ulaza problema diskretnog logaritma jest broj bitova ulaznih podataka). U kriptografiji su na tome zasnovani mnogi asimetrični kriptosustavi, npr. Ed25519.

Na algoritamskim natjecanjima za rješavanje problema diskretnog logaritma često se koristi BSGS (baby-step giant-step). Formalno, za \(a,b,m\in\mathbf{Z}^+\) taj algoritam u vremenu \(O(\sqrt{m})\) rješava

\[ a^x \equiv b \pmod m \]

gdje je \(a\perp m\). Rješenje \(x\) jednadžbe zadovoljava \(0 \le x < m\). (Napomena: \(m\) ne mora biti prost.)

Opis algoritma

Neka je \(x = A \left \lceil \sqrt m \right \rceil - B\), gdje je \(0\le A,B \le \left \lceil \sqrt m \right \rceil\). Tada je \(a^{A\left \lceil \sqrt m \right \rceil -B} \equiv b \pmod m\), a nakon male preinake \(a^{A\left \lceil \sqrt m \right \rceil} \equiv ba^B \pmod m\).

Poznati su nam \(a,b\), pa možemo najprije izračunati sve vrijednosti \(ba^B\) s desne strane jednakosti, iterirajući po \(B\), i spremiti ih u hash/map; zatim redom računamo \(a^{A\left \lceil \sqrt m \right \rceil}\), iterirajući po \(A\), i tražimo postoji li jednaka vrijednost \(ba^B\); tako dobivamo sve \(x\), \(x=A \left \lceil \sqrt m \right \rceil - B\).

Uočimo da su \(A,B\) oba manji od \(\left \lceil \sqrt m \right \rceil\), pa je vremenska složenost \(\Theta\left (\sqrt m\right )\); uz map dolazi još faktor \(\log\).

Zašto se zahtijeva da su \(a\) i \(m\) relativno prosti

Uočimo da mi zapravo nalazimo \(A,B\), pa moramo osigurati da se iz \(a^{A\left \lceil \sqrt m \right \rceil} \equiv ba^B \pmod m\) može natrag zaključiti \(a^{A\left \lceil \sqrt m \right \rceil -B} \equiv b \pmod m\). Druga se kongruencija dobiva dijeljenjem obiju strana prve s \(a^B\), pa mora vrijediti \(a^B \perp m\), tj. \(a\perp m\).

Prošireni BSGS algoritam

Za \(a,b,m\in\mathbf{Z}^+\) rješavamo

\[ a^x\equiv b\pmod m \]

gdje \(a,m\) ne moraju biti relativno prosti.

Kad je \((a, m)=1\), \(a\) ima inverz modulo \(m\), pa se može primijeniti BSGS algoritam. Zato ćemo pokušati učiniti ih relativno prostima.

Konkretno, neka je \(d_1=(a, m)\). Ako \(d_1\nmid b\), izvorna jednadžba nema rješenja. U suprotnom podijelimo jednadžbu s \(d_1\) i dobijemo

\[ \frac{a}{d_1}\cdot a^{x-1}\equiv \frac{b}{d_1}\pmod{\frac{m}{d_1}} \]

Ako \(a\) i \(\frac{m}{d_1}\) još nisu relativno prosti, dijelimo opet: neka je \(d_2=\left(a, \frac{m}{d_1}\right)\). Ako \(d_2\nmid \frac{b}{d_1}\), jednadžba nema rješenja; inače dijelimo s \(d_2\) i dobivamo

\[ \frac{a^2}{d_1d_2}\cdot a^{x-2}≡\frac{b}{d_1d_2} \pmod{\frac{m}{d_1d_2}} \]

Na isti način nastavljamo provjeravati sve dok ne bude \(a\perp \dfrac{m}{d_1d_2\cdots d_k}\).

Označimo \(D=\prod_{i=1}^kd_i\); jednadžba tada poprima oblik:

\[ \frac{a^k}{D}\cdot a^{x-k}\equiv\frac{b}{D} \pmod{\frac{m}{D}} \]

Budući da je \(a\perp\dfrac{m}{D}\), slijedi \(\dfrac{a^k}{D}\perp \dfrac{m}{D}\). Tako \(\dfrac{a^k}{D}\) ima inverz, pa ga prebacimo na desnu stranu jednadžbe i dobijemo običan BSGS problem; riješimo ga za \(x-k\) i dodamo \(k\) – to je rješenje izvorne jednadžbe.

Napomena: nije isključeno da je rješenje manje ili jednako \(k\), pa prije uklanjanja faktora napravimo iteraciju u \(\Theta(k)\) koraka i izravno provjerimo \(a^i\equiv b \pmod m\); time taj slučaj izbjegavamo.

Brzi diskretni logaritam s pretprocesiranjem po rasponu vrijednosti

Vremenska složenost prethodnog BSGS algoritma iznosi \(O(\sqrt m)\) po upitu, što je neučinkovito kad je broj upita velik. Ako je modul u svakom upitu isti fiksni prost broj \(p\), imamo brz algoritam zasnovan na pretprocesiranju po rasponu vrijednosti.

Već znamo da je \(\operatorname{ind}_g(ab)\equiv\operatorname{ind}_g a+\operatorname{ind}_g b\pmod{p-1}\), pa diskretne logaritme BSGS algoritmom možemo računati samo za proste brojeve, a diskretni logaritam složenog broja tom se formulom svodi na zbroj nekoliko već poznatih diskretnih logaritama prostih brojeva. Složenost tada još nije dobra, pa razmotrimo pretprocesiranje samo dijela diskretnih logaritama; konkretno, pretprocesiramo diskretne logaritme od \(1\) do \(L = \lfloor\sqrt p\rfloor + 1\). Primijetimo da duljina bloka \(B\) u BSGS-u sada ne smije biti \(O(\sqrt{L})\), jer je složenost pretprocesiranja u BSGS-u (umetanje u hash tablicu) \(O(B)\), a upita je ukupno \(O(\pi(L))\), pa je ukupna vremenska složenost \(O\left(B+\dfrac{\pi(L)p}{B}\right)\); optimalno je tek \(B=O(\sqrt{\pi(L)p})\). Prema teoremu o prostim brojevima \(\pi(n)\sim\dfrac{n}{\log n}\), pa se ukupna složenost pretprocesiranja može uravnotežiti na \(O\left(\dfrac{p^{3/4}}{\log^{1/2} p}\right)\).

Slijedi kako izračunati odgovor. Pretpostavimo da trenutačno tražimo \(\operatorname{ind}_g y\). Ako je \(y\le L\), odgovor izravno vraćamo; inače neka je \(p=vy+r\), pa je \(v=\left\lfloor\dfrac{p}{y}\right\rfloor<L\), \(r=p\bmod y\), \(y=\dfrac{p-r}{v}\), odakle

\[ \begin{aligned} \operatorname{ind}_g y &\equiv \operatorname{ind}_g (p-r)-\operatorname{ind}_g v\\ &\equiv \operatorname{ind}_g (-r)-\operatorname{ind}_g v\\ &\equiv \operatorname{ind}_g (p-1)+\operatorname{ind}_g r-\operatorname{ind}_g v \pmod{p-1}. \end{aligned} \]

Uočimo da je \(\operatorname{ind}_g (p-1)=(p-1)/2\), pa je dovoljno rekurzivno izračunati diskretni logaritam od \(r\).

Možemo razmotriti i drugi zapis broja \(y\): uočimo da je \(p=vy+r=(v+1)y+r-y\), pa je \(y=\dfrac{p-r+y}{v+1}\), odakle

\[ \operatorname{ind}_g y\equiv \operatorname{ind}_g (y-r)-\operatorname{ind}_g (v+1) \pmod{p-1}. \]

Vrijedi \(v+1 \le L\), pa je dovoljno rekurzivno izračunati diskretni logaritam od \(y-r\).

Kombiniranjem tih dvaju načina računanja imamo \(\min\{r,y-r\}\le \dfrac{y}{2}\), pa rekurzivnim računanjem manjeg od njih postižemo složenost upita \(O(\log p)\).

Time smo dobili algoritam vremenske složenosti \(O\left(\dfrac{p^{3/4}}{\log^{1/2} p}\right)-O(\log p)\).

Luogu11175【模板】基于值域预处理的快速离散对数 (predložak: brzi diskretni logaritam s pretprocesiranjem po rasponu vrijednosti) 
#include <cmath>
#include <iostream>
#include <unordered_map>
using namespace std;

const int N = 1'000'000;  // sqrt(P * sqrt(P) / ln(P))

unordered_map<int, int> M;
int Lg[N], p[N], t;
bool vis[N];
int P, g, B, sq, LP_1, inv;

int fadd(int x, int y, int P) {
  x += y;
  if (x >= P) x -= P;
  return x;
}

int fsub(int x, int y, int P) {
  x -= y;
  if (x < 0) x += P;
  return x;
}

int fmul(int x, int y, int P) { return 1ll * x * y % P; }

int qpow(int x, int y) {
  int ans = 1;
  while (y) {
    if (y & 1) ans = fmul(ans, x, P);
    x = fmul(x, x, P);
    y >>= 1;
  }
  return ans;
}

int calc(int x) {
  int s = x;
  for (int i = 0; i <= P / B; ++i) {
    if (M.find(s) != M.end()) return i * B + M[s];
    s = fmul(s, inv, P);
  }
  return -1;
}

void init() {
  int s = 1;
  for (int i = 0; i < B; ++i) {
    if (M.find(s) != M.end()) break;
    M[s] = i, s = fmul(s, g, P);
  }
  inv = qpow(qpow(g, B), P - 2);
  for (int i = 2; i <= sq; ++i) {
    if (!vis[i]) {
      p[++t] = i;
      Lg[i] = calc(i);
    }
    for (int j = 1; j <= t && p[j] * i <= sq; ++j) {
      vis[p[j] * i] = true;
      Lg[p[j] * i] = fadd(Lg[p[j]], Lg[i], P - 1);
      if (i % p[j] == 0) break;
    }
  }
}

int solve(int y) {
  if (y <= sq) return Lg[y];
  int v = P / y, r = P % y;
  if (r < y - r) return fadd(fsub(solve(r), Lg[v], P - 1), LP_1, P - 1);
  return fsub(solve(y - r), Lg[v + 1], P - 1);
}

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  cin >> P >> g;
  sq = sqrt(P) + 1;
  B = sqrt(1ll * P * sqrt(P) / log(P));
  init();
  LP_1 = (P - 1) / 2;  // g ^ LP_1 = P - 1 (mod P)
  int T;
  cin >> T;
  while (T--) {
    int x;
    cin >> x;
    cout << solve(x) << '\n';
  }
  return 0;
}

Definition

Prerequisites: Multiplicative order and primitive roots.

The discrete logarithm is defined similarly to the logarithm. Take a positive integer modulus \(m\) that has a primitive root, and let \(g\) be one of its primitive roots. For an integer \(a\) with \((a,m)=1\), we know that there must exist a unique integer \(0\leq k<\varphi(m)\) such that

\[ g^k\equiv a\pmod m \]

We call this \(k\) the discrete logarithm to the base \(g\) modulo \(m\), written \(k=\operatorname{ind}_g a\); when there is no risk of confusion, it may be written \(\operatorname{ind} a\).

Clearly \(\operatorname{ind}_g 1=0\), \(\operatorname{ind}_g g=1\).

Properties

The properties of the discrete logarithm also resemble those of the logarithm in many ways.

Properties

Let \(g\) be a primitive root modulo \(m\) and \((a,m)=(b,m)=1\). Then:

  1. \(\operatorname{ind}_g(ab)\equiv\operatorname{ind}_g a+\operatorname{ind}_g b\pmod{\varphi(m)}\)

    Furthermore, \((\forall n\in\mathbf{N}),~~\operatorname{ind}_g a^n\equiv n\operatorname{ind}_g a\pmod{\varphi(m)}\)

  2. If \(g_1\) is also a primitive root modulo \(m\), then \(\operatorname{ind}_g a\equiv\operatorname{ind}_{g_1}a \cdot \operatorname{ind}_g g_1\pmod{\varphi(m)}\)

  3. \(a\equiv b\pmod m\iff \operatorname{ind}_g a=\operatorname{ind}_g b\)
Proof
  1. \(g^{\operatorname{ind}_g(ab)}\equiv ab\equiv g^{\operatorname{ind}_g a}g^{\operatorname{ind}_g b}\equiv g^{\operatorname{ind}_g a+\operatorname{ind}_g b}\pmod m\)

  2. Let \(x=\operatorname{ind}_{g_1}a\); then \(a\equiv g_1^x\pmod m\). Also let \(y=\operatorname{ind}_g g_1\); then \(g_1\equiv g^y\pmod m\).

    Hence \(a\equiv g^{xy}\pmod m\), i.e. \(\operatorname{ind}_g a\equiv xy\equiv\operatorname{ind}_{g_1}a \cdot \operatorname{ind}_g g_1\pmod{\varphi(m)}\)

  3. Note that

    \[ \begin{aligned} \operatorname{ind}_g a=\operatorname{ind}_g b&\iff \operatorname{ind}_g a\equiv\operatorname{ind}_g b\pmod{\varphi(m)}\\ &\iff g^{\operatorname{ind}_g a}\equiv g^{\operatorname{ind}_g b}\pmod m\\ &\iff a\equiv b\pmod m \end{aligned} \]

Baby-step giant-step algorithm

At present there is still no polynomial-time classical algorithm for the discrete logarithm problem (the input size of the discrete logarithm problem is the number of bits of the input data). In cryptography, many asymmetric encryption schemes have been designed based on this fact, such as Ed25519.

In competitive programming, BSGS (baby-step giant-step) is commonly used to solve the discrete logarithm problem. Formally, for \(a,b,m\in\mathbf{Z}^+\), the algorithm solves

\[ a^x \equiv b \pmod m \]

in \(O(\sqrt{m})\) time, where \(a\perp m\). The solution \(x\) of the equation satisfies \(0 \le x < m\). (Note that \(m\) is not necessarily prime.)

Algorithm description

Let \(x = A \left \lceil \sqrt m \right \rceil - B\), where \(0\le A,B \le \left \lceil \sqrt m \right \rceil\). Then \(a^{A\left \lceil \sqrt m \right \rceil -B} \equiv b \pmod m\), and after a small rearrangement, \(a^{A\left \lceil \sqrt m \right \rceil} \equiv ba^B \pmod m\).

We know \(a,b\), so we can first compute all values of \(ba^B\) on the right-hand side by enumerating \(B\) and store them in a hash/map; then we compute \(a^{A\left \lceil \sqrt m \right \rceil}\) one by one, enumerating \(A\), and look for an equal \(ba^B\); in this way we obtain all \(x\), \(x=A \left \lceil \sqrt m \right \rceil - B\).

Note that \(A,B\) are both less than \(\left \lceil \sqrt m \right \rceil\), so the time complexity is \(\Theta\left (\sqrt m\right )\); using a map adds an extra \(\log\) factor.

Why \(a\) and \(m\) must be coprime

Note that what we actually find are \(A,B\), and we need to make sure that from \(a^{A\left \lceil \sqrt m \right \rceil} \equiv ba^B \pmod m\) we can go back to \(a^{A\left \lceil \sqrt m \right \rceil -B} \equiv b \pmod m\). The latter is obtained from the former by dividing both sides by \(a^B\), so we must have \(a^B \perp m\), i.e. \(a\perp m\).

Extended BSGS algorithm

For \(a,b,m\in\mathbf{Z}^+\), solve

\[ a^x\equiv b\pmod m \]

where \(a,m\) are not necessarily coprime.

When \((a, m)=1\), \(a\) has an inverse modulo \(m\), so the BSGS algorithm can be used. So we try to make them coprime.

Specifically, let \(d_1=(a, m)\). If \(d_1\nmid b\), the original equation has no solution. Otherwise we divide the equation by \(d_1\) and get

\[ \frac{a}{d_1}\cdot a^{x-1}\equiv \frac{b}{d_1}\pmod{\frac{m}{d_1}} \]

If \(a\) and \(\frac{m}{d_1}\) are still not coprime, we divide again: let \(d_2=\left(a, \frac{m}{d_1}\right)\). If \(d_2\nmid \frac{b}{d_1}\), the equation has no solution; otherwise we divide by \(d_2\) and get

\[ \frac{a^2}{d_1d_2}\cdot a^{x-2}≡\frac{b}{d_1d_2} \pmod{\frac{m}{d_1d_2}} \]

Similarly, we keep checking in this way until \(a\perp \dfrac{m}{d_1d_2\cdots d_k}\).

Let \(D=\prod_{i=1}^kd_i\); the equation then becomes:

\[ \frac{a^k}{D}\cdot a^{x-k}\equiv\frac{b}{D} \pmod{\frac{m}{D}} \]

Since \(a\perp\dfrac{m}{D}\), it follows that \(\dfrac{a^k}{D}\perp \dfrac{m}{D}\). So \(\dfrac{a^k}{D}\) has an inverse, and we move it to the right-hand side of the equation, which gives an ordinary BSGS problem; solving for \(x-k\) and adding \(k\) gives the solution of the original equation.

Note that a solution less than or equal to \(k\) is not ruled out, so before removing the factors we do a \(\Theta(k)\) enumeration and directly check \(a^i\equiv b \pmod m\); this avoids that case.

Fast discrete logarithm with value-range preprocessing

The BSGS algorithm above has a time complexity of \(O(\sqrt m)\) per query, which is inefficient when the number of queries is large. If the modulus of every query is the same fixed prime \(p\), we have a fast algorithm based on preprocessing over the value range.

We already know that \(\operatorname{ind}_g(ab)\equiv\operatorname{ind}_g a+\operatorname{ind}_g b\pmod{p-1}\), so we can compute discrete logarithms with the BSGS algorithm only for primes, and the discrete logarithm of a composite number can be converted by this formula into a sum of several already known discrete logarithms of primes. The complexity is still not good at this point, so we consider preprocessing only part of the discrete logarithms; specifically, we preprocess the discrete logarithms from \(1\) to \(L = \lfloor\sqrt p\rfloor + 1\). Note that the BSGS block length \(B\) cannot be \(O(\sqrt{L})\) here, because the preprocessing part of BSGS (inserting into the hash table) has complexity \(O(B)\), while a total of \(O(\pi(L))\) queries are needed, so the total time complexity is \(O\left(B+\dfrac{\pi(L)p}{B}\right)\), and only \(B=O(\sqrt{\pi(L)p})\) is optimal. By the prime number theorem \(\pi(n)\sim\dfrac{n}{\log n}\), so the total preprocessing time complexity can be balanced to \(O\left(\dfrac{p^{3/4}}{\log^{1/2} p}\right)\).

Next, how to compute the answer. Suppose we currently want \(\operatorname{ind}_g y\). If \(y\le L\), we return it directly; otherwise let \(p=vy+r\), so \(v=\left\lfloor\dfrac{p}{y}\right\rfloor<L\), \(r=p\bmod y\), \(y=\dfrac{p-r}{v}\), and therefore

\[ \begin{aligned} \operatorname{ind}_g y &\equiv \operatorname{ind}_g (p-r)-\operatorname{ind}_g v\\ &\equiv \operatorname{ind}_g (-r)-\operatorname{ind}_g v\\ &\equiv \operatorname{ind}_g (p-1)+\operatorname{ind}_g r-\operatorname{ind}_g v \pmod{p-1}. \end{aligned} \]

Note that \(\operatorname{ind}_g (p-1)=(p-1)/2\), so it suffices to recursively compute the discrete logarithm of \(r\).

We can also consider another expression for \(y\): note that \(p=vy+r=(v+1)y+r-y\), so \(y=\dfrac{p-r+y}{v+1}\), and therefore

\[ \operatorname{ind}_g y\equiv \operatorname{ind}_g (y-r)-\operatorname{ind}_g (v+1) \pmod{p-1}. \]

We have \(v+1 \le L\), so it suffices to recursively compute the discrete logarithm of \(y-r\).

Combining these two ways of computing, we have \(\min\{r,y-r\}\le \dfrac{y}{2}\), so recursing on the smaller one achieves a query complexity of \(O(\log p)\).

Thus we have obtained an algorithm with time complexity \(O\left(\dfrac{p^{3/4}}{\log^{1/2} p}\right)-O(\log p)\).

  int ans = 1;
  while (y) {
    if (y & 1) ans = fmul(ans, x, P);
    x = fmul(x, x, P);
    y >>= 1;
  }
  return ans;
}

int calc(int x) {
  int s = x;
  for (int i = 0; i <= P / B; ++i) {
    if (M.find(s) != M.end()) return i * B + M[s];
    s = fmul(s, inv, P);
  }
  return -1;
}

void init() {
  int s = 1;
  for (int i = 0; i < B; ++i) {
    if (M.find(s) != M.end()) break;
    M[s] = i, s = fmul(s, g, P);
  }
  inv = qpow(qpow(g, B), P - 2);
  for (int i = 2; i <= sq; ++i) {
    if (!vis[i]) {
      p[++t] = i;
      Lg[i] = calc(i);
    }
    for (int j = 1; j <= t && p[j] * i <= sq; ++j) {
      vis[p[j] * i] = true;
      Lg[p[j] * i] = fadd(Lg[p[j]], Lg[i], P - 1);
      if (i % p[j] == 0) break;
    }
  }
}

int solve(int y) {
  if (y <= sq) return Lg[y];
  int v = P / y, r = P % y;
  if (r < y - r) return fadd(fsub(solve(r), Lg[v], P - 1), LP_1, P - 1);
  return fsub(solve(y - r), Lg[v + 1], P - 1);
}

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  cin >> P >> g;
  sq = sqrt(P) + 1;
  B = sqrt(1ll * P * sqrt(P) / log(P));
  init();
  LP_1 = (P - 1) / 2;  // g ^ LP_1 = P - 1 (mod P)
  int T;
  cin >> T;
  while (T--) {
    int x;
    cin >> x;
    cout << solve(x) << '\n';
  }
  return 0;
}
