Definicija

Najveći zajednički djelitelj (engl. Greatest Common Divisor) obično se skraćeno označava gcd.

Zajednički djelitelj skupa cijelih brojeva jest broj koji je istodobno djelitelj svakog broja iz tog skupa. \(\pm 1\) je zajednički djelitelj svakog skupa cijelih brojeva.

Najveći zajednički djelitelj skupa cijelih brojeva jest najveći među svim njihovim zajedničkim djeliteljima.

Za cijele brojeve \(a,b\) koji nisu oba \(0\) njihov najveći zajednički djelitelj označavamo \(\gcd(a,b)\), a kad nema opasnosti od zabune skraćeno \((a,b)\).

Za cijele brojeve \(a_1,\dots,a_n\) koji nisu svi \(0\) njihov najveći zajednički djelitelj označavamo \(\gcd(a_1,\dots,a_n)\), a kad nema opasnosti od zabune skraćeno \((a_1,\dots,a_n)\).

Svojstva najvećeg zajedničkog djelitelja i najmanjeg zajedničkog višekratnika vidi u Osnovama teorije brojeva.

Kako, dakle, izračunati najveći zajednički djelitelj? Razmotrimo najprije slučaj dvaju brojeva.

Euklidov algoritam

Postupak

Ako su nam poznata dva broja \(a\) i \(b\), kako izračunati njihov najveći zajednički djelitelj?

Bez smanjenja općenitosti neka je \(a > b\).

Uočavamo: ako je \(b\) djelitelj od \(a\), onda je \(b\) njihov najveći zajednički djelitelj. Razmotrimo sada slučaj kada dijeljenje nije bez ostatka, tj. \(a = b \times q + r\), gdje je \(r < b\).

Dokazom možemo dobiti \(\gcd(a,b)=\gcd(b,a \bmod b)\); postupak je sljedeći:

Dokaz

Neka je \(a=bk+c\); očito je \(c=a \bmod b\). Neka \(d \mid a,~d \mid b\); tada je \(c=a-bk, \frac{c}{d}=\frac{a}{d}-\frac{b}{d}k\).

Iz desne strane vidimo da je \(\frac{c}{d}\) cijeli broj, tj. \(d \mid c\), pa je svaki zajednički djelitelj od \(a,b\) ujedno zajednički djelitelj od \(b,a \bmod b\).

Treba dokazati i obrat:

Neka \(d \mid b,~d\mid (a \bmod b)\); kao i prije dobivamo \(\frac{a\bmod b}{d}=\frac{a}{d}-\frac{b}{d}k,~\frac{a\bmod b}{d}+\frac{b}{d}k=\frac{a}{d}\).

Budući da je lijeva strana očito cijeli broj, i \(\frac{a}{d}\) je cijeli broj, tj. \(d \mid a\), pa je svaki zajednički djelitelj od \(b,a\bmod b\) ujedno zajednički djelitelj od \(a,b\).

Budući da su zajednički djelitelji obaju parova isti, isti su i najveći zajednički djelitelji.

Time dobivamo formulu \(\gcd(a,b)=\gcd(b,a\bmod b)\)

Budući da smo dobili \(\gcd(a, b) = \gcd(b, r)\), pri čemu se veličina dvaju brojeva ne povećava, dobili smo rekurzivni postupak za najveći zajednički djelitelj dvaju brojeva.

Implementacija

// Version 1
int gcd(int a, int b) {
  if (b == 0) return a;
  return gcd(b, a % b);
}

// Version 2
int gcd(int a, int b) { return b == 0 ? a : gcd(b, a % b); }

// Version 1
public int gcd(int a, int b) {
    if (b == 0) return a;
    return gcd(b, a % b);
}

// Version 2
public int gcd(int a, int b) {
    return b == 0 ? a : gcd(b, a % b);
}

def gcd(a, b):
    if b == 0:
        return a
    return gcd(b, a % b)

Rekurzija ide do slučaja b == 0 (tj. a % b == 0 u prethodnom koraku) i tada vraća vrijednost.

Na temelju gornjeg rekurzivnog postupka možemo napisati i iterativni:

int gcd(int a, int b) {
  while (b != 0) {
    int tmp = a;
    a = b;
    b = tmp % b;
  }
  return a;
}

public int gcd(int a, int b) {
    while(b != 0) {
        int tmp = a;
        a = b;
        b = tmp % b;
    }
    return a;
}

def gcd(a, b):
    while b != 0:
        a, b = b, a % b
    return a

Svi gornji algoritmi mogu se nazvati Euklidovim algoritmom (Euclidean algorithm).

Osim toga, u C++17 možemo koristiti std::gcd i std::lcm iz zaglavlja <numeric> za računanje najvećeg zajedničkog djelitelja i najmanjeg zajedničkog višekratnika.

Napomena

U nekim prevoditeljima u C++14 najveći zajednički djelitelj može se računati funkcijom std::__gcd(a,b), ali ona je samo privatna pomoćna funkcija za std::rotate.1Korištenje te funkcije može dovesti do neočekivanih problema, pa se u pravilu ne preporučuje.

Ako dva broja \(a\) i \(b\) zadovoljavaju \(\gcd(a, b) = 1\), kažemo da su \(a\) i \(b\) relativno prosti.

Svojstva

Koliko je Euklidov algoritam vremenski učinkovit? U nastavku dokazujemo da je, kad su ulaz dva binarna cijela broja duljine \(n\), vremenska složenost Euklidova algoritma \(O(n)\). (Drugim riječima, uz uobičajenu pretpostavku da su \(a, b\) istog reda veličine, vremenska je složenost \(O(\log\max(a, b))\).)

Dokaz

Kad računamo \(\gcd(a,b)\), susrećemo dva slučaja:

  • \(a < b\); tada je \(\gcd(a,b)=\gcd(b,a)\);
  • \(a \geq b\); tada je \(\gcd(a,b)=\gcd(b,a \bmod b)\), a uzimanje ostatka od \(a\) barem prepolovi \(a\). To znači da se ovaj korak može dogoditi najviše \(O(\log a) = O(n)\) puta.

Nakon prvog slučaja sigurno slijedi drugi slučaj, pa se prvi slučaj događa ne više puta od drugoga.

Stoga rezultat dobivamo nakon najviše \(O(n)\) rekurzivnih poziva.

Zapravo, ako Euklidovim algoritmom pokušamo izračunati najveći zajednički djelitelj dvaju susjednih članova Fibonaccijeva niza, algoritam dostiže najgoru složenost.

Metoda uzastopnog oduzimanja (更相减损术)

Uzimanje ostatka kod velikih cijelih brojeva ima veliku vremensku složenost, a zbrajanje i oduzimanje malu. Za velike cijele brojeve najveći zajednički djelitelj možemo izračunati zbrajanjem i oduzimanjem umjesto množenjem i dijeljenjem.

Postupak

Zadani su brojevi \(a\) i \(b\); tražimo \(\gcd(a,b)\).

Bez smanjenja općenitosti neka je \(a \ge b\). Ako je \(a = b\), onda je \(\gcd(a,b)=a=b\). Inače, \(\forall d\mid a, d\mid b\) može se dokazati \(d\mid a-b\).

Stoga su svi zajednički djelitelji od \(a\) i \(b\) ujedno zajednički djelitelji od \(a-b\) i \(b\), pa je \(\gcd(a,b) = \gcd(a-b, b)\).

Optimizacija: Steinov algoritam

Ako je \(a\gg b\), složenost \(O(n)\) metode uzastopnog oduzimanja dostiže najgori slučaj.

Razmotrimo optimizaciju: ako \(2\mid a,2\mid b\), onda je \(\gcd(a,b) = 2\gcd\left(\dfrac a2, \dfrac b2\right)\).

Inače, ako \(2\mid a\) (slučaj \(2\mid b\) analogno), budući da je slučaj \(2\mid b\) već razmotren, vrijedi \(2 \nmid b\). Stoga je \(\gcd(a,b)=\gcd\left(\dfrac a2,b\right)\).

Vremenska složenost optimiziranog algoritma (tj. Steinova algoritma) je \(O(\log n)\).

Dokaz

Ako \(2\mid a\) ili \(2\mid b\), svaki rekurzivni korak barem jedan od \(a,b\) prepolovi.

Inače \(2\mid a-b\), čime se vraćamo na prethodni slučaj.

Algoritam ima najviše \(O(\log n)\) rekurzivnih poziva.

Implementacija

Predložak za velike brojeve vidi u Aritmetici velikih brojeva.

Za velike brojeve treba implementirati: oduzimanje, usporedbu, pomak ulijevo, pomak udesno (mogu se zamijeniti množenjem/dijeljenjem malim brojem) i broj nula na kraju binarnog zapisa (može se izračunati grubom silom provjerom parnosti).

C++ 
Big gcd(Big a, Big b) {
  if (a == 0) return b;
  if (b == 0) return a;
  // bilježimo koliko se puta 2 pojavljuje kao zajednički faktor od a i b; countr_zero je broj nula na kraju binarnog zapisa
  int atimes = countr_zero(a);
  int btimes = countr_zero(b);
  int mintimes = min(atimes, btimes);
  a >>= atimes;
  for (;;) {
    // dvojke iz zajedničkih faktora od a i b već su obrađene, pa a dalje ne može biti paran
    b >>= btimes;
    // osiguravamo a<=b
    if (a > b) swap(a, b);
    b -= a;
    if (b == 0) break;
    btimes = countr_zero(b);
  }
  return a << mintimes;
}

Gornji kod slijedi implementacije C++17 std::gcd u libstdc++ i MSVC. U rasponu tipova unsigned int i unsigned long long, ako se countr_zero može izračunati vrlo brzo, Steinov je algoritam brži od Euklidova, a inače može biti i sporiji od Euklidova.

O funkciji countr_zero
  1. gcc ima ugrađene funkcije __builtin_ctz (32-bitnu) i __builtin_ctzll (64-bitnu) koje mogu zamijeniti countr_zero u gornjem kodu;
  2. Od C++20 zaglavlje <bit> sadrži std::countr_zero;
  3. Ako ne želite koristiti funkcije izvan standardne knjižnice, a ne možete koristiti standard C++20, sljedeći je kod implementacija koja u modelu Word-RAM with multiplication nakon pretprocesiranja radi u \(O(1)\):
constexpr int loghash[64] = {0,  32, 48, 56, 60, 62, 63, 31, 47, 55, 59, 61, 30,
                             15, 39, 51, 57, 28, 46, 23, 43, 53, 58, 29, 14, 7,
                             35, 49, 24, 44, 54, 27, 45, 22, 11, 37, 50, 25, 12,
                             38, 19, 41, 52, 26, 13, 6,  3,  33, 16, 40, 20, 42,
                             21, 10, 5,  34, 17, 8,  36, 18, 9,  4,  2,  1};

int countr_zero(unsigned long long x) {
  return loghash[(x & -x) * 0x9150D32D8EB9EFC0Ui64 >> 58];
}

Kod velikih brojeva, ako je implementacija slična bitsetu, uz gornju implementaciju countr_zero to se može obaviti u vremenskoj složenosti O(n / w). Ako pak nije zgodno dijeliti po binarnim bitovima, najveću potenciju broja \(2\) koja dijeli broj možemo odrediti samo grubom silom, a vremenska složenost ovisi o implementaciji. Na primjer:

// binarni Big u little-endian poretku; mora se moći proći kroz svaki element
int countr_zero(Big a) {
  int ans = 0;
  for (auto x : a) {
    if (x != 0) {
      ans += 32;  // broj bitova tipa podataka jednog elementa
    } else {
      return ans + countr_zero(x);
    }
  }
  return ans;
}

// izračun grubom silom; ako se koristi, preporučuje se ugraditi ga izravno u gcd radi bolje konstante
int countr_zero(Big a) {
  int ans = 0;
  while ((a & 1) == 0) {
    a >>= 1;
    ++ans;
  }
  return ans;
}

Najveći zajednički djelitelj više brojeva

Kako pak izračunati najveći zajednički djelitelj više brojeva? Odgovor je očito djelitelj svakog od brojeva, pa je sigurno i djelitelj svaka dva susjedna broja. Indukcijom se može dokazati da uzimanje dvaju brojeva, računanje njihova rezultata i vraćanje tog rezultata natrag ne utječe na traženi odgovor.

Najmanji zajednički višekratnik

Sada ćemo pokazati kako izračunati najmanji zajednički višekratnik (Least Common Multiple, LCM).

Definicija

Zajednički višekratnik skupa cijelih brojeva jest broj koji je istodobno višekratnik svakog broja iz tog skupa. 0 je zajednički višekratnik svakog skupa cijelih brojeva.

Najmanji zajednički višekratnik skupa cijelih brojeva jest najmanji među svim pozitivnim zajedničkim višekratnicima.

Za cijele brojeve \(a,b\) njihov najmanji zajednički višekratnik označavamo \(\operatorname{lcm}(a,b)\), a kad nema opasnosti od zabune skraćeno \([a,b]\).

Za cijele brojeve \(a_1,\dots,a_n\) njihov najmanji zajednički višekratnik označavamo \(\operatorname{lcm}(a_1,\dots,a_n)\), a kad nema opasnosti od zabune skraćeno \([a_1,\dots,a_n]\).

Dva broja

Neka je \(a = p_1^{k_{a_1}}p_2^{k_{a_2}} \cdots p_s^{k_{a_s}}\), \(b = p_1^{k_{b_1}}p_2^{k_{b_2}} \cdots p_s^{k_{b_s}}\)

Uočavamo da je za \(a\) i \(b\) njihov najveći zajednički djelitelj jednak

\(p_1^{\min(k_{a_1}, k_{b_1})}p_2^{\min(k_{a_2}, k_{b_2})} \cdots p_s^{\min(k_{a_s}, k_{b_s})}\)

a najmanji zajednički višekratnik jednak

\(p_1^{\max(k_{a_1}, k_{b_1})}p_2^{\max(k_{a_2}, k_{b_2})} \cdots p_s^{\max(k_{a_s}, k_{b_s})}\)

Budući da je \(k_a + k_b = \max(k_a, k_b) + \min(k_a, k_b)\)

dobivamo zaključak \(\gcd(a, b) \times \operatorname{lcm}(a, b) = a \times b\)

Da bismo izračunali najmanji zajednički višekratnik dvaju brojeva, dovoljno je najprije izračunati najveći zajednički djelitelj.

Više brojeva

Vidimo da je, kad izračunamo \(\gcd\) dvaju brojeva, računanje najmanjeg zajedničkog višekratnika složenosti \(O(1)\). Za više brojeva zapravo nije potrebno računati zajednički najveći zajednički djelitelj pa onda dalje obrađivati; najizravniji je način ovaj: kao što pri računanju \(\gcd\) više brojeva, nakon što izračunamo \(\gcd\) dvaju brojeva, rezultat vraćamo u niz i nastavljamo s preostalim brojevima, tako i ovdje, analogno, u niz izravno stavimo najmanji zajednički višekratnik.

Prošireni Euklidov algoritam

Prošireni Euklidov algoritam (Extended Euclidean algorithm, EXGCD) često se koristi za nalaženje jednog rješenja jednadžbe \(ax+by=\gcd(a,b)\).

Postupak

Neka je

\(ax_1+by_1=\gcd(a,b)\)

\(bx_2+(a\bmod b)y_2=\gcd(b,a\bmod b)\)

Po Euklidovu teoremu: \(\gcd(a,b)=\gcd(b,a\bmod b)\)

pa je \(ax_1+by_1=bx_2+(a\bmod b)y_2\)

Osim toga, \(a\bmod b=a-(\lfloor\frac{a}{b}\rfloor\times b)\)

pa je \(ax_1+by_1=bx_2+(a-(\lfloor\frac{a}{b}\rfloor\times b))y_2\)

\(ax_1+by_1=ay_2+bx_2-\lfloor\frac{a}{b}\rfloor\times by_2=ay_2+b(x_2-\lfloor\frac{a}{b}\rfloor y_2)\)

Budući da je \(a=a,b=b\), slijedi \(x_1=y_2,y_1=x_2-\lfloor\frac{a}{b}\rfloor y_2\)

Uvrštavamo \(x_2,y_2\) rekurzivno sve dok \(b\) ne postane \(0\), kada je \(x=1,y=0\), a zatim se vraćamo natrag i računamo rješenje.

Implementacija

int Exgcd(int a, int b, int &x, int &y) {
  if (!b) {
    x = 1;
    y = 0;
    return a;
  }
  int d = Exgcd(b, a % b, x, y);
  int t = x;
  x = y;
  y = t - (a / b) * y;
  return d;
}

def Exgcd(a, b):
    if b == 0:
        return a, 1, 0
    d, x, y = Exgcd(b, a % b)
    return d, y, x - (a // b) * y

Funkcija vraća \(\gcd\), a usput računa \(x,y\).

Analiza raspona vrijednosti

Jednadžba \(ax+by=\gcd(a,b)\) ima beskonačno mnogo rješenja i očito neka od njih prekoračuju long long.
Srećom, ako je \(b\not= 0\), rješenje koje daje prošireni Euklidov algoritam sigurno zadovoljava \(|x|\le b,|y|\le a\).
Slijedi dokaz tog svojstva.

Dokaz
  • Kad je \(\gcd(a,b)=b\), vrijedi \(a\bmod b=0\), pa rekurzija sigurno završava na sljedećoj razini.
    Dobivamo \(x_1=0,y_1=1\) i očito \(a,b\ge 1\ge |x_1|,|y_1|\).
  • Kad je \(\gcd(a,b)\not= b\), pretpostavimo \(|x_2|\le (a\bmod b),|y_2|\le b\).
    Budući da je \(x_1=y_2,y_1=x_2-{\left\lfloor\dfrac{a}{b}\right\rfloor}y_2\)
    vrijedi \(|x_1|=|y_2|\le b,|y_1|\le|x_2|+|{\left\lfloor\dfrac{a}{b}\right\rfloor}y_2|\le (a\bmod b)+{\left\lfloor\dfrac{a}{b}\right\rfloor}|y_2|\)
    \(\le a-{\left\lfloor\dfrac{a}{b}\right\rfloor}b+{\left\lfloor\dfrac{a}{b}\right\rfloor}|y_2|\le a-{\left\lfloor\dfrac{a}{b}\right\rfloor}(b-|y_2|)\)
    \(a\bmod b=a-{\left\lfloor\dfrac{a}{b}\right\rfloor}b\le a-{\left\lfloor\dfrac{a}{b}\right\rfloor}(b-|y_2|)\le a\)
    Stoga vrijedi \(|x_1|\le b,|y_1|\le a\).

Iterativna izvedba proširenog Euklidova algoritma

Najprije, za \(x = 1\), \(y = 0\), \(x_1 = 0\), \(y_1 = 1\) očito vrijedi:

\[ \begin{cases} ax + by & = a \\ ax_1 + by_1 & = b \end{cases} \]

Znamo da je \(a\bmod b = a - (\lfloor \frac{a}{b} \rfloor \times b)\); označimo \(q = \lfloor \frac{a}{b} \rfloor\). Po uzoru na iterativno računanje gcd-a, svaki korak iteracije možemo zapisati kao:

\[ (a, b) \rightarrow (b, a - qb) \]

Zamijenimo li u iteraciji \(a\) s \(ax + by = a\), a \(b\) s \(ax_1 + by_1 = b\), dobivamo:

\[ \begin{aligned} & \begin{cases} ax + by & = a \\ ax_1 + by_1 & = b \end{cases} \\ \rightarrow & \begin{cases} ax_1 + by_1 & = b \\ a(x - qx_1) + b(y - qy_1) & = a - qb \end{cases} \end{aligned} \]

Na temelju toga dobivamo iterativni exgcd.

Budući da iterativna metoda izbjegava rekurziju, kod će se izvršavati nešto brže od rekurzivnog.

int gcd(int a, int b, int& x, int& y) {
  x = 1, y = 0;
  int x1 = 0, y1 = 1, a1 = a, b1 = b;
  while (b1) {
    int q = a1 / b1;
    tie(x, x1) = make_tuple(x1, x - q * x1);
    tie(y, y1) = make_tuple(y1, y - q * y1);
    tie(a1, b1) = make_tuple(b1, a1 - q * b1);
  }
  return a1;
}

Pogledate li pažljivo \(a_1\) i \(b_1\), primijetit ćete da poprimaju potpuno iste vrijednosti kao u iterativnoj inačici Euklidova algoritma, te da sljedeće formule vrijede u svakom trenutku (prije petlje while i na kraju svake iteracije): \(x \cdot a +y \cdot b =a_1\) i \(x_1 \cdot a +y_1 \cdot b= b_1\). Stoga algoritam sigurno ispravno računa \(\gcd\).

Na kraju znamo da je \(a_1\) upravo traženi \(\gcd\), pa vrijedi \(x \cdot a +y \cdot b = g\).

Matrično tumačenje

Jedan korak Euklidova algoritma za pozitivne cijele brojeve \(a\) i \(b\), tj. \(\gcd(a,b)=\gcd(b,a\bmod b)\), matrično se zapisuje kao

\[ \begin{bmatrix} b\\a\bmod b \end{bmatrix} = \begin{bmatrix} 0&1\\1&-\lfloor a/b\rfloor \end{bmatrix} \begin{bmatrix} a\\b \end{bmatrix} \]

gdje oznaka donjeg cijelog dijela \(\lfloor c\rfloor\) označava najveći cijeli broj koji nije veći od \(c\). Definiramo transformaciju \(\begin{bmatrix}a\\b\end{bmatrix}\mapsto \begin{bmatrix}0&1\\1&-\lfloor a/b\rfloor\end{bmatrix}\begin{bmatrix}a\\b\end{bmatrix}\).

Lako se vidi da je Euklidov algoritam upravo uzastopna primjena te transformacije, pa vrijedi

\[ \begin{bmatrix} \gcd(a,b)\\0 \end{bmatrix} = \left( \cdots \begin{bmatrix} 0&1\\1&-\lfloor a/b\rfloor \end{bmatrix} \begin{bmatrix} 1&0\\0&1 \end{bmatrix} \right) \begin{bmatrix} a\\b \end{bmatrix} \]

Neka je

\[ \begin{bmatrix} x_1&x_2\\x_3&x_4 \end{bmatrix} = \cdots \begin{bmatrix} 0&1\\1&-\lfloor a/b\rfloor \end{bmatrix} \begin{bmatrix} 1&0\\0&1 \end{bmatrix} \]

Tada je

\[ \begin{bmatrix} \gcd(a,b)\\0 \end{bmatrix} = \begin{bmatrix} x_1&x_2\\x_3&x_4 \end{bmatrix} \begin{bmatrix} a\\b \end{bmatrix} \]

i vrijedi \(a\cdot x_1+b\cdot x_2=\gcd(a,b)\), što je upravo prošireni Euklidov algoritam. Primijetite da množenje jediničnom matricom na kraju ne utječe na rezultat, što nam sugerira da na početku možemo održavati jediničnu matricu \(2\times 2\) i napisati sažetiju iterativnu inačicu:

int exgcd(int a, int b, int &x, int &y) {
  int x1 = 1, x2 = 0, x3 = 0, x4 = 1;
  while (b != 0) {
    int c = a / b;
    std::tie(x1, x2, x3, x4, a, b) =
        std::make_tuple(x3, x4, x1 - x3 * c, x2 - x4 * c, b, a - b * c);
  }
  x = x1, y = x2;
  return a;
}

Ovaj je prikaz jednostavniji od rekurzivnog.

Definition

The greatest common divisor is commonly abbreviated as gcd.

A common divisor of a set of integers is a number that is simultaneously a divisor of every number in the set. \(\pm 1\) is a common divisor of any set of integers.

The greatest common divisor of a set of integers is the largest of all their common divisors.

For integers \(a,b\) not both \(0\), their greatest common divisor is denoted \(\gcd(a,b)\), or simply \((a,b)\) when there is no ambiguity.

For integers \(a_1,\dots,a_n\) not all \(0\), their greatest common divisor is denoted \(\gcd(a_1,\dots,a_n)\), or simply \((a_1,\dots,a_n)\) when there is no ambiguity.

For the properties of the greatest common divisor and the least common multiple, see Number theory basics.

So how do we compute the greatest common divisor? Let us first consider the case of two numbers.

Euclidean algorithm

Procedure

Given two numbers \(a\) and \(b\), how do we find their greatest common divisor?

Without loss of generality, let \(a > b\).

We observe that if \(b\) is a divisor of \(a\), then \(b\) is the greatest common divisor of the two. Below we discuss the case where the division is not exact, i.e., \(a = b \times q + r\) with \(r < b\).

By a proof we obtain \(\gcd(a,b)=\gcd(b,a \bmod b)\); the procedure is as follows:

Proof

Let \(a=bk+c\); clearly \(c=a \bmod b\). Let \(d \mid a,~d \mid b\); then \(c=a-bk, \frac{c}{d}=\frac{a}{d}-\frac{b}{d}k\).

From the right-hand side we see that \(\frac{c}{d}\) is an integer, i.e., \(d \mid c\), so any common divisor of \(a,b\) is also a common divisor of \(b,a \bmod b\).

The converse also needs to be proven:

Let \(d \mid b,~d\mid (a \bmod b)\); as before we obtain \(\frac{a\bmod b}{d}=\frac{a}{d}-\frac{b}{d}k,~\frac{a\bmod b}{d}+\frac{b}{d}k=\frac{a}{d}\).

Since the left-hand side is clearly an integer, \(\frac{a}{d}\) is also an integer, i.e., \(d \mid a\), so any common divisor of \(b,a\bmod b\) is also a common divisor of \(a,b\).

Since the common divisors of both pairs are the same, the greatest common divisors are the same as well.

Hence we obtain the formula \(\gcd(a,b)=\gcd(b,a\bmod b)\)

Since we have \(\gcd(a, b) = \gcd(b, r)\), where the sizes of the two numbers never increase, we have obtained a recursive method for the greatest common divisor of two numbers.

Implementation

// Version 1
int gcd(int a, int b) {
  if (b == 0) return a;
  return gcd(b, a % b);
}

// Version 2
int gcd(int a, int b) { return b == 0 ? a : gcd(b, a % b); }

// Version 1
public int gcd(int a, int b) {
    if (b == 0) return a;
    return gcd(b, a % b);
}

// Version 2
public int gcd(int a, int b) {
    return b == 0 ? a : gcd(b, a % b);
}

def gcd(a, b):
    if b == 0:
        return a
    return gcd(b, a % b)

Recurse until the case b == 0 (i.e., a % b == 0 in the previous step) and then return the value.

Based on the recursive method above, we can also write an iterative one:

int gcd(int a, int b) {
  while (b != 0) {
    int tmp = a;
    a = b;
    b = tmp % b;
  }
  return a;
}

public int gcd(int a, int b) {
    while(b != 0) {
        int tmp = a;
        a = b;
        b = tmp % b;
    }
    return a;
}

def gcd(a, b):
    while b != 0:
        a, b = b, a % b
    return a

All the algorithms above can be called the Euclidean algorithm.

In addition, in C++17 we can use std::gcd and std::lcm from the <numeric> header to compute the greatest common divisor and the least common multiple.

Note

In some compilers, the function std::__gcd(a,b) can be used in C++14 to compute the greatest common divisor, but it is only a private helper function of std::rotate.1Using this function may lead to unexpected problems, so it is generally not recommended.

If two numbers \(a\) and \(b\) satisfy \(\gcd(a, b) = 1\), we say that \(a\) and \(b\) are coprime.

Properties

How efficient is the Euclidean algorithm? Below we prove that when the input consists of two binary integers of length \(n\), the time complexity of the Euclidean algorithm is \(O(n)\). (In other words, assuming by default that \(a, b\) are of the same order, the time complexity is \(O(\log\max(a, b))\).)

Proof

When computing \(\gcd(a,b)\), we encounter two cases:

  • \(a < b\); then \(\gcd(a,b)=\gcd(b,a)\);
  • \(a \geq b\); then \(\gcd(a,b)=\gcd(b,a \bmod b)\), and taking the remainder of \(a\) at least halves \(a\). This means this step happens at most \(O(\log a) = O(n)\) times.

The first case is always followed by the second case, so the number of occurrences of the first case is no more than that of the second case.

Hence we obtain the result after at most \(O(n)\) recursive calls.

In fact, if we try to use the Euclidean algorithm to compute the greatest common divisor of two adjacent terms of the Fibonacci sequence, the algorithm reaches its worst-case complexity.

Successive subtraction method (更相减损术)

Taking the remainder of big integers has a high time complexity, while addition and subtraction have a low one. For big integers, we can use addition and subtraction instead of multiplication and division to compute the greatest common divisor.

Procedure

Given two numbers \(a\) and \(b\), find \(\gcd(a,b)\).

Without loss of generality, let \(a \ge b\). If \(a = b\), then \(\gcd(a,b)=a=b\). Otherwise, \(\forall d\mid a, d\mid b\), it can be proven that \(d\mid a-b\).

Therefore, all common divisors of \(a\) and \(b\) are common divisors of \(a-b\) and \(b\), and \(\gcd(a,b) = \gcd(a-b, b)\).

Optimization by Stein's algorithm

If \(a\gg b\), the \(O(n)\) complexity of the successive subtraction method reaches its worst case.

Consider an optimization: if \(2\mid a,2\mid b\), then \(\gcd(a,b) = 2\gcd\left(\dfrac a2, \dfrac b2\right)\).

Otherwise, if \(2\mid a\) (the case \(2\mid b\) is analogous), since the case \(2\mid b\) has already been discussed, we have \(2 \nmid b\). Therefore \(\gcd(a,b)=\gcd\left(\dfrac a2,b\right)\).

The time complexity of the optimized algorithm (i.e., Stein's algorithm) is \(O(\log n)\).

Proof

If \(2\mid a\) or \(2\mid b\), each recursive step halves at least one of \(a,b\).

Otherwise \(2\mid a-b\), which brings us back to the previous case.

The algorithm recurses at most \(O(\log n)\) times.

Implementation

For a bignum template, see Arbitrary-precision arithmetic.

The bignum implementation needs: subtraction, comparison, left shift, right shift (can be replaced by multiplication/division by a small number), and the number of trailing binary zeros (can be computed by brute force by checking parity).

C++ 
Big gcd(Big a, Big b) {
  if (a == 0) return b;
  if (b == 0) return a;
  // record how many times 2 appears as a common factor of a and b; countr_zero is the number of trailing binary zeros
  int atimes = countr_zero(a);
  int btimes = countr_zero(b);
  int mintimes = min(atimes, btimes);
  a >>= atimes;
  for (;;) {
    // the 2s among the common factors of a and b have already been handled, so a can never be even from now on
    b >>= btimes;
    // make sure a<=b
    if (a > b) swap(a, b);
    b -= a;
    if (b == 0) break;
    btimes = countr_zero(b);
  }
  return a << mintimes;
}

The code above follows the implementations of C++17 std::gcd in libstdc++ and MSVC. Within the data ranges of unsigned int and unsigned long long, if countr_zero can be computed extremely fast, Stein's algorithm is faster than the Euclidean algorithm; otherwise it may be slower than the Euclidean algorithm.

About countr_zero
  1. gcc has the built-in functions __builtin_ctz (32-bit) and __builtin_ctzll (64-bit), which can replace countr_zero in the code above;
  2. Starting from C++20, the header <bit> contains std::countr_zero;
  3. If you do not want to use functions outside the standard library and cannot use the C++20 standard, the following code is an \(O(1)\) implementation (after preprocessing) in the Word-RAM with multiplication model:
constexpr int loghash[64] = {0,  32, 48, 56, 60, 62, 63, 31, 47, 55, 59, 61, 30,
                             15, 39, 51, 57, 28, 46, 23, 43, 53, 58, 29, 14, 7,
                             35, 49, 24, 44, 54, 27, 45, 22, 11, 37, 50, 25, 12,
                             38, 19, 41, 52, 26, 13, 6,  3,  33, 16, 40, 20, 42,
                             21, 10, 5,  34, 17, 8,  36, 18, 9,  4,  2,  1};

int countr_zero(unsigned long long x) {
  return loghash[(x & -x) * 0x9150D32D8EB9EFC0Ui64 >> 58];
}

As for bignums, if the implementation is similar to bitset, then together with the implementation of countr_zero above this can be done in O(n / w) time. But if splitting by binary bits is inconvenient, the largest power-of-\(2\) factor can only be determined by brute force, and the time complexity depends on the implementation. For example:

// a binary Big implemented in little-endian order; it must be possible to iterate over every element
int countr_zero(Big a) {
  int ans = 0;
  for (auto x : a) {
    if (x != 0) {
      ans += 32;  // bit width of the data type of each element
    } else {
      return ans + countr_zero(x);
    }
  }
  return ans;
}

// brute-force computation; if used, it is recommended to inline it directly into gcd to improve the constant
int countr_zero(Big a) {
  int ans = 0;
  while ((a & 1) == 0) {
    a >>= 1;
    ++ans;
  }
  return ans;
}

Greatest common divisor of several numbers

So how do we find the greatest common divisor of several numbers? Clearly the answer must be a divisor of each number, and hence also a divisor of every two adjacent numbers. By induction, we can prove that taking out two numbers, computing their result, and putting it back does not affect the required answer.

Least common multiple

Next we introduce how to compute the least common multiple (LCM).

Definition

A common multiple of a set of integers is a number that is simultaneously a multiple of every number in the set. 0 is a common multiple of any set of integers.

The least common multiple of a set of integers is the smallest of all their positive common multiples.

For integers \(a,b\), their least common multiple is denoted \(\operatorname{lcm}(a,b)\), or simply \([a,b]\) when there is no ambiguity.

For integers \(a_1,\dots,a_n\), their least common multiple is denoted \(\operatorname{lcm}(a_1,\dots,a_n)\), or simply \([a_1,\dots,a_n]\) when there is no ambiguity.

Two numbers

Let \(a = p_1^{k_{a_1}}p_2^{k_{a_2}} \cdots p_s^{k_{a_s}}\), \(b = p_1^{k_{b_1}}p_2^{k_{b_2}} \cdots p_s^{k_{b_s}}\)

We find that for \(a\) and \(b\), their greatest common divisor equals

\(p_1^{\min(k_{a_1}, k_{b_1})}p_2^{\min(k_{a_2}, k_{b_2})} \cdots p_s^{\min(k_{a_s}, k_{b_s})}\)

and the least common multiple equals

\(p_1^{\max(k_{a_1}, k_{b_1})}p_2^{\max(k_{a_2}, k_{b_2})} \cdots p_s^{\max(k_{a_s}, k_{b_s})}\)

Since \(k_a + k_b = \max(k_a, k_b) + \min(k_a, k_b)\)

we conclude that \(\gcd(a, b) \times \operatorname{lcm}(a, b) = a \times b\)

To find the least common multiple of two numbers, it suffices to first compute the greatest common divisor.

Several numbers

We can see that once we have the \(\gcd\) of two numbers, computing the least common multiple takes \(O(1)\). So for several numbers, there is actually no need to compute a common greatest common divisor first and then process it; the most direct approach is this: just as when computing the \(\gcd\) of several numbers we put the \(\gcd\) of two numbers back into the sequence and continue with the following numbers, here, by analogy, we directly put the least common multiple into the sequence.

Extended Euclidean algorithm

The extended Euclidean algorithm (EXGCD) is commonly used to find one feasible solution of \(ax+by=\gcd(a,b)\).

Procedure

Let

\(ax_1+by_1=\gcd(a,b)\)

\(bx_2+(a\bmod b)y_2=\gcd(b,a\bmod b)\)

By Euclid's theorem: \(\gcd(a,b)=\gcd(b,a\bmod b)\)

So \(ax_1+by_1=bx_2+(a\bmod b)y_2\)

Also, since \(a\bmod b=a-(\lfloor\frac{a}{b}\rfloor\times b)\)

we have \(ax_1+by_1=bx_2+(a-(\lfloor\frac{a}{b}\rfloor\times b))y_2\)

\(ax_1+by_1=ay_2+bx_2-\lfloor\frac{a}{b}\rfloor\times by_2=ay_2+b(x_2-\lfloor\frac{a}{b}\rfloor y_2)\)

Since \(a=a,b=b\), we get \(x_1=y_2,y_1=x_2-\lfloor\frac{a}{b}\rfloor y_2\)

Keep substituting \(x_2,y_2\) recursively until \(b\) becomes \(0\), where \(x=1,y=0\), and then go back up to compute the solution.

Implementation

int Exgcd(int a, int b, int &x, int &y) {
  if (!b) {
    x = 1;
    y = 0;
    return a;
  }
  int d = Exgcd(b, a % b, x, y);
  int t = x;
  x = y;
  y = t - (a / b) * y;
  return d;
}

def Exgcd(a, b):
    if b == 0:
        return a, 1, 0
    d, x, y = Exgcd(b, a % b)
    return d, y, x - (a // b) * y

The function returns \(\gcd\), and \(x,y\) are computed along the way.

Analysis of the value range

\(ax+by=\gcd(a,b)\) has infinitely many solutions, and obviously some of them overflow long long.
Fortunately, if \(b\not= 0\), the feasible solution found by the extended Euclidean algorithm always satisfies \(|x|\le b,|y|\le a\).
A proof of this property is given below.

Proof
  • When \(\gcd(a,b)=b\), we have \(a\bmod b=0\), so the recursion must terminate at the next level.
    We get \(x_1=0,y_1=1\), and clearly \(a,b\ge 1\ge |x_1|,|y_1|\).
  • When \(\gcd(a,b)\not= b\), suppose \(|x_2|\le (a\bmod b),|y_2|\le b\).
    Since \(x_1=y_2,y_1=x_2-{\left\lfloor\dfrac{a}{b}\right\rfloor}y_2\)
    we have \(|x_1|=|y_2|\le b,|y_1|\le|x_2|+|{\left\lfloor\dfrac{a}{b}\right\rfloor}y_2|\le (a\bmod b)+{\left\lfloor\dfrac{a}{b}\right\rfloor}|y_2|\)
    \(\le a-{\left\lfloor\dfrac{a}{b}\right\rfloor}b+{\left\lfloor\dfrac{a}{b}\right\rfloor}|y_2|\le a-{\left\lfloor\dfrac{a}{b}\right\rfloor}(b-|y_2|)\)
    \(a\bmod b=a-{\left\lfloor\dfrac{a}{b}\right\rfloor}b\le a-{\left\lfloor\dfrac{a}{b}\right\rfloor}(b-|y_2|)\le a\)
    Therefore \(|x_1|\le b,|y_1|\le a\) holds.

Iterative implementation of the extended Euclidean algorithm

First, when \(x = 1\), \(y = 0\), \(x_1 = 0\), \(y_1 = 1\), obviously

\[ \begin{cases} ax + by & = a \\ ax_1 + by_1 & = b \end{cases} \]

holds.

We know that \(a\bmod b = a - (\lfloor \frac{a}{b} \rfloor \times b)\); below let \(q = \lfloor \frac{a}{b} \rfloor\). Following the iterative computation of the gcd, each round of the iteration can be expressed as:

\[ (a, b) \rightarrow (b, a - qb) \]

Replacing \(a\) in the iteration with \(ax + by = a\) and \(b\) with \(ax_1 + by_1 = b\), we get:

\[ \begin{aligned} & \begin{cases} ax + by & = a \\ ax_1 + by_1 & = b \end{cases} \\ \rightarrow & \begin{cases} ax_1 + by_1 & = b \\ a(x - qx_1) + b(y - qy_1) & = a - qb \end{cases} \end{aligned} \]

From this we obtain the iterative exgcd.

Because the iterative method avoids recursion, the code runs a bit faster than the recursive code.

int gcd(int a, int b, int& x, int& y) {
  x = 1, y = 0;
  int x1 = 0, y1 = 1, a1 = a, b1 = b;
  while (b1) {
    int q = a1 / b1;
    tie(x, x1) = make_tuple(x1, x - q * x1);
    tie(y, y1) = make_tuple(y1, y - q * y1);
    tie(a1, b1) = make_tuple(b1, a1 - q * b1);
  }
  return a1;
}

If you look closely at \(a_1\) and \(b_1\), you will notice that they take exactly the same values as in the iterative version of the Euclidean algorithm, and that the following formulas hold at all times (before the while loop and at the end of each iteration): \(x \cdot a +y \cdot b =a_1\) and \(x_1 \cdot a +y_1 \cdot b= b_1\). Therefore, the algorithm is guaranteed to compute \(\gcd\) correctly.

Finally, we know that \(a_1\) is the required \(\gcd\), and \(x \cdot a +y \cdot b = g\).

Matrix interpretation

One step of the Euclidean algorithm for positive integers \(a\) and \(b\), i.e., \(\gcd(a,b)=\gcd(b,a\bmod b)\), is expressed with matrices as

\[ \begin{bmatrix} b\\a\bmod b \end{bmatrix} = \begin{bmatrix} 0&1\\1&-\lfloor a/b\rfloor \end{bmatrix} \begin{bmatrix} a\\b \end{bmatrix} \]

where the floor symbol \(\lfloor c\rfloor\) denotes the largest integer not greater than \(c\). We define the transformation \(\begin{bmatrix}a\\b\end{bmatrix}\mapsto \begin{bmatrix}0&1\\1&-\lfloor a/b\rfloor\end{bmatrix}\begin{bmatrix}a\\b\end{bmatrix}\).

It is easy to see that the Euclidean algorithm is just the repeated application of this transformation, so

\[ \begin{bmatrix} \gcd(a,b)\\0 \end{bmatrix} = \left( \cdots \begin{bmatrix} 0&1\\1&-\lfloor a/b\rfloor \end{bmatrix} \begin{bmatrix} 1&0\\0&1 \end{bmatrix} \right) \begin{bmatrix} a\\b \end{bmatrix} \]

Let

\[ \begin{bmatrix} x_1&x_2\\x_3&x_4 \end{bmatrix} = \cdots \begin{bmatrix} 0&1\\1&-\lfloor a/b\rfloor \end{bmatrix} \begin{bmatrix} 1&0\\0&1 \end{bmatrix} \]

Then

\[ \begin{bmatrix} \gcd(a,b)\\0 \end{bmatrix} = \begin{bmatrix} x_1&x_2\\x_3&x_4 \end{bmatrix} \begin{bmatrix} a\\b \end{bmatrix} \]

which satisfies \(a\cdot x_1+b\cdot x_2=\gcd(a,b)\), i.e., the extended Euclidean algorithm. Note that multiplying by an identity matrix at the end does not affect the result, which suggests that we can maintain a \(2\times 2\) identity matrix from the start and write a more concise iterative version:

int exgcd(int a, int b, int &x, int &y) {
  int x1 = 1, x2 = 0, x3 = 0, x4 = 1;
  while (b != 0) {
    int c = a / b;
    std::tie(x1, x2, x3, x4, a, b) =
        std::make_tuple(x3, x4, x1 - x3 * c, x2 - x4 * c, b, a - b * c);
  }
  x = x1, y = x2;
  return a;
}

This formulation is simpler than the recursive one.
