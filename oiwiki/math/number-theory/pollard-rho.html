Uvod

Zadan je prirodan broj \(N \in \mathbf{N}_{+}\); treba brzo pronaći jedan njegov netrivijalni djelitelj.

Razmotrimo naivni algoritam. Djelitelji dolaze u parovima, pa se svi djelitelji broja \(N\) mogu podijeliti u dva dijela, \([2, \sqrt N]\) i \([\sqrt N+1,N)\). Dovoljno je proći kroz brojeve iz \([2, \sqrt N]\) i zatim dijeljenjem pronaći barem dva djelitelja. Vremenska složenost ove metode jest \(O(\sqrt N)\).

Kad je \(N\ge10^{18}\), vrijeme izvođenja ovog algoritma za nas je neprihvatljivo, pa želimo bolji algoritam. Jedna je ideja randomizirani pristup: pogađamo je li neki broj djelitelj broja \(N\); uz sreću odgovor dobivamo u vremenskoj složenosti \(O(1)\), ali za podatke s \(N\ge10^{18}\) vjerojatnost uspješnog pogotka iznosi \(\frac{1}{10^{18}}\), a očekivani broj pogađanja \(10^{18}\). Ako pogađamo unutar \([2,\sqrt N]\), vjerojatnost uspjeha nešto je veća. Želimo metodu kojom ćemo pogađanje optimizirati.

Naivni algoritam

Najjednostavniji je algoritam prolazak kroz \([2, \sqrt N]\).

vector<int> breakdown(int N) {
  vector<int> result;
  for (int i = 2; i * i <= N; i++) {
    if (N % i == 0) {  // ako i dijeli N, tada je i jedan prosti faktor broja N.
      while (N % i == 0) N /= i;
      result.push_back(i);
    }
  }
  if (N != 1) {  // znači da je nakon svih operacija od N ostao prost broj
    result.push_back(N);
  }
  return result;
}

def breakdown(N):
    result = []
    for i in range(2, int(sqrt(N)) + 1):
        if N % i == 0:  # ako i dijeli N, tada je i jedan prosti faktor broja N.
            while N % i == 0:
                N //= i
            result.append(i)
    if N != 1:  # znači da je nakon svih operacija od N ostao prost broj
        result.append(N)
    return result

Možemo dokazati da su svi elementi u result upravo svi prosti faktori broja N.

Dokaz da su elementi u result upravo svi prosti faktori broja \(N\)

Najprije promotrimo kako se N mijenja. Kad završi iteracija petlje za i, budući da je upravo izvršen dio while(N % i == 0) N /= i, i više ne dijeli N. Osim toga, svaki put kad uklonimo jedan faktor, N i dalje dijeli \(N\). Ove dvije činjenice jamče da je na početku iteracije za i broj N djelitelj broja \(N\) koji nije djeljiv nijednim cijelim brojem manjim od i.

Zatim dokazujemo da su svi elementi u result djelitelji broja \(N\). Kad petlja dođe do i, uvjet za spremanje i u result jest N % i == 0, što znači da i dijeli N, a već smo pokazali da je N djelitelj broja \(N\), pa je i i djelitelj broja \(N\). Kad petlja po i završi, ako N nije jednak jedan, i on se sprema u result. Prema prethodnome, i on je tada nužno djelitelj broja \(N\).

Zatim dokazujemo da su svi elementi u result prosti. Pretpostavimo da u result postoji složen broj \(K\); tada nužno postoji i veći od jedan i ne veći od \(\sqrt K\) takav da je i djelitelj broja \(K\). Takav \(K\) ne može biti spremljen u result kao neki i iz petlje, jer je u prvom odlomku pokazano da u trenutku kad petlja dođe do \(K\) broj N nije djeljiv nijednim i manjim od \(K\). Takav \(K\) ne može biti dodan ni nakon završetka petlje, jer je uvjet izlaska iz petlje i * i > N, pa su već obiđeni svi i koji ne premašuju \(\sqrt K\), a prema rečenome ti i nikako ne dijele trenutačni N, tj. \(K\).

Naposljetku dokazujemo da se svi prosti faktori broja \(N\) nužno pojavljuju u result. Pretpostavimo da je \(p\) prosti faktor broja \(N\) koji se ne pojavljuje u result. Prema prethodnoj raspravi, \(p\) ne može biti neki i koji se pojavio u petlji. Neka je i posljednji i prije izlaska iz petlje; tada je i strogo manji od \(p\), a N nakon izlaska iz petlje nije djeljiv nijednim prethodnim i, pa \(p\) dijeli N. Dakle, završni je N veći od jedan, pa je prema prethodnome nužno prost, pa je N jednak \(p\) i sigurno se na kraju dodaje u result, što je u suprotnosti s pretpostavkom.

Vrijedi istaknuti da, ako na početku već imamo pripremljenu tablicu prostih brojeva, vremenska složenost pada s \(O(\sqrt N)\) na \(O(\frac {\sqrt{N}} {\ln N})\). Više o pripremi tablica pogledajte u odjeljku Sita.

Pollardov rho algoritam

Uvod

Složenost pronalaženja jednog netrivijalnog djelitelja grubom silom jest \(O(p)=O(\sqrt N)\), gdje je \(p\) najmanji prosti faktor broja \(N\). Pollardov rho algoritam koji ćemo sada predstaviti randomizirani je algoritam koji netrivijalni djelitelj pronalazi u očekivanoj složenosti \(O(\sqrt p)=O(N^{1/4})\) (pozor: netrivijalni djelitelj ne mora biti prost).

Njegova je ključna ideja sljedeća: za slučajno preslikavanje \(f: \mathbf Z_p \rightarrow \mathbf Z_p\) u samog sebe, krenemo li iz bilo koje točke \(x_1\) i iterativno računamo \(x_n = f(x_{n-1})\), u očekivanom vremenu \(O(\sqrt p)\) ulazimo u ciklus. Ako uspijemo pronaći \(x_i \equiv x_j \pmod p\), tada \(p\) dijeli \(\gcd(|x_i-x_j|, N)\), a taj je najveći zajednički djelitelj netrivijalni djelitelj broja \(N\).

Za razumijevanje toga zašto je očekivano vrijeme ulaska u ciklus \(O(\sqrt p)\) možemo se nadahnuti paradoksom rođendana.

Paradoks rođendana

Ne uzimajući u obzir godinu rođenja (pretpostavimo da svaka godina ima 365 dana), pitamo: koliko najmanje ljudi mora biti u sobi da bi vjerojatnost da dvoje od njih imaju isti rođendan dosegnula \(50\%\)?

Rješenje: pretpostavimo da godina ima \(n\) dana i da je u sobi \(k\) ljudi, koje numeriramo cijelim brojevima \(1, 2,\dots, k\). Pretpostavimo da je rođendan svake osobe jednoliko raspodijeljen među \(n\) dana te da su rođendani dviju osoba međusobno nezavisni.

Neka je \(A\) događaj da svih \(k\) ljudi ima međusobno različite rođendane; tada je vjerojatnost događaja \(A\)

\[ P(A)=\prod_{i=0}^{k-1}\frac{n-i}{n} \]

Vjerojatnost da barem dvoje ljudi ima isti rođendan jest \(P(\overline A)=1-P(A)\). Prema uvjetu zadatka \(P(\overline A)\ge\frac{1}{2}\), pa imamo

\[ P(A)=\prod_{i=0}^{k-1}\frac{n-i}{n} \le \frac{1}{2} \]

Iz nejednakosti \(1+x\le \mathrm{e}^x\) dobivamo

\[ P(A) \le \prod_{i=1}^{k-1}\exp\left({-\frac{i}{n}}\right)=\exp \left({-\frac{k(k-1)}{2n}}\right) \]

Stoga

\[ \exp\left({-\dfrac{k(k-1)}{2n}}\right) \le \frac{1}{2}\implies P(A) \le \frac{1}{2} \]

Uvrštavanjem \(n=365\) dobivamo \(k\geq 23\). Dakle, dovoljno je \(23\) ljudi u sobi da vjerojatnost da dvoje od njih imaju isti rođendan dosegne \(50\%\); budući da je ta matematička činjenica vrlo protuintuitivna, naziva se paradoksom.

Kad je \(k>56\) i \(n=365\), vjerojatnost da dvoje ljudi imaju rođendan istog dana veća je od \(99\%\)1. Dakle, ako godina ima \(n\) dana, kad je u sobi \(\frac{1}{2}(\sqrt{8n\ln 2+1}+1)\approx \sqrt{2n\ln 2}\) ljudi, vjerojatnost da barem dvoje imaju isti rođendan iznosi približno \(50\%\).

Slično se može izračunati da je, biramo li slučajno i jednoliko niz rođendana, očekivani broj ljudi potreban da se prvi put pojavi ponovljeni rođendan također \(O(\sqrt n)\). Označimo li taj broj ljudi s \(X\), vrijedi

\[ E(X) = \sum_{x=0}^{n}P(X\ge x+1) = \sum_{x=0}^n\frac{n!}{(n-x)!n^x} = \sqrt{\frac{\pi n}{2}}+\frac23+o(1). \]

To nas navodi na zaključak da je, ako slučajno biramo niz brojeva, očekivana veličina uzorka potrebna da se pojavi ponovljeni broj također \(O(\sqrt n)\).

Pronalaženje djelitelja pomoću najvećeg zajedničkog djelitelja

Konstruirati niz slučajnih brojeva modulo \(p\) u praksi nije moguće, jer je \(p\) upravo ono što tražimo. Zato pseudoslučajni niz \(\{x_i\}\) generiramo pomoću \(f(x)=(x^2+c)\bmod N\): slučajno odaberemo \(x_1\) i stavimo \(x_2=f(x_1),\ x_3=f(x_2),\ \dots,\ x_i=f(x_{i-1})\), gdje je \(c\in[1,N)\) slučajno odabrana konstanta.

Ovdje odabrana funkcija lako se računa i često daje prilično slučajne nizove. No niz nije potpuno slučajan. Na primjer, neka je \(N=50,\ c=6,\ x_1=1\); \(f(x)\) generira podatke

\[ 1, 7, 5, 31, 17, 45, 31, 17, 45, 31,\dots \]

Vidimo da se podatci nakon \(x_4\) ciklički ponavljaju među \(31,17,45\). Rasporedimo li te brojeve kao na slici ispod, uočit ćemo da slika nalikuje slovu \(\rho\), po čemu je algoritam i dobio ime rho.

Još je važnije da ovakva funkcija doista daje preslikavanje \(\mathbf Z_p\) u samog sebe. Drugim riječima, zadovoljava svojstvo: ako je \(x\equiv y\pmod p\), tada je \(f(x)\equiv f(y)\pmod p\).

Dokaz

Ako je \(x\equiv y\pmod p\), tada je \(x^2+c\equiv y^2+c\pmod p\). Primijetimo da je \(f(x)=x^2+c-k_xN\), gdje je \(k_x\) cijeli broj koji ovisi o \(x\), a \(p\mid N\), pa vrijedi \(f(x)\equiv x^2+c\pmod p\), dakle \(f(x)\equiv f(y)\pmod p\).

Kao niz dobiven uzastopnim iteriranjem pseudoslučajnog preslikavanja \(\mathbf Z_p\) u samog sebe, \(\{x_n\bmod p\}\) ponovit će se u očekivanom vremenu \(O(\sqrt p)\). Čim uočimo takvo ponavljanje \(x_i\equiv x_j\pmod p\), iz \(\gcd(|x_i-x_j|,N)\) možemo dobiti netrivijalni djelitelj broja \(N\). Primijetimo da, budući da je \(p\) nepoznat, ne možemo izravno utvrditi je li se ponavljanje dogodilo; jednostavan kriterij upravo je to da je \(\gcd(|x_i-x_j|,N)\) strogo veći od jedan.

Ovaj algoritam ne uspijeva uvijek, jer \(\gcd(|x_i-x_j|,N)\) može biti jednak \(N\). Drugim riječima, \(x_i\equiv x_j\pmod N\). Tada se u trenutku kad se \(\{x_n\bmod p\}\) prvi put ponovi ponovio i \(\{x_n\}\). Nismo dobili netrivijalni djelitelj. Štoviše, nakon što \(\{x_n\}\) uđe u ciklus, daljnje iteriranje nema smisla, jer će se dalje samo ponavljati taj ciklus. Algoritam tada treba javiti neuspjeh rastava, a rastav treba ponoviti s drukčije odabranim \(c\) u \(f(x)\).

Prema gornjoj analizi, teoretski se ovdje može upotrijebiti bilo koja funkcija \(f(x)\) koja zadovoljava \(\forall x \equiv y \pmod p, f(x) \equiv f(y) \pmod p\) i jamči određenu pseudoslučajnost (na primjer neke polinomne funkcije). U praksi se uglavnom koristi \(f(x)=x^2+c\ (c\neq 0,-2)\).2

Implementacija

Trebamo implementirati algoritam koji tijekom iteriranja brzo utvrđuje je li se \(\{x_n\bmod p\}\) već ponovio. Promatramo li \(f\) kao bridove usmjerenog grafa čiji su vrhovi elementi \(\mathbf Z_p\), zapravo trebamo implementirati algoritam za otkrivanje ciklusa, s tim da provjeru jednakosti zamjenjujemo provjerom je li \(\gcd(|x_i-x_j|,N)\) veći od jedan.

Floydovo otkrivanje ciklusa

Zamislimo da se dvoje ljudi utrkuje: A je brz, B je spor. Nakon nekog vremena A će sigurno sustići B-a, a u trenutku susreta razlika ukupne udaljenosti koju je prešao A i ukupne udaljenosti koju je prešao B sigurno je višekratnik duljine kruga.

Neka je \(a=f(0),b=f(f(0))\); u svakom koraku ažuriramo \(a=f(a),b=f(f(b))\) i samo provjeravamo jesu li \(a\) i \(b\) tijekom ažuriranja postali jednaki; ako jesu, pojavio se ciklus.

U svakom koraku stavimo \(d=\gcd(|x_i-x_j|,N)\) i provjerimo zadovoljava li \(d\) uvjet \(1< d< N\); ako zadovoljava, možemo izravno vratiti \(d\). Ako je \(d=N\), to znači da je \(\{x_i\}\) već zatvorio ciklus; kad se ciklus zatvori, ne može se dalje nastaviti, pa izravno vraćamo sam \(N\), a u daljnjem postupku mijenjamo slučajnu konstantu \(c\) i ponavljamo rastav.

Pollardov rho algoritam s Floydovim otkrivanjem ciklusa 
ll Pollard_Rho(ll N) {
  if (N == 4) return 2;  // budući da na početku skačemo dva koraka, 4 treba posebno obraditi
  ll c = rand() % (N - 1) + 1;
  ll t = f(0, c, N);
  ll r = f(f(0, c, N), c, N);
  while (t != r) {
    ll d = gcd(abs(t - r), N);
    if (d > 1) return d;
    t = f(t, c, N);
    r = f(f(r, c, N), c, N);
  }
  return N;
}

import random


def Pollard_Rho(N):
    if N == 4:
        return 2  # budući da na početku skačemo dva koraka, 4 treba posebno obraditi
    c = random.randint(1, N - 1)
    t = f(0, c, N)
    r = f(f(0, c, N), c, N)
    while t != r:
        d = gcd(abs(t - r), N)
        if d > 1:
            return d
        t = f(t, c, N)
        r = f(f(r, c, N), c, N)
    return N

Brentovo otkrivanje ciklusa

Zapravo se Floydov algoritam za otkrivanje ciklusa može poboljšati u konstanti. Brentovo otkrivanje ciklusa počinje od \(k=1\) i povećava \(k\); u \(k\)-tom krugu A čeka na mjestu, a B se pomiče \(2^k\) koraka naprijed. Ako B pritom sretne A-a, ciklus je pronađen; inače A trenutačno premještamo na položaj B-a i prelazimo na sljedeći krug.

Može se dokazati3 da broj poziva funkcije \(f\) potrebnih da se tako pronađe ciklus nikad nije veći nego kod Floydova algoritma. Testovi u izvornom radu pokazuju da je prosječno vrijeme Brentova otkrivanja ciklusa za \(24\%\) manje od Floydova.

Optimizacija udvostručavanjem

Bilo da se koristi Floydovo ili Brentovo otkrivanje ciklusa, broj iteracija jest \(O(\sqrt p)\). No računanje \(\gcd\) u svakoj iteraciji radi provjere ciklusa usporava algoritam. Broj računanja \(\gcd\) može se smanjiti akumuliranjem umnoška.

Jednostavno rečeno, ako je \(\gcd(a,N)>1\), tada je \(\gcd(ab\bmod N,N)=\gcd(ab,N)>1\) za svaki \(b\in\mathbf N_+\). Drugim riječima, ako izračunamo \(\gcd(\prod |x_i-x_j| \bmod N,N)>1\), tada nužno neki par \((x_i,x_j)\) zadovoljava \(\gcd(|x_i-x_j|,N)>1\). Ako umnožak u nekom trenutku postane nula, rastav nije uspio; izlazimo i vraćamo sam \(N\).

Ako \(\gcd\) računamo svakih \(k\) parova, složenost algoritma pada na \(O(\sqrt p+k^{-1}\sqrt p\log N)\), gdje je \(\log N\) trošak jednog računanja \(\gcd\). Primijetimo da, kad su \(k\) i \(\log N\) otprilike istog reda veličine, dobivamo očekivanu složenost \(O(\sqrt p)\). U konkretnim implementacijama najčešće se uzima \(k=127\).

Ovdje dajemo implementaciju Pollardova rho algoritma s Brentovim otkrivanjem ciklusa i optimizacijom udvostručavanjem.

Implementacija 
ll Pollard_Rho(ll x) {
  ll t = 0;
  ll c = rand() % (x - 1) + 1;
  ll s = t;
  int step = 0, goal = 1;
  ll val = 1;
  for (goal = 1;; goal <<= 1, s = t, val = 1) {
    for (step = 1; step <= goal; ++step) {
      t = f(t, c, x);
      val = val * abs(t - s) % x;
      // ako je val jednak 0, izlazimo i ponavljamo rastav
      if (!val) return x;
      if (step % 127 == 0) {
        ll d = gcd(val, x);
        if (d > 1) return d;
      }
    }
    ll d = gcd(val, x);
    if (d > 1) return d;
  }
}

from random import randint
from math import gcd


def Pollard_Rho(x):
    c = randint(1, x - 1)
    s = t = f(0, c, x)
    goal = val = 1
    while True:
        for step in range(1, goal + 1):
            t = f(t, c, x)
            val = val * abs(t - s) % x
            if val == 0:
                return x  # ako je val jednak 0, izlazimo i ponavljamo rastav
            if step % 127 == 0:
                d = gcd(val, x)
                if d > 1:
                    return d
        d = gcd(val, x)
        if d > 1:
            return d
        s = t
        goal <<= 1
        val = 1

Složenost

Očekivani broj iteracija u Pollardovu rho algoritmu jest \(O(\sqrt p)\), gdje je \(p\) najmanji prosti faktor broja \(N\). Bez obzira na to koristi li konkretna implementacija Floydovo ili Brentovo otkrivanje ciklusa, bez optimizacije udvostručavanjem očekivana je složenost \(O(\sqrt p\log N)\); uz optimizaciju udvostručavanjem dobiva se približno očekivana složenost \(O(\sqrt p)\).

Vrijedi spomenuti da se gornja analiza temelji na potpuno slučajnom preslikavanju u samog sebe, dok Pollardov rho algoritam zapravo koristi pseudoslučajnu funkciju, pa algoritam nema strogu analizu složenosti, ali je u praksi obično prilično brz.

Primjer zadatka: najveći prosti faktor broja

Primjer zadatka: P4718【模板】Pollard-Rho 算法 (Predložak: Pollardov rho algoritam)

Za broj \(n\) Miller–Rabinovim algoritmom provjerimo je li prost; ako jest, možemo ga odmah vratiti, a inače Pollardovim rho algoritmom pronađemo djelitelj \(p\) i iz \(n\) uklonimo faktor \(p\). Zatim rekurzivno rastavljamo \(n\) i \(p\), Miller–Rabinovim testom provjeravamo jesmo li došli do prostog faktora i ažuriramo max_factor; tako dobivamo najveći prosti faktor. Budući da su podatci u ovom zadatku vrlo veliki, Floydovo otkrivanje ciklusa nije dovoljno, pa ovdje koristimo optimizaciju udvostručavanjem.

Implementacija 
#include <algorithm>
#include <cstdlib>
#include <ctime>
#include <iostream>

using namespace std;
using ll = long long;
using ull = unsigned long long;

int t;
ll max_factor, n;

ll gcd(ll a, ll b) {
  if (b == 0) return a;
  return gcd(b, a % b);
}

ll bmul(ll a, ll b, ll m) {  // brzo množenje
  ull c = (ull)a * (ull)b - (ull)((long double)a / m * b + 0.5L) * (ull)m;
  if (c < (ull)m) return c;
  return c + m;
}

ll qpow(ll x, ll p, ll mod) {  // brzo potenciranje
  ll ans = 1;
  while (p) {
    if (p & 1) ans = bmul(ans, x, mod);
    x = bmul(x, x, mod);
    p >>= 1;
  }
  return ans;
}

bool Miller_Rabin(ll p) {  // provjera prostosti
  if (p < 2) return false;
  if (p == 2) return true;
  if (p == 3) return true;
  ll d = p - 1, r = 0;
  while (!(d & 1)) ++r, d >>= 1;  // pretvori d u neparan broj
  for (ll k = 0; k < 10; ++k) {
    ll a = rand() % (p - 2) + 2;
    ll x = qpow(a, d, p);
    if (x == 1 || x == p - 1) continue;
    for (int i = 0; i < r - 1; ++i) {
      x = bmul(x, x, p);
      if (x == p - 1) break;
    }
    if (x != p - 1) return false;
  }
  return true;
}

ll Pollard_Rho(ll x) {
  ll s = 0, t = 0;
  ll c = (ll)rand() % (x - 1) + 1;
  int step = 0, goal = 1;
  ll val = 1;
  for (goal = 1;; goal *= 2, s = t, val = 1) {  // optimizacija udvostručavanjem
    for (step = 1; step <= goal; ++step) {
      t = (bmul(t, t, x) + c) % x;
      val = bmul(val, abs(t - s), x);
      if ((step % 127) == 0) {
        ll d = gcd(val, x);
        if (d > 1) return d;
      }
    }
    ll d = gcd(val, x);
    if (d > 1) return d;
  }
}

void fac(ll x) {
  if (x <= max_factor || x < 2) return;
  if (Miller_Rabin(x)) {              // ako je x prost
    max_factor = max(max_factor, x);  // ažuriraj odgovor
    return;
  }
  ll p = x;
  while (p >= x) p = Pollard_Rho(x);  // primijeni algoritam
  while ((x % p) == 0) x /= p;
  fac(x), fac(p);  // nastavi rastavljati x i p
}

int main() {
  cin >> t;
  while (t--) {
    srand((unsigned)time(NULL));
    max_factor = 0;
    cin >> n;
    fac(n);
    if (max_factor == n)  // najveći prosti faktor je sam broj
      cout << "Prime\n";
    else
      cout << max_factor << '\n';
  }
  return 0;
}

Introduction

Given a positive integer \(N \in \mathbf{N}_{+}\), try to quickly find one of its non-trivial divisors.

Consider the naive algorithm. Divisors come in pairs, so all divisors of \(N\) can be split into two parts, \([2, \sqrt N]\) and \([\sqrt N+1,N)\). It suffices to iterate over the numbers in \([2, \sqrt N]\) and then use division to find at least two divisors. The time complexity of this method is \(O(\sqrt N)\).

When \(N\ge10^{18}\), the running time of this algorithm is unacceptable for us, so we hope for a better algorithm. One idea is a randomized approach: guess whether a number is a divisor of \(N\); with luck the answer is found in \(O(1)\) time, but for data with \(N\ge10^{18}\) the probability of a successful guess is \(\frac{1}{10^{18}}\) and the expected number of guesses is \(10^{18}\). If we guess within \([2,\sqrt N]\), the success rate is somewhat higher. We hope for a method to optimize the guessing.

Naive algorithm

The simplest algorithm is to iterate over \([2, \sqrt N]\).

vector<int> breakdown(int N) {
  vector<int> result;
  for (int i = 2; i * i <= N; i++) {
    if (N % i == 0) {  // if i divides N, then i is a prime factor of N.
      while (N % i == 0) N /= i;
      result.push_back(i);
    }
  }
  if (N != 1) {  // means that after the operations N is left as a prime
    result.push_back(N);
  }
  return result;
}

def breakdown(N):
    result = []
    for i in range(2, int(sqrt(N)) + 1):
        if N % i == 0:  # if i divides N, then i is a prime factor of N.
            while N % i == 0:
                N //= i
            result.append(i)
    if N != 1:  # means that after the operations N is left as a prime
        result.append(N)
    return result

We can prove that the elements in result are exactly all prime factors of N.

Proof that the elements in result are exactly all prime factors of \(N\)

First, examine how N changes. When the loop iteration for i ends, since the part while(N % i == 0) N /= i has just been executed, i no longer divides N. Moreover, every time a factor is removed, N still divides \(N\). These two facts guarantee that, when the loop iteration for i begins, N is a divisor of \(N\) that is not divisible by any integer smaller than i.

Next, we prove that the elements in result are all divisors of \(N\). When the loop reaches i, the condition for storing i in result is N % i == 0, which means i divides N, and it has already been shown that N is a divisor of \(N\), hence i is a divisor of \(N\). When the loop over i ends, if N is not one, it is also stored in result. By the above, it is then necessarily a divisor of \(N\) as well.

Next, we prove that all elements in result are prime. Suppose there is a composite number \(K\) in result; then there necessarily exists an i greater than one and not exceeding \(\sqrt K\) such that i is a divisor of \(K\). Such a \(K\) cannot be stored in result as some i in the loop, because the first paragraph showed that when the loop reaches \(K\), N is not divisible by any i smaller than \(K\). Such a \(K\) also cannot be added after the loop ends, because the loop exit condition is i * i > N, so all i not exceeding \(\sqrt K\) have already been visited, and by the above these i can never divide the current N, i.e. \(K\).

Finally, we prove that all prime factors of \(N\) necessarily appear in result. Suppose \(p\) is a prime factor of \(N\) that does not appear in result. By the discussion above, \(p\) cannot be an i that appeared in the loop. Let i be the last i before exiting the loop; then i is strictly smaller than \(p\), and N after exiting the loop is not divisible by any previous i, hence \(p\) divides N. So the final N is greater than one, and by the above it is necessarily prime, so N equals \(p\) and will certainly be added to result at the end, contradicting the assumption.

It is worth pointing out that if a table of primes has already been prepared at the start, the time complexity drops from \(O(\sqrt N)\) to \(O(\frac {\sqrt{N}} {\ln N})\). See Sieves for more information on building such tables.

Pollard's rho algorithm

Introduction

The complexity of obtaining a non-trivial divisor by brute force is \(O(p)=O(\sqrt N)\), where \(p\) is the smallest prime factor of \(N\). Pollard's rho algorithm, introduced below, is a randomized algorithm that obtains a non-trivial divisor in expected complexity \(O(\sqrt p)=O(N^{1/4})\) (note: a non-trivial divisor is not necessarily a prime factor).

Its core idea is that for a random self-map \(f: \mathbf Z_p \rightarrow \mathbf Z_p\), starting from any point \(x_1\) and iteratively computing \(x_n = f(x_{n-1})\), we enter a cycle in expected time \(O(\sqrt p)\). If we can find \(x_i \equiv x_j \pmod p\), then \(p\) divides \(\gcd(|x_i-x_j|, N)\), and this greatest common divisor is a non-trivial divisor of \(N\).

To understand why the expected time to enter a cycle is \(O(\sqrt p)\), we can take inspiration from the birthday paradox.

Birthday paradox

Ignoring the year of birth (assume every year has 365 days), we ask: at least how many people must be in a room so that the probability that two of them share a birthday reaches \(50\%\)?

Solution: suppose a year has \(n\) days and there are \(k\) people in the room, numbered with the integers \(1, 2,\dots, k\). Assume that each person's birthday is uniformly distributed over the \(n\) days and that the birthdays of any two people are independent.

Let \(A\) be the event that the \(k\) people all have distinct birthdays; then the probability of event \(A\) is

\[ P(A)=\prod_{i=0}^{k-1}\frac{n-i}{n} \]

The probability that at least two people share a birthday is \(P(\overline A)=1-P(A)\). By the problem statement \(P(\overline A)\ge\frac{1}{2}\), so we have

\[ P(A)=\prod_{i=0}^{k-1}\frac{n-i}{n} \le \frac{1}{2} \]

From the inequality \(1+x\le \mathrm{e}^x\) we get

\[ P(A) \le \prod_{i=1}^{k-1}\exp\left({-\frac{i}{n}}\right)=\exp \left({-\frac{k(k-1)}{2n}}\right) \]

Therefore

\[ \exp\left({-\dfrac{k(k-1)}{2n}}\right) \le \frac{1}{2}\implies P(A) \le \frac{1}{2} \]

Substituting \(n=365\), we solve \(k\geq 23\). So at least \(23\) people in a room make the probability that two of them share a birthday reach \(50\%\); since this mathematical fact is very counterintuitive, it is called a paradox.

When \(k>56\) and \(n=365\), the probability that two people have the same birthday exceeds \(99\%\)1. Thus, when a year has \(n\) days and there are \(\frac{1}{2}(\sqrt{8n\ln 2+1}+1)\approx \sqrt{2n\ln 2}\) people in the room, the probability that at least two of them share a birthday is about \(50\%\).

Similarly one can compute that, if a sequence of birthdays is chosen uniformly at random, the expected number of people needed until the first repeated birthday is also \(O(\sqrt n)\). Let this number of people be \(X\); then

\[ E(X) = \sum_{x=0}^{n}P(X\ge x+1) = \sum_{x=0}^n\frac{n!}{(n-x)!n^x} = \sqrt{\frac{\pi n}{2}}+\frac23+o(1). \]

This suggests that if we can choose a sequence of numbers at random, the expected sample size needed for a repeated number to appear is also \(O(\sqrt n)\).

Finding a divisor using the greatest common divisor

Actually constructing a sequence of random numbers modulo \(p\) is not realistic, because \(p\) is exactly what we need to find. So we generate a pseudorandom sequence \(\{x_i\}\) via \(f(x)=(x^2+c)\bmod N\): pick a random \(x_1\) and let \(x_2=f(x_1),\ x_3=f(x_2),\ \dots,\ x_i=f(x_{i-1})\), where \(c\in[1,N)\) is a randomly chosen constant.

The function chosen here is easy to compute and often generates fairly random sequences. But it is not completely random. For example, let \(N=50,\ c=6,\ x_1=1\); the data generated by \(f(x)\) are

\[ 1, 7, 5, 31, 17, 45, 31, 17, 45, 31,\dots \]

We can see that after \(x_4\) the data cycle among \(31,17,45\). If these numbers are arranged as in the figure below, the picture looks very much like a \(\rho\), which is why the algorithm is named rho.

More importantly, such a function indeed provides a self-map on \(\mathbf Z_p\). That is, it satisfies the property: if \(x\equiv y\pmod p\), then \(f(x)\equiv f(y)\pmod p\).

Proof

If \(x\equiv y\pmod p\), then \(x^2+c\equiv y^2+c\pmod p\). Note that \(f(x)=x^2+c-k_xN\), where \(k_x\) is an integer depending on \(x\), and \(p\mid N\), so \(f(x)\equiv x^2+c\pmod p\), and hence \(f(x)\equiv f(y)\pmod p\).

As a sequence obtained by repeatedly iterating a pseudorandom self-map on \(\mathbf Z_p\), \(\{x_n\bmod p\}\) repeats within expected time \(O(\sqrt p)\). As soon as we observe such a repetition \(x_i\equiv x_j\pmod p\), we can obtain a non-trivial divisor of \(N\) from \(\gcd(|x_i-x_j|,N)\). Note that since \(p\) is unknown, we have no way to detect the repetition directly; a simple criterion is precisely that \(\gcd(|x_i-x_j|,N)\) is strictly greater than one.

This algorithm does not always succeed, because \(\gcd(|x_i-x_j|,N)\) may equal \(N\). That is, \(x_i\equiv x_j\pmod N\). In this case, when \(\{x_n\bmod p\}\) repeats for the first time, \(\{x_n\}\) happens to repeat as well. We have not obtained a non-trivial divisor. Moreover, once \(\{x_n\}\) starts cycling, further iteration is pointless, because afterwards only this cycle repeats. The algorithm should report that the factorization failed, and the factorization must be redone with a different choice of \(c\) in \(f(x)\).

By the analysis above, in theory any function \(f(x)\) that satisfies \(\forall x \equiv y \pmod p, f(x) \equiv f(y) \pmod p\) and guarantees a certain pseudorandomness (for example, certain polynomial functions) can be used here. In practice, mainly \(f(x)=x^2+c\ (c\neq 0,-2)\) is used.2

Implementation

The algorithm we need to implement must quickly determine during the iteration whether \(\{x_n\bmod p\}\) has already repeated. Viewing \(f\) as the edges of a directed graph with vertex set \(\mathbf Z_p\), what we actually need to implement is a cycle detection algorithm, except that the equality check is replaced by checking whether \(\gcd(|x_i-x_j|,N)\) is greater than one.

Floyd's cycle detection

Suppose two people are racing: A is fast and B is slow. After some time, A will certainly meet B, and at the meeting the total distance run by A minus the total distance run by B is certainly a multiple of the lap length.

Let \(a=f(0),b=f(f(0))\); in each step update \(a=f(a),b=f(f(b))\), and just check whether \(a\) and \(b\) become equal during the updates; if they do, a cycle has appeared.

In each step we let \(d=\gcd(|x_i-x_j|,N)\) and check whether \(d\) satisfies \(1< d< N\); if so, we can directly return \(d\). If \(d=N\), then \(\{x_i\}\) has already formed a cycle, and once a cycle is formed we cannot continue, so we directly return \(N\) itself, and in subsequent operations adjust the random constant \(c\) and factor again.

Pollard's rho algorithm based on Floyd's cycle detection 
ll Pollard_Rho(ll N) {
  if (N == 4) return 2;  // since we jump two steps at the start, 4 needs a special case
  ll c = rand() % (N - 1) + 1;
  ll t = f(0, c, N);
  ll r = f(f(0, c, N), c, N);
  while (t != r) {
    ll d = gcd(abs(t - r), N);
    if (d > 1) return d;
    t = f(t, c, N);
    r = f(f(r, c, N), c, N);
  }
  return N;
}

import random


def Pollard_Rho(N):
    if N == 4:
        return 2  # since we jump two steps at the start, 4 needs a special case
    c = random.randint(1, N - 1)
    t = f(0, c, N)
    r = f(f(0, c, N), c, N)
    while t != r:
        d = gcd(abs(t - r), N)
        if d > 1:
            return d
        t = f(t, c, N)
        r = f(f(r, c, N), c, N)
    return N

Brent's cycle detection

In fact, Floyd's cycle detection algorithm can be improved by a constant factor. Brent's cycle detection starts from \(k=1\) and increments \(k\); in round \(k\), A waits in place while B moves forward \(2^k\) steps. If B meets A during this process, a cycle has been found; otherwise A teleports to B's position and the next round begins.

It can be proved3 that the number of calls to \(f\) needed before a cycle is found this way is never greater than in Floyd's cycle detection algorithm. The tests in the original paper show that the average time needed by Brent's cycle detection is \(24\%\) less than that of Floyd's cycle detection.

Doubling optimization

Whether Floyd's or Brent's cycle detection is used, the number of iterations is \(O(\sqrt p)\). But using \(\gcd\) in every iteration to check for a cycle slows down the algorithm. The number of \(\gcd\) computations can be reduced by accumulating a product.

Simply put, if \(\gcd(a,N)>1\), then \(\gcd(ab\bmod N,N)=\gcd(ab,N)>1\) holds for any \(b\in\mathbf N_+\). That is, if we compute \(\gcd(\prod |x_i-x_j| \bmod N,N)>1\), then necessarily some pair \((x_i,x_j)\) satisfies \(\gcd(|x_i-x_j|,N)>1\). If the product becomes zero at some point, the factorization fails; exit and return \(N\) itself.

If a \(\gcd\) is computed every \(k\) pairs, the complexity of the algorithm drops to \(O(\sqrt p+k^{-1}\sqrt p\log N)\), where \(\log N\) is the cost of a single \(\gcd\) computation. Note that when \(k\) and \(\log N\) are roughly of the same order, we get an expected complexity of \(O(\sqrt p)\). In concrete implementations, \(k=127\) is mostly chosen.

Here we provide an implementation of Pollard's rho algorithm with Brent's cycle detection plus the doubling optimization.

Implementation 
ll Pollard_Rho(ll x) {
  ll t = 0;
  ll c = rand() % (x - 1) + 1;
  ll s = t;
  int step = 0, goal = 1;
  ll val = 1;
  for (goal = 1;; goal <<= 1, s = t, val = 1) {
    for (step = 1; step <= goal; ++step) {
      t = f(t, c, x);
      val = val * abs(t - s) % x;
      // if val is 0, exit and factor again
      if (!val) return x;
      if (step % 127 == 0) {
        ll d = gcd(val, x);
        if (d > 1) return d;
      }
    }
    ll d = gcd(val, x);
    if (d > 1) return d;
  }
}

from random import randint
from math import gcd


def Pollard_Rho(x):
    c = randint(1, x - 1)
    s = t = f(0, c, x)
    goal = val = 1
    while True:
        for step in range(1, goal + 1):
            t = f(t, c, x)
            val = val * abs(t - s) % x
            if val == 0:
                return x  # if val is 0, exit and factor again
            if step % 127 == 0:
                d = gcd(val, x)
                if d > 1:
                    return d
        d = gcd(val, x)
        if d > 1:
            return d
        s = t
        goal <<= 1
        val = 1

Complexity

The expected number of iterations in Pollard's rho algorithm is \(O(\sqrt p)\), where \(p\) is the smallest prime factor of \(N\). Whether the concrete implementation uses Floyd's or Brent's cycle detection, without the doubling optimization the expected complexity is \(O(\sqrt p\log N)\); with the doubling optimization, an expected complexity of approximately \(O(\sqrt p)\) is obtained.

It is worth mentioning that the analysis above is based on a completely random self-map, whereas Pollard's rho algorithm actually uses a pseudorandom function, so the algorithm has no rigorous complexity analysis, but in practice it usually runs quite fast.

Example problem: the largest prime factor of a number

Example problem: P4718【模板】Pollard-Rho 算法 (Template: Pollard's rho algorithm)

For a number \(n\), use the Miller–Rabin algorithm to test whether it is prime; if so, it can be returned directly, otherwise use Pollard's rho algorithm to find a divisor \(p\) and remove the factor \(p\) from \(n\). Then recursively factor \(n\) and \(p\), use Miller–Rabin to check whether a prime factor has appeared, and update max_factor to obtain the largest prime factor. Since the data of this problem are very large, Floyd's cycle detection is not enough, so the doubling optimization is used here.

Implementation 
#include <algorithm>
#include <cstdlib>
#include <ctime>
#include <iostream>

using namespace std;
using ll = long long;
using ull = unsigned long long;

int t;
ll max_factor, n;

ll gcd(ll a, ll b) {
  if (b == 0) return a;
  return gcd(b, a % b);
}

ll bmul(ll a, ll b, ll m) {  // fast multiplication
  ull c = (ull)a * (ull)b - (ull)((long double)a / m * b + 0.5L) * (ull)m;
  if (c < (ull)m) return c;
  return c + m;
}

ll qpow(ll x, ll p, ll mod) {  // fast exponentiation
  ll ans = 1;
  while (p) {
    if (p & 1) ans = bmul(ans, x, mod);
    x = bmul(x, x, mod);
    p >>= 1;
  }
  return ans;
}

bool Miller_Rabin(ll p) {  // primality test
  if (p < 2) return false;
  if (p == 2) return true;
  if (p == 3) return true;
  ll d = p - 1, r = 0;
  while (!(d & 1)) ++r, d >>= 1;  // make d odd
  for (ll k = 0; k < 10; ++k) {
    ll a = rand() % (p - 2) + 2;
    ll x = qpow(a, d, p);
    if (x == 1 || x == p - 1) continue;
    for (int i = 0; i < r - 1; ++i) {
      x = bmul(x, x, p);
      if (x == p - 1) break;
    }
    if (x != p - 1) return false;
  }
  return true;
}

ll Pollard_Rho(ll x) {
  ll s = 0, t = 0;
  ll c = (ll)rand() % (x - 1) + 1;
  int step = 0, goal = 1;
  ll val = 1;
  for (goal = 1;; goal *= 2, s = t, val = 1) {  // doubling optimization
    for (step = 1; step <= goal; ++step) {
      t = (bmul(t, t, x) + c) % x;
      val = bmul(val, abs(t - s), x);
      if ((step % 127) == 0) {
        ll d = gcd(val, x);
        if (d > 1) return d;
      }
    }
    ll d = gcd(val, x);
    if (d > 1) return d;
  }
}

void fac(ll x) {
  if (x <= max_factor || x < 2) return;
  if (Miller_Rabin(x)) {              // if x is prime
    max_factor = max(max_factor, x);  // update the answer
    return;
  }
  ll p = x;
  while (p >= x) p = Pollard_Rho(x);  // use the algorithm
  while ((x % p) == 0) x /= p;
  fac(x), fac(p);  // keep factoring x and p
}

int main() {
  cin >> t;
  while (t--) {
    srand((unsigned)time(NULL));
    max_factor = 0;
    cin >> n;
    fac(n);
    if (max_factor == n)  // the largest prime factor is n itself
      cout << "Prime\n";
    else
      cout << max_factor << '\n';
  }
  return 0;
}
