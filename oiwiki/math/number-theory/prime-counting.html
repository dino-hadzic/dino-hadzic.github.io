Ovaj članak predstavlja sublinearne algoritme za problem prebrojavanja prostih brojeva (prime counting). Problem prebrojavanja prostih brojeva sastoji se u izračunavanju broja prostih brojeva koji ne premašuju \(n\), tj. \(\pi(n)\). Za \(n\sim 10^8\) to se može izračunati sitom u vremenu \(\tilde O(n)\). Međutim, kada je \(n \sim 10^{10}\) ili čak veći, sito i drugi algoritmi temeljeni na nabrajanju teško su primjenjivi. Za tu situaciju ovaj članak predstavlja niz algoritama koje je razmjerno lako implementirati, a čija je vremenska složenost uglavnom između \(\tilde O(n^{2/3})\) i \(\tilde O(n^{3/4})\).

Problem prebrojavanja prostih brojeva poseban je slučaj problema prefiksnih suma potencija prostih brojeva. Lucyjev algoritam predstavljen u ovom članku može se izravno poopćiti na prefiksne sume potencija prostih brojeva, a to poopćenje čini dio algoritama za sumiranje multiplikativnih funkcija kao što je Min_25 sito.

Savjet

Ovaj članak nudi mnogo algoritama za prebrojavanje prostih brojeva. Radi čitljivosti ni na jednom nije napravljeno mnogo optimizacija konstante. Ti se algoritmi razlikuju po vremenskim i prostornim performansama te težini implementacije, pa čitatelj može odabrati prikladan algoritam prema vlastitim potrebama. Za podatke u rasponu \(10^{11}\sim 10^{13}\) algoritam iz odjeljka Lehmerovo pravilo odsijecanja često je već dovoljno učinkovit, a implementacija mu je razmjerno jednostavna; optimizirani Lucyjev algoritam nešto je složeniji za implementaciju, ali ima izvrsne vremenske i prostorne performanse. Za manje raspone podataka izvorni Lucyjev algoritam najjednostavniji je za implementaciju i ima širu primjenu u sumiranju multiplikativnih funkcija.

Osnovni pojmovi i oznake

U ovom članku koristit će se sljedeće oznake:

  • \(\mathbf P\) je skup (pozitivnih) prostih brojeva, a \(p_a\) je \(a\)-ti najmanji prosti broj (indeksi počinju od \(1\)). Radi jednostavnosti izlaganja dodatno stavljamo \(p_0=1\). U ovom članku slova \(p\) i \(q\) uvijek označavaju proste brojeve.
  • \(\operatorname{lpf}(n)\) označava najmanji prosti faktor broja \(n\). Dodatno stavljamo \(\operatorname{lpf}(1)=+\infty\).
  • \(D(x) = \{\lfloor x/i\rfloor : i = 1,2,\dots,\lfloor x\rfloor\}\). Njegova su svojstva detaljno opisana u odjeljku Svojstva blokovskog dijeljenja po cjelobrojnom kvocijentu.
  • \(\pi(x)\) je broj prostih brojeva koji ne premašuju \(x\).
  • \(\varphi(x,a)=\#\{n \in\mathbf N_+ : n \le x,~ (p\mid n \implies p > p_a)\}\) je broj pozitivnih cijelih brojeva koji ne premašuju \(x\) i čiji su svi prosti faktori veći od \(p_a\).
  • \(P_k(x,a)=\#\{n\in\mathbf N_+ : n \le x,~ n = q_1q_2\cdots q_k,~ \forall i(q_i > p_a)\}\) je broj pozitivnih cijelih brojeva koji ne premašuju \(x\), imaju točno \(k\) prostih faktora (brojeći kratnost) i svi su im prosti faktori veći od \(p_a\).
  • \(S(x,a)\) je broj cijelih brojeva većih od \(1\) i ne većih od \(x\) koji u Eratostenovu situ preostaju nakon prosijavanja prvih \(a\) prostih brojeva.

Te funkcije imaju sljedeća jednostavna svojstva:

  • \(\varphi(x,0) = \lfloor x\rfloor\).
  • \(S(x,a) = \varphi(x,a) + \min\{\pi(x),a\} - 1\).
  • \(\varphi(x,a) = \sum_{k=0}^{\infty} P_k(x,a)\).
  • \(P_0(x,a) = 1\).
  • \(P_1(x,a) = \pi(x) - \min\{\pi(x),a\}\).
  • Za \(x < p_{a+1}^k\) vrijedi \(P_k(x,a) = 0\).

Sva se ta svojstva lako izvode iz definicija.

Meissel–Lehmerov algoritam

Uvrštavanjem izraza za \(P_0\) i \(P_1\) u razvoj od \(\varphi\) i jednostavnim sređivanjem dobiva se

\[ \pi(x) = \varphi(x,a) + a - 1 - P_2(x,a) - P_3(x,a) - \cdots. \]

To znači da se \(\pi(x)\) može dobiti izračunavanjem vrijednosti \(\varphi(x,a)\), pri čemu je pogreška zadana nizom članova \(P_k\). Kako vrijednost \(a\) raste, broj članova pogreške postupno se smanjuje. Posebno, za \(a = \pi(\sqrt{x})\) vrijedi \(P_2(x,a)=P_3(x,a)=\cdots=0\), to jest

\[ \pi(x) = \varphi(x,\pi(\sqrt{x})) + \pi(\sqrt{x}) - 1. \]

Za \(\pi(x^{1/3}) \le a < \pi(\sqrt{x})\) član \(P_2(x,a)\) nije nula, ali su svi sljedeći članovi i dalje nula, tj.

\[ \pi(x) = \varphi(x,a) + a - 1 - P_2(x,a). \]

Slično, za \(\pi(x^{1/4}) \le a < \pi(x^{1/3})\) oba su člana \(P_2(x,a)\) i \(P_3(x,a)\) različita od nule, i tako dalje. Ukratko, pomoću tih relacija izračunavanje \(\pi(x)\) može se svesti na izračunavanje \(\varphi(x,a)\) i članova \(P_k(x,a)\). Svi algoritmi koji se oslanjaju na te relacije mogu se nazvati Meissel–Lehmerovim algoritmima.

Za \(\varphi(x,a)\) vrijedi sljedeća rekurzivna relacija:

\[ \varphi(x,a) = \varphi(x,a - 1) - \varphi\left(\dfrac{x}{p_a},a-1\right). \]

Prirodno, rubni je uvjet zadan s \(\varphi(x,0) = \lfloor x\rfloor\).

Primjer

Uzmimo za primjer \(x=30,a=2\) (\(p_a=3\)); jedan korak rekurzije prikazan je na slici:

Na slici zelena polja označavaju cijele brojeve čiji su svi prosti faktori veći od \(p_a=3\) (\(1\) nema prostih faktora, pa se također ubraja), a zelena i narančasta polja zajedno označavaju cijele brojeve čiji su svi prosti faktori veći od \(2\). Prvih ima \(\varphi(x,a)=\varphi(30,2)=10\), a drugih \(\varphi(x,a-1)=\varphi(30,1)=15\).

Razlika između njih upravo je narančasti dio: brojevi djeljivi s \(3\) koji nemaju prostog faktora manjeg od \(3\). Stoga su svi narančasti brojevi oblika \(n=3k\). Budući da je svaki prosti faktor od \(k\) ujedno i prosti faktor od \(n\), ni \(k\) nema prostog faktora manjeg od \(3\), tj. i sam \(k\) pada u zeleno ili narančasto polje; nadalje, iz \(3k\le 30\) slijedi \(k\le\lfloor x/p_a\rfloor=10\). Vrijedi i obrnuto: prosti faktori od \(n=3k\) nisu ništa drugo nego \(3\) i prosti faktori od \(k\), pa čim je \(k\le 10\) i nema prostog faktora manjeg od \(3\), \(n\) pada u narančasti dio. Stoga su oni u bijekciji.

Tablica je namjerno složena u \(30/3=10\) stupaca, tako da je prvi redak upravo \(1,\dots,10\). Takvi \(k\) upravo su zelena i narančasta polja unutar isprekidanog okvira, ukupno njih \(\varphi(x/p_a,a-1)=\varphi(30/3,1)=5\); oznaka \(3\times k\) u gornjem desnom kutu svakog narančastog polja pokazuje pripadni \(k\). Stoga je

\[ \varphi(x,a) = \varphi(x,a-1) - \varphi\left(\left\lfloor\dfrac{x}{p_a}\right\rfloor,a-1\right). \]

To jest, \(\varphi(30,2)=\varphi(30,1)-\varphi(30/3,1)=15-5=10\).

Stablo rekurzije koje nastaje rekurzivnim računanjem po toj relaciji binarno je stablo. Potpunim razvojem dobiva se

\[ \varphi(x,a) = \sum_{n\mid p_1p_2\cdots p_a} \mu(n)\left\lfloor\dfrac{x}{n}\right\rfloor. \]

Iz toga slijedi da je broj listova tog binarnog stabla jednak broju svih \(p_a\)-glatkih brojeva bez kvadratnih faktora (tj. cijelih brojeva koji nemaju prostog faktora većeg od \(p_a\)) koji ne premašuju \(x\), a taj je broj \(\Theta(x)\)1. To znači da je složenost izravnog rekurzivnog računanja i dalje \(\Omega(x)\). Za brzo računanje to binarno stablo treba prikladno odsjeći (pruning). Glavna razlika među raznim Meissel–Lehmerovim algoritmima upravo je u načinu odsijecanja. U literaturi se oni nazivaju pravilima odsijecanja (truncation rule). U nastavku će ovaj odjeljak predstaviti nekoliko jednostavnih pravila odsijecanja.

Na kraju treba obraditi \(P_k(x,a)\). Uzmimo za primjer \(P_2(x,a)\):

\[ \begin{aligned} P_2(x,a) &= \sum_{i,j:~p_a < p_i\le p_j\le x/p_i} 1 = \sum_{i = a+1}^{\pi(\sqrt{x})}\sum_{j=i}^{\pi(x/p_i)} 1 \\ &= \sum_{i = a+1}^{\pi(\sqrt{x})}\left(\pi\left(\dfrac{x}{p_i}\right) - i + 1\right)\\ &= \sum_{i = a+1}^{\pi(\sqrt{x})}\pi\left(\dfrac{x}{p_i}\right)-\dfrac{1}{2}\left(\pi(\sqrt{x})+a-1\right)\left(\pi(\sqrt{x}) - a\right). \end{aligned} \]

To znači da se izračunavanje \(P_2(x,a)\) može svesti na izračunavanje nekoliko vrijednosti \(\pi(x/p)\). Za \(k>2\) i dalje postoje slični izrazi sa sumama, ali broj razina sumiranja raste, pa postupno prestaju biti praktični. Uobičajeni algoritmi većinom uzimaju \(a\ge\pi(x^{1/3})\) kako bi izbjegli računanje daljnjih članova \(P_k\). U praksi se vrijednosti \(\pi(x/p)\) za ovaj dio obično predobrađuju sitom.

Matematičari su se vrlo rano bavili problemom izravnog računanja \(\pi(x)\) bez nabrajanja. Legendre je dao gornji izraz za \(a=\pi(\sqrt{x})\), ali potpuni razvoj od \(\varphi(x,a)\) daje previše članova da bi se mogao stvarno upotrijebiti za računanje. Godine 1870. Meissel je predložio računanje pri \(a=\pi(x^{1/3})\), čime se smanjuje broj članova u razvoju od \(\varphi(x,a)\), a pogreška se i dalje lako računa. Godine 1959. Lehmer je taj postupak dodatno poboljšao i pojednostavnio. Godine 1985. pravilo odsijecanja koje su predložili Lagarias, Miller i Odlyzko prvi je put tu ideju dovelo do sublinearne složenosti, s vremenskom složenošću \(\tilde O(x^{2/3})\) i prostornom složenošću \(\tilde O(x^{1/3})\). Poslije su Deléglise i Rivat (1996), Gourdon (2001), Staple (2015) i drugi u tom smjeru napravili daljnje optimizacije i dodatno smanjili potenciju od \(\log x\) u složenosti. Treba napomenuti da su ti algoritmi, kako bi zadržali dobru prostornu složenost i mogli obrađivati probleme veličine \(x\sim 10^{26}\), obično prilično složeni. Ovaj će odjeljak znatno pojednostavniti detalje i predstaviti samo neke jednostavne ideje za optimizaciju. Time se žrtvuje nešto vremenske i prostorne složenosti, ali kôd je lakše implementirati. Čitatelji koje zanima izvorna obrada mogu je samostalno proučiti u literaturi navedenoj na kraju članka.

Osim toga, uz metode nabrajanja i kombinatorne metode predstavljene u ovom članku, \(\pi(x)\) se može računati i analitičkim metodama, s vremenskom složenošću \(\tilde O(\sqrt{x})\). No one se ne mogu primijeniti na algoritamskim natjecanjima, pa ih ovaj članak ne obrađuje.

Lehmerovo pravilo odsijecanja

Lehmer (1959) predložio je jedno pravilo odsijecanja. U sljedeća dva slučaja \(\varphi(u,b)\) se više ne razvija:

  1. kada je \(u < p_b\);
  2. kada je \(b = c\), gdje je \(c\) unaprijed odabran mali pozitivan cijeli broj.

U prvom slučaju, prema prethodnoj raspravi, nužno je \(\varphi(u,b)=1\), pa nema što računati. U drugom slučaju treba dodatno izračunati vrijednost \(\varphi(u,c)\). Po definiciji je

\[ \varphi(u,c) = \sum_{n=1}^{u} \prod_{b=1}^{c} [p_b \nmid n]. \]

Budući da je relacija djeljivosti s \(p_b\) periodična s periodom \(p_b\), član sume \(\prod_{b=1}^{c} [p_b \nmid n]\) periodičan je s periodom \(p_c\# = \prod_{b=1}^{c}p_b\). Iskorištavanjem periodičnosti dobiva se

\[ \varphi(u,c) = \left\lfloor\dfrac{u}{p_c\#}\right\rfloor \varphi(p_c\#, c) + \varphi(u \bmod p_c\#, c). \]

Stoga, čim se za \(n=0,1,2,\dots,p_c\#\) rekurzivnom relacijom predobrade sve vrijednosti \(\varphi(n,c)\), vrijednost \(\varphi(u,c)\) u drugom slučaju može se brzo očitati.

Treba napomenuti da, iako ta dva pravila odsijecanja doista povećavaju učinkovitost računanja, asimptotska se složenost algoritma ne poboljšava značajno. Lagarias, Miller i Odlyzko (1985) dokazali su da je u Lehmerovu algoritmu broj listova stabla rekurzije \(\Omega\left(\dfrac{x}{\log^4 x}\right)\), pa je vremenska složenost i dalje \(\tilde\Theta(x)\).

Naravno, prvo Lehmerovo pravilo odsijecanja može se prikladno poboljšati:

\[ \varphi(u,b) = \begin{cases} 1, & u \le p_b,\\ \pi(u) - b + 1, & p_b < u \le p_b^2,\\ \pi(u) -\dfrac{1}{2}\left(\pi(\sqrt{u})+b-2\right)\left(\pi(\sqrt{u}) - b+1\right) + \sum\limits_{i = b+1}^{\pi(\sqrt{u})}\pi\left(\dfrac{u}{p_i}\right), & p_b^2 < u \le p_b^3. \end{cases} \]

Posljednja dva slučaja koriste relacije izvedene ranije. To poboljšanje dodatno smanjuje veličinu stabla rekurzije, ali uvodi više članova \(\pi(u/p)\) koje treba izračunati. Budući da \(u/p\) može dosegnuti najviše \(x/p_{c+1}\), kako bi se smanjilo neučinkovito odsijecanje, može se postaviti gornja granica \(V\) za \(u\) pri kojoj se to pravilo smije aktivirati i unaprijed predobraditi vrijednosti \(\pi(u)\) za \([1,V]\); kada je \(u > V\), i dalje se provodi uobičajena rekurzija.

U nastavku je dana implementacija poboljšanog Lehmerova pravila odsijecanja:

Referentna implementacija 
// Modified from sgtlaugh's codes:
//   https://github.com/sgtlaugh/algovault/blob/master/code_library/fast_prime_counting.cpp
// Submission:
// * https://judge.yosupo.jp/submission/396797 (1e11)
// * https://www.luogu.com.cn/record/295291689 (1e13)
constexpr int V = 20000010;  // tuned for 1e12; at least sqrt{n} + 1.

constexpr int C = 7;
constexpr int N = 50;                            // N >= C must hold.
constexpr int Q = 2 * 3 * 5 * 7 * 11 * 13 * 17;  // = p_C#

std::vector<int> primes;
std::array<int, V> pi{};
std::array<std::array<int, Q + 1>, N> dp{};

// Find the primes and pi below V.
void sieve() {
  std::vector<bool> vis(V);
  for (int x = 2; x < V; ++x) {
    if (!vis[x]) primes.push_back(x);
    for (int p : primes) {
      if (x * p >= V) break;
      vis[x * p] = true;
      if (x % p == 0) break;
    }
  }
  for (int x = 2; x < V; ++x) {
    pi[x] = pi[x - 1] + !vis[x];
  }
}

// Initialization step.
// First sieve, then obtain the value of phi(u, C) for u <= p_C#.
void init() {
  sieve();
  for (int u = 1; u <= Q; ++u) dp[0][u] = u;
  for (int b = 1; b < N; ++b) {
    for (int u = 1; u <= Q; ++u) {
      dp[b][u] = dp[b - 1][u] - dp[b - 1][u / primes[b - 1]];
    }
  }
}

// Recursively find phi with Lehmer's truncation rule.
long long phi(long long u, int b) {
  if (u <= Q && b < N) return dp[b][u];
  if (b == C) return dp[b][u % Q] + (u / Q) * dp[b][Q];
  long long p = primes[b - 1];
  if (u < V && p * p >= u) return pi[u] - b + 1;
  if (p * p * p < u || u >= V) return phi(u, b - 1) - phi(u / p, b - 1);
  int lim = pi[(int)std::sqrt(u + 0.25l)];
  long long res = pi[u] - (lim + b - 2) * (lim - b + 1) / 2;
  for (int i = b; i < lim; ++i) {
    res += pi[u / primes[i]];
  }
  return res;
}

// Meissel-Lehmer with a = pi(n^{1/3}) and Lehmer's truncation rule.
long long lehmer_pi(long long n) {
  if (n < V) return pi[n];
  int sqr = std::sqrt(n + 0.25l);
  int a = std::cbrt(n + 0.25l);
  long long res = phi(n, pi[a]) + pi[a] - 1;
  for (int i = pi[a]; i < pi[sqr]; ++i) {
    res -= lehmer_pi(n / primes[i]) - i;
  }
  return res;
}

Iako je teorijsku složenost te implementacije teško dokazati2, njezina je prednost vrlo mala konstanta i jednostavna implementacija, pa je kôd u praksi vrlo učinkovit. Vrijednosti konstanti \(c,V,N\) i drugih u kodu mogu se prilagoditi stvarnim potrebama.

LMO pravilo odsijecanja

Lagarias, Miller i Odlyzko (1985) predložili su drugo pravilo odsijecanja. Odabere se \(y\) takav da je \(x^{1/3} \le y \le x^{2/5}\) i uzme \(a=\pi(y)\). Tada se u sljedeća dva slučaja \(\varphi(x/n,b)\) više ne razvija:

  1. kada je \(b=c\) i \(n\le y\), gdje je \(c\) unaprijed odabran mali prirodan broj;
  2. kada je \(n > y\).

LMO prvi slučaj naziva običnim listovima, a drugi posebnim listovima.

Prednost je tog pravila odsijecanja u tome što je lako prebrojiti listove. Primijetimo da različiti listovi nužno imaju različite \(n\). Obični listovi uvijek zadovoljavaju \(n \le y\), pa ih ima \(O(y)\). Posebni listovi uvijek zadovoljavaju \(n > y\) i \(\dfrac{n}{\operatorname{lpf}(n)} \le y\). Prema tome, posebni se listovi mogu podijeliti u dvije vrste: \(\operatorname{lpf}(n) < \sqrt{y}\) i \(\operatorname{lpf}(n) \ge \sqrt{y}\). Kod prve vrste nužno je \(\operatorname{lpf}(n) < \sqrt{y}\), pa broj mogućih \(\operatorname{lpf}(n)\) ne premašuje \(\pi(\sqrt{y})\), a za \(\dfrac{n}{\operatorname{lpf}(n)} \le y\) postoji najviše \(y\) izbora, pa broj mogućih \(n\) – tj. ukupan broj listova te vrste – ne premašuje \(y\pi(\sqrt{y})\). Kod druge vrste nužno je \(n=pq\) i \(\sqrt{y} \le p < q \le y\), pa je broj takvih listova najviše \(\dfrac{1}{2}\pi(y)^2\). Spajajući oba slučaja, ukupan je broj posebnih listova \(O\left(\dfrac{y^2}{\log^2x}\right)\).

Za obične listove može se koristiti ista metoda predobrade kao i prije. Za posebne listove, da bi se izračunala vrijednost \(\varphi(x/n,b)\), može se po definiciji shvatiti kao „broj pozitivnih cijelih brojeva ne većih od \(x/n\) čiji je najmanji prosti faktor strogo veći od \(p_b\)”. (Podsjetimo da je ranije postavljeno \(\operatorname{lpf}(1) = +\infty\).) Nakon te pretvorbe svi se upiti u posebnim listovima mogu obraditi offline: predobrade se i sortiraju vrijednosti \(\operatorname{lpf}\) cijelih brojeva u \([1,x/y]\), a zatim se Fenwickovim stablom ažurira i odgovara na upite. Uzimajući u obzir sortiranje offline upita i operacije na Fenwickovu stablu, vremenska je složenost tog postupka

\[ O\left(\dfrac{y^2}{\log^2x}\log \dfrac{y^2}{\log^2x} + \left(\dfrac{x}{y} + \dfrac{y^2}{\log^2x}\right)\log\pi\left(\dfrac{x}{y}\right)\right) = O\left(\dfrac{x}{y}\log x + \dfrac{y^2}{\log x}\right). \]

Osim izračunavanja \(\varphi(x,a)\), koje je posebno, ostatak je izračuna sličan onome u prethodnom odjeljku. Dovoljno je predobraditi vrijednosti \(\pi(u)\) za \([1,x/y]\), a zatim pomoću prethodne relacije izračunati \(P_2(x,a)\); za slučaj \(c > 0\) treba još predobraditi vrijednosti \(\varphi(u,c)\). Napomenimo da, radi potreba offline upita, tijekom rekurzivnog pretraživanja listova treba zabilježiti i predznak ispred svakog lista, tj. vrijednost \(\mu(n)\), kako bi se zbrojili doprinosi. Time se dobiva potpun algoritam.

Vremenska i prostorna složenost tog algoritma obje su \(\tilde O(x^{2/3})\). Ako se uzme \(c = 0\), složenost ostalih dijelova može se zanemariti, pa ukupna složenost algoritma dostiže minimum \(O(x^{2/3}\log^{1/3}x)\) pri \(y = x^{1/3}\log^{2/3}x\). Tada je prostorna složenost algoritma \(O(x^{2/3}\log^{-2/3}x)\). Ako se za \(c\) uzme mali pozitivan cijeli broj, treba uravnotežiti vremenske i prostorne troškove predobrade s poboljšanjem konstante kasnijih upita, ali ukupna se složenost ne mijenja.

struct BIT {
  int n;
  std::vector<int> su;

  BIT(int _n) : n(_n), su(_n + 1) {}

    for (; x <= n; x += (x & (-x))) ++su[x];

  }

// Meissel-Lehmer with LMO's truncation rule and offline queries.
long long lmo_pi(long long n) {
  long long y = std::pow(n, 0.36l);  // tuned for n = 1e12 or 1e13.
  long long s = n / y;
  if (n < 100) s = n;
  // Linear sieve.
  // lpf records the prime rank (0-indexed).
  std::vector<int> primes, lpf(s + 1, -1);
  for (int x = 2; x <= s; ++x) {
    if (lpf[x] == -1) {
      lpf[x] = primes.size();
      primes.push_back(x);
    }
    for (int i = 0; i < (int)primes.size(); ++i) {
      int p = primes[i];
      if (x * p > s) break;
      lpf[x * p] = i;
      if (x % p == 0) break;
    }
  }
  if (n < 100) return primes.size();
  // pi(y).
  int pi_y = std::upper_bound(primes.begin(), primes.end(), y) - primes.begin();
  long long res = pi_y;
  // P2(n,pi(y)) with two pointers.
  int ptr = primes.size() - 1;
  for (int i = pi_y; i < (int)primes.size(); ++i) {
    while (ptr >= i && (long long)primes[i] * primes[ptr] > n) --ptr;
    if (ptr < i) break;
    res -= ptr - i + 1;
  }
  // phi(n,pi(y)).
  std::vector<std::tuple<long long, int, signed char>> queries;
  auto phi = [&](auto&& phi, long long u, int b, signed char sign = 1) -> void {
    if (!u) return;
    if (!b) return (void)(res += u * sign);
    if (u <= s) return (void)queries.emplace_back(u, b, sign);
    phi(phi, u, b - 1, sign);
    phi(phi, u / primes[b - 1], b - 1, -sign);
  };
  phi(phi, n, pi_y);
  std::sort(queries.begin(), queries.end());
  int sz = primes.size(), idx = 2;
  BIT bit(sz);
  for (const auto& query : queries) {
    long long u;
    int b;
    signed char sign;
    std::tie(u, b, sign) = query;
    while (idx <= u) bit.add(sz - lpf[idx++]);
    res += sign * (bit.get(sz - b) + 1);
  }
  queries.clear();
  return res - 1;
}

Usko je grlo to što pri predobradi treba pohraniti informacije o \(\operatorname{lpf}\) za \([1,x/y]\). Zapravo se te informacije koriste samo za kasnije offline upite, i to jednim sekvencijalnim prolazom, pa se sasvim mogu izračunati pri upitu segmentiranim sitom.

Zapravo, izvorni rad nudi način implementacije u potpunosti temeljen na segmentiranom situ. Izračunavanje \(P_2(x,a)\) i \(\varphi(x,a)\) obavlja se unutar segmentiranog sita, čime se dobiva algoritam vremenske složenosti \(\tilde O(x^{2/3})\) i prostorne složenosti \(\tilde O(x^{1/3})\). To zahtijeva da se svi listovi na neki način izravno nabroje i da se offline algoritam preradi u online algoritam. U nastavku predstavljamo jedan jednostavan način implementacije.

Srž je implementacije segmentirano sito: nakon predobrade prostih brojeva u \([1,y]\), interval \([1,x/y]\) dijeli se na blokove duljine \(y\) i na svaki se blok zasebno primjenjuje sito. Pri obradi svakog bloka treba zabilježiti vrijednosti \(\pi(u)\) i \(\varphi(u,b)\) u elementima tog bloka. Budući da su sve te vrijednosti brojači, lako ih je održavati tijekom obrade blokova. Zatim treba pronaći koji upiti padaju u raspon obrade tog bloka. U algoritmu opisanom ranije u ovom odjeljku neka je \(y=\tilde O(x^{1/3})\) i \(c=0\). Tada broj prostih brojeva \(\pi(x)\) ima sljedeći izraz:

\[ \begin{aligned} \pi(x) &= \dfrac{1}{2}\left(\pi(\sqrt{x})+a-2\right)\left(\pi(\sqrt{x}) - a + 1\right) - \sum_{y < p\le\sqrt{x}}\pi\left(\dfrac{x}{p}\right) \\ &\quad +\sum_{n\le y}\mu(n)\varphi\left(\dfrac{x}{n},0\right) + \sum_{n > y,~{n}/{\operatorname{lpf}(n)}\le y,~\operatorname{lpf}(n)\le y}\mu(n)\varphi\left(\dfrac{x}{n},\pi(\operatorname{lpf}(n))-1\right). \end{aligned} \]

Prvi član treba samo vrijednost \(\pi(\sqrt{x})\), koja se može izračunati kada obrada blokova dođe do tog elementa. Drugi član zahtijeva nabrajanje prostih brojeva \(p\) takvih da \(x/p\) pada u trenutačno obrađivani blok; nakon što se odredi interval u kojem se nalazi \(p\), odgovarajući niz prostih brojeva može se dobiti segmentiranim sitom. Budući da interval u kojem je \(p\) ne sadrži elemente veće od \(\sqrt{x}\), to unutarnje segmentirano sito treba samo proste brojeve unutar \([1,x^{1/4}]\). Za treći član dovoljno je nabrojiti elemente u \([1,y]\). Četvrti član zahtijeva nabrajanje prostih brojeva u \([1,y]\) kao \(\operatorname{lpf}(n)\), zatim određivanje raspona vrijednosti \(\dfrac{n}{\operatorname{lpf}(n)}\), pa nabrajanje onih elemenata u tom rasponu čiji prosti faktori nisu manji od \(\operatorname{lpf}(n)\)3; time se mogu izračunati vrijednosti tog dijela listova. Pri računanju doprinosa dijela u trenutačnom bloku može se koristiti Fenwickovo stablo. Tako se, uz zajamčenu prostornu složenost \(\tilde O(x^{1/3})\), i dalje postiže vremenska složenost \(\tilde O(x^{2/3})\). Naravno, implementacija je nešto zamršenija od offline algoritma.

// An implementation of LMO section 3.
// Submission:
// * https://judge.yosupo.jp/submission/397047 (1e11)
// * https://www.luogu.com.cn/record/295493092 (1e13)
// Binary-indexed tree.
struct BIT {
  int n;
  std::vector<int> su;

  void alloc(int _n) {
    n = _n;
    su.assign(_n + 1, 0);
  }

  BIT(int _n = 0) { alloc(_n); }

  void add(int x) {
    for (; x <= n; x += (x & (-x))) ++su[x];
  }

  int get(int x) {
    int res = 0;
    for (; x; x &= x - 1) res += su[x];
    return res;
  }
};

// Meissel-Lehmer with LMO's truncation rule and online queries.
long long lmo_pi(long long n) {
  long long y = std::pow(n, 0.36l);  // tuned for 1e12.
  long long s = n / y;
  long long sqr = std::sqrt(n + 0.25l);
  // Linear sieve for [1,y].
  if (n < 100) y = n;
  // lpf records the prime rank (0-indexed).
  std::vector<int> primes, lpf(y + 1, -1), mu(y + 1);
  mu[1] = 1;
  for (int x = 2; x <= y; ++x) {
    if (lpf[x] == -1) {
      lpf[x] = primes.size();
      primes.push_back(x);
      mu[x] = -1;
    }
    for (int i = 0; i < (int)primes.size(); ++i) {
      int p = primes[i];
      if (x * p > y) break;
      lpf[x * p] = lpf[p];
      mu[x * p] = x % p ? -mu[x] : 0;
      if (x % p == 0) break;
    }
  }
  if (n < 100) return primes.size();
  // The ordinary leaves.
  long long res = 0;
  for (int i = 1; i <= y; ++i) {
    if (mu[i]) res += mu[i] * (n / i);
  }
  // Segmented sieve.
  // Counts from previous blocks. phi[sz] stores the prime counts.
  int sz = primes.size();
  std::vector<int> phi(sz + 1, 0);
  BIT bit;
  auto phi_at = [&](long long v, int i) -> long long {
    return phi[i] + v - bit.get(v);
  };
  for (int id = 0; id * y + 1 <= s; ++id) {
    int ll = id * y + 1;
    int rr = std::min((id + 1) * y, s);
    int len = rr - ll + 1;
    bit.alloc(len);
    std::vector<bool> vis(len);
    for (int i = 0; i < sz; ++i) {
      int p = primes[i];
      // Special leaves.
      int nl = std::max(n / (rr + 1) / p, y / p) + 1;
      int nr = std::min(n / ll / p, y);
      for (int j = nl; j <= nr; ++j) {
        if (mu[j] && lpf[j] > i) {
          res += -mu[j] * phi_at(n / p / j - ll + 1, i);
        }
      }
      // Accumulate this block's info.
      phi[i] = phi_at(len, i);
      // Sieve this block with p.
      for (int x = (ll - 1) / p * p + p; x <= rr; x += p) {
        if (!vis[x - ll]) {
          bit.add(x - ll + 1);
          vis[x - ll] = true;
        }
      }
    }
    // All the remaining in this block are primes.
    // Those prime counts in P2(x,a).
    int nl = std::max(n / (rr + 1) + 1, y + 1);
    int nr = std::min(n / ll, sqr);
    if (nr >= nl) {
      std::vector<bool> vis(nr - nl + 1);
      for (int i = 0; i < sz; ++i) {
        int p = primes[i];
        if ((long long)p * p > nr) break;
        for (int x = (nl - 1) / p * p + p; x <= nr; x += p) {
          vis[x - nl] = true;
        }
      }
      for (int x = nl; x <= nr; ++x) {
        if (!vis[x - nl]) {
          res -= phi_at(n / x - ll + 1, sz);
        }
      }
    }
    // Those constant terms.
    if (ll <= sqr && sqr <= rr) {
      auto pi_sqr = phi_at(sqr - ll + 1, sz);
      res += (pi_sqr + sz - 2) * (pi_sqr - sz + 1) / 2;
    }
    // Accumulate the prime count.
    phi[sz] = id ? phi_at(len, sz) : sz;
  }
  return res;
}

Međutim, implementacija dana u ovom odjeljku dovoljna je za potrebe natjecanja, pa složenije ideje optimizacije Meissel–Lehmerova algoritma ovdje više ne razmatramo.

Lucyjev algoritam

Pri primjeni Meissel–Lehmerova algoritma jedan je od ključnih problema koje treba riješiti prevelika veličina stabla rekurzije za \(\varphi(x,a)\). Razlog je to što se uvjet zaustavljanja rekurzivne relacije za \(\varphi(x,a)\) pojavljuje samo pri \(a=0\). Razmotrimo zamjenu \(\varphi(x,a)\) sa \(S(x,a)\). Prednost je u tome što, ako je \(p_a^2 > x\), prosijavanje prostim brojem \(p_a\) u Eratostenovu situ ne izbacuje nijedan složen broj (jer oni nužno imaju manji prosti faktor), tj. \(S(x,a)=S(x,a-1)\). To omogućuje rano zaustavljanje stabla rekurzije. Za slučaj \(p_a^2\le x\) vrijedi \(a\le\pi(x)\), pa je \(S(x,a) = \varphi(x,a)+a-1\). Nadalje, iz \(a-1\le\pi(x/p_a)\) svi se članovi u rekurzivnoj relaciji za \(\varphi(x,a)\) mogu odgovarajuće zamijeniti sa \(S(\cdot,\cdot)\), čime se dobiva rekurzivna relacija za \(S(x,a)\). Spajajući oba slučaja, rekurzivna relacija za \(S(x,a)\) može se zapisati kao

\[ S(x,a) = S(x,a-1) - [p_a^2 \le x]\left(S\left(\dfrac{x}{p_a},a-1\right)-(a-1)\right). \]

Rubni je uvjet \(S(x,0)=\lfloor x\rfloor -1\). Na kraju, iz relacije

\[ \pi(x) = S(x,\pi(\sqrt{x})), \]

izravno se dobiva vrijednost funkcije prebrojavanja prostih brojeva \(\pi(x)\).

Primjer

Opet za slučaj \(x=30,a=2\), rekurzivna relacija za \(S(x,a)\) prikazana je na slici:

Početni je interval Eratostenova sita \([2,x] = [2,30]\), pa je polje \(1\) nacrtano bijelo i ne sudjeluje u prebrojavanju. Siva su polja složeni brojevi koji su već ranije prosijani, narančasta su polja složeni brojevi prosijani u ovom krugu prostim brojem \(p_a=3\); među preostalim poljima svijetloljubičasta označavaju prethodne proste brojeve, tamnoljubičasto trenutačni prosti broj \(3\), a zelena cijele brojeve koji još nisu prosijani (mogu biti prosti, a mogu biti i složeni, npr. \(25\)). Stoga je \(S(x,a-1)=S(30,1)=15\) zbroj narančastih, ljubičastih i zelenih polja, \(S(x,a)=S(30,2)=11\) zbroj ljubičastih i zelenih polja, a njihova je razlika upravo ona \(4\) narančasta polja.

Slično kao kod \(\varphi(x,a)\), ti su brojevi i dalje oblika \(3k\), a iz \(3k\le 30\) slijedi da \(k\) pada u \([2,\lfloor x/p_a\rfloor] = [2,10]\) unutar isprekidanog okvira (\(k=1\) nije u njemu, i upravo zato sam \(3\) ostaje i ne postaje narančast). Razlika je u tome što \(k\) sada prolazi samo kroz \(3,5,7,9\) (označeno u gornjem desnom kutu svakog narančastog polja): \(k\) mora biti preživjeli iz prethodnog kruga prosijavanja (inače bi \(3k\) bio već odavno prosijan zajedno s \(k\)), tj. \(2,3,5,7,9\) unutar okvira, ukupno njih \(S(x/p_a,a-1)=S(10,1)=5\); od njih još treba ukloniti proste brojeve manje od \(p_a\) – to su upravo prvih \(a-1\) prostih brojeva, ovdje samo \(k=2\) – jer je \(3\times 2=6\) već odavno prosijan s \(2\). Stoga je

\[ S(x,a) = S(x,a-1) - \left(S\left(\left\lfloor\dfrac{x}{p_a}\right\rfloor, a-1\right) - (a-1)\right). \]

To jest \(S(30,2)=S(30,1)-\bigl(S(10,1)-(2-1)\bigr)=15-(5-1)=11\).

Tu je rekurzivnu relaciju lako izračunati dinamičkim programiranjem. Budući da je \(S(x,a)=S(\lfloor x\rfloor,a)\), sva se dijeljenja u rekurzivnoj relaciji mogu shvatiti kao cjelobrojna. Prema svojstvima blokovskog dijeljenja po cjelobrojnom kvocijentu vrijednosti prve dimenzije u dinamičkom programiranju nužno su u skupu \(D(x)\), kojih ima samo \(\Theta(\sqrt{x})\). Štoviše, zbog posebnog oblika rekurzivne relacije vrijednosti \(S(\cdot,a)\) mogu se pohraniti u jednom polju duljine \(|D(x)|\); za svaki \(a\) prolaze se elementi skupa \(D(x)\) od većih prema manjima i polje se ažurira prema rekurzivnoj relaciji, sve dok element ne postane strogo manji od \(p_a^2\). Dovoljno je \(\pi(\sqrt{x})\) ažuriranja da se dobije konačan rezultat.

Prostorna je složenost algoritma očito \(O(x^{1/2})\). Što se tiče vremenske složenosti, složenost je predobrade \(O(x^{1/2})\), a složenost dijela s dinamičkim programiranjem zadana je s

\[ I = \sum_{a=1}^{\pi(\sqrt{x})}|\{u\in D(x) : u \ge p_a^2\}| \]

To se može procijeniti u dva dijela. Za \(a\in[1,\pi(x^{1/4})]\) član sume ne premašuje \(|D(x)|\), pa taj dio sume ne premašuje \(\pi(x^{1/4})|D(x)|\), što je \(O(x^{3/4}\log^{-1}x)\). Za \(a\in(\pi(x^{1/4}),\pi(\sqrt{x})]\) vrijedi \(p_a^2 > \sqrt{x}\); iz strukture skupa \(D(x)\) vidi se da je tih elemenata točno \(\lfloor x/p_a^2\rfloor\). Odatle, u kombinaciji s teoremom o prostim brojevima \(p_a\sim a\log a\), dobiva se

\[ \sum_{a=\pi(x^{1/4})+1}^{\pi(\sqrt{x})}\dfrac{x}{p_a^2} \in O\left(\int_{\pi(x^{1/4})}^{+\infty}\dfrac{x}{a^2\log^2a}da\right) = O\left(\dfrac{x^{3/4}}{\log x}\right). \]

Zbrajanjem obaju dijelova vidi se da je ukupna vremenska složenost algoritma \(O(x^{3/4}\log^{-1}x)\).

U konkretnoj implementaciji korak predobrade prostih brojeva ne većih od \(\sqrt{x}\) može se spojiti s postupkom dinamičkog programiranja. Dovoljno je od manjih prema većima nabrajati sve cijele brojeve \(u\) u intervalu \([2,\sqrt{x}]\) i provjeravati uvjet \(S(u,\pi(u-1)) \neq S(u-1,\pi(u-1))\) da bi se pronašli svi prosti brojevi u intervalu; kada je uvjet ispunjen, treba izvesti prijelaz stanja. Razlog je to što je, kada nabrajanje dođe do \(u\), već obavljen prijelaz na \(S(\cdot,\pi(u-1))\), pa je \(\pi(u) = S(u,\pi(u-1))\) i \(\pi(u-1) = S(u-1,\pi(u-1))\), a ispunjenost navedenog uvjeta nužno znači da je \(u\) prost. Osim toga, vrijednost \(a-1\) u jednadžbi prijelaza stanja također je dana sa \(S(u-1,\pi(u-1))\), pa je nije potrebno zasebno održavati. Time se dobiva sljedeća implementacija:

// Lucy's Quotient DP to find pi.
long long lucy_pi(long long n) {
  int s = std::sqrt(n + 0.25l);
  // D(n) = {floor(n/x): x=1,2,...,n}
  std::vector<long long> d;
  for (long long l = 1, r; l <= n; l = r + 1) {
    r = n / (n / l);
    d.push_back(r);
  }
  int m = d.size();
  auto id = [&](long long x) -> int { return x <= s ? x - 1 : m - n / x; };
  // Quotient DP.
  std::vector<long long> dp(m);
  for (int j = 0; j < m; ++j) dp[j] = d[j] - 1;
  for (int p = 2; p <= s; ++p) {
    if (dp[p - 1] == dp[p - 2]) continue;  // Only primes can survive.
    for (int j = m - 1; d[j] >= (long long)p * p; --j) {
      dp[j] -= dp[id(d[j] / p)] - dp[p - 2];
    }
  }
  return dp.back();
}

Taj je algoritam jednostavan za implementaciju; iako mu je vremenska složenost nešto lošija, zbog vrlo male konstante izvrsno se ponaša za manje veličine podataka. Još je važnije da, budući da \(\pi(x)=S(x,a)\) vrijedi za sve \(a\ge \pi(\sqrt{x})\), algoritam kao nusproizvod zapravo dobiva vrijednosti \(\pi(\cdot)\) u svim elementima skupa \(D(x)\). To je svojstvo osobito važno u problemima sumiranja multiplikativnih funkcija; njegovo poopćenje i primjene razmatrat ćemo poslije.

Optimizacija Fenwickovim stablom

Pomoću Fenwickova stabla lako je vremensku složenost Lucyjeva algoritma sniziti s \(\tilde O(x^{3/4})\) na \(\tilde O(x^{2/3})\).

U tu se svrhu uzme realan broj \(y\in (\sqrt{x},x]\). Trenutačno stanje \(S(\cdot,a)\) održava se u dva dijela: dio veći od \(y\) i dalje se računa rekurzivno prema prethodnoj rekurzivnoj relaciji; dio ne veći od \(y\) održava se Eratostenovim sitom, a Fenwickovim se stablom ažuriraju i očitavaju trenutačne vrijednosti \(S(\cdot,a)\).

Prostorna je složenost algoritma očito \(O(y)\). Za izračun vremenske složenosti treba razmotriti sljedeća tri dijela: u dijelu s Eratostenovim sitom svaki prosijani složen broj zahtijeva jedno ažuriranje Fenwickova stabla, ukupno \(O(y)\) složenih brojeva, pa je ukupan vremenski trošak \(O(y\log y)\); za \(p_a^2 \le y\) prijelaz stanja u odgovarajućem krugu treba izvesti \(O(x/y)\) puta, pri čemu je svaki upit pri prijelazu \(O(\log y)\), a takvih je krugova ukupno \(O(\pi(\sqrt{y}))\), pa je ukupan vremenski trošak

\[ O\left(\pi(\sqrt{y})\dfrac{x}{y}\log y\right) = O\left(\dfrac{x}{\sqrt{y}}\right) \]

Na kraju, za \(p_a^2 > y\) prijelaz stanja u odgovarajućem krugu treba izvesti \(O(x/p_a^2)\) puta, pa je metodom iz prethodnog pododjeljka ukupan vremenski trošak

\[ O\left(\sum_{a=\pi(\sqrt{y})+1}^{\pi(\sqrt{x})}\dfrac{x}{p_a^2}\log y\right) = O\left(\dfrac{x}{\sqrt{y}}\right) \]

Zbrajanjem triju dijelova i stavljanjem \(y = x^{2/3}\log^{-2/3}x\) dobiva se ukupna vremenska složenost \(O(x^{2/3}\log^{1/3}x)\). Tada je i prostorna složenost \(\tilde O(x^{2/3})\).

// Submission:
// * https://judge.yosupo.jp/submission/397277 (1e11)
// * https://www.luogu.com.cn/record/295680548 (1e13, TLE)
// Binary-indexed tree.
struct BIT {
  int n;
  std::vector<int> su;

  BIT(int _n) : n(_n), su(_n + 1) {}

  void add(int x) {
    for (; x <= n; x += (x & (-x))) ++su[x];
  }

  int get(int x) {
    int res = 0;
    for (; x; x &= x - 1) res += su[x];
    return res;
  }
};

// Lucy's Quotient DP to find pi, with BIT optimization.
long long lucy_pi(long long n) {
  if (n <= 1) return 0;
  int s = std::sqrt(n + 0.25l);
  int y = std::pow(n / std::log(n), 2.0l / 3);
  y = std::max(y, s + 1);
  // D(n) = {floor(n/x): x=1,2,...,n}
  std::vector<long long> d;
  for (long long l = 1, r; l <= n; l = r + 1) {
    r = n / (n / l);
    d.push_back(r);
  }
  int m = d.size();
  auto id = [&](long long x) -> int { return x <= s ? x - 1 : m - n / x; };
  // Quotient DP.
  std::vector<bool> vis(y + 1);
  BIT bit(y);
  std::vector<long long> dp(m);
  for (int j = 0; j < m; ++j) dp[j] = d[j] - 1;
  auto eval = [&](long long x) -> long long {
    return x <= y ? x - 1 - bit.get(x) : dp[id(x)];
  };
  for (long long p = 2; p * p <= n; ++p) {
    if (vis[p]) continue;
    auto a_1 = eval(p - 1);
    auto lim = n / std::max(p * p, (long long)y);
    for (int i = 1; i <= lim; ++i) {
      dp.end()[-i] -= eval(n / (p * i)) - a_1;
    }
    // Sieve.
    for (auto x = p * p; x <= y; x += p) {
      if (!vis[x]) {
        vis[x] = true;
        bit.add(x);
      }
    }
  }
  return dp.back();
}

Treba napomenuti da, iako se teorijska vremenska složenost doista smanjuje, gubitak na konstanti koji uvodi Fenwickovo stablo čini algoritam pri manjim veličinama podataka zapravo sporijim, a pri većim veličinama podataka znatno pogoršana potrošnja memorije ograničava njegovu upotrebu. Stoga ta optimizacija nije osobito praktična.

Daljnje optimizacije

Iako Fenwickovo stablo uspješno optimizira Lucyjev algoritam na \(\tilde O(x^{2/3})\), stvarna učinkovitost i dalje nije visoka. Da bi se dobio učinkovit algoritam, Lucyjev se algoritam može dodatno optimizirati na sljedeće načine (neka je \(z < w < y < x\) i sve su to potencije od \(x\)):

  1. U Lucyjevu algoritmu optimiziranom Fenwickovim stablom vremenski je trošak dijela s Eratostenovim sitom \(O(y\log y)\). Zapravo se u prvih nekoliko krugova prijelaza stanja prosijava golem broj složenih brojeva, pa ih nije potrebno održavati Fenwickovim stablom. Stoga se može odabrati \(z < y\). Kada je \(p_a \le z\), koristi se samo jednadžba prijelaza stanja; kada je \(p_a > z\), uvodi se Fenwickovo stablo za održavanje dijela \(S(\cdot,a)\) koji ne premašuje \(y\). Budući da su pri uvođenju Fenwickova stabla već prosijani svi cijeli brojevi koji sadrže prosti faktor ne veći od \(z\), među preostalim brojevima – obično zvanima \(z\)-grubi brojevi (rough numbers) – onih koji ne premašuju \(y\) ima samo \(O\left(\dfrac{y}{\log z}\right)\)6. Time se vremenski trošak dijela sa sitom snižava na \(O(y)\). Vremenski trošak koji uvode ti početni krugovi prijelaza stanja iznosi \(O(x^{1/2}z/\log x)\).

  2. Ranije opisani Lucyjev algoritam na kraju daje vrijednosti \(\pi(\cdot)\) u svim elementima skupa \(D(x)\). Ako želimo samo vrijednost \(\pi(x)\), mnogi prijelazi stanja nisu potrebni. Na primjer, za izračun vrijednosti \(S(x,a)\) dovoljno je znati vrijednosti \(S(x,a-1)\) i \(S\left(\dfrac{x}{p_a},a-1\right)\); a za izračun tih dviju vrijednosti dovoljno je znati vrijednosti

    \[ S(x,a-2),~ S\left(\dfrac{x}{p_a},a-2\right),~ S\left(\dfrac{x}{p_{a-1}},a-2\right),~ S\left(\dfrac{x}{p_ap_{a-1}},a-2\right) \]

    Odatle se indukcijom vidi da je pri \(i\)-tom krugu prijelaza stanja \(n\) u stanjima \(S\left(\dfrac{x}{n},i\right)\) čije vrijednosti treba znati nužno \(p_i\)-grubi broj. Budući da su \(p_i\)-grubi brojevi zatvoreni na množenje, dovoljno je da se pri svakom prijelazu stanja obrade svi \(p_i\)-grubi brojevi (kao čvorovi-djelitelji) kako bi se osiguralo da su po završetku prijelaza stanja vrijednosti u svim čvorovima za \(p_i\)-grube brojeve ispravne.

    Naravno, skup \(p_i\)-grubih brojeva može se dinamički održavati tijekom prosijavanja7; ili se može ponovno iskoristiti prethodni skup \(z\)-grubih brojeva i njime zamijeniti sve skupove \(p_i\)-grubih brojeva. Naizgled drugi pristup obavlja nešto nepotrebnog posla, ali oba smanjuju složenost dijela s prijelazima stanja za jedan faktor \(\log x\); razlika je samo u konstanti.

  3. Slično kao kod dijela sa sitom, i dio s prijelazima stanja ima problem dodatnog faktora \(\log x\) koji uvodi Fenwickovo stablo. Da bi se smanjio broj upita na Fenwickovu stablu, dio Fenwickova stabla koji se više ne ažurira može se pohraniti u statičko polje. Konkretno, kada prijelazi stanja dođu do \(i\)-tog kruga, vrijednosti \(S(u,i)\) za \(u < p_i^2\) više se ne mijenjaju, pa se mogu očitati i pohraniti.

    Izračunajmo poboljšanje složenosti koje to donosi. Da bi se uključio utjecaj ostalih optimizacija, ovdje pretpostavljamo da se prijelazi stanja sa sitom na Fenwickovu stablu koriste samo za dio \(z < p_i \le w\) i pretpostavljamo \(y \ge w^2\), kako bi donje prebrojavanje bilo tijesno. Budući da \(u\) za koje treba izvesti prijelaz stanja nužno imaju oblik \(\lfloor x/j\rfloor\), dovoljno je prebrojiti odgovarajuće \(j\). Radi jednostavnosti računa zanemarujemo raspravu o rubovima nejednakosti. Budući da je \(u > y\), nužno je \(j < x / y\). Ako je \(jp_i < x / y\), Fenwickovo stablo nije uključeno; ako je \(x / y < jp_i < \min\{x/p_i^2,p_ix/y\}\), upit se može izvesti samo na Fenwickovu stablu; ako je \(\min\{x/p_i^3,x/y\} < j < x/y\), upit se može izvesti u statičkom polju ili na Fenwickovu stablu. Ukupan broj u prvom dijelu iznosi

    \[ \sum_{z < p_i < w}\dfrac{x}{yp_i} = \dfrac{x}{y}\log\dfrac{\log w}{\log z} \in O\left(\dfrac{x}{y}\right). \]

    Ukupan broj u drugom dijelu iznosi

    \[ \sum_{z < p_i < y^{1/3}}\dfrac{x}{y}\left(1-\dfrac{1}{p_i}\right) + \sum_{y^{1/3} < p_i < w}\left(\dfrac{x}{p_i^3} - \dfrac{x}{yp_i}\right) \le \dfrac{x}{y}\pi(y^{1/3}) + \dfrac{x}{y^{2/3}\log y} \in O\left(\dfrac{x}{y^{2/3}\log y}\right). \]

    Ukupan broj u trećem dijelu iznosi

    \[ \sum_{y^{1/3} < p_i < w}\left(\dfrac{x}{y}-\dfrac{x}{p_i^3}\right) \le \pi(w)\dfrac{x}{y} \in O\left(\dfrac{xw}{y\log w}\right). \]

    Broj u prvom dijelu daleko je manji od ostalih dvaju i može se zanemariti. Kada je \(w^2 \le y \ll w^3\), ukupan je broj u trećem dijelu daleko veći od onoga u drugom. Samo tada pohranjivanje tog dijela vrijednosti u statičko polje smanjuje ukupnu vremensku složenost dijela s prijelazima stanja za jedan faktor \(\log x\); inače upiti u drugom dijelu postaju usko grlo. Ukratko, nakon uvođenja te optimizacije ukupna vremenska složenost dijela s prijelazima stanja iznosi

    \[ O\left(\max\left\{\dfrac{x}{y^{2/3}},\dfrac{xw}{y\log x}\right\}\right). \]

    Primijetimo da je, budući da je raspodjela grubih brojeva približno jednolika, učinak druge optimizacije (tj. optimizacije grubim brojevima u dijelu s prijelazima stanja) neovisan o ovoj. Ako se istodobno primijeni optimizacija grubim brojevima, ovdje dobivena složenost može se smanjiti za još jedan \(\log x\).

  4. Prijelazi stanja mogu se prekinuti ranije, ažurirajući samo do dijela \(p_a\le w\), a preostali se dio rješava idejom Meissel–Lehmerova algoritma. Za razliku od Meissel–Lehmerova algoritma, koji se oslanja na \(\varphi(x,a)\), \(S(x,a)\) čuva vrijednosti \(\pi(x)\) potrebne sve do \(x \le p_a^2\), pa dodatna predobrada nije potrebna. No pri kombiniranju s prethodnim metodama optimizacije treba paziti na utjecaj optimizacije grubim brojevima u dijelu s dinamičkim programiranjem (tj. optimizacije 2) i ne koristiti vrijednosti koje nisu ispravno ažurirane. To poboljšava i vremensku i prostornu složenost algoritma, ali konkretan opseg poboljšanja uvelike ovisi o implementaciji ostalih dijelova, pa ovdje ne dajemo opću analizu. U nastavku ćemo taj dio referentne implementacije konkretno analizirati.

Spojimo te četiri male optimizacije. Za proizvoljan \(w \le x^{1/3}\), za \(z < w\) i \(w^2 \le y < w^3\), ukupna vremenska složenost dijela sa sitom i dijela s prijelazima stanja iznosi

\[ O\left(y + \dfrac{z\sqrt{x}}{\log x} + \dfrac{xw}{y\log x}\right). \]

Stoga pri \(y=x^{5/8}\log^{-1}x\) i \(z=w^{1/2}\) ukupna vremenska složenost dostiže \(O\left(\dfrac{\sqrt{xw}}{\log x}\right)\). Pritom se \(z\) uzima što veći, a da se ne poveća ukupna složenost, kako bi se smanjila gustoća \(z\)-grubih brojeva i snizila konstanta algoritma.

Ako se algoritam prekine ranije pri \(w=x^{1/3}\), vremenska i prostorna složenost algoritma obje su barem4 \(O(x^{2/3}\log^{-1}x)\). U nastavku pokazujemo da se, prekine li se algoritam pri \(w=x^{1/4}\), dobiva niža vremenska i prostorna složenost.

Neka je \(w=x^{1/4}\). Budući da je algoritam prekinut ranije pri \(a=\pi(x^{1/4})\), za dobivanje \(\pi(x)\) treba iskoristiti relaciju:

\[ \pi(x) = S(x,a) - P_2(x,a) - P_3(x,a). \]

Iz prethodne analize znamo

\[ P_2(x,a) = \sum_{i=a+1}^{\pi(\sqrt{x})}\pi\left(\dfrac{x}{p_i}\right) - \dfrac{1}{2}(\pi(\sqrt{x})+a-1)(\pi(\sqrt{x})-a). \]

Budući da je već prosijano do \(p_a\), \(\pi(\sqrt{x})\) može se dobiti iz \(S(\cdot,a)\). Međutim, budući da je \(x/p_i\in[\sqrt{x},x^{3/4})\), \(\pi(\cdot)\) u sumi i dalje se ne podudara sa \(S(\cdot,a)\). Stoga daljnjim razvojem dobivamo

\[ \sum_{i=a+1}^{\pi(\sqrt{x})}\pi\left(\dfrac{x}{p_i}\right) = \sum_{i=a+1}^{\pi(\sqrt{x})}S\left(\dfrac{x}{p_i},a\right) - \sum_{i=a+1}^{\pi(\sqrt{x})}P_2\left(\dfrac{x}{p_i},a\right). \]

Uvrštavanjem natrag u prethodnu formulu dobiva se

\[ \begin{aligned} \pi(x) &= S(x,a) + \dfrac{1}{2}(\pi(\sqrt{x})+a-1)(\pi(\sqrt{x})-a) \\ &\quad - \sum_{i=a+1}^{\pi(\sqrt{x})}S\left(\dfrac{x}{p_i},a\right) + \underbrace{ \sum_{i=a+1}^{\pi(\sqrt{x})}P_2\left(\dfrac{x}{p_i},a\right) - P_3(x,a) }_{\Delta(x)}. \end{aligned} \]

Za izračun \(\Delta(x)\) razmotrimo njegovo kombinatorno značenje. Iz definicija \(P_2(x,a)\) i \(P_3(x,a)\) slijedi

\[ \begin{aligned} \sum_{i=a+1}^{\pi(\sqrt{x})}P_2\left(\dfrac{x}{p_i},a\right) &= \#\{p_ip_jp_k \le x : a < i,~ a < j \le k\},\\ P_3(x,a) &= \#\{p_ip_jp_k \le x : a < i \le j \le k\}. \end{aligned} \]

Oduzimanjem tih dvaju skupova dobiva se

\[ \Delta(x) = \#\{p_ip_jp_k \le x : a < j,~ j < i,~ j \le k\}. \]

Za prebrojavanje i dalje razmatramo nabrajanje najmanjeg prostog faktora \(p_j\) (jer mu je gornja granica nabrajanja najmanja); za fiksni \(j\) ostali indeksi moraju zadovoljavati \(i > j\) i \(k \ge j\); stoga, izdvoji li se poseban slučaj \(k=j\), u preostalim slučajevima vrijedi \(i,k > j\), što se pomoću simetrije može dodatno pojednostavniti, pa se dobiva sljedeći izraz:

\[ \Delta(x) = \underbrace{\sum_{j=a+1}^{\pi(x^{1/3})}\left(\pi\left(\dfrac{x}{p_j^2}\right) - j\right)}_{i > j = k} + \underbrace{2\sum_{j=a+1}^{\pi(x^{1/3})}\left(\sum_{i=j+1}^{\pi(\sqrt{x/p_j})}\left(\pi\left(\dfrac{x}{p_ip_j}\right) - i\right) \right)}_{i > k > j \text{ or }k > i > j } + \underbrace{\sum_{j=a+1}^{\pi(x^{1/3})}\left(\pi\left(\sqrt{\dfrac{x}{p_j}}\right) - j\right)}_{i=k > j}. \]

Sređivanjem suma dobiva se

\[ \Delta(x) = \sum_{j=a+1}^{\pi(x^{1/3})}\left(\pi\left(\dfrac{x}{p_j^2}\right) - j + 2 \sum_{i=j+1}^{\pi(\sqrt{x/p_j})}\pi\left(\dfrac{x}{p_ip_j}\right) - \left( \pi\left(\sqrt{\dfrac{x}{p_j}}\right) ^ 2 - j^2 \right) \right). \]

Pomoću tog izraza složenost izračuna \(\Delta(x)\) iznosi (za način procjene vidi raniji dio o složenosti Lucyjeva algoritma)

\[ O\left(\sum_{x^{1/4} < p \le x^{1/3}}\pi\left(\sqrt{\dfrac{x}{p}}\right)\right) = O\left(\dfrac{x^{2/3}}{\log^2 x}\right). \]

To je ujedno složenost izračuna posljednjeg dijela. Jednostavnom se provjerom vidi da svi članovi \(\pi(x/n)\) koji se pojavljuju pri izračunu \(\Delta(x)\) zadovoljavaju \(x/n\le\sqrt{x} < y\), pa se svi mogu izravno dobiti iz \(S(\cdot,a)\) pohranjenih u Fenwickovu stablu (treba ih unaprijed pohraniti u statičko polje kako se ne bi uveli dodatni upiti složenosti \(O(\log x)\)).

U kombinaciji s prethodnom analizom, kada je \(z=x^{1/8},~w=x^{1/4},~y=x^{5/8}\log^{-1}x\), ukupna vremenska složenost dijela sa sitom i dijela s dinamičkim programiranjem iznosi \(O(x^{5/8}\log^{-1}x)\), pa je ukupna vremenska složenost algoritma \(O(x^{2/3}\log^{-2}x)\). Prostorna je složenost duljina Fenwickova stabla \(O(y)=O(x^{5/8}\log^{-1}x)\).

// Modified from 渐变色's codes:
//   https://www.luogu.com.cn/article/q4d4jl20
// Submission:
// * https://judge.yosupo.jp/submission/398981 (1e11)
// * https://www.luogu.com.cn/record/296415705 (1e13)
long long count_pi(long long n) {
  if (n <= 1) return 0;
  // Constants.
  int v = std::sqrt(n + 0.25l);                // x^{1/2}.
  int w = std::sqrt(v + 0.25l);                // x^{1/4}. Phase II stops here.
  int z = std::min(w, (int)std::sqrt(w) * 2);  // ~x^{1/8}. Phase I stops here.
  int y = std::pow(n, 0.625l) / std::log(n) * 2;  // ~x^{5/8}/log(x). BIT size.
  y = std::min<long long>(std::max(y, v), n);
  int B = n / y;  // the largest j such that n/j >= y.
  B = std::min<long long>(n / (n / B), y);
  // Initialize.
  std::vector<long long> l(v + 1);  // l[i] = S(n/i, .)
  std::vector<int> s(y + 1);        // phase I: S(i, .); phase II: BIT.
  std::vector<bool> e(y + 1);       // e[i] == true once i has been crossed out.
  std::vector<int> pi(y + 1);       // prefix for e; then pi(.) for O(1) query.
  for (int i = 1; i <= v; ++i) l[i] = n / i - 1;  // Lucy DP initialization.
  for (int i = 1; i <= v; ++i) s[i] = i - 1;

  // ============ PHASE I: plain Lucy DP, p <= z ~ n^(1/8) ===================
  int p;
  for (p = 2; p <= z; ++p) {
    if (s[p] != s[p - 1]) {  // when p is prime.
      auto m = n / p;
      int t0 = s[p - 1];  // the number of primes < p.
      int t = v / p;      // splitting point by where n/(i*p) lands.
      // S(u, .) -= (S(u / p) - t0), case by case.
      for (int i = 1; i <= t; ++i) l[i] -= l[i * p] - t0;
      for (int i = t + 1; i <= v; ++i) l[i] -= s[m / i] - t0;
      for (int i = v, j = t; j >= p; --j)
        for (int k = j * p; i >= k; --i) s[i] -= s[j] - t0;
      // Sieve.
      for (int i = p * p; i <= y; i += p) e[i] = 1;
    }
  }
  // Obtain z-rough number list for [2,B].
  e[1] = 1;
  int id = 1;
  std::vector<int> roughs(B + 1);
  for (int i = 1; i <= B; ++i)
    if (!e[i]) roughs[id++] = i;
  roughs[id] = 0x7fffffff;  // sentinel: terminates every walk.
  // Build the BIT (i.e., Fenwick tree).
  for (int i = 1; i <= y; ++i) pi[i] = pi[i - 1] + e[i];
  for (int i = 1; i <= y; ++i) s[i] = pi[i] - pi[i & (i - 1)];
  // BIT query: obtain S(x,.).
  const auto query = [&](int x) -> int {
    int sum = x;
    for (; x; x &= x - 1) sum -= s[x];
    return sum;
  };
  // BIT modify: mark composite and add 1 in the BIT.
  const auto add = [&](int x) -> void {
    e[x] = 1;
    for (; x <= y; x += x & -x) ++s[x];
  };

  // ============ PHASE II: Lucy DP with BIT sieve, z < p <= n^(1/4) =========
  id = 1;
  for (; p <= w; ++p) {
    if (e[p]) continue;
    auto q = (long long)p * p;
    auto m = n / p;
    int t0 = query(p - 1);  // the number of primes < p.
    // freeze finalized values for O(1) query.
    // the frozen S(i, .) is actually pi(i).
    for (; id < q; ++id) pi[id] = query(id);
    // splitting point by where n/(i*p) lands.
    int t1 = B / p;
    int t2 = std::min<long long>(B, m / q);
    // S(u, .) -= (S(u / p) - t0), case by case.
    int i = 1, j = 1;
    for (; i <= t1; i = roughs[++j]) l[i] -= l[i * p] - t0;
    for (; i <= t2; i = roughs[++j]) l[i] -= query(m / i) - t0;
    for (; i <= B; i = roughs[++j]) l[i] -= pi[m / i] - t0;
    // Sieve (with BIT).
    for (int i = q; i <= y; i += p)
      if (!e[i]) add(i);
  }
  // freeze value till v=x^{1/2}.
  for (; id <= v; ++id) pi[id] = query(id);
  // prime list till v=x^{1/2}.
  std::vector<int> primes;
  primes.push_back(1);  // dummy, p_0=1.
  for (int i = 2; i <= v; ++i)
    if (!e[i]) primes.push_back(i);

  // ============ PHASE III: stop early, correct with P2 and P3 ==============
  // ---- -P2, part 1: the triangular part.
  l[1] += (pi[v] + pi[w] - 1LL) * (pi[v] - pi[w]) / 2;
  // ---- -P2, part 2: the sum of S(n/p,a).
  for (int i = pi[w] + 1; i <= pi[B]; ++i) l[1] -= l[primes[i]];
  for (int i = pi[B] + 1; i <= pi[v]; ++i) l[1] -= query(n / primes[i]);
  // ---- +Delta(n).
  for (int i = pi[w] + 1; i <= pi[v]; ++i) {
    int p = primes[i];
    auto m = n / p;
    int e = pi[m / p];  // pi(n/p^2).
    if (e <= i) break;  // i.e., p^3 > n.
    l[1] += e - i;
    long long t = 0;
    auto s = pi[(int)std::sqrt(m + 0.25l)];  // pi(sqrt(n/p)).
    for (int k = i + 1; k <= s; ++k) t += pi[m / primes[k]];
    l[1] += 2 * t - (long long)(i + s) * (s - i);
  }

  return l[1];
}

U rasponima podataka uobičajenima na algoritamskim natjecanjima (\(10^{10}\sim 10^{14}\)) vremenski i prostorni troškovi te implementacije prilično su dobri. Treba napomenuti da, iako je u teorijskoj analizi složenosti posljednji dio usko grlo složenosti, zbog manjeg logaritamskog faktora i bolje konstante u njegovoj složenosti u navedenom su rasponu podataka stvarno usko grlo algoritma i dalje dio sa sitom i dio s dinamičkim programiranjem. Upravo je zato optimizacija njihove složenosti neophodna.

Poopćenje: prefiksne sume potencija prostih brojeva

Općenitije, razmotrimo sljedeći problem:

\[ F_{\text{prime}}(x) = \sum_{p\in\mathbf P,~p\le x}f(p). \]

Drugim riječima, treba izračunati zbroj vrijednosti teorijsko-brojevne funkcije \(f(\cdot)\) u prostim brojevima koji ne premašuju \(x\). Funkcija prebrojavanja prostih brojeva \(\pi(x)\) poseban je slučaj za \(f\equiv 1\).

Pretpostavimo da teorijsko-brojevna funkcija \(f\) zadovoljava sljedeće uvjete:

  1. \(f\) je potpuno multiplikativna funkcija, tj. \(f(mn)=f(m)f(n)\) vrijedi za sve pozitivne cijele brojeve \(m,n\);
  2. prefiksna suma \(F(x)=\sum_{n \le x}f(n)\) lako se računa.

Uobičajene teorijsko-brojevne funkcije koje zadovoljavaju te uvjete uključuju potencije i Dirichletove karaktere (npr. Legendreov simbol). Naravno, ako se neka funkcija može prikazati kao linearna kombinacija funkcija koje zadovoljavaju te uvjete, i njezina se prefiksna suma po prostim brojevima može izračunati. Stoga metoda iz ovog odjeljka može obraditi slučajeve kada je \(f\) polinom ili kada je \(f\) periodična funkcija5. Drugi, sažetiji način obrade periodičnih funkcija opisan je u primjeru zadatka u nastavku.

Pod tim uvjetima može se poopćiti prethodna rekurzivna relacija. Definirajmo \(S(x,a)\) kao zbroj vrijednosti \(f(\cdot)\) u cijelim brojevima koji u intervalu \([2,x]\) preostaju nakon prosijavanja prvih \(a\) prostih brojeva, tj.

\[ S(x,a) = \sum_{1 < n \le x,~ (n\in\mathbf P) \lor (\operatorname{lpf}(n) > p_a)} f(n). \]

Tada se prethodna rekurzivna relacija za \(S(x,a)\) može prepisati ovako:

\[ S(x,a) = S(x,a-1) - [p_a^2 \le x]f(p_a)\left(S\left(\dfrac{x}{p_a},a-1\right)-S(p_{a}-1,a-1)\right). \]

Rubni je uvjet \(S(x,0) = F(x) - 1\). Sadržaj te formule sličan je prethodnome: u Eratostenovu situ složeni brojevi prosijani s \(p_a\) nužno su umnožak \(p_a\) i nekog cijelog broja koji još nije prosijan prvih \(a-1\) prostih brojeva. Međutim, među svim cijelim brojevima koji još nisu prosijani prvih \(a-1\) prostih brojeva nalaze se i sami prvi \(a-1\) prosti brojevi, koje treba dodatno izbaciti. Stoga se, da bi se dobio zbroj vrijednosti funkcije u tim složenim brojevima, pomoću potpune multiplikativnosti može izlučiti koeficijent \(f(p_a)\), a preostali je zbroj \(S(x/p_a,a-1)\) umanjen za doprinos prvih \((a-1)\) prostih brojeva \(S(p_a-1,a-1)\). Primijetimo da se oduzeti član može zapisati i kao \(S(p_{a-1},a-1)\); oni su jednaki.

Pomoću te rekurzivne relacije Lucyjevim se algoritmom vrijednost \(F_{\text{prime}}(x)\) može izračunati u vremenu \(O(x^{3/4}\log^{-1}x)\), uz prostornu složenost od samo \(O(x^{1/2})\). Fenwickovim se stablom vremenska složenost može sniziti na \(\tilde O(x^{2/3})\), ali to nije osobito praktično.

Referentna implementacija za zadatak-predložak Luogu P5493 质数前缀统计 (prefiksna statistika prostih brojeva) 
#include <cmath>
#include <iostream>
#include <vector>

int solve(long long n, int k, int P) {
  int s = std::sqrt(n + 0.25l);
  // Linear sieve.
  std::vector<int> primes, vis(s + 1);
  for (int x = 2; x <= s; ++x) {
    if (!vis[x]) primes.push_back(x);
    for (int p : primes) {
      if (x * p > s) break;
      vis[x * p] = true;
      if (x % p == 0) break;
    }
  }
  // D(n) = {floor(n/x): x=1,2,...,n}.
  std::vector<long long> d;
  for (long long l = 1, r; l <= n; l = r + 1) {
    r = n / (n / l);
    d.push_back(r);
  }
  int m = d.size();
  auto id = [&](long long x) -> int { return x <= s ? x - 1 : m - n / x; };
  // binary exponentiation.
  auto pow = [&](long long a, int b) -> int {
    int res = 1, po = a % P;
    for (; b; b >>= 1) {
      if (b & 1) res = (long long)res * po % P;
      po = (long long)po * po % P;
    }
    return res;
  };
  // lagrange interpolation to initialize DP.
  std::vector<int> dp(m, P - 1), su(k + 2);
  for (int i = 1; i <= k + 1; ++i) {
    su[i] = (su[i - 1] + pow(i, k)) % P;
  }
  std::vector<int> ifa(k + 2);
  ifa[0] = ifa[1] = 1;
  for (int i = 2; i <= k + 1; ++i) {
    ifa[i] = (long long)(P - P / i) * ifa[P % i] % P;
  }
  for (int i = 2; i <= k + 1; ++i) {
    ifa[i] = (long long)ifa[i] * ifa[i - 1] % P;
  }
  for (int j = 0; j < m; ++j) {
    long long x = d[j] % P;
    std::vector<int> lp(k + 2), rp(k + 2);
    lp[0] = rp[k + 1] = 1;
    for (int i = 1; i <= k + 1; ++i) {
      lp[i] = lp[i - 1] * (x + P - (i - 1)) % P;
      rp[k + 1 - i] = rp[k + 2 - i] * (x + P - (k + 2 - i)) % P;
    }
    for (int i = 0; i <= k + 1; ++i) {
      dp[j] += ((k + 1 - i) % 2 ? P - 1LL : 1LL) * su[i] % P * lp[i] % P *
               rp[i] % P * ifa[i] % P * ifa[k + 1 - i] % P;
      if (dp[j] >= P) dp[j] -= P;
    }
  }
  // Lucy's Quotient DP.
  for (int p : primes) {
    auto pk_ = (P - 1LL) * pow(p, k) % P;
    for (int j = m - 1; d[j] >= (long long)p * p; --j) {
      dp[j] += pk_ * (dp[id(d[j] / p)] + P - dp[p - 2]) % P;
      if (dp[j] >= P) dp[j] -= P;
    }
  }
  // Output.
  long long res = 0;
  for (int i = 1; i <= s; ++i) {
    res += (long long)i * i % P * dp.end()[-i] % P;
  }
  return res % P;
}

int main() {
  long long n;
  int k, p;
  std::cin >> n >> k >> p;
  std::cout << solve(n, k, p) << std::endl;
  return 0;
}

Razlog je to što kriterij \(S(u,\pi(u-1))\neq S(u-1,\pi(u-1))\) za općenit \(f\) ne mora vrijediti. Osim toga, iako je u ovom odjeljku razmotreno samo poopćenje Lucyjeva algoritma, i drugi se algoritmi mogu slično poopćiti; no Lucyjev algoritam može izračunati vrijednosti \(F_\text{prime}\) u svim vrijednostima iz \(D(x)\), što je korisnije za kasnije sumiranje multiplikativnih funkcija, pa ovaj odjeljak predstavlja samo njegovo poopćenje.

Codeforces 665 F. Four Divisors

Zadan je \(n\); odredite broj cijelih brojeva u \([1,n]\) koji imaju točno \(4\) djelitelja. Pritom je \(1\le n\le 10^{11}\).

Rješenje

Cijeli broj s točno \(4\) djelitelja nužno je oblika \(p^3\) ili \(pq\), gdje su \(p,q\) prosti i \(p < q\). U intervalu \([1,n]\) cijelih brojeva oblika \(p^3\) ima ukupno \(\pi(n^{1/3})\), a cijelih brojeva oblika \(pq\) ima ukupno

\[ \sum_{p < \sqrt{n}}\left(\pi\left(\dfrac{n}{p}\right)-\pi(p)\right) \]

Budući da se sve funkcije prebrojavanja prostih brojeva u gornjem izrazu mogu izračunati iz vrijednosti u skupu \(D(n)\), dovoljno je jednom izvesti Lucyjev algoritam da bi se zadatak riješio. Vremenska je složenost \(O(n^{3/4}\log^{-1}n)\), a prostorna \(O(n^{1/2})\).

Referentna implementacija 
#include <cmath>
#include <iostream>
#include <vector>

long long solve(long long n) {
  int s = std::sqrt(n + 0.25l);
  // D(n) = {floor(n/x): x=1,2,...,n}
  std::vector<long long> d;
  for (long long l = 1, r; l <= n; l = r + 1) {
    r = n / (n / l);
    d.push_back(r);
  }
  int m = d.size();
  auto id = [&](long long x) -> int { return x <= s ? x - 1 : m - n / x; };
  // Lucy's Quotient DP to find pi.
  std::vector<long long> dp(m);
  for (int j = 0; j < m; ++j) dp[j] = d[j] - 1;
  for (int p = 2; p <= s; ++p) {
    if (dp[p - 1] == dp[p - 2]) continue;  // Only primes can survive.
    for (int j = m - 1; d[j] >= (long long)p * p; --j) {
      dp[j] -= dp[id(d[j] / p)] - dp[p - 2];
    }
  }
  // Count p^3.
  long long res = dp[(int)std::cbrt(n + 0.25l) - 1];
  // Count pq.
  for (int p = 2; p <= s; ++p) {
    if (dp[p - 1] == dp[p - 2]) continue;
    res += dp.end()[-p] - dp[p - 1];
  }
  return res;
}

int main() {
  long long n;
  std::cin >> n;
  std::cout << solve(n) << std::endl;
  return 0;
}
LOJ 6028. „from CommonAnts” 质数计数 II (prebrojavanje prostih brojeva II)

Zadani su \(n,m\); za svaki od ostataka \(0,1,2,\dots,m-1\) odredite koliko prostih brojeva u \([1,n]\) daje taj ostatak pri dijeljenju s \(m\). Pritom je \(1\le n\le 3\times 10^{10}\), \(1 < m\le 12\) i \(n > m\).

Rješenje

Za bilo koji ostatak \(r=0,1,2,\dots,m-1\) funkcija \([n\bmod m = r]\) očito je periodična. Ranije je rečeno da se takvi problemi mogu obraditi sumiranjem Dirichletovih karaktera, ali to je previše zamršeno i uključuje računanje s kompleksnim brojevima. Stoga ovaj zadatak rješavamo drugom metodom.

Razmotrimo dodavanje jedne dimenzije u jednadžbu prijelaza stanja Lucyjeva algoritma. Neka \(S(n,r,a)\) označava broj cijelih brojeva u \([2,n]\) koji nakon prosijavanja prvih \(a\) prostih brojeva preostaju i daju ostatak \(r\) pri dijeljenju s \(m\). Slično kao u glavnom tekstu, dobiva se sljedeća rekurzivna relacija:

\[ S(n,rp_a\bmod m,a) = S(n,rp_a\bmod m,a-1) - [p_a^2 \le n]\left(S\left(\dfrac{n}{p_a},r,a-1\right)-S(p_{a}-1,r,a-1)\right). \]

U rekurzivnoj formuli drugi argument funkcije koristi množenje umjesto dijeljenja, uzimajući u obzir mogućnost \(p_a\mid m\). Rubni je uvjet \(S(n,r,0) = \left\lfloor\dfrac{n-r}{m}\right\rfloor + [r> 1]\). Na temelju toga zadatak se rješava dinamičkim programiranjem. Vremenska je složenost \(O(mn^{3/4}\log^{-1}n)\), a prostorna \(O(mn^{1/2})\).

Referentna implementacija 
#include <cmath>
#include <iostream>
#include <numeric>
#include <vector>

std::vector<long long> solve(long long n, int m) {
  int s = std::sqrt(n + 0.25l);
  // Linear sieve.
  std::vector<int> primes, vis(s + 1);
  for (int x = 2; x <= s; ++x) {
    if (!vis[x]) primes.push_back(x);
    for (int p : primes) {
      if (x * p > s) break;
      vis[x * p] = true;
      if (x % p == 0) break;
    }
  }
  // D(n) = {floor(n/x): x=1,2,...,n}
  std::vector<long long> d;
  for (long long l = 1, r; l <= n; l = r + 1) {
    r = n / (n / l);
    d.push_back(r);
  }
  int sz = d.size();
  auto id = [&](long long x) -> int { return x <= s ? x - 1 : sz - n / x; };
  // Lucy DP mod MOD.
  std::vector<std::vector<long long>> dp(sz, std::vector<long long>(m));
  for (int j = 0; j < sz; ++j) {
    for (int r = 0; r < m; ++r) {
      dp[j][r] = (d[j] + m - r) / m - (r <= 1);
    }
  }
  for (int p : primes) {
    for (int j = sz - 1; d[j] >= (long long)p * p; --j) {
      for (int r = 0; r < m; ++r) {
        dp[j][r * p % m] -= dp[id(d[j] / p)][r] - dp[p - 2][r];
      }
    }
  }
  // Finalize.
  return dp.back();
}

int main() {
  long long n;
  int m;
  std::cin >> n >> m;
  auto res = solve(n, m);
  for (auto x : res) std::cout << x << '\n';
  return 0;
}

This article introduces sublinear algorithms for the prime counting problem. The prime counting problem asks for the number of primes not exceeding \(n\), i.e., \(\pi(n)\). For \(n\sim 10^8\) it can be computed with a sieve in \(\tilde O(n)\) time. However, when \(n \sim 10^{10}\) or even larger, sieves and other algorithms based on enumeration become hard to apply. For this situation, this article introduces a series of algorithms that are relatively easy to implement, with time complexities mostly between \(\tilde O(n^{2/3})\) and \(\tilde O(n^{3/4})\).

The prime counting problem is a special case of the problem of prefix sums of prime powers. Lucy's algorithm introduced in this article generalizes directly to prefix sums of prime powers, and this generalization forms part of algorithms for summing multiplicative functions such as the Min_25 sieve.

Tip

This article provides many prime counting algorithms. For readability, none of them has received much constant-factor optimization. These algorithms differ in time and space performance and in implementation difficulty, so readers can choose a suitable algorithm according to their own needs. For data in the range \(10^{11}\sim 10^{13}\), the algorithm of the section Lehmer's truncation rule is often already efficient enough and relatively simple to implement, while the optimized Lucy's algorithm is slightly more complex to implement but has excellent time and space performance. For smaller data ranges, the original Lucy's algorithm is the simplest to implement and has wider uses in summing multiplicative functions.

Basic concepts and notation

This article uses the following notation:

  • \(\mathbf P\) is the set of (positive) primes, and \(p_a\) is the \(a\)-th smallest prime (indices start from \(1\)). For convenience of exposition, we also set \(p_0=1\). In this article, the letters \(p\) and \(q\) always denote primes.
  • \(\operatorname{lpf}(n)\) denotes the least prime factor of \(n\). We also set \(\operatorname{lpf}(1)=+\infty\).
  • \(D(x) = \{\lfloor x/i\rfloor : i = 1,2,\dots,\lfloor x\rfloor\}\). Its properties are described in detail in the section Properties of floor-division blocks.
  • \(\pi(x)\) is the number of primes not exceeding \(x\).
  • \(\varphi(x,a)=\#\{n \in\mathbf N_+ : n \le x,~ (p\mid n \implies p > p_a)\}\) is the number of positive integers not exceeding \(x\) all of whose prime factors are greater than \(p_a\).
  • \(P_k(x,a)=\#\{n\in\mathbf N_+ : n \le x,~ n = q_1q_2\cdots q_k,~ \forall i(q_i > p_a)\}\) is the number of positive integers not exceeding \(x\) that have exactly \(k\) prime factors (counted with multiplicity), all of which are greater than \(p_a\).
  • \(S(x,a)\) is the number of integers greater than \(1\) and not exceeding \(x\) that remain in the sieve of Eratosthenes after sieving with the first \(a\) primes.

These functions have the following simple properties:

  • \(\varphi(x,0) = \lfloor x\rfloor\).
  • \(S(x,a) = \varphi(x,a) + \min\{\pi(x),a\} - 1\).
  • \(\varphi(x,a) = \sum_{k=0}^{\infty} P_k(x,a)\).
  • \(P_0(x,a) = 1\).
  • \(P_1(x,a) = \pi(x) - \min\{\pi(x),a\}\).
  • For \(x < p_{a+1}^k\), we have \(P_k(x,a) = 0\).

All these properties follow easily from the definitions.

Meissel–Lehmer algorithm

Substituting the expressions for \(P_0\) and \(P_1\) into the expansion of \(\varphi\) and simplifying, we obtain

\[ \pi(x) = \varphi(x,a) + a - 1 - P_2(x,a) - P_3(x,a) - \cdots. \]

This means that \(\pi(x)\) can be obtained by computing the value of \(\varphi(x,a)\), with the error given by a series of \(P_k\) terms. As the value of \(a\) increases, the number of error terms gradually decreases. In particular, for \(a = \pi(\sqrt{x})\) we have \(P_2(x,a)=P_3(x,a)=\cdots=0\), that is,

\[ \pi(x) = \varphi(x,\pi(\sqrt{x})) + \pi(\sqrt{x}) - 1. \]

For \(\pi(x^{1/3}) \le a < \pi(\sqrt{x})\), the term \(P_2(x,a)\) is nonzero, but the subsequent terms are still zero, i.e.,

\[ \pi(x) = \varphi(x,a) + a - 1 - P_2(x,a). \]

Similarly, for \(\pi(x^{1/4}) \le a < \pi(x^{1/3})\), both terms \(P_2(x,a)\) and \(P_3(x,a)\) are nonzero, and so on. In short, using these relations, the computation of \(\pi(x)\) can be reduced to the computation of \(\varphi(x,a)\) and of the terms \(P_k(x,a)\). All algorithms that rely on these reduction relations may be called Meissel–Lehmer algorithms.

For \(\varphi(x,a)\), we have the following recurrence relation:

\[ \varphi(x,a) = \varphi(x,a - 1) - \varphi\left(\dfrac{x}{p_a},a-1\right). \]

Naturally, the boundary condition is given by \(\varphi(x,0) = \lfloor x\rfloor\).

Example

Take \(x=30,a=2\) as an example (\(p_a=3\)); one step of the recurrence is shown in the figure below:

In the figure, green cells denote integers all of whose prime factors are greater than \(p_a=3\) (\(1\) has no prime factors and is also counted), while green and orange cells together denote integers all of whose prime factors are greater than \(2\). The number of the former is \(\varphi(x,a)=\varphi(30,2)=10\), and the number of the latter is \(\varphi(x,a-1)=\varphi(30,1)=15\).

The difference between the two is exactly the orange part: numbers divisible by \(3\) that have no prime factor smaller than \(3\). Hence all orange numbers have the form \(n=3k\). Since every prime factor of \(k\) is also a prime factor of \(n\), \(k\) likewise has no prime factor smaller than \(3\), i.e., \(k\) itself also falls in a green or orange cell; moreover, from \(3k\le 30\) we get \(k\le\lfloor x/p_a\rfloor=10\). The converse holds as well: the prime factors of \(n=3k\) are nothing but \(3\) and the prime factors of \(k\), so as long as \(k\le 10\) and it has no prime factor smaller than \(3\), \(n\) falls in the orange part. The two are therefore in one-to-one correspondence.

The table is deliberately arranged in \(30/3=10\) columns, so the first row is exactly \(1,\dots,10\). Such \(k\) are precisely the green and orange cells inside the dashed box, \(\varphi(x/p_a,a-1)=\varphi(30/3,1)=5\) in total; the label \(3\times k\) in the upper right corner of each orange cell indicates its corresponding \(k\). Therefore

\[ \varphi(x,a) = \varphi(x,a-1) - \varphi\left(\left\lfloor\dfrac{x}{p_a}\right\rfloor,a-1\right). \]

That is, \(\varphi(30,2)=\varphi(30,1)-\varphi(30/3,1)=15-5=10\).

The recursion tree obtained by computing recursively with this relation is a binary tree. Expanding it completely, we get

\[ \varphi(x,a) = \sum_{n\mid p_1p_2\cdots p_a} \mu(n)\left\lfloor\dfrac{x}{n}\right\rfloor. \]

It follows that the number of leaves of this binary tree equals the number of all squarefree \(p_a\)-smooth numbers (i.e., integers with no prime factor exceeding \(p_a\)) not exceeding \(x\), and this number is \(\Theta(x)\)1. This means that the complexity of direct recursive computation is still \(\Omega(x)\). For fast computation, this binary tree needs to be pruned appropriately. The main difference between the various Meissel–Lehmer algorithms lies precisely in the pruning method. In the literature these are called truncation rules. Next, this section focuses on several simple truncation rules.

Finally, we deal with \(P_k(x,a)\). Taking \(P_2(x,a)\) as an example, we have

\[ \begin{aligned} P_2(x,a) &= \sum_{i,j:~p_a < p_i\le p_j\le x/p_i} 1 = \sum_{i = a+1}^{\pi(\sqrt{x})}\sum_{j=i}^{\pi(x/p_i)} 1 \\ &= \sum_{i = a+1}^{\pi(\sqrt{x})}\left(\pi\left(\dfrac{x}{p_i}\right) - i + 1\right)\\ &= \sum_{i = a+1}^{\pi(\sqrt{x})}\pi\left(\dfrac{x}{p_i}\right)-\dfrac{1}{2}\left(\pi(\sqrt{x})+a-1\right)\left(\pi(\sqrt{x}) - a\right). \end{aligned} \]

This means that the computation of \(P_2(x,a)\) can be reduced to the computation of several values \(\pi(x/p)\). For \(k>2\) similar summation formulas still exist, but the number of summation levels grows, so they gradually become impractical. Common algorithms mostly take \(a\ge\pi(x^{1/3})\) to avoid computing more \(P_k\) terms. In actual computation, the values \(\pi(x/p)\) for this part are usually precomputed with a sieve.

Mathematicians thought very early about computing \(\pi(x)\) directly without enumeration. Legendre gave the above expression for \(a=\pi(\sqrt{x})\), but expanding \(\varphi(x,a)\) completely yields too many terms to be practically usable for computation. In 1870, Meissel proposed computing at \(a=\pi(x^{1/3})\), reducing the number of terms in the expansion of \(\varphi(x,a)\) while the error remains easy to compute. In 1959, Lehmer further improved and simplified the procedure. In 1985, the truncation rule proposed by Lagarias, Miller, and Odlyzko for the first time brought this idea to sublinear complexity, achieving \(\tilde O(x^{2/3})\) time complexity and \(\tilde O(x^{1/3})\) space complexity. Afterwards, Deléglise and Rivat (1996), Gourdon (2001), Staple (2015), and others made further optimizations in this direction, further reducing the power of \(\log x\) in the complexity. It should be noted that, in order to keep good space complexity and handle problems of size around \(x\sim 10^{26}\), these algorithms are usually rather intricate. This section greatly simplifies the details and only introduces some simple optimization ideas. This sacrifices some time and space complexity, but the code is easier to implement. Readers interested in the original treatment can study the references at the end of the article on their own.

In addition, besides enumeration methods and the combinatorial methods introduced in this article, \(\pi(x)\) can also be computed with analytic methods, achieving \(\tilde O(\sqrt{x})\) time complexity. But they cannot be applied in algorithm competitions, so this article does not cover them.

Lehmer's truncation rule

Lehmer (1959) proposed a truncation rule. In the following two cases, \(\varphi(u,b)\) is no longer expanded:

  1. when \(u < p_b\);
  2. when \(b = c\), where \(c\) is a small positive integer chosen in advance.

In the first case, by the earlier discussion, necessarily \(\varphi(u,b)=1\), so nothing needs to be computed. In the second case, the value \(\varphi(u,c)\) needs to be computed additionally. By definition,

\[ \varphi(u,c) = \sum_{n=1}^{u} \prod_{b=1}^{c} [p_b \nmid n]. \]

Since the divisibility relation by \(p_b\) is periodic with period \(p_b\), the summand \(\prod_{b=1}^{c} [p_b \nmid n]\) is periodic with period \(p_c\# = \prod_{b=1}^{c}p_b\). Using the periodicity, we have

\[ \varphi(u,c) = \left\lfloor\dfrac{u}{p_c\#}\right\rfloor \varphi(p_c\#, c) + \varphi(u \bmod p_c\#, c). \]

Therefore, as long as all values \(\varphi(n,c)\) for \(n=0,1,2,\dots,p_c\#\) are precomputed with the recurrence relation, the value \(\varphi(u,c)\) in the second case can be looked up quickly.

It should be noted that although these two truncation rules do improve computational efficiency, the asymptotic complexity of the algorithm does not improve significantly. Lagarias, Miller, and Odlyzko (1985) proved that in Lehmer's algorithm the number of leaves of the recursion tree is \(\Omega\left(\dfrac{x}{\log^4 x}\right)\), so the time complexity is still \(\tilde\Theta(x)\).

Of course, the first truncation rule proposed by Lehmer can be improved appropriately:

\[ \varphi(u,b) = \begin{cases} 1, & u \le p_b,\\ \pi(u) - b + 1, & p_b < u \le p_b^2,\\ \pi(u) -\dfrac{1}{2}\left(\pi(\sqrt{u})+b-2\right)\left(\pi(\sqrt{u}) - b+1\right) + \sum\limits_{i = b+1}^{\pi(\sqrt{u})}\pi\left(\dfrac{u}{p_i}\right), & p_b^2 < u \le p_b^3. \end{cases} \]

The last two cases use the relations derived earlier. This improvement further reduces the size of the recursion tree, but introduces more \(\pi(u/p)\) terms that need to be computed. Since \(u/p\) can reach up to \(x/p_{c+1}\), in order to reduce ineffective pruning, one can set an upper bound \(V\) on the \(u\) for which this rule may be triggered, and precompute the values \(\pi(u)\) for \([1,V]\); when \(u > V\), the normal recursion is still used.

Below is an implementation of the improved Lehmer truncation rule:

Reference implementation 
// Modified from sgtlaugh's codes:
//   https://github.com/sgtlaugh/algovault/blob/master/code_library/fast_prime_counting.cpp
// Submission:
// * https://judge.yosupo.jp/submission/396797 (1e11)
// * https://www.luogu.com.cn/record/295291689 (1e13)
constexpr int V = 20000010;  // tuned for 1e12; at least sqrt{n} + 1.

constexpr int C = 7;
constexpr int N = 50;                            // N >= C must hold.
constexpr int Q = 2 * 3 * 5 * 7 * 11 * 13 * 17;  // = p_C#

std::vector<int> primes;
std::array<int, V> pi{};
std::array<std::array<int, Q + 1>, N> dp{};

// Find the primes and pi below V.
void sieve() {
  std::vector<bool> vis(V);
  for (int x = 2; x < V; ++x) {
    if (!vis[x]) primes.push_back(x);
    for (int p : primes) {
      if (x * p >= V) break;
      vis[x * p] = true;
      if (x % p == 0) break;
    }
  }
  for (int x = 2; x < V; ++x) {
    pi[x] = pi[x - 1] + !vis[x];
  }
}

// Initialization step.
// First sieve, then obtain the value of phi(u, C) for u <= p_C#.
void init() {
  sieve();
  for (int u = 1; u <= Q; ++u) dp[0][u] = u;
  for (int b = 1; b < N; ++b) {
    for (int u = 1; u <= Q; ++u) {
      dp[b][u] = dp[b - 1][u] - dp[b - 1][u / primes[b - 1]];
    }
  }
}

// Recursively find phi with Lehmer's truncation rule.
long long phi(long long u, int b) {
  if (u <= Q && b < N) return dp[b][u];
  if (b == C) return dp[b][u % Q] + (u / Q) * dp[b][Q];
  long long p = primes[b - 1];
  if (u < V && p * p >= u) return pi[u] - b + 1;
  if (p * p * p < u || u >= V) return phi(u, b - 1) - phi(u / p, b - 1);
  int lim = pi[(int)std::sqrt(u + 0.25l)];
  long long res = pi[u] - (lim + b - 2) * (lim - b + 1) / 2;
  for (int i = b; i < lim; ++i) {
    res += pi[u / primes[i]];
  }
  return res;
}

// Meissel-Lehmer with a = pi(n^{1/3}) and Lehmer's truncation rule.
long long lehmer_pi(long long n) {
  if (n < V) return pi[n];
  int sqr = std::sqrt(n + 0.25l);
  int a = std::cbrt(n + 0.25l);
  long long res = phi(n, pi[a]) + pi[a] - 1;
  for (int i = pi[a]; i < pi[sqr]; ++i) {
    res -= lehmer_pi(n / primes[i]) - i;
  }
  return res;
}

Although the theoretical complexity of this implementation is hard to prove2, its advantage is a very small constant factor and a simple implementation, so the code runs very efficiently in practice. The values of the constants \(c,V,N\) etc. in the code can be adjusted according to actual needs.

LMO truncation rule

Lagarias, Miller, and Odlyzko (1985) proposed another truncation rule. Choose \(y\) satisfying \(x^{1/3} \le y \le x^{2/5}\) and take \(a=\pi(y)\). Then, in the following two cases, \(\varphi(x/n,b)\) is no longer expanded:

  1. when \(b=c\) and \(n\le y\), where \(c\) is a small natural number chosen in advance;
  2. when \(n > y\).

LMO call the first case ordinary leaves and the second case special leaves.

The advantage of this truncation rule is that the leaves are easy to count. Note that different leaves necessarily have different \(n\). Ordinary leaves always satisfy \(n \le y\), so their number is \(O(y)\). Special leaves always satisfy \(n > y\) and \(\dfrac{n}{\operatorname{lpf}(n)} \le y\). Accordingly, special leaves can be divided into two kinds: \(\operatorname{lpf}(n) < \sqrt{y}\) and \(\operatorname{lpf}(n) \ge \sqrt{y}\). For the first kind, necessarily \(\operatorname{lpf}(n) < \sqrt{y}\), so the number of possible \(\operatorname{lpf}(n)\) does not exceed \(\pi(\sqrt{y})\), and \(\dfrac{n}{\operatorname{lpf}(n)} \le y\) has at most \(y\) choices, so the number of possible \(n\) – that is, the total number of leaves of this kind – does not exceed \(y\pi(\sqrt{y})\). For the second kind, necessarily \(n=pq\) with \(\sqrt{y} \le p < q \le y\), so the number of such leaves is at most \(\dfrac{1}{2}\pi(y)^2\). Combining both cases, the total number of special leaves is \(O\left(\dfrac{y^2}{\log^2x}\right)\).

For ordinary leaves, the same precomputation method as described earlier can be used. For special leaves, to compute the value \(\varphi(x/n,b)\), it can be understood by definition as "the number of positive integers not exceeding \(x/n\) whose least prime factor is strictly greater than \(p_b\)." (Recall that we set \(\operatorname{lpf}(1) = +\infty\) earlier.) After this transformation, all queries at special leaves can be processed offline: precompute the values of \(\operatorname{lpf}\) for the integers in \([1,x/y]\) and sort them, then update and query with a Fenwick tree. Taking into account the sorting of the offline queries and the Fenwick tree operations, the time complexity of this approach is

\[ O\left(\dfrac{y^2}{\log^2x}\log \dfrac{y^2}{\log^2x} + \left(\dfrac{x}{y} + \dfrac{y^2}{\log^2x}\right)\log\pi\left(\dfrac{x}{y}\right)\right) = O\left(\dfrac{x}{y}\log x + \dfrac{y^2}{\log x}\right). \]

Apart from the computation of \(\varphi(x,a)\), which is special, the rest of the computation is similar to the previous section. It suffices to precompute the values \(\pi(u)\) for \([1,x/y]\) and then compute \(P_2(x,a)\) using the earlier relation; for the case \(c > 0\), the values \(\varphi(u,c)\) also need to be precomputed. Note that, to meet the needs of the offline queries, during the recursive search for leaves one also needs to record the sign in front of each leaf, i.e., the value of \(\mu(n)\), in order to accumulate the contributions. This yields the complete algorithm.

The time and space complexity of this algorithm are both \(\tilde O(x^{2/3})\). If \(c = 0\) is taken, the complexity of the other parts is negligible, and the total complexity of this algorithm attains its minimum \(O(x^{2/3}\log^{1/3}x)\) at \(y = x^{1/3}\log^{2/3}x\). In this case, the space complexity of the algorithm is \(O(x^{2/3}\log^{-2/3}x)\). If \(c\) is taken to be a small positive integer, the time and space cost of precomputation must be balanced against the constant-factor improvement of the subsequent queries, but the overall complexity does not change.

Below is a reference implementation of this algorithm for \(c=0\):

Reference implementation 
// Modified from Maksim1744's codes:
//   https://codeforces.com/blog/entry/91632
// Submission:
// * https://judge.yosupo.jp/submission/396868 (1e11)
// * https://www.luogu.com.cn/record/295345663 (1e13, MLE)
// Submission: (lpf with segmented sieve)
// * https://judge.yosupo.jp/submission/396984 (1e11)
// * https://www.luogu.com.cn/record/295487031 (1e13)
// Binary-indexed tree.
struct BIT {
  int n;
  std::vector<int> su;

  BIT(int _n) : n(_n), su(_n + 1) {}

  void add(int x) {
    for (; x <= n; x += (x & (-x))) ++su[x];
  }

  int get(int x) {
    int res = 0;
    for (; x; x &= x - 1) res += su[x];
    return res;
  }
};

// Meissel-Lehmer with LMO's truncation rule and offline queries.
long long lmo_pi(long long n) {
  long long y = std::pow(n, 0.36l);  // tuned for n = 1e12 or 1e13.
  long long s = n / y;
  if (n < 100) s = n;
  // Linear sieve.
  // lpf records the prime rank (0-indexed).
  std::vector<int> primes, lpf(s + 1, -1);
  for (int x = 2; x <= s; ++x) {
    if (lpf[x] == -1) {
      lpf[x] = primes.size();
      primes.push_back(x);
    }
    for (int i = 0; i < (int)primes.size(); ++i) {
      int p = primes[i];
      if (x * p > s) break;
      lpf[x * p] = i;
      if (x % p == 0) break;
    }
  }
  if (n < 100) return primes.size();
  // pi(y).
  int pi_y = std::upper_bound(primes.begin(), primes.end(), y) - primes.begin();
  long long res = pi_y;
  // P2(n,pi(y)) with two pointers.
  int ptr = primes.size() - 1;
  for (int i = pi_y; i < (int)primes.size(); ++i) {
    while (ptr >= i && (long long)primes[i] * primes[ptr] > n) --ptr;
    if (ptr < i) break;
    res -= ptr - i + 1;
  }
  // phi(n,pi(y)).
  std::vector<std::tuple<long long, int, signed char>> queries;
  auto phi = [&](auto&& phi, long long u, int b, signed char sign = 1) -> void {
    if (!u) return;
    if (!b) return (void)(res += u * sign);
    if (u <= s) return (void)queries.emplace_back(u, b, sign);
    phi(phi, u, b - 1, sign);
    phi(phi, u / primes[b - 1], b - 1, -sign);
  };
  phi(phi, n, pi_y);
  std::sort(queries.begin(), queries.end());
  int sz = primes.size(), idx = 2;
  BIT bit(sz);
  for (const auto& query : queries) {
    long long u;
    int b;
    signed char sign;
    std::tie(u, b, sign) = query;
    while (idx <= u) bit.add(sz - lpf[idx++]);
    res += sign * (bit.get(sz - b) + 1);
  }
  queries.clear();
  return res - 1;
}

This offline approach has a high space complexity and has difficulty handling problems of size \(10^{13}\). The bottleneck is that the \(\operatorname{lpf}\) information for \([1,x/y]\) needs to be stored during precomputation. In fact, this information is only used for the subsequent offline queries, and only a single sequential pass is needed, so it can perfectly well be computed at query time with a segmented sieve.

In fact, the original paper provides an implementation entirely based on the segmented sieve. Both the computation of \(P_2(x,a)\) and of \(\varphi(x,a)\) are done inside the segmented sieve, yielding an algorithm with \(\tilde O(x^{2/3})\) time complexity and \(\tilde O(x^{1/3})\) space complexity. This requires enumerating all leaves directly in some way and converting the offline algorithm into an online one. Next, we introduce a simple way to implement it.

The core of the implementation is the segmented sieve: after precomputing the primes in \([1,y]\), split \([1,x/y]\) into blocks of length \(y\) and apply the sieve to each block separately. When processing each block, the values \(\pi(u)\) and \(\varphi(u,b)\) at the elements of that block need to be recorded. Since these values are all counts, they are easy to maintain during the block processing. Then, one needs to find which queries fall into the processing range of that block. In the algorithm described earlier in this section, let \(y=\tilde O(x^{1/3})\) and \(c=0\). Then the number of primes \(\pi(x)\) has the following expression:

\[ \begin{aligned} \pi(x) &= \dfrac{1}{2}\left(\pi(\sqrt{x})+a-2\right)\left(\pi(\sqrt{x}) - a + 1\right) - \sum_{y < p\le\sqrt{x}}\pi\left(\dfrac{x}{p}\right) \\ &\quad +\sum_{n\le y}\mu(n)\varphi\left(\dfrac{x}{n},0\right) + \sum_{n > y,~{n}/{\operatorname{lpf}(n)}\le y,~\operatorname{lpf}(n)\le y}\mu(n)\varphi\left(\dfrac{x}{n},\pi(\operatorname{lpf}(n))-1\right). \end{aligned} \]

The first term only needs the value \(\pi(\sqrt{x})\), which can be computed when the block processing reaches that element. The second term requires enumerating primes \(p\) such that \(x/p\) lies in the block currently being processed; after solving for the interval in which \(p\) lies, the corresponding sequence of primes can be obtained with a segmented sieve. Since the interval in which \(p\) lies contains no elements greater than \(\sqrt{x}\), this inner segmented sieve only needs the primes within \([1,x^{1/4}]\). For the third term, it suffices to enumerate the elements in \([1,y]\). The fourth term requires enumerating the primes in \([1,y]\) as \(\operatorname{lpf}(n)\), then determining the range of values of \(\dfrac{n}{\operatorname{lpf}(n)}\), and then enumerating those elements in it whose prime factors are not less than \(\operatorname{lpf}(n)\)3; this computes the values of this part of the leaves. When computing the contribution of the part in the current block, a Fenwick tree can be used. In this way, while guaranteeing \(\tilde O(x^{1/3})\) space complexity, \(\tilde O(x^{2/3})\) time complexity is still achieved. Of course, its implementation is somewhat more involved than the offline algorithm.

Reference implementation 
// An implementation of LMO section 3.
// Submission:
// * https://judge.yosupo.jp/submission/397047 (1e11)
// * https://www.luogu.com.cn/record/295493092 (1e13)
// Binary-indexed tree.

    n = _n;
    su.assign(_n + 1, 0);
  }

  void add(int x) {
    for (; x <= n; x += (x & (-x))) ++su[x];
  }

  int get(int x) {
    int res = 0;
    for (; x; x &= x - 1) res += su[x];
    return res;
  }
};

// Meissel-Lehmer with LMO's truncation rule and online queries.
long long lmo_pi(long long n) {
  long long y = std::pow(n, 0.36l);  // tuned for 1e12.
  long long s = n / y;
  long long sqr = std::sqrt(n + 0.25l);
  // Linear sieve for [1,y].
  if (n < 100) y = n;
  // lpf records the prime rank (0-indexed).
  std::vector<int> primes, lpf(y + 1, -1), mu(y + 1);
  mu[1] = 1;
  for (int x = 2; x <= y; ++x) {
    if (lpf[x] == -1) {
      lpf[x] = primes.size();
      primes.push_back(x);
      mu[x] = -1;
    }
    for (int i = 0; i < (int)primes.size(); ++i) {
      int p = primes[i];
      if (x * p > y) break;
      lpf[x * p] = lpf[p];
      mu[x * p] = x % p ? -mu[x] : 0;
      if (x % p == 0) break;
    }
  }
  if (n < 100) return primes.size();
  // The ordinary leaves.
  long long res = 0;
  for (int i = 1; i <= y; ++i) {
    if (mu[i]) res += mu[i] * (n / i);
  }
  // Segmented sieve.
  // Counts from previous blocks. phi[sz] stores the prime counts.
  int sz = primes.size();
  std::vector<int> phi(sz + 1, 0);
  BIT bit;
  auto phi_at = [&](long long v, int i) -> long long {
    return phi[i] + v - bit.get(v);
  };
  for (int id = 0; id * y + 1 <= s; ++id) {
    int ll = id * y + 1;
    int rr = std::min((id + 1) * y, s);
    int len = rr - ll + 1;
    bit.alloc(len);
    std::vector<bool> vis(len);
    for (int i = 0; i < sz; ++i) {
      int p = primes[i];
      // Special leaves.
      int nl = std::max(n / (rr + 1) / p, y / p) + 1;
      int nr = std::min(n / ll / p, y);
      for (int j = nl; j <= nr; ++j) {
        if (mu[j] && lpf[j] > i) {
          res += -mu[j] * phi_at(n / p / j - ll + 1, i);
        }
      }
      // Accumulate this block's info.
      phi[i] = phi_at(len, i);
      // Sieve this block with p.
      for (int x = (ll - 1) / p * p + p; x <= rr; x += p) {
        if (!vis[x - ll]) {
          bit.add(x - ll + 1);
          vis[x - ll] = true;
        }
      }
    }
    // All the remaining in this block are primes.
    // Those prime counts in P2(x,a).
    int nl = std::max(n / (rr + 1) + 1, y + 1);
    int nr = std::min(n / ll, sqr);
    if (nr >= nl) {
      std::vector<bool> vis(nr - nl + 1);
      for (int i = 0; i < sz; ++i) {
        int p = primes[i];
        if ((long long)p * p > nr) break;
        for (int x = (nl - 1) / p * p + p; x <= nr; x += p) {
          vis[x - nl] = true;
        }
      }
      for (int x = nl; x <= nr; ++x) {
        if (!vis[x - nl]) {
          res -= phi_at(n / x - ll + 1, sz);
        }
      }
    }
    // Those constant terms.
    if (ll <= sqr && sqr <= rr) {
      auto pi_sqr = phi_at(sqr - ll + 1, sz);
      res += (pi_sqr + sz - 2) * (pi_sqr - sz + 1) / 2;
    }
    // Accumulate the prime count.
    phi[sz] = id ? phi_at(len, sz) : sz;
  }
  return res;
}

Lucy's algorithm

When applying the Meissel–Lehmer algorithm, one of the core problems to solve is that the recursion tree of \(\varphi(x,a)\) is too large. This is because the termination condition of the recurrence relation of \(\varphi(x,a)\) only occurs at \(a=0\). Consider replacing \(\varphi(x,a)\) with \(S(x,a)\). Its advantage is that if \(p_a^2 > x\), then sieving with the prime \(p_a\) in the sieve of Eratosthenes does not remove any composite number (since they necessarily have a smaller prime factor), i.e., \(S(x,a)=S(x,a-1)\). This makes early termination of the recursion tree possible. For the case \(p_a^2\le x\), we have \(a\le\pi(x)\), so \(S(x,a) = \varphi(x,a)+a-1\). Moreover, from \(a-1\le\pi(x/p_a)\), all terms in the recurrence relation of \(\varphi(x,a)\) can be correspondingly replaced with \(S(\cdot,\cdot)\), which yields the recurrence relation of \(S(x,a)\). Combining both cases, the recurrence relation of \(S(x,a)\) can be written as

\[ S(x,a) = S(x,a-1) - [p_a^2 \le x]\left(S\left(\dfrac{x}{p_a},a-1\right)-(a-1)\right). \]

The boundary condition is \(S(x,0)=\lfloor x\rfloor -1\). Finally, from the relation

\[ \pi(x) = S(x,\pi(\sqrt{x})), \]

the value of the prime counting function \(\pi(x)\) is obtained directly.

The initial interval of the sieve of Eratosthenes is \([2,x] = [2,30]\), so cell \(1\) is drawn white and does not participate in the count. Gray cells are composite numbers sieved out earlier, orange cells are composite numbers sieved out in this round by the prime \(p_a=3\); among the remaining cells, light purple denotes the previous primes, dark purple denotes the current prime \(3\), and green denotes integers not yet sieved out (which may be prime or composite, such as \(25\)). Thus \(S(x,a-1)=S(30,1)=15\) is the total of the orange, purple, and green cells, \(S(x,a)=S(30,2)=11\) is the total of the purple and green cells, and the difference between the two is exactly those \(4\) orange cells.

Similarly to the case of \(\varphi(x,a)\), these numbers still have the form \(3k\), and from \(3k\le 30\) we know that \(k\) falls in \([2,\lfloor x/p_a\rfloor] = [2,10]\) inside the dashed box (\(k=1\) is not among them, which is exactly why \(3\) itself remains and does not turn orange). The difference is that \(k\) now only ranges over \(3,5,7,9\) (marked in the upper right corner of each orange cell): \(k\) must be a survivor of the previous round of sieving (otherwise \(3k\) would long ago have been sieved out together with \(k\)), i.e., \(2,3,5,7,9\) inside the box, \(S(x/p_a,a-1)=S(10,1)=5\) in total; among these, the primes smaller than \(p_a\) must also be removed – they are exactly the first \(a-1\) primes, here just \(k=2\) – because \(3\times 2=6\) was long ago sieved out by \(2\). Therefore

\[ S(x,a) = S(x,a-1) - \left(S\left(\left\lfloor\dfrac{x}{p_a}\right\rfloor, a-1\right) - (a-1)\right). \]

That is, \(S(30,2)=S(30,1)-\bigl(S(10,1)-(2-1)\bigr)=15-(5-1)=11\).

This recurrence relation is easy to compute with dynamic programming. Since \(S(x,a)=S(\lfloor x\rfloor,a)\), all divisions in the recurrence relation can be regarded as integer divisions. By the properties of floor-division blocks, the values of the first dimension in the dynamic programming must lie in the set \(D(x)\), which has only \(\Theta(\sqrt{x})\) elements. Moreover, due to the special form of the recurrence relation, the values \(S(\cdot,a)\) can be stored in a single array of length \(|D(x)|\); for each \(a\), traverse the elements of \(D(x)\) from largest to smallest and update the array using the recurrence relation, until the element is strictly smaller than \(p_a^2\). Only \(\pi(\sqrt{x})\) rounds of updates are needed to obtain the final result.

The space complexity of the algorithm is clearly \(O(x^{1/2})\). As for the time complexity, the complexity of the precomputation part is \(O(x^{1/2})\), and the complexity of the dynamic programming part is given by

\[ I = \sum_{a=1}^{\pi(\sqrt{x})}|\{u\in D(x) : u \ge p_a^2\}| \]

It can be estimated in two parts. For \(a\in[1,\pi(x^{1/4})]\), since the summand does not exceed \(|D(x)|\), this part of the sum does not exceed \(\pi(x^{1/4})|D(x)|\), which is \(O(x^{3/4}\log^{-1}x)\). For \(a\in(\pi(x^{1/4}),\pi(\sqrt{x})]\), we have \(p_a^2 > \sqrt{x}\); from the structure of the set \(D(x)\), the number of these elements is exactly \(\lfloor x/p_a^2\rfloor\). From this, combined with the prime number theorem \(p_a\sim a\log a\), we get

\[ \sum_{a=\pi(x^{1/4})+1}^{\pi(\sqrt{x})}\dfrac{x}{p_a^2} \in O\left(\int_{\pi(x^{1/4})}^{+\infty}\dfrac{x}{a^2\log^2a}da\right) = O\left(\dfrac{x^{3/4}}{\log x}\right). \]

Adding the two parts, the overall time complexity of the algorithm is \(O(x^{3/4}\log^{-1}x)\).

In a concrete implementation, the step of precomputing the primes not exceeding \(\sqrt{x}\) can be merged into the dynamic programming process. It suffices to enumerate all integers \(u\) in the interval \([2,\sqrt{x}]\) from small to large and check the condition \(S(u,\pi(u-1)) \neq S(u-1,\pi(u-1))\) to find all primes in the interval; when the condition holds, a state transition must be performed. The reason is that when the enumeration reaches \(u\), the transition to \(S(\cdot,\pi(u-1))\) has already been made, so \(\pi(u) = S(u,\pi(u-1))\) and \(\pi(u-1) = S(u-1,\pi(u-1))\), and the above condition holding necessarily means that \(u\) is prime. In addition, the value \(a-1\) in the state transition equation is also given by \(S(u-1,\pi(u-1))\), so it does not need to be maintained separately. This yields the following implementation:

// Lucy's Quotient DP to find pi.
long long lucy_pi(long long n) {
  int s = std::sqrt(n + 0.25l);
  // D(n) = {floor(n/x): x=1,2,...,n}
  std::vector<long long> d;
  for (long long l = 1, r; l <= n; l = r + 1) {
    r = n / (n / l);
    d.push_back(r);
  }
  int m = d.size();
  auto id = [&](long long x) -> int { return x <= s ? x - 1 : m - n / x; };
  // Quotient DP.
  std::vector<long long> dp(m);
  for (int j = 0; j < m; ++j) dp[j] = d[j] - 1;
  for (int p = 2; p <= s; ++p) {
    if (dp[p - 1] == dp[p - 2]) continue;  // Only primes can survive.
    for (int j = m - 1; d[j] >= (long long)p * p; --j) {
      dp[j] -= dp[id(d[j] / p)] - dp[p - 2];
    }
  }
  return dp.back();
}

This algorithm is simple to implement; although its time complexity is slightly worse, thanks to its very small constant factor it performs excellently for smaller data sizes. More importantly, since \(\pi(x)=S(x,a)\) holds for all \(a\ge \pi(\sqrt{x})\), as a byproduct the algorithm actually obtains the values of \(\pi(\cdot)\) at all elements of the set \(D(x)\). This property is especially important in problems of summing multiplicative functions; its generalization and applications will be discussed later.

Fenwick tree optimization

Using a Fenwick tree, it is easy to reduce the time complexity of Lucy's algorithm from \(\tilde O(x^{3/4})\) to \(\tilde O(x^{2/3})\).

To this end, take a real number \(y\in (\sqrt{x},x]\). The current state \(S(\cdot,a)\) is maintained in two parts: the part greater than \(y\) is still computed recursively according to the recurrence relation above; the part not greater than \(y\) is maintained with the sieve of Eratosthenes, using a Fenwick tree to update and query the current values of \(S(\cdot,a)\).

The space complexity of the algorithm is clearly \(O(y)\). To compute the time complexity of the algorithm, the following three parts need to be considered: in the sieve of Eratosthenes part, every composite number sieved out requires one update of the Fenwick tree, \(O(y)\) composite numbers in total, so the total time cost is \(O(y\log y)\); for \(p_a^2 \le y\), the state transition of the corresponding round needs to be performed \(O(x/y)\) times, each transition involving an \(O(\log y)\) query, with \(O(\pi(\sqrt{y}))\) such rounds in total, so the total time cost is

\[ O\left(\pi(\sqrt{y})\dfrac{x}{y}\log y\right) = O\left(\dfrac{x}{\sqrt{y}}\right) \]

Finally, for \(p_a^2 > y\), the state transition of the corresponding round needs to be performed \(O(x/p_a^2)\) times, and by the method of the previous subsection the total time cost is

\[ O\left(\sum_{a=\pi(\sqrt{y})+1}^{\pi(\sqrt{x})}\dfrac{x}{p_a^2}\log y\right) = O\left(\dfrac{x}{\sqrt{y}}\right) \]

Adding the three parts and setting \(y = x^{2/3}\log^{-2/3}x\), we get the overall time complexity \(O(x^{2/3}\log^{1/3}x)\). In this case, the space complexity is also \(\tilde O(x^{2/3})\).

// Submission:
// * https://judge.yosupo.jp/submission/397277 (1e11)
// * https://www.luogu.com.cn/record/295680548 (1e13, TLE)
// Binary-indexed tree.
struct BIT {
  int n;
  std::vector<int> su;

  BIT(int _n) : n(_n), su(_n + 1) {}

  void add(int x) {
    for (; x <= n; x += (x & (-x))) ++su[x];
  }

  int get(int x) {
    int res = 0;
    for (; x; x &= x - 1) res += su[x];
    return res;
  }
};

// Lucy's Quotient DP to find pi, with BIT optimization.
long long lucy_pi(long long n) {
  if (n <= 1) return 0;
  int s = std::sqrt(n + 0.25l);
  int y = std::pow(n / std::log(n), 2.0l / 3);
  y = std::max(y, s + 1);
  // D(n) = {floor(n/x): x=1,2,...,n}
  std::vector<long long> d;
  for (long long l = 1, r; l <= n; l = r + 1) {
    r = n / (n / l);
    d.push_back(r);
  }
  int m = d.size();
  auto id = [&](long long x) -> int { return x <= s ? x - 1 : m - n / x; };
  // Quotient DP.
  std::vector<bool> vis(y + 1);
  BIT bit(y);
  std::vector<long long> dp(m);
  for (int j = 0; j < m; ++j) dp[j] = d[j] - 1;
  auto eval = [&](long long x) -> long long {
    return x <= y ? x - 1 - bit.get(x) : dp[id(x)];
  };
  for (long long p = 2; p * p <= n; ++p) {
    if (vis[p]) continue;
    auto a_1 = eval(p - 1);
    auto lim = n / std::max(p * p, (long long)y);
    for (int i = 1; i <= lim; ++i) {
      dp.end()[-i] -= eval(n / (p * i)) - a_1;
    }
    // Sieve.
    for (auto x = p * p; x <= y; x += p) {
      if (!vis[x]) {
        vis[x] = true;
        bit.add(x);
      }
    }
  }
  return dp.back();
}

It should be noted that although the theoretical time complexity is indeed reduced, the constant-factor loss introduced by the Fenwick tree actually makes the algorithm slower for smaller data sizes, while for larger data sizes the significantly worse memory usage limits the algorithm's use. Therefore, this optimization is not very practical.

Further optimizations

Although the Fenwick tree successfully optimizes Lucy's algorithm to \(\tilde O(x^{2/3})\), the actual running efficiency is still not high. To obtain an efficient algorithm, Lucy's algorithm can be further optimized as follows (let \(z < w < y < x\), all of which are powers of \(x\)):

  1. In the Fenwick-tree-optimized Lucy's algorithm, the time cost of the sieve of Eratosthenes part is \(O(y\log y)\). In fact, in the first several rounds of state transitions, the number of composite numbers sieved out is huge, and there is no need to maintain them with a Fenwick tree. Therefore, one can choose \(z < y\). When \(p_a \le z\), only the state transition equation is used; when \(p_a > z\), the Fenwick tree is introduced to maintain the part of \(S(\cdot,a)\) not exceeding \(y\). Since by the time the Fenwick tree is introduced all integers containing a prime factor not greater than \(z\) have already been sieved out, among the remaining numbers – usually called \(z\)-rough numbers – only \(O\left(\dfrac{y}{\log z}\right)\) do not exceed \(y\)6. Thus the time cost of the sieve part can be reduced to \(O(y)\). The time cost introduced by these initial rounds of state transitions is \(O(x^{1/2}z/\log x)\).

  2. Lucy's algorithm described above ultimately obtains the values of \(\pi(\cdot)\) at all elements of \(D(x)\). If only the value \(\pi(x)\) is wanted, many state transitions are unnecessary. For example, to compute the value \(S(x,a)\), one only needs to know the values \(S(x,a-1)\) and \(S\left(\dfrac{x}{p_a},a-1\right)\); and to compute these two values, one only needs to know the values

    \[ S(x,a-2),~ S\left(\dfrac{x}{p_a},a-2\right),~ S\left(\dfrac{x}{p_{a-1}},a-2\right),~ S\left(\dfrac{x}{p_ap_{a-1}},a-2\right) \]

    By induction, at the \(i\)-th round of state transitions, the \(n\) in the states \(S\left(\dfrac{x}{n},i\right)\) whose values need to be known must be \(p_i\)-rough numbers. Since \(p_i\)-rough numbers are closed under multiplication, it suffices to process all \(p_i\)-rough numbers (as divisor nodes) at every state transition to guarantee that, when the state transitions terminate, the node values at all \(p_i\)-rough numbers are correct.

    Of course, the set of \(p_i\)-rough numbers can be maintained dynamically during the sieving process7; alternatively, the earlier set of \(z\)-rough numbers can be reused in place of all the sets of \(p_i\)-rough numbers. The second approach seemingly does some useless work, but both reduce the complexity of the state transition part by a factor of \(\log x\); they only differ in the constant factor.

  3. Similarly to the sieve part, the state transition part also has the problem of the extra \(\log x\) factor introduced by the Fenwick tree. To reduce Fenwick tree queries, the part of the Fenwick tree that is no longer updated can be stored in a static array. Specifically, when the state transitions reach the \(i\)-th round, the values \(S(u,i)\) at \(u < p_i^2\) no longer change, so they can be queried and stored.

    Let us compute the complexity improvement this brings. To incorporate the influence of the other optimizations, here we assume that state transitions with the Fenwick tree sieve are only used for the part \(z < p_i \le w\), and assume \(y \ge w^2\) so that the counts below are tight. Since the \(u\) for which a state transition needs to be performed necessarily have the form \(\lfloor x/j\rfloor\), it suffices to count the corresponding \(j\). For ease of computation, we ignore the discussion of the boundaries of the inequalities. Since \(u > y\), necessarily \(j < x / y\). If \(jp_i < x / y\), the Fenwick tree is not involved; if \(x / y < jp_i < \min\{x/p_i^2,p_ix/y\}\), the query can only be done on the Fenwick tree; if \(\min\{x/p_i^3,x/y\} < j < x/y\), the query can be done in the static array or on the Fenwick tree. The total count of the first part is

    \[ \sum_{z < p_i < w}\dfrac{x}{yp_i} = \dfrac{x}{y}\log\dfrac{\log w}{\log z} \in O\left(\dfrac{x}{y}\right). \]

    The total count of the second part is

    \[ \sum_{z < p_i < y^{1/3}}\dfrac{x}{y}\left(1-\dfrac{1}{p_i}\right) + \sum_{y^{1/3} < p_i < w}\left(\dfrac{x}{p_i^3} - \dfrac{x}{yp_i}\right) \le \dfrac{x}{y}\pi(y^{1/3}) + \dfrac{x}{y^{2/3}\log y} \in O\left(\dfrac{x}{y^{2/3}\log y}\right). \]

    The total count of the third part is

    \[ \sum_{y^{1/3} < p_i < w}\left(\dfrac{x}{y}-\dfrac{x}{p_i^3}\right) \le \pi(w)\dfrac{x}{y} \in O\left(\dfrac{xw}{y\log w}\right). \]

    The count of the first part is far smaller than the other two and can be neglected. When \(w^2 \le y \ll w^3\), the total count of the third part is far larger than that of the second part. Only then does storing this part of the values in a static array reduce the total time complexity of the state transition part by a factor of \(\log x\); otherwise, the queries of the second part become the bottleneck. In summary, after introducing this optimization, the total time complexity of the state transition part is

    \[ O\left(\max\left\{\dfrac{x}{y^{2/3}},\dfrac{xw}{y\log x}\right\}\right). \]

    Note that, since the distribution of rough numbers is roughly uniform, the effect of the second optimization (i.e., the rough number optimization of the state transition part) is independent of this one. If the rough number optimization is applied at the same time, the complexity obtained here can be reduced by another \(\log x\).

  4. The state transitions can be terminated early, updating only up to the part \(p_a\le w\), and the remaining part is handled with the idea of the Meissel–Lehmer algorithm. Unlike the Meissel–Lehmer algorithm, which relies on \(\varphi(x,a)\), \(S(x,a)\) stores the values of \(\pi(x)\) needed up to \(x \le p_a^2\), so no extra precomputation is needed. However, when combined with the previous optimization methods, one must pay attention to the influence of the rough number optimization of the dynamic programming part (i.e., optimization 2) and not use values that have not been correctly updated. Doing so improves both the time and the space complexity of the algorithm, but the specific extent of the improvement depends heavily on the implementation of the remaining parts, so no general analysis is given here. This part of the reference implementation will be analyzed concretely below.

Combine these four small optimizations. For any \(w \le x^{1/3}\), with \(z < w\) and \(w^2 \le y < w^3\), the total time complexity of the sieve part and the state transition part is

\[ O\left(y + \dfrac{z\sqrt{x}}{\log x} + \dfrac{xw}{y\log x}\right). \]

Hence, at \(y=x^{5/8}\log^{-1}x\) and \(z=w^{1/2}\), the total time complexity reaches \(O\left(\dfrac{\sqrt{xw}}{\log x}\right)\). Here, \(z\) is taken as large as possible without increasing the overall complexity, in order to reduce the density of \(z\)-rough numbers and lower the constant factor of the algorithm.

If the algorithm is terminated early at \(w=x^{1/3}\), the time and space complexity of the algorithm are both at least4 \(O(x^{2/3}\log^{-1}x)\). Below we show that if the algorithm is terminated at \(w=x^{1/4}\), lower time and space complexity is obtained.

Let \(w=x^{1/4}\). Since the algorithm terminates early at \(a=\pi(x^{1/4})\), to obtain \(\pi(x)\) we need to use the relation:

\[ \pi(x) = S(x,a) - P_2(x,a) - P_3(x,a). \]

From the earlier analysis we know

\[ P_2(x,a) = \sum_{i=a+1}^{\pi(\sqrt{x})}\pi\left(\dfrac{x}{p_i}\right) - \dfrac{1}{2}(\pi(\sqrt{x})+a-1)(\pi(\sqrt{x})-a). \]

Since we have already sieved up to \(p_a\), \(\pi(\sqrt{x})\) can be obtained from \(S(\cdot,a)\). However, since \(x/p_i\in[\sqrt{x},x^{3/4})\), the \(\pi(\cdot)\) in the sum still does not agree with \(S(\cdot,a)\). Hence, expanding further, we have

\[ \sum_{i=a+1}^{\pi(\sqrt{x})}\pi\left(\dfrac{x}{p_i}\right) = \sum_{i=a+1}^{\pi(\sqrt{x})}S\left(\dfrac{x}{p_i},a\right) - \sum_{i=a+1}^{\pi(\sqrt{x})}P_2\left(\dfrac{x}{p_i},a\right). \]

Substituting back into the previous formula, we get

\[ \begin{aligned} \pi(x) &= S(x,a) + \dfrac{1}{2}(\pi(\sqrt{x})+a-1)(\pi(\sqrt{x})-a) \\ &\quad - \sum_{i=a+1}^{\pi(\sqrt{x})}S\left(\dfrac{x}{p_i},a\right) + \underbrace{ \sum_{i=a+1}^{\pi(\sqrt{x})}P_2\left(\dfrac{x}{p_i},a\right) - P_3(x,a) }_{\Delta(x)}. \end{aligned} \]

To compute \(\Delta(x)\), consider its combinatorial meaning. From the definitions of \(P_2(x,a)\) and \(P_3(x,a)\) we know

\[ \begin{aligned} \sum_{i=a+1}^{\pi(\sqrt{x})}P_2\left(\dfrac{x}{p_i},a\right) &= \#\{p_ip_jp_k \le x : a < i,~ a < j \le k\},\\ P_3(x,a) &= \#\{p_ip_jp_k \le x : a < i \le j \le k\}. \end{aligned} \]

Taking the difference of the two sets, we get

\[ \Delta(x) = \#\{p_ip_jp_k \le x : a < j,~ j < i,~ j \le k\}. \]

To count, we still consider enumerating the least prime factor \(p_j\) (because its enumeration upper bound is the smallest); for fixed \(j\), the remaining indices must satisfy \(i > j\) and \(k \ge j\); hence, splitting off the special case \(k=j\), the remaining cases have \(i,k > j\), which can be further simplified using symmetry, giving the following expression:

\[ \Delta(x) = \underbrace{\sum_{j=a+1}^{\pi(x^{1/3})}\left(\pi\left(\dfrac{x}{p_j^2}\right) - j\right)}_{i > j = k} + \underbrace{2\sum_{j=a+1}^{\pi(x^{1/3})}\left(\sum_{i=j+1}^{\pi(\sqrt{x/p_j})}\left(\pi\left(\dfrac{x}{p_ip_j}\right) - i\right) \right)}_{i > k > j \text{ or }k > i > j } + \underbrace{\sum_{j=a+1}^{\pi(x^{1/3})}\left(\pi\left(\sqrt{\dfrac{x}{p_j}}\right) - j\right)}_{i=k > j}. \]

Rearranging the sums, we get

\[ \Delta(x) = \sum_{j=a+1}^{\pi(x^{1/3})}\left(\pi\left(\dfrac{x}{p_j^2}\right) - j + 2 \sum_{i=j+1}^{\pi(\sqrt{x/p_j})}\pi\left(\dfrac{x}{p_ip_j}\right) - \left( \pi\left(\sqrt{\dfrac{x}{p_j}}\right) ^ 2 - j^2 \right) \right). \]

Using this expression, the complexity of computing \(\Delta(x)\) is (for the estimation method, see the earlier part on the complexity of Lucy's algorithm)

\[ O\left(\sum_{x^{1/4} < p \le x^{1/3}}\pi\left(\sqrt{\dfrac{x}{p}}\right)\right) = O\left(\dfrac{x^{2/3}}{\log^2 x}\right). \]

This is also the complexity of the computation of the last part. A simple check shows that all terms \(\pi(x/n)\) involved in computing \(\Delta(x)\) satisfy \(x/n\le\sqrt{x} < y\), so they can all be obtained directly from the \(S(\cdot,a)\) stored in the Fenwick tree (they need to be stored in a static array in advance, to avoid introducing extra \(O(\log x)\) queries).

Combining with the earlier analysis, when \(z=x^{1/8},~w=x^{1/4},~y=x^{5/8}\log^{-1}x\), the total time complexity of the sieve and dynamic programming parts is \(O(x^{5/8}\log^{-1}x)\), so the overall time complexity of the algorithm is \(O(x^{2/3}\log^{-2}x)\). The space complexity is the length of the Fenwick tree, \(O(y)=O(x^{5/8}\log^{-1}x)\).

// Modified from 渐变色's codes:
//   https://www.luogu.com.cn/article/q4d4jl20
// Submission:
// * https://judge.yosupo.jp/submission/398981 (1e11)
// * https://www.luogu.com.cn/record/296415705 (1e13)
long long count_pi(long long n) {
  if (n <= 1) return 0;
  // Constants.
  int v = std::sqrt(n + 0.25l);                // x^{1/2}.
  int w = std::sqrt(v + 0.25l);                // x^{1/4}. Phase II stops here.
  int z = std::min(w, (int)std::sqrt(w) * 2);  // ~x^{1/8}. Phase I stops here.
  int y = std::pow(n, 0.625l) / std::log(n) * 2;  // ~x^{5/8}/log(x). BIT size.
  y = std::min<long long>(std::max(y, v), n);
  int B = n / y;  // the largest j such that n/j >= y.
  B = std::min<long long>(n / (n / B), y);
  // Initialize.
  std::vector<long long> l(v + 1);  // l[i] = S(n/i, .)
  std::vector<int> s(y + 1);        // phase I: S(i, .); phase II: BIT.
  std::vector<bool> e(y + 1);       // e[i] == true once i has been crossed out.
  std::vector<int> pi(y + 1);       // prefix for e; then pi(.) for O(1) query.
  for (int i = 1; i <= v; ++i) l[i] = n / i - 1;  // Lucy DP initialization.
  for (int i = 1; i <= v; ++i) s[i] = i - 1;

  // ============ PHASE I: plain Lucy DP, p <= z ~ n^(1/8) ===================
  int p;
  for (p = 2; p <= z; ++p) {
    if (s[p] != s[p - 1]) {  // when p is prime.
      auto m = n / p;
      int t0 = s[p - 1];  // the number of primes < p.
      int t = v / p;      // splitting point by where n/(i*p) lands.
      // S(u, .) -= (S(u / p) - t0), case by case.
      for (int i = 1; i <= t; ++i) l[i] -= l[i * p] - t0;
      for (int i = t + 1; i <= v; ++i) l[i] -= s[m / i] - t0;
      for (int i = v, j = t; j >= p; --j)
        for (int k = j * p; i >= k; --i) s[i] -= s[j] - t0;
      // Sieve.
      for (int i = p * p; i <= y; i += p) e[i] = 1;
    }
  }
  // Obtain z-rough number list for [2,B].
  e[1] = 1;
  int id = 1;
  std::vector<int> roughs(B + 1);
  for (int i = 1; i <= B; ++i)
    if (!e[i]) roughs[id++] = i;
  roughs[id] = 0x7fffffff;  // sentinel: terminates every walk.
  // Build the BIT (i.e., Fenwick tree).
  for (int i = 1; i <= y; ++i) pi[i] = pi[i - 1] + e[i];
  for (int i = 1; i <= y; ++i) s[i] = pi[i] - pi[i & (i - 1)];
  // BIT query: obtain S(x,.).
  const auto query = [&](int x) -> int {
    int sum = x;
    for (; x; x &= x - 1) sum -= s[x];
    return sum;
  };
  // BIT modify: mark composite and add 1 in the BIT.
  const auto add = [&](int x) -> void {
    e[x] = 1;
    for (; x <= y; x += x & -x) ++s[x];
  };

  // ============ PHASE II: Lucy DP with BIT sieve, z < p <= n^(1/4) =========
  id = 1;
  for (; p <= w; ++p) {
    if (e[p]) continue;
    auto q = (long long)p * p;
    auto m = n / p;
    int t0 = query(p - 1);  // the number of primes < p.
    // freeze finalized values for O(1) query.
    // the frozen S(i, .) is actually pi(i).
    for (; id < q; ++id) pi[id] = query(id);
    // splitting point by where n/(i*p) lands.
    int t1 = B / p;
    int t2 = std::min<long long>(B, m / q);
    // S(u, .) -= (S(u / p) - t0), case by case.
    int i = 1, j = 1;
    for (; i <= t1; i = roughs[++j]) l[i] -= l[i * p] - t0;
    for (; i <= t2; i = roughs[++j]) l[i] -= query(m / i) - t0;
    for (; i <= B; i = roughs[++j]) l[i] -= pi[m / i] - t0;
    // Sieve (with BIT).
    for (int i = q; i <= y; i += p)
      if (!e[i]) add(i);
  }
  // freeze value till v=x^{1/2}.
  for (; id <= v; ++id) pi[id] = query(id);
  // prime list till v=x^{1/2}.
  std::vector<int> primes;
  primes.push_back(1);  // dummy, p_0=1.
  for (int i = 2; i <= v; ++i)
    if (!e[i]) primes.push_back(i);

  // ============ PHASE III: stop early, correct with P2 and P3 ==============
  // ---- -P2, part 1: the triangular part.
  l[1] += (pi[v] + pi[w] - 1LL) * (pi[v] - pi[w]) / 2;
  // ---- -P2, part 2: the sum of S(n/p,a).
  for (int i = pi[w] + 1; i <= pi[B]; ++i) l[1] -= l[primes[i]];
  for (int i = pi[B] + 1; i <= pi[v]; ++i) l[1] -= query(n / primes[i]);
  // ---- +Delta(n).
  for (int i = pi[w] + 1; i <= pi[v]; ++i) {
    int p = primes[i];
    auto m = n / p;
    int e = pi[m / p];  // pi(n/p^2).
    if (e <= i) break;  // i.e., p^3 > n.
    l[1] += e - i;
    long long t = 0;
    auto s = pi[(int)std::sqrt(m + 0.25l)];  // pi(sqrt(n/p)).
    for (int k = i + 1; k <= s; ++k) t += pi[m / primes[k]];
    l[1] += 2 * t - (long long)(i + s) * (s - i);
  }

  return l[1];
}

Within the data ranges common in algorithm competitions (\(10^{10}\sim 10^{14}\)), the time and space cost of this implementation is quite good. It should be noted that although in the theoretical complexity analysis the last part is the complexity bottleneck, since its complexity has a smaller logarithmic factor and a better constant, within the above data ranges the actual bottleneck of the algorithm is still the sieve and dynamic programming parts. This is precisely why optimizing their complexity is indispensable.

Generalization: prefix sums of prime powers

More generally, consider the following problem:

\[ F_{\text{prime}}(x) = \sum_{p\in\mathbf P,~p\le x}f(p). \]

That is, compute the sum of the values of the number-theoretic function \(f(\cdot)\) at the primes not exceeding \(x\). The prime counting function \(\pi(x)\) is the special case \(f\equiv 1\).

Assume that the number-theoretic function \(f\) satisfies the following conditions:

  1. \(f\) is completely multiplicative, i.e., \(f(mn)=f(m)f(n)\) holds for all positive integers \(m,n\);
  2. the prefix sum \(F(x)=\sum_{n \le x}f(n)\) is easy to compute.

Common number-theoretic functions satisfying these conditions include power functions and Dirichlet characters (for example, the Legendre symbol). Of course, if some function can be expressed as a linear combination of several functions satisfying these conditions, its prefix sum over primes can also be obtained. Therefore, the method of this section can handle the cases where \(f\) is a polynomial or \(f\) is a periodic function5. Another, more concise way of handling periodic functions is described in the example problems below.

Under these conditions, the earlier recurrence relation can be generalized. Define \(S(x,a)\) as the sum of the values of \(f(\cdot)\) at the integers remaining in the interval \([2,x]\) after sieving out the first \(a\) primes, i.e.,

\[ S(x,a) = \sum_{1 < n \le x,~ (n\in\mathbf P) \lor (\operatorname{lpf}(n) > p_a)} f(n). \]

Then the earlier recurrence relation for \(S(x,a)\) can be rewritten as follows:

\[ S(x,a) = S(x,a-1) - [p_a^2 \le x]f(p_a)\left(S\left(\dfrac{x}{p_a},a-1\right)-S(p_{a}-1,a-1)\right). \]

The boundary condition is \(S(x,0) = F(x) - 1\). What this formula expresses is similar to before: in the sieve of Eratosthenes, a composite number sieved out by \(p_a\) must be the product of \(p_a\) and some integer not yet sieved out by the first \(a-1\) primes. However, among all integers not yet sieved out by the first \(a-1\) primes are the first \(a-1\) primes themselves, which need to be removed additionally. Therefore, to obtain the sum of the function values at these composite numbers, using complete multiplicativity, the coefficient \(f(p_a)\) can be factored out, and the remaining sum is \(S(x/p_a,a-1)\) minus the contribution \(S(p_a-1,a-1)\) of the first \((a-1)\) primes. Note that the subtracted term can also be written as \(S(p_{a-1},a-1)\); they are equal.

Using this recurrence relation, the value of \(F_{\text{prime}}(x)\) can be computed with Lucy's algorithm in \(O(x^{3/4}\log^{-1}x)\) time, with a space complexity of only \(O(x^{1/2})\). Using a Fenwick tree, the time complexity can be reduced to \(\tilde O(x^{2/3})\), but this is not very practical.

Reference implementation for the template problem Luogu P5493 质数前缀统计 (prime prefix statistics) 
#include <cmath>
#include <iostream>
#include <vector>

int solve(long long n, int k, int P) {
  int s = std::sqrt(n + 0.25l);
  // Linear sieve.
  std::vector<int> primes, vis(s + 1);
  for (int x = 2; x <= s; ++x) {
    if (!vis[x]) primes.push_back(x);
    for (int p : primes) {
      if (x * p > s) break;
      vis[x * p] = true;
      if (x % p == 0) break;
    }
  }
  // D(n) = {floor(n/x): x=1,2,...,n}.
  std::vector<long long> d;
  for (long long l = 1, r; l <= n; l = r + 1) {
    r = n / (n / l);
    d.push_back(r);
  }
  int m = d.size();
  auto id = [&](long long x) -> int { return x <= s ? x - 1 : m - n / x; };
  // binary exponentiation.
  auto pow = [&](long long a, int b) -> int {
    int res = 1, po = a % P;
    for (; b; b >>= 1) {
      if (b & 1) res = (long long)res * po % P;
      po = (long long)po * po % P;
    }
    return res;
  };
  // lagrange interpolation to initialize DP.
  std::vector<int> dp(m, P - 1), su(k + 2);
  for (int i = 1; i <= k + 1; ++i) {
    su[i] = (su[i - 1] + pow(i, k)) % P;
  }
  std::vector<int> ifa(k + 2);
  ifa[0] = ifa[1] = 1;
  for (int i = 2; i <= k + 1; ++i) {
    ifa[i] = (long long)(P - P / i) * ifa[P % i] % P;
  }
  for (int i = 2; i <= k + 1; ++i) {
    ifa[i] = (long long)ifa[i] * ifa[i - 1] % P;
  }
  for (int j = 0; j < m; ++j) {
    long long x = d[j] % P;
    std::vector<int> lp(k + 2), rp(k + 2);
    lp[0] = rp[k + 1] = 1;
    for (int i = 1; i <= k + 1; ++i) {
      lp[i] = lp[i - 1] * (x + P - (i - 1)) % P;
      rp[k + 1 - i] = rp[k + 2 - i] * (x + P - (k + 2 - i)) % P;
    }
    for (int i = 0; i <= k + 1; ++i) {
      dp[j] += ((k + 1 - i) % 2 ? P - 1LL : 1LL) * su[i] % P * lp[i] % P *
               rp[i] % P * ifa[i] % P * ifa[k + 1 - i] % P;
      if (dp[j] >= P) dp[j] -= P;
    }
  }
  // Lucy's Quotient DP.
  for (int p : primes) {
    auto pk_ = (P - 1LL) * pow(p, k) % P;
    for (int j = m - 1; d[j] >= (long long)p * p; --j) {
      dp[j] += pk_ * (dp[id(d[j] / p)] + P - dp[p - 2]) % P;
      if (dp[j] >= P) dp[j] -= P;
    }
  }
  // Output.
  long long res = 0;
  for (int i = 1; i <= s; ++i) {
    res += (long long)i * i % P * dp.end()[-i] % P;
  }
  return res % P;
}

int main() {
  long long n;
  int k, p;
  std::cin >> n >> k >> p;
  std::cout << solve(n, k, p) << std::endl;
  return 0;
}

In principle, for the generalized Lucy's algorithm it is recommended to precompute the primes rather than merging this into the dynamic programming. This is because the criterion \(S(u,\pi(u-1))\neq S(u-1,\pi(u-1))\) does not necessarily hold for general \(f\). In addition, although this section only discusses the generalization of Lucy's algorithm, the other algorithms can be generalized similarly; however, Lucy's algorithm can compute the values of \(F_\text{prime}\) at all values in \(D(x)\), which is more useful for the subsequent summation of multiplicative functions, so this section only introduces its generalization.

Codeforces 665 F. Four Divisors

Given \(n\), find the number of integers in \([1,n]\) that have exactly \(4\) divisors. Here \(1\le n\le 10^{11}\).

Solution

An integer with exactly \(4\) divisors must have the form \(p^3\) or \(pq\), where \(p,q\) are primes and \(p < q\). In the interval \([1,n]\), there are \(\pi(n^{1/3})\) integers of the form \(p^3\), and the number of integers of the form \(pq\) is

\[ \sum_{p < \sqrt{n}}\left(\pi\left(\dfrac{n}{p}\right)-\pi(p)\right) \]

Since all prime counting functions involved in the above expression can be computed from the values in the set \(D(n)\), a single run of Lucy's algorithm suffices to solve the problem. The time complexity is \(O(n^{3/4}\log^{-1}n)\), and the space complexity is \(O(n^{1/2})\).

Reference implementation 
#include <cmath>
#include <iostream>
#include <vector>

long long solve(long long n) {
  int s = std::sqrt(n + 0.25l);
  // D(n) = {floor(n/x): x=1,2,...,n}
  std::vector<long long> d;
  for (long long l = 1, r; l <= n; l = r + 1) {
    r = n / (n / l);
    d.push_back(r);
  }
  int m = d.size();
  auto id = [&](long long x) -> int { return x <= s ? x - 1 : m - n / x; };
  // Lucy's Quotient DP to find pi.
  std::vector<long long> dp(m);
  for (int j = 0; j < m; ++j) dp[j] = d[j] - 1;
  for (int p = 2; p <= s; ++p) {
    if (dp[p - 1] == dp[p - 2]) continue;  // Only primes can survive.
    for (int j = m - 1; d[j] >= (long long)p * p; --j) {
      dp[j] -= dp[id(d[j] / p)] - dp[p - 2];
    }
  }
  // Count p^3.
  long long res = dp[(int)std::cbrt(n + 0.25l) - 1];
  // Count pq.
  for (int p = 2; p <= s; ++p) {
    if (dp[p - 1] == dp[p - 2]) continue;
    res += dp.end()[-p] - dp[p - 1];
  }
  return res;
}

int main() {
  long long n;
  std::cin >> n;
  std::cout << solve(n) << std::endl;
  return 0;
}
LOJ 6028. “from CommonAnts” 质数计数 II (prime counting II)

Given \(n,m\), find, for each of the residues \(0,1,2,\dots,m-1\), how many primes in \([1,n]\) are congruent to it modulo \(m\). Here \(1\le n\le 3\times 10^{10}\), \(1 < m\le 12\), and \(n > m\).

Solution

For any residue \(r=0,1,2,\dots,m-1\), the function \([n\bmod m = r]\) is clearly periodic. As explained earlier, such problems can be handled by summing Dirichlet characters, but that is too cumbersome and involves complex-number computation. Therefore, this problem is solved with another method.

Consider adding one dimension to the state transition equation of Lucy's algorithm. Let \(S(n,r,a)\) denote the number of integers in \([2,n]\) that remain after sieving with the first \(a\) primes and are congruent to \(r\) modulo \(m\). Similarly to the main text, the following recurrence relation is obtained:

\[ S(n,rp_a\bmod m,a) = S(n,rp_a\bmod m,a-1) - [p_a^2 \le n]\left(S\left(\dfrac{n}{p_a},r,a-1\right)-S(p_{a}-1,r,a-1)\right). \]

In the recurrence formula, the second argument of the function uses multiplication rather than division, taking into account the possibility that \(p_a\mid m\). The boundary condition is \(S(n,r,0) = \left\lfloor\dfrac{n-r}{m}\right\rfloor + [r> 1]\). Based on this, the problem can be solved by dynamic programming. The time complexity is \(O(mn^{3/4}\log^{-1}n)\), and the space complexity is \(O(mn^{1/2})\).

Reference implementation 
#include <cmath>
#include <iostream>
#include <numeric>
#include <vector>

std::vector<long long> solve(long long n, int m) {
  int s = std::sqrt(n + 0.25l);
  // Linear sieve.
  std::vector<int> primes, vis(s + 1);
  for (int x = 2; x <= s; ++x) {
    if (!vis[x]) primes.push_back(x);
    for (int p : primes) {
      if (x * p > s) break;
      vis[x * p] = true;
      if (x % p == 0) break;
    }
  }
  // D(n) = {floor(n/x): x=1,2,...,n}
  std::vector<long long> d;
  for (long long l = 1, r; l <= n; l = r + 1) {
    r = n / (n / l);
    d.push_back(r);
  }
  int sz = d.size();
  auto id = [&](long long x) -> int { return x <= s ? x - 1 : sz - n / x; };
  // Lucy DP mod MOD.
  std::vector<std::vector<long long>> dp(sz, std::vector<long long>(m));
  for (int j = 0; j < sz; ++j) {
    for (int r = 0; r < m; ++r) {
      dp[j][r] = (d[j] + m - r) / m - (r <= 1);
    }
  }
  for (int p : primes) {
    for (int j = sz - 1; d[j] >= (long long)p * p; --j) {
      for (int r = 0; r < m; ++r) {
        dp[j][r * p % m] -= dp[id(d[j] / p)][r] - dp[p - 2][r];
      }
    }
  }
  // Finalize.
  return dp.back();
}

int main() {
  long long n;
  int m;
  std::cin >> n >> m;
  auto res = solve(n, m);
  for (auto x : res) std::cout << x << '\n';
  return 0;
}
