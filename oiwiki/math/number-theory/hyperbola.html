Predznanje: Dirichletova konvolucija, blokovsko dijeljenje po cjelobrojnom kvocijentu

Ovaj članak predstavlja Dirichletovu metodu hiperbole, kojom se u sublinearnoj vremenskoj složenosti može izračunati prefiksna suma Dirichletove konvolucije dviju teorijsko-brojevnih funkcija. Analizom tog algoritma dolazi se do pojma blokovskog sita; na temelju toga članak dalje predstavlja metodu brzog računanja konvolucije blokovskih sita. Na kraju članak predstavlja Du sito, kojim se može izračunati prefiksna suma kvocijenta dviju teorijsko-brojevnih funkcija u smislu Dirichletove konvolucije.

Dirichletova metoda hiperbole

Dirichletova metoda hiperbole može se koristiti za računanje prefiksne sume Dirichletove konvolucije dviju teorijsko-brojevnih funkcija.

Neka su \(f,g,h\) teorijsko-brojevne funkcije i \(h = f\ast g\). Tada je, prema definiciji Dirichletove konvolucije, prefiksna suma \(h\)

\[ H(n) = \sum_{k=1}^nh(k) = \sum_{k=1}^n\sum_{xy=k}f(x)g(y). \]

Skup točaka po kojima suma prolazi upravo je skup cjelobrojnih točaka u prvom kvadrantu (bez koordinatnih osi) ispod hiperbole \(xy=n\). Pridružimo li cjelobrojnoj točki \((x,y)\) težinu \(f(x)g(y)\), onda je \(H(n)\) zbroj tih težina.

Kao što slika pokazuje, taj se zbroj težina može izračunati načelom uključivanja-isključivanja:

\[ H(n) = \sum_{x=1}^{\lfloor x_0\rfloor}f(x)G\left(\left\lfloor\dfrac{n}{x}\right\rfloor\right) + \sum_{y=1}^{\lfloor y_0\rfloor}F\left(\left\lfloor\dfrac{n}{y}\right\rfloor\right)g(y) - F(\lfloor x_0\rfloor)G(\lfloor y_0\rfloor). \]

Pritom su \(F,G\) redom funkcije prefiksnih suma od \(f,g\), a \((x_0,y_0)\) je proizvoljna točka na hiperboli \(xy=n\). U izrazu prvi član predstavlja zbroj težina zelenog područja na slici, drugi član zbroj težina narančastog područja, a treći član zbroj težina presjeka tih dvaju područja. Taj izraz ima samo \(\lfloor x_0\rfloor + \lfloor y_0\rfloor + 1\) članova. Za razumno odabranu točku \((x_0,y_0)\) njegova je složenost računanja znatno bolja od izravnog (brute-force) računanja prefiksne sume \(h(n)\). To je Dirichletova metoda hiperbole (Dirichlet hyperbola method).

Računanje vrijednosti prefiksne sume konvolucije

Najosnovnija primjena Dirichletove metode hiperbole jest računanje vrijednosti \(H(n)\) funkcije prefiksnih suma u jednoj točki.

Ako su vrijednosti \(F,G\) poznate (ili se mogu izračunati u \(O(1)\)), a time su poznate i vrijednosti \(f,g\), onda se svaki član u izrazu Dirichletove metode hiperbole može izračunati u \(O(1)\), pa je ukupna vremenska složenost \(O(x_0+y_0)\). Budući da je \(x_0y_0=n\), iz nejednakosti između aritmetičke i geometrijske sredine slijedi da se za \(x_0=y_0=\sqrt{n}\) dobiva najmanja vremenska složenost \(O(\sqrt{n})\).

To nije novi rezultat. Stavimo li u izrazu Dirichletove metode hiperbole \(x_0 > n\), dobivamo

\[ H(n) = \sum_{x=1}^nf(x)G\left(\left\lfloor\dfrac{n}{x}\right\rfloor\right). \]

Tehnikom blokovskog dijeljenja po cjelobrojnom kvocijentu taj se izraz, kad su vrijednosti \(F,G\) poznate, može izračunati u vremenu \(O(\sqrt{n})\). To je zapravo gotovo ekvivalentno algoritmu dobivenom u ovom odjeljku: obje metode zahtijevaju u osnovi iste poznate informacije, a izrazi koje računaju otprilike su isti.

Objašnjenje ekvivalentnosti

Pažljivijim promatranjem postupka računanja blokovskim dijeljenjem vidi se da se zapravo računa izraz

\[ H(n) = \sum_{y\in D(n)}\left(F\left(\left\lfloor\dfrac{n}{y}\right\rfloor\right)-F\left(\left\lfloor\dfrac{n}{y+1}\right\rfloor\right)\right)G(y). \]

Pritom je \(D(n) = \left\{\left\lfloor\dfrac{n}{x}\right\rfloor : 1 \le x \le n,~x\in\mathbf N_+\right\}\) skup ključnih točaka blokovskog dijeljenja.

Prema svojstvima blokovskog dijeljenja, za \(x\le\sqrt{n}\) visine odgovarajućih blokova \(y = \lfloor n/x\rfloor\) međusobno su različite, pa su duljine tih blokova sve jednake \(1\), tj.

\[ \left\lfloor\dfrac{n}{y+1}\right\rfloor + 1 = x = \left\lfloor\dfrac{n}{y}\right\rfloor. \]

Stoga je suma koja odgovara tim blokovima

\[ I_1 = \sum_{x=1}^{\lfloor\sqrt{n}\rfloor}\left(F(x)-F(x-1)\right)G\left(\left\lfloor\dfrac{n}{x}\right\rfloor\right) = \sum_{x=1}^{\lfloor\sqrt{n}\rfloor}f(x)G\left(\left\lfloor\dfrac{n}{x}\right\rfloor\right). \]

Za preostale blokove visina \(y\) prolazi \(1,2,\cdots,y^*= \left\lfloor\dfrac{n}{\lfloor\sqrt{n}\rfloor + 1}\right\rfloor\). Primjenom Abelove transformacije (tj. sumacijskog oblika parcijalne integracije) na preostalu sumu dobivamo

\[ \begin{aligned} I_2 &= \sum_{y=1}^{y^*}\left(F\left(\left\lfloor\dfrac{n}{y}\right\rfloor\right)-F\left(\left\lfloor\dfrac{n}{y+1}\right\rfloor\right)\right)G(y) \\ &= \sum_{y=1}^{y^*}F\left(\left\lfloor\dfrac{n}{y}\right\rfloor\right)g(y) - F\left(\left\lfloor\dfrac{n}{y^*+1}\right\rfloor\right)G(y^*). \end{aligned} \]

Svojstva blokovskog dijeljenja kažu da je \(\lfloor n/\lfloor \sqrt{n}\rfloor\rfloor \ge \lfloor \sqrt{n}\rfloor\). Razlikujemo dva slučaja:

  • Kada je \(\lfloor n/\lfloor \sqrt{n}\rfloor\rfloor = \lfloor \sqrt{n}\rfloor\), nužno je \(y^* < \lfloor \sqrt{n}\rfloor\). Budući da je taj blok susjedan bloku u kojem je \(x = \lfloor \sqrt{n}\rfloor\), visine blokova mogu se razlikovati samo za točno jedan, tj. \(y^* = \lfloor \sqrt{n}\rfloor - 1\). Tada vrijedi

    \[ \begin{aligned} I_2 &= \sum_{y=1}^{\lfloor\sqrt{n}\rfloor-1}F\left(\left\lfloor\dfrac{n}{y}\right\rfloor\right)g(y) - F(\lfloor\sqrt{n}\rfloor)G(\lfloor\sqrt{n}\rfloor-1)\\ &= \sum_{y=1}^{\lfloor\sqrt{n}\rfloor-1}F\left(\left\lfloor\dfrac{n}{y}\right\rfloor\right)g(y) - F(\lfloor\sqrt{n}\rfloor)\left(G(\lfloor\sqrt{n}\rfloor) - g(\lfloor\sqrt{n}\rfloor)\right) \\ &= \sum_{y=1}^{\lfloor\sqrt{n}\rfloor}F\left(\left\lfloor\dfrac{n}{y}\right\rfloor\right)g(y) - F(\lfloor\sqrt{n}\rfloor)G(\lfloor\sqrt{n}\rfloor). \end{aligned} \]

  • Kada je \(\lfloor n/\lfloor \sqrt{n}\rfloor\rfloor > \lfloor \sqrt{n}\rfloor\), nužno je \(y^* = \lfloor \sqrt{n}\rfloor\). Izravnim uvrštavanjem u sumu dobivamo

    \[ I_2 = \sum_{y=1}^{\lfloor\sqrt{n}\rfloor}F\left(\left\lfloor\dfrac{n}{y}\right\rfloor\right)g(y) - F(\lfloor\sqrt{n}\rfloor)G(\lfloor\sqrt{n}\rfloor). \]

Ukupno, osim jedne Abelove transformacije, postupak računanja blokovskim dijeljenjem zapravo računa sljedeći izraz:

\[ H(n) = \sum_{x=1}^{\lfloor\sqrt{n}\rfloor}f(x)G\left(\left\lfloor\dfrac{n}{x}\right\rfloor\right) + \sum_{y=1}^{\lfloor\sqrt{n}\rfloor}F\left(\left\lfloor\dfrac{n}{y}\right\rfloor\right)g(y) - F(\lfloor\sqrt{n}\rfloor)G(\lfloor\sqrt{n}\rfloor). \]

To je upravo izraz Dirichletove metode hiperbole za \((x_0,y_0)=(\sqrt{n},\sqrt{n})\). Stoga možemo reći da su postupci računanja obaju algoritama gotovo ekvivalentni. Štoviše, budući da Dirichletova metoda hiperbole koristi više svojstava blokovskog dijeljenja i izbjegava nepotrebna računanja naivnog blokovskog dijeljenja, ima nešto manju konstantu.

Pri rješavanju stvarnih problema uvjet da su vrijednosti \(F,G\) poznate može biti prejak. Međutim, Dirichletova metoda hiperbole (ili odgovarajuće blokovsko dijeljenje) zapravo ne zahtijeva informacije o svim vrijednostima \(F,G\). Promotrimo li izraz za sumu, vidimo da su zapravo potrebne samo vrijednosti \(F\) i \(G\) na skupu ključnih točaka blokovskog dijeljenja

\[ D(n) = \left\{\left\lfloor\dfrac{n}{x}\right\rfloor : 1 \le x \le n,~x\in\mathbf N_+\right\} \]

To je ujedno skup svih visina blokova i skup svih desnih krajeva blokova. Uočimo da prema svojstvima blokovskog dijeljenja taj skup sadrži sve cijele brojeve \(1\le x\le\sqrt{n}\), pa je poznavanje vrijednosti \(F,G\) na \(D(n)\) ekvivalentno poznavanju vrijednosti \(f,g\) u svim točkama \(1\le x\le\sqrt{n}\). Veličina tog skupa je \(\Theta(\sqrt{n})\), pa je pri računanju \(H(n)\) dovoljno znati vrijednosti \(F,G\) na rijetkom skupu točaka. To je opažanje ključno za optimizaciju računanja prefiksnih suma teorijsko-brojevnih funkcija.

Blokovsko sito i njegova konvolucija

Ponekad \(h=f\ast g\) nije funkcija čiju prefiksnu sumu na kraju treba izračunati, nego samo jedan od međukoraka. Prema prethodnoj analizi, za daljnje računanje treba odrediti vrijednosti funkcije prefiksnih suma \(H\) na skupu \(D(n)\). To nazivamo blokovskim sitom (block sieve) teorijsko-brojevne funkcije \(h\):

\[ \mathcal S_h(n) = \left\{H(x) : x \in D(n)\right\}. \]

Ovaj odjeljak razmatra metode računanja problema konvolucije blokovskih sita: za poznata blokovska sita \(f,g\) odrediti blokovsko sito njihove Dirichletove konvolucije \(h = f\ast g\).

Naivni algoritam

Naivni algoritam promatra računanje blokovskog sita kao \(|D(n)|\) računanja vrijednosti prefiksne sume. Ukupna je vremenska složenost tog pristupa

\[ \begin{aligned} O\left(\sum_{d\in D(n)}\sqrt{d}\right) &= O\left(\sum_{x=1}^{\lfloor\sqrt{n}\rfloor}\sqrt{x} + \sum_{x=1}^{\lfloor\sqrt{n}\rfloor}\sqrt{\dfrac{n}{x}}\right) \\ &= O\left(\int_1^{\sqrt{n}}\sqrt{x}\mathrm{d}x + \int_1^{\sqrt{n}}\sqrt{\dfrac{n}{x}}\mathrm{d}x\right)\\ &= O(n^{3/4}). \end{aligned} \]

Upravo zato što je blokovsko sito rijetko, cijelo se blokovsko sito može izračunati u sublinearnom vremenu.

Ipak, taj je algoritam očito previše grub. Manji elementi skupa \(D(n)\) relativno su gusti, pa se susjedne prefiksne sume u blokovskom situ ne razlikuju mnogo; sasvim je moguće izravno izračunati vrijednosti konvolucije \(h\) i zatim njihovu prefiksnu sumu. To je brže nego za svaku točku zasebno računati vrijednost prefiksne sume. Primjerice, računanje vrijednosti prefiksne sume zasebno za \(x = 1,2,\cdots,\lfloor\sqrt{n}\rfloor\) zahtijeva

\[ O\left(\sum_{x=1}^{\lfloor\sqrt{n}\rfloor}\sqrt{x}\right) = O(n^{3/4}) \]

vremena; no izravno računanje vrijednosti \(h\) u tim točkama i zatim zbrajanje zahtijeva samo \(O(n^{1/2}\log n)\) vremena. Unatoč tome, ako su poznata samo blokovska sita \(f,g\) i ništa više, tom se idejom složenost algoritma ne može dalje optimizirati. Naime, blokovsko sito sadrži informacije o vrijednostima samo za \(x \le \sqrt{n}\), pa se vrijednosti \(h\) mogu izračunati najviše u točkama \(1\le x\le\sqrt{n}\), dok računanje preostalih vrijednosti prefiksne sume i dalje zahtijeva \(O(n^{3/4})\) vremena.

Optimizacija pomoću informacija o vrijednostima

Ako poznate informacije osim blokovskih sita \(f,g\) uključuju i više njihovih vrijednosti, složenost se tog algoritma doista može poboljšati. U praksi se taj algoritam obično primjenjuje kad se vrijednosti \(f,g\) mogu brzo predračunati.

Odaberimo \(z \ge \sqrt{n}\). Blokovsko sito konvolucije \(h\) dijelimo na dva dijela:

  • Izračunamo vrijednosti konvolucije \(h\) od \(f\ast g\) u točkama \(1\le x \le z\), a zatim izravnim zbrajanjem dobijemo vrijednosti \(H\) u točkama \(1\le x\le z\).
  • Za \(x\in D(n)\) takve da je \(x > z\) vrijednost \(H\) u točki \(x\) računamo Dirichletovom metodom hiperbole.

U općem slučaju vremenska je složenost tog pristupa

\[ \begin{aligned} O\left(z\log z + \sum_{d\in D(n),~d\ge z}\sqrt{d}\right) &= O\left(z\log z + \sum_{x=1}^{n/z}\sqrt{\dfrac{n}{x}}\right)\\ &= O\left(z\log z + \int_1^{n/z}\sqrt{\dfrac{n}{x}}\mathrm{d}x\right)\\ &= O\left(z\log z + \dfrac{n}{\sqrt{z}}\right). \end{aligned} \]

Za \(z=\left(\dfrac{n}{\log n}\right)^{2/3}\) ukupna vremenska složenost je najmanja i iznosi \(O\left(n^{2/3}(\log n)^{1/3}\right)\).

Naravno, složenost računanja vrijednosti Dirichletove konvolucije ovisi o svojstvima \(f,g,h\). Kad \(f,g,h\) imaju posebna svojstva, optimalna točka podjele i složenost malo se razlikuju:

  • Ako je \(f\) ili \(g\) multiplikativna, onda je za \(z=\left(\dfrac{n}{\log\log n}\right)^{2/3}\) ukupna vremenska složenost najmanja i iznosi \(O\left(n^{2/3}(\log\log n)^{1/3}\right)\).
  • Ako je \(h\) multiplikativna, onda je za \(z=n^{2/3}\) ukupna vremenska složenost najmanja i iznosi \(O(n^{2/3})\).

Za primjenu ove optimizacije nisu potrebne sve vrijednosti \(f,g\), nego samo njihove vrijednosti u točkama \(1\le x\le z\). Budući da ovaj algoritam daje i vrijednosti \(h\) u točkama \(1\le x\le z\), kad je \(h\) međurezultat, i vrijednosti \(h\) mogu se iskoristiti za optimizaciju daljnjeg računanja. Blokovsko sito teorijsko-brojevne funkcije zajedno s tim vrijednostima čini pojačanu verziju blokovskog sita: to su sve informacije potrebne za računanje prefiksne sume konvolucije u vremenu \(O(n^{2/3+\varepsilon})\).

Brza konvolucija blokovskih sita

Predznanje: brza Fourierova transformacija

Napomena

Početnici mogu preskočiti ovaj odjeljak.

Ovaj odjeljak razmatra algoritam brze konvolucije blokovskih sita koji je Zhou Kangyang predložio u radu za kineski nacionalni pripremni tim 2024. godine. On u vremenu \(O(\sqrt{n}\log^2n)\) iz blokovskih sita \(\mathcal S_f\) i \(\mathcal S_g\) računa vrijednosti \(\mathcal S_h\) njihove konvolucije. Taj algoritam ne ovisi o dodatnim informacijama o vrijednostima ni o multiplikativnosti teorijsko-brojevnih funkcija, ali je implementacija složenija.

Problem konvolucije blokovskih sita traži da se izračunaju prefiksne sume

\[ h(z) = \sum_{xy=z} f(x)g(y) \]

na blokovskom situ \(D(n) = \{\left\lfloor n / t\right\rfloor : 1\le t \le n\}\). Za taj se problem pojedinačni doprinos može označiti trojkom \((x,y,t)\), tj. postupkom pribrajanja člana \(f(x)g(y)\) prefiksnoj sumi u točki \(\left\lfloor n / t\right\rfloor\). Algoritam te doprinose obrađuje podijeljene u nekoliko skupina.

Prvo razmotrimo doprinose svih točaka s \(x > \sqrt{n}\) ovom nizu prefiksnih suma; doprinosi s \(y > \sqrt{n}\) obrađuju se analogno. Budući da svi doprinosi moraju zadovoljavati \(xy \le \lfloor n / t\rfloor\), tj. \(xyt \le n\), dovoljno je nabrojiti sve moguće \(t,y\) i pomoću tehnike prefiksnih suma te informacija iz blokovskog sita \(\mathcal S_f\) taj se dio doprinosa može izračunati u vremenu \(O(\sum_{t,y: ty\le\sqrt{n}} 1) = O(\sqrt{n}\log n)\).

Zatim razmotrimo dio doprinosa za koje je \(\left\lfloor n / t\right\rfloor\le\sqrt{n}\). Taj se dio također može obaviti izravnim nabrajanjem svih mogućih \(x,y\), a vremenska je složenost i dalje \(O(\sum_{x,y:xy\le\sqrt{n}}1) = O(\sqrt{n}\log n)\). Tim se dijelom zapravo dobivaju prve \(\lfloor\sqrt{n}\rfloor\) vrijednosti funkcije \(h\) na \(D(n)\).

Razmotrimo preostale doprinose, tj. one za koje je \(x,y\le\sqrt{n}\) i \(\left\lfloor n / t\right\rfloor > \sqrt{n}\). Svi doprinosi moraju zadovoljavati \(xyt\le n\), tj. \(\ln x + \ln y \le \ln(n/t)\). Uzmimo pozitivan broj \(S\); taj se uvjet može približno procijeniti pomoću \(\lceil S\ln x\rceil + \lceil S\ln y\rceil \le S\ln(n/t)\). Definirajmo polinome \(\sigma_f(u)\) i \(\sigma_g(u)\) tako da su njihovi koeficijenti \([u^k]\sigma_f\) i \([u^k]\sigma_g\) redom jednaki zbroju vrijednosti \(f(x)\) za koje je \(\lceil S\ln x\rceil = k\) i zbroju vrijednosti \(g(y)\) za koje je \(\lceil S\ln y\rceil = k\) (promatramo samo dio s \(x,y\le\sqrt{n}\)). Brzom Fourierovom transformacijom (FFT) možemo dobiti njihov umnožak \(\sigma_f\sigma_g\), čiji koeficijent \([u^k](\sigma_f\sigma_g)\) predstavlja zbroj \(f(x)g(y)\) za koje je \(\lceil S\ln x\rceil + \lceil S\ln y\rceil = k\). Stoga je za svaki preostali \(\lfloor n/t\rfloor\) u \(D(n)\) dovoljno pronaći najveću vrijednost \(k\) koja zadovoljava \(k \le S\ln(n/t)\) i dobivamo procjenu tog dijela doprinosa.

Naposljetku za taj dio doprinosa provodimo ispravak pogreške. Prethodno smo uvjet \(\ln x + \ln y \le \ln(n/t)\) pokušali aproksimirati jačim uvjetom \(\lceil S\ln x\rceil + \lceil S\ln y\rceil \le S\ln(n/t)\), čime je dio doprinosa možda propušten. To se može dogoditi samo kada je \(\lceil S\ln x\rceil + \lceil S\ln y\rceil > S\ln(n/t)\), pa vrijedi

\[ S\ln x + 1 + S\ln y + 1 \ge \lceil S\ln x\rceil + \lceil S\ln y\rceil > S\ln(n/t) \ge S\ln x + S\ln y. \]

To je ekvivalentno s

\[ xyt \in (n\mathrm{e}^{-2/S},n]. \]

To je interval duljine \(O(n/S)\). Nabrajanjem svih mogućih doprinosa \((x,y,t)\) unutar intervala i provjerom jednog po jednog je li propušten dovršavamo ispravak pogreške. Da bismo brzo nabrojili sve doprinose unutar intervala, možemo najprije prosijati sve proste brojeve koji ne prelaze \(\sqrt{n}\), a zatim tim prostim brojevima dijeliti cijele brojeve u intervalu; preostali faktor nužno je prost broj veći od \(\sqrt{n}\), čime dobivamo rastav na proste faktore svih cijelih brojeva u intervalu, a potom možemo brzo nabrojiti sve moguće \((x,y,t)\).

Promotrimo vremensku složenost računanja ovog posljednjeg dijela doprinosa. Pri procjeni doprinosa treba pomnožiti polinome duljine \(S\log n\), što ima vremensku složenost \(O(S\log n\log(S\log n))\). Pri ispravku pogreške vremenska složenost predračuna rastava na proste faktore iznosi \(O(\sqrt{n}+(n/S)\log\log n)\), a vremenska složenost nabrajanja svih doprinosa u intervalu iznosi \(O(\sum_{k\in(n\mathrm{e}^{-2/S},n]}d_3(k))\), gdje \(d_3(n)\) označava broj načina da se \(n\) zapiše kao umnožak triju uređenih cijelih brojeva. Rezultat analitičke teorije brojeva1 kaže:

\[ \sum_{k\le n}d_3(k) = nP(\log n) + O(n^{43/96+\varepsilon}), \]

gdje je \(P(\cdot)\) polinom drugog stupnja. Budući da je vremenska složenost prvih dvaju koraka već \(O(\sqrt{n}\log n)\), zanemarimo li sve članove \(o(\sqrt{n}\log n)\), vremenska složenost računanja ovog posljednjeg dijela doprinosa iznosi

\[ O\left(S\log n\log(S\log n) + \dfrac{n}{S} \log^2n\right). \]

Uzmemo li \(S = \sqrt{n}\), dobivamo vremensku složenost \(O(\sqrt{n}\log^2n)\). To je ujedno ukupna vremenska složenost algoritma.

Referentna implementacija 
struct BlockSieve {
  long long n, b;
  std::vector<int> s1, s2;

  BlockSieve(long long _n)
      : n(_n), b(std::sqrt(_n + 0.25l)), s1(b + 1), s2(b + 1) {}

  int& operator[](long long x) { return x <= b ? s1[x] : s2[n / x]; }
};

// Fast block sieve convolution by ZKY.
BlockSieve block_sieve_convolute(const BlockSieve& f, const BlockSieve& g) {
  // Special cases for n <= 3 are not implemented.
  // The upper bound is a loose bound for NTT to work for M = 998244353.
  assert(f.n == g.n && f.n > 3 && f.n < 1e11);
  long long n = f.n, b = f.b;
  BlockSieve h(n);
  std::vector<int> df(b + 1), dg(b + 1);
  for (int i = 1; i <= b; ++i) {
    df[i] = (f.s1[i] + M - f.s1[i - 1]) % M;
    dg[i] = (g.s1[i] + M - g.s1[i - 1]) % M;
  }
  // Prefix sum trick for x or y > sqrt(n).
  for (int t = 1; t <= n / (b + 1); ++t) {
    long long x;
    for (int y = 1; (x = n / (t * y)) > b; ++y) {
      (h.s2[t] += (long long)dg[y] * (f.s2[n / x] + M - f.s1[b]) % M) %= M;
      (h.s2[t] += (long long)df[y] * (g.s2[n / x] + M - g.s1[b]) % M) %= M;
    }
  }
  // Brutal force for small x*y.
  for (int x = 1; x <= b; ++x) {
    for (int y = 1; x * y <= b; ++y) {
      (h.s1[x * y] += (long long)df[x] * dg[y] % M) %= M;
    }
  }
  for (int i = 1; i <= b; ++i) {
    (h.s1[i] += h.s1[i - 1]) %= M;
  }
  // Approximation.
  std::vector<int> id1(b + 1);
  for (int i = 1; i <= b; ++i) {
    id1[i] = std::ceil(b * std::log(i));
  }
  std::vector<long double> id2(b + 1);
  for (int i = 1; i <= b; ++i) {
    id2[i] = b * std::log(1.0l * n / i);
  }
  std::vector<int> sf(id1[b] + 1), sg(id1[b] + 1);
  for (int i = 1; i <= b; ++i) {
    (sf[id1[i]] += df[i]) %= M;
    (sg[id1[i]] += dg[i]) %= M;
  }
  auto sh = ntt_mul(sf, sg);
  for (int i = 1; i < (int)sh.size(); ++i) {
    (sh[i] += sh[i - 1]) %= M;
  }
  for (int t = 1; t <= n / (b + 1); ++t) {
    int k = std::min((int)std::floor(id2[t]), (int)sh.size() - 1);
    (h.s2[t] += sh[k]) %= M;
  }
  // Correction.
  auto primes = get_primes(b);  // Obtain primes not exceeding b.
  long long l = n * std::exp(-2.0l / b);
  std::vector<long long> co(n - l + 1);
  std::iota(co.begin(), co.end(), l);
  std::vector<std::vector<std::pair<long long, int>>> fac(n - l + 1);
  for (int p : primes) {
    for (int i = (l + p - 1) / p * p - l; i <= n - l; i += p) {
      int e = 0;
      for (; co[i] % p == 0; co[i] /= p) ++e;
      fac[i].emplace_back(p, e);
    }
  }
  for (int i = 0; i <= n - l; ++i) {
    if (co[i] != 1) {
      fac[i].emplace_back(co[i], 1);
    }
  }
  long long num = 0;
  std::vector<std::pair<long long, int>> cur;
  auto dfs = [&](auto&& dfs, int k, int x, int y) {
    if (k == (int)cur.size()) {
      auto t = num / x / y;
      if (t && t <= n / (b + 1) && id1[x] + id1[y] > id2[t]) {
        (h.s2[t] += (long long)df[x] * dg[y] % M) %= M;
      }
      return;
    }
    auto p = cur[k].first;
    auto e = cur[k].second;
    long long nx = x;
    for (int e1 = 0; e1 <= e; ++e1) {
      if (e1) {
        nx *= p;
        if (nx > b) break;
      }
      long long ny = y;
      for (int e2 = 0; e1 + e2 <= e; ++e2) {
        if (e2) {
          ny *= p;
          if (ny > b) break;
        }
        dfs(dfs, k + 1, nx, ny);
      }
    }
  };
  for (int i = 0; i <= n - l; ++i) {
    num = l + i;
    cur = fac[i];
    dfs(dfs, 0, 1, 1);
  }
  return h;
}

Du sito

Prethodno smo raspravili kako izračunati prefiksnu sumu Dirichletove konvolucije teorijsko-brojevnih funkcija. Ovaj odjeljak razmatra obratni postupak: neka je \(f \ast g = h\) i neka su \(f,h\) poznate; izračunati prefiksnu sumu \(g\)

\[ G(n) = \sum_{x=1}^ng(x). \]

Drugim riječima, ovaj odjeljak razmatra računanje prefiksne sume kvocijenta dviju teorijsko-brojevnih funkcija u smislu Dirichletove konvolucije. U ovom odjeljku uvijek pretpostavljamo \(f(1)\neq 0\), kako bi \(f\) bila invertibilna.

U tu svrhu u izrazu Dirichletove metode hiperbole stavimo \(x_0 > n\) i dobivamo

\[ H(n) = \sum_{x=1}^{n}f(x)G\left(\left\lfloor\dfrac{n}{x}\right\rfloor\right). \]

Izravnim rješavanjem po \(G(n)\) dobivamo

\[ G(n) = \dfrac{1}{f(1)}\left(H(n)-\sum_{x=2}^nf(x)G\left(\left\lfloor\dfrac{n}{x}\right\rfloor\right)\right). \]

To je izraz Du sita. Zapravo, za \(x_0 \ge 1\) uvijek vrijedi

\[ G(n) = \dfrac{1}{f(1)}\left(H(n)-\sum_{x=2}^{\lfloor x_0\rfloor}f(x)G\left(\left\lfloor\dfrac{n}{x}\right\rfloor\right) - \sum_{y=1}^{\lfloor y_0\rfloor}F\left(\left\lfloor\dfrac{n}{y}\right\rfloor\right)g(y) + F(\lfloor x_0\rfloor)G(\lfloor y_0\rfloor)\right). \]

U bilo kojem obliku to je rekurzivna relacija za \(G(n)\). Da bismo izračunali vrijednost \(G(n)\), treba izračunati vrijednosti \(G\) na \(D(n)\setminus\{n\}\). Budući da \(D(n)\) ima rekurzivnu strukturu, tj. za \(m\in D(n)\) uvijek vrijedi \(D(m)\subseteq D(n)\), u cijelom rekurzivnom postupku dovoljno je vrijednost \(G\) u svakom elementu \(D(n)\) izračunati samo jedanput. Drugim riječima, računajući \(G(n)\) zapravo dobivamo blokovsko sito \(\mathcal S_g(n)\) funkcije \(g\).

U konkretnoj implementaciji može se upotrijebiti rekurzija uz memoizaciju radi izbjegavanja ponovljenih računanja. Naravno, može se koristiti i iterativna metoda, računajući vrijednosti \(G\) u točkama \(D(n)\) redom od najmanje prema najvećoj. Pritom se suma u izrazu može računati i blokovskim dijeljenjem i Dirichletovom metodom hiperbole.

Složenost je tih implementacija jednaka. Budući da Du sito uvijek daje blokovsko sito, složenost Du sita zapravo odgovara složenosti računanja blokovskog sita. Ako su poznata samo blokovska sita \(F,H\), složenost Du sita je \(O(n^{3/4})\); ako se za neki \(z\ge\sqrt{n}\) vrijednosti \(g\) u točkama \(1\le x \le z\) mogu predračunati u vremenu \(T_0(z)\), složenost Du sita je

\[ O\left(T_0(z) + \dfrac{n}{\sqrt{z}}\right). \]

Kad je \(g\) multiplikativna funkcija, može se primijeniti linearno sito, tj. \(T_0(z)=\Theta(z)\), pa je optimalno predračunati do \(z = n^{2/3}\), a ukupna vremenska složenost iznosi \(O(n^{2/3})\); u općenitijem slučaju ukupna je vremenska složenost \(O(n^{2/3}(\log n)^{1/3})\). Sve se to u potpunosti slaže s analizom u dijelu o blokovskim sitima.

Rekurzivna implementacija bez memoizacije daje pogrešnu složenost

U izrazu Du sita računanje vrijednosti \(G(n)\) ovisi o vrijednostima \(G\) na \(D(n)\setminus\{n\}\). Ključ za jamstvo složenosti jest uočiti rekurzivnu strukturu skupa \(D(n)\): kad je \(m\in D(n)\), vrijedi \(D(m)\subseteq D(n)\). Pomoću tog svojstva računanje se može ubrzati memoizacijom. Uz memoizaciju, kao što je prethodno pokazano, složenost je algoritma \(O(n^{3/4})\). Ovdje želimo pokazati da je bez memoizacije složenost algoritma pogrešna.

Neka je \(T(n)\) složenost rekurzivnog računanja \(G(n)\) bez memoizacije. Tada vrijedi

\[ \begin{aligned} T(n) &= \Theta(\sqrt{n}) + \sum_{d\in D(n),~d\neq n}T(d)\\ &= \Theta(\sqrt{n}) + \sum_{x=1}^{\lfloor n/\lfloor\sqrt{n}\rfloor\rfloor - 1} T(x) + \sum_{x = 2}^{\lfloor\sqrt{n}\rfloor}T\left(\left\lfloor\dfrac{n}{x}\right\rfloor\right). \end{aligned} \]

Idejom dokaza sličnom onoj za glavni teorem može se pokazati da posljednji član dominira rastom tog izraza i da je \(T(n)\in\Theta(n^\alpha)\), gdje je \(\alpha\approx 1.73\) korijen jednadžbe \(\zeta(\alpha)=2\).

Pri primjeni Du sita za računanje prefiksne sume teorijsko-brojevne funkcije \(g\) ključno je pronaći prikladne \(f,h\) takve da je \(h=f\ast g\) i da se blokovska sita \(f,h\) lako računaju. Ponekad su takve \(f,h\) očite; drugi ih put treba izvesti pomoću svojstava Dirichletove konvolucije, a odgovarajući se rastav može pronaći i računanjem pripadnih Dirichletovih funkcija izvodnica ili Bellovih redova (kad vrijedi multiplikativnost). Primjeri u nastavku prikazuju te situacije.

\[ f_n(m) = \sum_{k\mid m}f_{n-1}(k). \]

constexpr int M = 998244353;

// Compute the Dirichlet convolution h = f * g.
// Assume that h is multiplicative.
auto dirichlet_convolute(const std::vector<int>& f, const std::vector<int>& g) {
  int n = f.size() - 1;
  std::vector<int> h(n + 1), primes, rem(n + 1), lpf(n + 1);
  std::vector<bool> vis(n + 1);
  h[1] = 1;
  for (int x = 2; x <= n; ++x) {
    if (!vis[x]) {
      primes.push_back(x);
      rem[x] = 1;
      lpf[x] = x;
    }
    for (int p : primes) {
      if (x * p > n) break;
      vis[x * p] = true;
      rem[x * p] = x % p ? x : rem[x];
      lpf[x * p] = p;
      if (x % p == 0) break;
    }
    if (rem[x] == 1) {  // prime powers.
      for (int k = x; k; k /= lpf[x]) {
        (h[x] += (long long)f[k] * g[x / k] % M) %= M;
      }
    } else {  // other cases.
      h[x] = (long long)h[rem[x]] * h[x / rem[x]] % M;
    }
  }
  return h;
}

struct BlockSieve {
  int n, z;
  std::vector<int> f, F, F2;

  BlockSieve(int _n, int _z)
      : n(_n), z(_z), f(_z + 1), F(_z + 1), F2(_n / _z + 1) {}

  int sum(int x) const { return x <= z ? F[x] : F2[n / x]; }

  BlockSieve operator*(const BlockSieve& oth) const {
    assert(n == oth.n && z == oth.z);
    BlockSieve res(n, z);
    res.f = dirichlet_convolute(f, oth.f);
    for (int i = 1; i <= z; ++i) {
      res.F[i] = (res.F[i - 1] + res.f[i]) % M;
    }
    for (int i = 1; i <= n / z; ++i) {
      int k = n / i;
      int sqr = std::sqrt(k + 0.25l);
      for (int x = 1; x <= sqr; ++x) {
        (res.F2[i] += (long long)f[x] * oth.sum(k / x) % M) %= M;
        (res.F2[i] += (long long)sum(k / x) * oth.f[x] % M) %= M;
      }
      (res.F2[i] += (M - (long long)sum(sqr) * oth.sum(sqr) % M)) %= M;
    }
    return res;
  }
};

Rješenje

Uočimo relacije Dirichletove konvolucije:

\[ \varepsilon = \mu \ast 1,~ \operatorname{id} = \varphi \ast 1. \]

Pritom je \(\varepsilon(n) = [n=1]\) jedinična funkcija za Dirichletovu konvoluciju, \(\operatorname{id}(n) = n\) je funkcija identiteta, a \(1(n) = 1\) je konstantna funkcija. Za računanje prefiksne sume Eulerove funkcije druga je metoda korištenje Möbiusove inverzije. Uočimo

\[ \begin{aligned} S_2(n) &= \sum_{i=1}^n\varphi(i) = \sum_{i=1}^n\sum_{j=1}^i[i\perp j] \\ &= \sum_{i=1}^n\sum_{j=1}^i\sum_d\mu(d)[d\mid i][d\mid j] \\ &= \sum_d\mu(d)\dfrac{1}{2}\left\lfloor\dfrac{n}{d}\right\rfloor\left(\left\lfloor\dfrac{n}{d}\right\rfloor+1\right). \end{aligned} \]

Zadani su \(p,n\); izračunajte

\[ \sum_{i=1}^n\sum_{j=1}^nij\cdot\gcd(i,j)\pmod p. \]

Ograničenja: \(n\leq 10^{10}\), \(5\times 10^8\leq p\leq 1.1\times 10^9\) i \(p\) je prost.

Rješenje

Pomoću svojstava Eulerove funkcije provodimo sljedeću inverziju:

\[ \begin{aligned} T(n) &= \sum_{i=1}^n\sum_{j=1}^nij\cdot\gcd(i,j)\\ &= \sum_{i=1}^n\sum_{j=1}^nij\sum_d\varphi(d)[d\mid i][d\mid j]\\ &= \sum_d\varphi(d)\left(\sum_{i=1}^{\lfloor n/d\rfloor}id\right)\left(\sum_{j=1}^{\lfloor n/d\rfloor}jd\right)\\ &= \sum_d d^2\varphi(d) F\left(\left\lfloor\dfrac{n}{d}\right\rfloor\right)^2. \end{aligned} \]

Pritom je \(F(n) = \dfrac{1}{2}n(n+1)\). Taj se izraz može izračunati blokovskim dijeljenjem, ali treba predračunati prefiksnu sumu \(d^2\varphi(d)\).

U tu svrhu možemo iskoristiti Du sito. Označimo \(f(n)=(\operatorname{id}^2\varphi)(n)\) i \(S(n)=\sum_{i=1}^n f(i)\). Ključ primjene Du sita jest konstruirati funkciju \(g\) takvu da se i \(f\ast g\) i \(g\) mogu brzo sumirati. Prethodno smo već raspravili metodu predračuna prefiksne sume \(\varphi\) Du sitom, za što je dovoljno iskoristiti relaciju \(\operatorname{id} = \varphi\ast 1\). U odnosu na \(\varphi\), ovdje \(f\) ima dodatni faktor \(\operatorname{id}^2\). Budući da je \(\operatorname{id}\) potpuno multiplikativna funkcija, prema svojstvima Dirichletove konvolucije dovoljno je analogno svaki član pomnožiti s \(\operatorname{id}^2\) i dobivamo

\[ \operatorname{id}^3 = f \ast \operatorname{id}^2. \]

Budući da se prefiksne sume \(\operatorname{id}^2(n)=n^2\) i \(\operatorname{id}^3(n)=n^3\) mogu izračunati u \(O(1)\), prefiksna suma \(f\) može se predračunati u vremenu \(O(n^{2/3})\). Zajedno s blokovskim dijeljenjem ukupna vremenska složenost i dalje je \(O(n^{2/3})\).

Drugi način da se slična multiplikativna funkcija prikaže kao kvocijent (u smislu Dirichletove konvolucije) dviju funkcija jest pomoću Dirichletovih funkcija izvodnica.

long long s3(long long k) {  // zbroj kubova
  return k %= P, (k * (k + 1) / 2) % P * ((k * (k + 1) / 2) % P) % P;
}

long long s2(long long k) {  // zbroj kvadrata
  return k %= P, k * (k + 1) % P * (k * 2 + 1) % P * inv6 % P;
}

long long calc(long long k) {  // računa S(k)
  if (k <= pn) return s[k];
  if (s_map[k]) return s_map[k];  // vrijednosti veće od pn spremaju se rijetko, u map
  long long res = s3(k), pre = 1, cur;
  for (long long i = 2, j; i <= k; i = j + 1)
    j = k / (k / i), cur = s2(j),
    res = (res - calc(k / i) * (cur - pre) % P) % P, pre = cur;
  return s_map[k] = (res + P) % P;
}

long long solve() {
  long long res = 0, pre = 0, cur;
  for (long long i = 1, j; i <= n; i = j + 1) {
    j = n / (n / i);
    cur = calc(j);
    res = (res + (s3(n / i) * (cur - pre)) % P) % P;
    pre = cur;
  }
  return (res + P) % P;
}

This article introduces the Dirichlet hyperbola method, which can be used to compute the prefix sum of the Dirichlet convolution of two arithmetic functions in sublinear time complexity. Analyzing this algorithm leads to the concept of a block sieve; based on it, the article further introduces a fast method for computing the convolution of block sieves. Finally, the article introduces Du's sieve, which can be used to compute the prefix sum of the quotient of two arithmetic functions in the sense of Dirichlet convolution.

Dirichlet hyperbola method

The Dirichlet hyperbola method can be used to compute the prefix sum of the Dirichlet convolution of two arithmetic functions.

Let \(f,g,h\) be arithmetic functions with \(h = f\ast g\). Then, by the definition of Dirichlet convolution, the prefix sum of \(h\) is

\[ H(n) = \sum_{k=1}^nh(k) = \sum_{k=1}^n\sum_{xy=k}f(x)g(y). \]

The set of points traversed by the sum is exactly the set of lattice points in the first quadrant (excluding the coordinate axes) below the hyperbola \(xy=n\). Assign the lattice point \((x,y)\) the weight \(f(x)g(y)\); then \(H(n)\) is the sum of these weights.

As the figure shows, this weight sum can be computed by the inclusion–exclusion principle:

\[ H(n) = \sum_{x=1}^{\lfloor x_0\rfloor}f(x)G\left(\left\lfloor\dfrac{n}{x}\right\rfloor\right) + \sum_{y=1}^{\lfloor y_0\rfloor}F\left(\left\lfloor\dfrac{n}{y}\right\rfloor\right)g(y) - F(\lfloor x_0\rfloor)G(\lfloor y_0\rfloor). \]

Here \(F,G\) are the prefix-sum functions of \(f,g\) respectively, and \((x_0,y_0)\) is an arbitrary point on the hyperbola \(xy=n\). In the expression, the first term is the weight sum of the green region in the figure, the second term is the weight sum of the orange region, and the third term is the weight sum of the overlap of the two regions. This expression has only \(\lfloor x_0\rfloor + \lfloor y_0\rfloor + 1\) terms. For a reasonably chosen \((x_0,y_0)\), its computational complexity is significantly better than brute-force computation of the prefix sum of \(h(n)\). This is the Dirichlet hyperbola method.

Computing a value of the convolution prefix sum

The most basic application of the Dirichlet hyperbola method is computing a single value \(H(n)\) of the prefix-sum function.

If the values of \(F,G\) are known (or can be computed in \(O(1)\) time), and hence the values of \(f,g\) are also known, then every term in the expression of the Dirichlet hyperbola method can be computed in \(O(1)\) time, and the total time complexity is \(O(x_0+y_0)\). Since \(x_0y_0=n\), the AM–GM inequality shows that the lowest time complexity \(O(\sqrt{n})\) is obtained when \(x_0=y_0=\sqrt{n}\).

This is not a new result. Setting \(x_0 > n\) in the expression of the Dirichlet hyperbola method gives

\[ H(n) = \sum_{x=1}^nf(x)G\left(\left\lfloor\dfrac{n}{x}\right\rfloor\right). \]

Using the technique of floor-division blocks, when the values of \(F,G\) are known, this expression can be computed in \(O(\sqrt{n})\) time. This is in fact almost equivalent to the algorithm obtained in this section: the two methods require essentially the same known information, and the expressions they compute are roughly the same.

Explanation of the equivalence

Examining the computation of floor-division blocks closely, one finds that the expression actually computed is

\[ H(n) = \sum_{y\in D(n)}\left(F\left(\left\lfloor\dfrac{n}{y}\right\rfloor\right)-F\left(\left\lfloor\dfrac{n}{y+1}\right\rfloor\right)\right)G(y). \]

Here \(D(n) = \left\{\left\lfloor\dfrac{n}{x}\right\rfloor : 1 \le x \le n,~x\in\mathbf N_+\right\}\) is the set of key points of floor-division blocks.

By the properties of floor-division blocks, for \(x\le\sqrt{n}\) the heights \(y = \lfloor n/x\rfloor\) of the corresponding blocks are pairwise distinct, so the lengths of these blocks are all \(1\), i.e.,

\[ \left\lfloor\dfrac{n}{y+1}\right\rfloor + 1 = x = \left\lfloor\dfrac{n}{y}\right\rfloor. \]

Therefore, the sum corresponding to these blocks is

\[ I_1 = \sum_{x=1}^{\lfloor\sqrt{n}\rfloor}\left(F(x)-F(x-1)\right)G\left(\left\lfloor\dfrac{n}{x}\right\rfloor\right) = \sum_{x=1}^{\lfloor\sqrt{n}\rfloor}f(x)G\left(\left\lfloor\dfrac{n}{x}\right\rfloor\right). \]

For the remaining blocks, the height \(y\) runs over \(1,2,\cdots,y^*= \left\lfloor\dfrac{n}{\lfloor\sqrt{n}\rfloor + 1}\right\rfloor\). Applying the Abel transformation (i.e., the summation form of integration by parts) to the remaining sum gives

\[ \begin{aligned} I_2 &= \sum_{y=1}^{y^*}\left(F\left(\left\lfloor\dfrac{n}{y}\right\rfloor\right)-F\left(\left\lfloor\dfrac{n}{y+1}\right\rfloor\right)\right)G(y) \\ &= \sum_{y=1}^{y^*}F\left(\left\lfloor\dfrac{n}{y}\right\rfloor\right)g(y) - F\left(\left\lfloor\dfrac{n}{y^*+1}\right\rfloor\right)G(y^*). \end{aligned} \]

The properties of floor-division blocks show that \(\lfloor n/\lfloor \sqrt{n}\rfloor\rfloor \ge \lfloor \sqrt{n}\rfloor\). We distinguish two cases:

  • When \(\lfloor n/\lfloor \sqrt{n}\rfloor\rfloor = \lfloor \sqrt{n}\rfloor\), necessarily \(y^* < \lfloor \sqrt{n}\rfloor\). Since this block is adjacent to the block containing \(x = \lfloor \sqrt{n}\rfloor\), the block heights can differ only by exactly one, i.e., \(y^* = \lfloor \sqrt{n}\rfloor - 1\). In this case,

    \[ \begin{aligned} I_2 &= \sum_{y=1}^{\lfloor\sqrt{n}\rfloor-1}F\left(\left\lfloor\dfrac{n}{y}\right\rfloor\right)g(y) - F(\lfloor\sqrt{n}\rfloor)G(\lfloor\sqrt{n}\rfloor-1)\\ &= \sum_{y=1}^{\lfloor\sqrt{n}\rfloor-1}F\left(\left\lfloor\dfrac{n}{y}\right\rfloor\right)g(y) - F(\lfloor\sqrt{n}\rfloor)\left(G(\lfloor\sqrt{n}\rfloor) - g(\lfloor\sqrt{n}\rfloor)\right) \\ &= \sum_{y=1}^{\lfloor\sqrt{n}\rfloor}F\left(\left\lfloor\dfrac{n}{y}\right\rfloor\right)g(y) - F(\lfloor\sqrt{n}\rfloor)G(\lfloor\sqrt{n}\rfloor). \end{aligned} \]

  • When \(\lfloor n/\lfloor \sqrt{n}\rfloor\rfloor > \lfloor \sqrt{n}\rfloor\), necessarily \(y^* = \lfloor \sqrt{n}\rfloor\). Substituting directly into the sum gives

    \[ I_2 = \sum_{y=1}^{\lfloor\sqrt{n}\rfloor}F\left(\left\lfloor\dfrac{n}{y}\right\rfloor\right)g(y) - F(\lfloor\sqrt{n}\rfloor)G(\lfloor\sqrt{n}\rfloor). \]

In summary, apart from one Abel transformation, the computation of floor-division blocks is actually computing the following expression:

\[ H(n) = \sum_{x=1}^{\lfloor\sqrt{n}\rfloor}f(x)G\left(\left\lfloor\dfrac{n}{x}\right\rfloor\right) + \sum_{y=1}^{\lfloor\sqrt{n}\rfloor}F\left(\left\lfloor\dfrac{n}{y}\right\rfloor\right)g(y) - F(\lfloor\sqrt{n}\rfloor)G(\lfloor\sqrt{n}\rfloor). \]

This is exactly the expression of the Dirichlet hyperbola method for \((x_0,y_0)=(\sqrt{n},\sqrt{n})\). Hence one can say that the computations of the two algorithms are almost equivalent. Moreover, since the Dirichlet hyperbola method exploits more properties of floor-division blocks and avoids the unnecessary computations of naive floor-division blocks, its constant factor is somewhat smaller.

When dealing with real problems, the condition that the values of \(F,G\) are known may be too strong. However, the Dirichlet hyperbola method (or the corresponding floor-division blocks) does not actually need all the values of \(F,G\). Looking at the summation expression, we see that only the values of \(F\) and \(G\) on the set of key points of floor-division blocks

\[ D(n) = \left\{\left\lfloor\dfrac{n}{x}\right\rfloor : 1 \le x \le n,~x\in\mathbf N_+\right\} \]

are needed. It is both the set of all block heights and the set of all right endpoints of the blocks. Note that by the properties of floor-division blocks, this set contains all integers \(1\le x\le\sqrt{n}\), so knowing the values of \(F,G\) on \(D(n)\) is equivalent to knowing the values of \(f,g\) at all \(1\le x\le\sqrt{n}\). The size of this set is \(\Theta(\sqrt{n})\), so when computing \(H(n)\) we only need to know the values of \(F,G\) on a sparse set. This observation is the key to optimizing the computation of prefix sums of arithmetic functions.

Block sieves and their convolution

Sometimes \(h=f\ast g\) is not the function whose prefix sum is ultimately needed, but only one of the intermediate steps. According to the analysis above, for the subsequent computation we need the values of the prefix-sum function \(H\) on the set \(D(n)\). This is called the block sieve of the arithmetic function \(h\):

\[ \mathcal S_h(n) = \left\{H(x) : x \in D(n)\right\}. \]

This section discusses methods for the block sieve convolution problem: given the block sieves of \(f,g\), find the block sieve of their Dirichlet convolution \(h = f\ast g\).

Naive algorithm

The naive algorithm treats the computation of the block sieve as \(|D(n)|\) computations of single prefix-sum values. The total time complexity of this is

\[ \begin{aligned} O\left(\sum_{d\in D(n)}\sqrt{d}\right) &= O\left(\sum_{x=1}^{\lfloor\sqrt{n}\rfloor}\sqrt{x} + \sum_{x=1}^{\lfloor\sqrt{n}\rfloor}\sqrt{\dfrac{n}{x}}\right) \\ &= O\left(\int_1^{\sqrt{n}}\sqrt{x}\mathrm{d}x + \int_1^{\sqrt{n}}\sqrt{\dfrac{n}{x}}\mathrm{d}x\right)\\ &= O(n^{3/4}). \end{aligned} \]

It is precisely because the block sieve is sparse that the whole block sieve can be computed in sublinear time.

However, this algorithm is obviously too brute-force. The smaller elements of the set \(D(n)\) are relatively dense, so adjacent prefix sums in the block sieve do not differ much; one can simply compute the values of the convolution \(h\) directly and then take their prefix sums. This is faster than computing the prefix-sum value separately for each point. For example, computing the prefix-sum values separately for \(x = 1,2,\cdots,\lfloor\sqrt{n}\rfloor\) takes

\[ O\left(\sum_{x=1}^{\lfloor\sqrt{n}\rfloor}\sqrt{x}\right) = O(n^{3/4}) \]

time; but computing the values of \(h\) at these points directly and then accumulating them takes only \(O(n^{1/2}\log n)\) time. Nevertheless, if only the block sieves of \(f,g\) are known and nothing more, this idea cannot further optimize the complexity of the algorithm. This is because the block sieve only contains value information for \(x \le \sqrt{n}\), so at most the values of \(h\) at \(1\le x\le\sqrt{n}\) can be computed, while computing the remaining prefix-sum values still takes \(O(n^{3/4})\) time.

Optimization using value information

If the known information includes, besides the block sieves of \(f,g\), more of their values, then the complexity of this algorithm can indeed be improved. In practice, this algorithm is usually applied when the values of \(f,g\) can be precomputed quickly.

Choose \(z \ge \sqrt{n}\). The block sieve of the convolution \(h\) is split into two parts:

  • Compute the values of the convolution \(h\) of \(f\ast g\) at \(1\le x \le z\), then accumulate them directly to obtain the values of \(H\) at \(1\le x\le z\).
  • For \(x\in D(n)\) with \(x > z\), compute the value of \(H\) at \(x\) by the Dirichlet hyperbola method.

In the general case, the time complexity of this is

\[ \begin{aligned} O\left(z\log z + \sum_{d\in D(n),~d\ge z}\sqrt{d}\right) &= O\left(z\log z + \sum_{x=1}^{n/z}\sqrt{\dfrac{n}{x}}\right)\\ &= O\left(z\log z + \int_1^{n/z}\sqrt{\dfrac{n}{x}}\mathrm{d}x\right)\\ &= O\left(z\log z + \dfrac{n}{\sqrt{z}}\right). \end{aligned} \]

When \(z=\left(\dfrac{n}{\log n}\right)^{2/3}\), the total time complexity is minimized at \(O\left(n^{2/3}(\log n)^{1/3}\right)\).

Of course, the complexity of computing the values of a Dirichlet convolution depends on the properties of \(f,g,h\). When \(f,g,h\) have special properties, the optimal split point and the complexity are slightly different:

  • If \(f\) or \(g\) is multiplicative, then when \(z=\left(\dfrac{n}{\log\log n}\right)^{2/3}\) the total time complexity is minimized at \(O\left(n^{2/3}(\log\log n)^{1/3}\right)\).
  • If \(h\) is multiplicative, then when \(z=n^{2/3}\) the total time complexity is minimized at \(O(n^{2/3})\).

Applying this optimization does not require all the values of \(f,g\), only their values at \(1\le x\le z\). Since this algorithm also yields the values of \(h\) at \(1\le x\le z\), when \(h\) is an intermediate variable, the values of \(h\) can likewise be used to optimize the subsequent computation. The block sieve of an arithmetic function together with these values forms an enhanced block sieve: they are all the information necessary to compute convolution prefix sums in \(O(n^{2/3+\varepsilon})\) time.

Fast block sieve convolution

Prerequisites: fast Fourier transform

Note

Beginners may skip this section.

This section discusses the fast block sieve convolution algorithm proposed by Zhou Kangyang in his 2024 Chinese national training team paper. It computes the values of \(\mathcal S_h\), the convolution of the block sieves \(\mathcal S_f\) and \(\mathcal S_g\), in \(O(\sqrt{n}\log^2n)\) time. This algorithm does not depend on additional value information or on the multiplicativity of the arithmetic functions, but its implementation is rather complex.

The block sieve convolution problem asks for the prefix sums of

\[ h(z) = \sum_{xy=z} f(x)g(y) \]

on the block sieve \(D(n) = \{\left\lfloor n / t\right\rfloor : 1\le t \le n\}\). For this problem, a single contribution can be labeled by \((x,y,t)\), i.e., the process of adding the term \(f(x)g(y)\) to the prefix sum at \(\left\lfloor n / t\right\rfloor\). The algorithm handles these contributions in several groups.

First, consider the contributions of all points with \(x > \sqrt{n}\) to this series of prefix sums; the contributions with \(y > \sqrt{n}\) are handled similarly. Since every contribution must satisfy \(xy \le \lfloor n / t\rfloor\), i.e., \(xyt \le n\), it suffices to enumerate all possible \(t,y\), and using the prefix-sum technique together with the information in the block sieve \(\mathcal S_f\), this part of the contributions can be computed in \(O(\sum_{t,y: ty\le\sqrt{n}} 1) = O(\sqrt{n}\log n)\) time.

Next, consider the part of the contributions with \(\left\lfloor n / t\right\rfloor\le\sqrt{n}\). This part can likewise be done by brute-force enumeration of all possible \(x,y\), and the time complexity is still \(O(\sum_{x,y:xy\le\sqrt{n}}1) = O(\sqrt{n}\log n)\). This part actually yields the first \(\lfloor\sqrt{n}\rfloor\) values of the function \(h\) on \(D(n)\).

Consider the remaining contributions, i.e., those satisfying \(x,y\le\sqrt{n}\) and \(\left\lfloor n / t\right\rfloor > \sqrt{n}\). All contributions must satisfy \(xyt\le n\), i.e., \(\ln x + \ln y \le \ln(n/t)\). Take a positive number \(S\); this condition can be approximated by \(\lceil S\ln x\rceil + \lceil S\ln y\rceil \le S\ln(n/t)\). Define polynomials \(\sigma_f(u)\) and \(\sigma_g(u)\) such that their coefficients \([u^k]\sigma_f\) and \([u^k]\sigma_g\) equal, respectively, the sum of \(f(x)\) over those with \(\lceil S\ln x\rceil = k\) and the sum of \(g(y)\) over those with \(\lceil S\ln y\rceil = k\) (considering only the part with \(x,y\le\sqrt{n}\)). Using the fast Fourier transform (FFT) we can obtain their product \(\sigma_f\sigma_g\), whose coefficient \([u^k](\sigma_f\sigma_g)\) represents the sum of \(f(x)g(y)\) over pairs with \(\lceil S\ln x\rceil + \lceil S\ln y\rceil = k\). Thus, for each remaining \(\lfloor n/t\rfloor\) in \(D(n)\) it suffices to find the largest \(k\) satisfying \(k \le S\ln(n/t)\) to obtain an estimate of this part of the contributions.

Finally, we correct the error of this part of the contributions. Above, we tried to approximate \(\ln x + \ln y \le \ln(n/t)\) by the stronger condition \(\lceil S\ln x\rceil + \lceil S\ln y\rceil \le S\ln(n/t)\), which may miss some contributions. This can only happen when \(\lceil S\ln x\rceil + \lceil S\ln y\rceil > S\ln(n/t)\), so we have

\[ S\ln x + 1 + S\ln y + 1 \ge \lceil S\ln x\rceil + \lceil S\ln y\rceil > S\ln(n/t) \ge S\ln x + S\ln y. \]

This is equivalent to

\[ xyt \in (n\mathrm{e}^{-2/S},n]. \]

This is an interval of length \(O(n/S)\). Enumerating all possible contributions \((x,y,t)\) in the interval and checking one by one whether they were missed completes the error correction. To enumerate all contributions in the interval quickly, we can first sieve all primes not exceeding \(\sqrt{n}\), then divide the integers in the interval by these primes; the remaining factor must be a prime greater than \(\sqrt{n}\), which yields the prime factorization of all integers in the interval, and then all possible \((x,y,t)\) can be enumerated quickly.

Let us examine the time complexity of computing this last part of the contributions. When estimating the contributions, we need to multiply polynomials of length \(S\log n\), with time complexity \(O(S\log n\log(S\log n))\). In the error correction, the time complexity of precomputing the prime factorizations is \(O(\sqrt{n}+(n/S)\log\log n)\), and the time complexity of enumerating all contributions in the interval is \(O(\sum_{k\in(n\mathrm{e}^{-2/S},n]}d_3(k))\), where \(d_3(n)\) denotes the number of ways to write \(n\) as a product of three ordered integers. A result from analytic number theory1 states:

\[ \sum_{k\le n}d_3(k) = nP(\log n) + O(n^{43/96+\varepsilon}), \]

where \(P(\cdot)\) is a quadratic polynomial. Since the time complexity of the first two steps is already \(O(\sqrt{n}\log n)\), ignoring all \(o(\sqrt{n}\log n)\) terms, the time complexity of computing this last part of the contributions is

\[ O\left(S\log n\log(S\log n) + \dfrac{n}{S} \log^2n\right). \]

Taking \(S = \sqrt{n}\) gives a time complexity of \(O(\sqrt{n}\log^2n)\). This is also the total time complexity of the algorithm.

struct BlockSieve {
  long long n, b;
  std::vector<int> s1, s2;

  BlockSieve(long long _n)
      : n(_n), b(std::sqrt(_n + 0.25l)), s1(b + 1), s2(b + 1) {}

  int& operator[](long long x) { return x <= b ? s1[x] : s2[n / x]; }
};

// Fast block sieve convolution by ZKY.
BlockSieve block_sieve_convolute(const BlockSieve& f, const BlockSieve& g) {
  // Special cases for n <= 3 are not implemented.
  // The upper bound is a loose bound for NTT to work for M = 998244353.
  assert(f.n == g.n && f.n > 3 && f.n < 1e11);
  long long n = f.n, b = f.b;
  BlockSieve h(n);
  std::vector<int> df(b + 1), dg(b + 1);
  for (int i = 1; i <= b; ++i) {
    df[i] = (f.s1[i] + M - f.s1[i - 1]) % M;
    dg[i] = (g.s1[i] + M - g.s1[i - 1]) % M;
  }
  // Prefix sum trick for x or y > sqrt(n).
  for (int t = 1; t <= n / (b + 1); ++t) {
    long long x;
    for (int y = 1; (x = n / (t * y)) > b; ++y) {
      (h.s2[t] += (long long)dg[y] * (f.s2[n / x] + M - f.s1[b]) % M) %= M;
      (h.s2[t] += (long long)df[y] * (g.s2[n / x] + M - g.s1[b]) % M) %= M;
    }
  }
  // Brutal force for small x*y.
  for (int x = 1; x <= b; ++x) {
    for (int y = 1; x * y <= b; ++y) {
      (h.s1[x * y] += (long long)df[x] * dg[y] % M) %= M;
    }
  }
  for (int i = 1; i <= b; ++i) {
    (h.s1[i] += h.s1[i - 1]) %= M;
  }
  // Approximation.
  std::vector<int> id1(b + 1);
  for (int i = 1; i <= b; ++i) {
    id1[i] = std::ceil(b * std::log(i));
  }
  std::vector<long double> id2(b + 1);
  for (int i = 1; i <= b; ++i) {
    id2[i] = b * std::log(1.0l * n / i);
  }
  std::vector<int> sf(id1[b] + 1), sg(id1[b] + 1);
  for (int i = 1; i <= b; ++i) {
    (sf[id1[i]] += df[i]) %= M;
    (sg[id1[i]] += dg[i]) %= M;
  }
  auto sh = ntt_mul(sf, sg);
  for (int i = 1; i < (int)sh.size(); ++i) {
    (sh[i] += sh[i - 1]) %= M;
  }
  for (int t = 1; t <= n / (b + 1); ++t) {
    int k = std::min((int)std::floor(id2[t]), (int)sh.size() - 1);
    (h.s2[t] += sh[k]) %= M;
  }
  // Correction.
  auto primes = get_primes(b);  // Obtain primes not exceeding b.
  long long l = n * std::exp(-2.0l / b);
  std::vector<long long> co(n - l + 1);
  std::iota(co.begin(), co.end(), l);
  std::vector<std::vector<std::pair<long long, int>>> fac(n - l + 1);
  for (int p : primes) {
    for (int i = (l + p - 1) / p * p - l; i <= n - l; i += p) {
      int e = 0;
      for (; co[i] % p == 0; co[i] /= p) ++e;
      fac[i].emplace_back(p, e);
    }
  }
  for (int i = 0; i <= n - l; ++i) {
    if (co[i] != 1) {
      fac[i].emplace_back(co[i], 1);
    }
  }
  long long num = 0;
  std::vector<std::pair<long long, int>> cur;
  auto dfs = [&](auto&& dfs, int k, int x, int y) {
    if (k == (int)cur.size()) {
      auto t = num / x / y;
      if (t && t <= n / (b + 1) && id1[x] + id1[y] > id2[t]) {
        (h.s2[t] += (long long)df[x] * dg[y] % M) %= M;
      }
      return;
    }
    auto p = cur[k].first;
    auto e = cur[k].second;
    long long nx = x;
    for (int e1 = 0; e1 <= e; ++e1) {
      if (e1) {
        nx *= p;
        if (nx > b) break;
      }
      long long ny = y;
      for (int e2 = 0; e1 + e2 <= e; ++e2) {
        if (e2) {
          ny *= p;
          if (ny > b) break;
        }
        dfs(dfs, k + 1, nx, ny);
      }
    }
  };
  for (int i = 0; i <= n - l; ++i) {
    num = l + i;
    cur = fac[i];
    dfs(dfs, 0, 1, 1);
  }
  return h;
}

Du's sieve

Above we discussed how to compute the prefix sum of the Dirichlet convolution of arithmetic functions. This section considers the reverse process: let \(f \ast g = h\) with \(f,h\) known; compute the prefix sum of \(g\)

\[ G(n) = \sum_{x=1}^ng(x). \]

In other words, this section considers computing the prefix sum of the quotient of two arithmetic functions in the sense of Dirichlet convolution. Throughout this section we assume \(f(1)\neq 0\), so that \(f\) is invertible.

To this end, setting \(x_0 > n\) in the expression of the Dirichlet hyperbola method gives

\[ H(n) = \sum_{x=1}^{n}f(x)G\left(\left\lfloor\dfrac{n}{x}\right\rfloor\right). \]

Solving directly for \(G(n)\) gives

\[ G(n) = \dfrac{1}{f(1)}\left(H(n)-\sum_{x=2}^nf(x)G\left(\left\lfloor\dfrac{n}{x}\right\rfloor\right)\right). \]

This is the expression of Du's sieve. In fact, for \(x_0 \ge 1\) we always have

\[ G(n) = \dfrac{1}{f(1)}\left(H(n)-\sum_{x=2}^{\lfloor x_0\rfloor}f(x)G\left(\left\lfloor\dfrac{n}{x}\right\rfloor\right) - \sum_{y=1}^{\lfloor y_0\rfloor}F\left(\left\lfloor\dfrac{n}{y}\right\rfloor\right)g(y) + F(\lfloor x_0\rfloor)G(\lfloor y_0\rfloor)\right). \]

In either form, it is a recurrence relation for \(G(n)\). To compute the value of \(G(n)\), we need to compute the values of \(G\) on \(D(n)\setminus\{n\}\). Since \(D(n)\) has a recursive structure, i.e., for \(m\in D(n)\) we always have \(D(m)\subseteq D(n)\), during the whole recursive computation the value of \(G\) at each element of \(D(n)\) needs to be computed only once. In other words, when computing \(G(n)\), we actually obtain the block sieve \(\mathcal S_g(n)\) of \(g\).

In a concrete implementation, one can use recursion with memoization to avoid repeated computations. Of course, one can also use an iterative method, computing the values of \(G\) at the points of \(D(n)\) in increasing order. In this case, the sum in the expression can be computed either with floor-division blocks or with the Dirichlet hyperbola method.

The complexity of these implementations is the same. Since Du's sieve always yields a block sieve, the complexity of Du's sieve is in fact equivalent to the complexity of computing a block sieve. If the only known information is the block sieves of \(F,H\), the complexity of Du's sieve is \(O(n^{3/4})\); if for some \(z\ge\sqrt{n}\) the values of \(g\) at \(1\le x \le z\) can be precomputed in \(T_0(z)\) time, the complexity of Du's sieve is

\[ O\left(T_0(z) + \dfrac{n}{\sqrt{z}}\right). \]

When \(g\) is a multiplicative function, a linear sieve can be applied, i.e., \(T_0(z)=\Theta(z)\), so it is optimal to precompute up to \(z = n^{2/3}\), and the total time complexity is \(O(n^{2/3})\); in the more general case, the total time complexity is \(O(n^{2/3}(\log n)^{1/3})\). All of this is fully consistent with the analysis in the block sieve section.

A recursive implementation without memoization leads to wrong complexity

In the expression of Du's sieve, computing the value of \(G(n)\) depends on the values of \(G\) on \(D(n)\setminus\{n\}\). The key to guaranteeing the complexity here is to notice the recursive structure of the set \(D(n)\): when \(m\in D(n)\), \(D(m)\subseteq D(n)\). Using this property, the computation can be accelerated by memoization. With memoization, as shown above, the complexity of the algorithm is \(O(n^{3/4})\). What we want to show here is that without memoization the complexity of the algorithm is wrong.

Let \(T(n)\) be the complexity of computing \(G(n)\) recursively without memoization. Then we have

\[ \begin{aligned} T(n) &= \Theta(\sqrt{n}) + \sum_{d\in D(n),~d\neq n}T(d)\\ &= \Theta(\sqrt{n}) + \sum_{x=1}^{\lfloor n/\lfloor\sqrt{n}\rfloor\rfloor - 1} T(x) + \sum_{x = 2}^{\lfloor\sqrt{n}\rfloor}T\left(\left\lfloor\dfrac{n}{x}\right\rfloor\right). \end{aligned} \]

Using a proof idea similar to that of the master theorem, one can show that the last term dominates the growth of this expression and that \(T(n)\in\Theta(n^\alpha)\), where \(\alpha\approx 1.73\) is the root of \(\zeta(\alpha)=2\).

When applying Du's sieve to compute the prefix sum of an arithmetic function \(g\), the key is to find suitable \(f,h\) such that \(h=f\ast g\) and the block sieves of \(f,h\) are both easy to compute. Sometimes such \(f,h\) are obvious; at other times they need to be derived using the properties of Dirichlet convolution, and the corresponding decomposition can also be found by computing the corresponding Dirichlet generating functions or Bell series (when multiplicativity holds). The examples below illustrate these situations.

AtCoder Regular Contest 116 C - Multiple Sequences

Given positive integers \(N\) and \(M\). Compute how many sequences \(A\) of length \(N\) satisfy \(1 \le A_i \le M\) and \(A_i\) divides \(A_{i+1}\). The answer is taken modulo \(998244353\). Constraints: \(1 \le N, M \le 2\times 10^5\).

Solution

Let \(f_n(m)\) be the number of sequences of length \(n\) with \(A_n=m\). Then the final answer is \(\sum_{m=1}^M f_N(m)\). To compute \(f_n(m)\), consider dynamic programming. The transition equation is:

\[ f_n(m) = \sum_{k\mid m}f_{n-1}(k). \]

In the notation of Dirichlet convolution, it can be written as \(f_n = f_{n-1}\ast 1\), where \(1\) is the constant arithmetic function. Note that \(f_1 = 1\), so by induction \(f_n = 1 ^{\ast n}\). That is, \(f_n\) is the convolution of \(n\) constant functions. The final answer is the prefix sum of \(f_N\). Since only multiplicative functions are involved in the process, using the method for computing prefix sums of Dirichlet convolutions introduced above, a single convolution prefix-sum computation takes only \(O(M^{2/3})\) time; using binary exponentiation, only \(O(\log N)\) convolution prefix-sum computations are needed to obtain the value of the convolution prefix sum of \(f_N\). The overall time complexity is \(O(M^{2/3}\log N)\).

Reference implementation 
#include <cassert>
#include <cmath>
#include <iostream>
#include <vector>

constexpr int M = 998244353;

// Compute the Dirichlet convolution h = f * g.
// Assume that h is multiplicative.
auto dirichlet_convolute(const std::vector<int>& f, const std::vector<int>& g) {
  int n = f.size() - 1;
  std::vector<int> h(n + 1), primes, rem(n + 1), lpf(n + 1);
  std::vector<bool> vis(n + 1);
  h[1] = 1;
  for (int x = 2; x <= n; ++x) {
    if (!vis[x]) {
      primes.push_back(x);
      rem[x] = 1;
      lpf[x] = x;
    }
    for (int p : primes) {
      if (x * p > n) break;
      vis[x * p] = true;
      rem[x * p] = x % p ? x : rem[x];
      lpf[x * p] = p;
      if (x % p == 0) break;
    }
    if (rem[x] == 1) {  // prime powers.
      for (int k = x; k; k /= lpf[x]) {
        (h[x] += (long long)f[k] * g[x / k] % M) %= M;
      }
    } else {  // other cases.
      h[x] = (long long)h[rem[x]] * h[x / rem[x]] % M;
    }
  }
  return h;
}

// Block sieve convolution for multiplicative functions.
struct BlockSieve {
  int n, z;
  std::vector<int> f, F, F2;

  BlockSieve(int _n, int _z)
      : n(_n), z(_z), f(_z + 1), F(_z + 1), F2(_n / _z + 1) {}

  int sum(int x) const { return x <= z ? F[x] : F2[n / x]; }

  BlockSieve operator*(const BlockSieve& oth) const {
    assert(n == oth.n && z == oth.z);
    BlockSieve res(n, z);
    res.f = dirichlet_convolute(f, oth.f);
    for (int i = 1; i <= z; ++i) {
      res.F[i] = (res.F[i - 1] + res.f[i]) % M;
    }
    for (int i = 1; i <= n / z; ++i) {
      int k = n / i;
      int sqr = std::sqrt(k + 0.25l);
      for (int x = 1; x <= sqr; ++x) {
        (res.F2[i] += (long long)f[x] * oth.sum(k / x) % M) %= M;
        (res.F2[i] += (long long)sum(k / x) * oth.f[x] % M) %= M;
      }
      (res.F2[i] += (M - (long long)sum(sqr) * oth.sum(sqr) % M)) %= M;
    }
    return res;
  }
};

int main() {
  int n, k;
  std::cin >> k >> n;
  int z = std::pow(n, 2.0l / 3);
  // Initialization of inputs.
  BlockSieve po(n, z);
  for (int i = 1; i <= z; ++i) {
    po.f[i] = 1;
    po.F[i] = i;
  }
  for (int i = 1; i <= n / z; ++i) {
    po.F2[i] = n / i;
  }
  BlockSieve res(n, z);
  res.f[1] = 1;
  for (int i = 1; i <= z; ++i) {
    res.F[i] = 1;
  }
  for (int i = 1; i <= n / z; ++i) {
    res.F2[i] = 1;
  }
  // Binary exponentiation.
  for (; k; k >>= 1) {
    if (k & 1) res = res * po;
    po = po * po;
  }
  std::cout << res.sum(n) << std::endl;
  return 0;
}
P4213【模板】杜教筛（Sum） (Template: Du's sieve (Sum))

Let \(\mu\) and \(\varphi\) be the Möbius function and Euler's totient function, respectively. Compute the values of \(S_1(n)= \sum_{i=1}^{n} \mu(i)\) and \(S_2(n)= \sum_{i=1}^{n} \varphi(i)\). Constraints: \(1\leq n<2^{31}\).

Solution

Note the Dirichlet convolution relations:

\[ \varepsilon = \mu \ast 1,~ \operatorname{id} = \varphi \ast 1. \]

Here \(\varepsilon(n) = [n=1]\) is the identity element of Dirichlet convolution, \(\operatorname{id}(n) = n\) is the identity function, and \(1(n) = 1\) is the constant function. Since the prefix sums of these three functions can all be computed in \(O(1)\) time and they are all multiplicative, the Du's sieve method introduced above computes them in \(O(n^{2/3})\) time.

For computing the prefix sum of Euler's totient function, another method is to use Möbius inversion. Note that

\[ \begin{aligned} S_2(n) &= \sum_{i=1}^n\varphi(i) = \sum_{i=1}^n\sum_{j=1}^i[i\perp j] \\ &= \sum_{i=1}^n\sum_{j=1}^i\sum_d\mu(d)[d\mid i][d\mid j] \\ &= \sum_d\mu(d)\dfrac{1}{2}\left\lfloor\dfrac{n}{d}\right\rfloor\left(\left\lfloor\dfrac{n}{d}\right\rfloor+1\right). \end{aligned} \]

In the floor-division blocks process, the prefix sum of \(\mu(d)\) is needed, and it can be precomputed with Du's sieve. The time complexity is still \(O(n^{2/3})\).

Reference implementation 
#include <cstring>
#include <iostream>
#include <map>
using namespace std;
constexpr int MAXN = 2000010;
long long T, n, pri[MAXN], cur, mu[MAXN], sum_mu[MAXN];
bool vis[MAXN];
map<long long, long long> mp_mu;

long long S_mu(long long x) {  // prefix sum of mu
  if (x < MAXN) return sum_mu[x];
  if (mp_mu[x]) return mp_mu[x];  // if the mu value for this x is already in the map, return it directly
  long long ret = (long long)1;
  for (long long i = 2, j; i <= x; i = j + 1) {
    j = x / (x / i);
    ret -= S_mu(x / i) * (j - i + 1);
  }
  return mp_mu[x] = ret;  // memoization, makes the next computation easier
}

long long S_phi(long long x) {  // prefix sum of phi
  long long ret = (long long)0;
  long long j;
  for (long long i = 1; i <= x; i = j + 1) {
    j = x / (x / i);
    ret += (S_mu(j) - S_mu(i - 1)) * (x / i) * (x / i);
  }
  return (ret - 1) / 2 + 1;
}

int main() {
  cin.tie(nullptr)->sync_with_stdio(false);
  cin >> T;
  mu[1] = 1;
  for (int i = 2; i < MAXN; i++) {  // linear sieve to precompute the mu array
    if (!vis[i]) {
      pri[++cur] = i;
      mu[i] = -1;
    }
    for (int j = 1; j <= cur && i * pri[j] < MAXN; j++) {
      vis[i * pri[j]] = true;
      if (i % pri[j])
        mu[i * pri[j]] = -mu[i];
      else {
        mu[i * pri[j]] = 0;
        break;
      }
    }
  }
  for (int i = 1; i < MAXN; i++)
    sum_mu[i] = sum_mu[i - 1] + mu[i];  // prefix sums of the mu array
  while (T--) {
    cin >> n;
    cout << S_phi(n) << ' ' << S_mu(n) << '\n';
  }
  return 0;
}
“Luogu P3768” 简单的数学题 (A simple math problem)

Given \(p,n\), compute

\[ \sum_{i=1}^n\sum_{j=1}^nij\cdot\gcd(i,j)\pmod p. \]

Constraints: \(n\leq 10^{10}\), \(5\times 10^8\leq p\leq 1.1\times 10^9\), and \(p\) is prime.

Solution

Using the properties of Euler's totient function, perform the following inversion:

\[ \begin{aligned} T(n) &= \sum_{i=1}^n\sum_{j=1}^nij\cdot\gcd(i,j)\\ &= \sum_{i=1}^n\sum_{j=1}^nij\sum_d\varphi(d)[d\mid i][d\mid j]\\ &= \sum_d\varphi(d)\left(\sum_{i=1}^{\lfloor n/d\rfloor}id\right)\left(\sum_{j=1}^{\lfloor n/d\rfloor}jd\right)\\ &= \sum_d d^2\varphi(d) F\left(\left\lfloor\dfrac{n}{d}\right\rfloor\right)^2. \end{aligned} \]

Here \(F(n) = \dfrac{1}{2}n(n+1)\). This expression can be computed with floor-division blocks, but the prefix sum of \(d^2\varphi(d)\) must be precomputed.

For this, Du's sieve can be used. Let \(f(n)=(\operatorname{id}^2\varphi)(n)\) and \(S(n)=\sum_{i=1}^n f(i)\). The key to applying Du's sieve is to construct a function \(g\) such that both \(f\ast g\) and \(g\) can be summed quickly. Above we already discussed precomputing the prefix sum of \(\varphi\) with Du's sieve, which only requires the relation \(\operatorname{id} = \varphi\ast 1\). Compared with \(\varphi\), the \(f\) here has an extra factor \(\operatorname{id}^2\). Since \(\operatorname{id}\) is a completely multiplicative function, by the properties of Dirichlet convolution it suffices to similarly multiply each term by \(\operatorname{id}^2\), which gives

\[ \operatorname{id}^3 = f \ast \operatorname{id}^2. \]

Since the prefix sums of \(\operatorname{id}^2(n)=n^2\) and \(\operatorname{id}^3(n)=n^3\) can both be computed in \(O(1)\) time, the prefix sum of \(f\) can be precomputed in \(O(n^{2/3})\) time. Together with floor-division blocks, the overall time complexity is still \(O(n^{2/3})\).

Another way to represent a similar multiplicative function as the quotient (in the sense of Dirichlet convolution) of two functions is to use Dirichlet generating functions.

Reference implementation 
// Do not shrink the arrays to save memory, you will get stuck at 80 points
#include <cmath>
#include <iostream>
#include <map>
using namespace std;
constexpr int N = 5e6, NP = 5e6, SZ = N;
long long n, P, inv2, inv6, s[N];
int phi[N], p[NP], cnt, pn;
bool bp[N];
map<long long, long long> s_map;

long long ksm(long long a, long long m) {  // used for computing inverses
  long long res = 1;
  while (m) {
    if (m & 1) res = res * a % P;
    a = a * a % P, m >>= 1;
  }
  return res;
}

void prime_work(int k) {  // linear sieve for phi, s
  bp[0] = bp[1] = true, phi[1] = 1;
  for (int i = 2; i <= k; i++) {
    if (!bp[i]) p[++cnt] = i, phi[i] = i - 1;
    for (int j = 1; j <= cnt && i * p[j] <= k; j++) {
      bp[i * p[j]] = true;
      if (i % p[j] == 0) {
        phi[i * p[j]] = phi[i] * p[j];
        break;
      } else
        phi[i * p[j]] = phi[i] * phi[p[j]];
    }
  }
  for (int i = 1; i <= k; i++)
    s[i] = (1ll * i * i % P * phi[i] % P + s[i - 1]) % P;
}

long long s3(long long k) {  // sum of cubes
  return k %= P, (k * (k + 1) / 2) % P * ((k * (k + 1) / 2) % P) % P;
}

long long s2(long long k) {  // sum of squares
  return k %= P, k * (k + 1) % P * (k * 2 + 1) % P * inv6 % P;
}

long long calc(long long k) {  // compute S(k)
  if (k <= pn) return s[k];
  if (s_map[k]) return s_map[k];  // values above pn are stored sparsely in a map
  long long res = s3(k), pre = 1, cur;
  for (long long i = 2, j; i <= k; i = j + 1)
    j = k / (k / i), cur = s2(j),
    res = (res - calc(k / i) * (cur - pre) % P) % P, pre = cur;
  return s_map[k] = (res + P) % P;
}

long long solve() {
  long long res = 0, pre = 0, cur;
  for (long long i = 1, j; i <= n; i = j + 1) {
    j = n / (n / i);
    cur = calc(j);
    res = (res + (s3(n / i) * (cur - pre)) % P) % P;
    pre = cur;
  }
  return (res + P) % P;
}

int main() {
  cin.tie(nullptr)->sync_with_stdio(false);
  cin >> P >> n;
  inv2 = ksm(2, P - 2), inv6 = ksm(6, P - 2);
  pn = (long long)pow(n, 0.666667);  // n^(2/3)
  prime_work(pn);
  cout << solve();
  return 0;
}
