Uvod

Schreier–Simsov algoritam (Schreier–Sims algorithm) algoritam je računalne teorije grupa (computational group theory), nazvan po matematičarima Ottu Schreieru i Charlesu Simsu. Algoritam u polinomnom vremenu rješava mnoge probleme, kao što su određivanje reda konačne grupe permutacija ili provjera pripada li zadana permutacija zadanoj grupi. Schreier–Simsov algoritam prvi je uveo Sims 1970. godine, na temelju Schreierove leme. Godine 1981.1 Donald Knuth dodatno je poboljšao vrijeme izvođenja algoritma. Kasnije je razvijena i brža randomizirana inačica algoritma. Sustavi računalne algebre (primjerice GAP i Magma) obično koriste visoko optimiranu Monte Carlo inačicu tog algoritma2.

Oznake

U skladu s običajem u literaturi o računalnoj teoriji grupa, u ovom se članku djelovanje grupe zapisuje kao desno djelovanje, što znači da se permutacije komponiraju slijeva nadesno. Sva djelovanja grupa u ovom članku mogu se smatrati djelovanjima permutacijama, iako neki algoritmi vrijede i za općenitija djelovanja grupa. U skladu s tim, skup na kojem grupa djeluje je prema zadanom \(X=\{1,2,\cdots,n\}\), a njegovi se elementi nazivaju točkama. Rezultat djelovanja permutacije \(g\) na točku \(x\) označava se \(x^g\); kaže se i da permutacija \(g\) pomiče točku \(x\) u točku \(x^g\). Konačno, pod djelovanjem grupe permutacija \(G\) orbita točke \(x\) označava se \(x^G=\{x^g:g\in G\}\), a njezin stabilizator \(G_x=\{g\in G:x^g=x\}\). Pojam stabilizatora može se poopćiti i na skup \(B\subseteq X\); njegov je stabilizator definiran kao \(G_B=\bigcap_{x\in B}G_x\).

Pregled

Schreier–Simsov algoritam pokušava riješiti u osnovi sljedeći problem:

  • Zadan je skup \(S\) nekih permutacija skupa \(X\) veličine \(n\). Kako u računalu učinkovito pohraniti grupu permutacija \(G=\langle S\rangle\) koju generira \(S\) i odgovoriti na niz upita o toj grupi?

Očito, takva grupa \(G\) može biti vrlo velika, i to daleko veća od skupa \(X\) i generirajućeg skupa \(S\). Primjerice, simetrična grupa \(S_n=\langle(123\cdots n),(12)\rangle\) stupnja \(n\) ima \(n!\) elemenata, ali je generiraju samo dvije permutacije. Pohranjivanje svakog elementa grupe nije realistično.

Slično kao što se Gaussovom eliminacijom konstruira linearna baza vektorskog prostora, ideja je Schreier–Simsova algoritma pronaći „bazu” konačne grupe permutacija \(G\):

  1. Ulaz algoritma je generirajući skup \(S\) grupe \(G\) koji sadrži nekoliko permutacija;
  2. ako grupa \(G\) nije trivijalna, uvijek se može pronaći točka \(\beta\) čiji se položaj pod djelovanjem grupe \(G\) mijenja, tj. \(|\beta^G|>1\);
  3. nađe se orbita \(\Delta=\beta^{G}\) točke \(\beta\) i za svaku točku \(\delta\in\Delta\) orbite nađe se permutacija \(t_{\delta}\) u grupi \(G\) koja pomiče točku \(\beta\) u \(\delta\);
  4. nađe se generirajući skup \(S'\) stabilizatora \(G_{\beta}\) točke \(\beta\);
  5. algoritam se rekurzivno poziva na \(G'=\langle S'\rangle\), sve dok se ne dobije trivijalna grupa \(\{e\}\).

Opravdanost ove ideje leži u tome što je stabilizator \(G_{\beta}\) točke \(\beta\) podgrupa grupe \(G\), sve njegove (desne) susjedne klase čine particiju grupe \(G\), a te su klase u bijekciji s orbitom \(\beta^G\) točke \(\beta\); permutacije \(t_{\delta}\) pronađene u 3. koraku upravo su predstavnici tih klasa. Taj skup \(T\) predstavnika klasa naziva se transverzala (transversal) stabilizatora \(G_{\beta}\). Drugim riječima, svaki element \(g\) grupe \(G\) odgovara jedinstvenom paru elemenata \((h,t)\in G_\beta\times T\) takvom da je \(g=ht\). Stoga, ako se na neki način uspiju pohraniti podgrupa \(G_{\beta}\) i odgovarajuća transverzala \(T\), može se pohraniti i cijela grupa \(G\). A problem pohranjivanja podgrupe \(G_{\beta}\) već je riješen – dovoljno je rekurzivno pozvati algoritam.

Naravno, u implementaciji algoritma ima još mnogo detalja koje treba razjasniti, i to je glavni sadržaj ovog članka. No prije toga treba proučiti rezultat koji se dobiva pozivom algoritma, tj. u kakvu strukturu algoritam pohranjuje grupu i na koje upite pomoću nje može odgovoriti. Za to je potrebno razjasniti nekoliko pojmova.

Lanac stabilizatora

Pretpostavimo da je algoritam pozvan na grupi \(G=\langle S\rangle\) ukupno \(k\) puta te da je u \(i\)-tom pozivu ulaz bio skup permutacija \(S^{(i-1)}\), pronađena točka \(\beta_i\), dobivena transverzala \(T_i\), a dobiveni generirajući skup stabilizatora \(S^{(i)}\). Ako označimo \(G^{(i)}=\langle S^{(i)}\rangle\), algoritam je zapravo dobio lanac podgrupa

\[ G=G^{(0)}> G^{(1)}>\cdots> G^{(k-1)}> G^{(k)}=\{e\}. \]

Štoviše, svaka podgrupa u lancu je stabilizator

\[ G^{(i)}=G_{\beta_1,\cdots,\beta_i}. \]

Stoga se Schreier–Simsov algoritam može promatrati upravo kao računanje takvog lanca stabilizatora (stabilizer chain).

Baza i jaki generirajući skup

Ako podskup \(B\) skupa \(X\) zadovoljava \(G_B=\{e\}\), kaže se da je \(B\) baza (base) grupe permutacija \(G\). Očito je gornji algoritam dobio bazu \(B=\{\beta_1,\cdots,\beta_k\}\). To znači da rezultat djelovanja permutacije \(g\in G\) na te točke jedinstveno određuje tu permutaciju unutar grupe \(G\). Štoviše, baza koju algoritam vraća zadovoljava i uvjet

\[ G^{(i-1)}=G_{\beta_1,\cdots,\beta_{i-1}}>G_{\beta_1,\cdots,\beta_{i-1},\beta_i}=G^{(i)}. \]

To znači da svaka točka baze nosi stvarnu informaciju o elementima grupe. Takva se baza naziva neredundantnom (nonredundant). Algoritam uvijek vraća neredundantnu bazu. Lanac stabilizatora koji odgovara takvoj bazi strogo je padajući.

Istodobno, unija generirajućih skupova dobivenih algoritmom

\[ \bar S=\bigcup_{i=0}^kS^{(i)} \]

također je generirajući skup grupe \(G\) i vrijedi \(\langle\bar S\cap G^{(i)}\rangle = G^{(i)}\). Generirajući skup koji zadovoljava taj uvjet naziva se jakim generirajućim skupom (strong generating set) grupe \(G\) u odnosu na bazu \(B\). Stoga se Schreier–Simsov algoritam može promatrati i kao računanje baze i jakog generirajućeg skupa (base and strong generating set, BSGS) grupe \(G\). Ta je formulacija ekvivalentna formulaciji pomoću lanca stabilizatora i u ovom se članku ne razlikuju.

Naravno, algoritam daje i niz orbita \(\Delta_i=\beta_{i}^{G^{(i-1)}}\) i odgovarajućih transverzala \(T_i\). Te se orbite nazivaju osnovnim orbitama (basic orbits) grupe \(G\). Kad se u ovom članku spominju lanac stabilizatora ili baza i jaki generirajući skup grupe \(G\), uvijek se podrazumijeva da su odgovarajuće osnovne orbite i transverzale također izračunate.

Struktura podataka

U ovom će se članku dati niz pseudokodova. U pseudokodu se lanac stabilizatora grupe (ili baza i jaki generirajući skup) pohranjuje u strukturu podataka \(C\):

\[ C=(S,\Delta,T,C'). \]

Podatkovni članovi te strukture redom su generirajući skup \(S\) trenutačne grupe, osnovna orbita \(\Delta\), odgovarajuća transverzala \(T\) i stabilizator \(C'\) pohranjen kao ugniježđena podstruktura. Naravno, stabilizator \(C'\) također je struktura istog oblika. Cijela je grupa zapravo pohranjena u slojevitoj strukturi, gdje svaki sloj opisuje jednu grupu u lancu stabilizatora. Najunutarnjiji sloj prazna je struktura koja predstavlja \(G^{(k)}=\{e\}\).

U pseudokodu se članovima te strukture pristupa redom preko \(C.generators\), \(C.orbit\), \(C.transversal\) i \(C.next\). Prvi element orbite \(C.orbit[0]\) prema zadanom je točka \(\beta\) iz baze, a odgovarajući predstavnik klase \(C.transversal[\beta]\) prema zadanom je identiteta \(e\). Napomena: iako se ovdje elementima orbite i transverzale pristupa indeksima polja, oni ne moraju nužno biti pohranjeni kao polja; treba to shvatiti tako da pružaju način pristupa prvom elementu orbite te dohvaćanja predstavnika klase prema točki orbite. Konkretni detalji implementacije raspravljaju se u nastavku.

Primjene

Nakon što se dobiju baza i jaki generirajući skup grupe, može se riješiti niz upita o grupi. Među njima su najosnovniji, i oni s kojima se najčešće susreće na algoritamskim natjecanjima, upit o redu grupe i upit pripada li neka permutacija zadanoj grupi.

Red grupe

Ako su poznati baza i jaki generirajući skup grupe \(G\), primjenom Lagrangeova teorema i teorema o orbiti i stabilizatoru dobiva se da se red grupe \(G\) može izračunati kao

\[ |G|=\prod_{i=1}^k[G^{(i-1)}:G^{(i)}]=\prod_{i=1}^k[G^{(i-1)}:G^{(i-1)}_{\beta_i}]=\prod_{i=1}^k|T_i|. \]

Dakle, dovoljno je pomnožiti veličine svih transverzala \(T_i\) (ili, ekvivalentno, duljine osnovnih orbita \(\Delta_i\)) da bi se dobio red grupe \(G\).

Provjera pripadnosti

Ako su poznati baza i jaki generirajući skup grupe \(G\), može se odrediti i pripada li neka permutacija \(h\) grupi \(G\). To se naziva problemom provjere pripadnosti (membership testing).

Taj se problem može riješiti rekurzivno. Da bi se utvrdilo \(h\in G^{(i-1)}\), prvo treba pronaći predstavnika \(t\in T_i\) one klase podgrupe \(G^{(i)}\) koja sadrži \(h\). Ako se takav može pronaći, stavimo \(h'=ht^{-1}\); tada je \(h=h't\), a \(h\in G^{(i-1)}\) ekvivalentno je \(h'\in G^{(i)}\), pa se problem svodi na utvrđivanje \(h'\in G^{(i)}\). Ako se takav \(t\) ne može pronaći, ili je rekurzija već stigla do \(G^{(k)}=\{e\}\), ali je \(h\neq e\), može se zaključiti \(h\notin G\). Zapravo, taj postupak ne samo da utvrđuje \(h\in G\), nego u slučaju \(h\in G\) prikazuje \(h\) kao produkt niza predstavnika klasa \(t_k\cdots t_2t_1\), gdje je \(t_i\in T_i\). Za elemente grupe \(G\) takav prikaz postoji i jedinstven je. To ponovno dokazuje da je gornja formula za red grupe točna.

Taj postupak sada zapisujemo kao sljedeći pseudokod:

\[ \begin{array}{l} \textbf{Algorithm }\textrm{MembershipTest}(C,h):\\ \textbf{Input. }\textrm{A stabilizer chain }C\textrm{ for a group }G\textrm{ and a permutation }h.\\ \textbf{Output. }\textrm{Whether }h\in G.\\ \textbf{Method.}\\ \begin{array}{ll} 1 & \textbf{while }C\textrm{ is not empty }\\ 2 & \qquad \beta \leftarrow C.orbit[0]\\ 3 & \qquad \delta \leftarrow \beta^h\\ 4 & \qquad \textbf{if }\delta\in C.orbit\textbf{ then}\\ 5 & \qquad \qquad t \leftarrow C.transversal[\delta]\\ 6 & \qquad \qquad h \leftarrow ht^{-1}\\ 7 & \qquad \textbf{else }\\ 8 & \qquad \qquad \textbf{return }\textrm{false}\\ 9 & \qquad \textbf{end if}\\ 10 & \qquad C \leftarrow C.next\\ 11 & \textbf{end while}\\ 12 & \textbf{return }h=e \end{array} \end{array} \]

U nastavku će se vidjeti da je problem provjere pripadnosti ujedno važan sastavni dio implementacije Schreier–Simsova algoritma o kojoj govori ovaj članak.

Računanje orbite, transverzale i stabilizatora

Da bi se implementirao Schreier–Simsov algoritam, prvo treba riješiti sljedeći potproblem:3

  • Zadani su generirajući skup \(S\) grupe \(G\) i točka \(\beta\). Kako izračunati orbitu \(\beta^G\), odgovarajuću transverzalu \(T\) i generirajući skup stabilizatora \(G_\beta\)?

To je problem koji se rješava u ovom odjeljku.

Pohranjivanje orbite i transverzale

Da bi se dobile orbita i transverzala, dovoljno je izravno pretraživati. Pseudokod je sljedeći:

\[ \begin{array}{l} \textbf{Algorithm }\textrm{OrbitTransversal}(S,\beta):\\ \textbf{Input. }\textrm{A generating set }S\textrm{ for a group }G\textrm{ and a point }\beta.\\ \textbf{Output. }\textrm{The orbit }\Delta=\beta^G\textrm{ and the transversal }T.\\ \textbf{Method.}\\ \begin{array}{ll} 1 & \Delta \leftarrow [\beta]\\ 2 & T[\beta] \leftarrow e\\ 3 & \textbf{for }\delta\in\Delta\\ 4 & \qquad \textbf{for }s\in S\\ 5 & \qquad \qquad \gamma \leftarrow \delta^s\\ 6 & \qquad \qquad \textbf{if }\gamma\notin\Delta\textbf{ then}\\ 7 & \qquad \qquad \qquad\textrm{append }\gamma\textrm{ to }\Delta\\ 8 & \qquad \qquad \qquad T[\gamma] \leftarrow T[\delta]\cdot s\\ 9 & \qquad \qquad \textbf{end if}\\ 10 & \qquad \textbf{end for}\\ 11 & \textbf{end for}\\ 12 & \textbf{return }\Delta, T \end{array} \end{array} \]

U konkretnoj implementaciji mogu se koristiti i pretraživanje u širinu (BFS) i pretraživanje u dubinu (DFS). Broj stanja koja pretraživanje obiđe je \(|S||T|\); ako se orbita i transverzala razumno pohrane, vremenska je složenost sasvim prihvatljiva.

Budući da je u kontekstu grupa permutacija orbita tek skup od najviše \(n\) točaka, za učinkovito pretraživanje i dodavanje može se pohraniti kao polje Booleovih vrijednosti ili neuređeni skup. Tako su obje operacije složenosti \(O(1)\), a ukupno zauzeće prostora je \(O(n)\). Naravno, ovisno o implementaciji transverzale, možda će dodatno trebati označiti položaj prvog elementa.

Pitanje je kojom strukturom podataka pohraniti odgovarajuću transverzalu \(T\).

Izravno pohranjivanje

Najjednostavnija je metoda, naravno, izravno pohraniti svaki element \(t\) transverzale \(T\). Jedna permutacija pohranjena u jednorednom zapisu zauzima točno \(n\) prostora, pa je prostorna složenost pohranjivanja takve transverzale \(O(|T|n)\). Prednost je toga da je vremenska složenost pristupa jednom predstavniku klase \(O(1)\), a cijena je da je vremenska složenost prvog računanja tih predstavnika klasa \(O(|T|n)\).

Schreierovo stablo

Drugi je uobičajen pristup implementirati stablastu strukturu za pohranjivanje transverzale. Ona se naziva Schreierovim stablom (Schreier tree) ili Schreierovim vektorom (Schreier vector)4. Korijen joj je \(\beta\), a vrhovi su elementi \(\delta\) orbite \(\Delta\). Svaki put kad se tijekom pretraživanja dobije novi vrh \(\gamma=\delta^s\), povuče se brid od starog vrha \(\delta\) do novog vrha \(\gamma\) i na bridu se zabilježi indeks (ili pokazivač) permutacije \(s\) iz generirajućeg skupa \(S\). Budući da je generirajući skup već pohranjen, dodatna prostorna složenost pohranjivanja transverzale je \(O(|T|)\). Za slučajeve kad je \(n\) vrlo velik, to učinkovito štedi prostor, a složenost prvog računanja je \(O(|T|)\). Nuspojava je, međutim, da svaki put kad treba dobiti predstavnika klase treba proći bridovima na putu od vrha do korijena i ponovno izračunati predstavnika, pa vremenska složenost jako ovisi o dubini Schreierova stabla. U općem slučaju dubina stabla može doseći red veličine \(O(n)\).

U konkretnoj implementaciji treba, ovisno o situaciji, odvagnuti vremensku i prostornu složenost algoritma. U slučajevima s kojima se može susresti na algoritamskim natjecanjima \(n\) obično nije velik, prostora je dovoljno, a vremenska složenost često postaje usko grlo. Ubrzo će se vidjeti da upravo najzahtjevniji korak Schreier–Simsova algoritma mnogo puta pristupa predstavnicima klasa, pa je izravno pohranjivanje često bolje. No u nekim primjenama \(n\) može biti vrlo velik, a prostor oskudniji, pa transverzalu može biti potrebno pohraniti Schreierovim stablom. Za taj su slučaj, kako bi se izbjegla prevelika dubina Schreierova stabla, istraživači predložili mnoge metode kojima se, kad stablo postane preduboko, rekonstruira plitko Schreierovo stablo. Zainteresirani čitatelji mogu pogledati literaturu na kraju članka.

U pseudokodu ovaj članak neće razlikovati konkretne implementacije transverzale, nego će samo pretpostavljati da struktura podataka koja pohranjuje transverzalu \(T\) implementira operacije pristupa i izmjene predstavnika klase \(T[\delta]\) prema elementu orbite \(\delta\in\Delta\).

Schreierova lema

Nakon što se dobiju orbita \(\beta^G\) i transverzala \(T\), Schreierova lema daje način da se dobije generirajući skup stabilizatora \(G_\beta\).

Schreierova lema

Neka grupa \(G=\langle S\rangle\) ima podgrupu \(H\le G\). Neka je \(T\) (desna) transverzala podgrupe \(H\) takva da je \(e\in T\)9, i označimo s \(\overline g\) predstavnika \(t\in T\) one klase u kojoj leži \(g\in G\). Tada je skup

\[ U=\{ts(\overline{ts})^{-1}:t\in T,s\in S\} \]

generirajući skup podgrupe \(H\). Njegovi se elementi nazivaju Schreierovim generatorima (Schreier generators) podgrupe \(H\).

Dokaz

Prvo, prema definiciji predstavnika klase, \(ts(\overline{ts})^{-1}\in H\) vrijedi za sve \(t\in T,s\in S\), pa je \(\langle U\rangle\subseteq H\).

Obratno, za bilo koji \(h\in H\), budući da je \(S\) generirajući skup grupe \(G\ge H\), nužno postoji niz \(s_i\in S\cup S^{-1}\) takav da vrijedi

\[ h=s_1s_2\cdots s_r \]

Stavimo \(t_1=e\) i rekurzivno definirajmo \(t_{i+1}=\overline{t_is_i}\in T\); tada je

\[ \begin{aligned} h&=\left(t_1s_1t_2^{-1}\right)\left(t_2s_2t_3^{-1}\right)\cdots\left(t_rs_rt_{r+1}^{-1}\right)t_{r+1}. \end{aligned} \]

A za svaki \(i=1,2,\cdots,r\) vrijedi \(t_is_it_{i+1}^{-1}=t_is_i(\overline{t_is_i})^{-1}\in U\cup U^{-1}\subseteq H\), pa je \(t_{r+1}\in H\). No \(H\cap T=\{e\}\), pa je \(t_{r+1}=e\). To pokazuje da se svaki \(h\in H\) može zapisati kao produkt niza elemenata \(u_i=t_is_it_{i+1}^{-1}\in U\cup U^{-1}\), tj. \(U\) generira \(H\).

Budući da je podgrupa koja odgovara transverzali \(T\) upravo stabilizator \(G_\beta\), nakon što se izračuna transverzala \(T\), kombinirajući je s generirajućim skupom \(S\) grupe \(G\) dobiva se generirajući skup stabilizatora \(G_\beta\).

Algoritam

Uz malu izmjenu gornjeg pseudokoda može se, istodobno s računanjem orbite i transverzale, dobiti i generirajući skup odgovarajućeg stabilizatora:

\[ \begin{array}{l} \textbf{Algorithm }\textrm{OrbitTransversalStabilizer}(S,\beta):\\ \textbf{Input. }\textrm{A generating set }S\textrm{ for a group }G\textrm{ and a point }\beta.\\ \textbf{Output. }\textrm{The orbit }\Delta=\beta^G\textrm{, the transversal }T\textrm{, and a}\\ \qquad\textrm{ generating set }S'\textrm{ for the stabilizer }G_\beta.\\ \textbf{Method.}\\ \begin{array}{ll} 1 & \Delta \leftarrow [\beta]\\ 2 & T[\beta] \leftarrow e\\ 3 & S' \leftarrow [e]\\ 4 & \textbf{for }\delta\in\Delta\\ 5 & \qquad \textbf{for }s\in S\\ 6 & \qquad \qquad \gamma \leftarrow \delta^s\\ 7 & \qquad \qquad \textbf{if }\gamma\notin\Delta\textbf{ then}\\ 8 & \qquad \qquad \qquad\textrm{append }\gamma\textrm{ to }\Delta\\ 9 & \qquad \qquad \qquad T[\gamma] \leftarrow T[\delta]\cdot s\\ 10 & \qquad \qquad \textbf{else} \\ 11 & \qquad \qquad \qquad \textrm{append }T[\delta]\cdot s\cdot T[\gamma]^{-1}\textrm{ to }S'\\ 12 & \qquad \qquad \textbf{end if}\\ 13 & \qquad \textbf{end for}\\ 14 & \textbf{end for}\\ 15 & \textbf{return }\Delta, T, S' \end{array} \end{array} \]

U pseudokodu je, za svaki par \((\delta,s)\), \(t_\delta st_{\delta^s}^{-1}\) novi Schreierov generator samo kad u orbiti ne nastaje novi element; inače je to identiteta \(e\). Stoga Schreierovih generatora koji stvarno nastaju u algoritmu (ne računajući početnu identitetu) ima najviše

\[ |S||T|-(|T|-1) = (|S|-1)|T|+1 \]

U općem slučaju ta je gornja ograda oštra5. No za konačne grupe koje se u praksi obrađuju ta je ograda prilično labava: većina novodobivenih Schreierovih generatora ponavljanja su ranije dobivenih generatora ili se mogu dobiti kompozicijom ranijih generatora.

Budući da se osnovni tijek Schreier–Simsova algoritma može implementirati kao rekurzivno pozivanje gornjeg algoritma za računanje orbite i stabilizatora, zapravo smo već dobili jednu naivnu implementaciju Schreier–Simsova algoritma. No ako se ne provodi prosijavanje, broj Schreierovih generatora raste eksponencijalno: uzastopnom primjenom \(|S^{(i)}|=O(|S^{(i-1)}||T_i|)\) dobiva se da će veličina generirajućeg skupa najunutarnjijeg stabilizatora doseći \(O(|S||G|)\). To je očito apsurdno neučinkovito, jer je najunutarnjiji stabilizator \(\{e\}\).

Simsov rad daje način da se ograniči brzina rasta broja Schreierovih generatora, čime se jamči da je veličina konačno dobivenog jakog generirajućeg skupa \(\bar S\) jednaka \(O(n^2)\). Tako se baza i jaki generirajući skup mogu izračunati u polinomnom vremenu.

Schreier–Simsov algoritam

Da bi se riješio gornji problem, u ovom se odjeljku raspravlja o inkrementalnoj implementaciji Schreier–Simsova algoritma kojom se dobiva jaki generirajući skup veličine \(O(n^2)\).

Prosijavanje

Ključna optimizacija kojom Schreier–Simsov algoritam poboljšava gornji naivni algoritam vrlo je jednostavna: prije dodavanja bilo kojeg Schreierova generatora u generirajući skup stabilizatora zahtijeva se da on prvo prođe prosijavanje (sifting). Prosijavanje znači da se prvo provjeri nalazi li se novi Schreierov generator već u podgrupi koju generiraju postojeći generatori, a zatim se dodaju samo oni generatori kojih još nema. Za to je dovoljno upotrijebiti algoritam za provjeru pripadnosti \(\textrm{MembershipTest}(C,h)\) iz prethodnog teksta.

No preduvjet za to jest da je za Schreierove generatore koji su već proizvedeni na temelju trenutačne grupe već izgrađen lanac stabilizatora (ili baza i jaki generirajući skup) grupe koju oni generiraju. To znači da se pri svakom dodavanju novog Schreierova generatora u generirajući skup stabilizatora mora dinamički održavati unutarnji lanac stabilizatora, kako bi se mogao koristiti za kasnija prosijavanja. No svako umetanje generatora u trenutačni sloj može proizvesti više Schreierovih generatora, pa i više puta ažurirati unutarnju strukturu; a svako ažuriranje unutarnje strukture može izazvati više ažuriranja još dubljih struktura.

Čini se da ranije spomenuti problem eksponencijalne eksplozije i dalje postoji. Zapravo nije tako. Budući da se prosijavanje provodi unaprijed, struktura nekog sloja ažurira se samo kad generator koji se dodaje doista proširi tu strukturu. To pokazuje da je broj ažuriranja jednog sloja zapravo jednak broju strogih povećanja grupe pohranjene u tom sloju. No duljina lanca podgrupa grupe veličine \(|G|\) je najviše \(\log_2|G|\), jer Lagrangeov teorem jamči da se sa svakim produljenjem lanca podgrupa za jedan veličina grupe barem udvostruči. To pokazuje da se jedan sloj ažurira najviše \(\log_2|G|\) puta, pa je veličina konačno dobivenog jakog generirajućeg skupa \(\bar S\) jednaka \(O(|B|\log|G|)\).

Ta se ocjena može dodatno poboljšati. Budući da je grupa \(G\) koja se ovdje pojavljuje podgrupa simetrične grupe \(S_n\) stupnja \(n\), duljina lanca podgrupa grupe \(G\) ne može premašiti duljinu lanca podgrupa grupe \(S_n\). Može se dokazati6 da duljina strogo rastućeg lanca podgrupa grupe \(S_n\) ne premašuje \(3n/2\). To pokazuje da je broj ažuriranja jednog sloja zapravo \(O(n)\). Očito ni veličina baze ne premašuje \(n\). Stoga je veličina konačno dobivenog jakog generirajućeg skupa \(\bar S\) jednaka \(O(n^2)\).

Ovdje spomenutu metodu prosijavanja predložio je Sims i naziva se i Simsovim filtrom (Sims filter). Postoji i složenija metoda prosijavanja koju je predložio Jerrum, nazvana Jerrumov filtar (Jerrum filter), kojom se jamči da je veličina dobivenog jakog generirajućeg skupa \(O(n)\). Zainteresirani čitatelji mogu je proučiti sami.

Mala je optimizacija postupka prosijavanja da implementacija \(\textrm{MembershipTest}(C,h)\) ne vraća Booleovu vrijednost, nego konačno dobiveni „ostatak prosijavanja”7 \(h\) (tj. da se \(8\). i \(12\). redak pseudokoda zamijene s \(\textbf{return }h\)). Ako je „ostatak” \(h\neq e\), provjera pripadnosti nije uspjela, i tada se u trenutačni sloj može izravno dodati „ostatak” \(h\) umjesto izvornog \(h\). Taj je „ostatak” \(h\) već lišen faktora nekoliko predstavnika klasa, pa pomiče manje elemenata i time smanjuje lokalni obujam računanja. Ta optimizacija ne mijenja gornju analizu.

Postupak

Sad se može opisati konkretan postupak Schreier–Simsova algoritma: prvo se inicijalizira prazna struktura \(C\) za pohranjivanje lanca stabilizatora grupe. Zatim se u strukturu \(C\) jedan po jedan dodaju generatori iz generirajućeg skupa \(S\); konačno dobivena struktura \(C\) upravo je lanac stabilizatora grupe \(\langle S\rangle\). Pseudokod je sljedeći:

\[ \begin{array}{l} \textbf{Algorithm }\textrm{SchreierSims}(S):\\ \textbf{Input. }\textrm{A generating set }S\textrm{ for a group }G.\\ \textbf{Output. }\textrm{The stabilizer chain }C\textrm{ for the group }G.\\ \textbf{Method.}\\ \begin{array}{ll} 1 & C \leftarrow []\\ 2 & \textbf{for }s\in S\\ 3 & \qquad C \leftarrow \textrm{Extend}(C,s)\\ 4 & \textbf{end for}\\ 5 & \textbf{return }C \end{array} \end{array} \]

Srž algoritma je korak dodavanja novog generatora \(s\) u trenutačnu strukturu \(C\), tj. potprogram \(\textrm{Extend}(C,s)\). Kao što je rečeno, i prije i poslije dodavanja permutacije \(s\) treba osigurati da je \(C\) lanac stabilizatora. Tako se prije dodavanja permutacije \(s\) može prvo provesti prosijavanje. Ako se utvrdi da \(s\) nije u postojećoj grupi, inkrementalno se računaju orbita, predstavnici klasa i Schreierovi generatori. „Inkrementalno” ovdje znači da se ono što je već izračunato ne računa ponovno. Samo se tako može zajamčiti ispravna složenost.

Razmotrimo kako \(\textrm{OrbitTransversalStabilizer}(S,\beta)\) preraditi u inkrementalnu inačicu. Prostor stanja koji algoritam pretražuje je \(\Delta\times S\). Nakon dodavanja novog generatora \(s\) prostor stanja postaje \(\Delta'\times\left(S\cup\{s\}\right)\). Razlika tih dvaju skupova je

\[ \left(\Delta\times\{s\}\right)\cup\left((\Delta'\setminus\Delta)\times \left(S\cup\{s\}\right)\right). \]

To znači da pri dodavanju novog generatora \(s\) prvo treba izračunati kombinacije novog generatora \(s\) sa starom orbitom i odgovarajućim predstavnicima klasa; ako se pritom dobiju novi elementi orbite, razmatraju se i kombinacije tih elemenata sa svim generatorima (bez obzira na to jesu li novi ili stari); postupak se ponavlja dok se orbita više ne produljuje.

Druga implementacija

Gornja je implementacija već ispravna, ali se redci \(12\sim 19\) i \(23\sim 30\) pomalo ponavljaju. Na temelju toga Knuth je u svom radu predložio rekurzivnu implementaciju koja je sažetija. Njegov je pristup da se taj ponavljajući dio promatra kao ažuriranje transverzale (i orbite). Svako ažuriranje transverzale treba kombinirati sa svim generatorima, a ovisno o tome je li nastao novi predstavnik klase, odlučuje se hoće li se rekurzivno pozvati sam potprogram ili postupak dodavanja generatora. Pseudokod je sljedeći:

\[ \begin{array}{l} \textbf{Algorithm }\textrm{Extend}(C,g):\\ \textbf{Input. }\textrm{A stabilizer chain }C\textrm{ for the group generated by }S\textrm{ and a}\\ \qquad \textrm{permutation }g.\\ \textbf{Output. }\textrm{A stabilizer chain }C\textrm{ for the group generated by }S\cup\{g\}.\\ \textbf{Method.}\\ \begin{array}{ll} 1 & \textbf{if }\textrm{MembershipTest}(C,g)\textrm{ is passed}\textbf{ then}\\ 2 & \qquad \textbf{return }C\\ 3 & \textbf{end if}\\ 4 & \textbf{if }C\textrm{ is empty}\textbf{ then}\\ 5 & \qquad \beta \leftarrow \textrm{an element moved by }g\\ 6 & \qquad C.orbit[0] \leftarrow \beta \\ 7 & \qquad C.transversal[\beta] \leftarrow e\\ 8 & \textbf{end if}\\ 9 & \textrm{append }g\textrm{ to }C.generators\\ 10 & \textbf{for }t\in\textrm{a copy of }C.transversal\\ 11 & \qquad \textrm{ExtendTransversal}(C,t\cdot g)\\ 12 & \textbf{end for}\\ 13 & \textbf{return }C \end{array}\\ \\ \textbf{Sub-Algorithm }\textrm{ExtendTransversal}(C,t):\\ \textbf{Method.}\\ \begin{array}{ll} 1 & \beta \leftarrow C.orbit[0]\\ 2 & \gamma \leftarrow \beta^t\\ 3 & \textbf{if }\gamma\notin C.orbit\textbf{ then}\\ 4 & \qquad \textrm{append }\gamma\textrm{ to }C.orbit\\ 5 & \qquad C.transversal[\gamma] \leftarrow t\\ 6 & \qquad \textbf{for }s\in C.generators\\ 7 & \qquad \qquad \textrm{ExtendTransversal}(C,t\cdot s)\\ 8 & \qquad \textbf{end for}\\ 9 & \textbf{else}\\ 10 & \qquad s' \leftarrow t\cdot C.transversal[\gamma]^{-1}\\ 11 & \qquad C.next \leftarrow \textrm{Extend}(C.next,s')\\ 12 & \textbf{end if} \end{array} \end{array} \]

Usporedbom ovog pseudokoda s onim iz prethodnog odjeljka vidi se da je ispravan. Štoviše, složenosti im se ne razlikuju. Napomena: \(10\). redak potprograma \(\textrm{Extend}\) prolazi transverzalom kakva je bila pri ulasku u petlju; predstavnici klasa koji nastaju tijekom petlje već su u rekurziji \(\textrm{ExtendTransversal}\) kombinirani sa svim generatorima i ne treba ih ponovno prolaziti.

Složenost

Za analizu složenosti Schreier–Simsova algoritma potrebno je nekoliko oznaka. Neka je duljina permutacija \(n\), a veličina generirajućeg skupa \(|S|\) jednaka \(m\). Duljinu dobivene (neredundantne) baze označimo \(|B|\). Nadalje, u konačno dobivenom stabilizatoru \(G^{(i-1)}\) na \(i\)-tom sloju izvana prema unutra broj generatora označimo \(|S^{(i-1)}|\), a veličinu transverzale (ili duljinu orbite) \(|T_i|\). U nastavku se analizira vremenska složenost gornje inkrementalne implementacije Schreier–Simsova algoritma. Algoritam se sastoji od dva glavna dijela: prosijavanja te računanja orbita, transverzala i Schreierovih generatora.

I početno zadani generatori i Schreierovi generatori dobiveni u algoritmu moraju proći prosijavanje, pa je ukupan broj izvođenja postupka prosijavanja \(O(\sum_{i=1}^{|B|}|S^{(i-1)}||T_i|+|S|)\). Jedno prosijavanje zahtijeva računanje produkta permutacija s \(O(|B|)\) predstavnika klasa. Neka je vrijeme računanja produkta s jednim predstavnikom klase \(\tau\). Pri izravnom pohranjivanju predstavnika klasa je \(\tau\in O(n)\), a pri pohranjivanju predstavnika klasa Schreierovim stablom je \(\tau\in O(n^2)\). Ukupna vremenska složenost izvođenja postupka prosijavanja je \(O(\tau|B|\sum_{i=1}^{|B|}|S^{(i-1)}||T_i|+\tau|B||S|)\).

Što se tiče računanja orbita i ostalih podataka, budući da je implementacija inkrementalna, svaki par \((\delta,s)\in\Delta_i\times S^{(i-1)}\) u prostoru stanja računa se najviše jednom. Za računanje orbita i transverzala, ovisno o načinu pohranjivanja, vremenska složenost računanja jednog predstavnika klase može biti \(O(n)\) ili \(O(1)\). No u svakom slučaju ona ne premašuje složenost računanja Schreierovih generatora. Pri izravnom pohranjivanju ona je \(O(n)\), a uz Schreierovo stablo \(O(n^2)\). Usporedbom s ukupnom vremenskom složenošću postupka prosijavanja vidi se da vremenska složenost računanja tih podataka ne premašuje vremensku složenost potrebnu za prosijavanje. Stoga je vremenska složenost Schreier–Simsova algoritma upravo \(O(\tau|B|\sum_{i=1}^{|B|}|S^{(i-1)}||T_i|+\tau|B||S|)\), dobivena u prethodnom odlomku.

Što se tiče prostorne složenosti, struktura podataka koju algoritam na kraju daje pohranjuje \(O(\sum_{i=1}^{|B|}|S^{(i-1)}|)\) generatora i \(O(\sum_{i=1}^{|B|}|T_i|)\) predstavnika klasa. Pri izravnom pohranjivanju i generatori i predstavnici klasa zahtijevaju \(O(n)\) prostora; uz Schreierovo stablo generatori zahtijevaju \(O(n)\) prostora, a predstavnici klasa samo \(O(1)\).

Ranije je pokazano da je duljina strogo rastućeg lanca podgrupa simetrične grupe stupnja \(n\) jednaka \(O(n)\), što vrijedi i za \(|B|\) i za \(|S^{(i)}|\). Stoga Schreier–Simsov algoritam implementiran s izravnim pohranjivanjem transverzala ima vremensku složenost \(O(n^5+mn^2)\) i prostornu složenost \(O(n^3)\). Naravno, za slučaj \(\log|G|\in O(n)\) bolja je ocjena vremenske složenosti8 \(O(n^2\log^3|G|+mn\log|G|)\) i prostorne složenosti \(O(n^2\log|G|)\). Za slučajne generirajuće skupove praktična su mjerenja pokazala da je složenost algoritma znatno niža od \(\Theta(n^5)\) i da iznosi otprilike \(\Theta(n^4)\).

Iako u odnosu na izravno pohranjivanje Schreierovo stablo u vremensku složenost unosi dodatni faktor \(n\), u slučaju kad je \(n\) vrlo velik, a sama grupa daleko manja od simetrične grupe stupnja \(n\), njegova je prostorna složenost \(O(n\log^2|G|)\), što je daleko manje od \(O(n^2\log|G|)\) kod izravnog pohranjivanja. No na algoritamskim natjecanjima teško je naići na takvu situaciju u kojoj je pohranjivanje Schreierovim stablom bolje.

Referentna implementacija

Ovdje dajemo referentnu implementaciju Schreier–Simsova algoritma. Budući da je \(n\) malen, u implementaciji se baza \(B=\{n,n-1,\cdots,1\}\) izravno zadaje umjesto da je algoritam bira. Prednost je toga da permutacije u grupi na \(k\)-tom sloju iznutra prema van (ne računajući praznu strukturu) mijenjaju samo prvih \(k\) elemenata, što olakšava daljnje računanje. Druga je optimizacija u kodu da se pri pohranjivanju predstavnika klasa zapravo pohranjuju njihove inverzne permutacije, što pojednostavnjuje operacije s permutacijama.

Referentna implementacija 
#include <iostream>
#include <vector>

// A permutation.
class Permutation {
  std::vector<int> perm;

  void shrink() {
    int m = perm.size();
    for (; m && perm[m - 1] == m - 1; --m);
    perm.resize(m);
  }

 public:
  Permutation() {}

  Permutation(const std::vector<int>& vec) : perm(vec) { shrink(); }

  int operator[](int i) const { return i < perm.size() ? perm[i] : i; }

  bool empty() const { return perm.empty(); }

  // First LHS then RHS.
  Permutation operator*(const Permutation& rhs) const {
    Permutation res;
    res.perm.resize(std::max(perm.size(), rhs.perm.size()));
    for (int i = 0; i < res.perm.size(); ++i) {
      res.perm[i] = rhs[(*this)[i]];
    }
    res.shrink();
    return res;
  }

  // First LHS^{-1} then RHS.
  Permutation operator/(const Permutation& rhs) const {
    Permutation res;
    res.perm.resize(std::max(perm.size(), rhs.perm.size()));
    for (int i = 0; i < res.perm.size(); ++i) {
      res.perm[(*this)[i]] = rhs[i];
    }
    res.shrink();
    return res;
  }

  // Inverse.
  Permutation inv() const {
    Permutation res;
    res.perm.resize(perm.size());
    for (int i = 0; i < res.perm.size(); ++i) {
      res.perm[(*this)[i]] = i;
    }
    return res;
  }
};

// A stabilizer chain (a.k.a., BSGS) for a group.
class PermutationGroup {
  size_t n, k;
  std::vector<bool> orbit;               // Orbit of the n-th point.
  std::vector<Permutation> generators;   // Generators.
  std::vector<Permutation> transversal;  // Inverse of coset representatives.
  PermutationGroup* next;                // Stabilizer.

  // Sift a permutation.
  void sift(Permutation& h) const {
    if (!n) return;
    int i = h[n - 1];
    if (!orbit[i]) return;
    h = h * transversal[i];
    next->sift(h);
  }

  // Add one more element into the transversal.
  void extend_transversal(Permutation t) {
    int i = t[n - 1];
    if (!orbit[i]) {
      ++k;
      orbit[i] = true;
      transversal[i] = t.inv();
      for (const auto& s : generators) {
        extend_transversal(t * s);
      }
    } else {
      next->extend(t * transversal[i]);
    }
  }

 public:
  PermutationGroup(int n)
      : n(n), k(1), orbit(n), transversal(n), next(nullptr) {
    if (!n) return;
    // Initialize the current layer.
    orbit[n - 1] = true;
    next = new PermutationGroup(n - 1);
  }

  // Destructor.
  ~PermutationGroup() {
    if (next) delete next;
  }

  // Add one more permutation into the group.
  void extend(Permutation g) {
    sift(g);
    if (g.empty()) return;
    generators.emplace_back(g);
    for (int i = 0; i < n; ++i) {
      if (orbit[i]) {
        extend_transversal(transversal[i] / g);
      }
    }
  }

  // Check whether a permutation belongs to the group.
  bool membership_test(Permutation h) const {
    sift(h);
    return h.empty();
  }

  // Return the size of the group.
  long long size() const { return n ? next->size() * k : 1LL; }
};

int main() {
  int n, m;
  std::cin >> n >> m;
  PermutationGroup group(n);
  // Read permutations and insert them to the group.
  std::vector<int> vec(n);
  for (; m; --m) {
    for (int& x : vec) {
      std::cin >> x;
      --x;  // Index starting at 0.
    }
    group.extend(Permutation(vec));
  }
  // Output the size of the group.
  std::cout << group.size();
  return 0;
}

Prerequisites: Basic concepts of abstract algebra, Group theory, Permutations

Introduction

The Schreier–Sims algorithm is an algorithm of computational group theory, named after the mathematicians Otto Schreier and Charles Sims. The algorithm solves in polynomial time many problems such as finding the order of a finite permutation group or checking whether a given permutation belongs to a given group. The Schreier–Sims algorithm was first introduced by Sims in 1970, based on Schreier's lemma. In 19811, Donald Knuth further improved the running time of the algorithm. Later, a faster randomized version of the algorithm was developed. Computer algebra systems (such as GAP and Magma) usually use a highly optimized Monte Carlo version of the algorithm2.

Notation

Following the convention of the computational group theory literature, this article writes group actions as right actions, which means that permutations are composed from left to right. All group actions in this article can be regarded as permutation actions, although some of the algorithms also hold for more general group actions. Accordingly, the set acted on by the group is by default \(X=\{1,2,\cdots,n\}\), and its elements are called points. The result of the permutation \(g\) acting on the point \(x\) is denoted \(x^g\); one also says that the permutation \(g\) moves the point \(x\) to the point \(x^g\). Finally, under the action of the permutation group \(G\), the orbit of the point \(x\) is denoted \(x^G=\{x^g:g\in G\}\), and its stabilizer is denoted \(G_x=\{g\in G:x^g=x\}\). The notion of a stabilizer can also be generalized to a set \(B\subseteq X\); its stabilizer is defined as \(G_B=\bigcap_{x\in B}G_x\).

Overview

The Schreier–Sims algorithm essentially tries to solve the following problem:

  • Given a set \(S\) of some permutations of a set \(X\) of size \(n\), how can the permutation group \(G=\langle S\rangle\) generated by \(S\) be stored efficiently in a computer, and how can a series of queries about this group be answered?

Obviously, such a group \(G\) can be very large, far larger than the set \(X\) and the generating set \(S\). For example, the symmetric group \(S_n=\langle(123\cdots n),(12)\rangle\) of degree \(n\) has size \(n!\), but it can be generated by only two permutations. Storing every element of the group is not realistic.

Similarly to how Gaussian elimination is used to build a linear basis of a vector space, the idea of the Schreier–Sims algorithm is to find a "basis" of the finite permutation group \(G\):

  1. The input of the algorithm is a generating set \(S\) of \(G\) containing several permutations;
  2. if the group \(G\) is nontrivial, one can always find a point \(\beta\) whose position changes under the action of \(G\), i.e. \(|\beta^G|>1\);
  3. find the orbit \(\Delta=\beta^{G}\) of the point \(\beta\), and for every point \(\delta\in\Delta\) of the orbit find a permutation \(t_{\delta}\) in the group \(G\) that moves the point \(\beta\) to \(\delta\);
  4. find a generating set \(S'\) of the stabilizer \(G_{\beta}\) of the point \(\beta\);
  5. call the algorithm recursively on \(G'=\langle S'\rangle\), until the trivial group \(\{e\}\) is obtained.

The reason this idea works is that the stabilizer \(G_{\beta}\) of the point \(\beta\) is a subgroup of \(G\), all of its (right) cosets form a partition of \(G\), and these cosets are in one-to-one correspondence with the orbit \(\beta^G\) of the point \(\beta\); the permutations \(t_{\delta}\) found in step 3 are exactly the representatives of these cosets. This set \(T\) of coset representatives is called a transversal of the stabilizer \(G_{\beta}\). In other words, every element \(g\) of the group \(G\) corresponds to a unique pair of elements \((h,t)\in G_\beta\times T\) with \(g=ht\). Therefore, as long as one can find a way to store the subgroup \(G_{\beta}\) and the corresponding transversal \(T\), the whole group \(G\) can be stored. But the problem of storing the subgroup \(G_{\beta}\) has already been solved as well: just call the algorithm recursively.

Of course, there are still many details of the implementation of the algorithm to sort out, and that is the main content of this article. But before that, we should first examine the result obtained after calling the algorithm, to see in what kind of structure the algorithm stores the group and what kinds of queries it can answer. For this, several concepts need to be clarified.

Stabilizer chain

Suppose that the algorithm is called on the group \(G=\langle S\rangle\) a total of \(k\) times, and that in the \(i\)-th call the input is the set of permutations \(S^{(i-1)}\), the point found is \(\beta_i\), the transversal obtained is \(T_i\), and the generating set of the stabilizer obtained is \(S^{(i)}\). If we write \(G^{(i)}=\langle S^{(i)}\rangle\), then the algorithm has actually obtained the chain of subgroups

\[ G=G^{(0)}> G^{(1)}>\cdots> G^{(k-1)}> G^{(k)}=\{e\}. \]

Moreover, every subgroup in the chain is a stabilizer

\[ G^{(i)}=G_{\beta_1,\cdots,\beta_i}. \]

Therefore, the Schreier–Sims algorithm can be regarded as computing exactly such a stabilizer chain.

Base and strong generating set

If a subset \(B\) of the set \(X\) satisfies \(G_B=\{e\}\), then \(B\) is called a base of the permutation group \(G\). Obviously, the above algorithm has obtained a base \(B=\{\beta_1,\cdots,\beta_k\}\). This means that the result of the action of a permutation \(g\in G\) on these points uniquely determines this permutation within the group \(G\). Moreover, the base output by the algorithm also satisfies the condition

\[ G^{(i-1)}=G_{\beta_1,\cdots,\beta_{i-1}}>G_{\beta_1,\cdots,\beta_{i-1},\beta_i}=G^{(i)}. \]

This says that every point of the base carries genuine information about the elements of the group. Such a base is called nonredundant. The algorithm always outputs a nonredundant base. The stabilizer chain corresponding to such a base is strictly decreasing.

At the same time, the union of the generating sets obtained by the algorithm

\[ \bar S=\bigcup_{i=0}^kS^{(i)} \]

is also a generating set of the group \(G\), and \(\langle\bar S\cap G^{(i)}\rangle = G^{(i)}\) holds. A generating set satisfying this condition is called a strong generating set of the group \(G\) relative to the base \(B\). Therefore, the Schreier–Sims algorithm can also be regarded as computing a base and strong generating set (BSGS) of the group \(G\). This formulation is equivalent to the stabilizer chain formulation, and this article does not distinguish between them.

Of course, the algorithm also obtains a series of orbits \(\Delta_i=\beta_{i}^{G^{(i-1)}}\) and the corresponding transversals \(T_i\). These orbits are called the basic orbits of the group \(G\). Whenever this article mentions the stabilizer chain or the base and strong generating set of a group \(G\), it is always assumed by default that the corresponding basic orbits and transversals have been computed as well.

Data structure

This article will provide a series of pseudocodes. In the pseudocode, the stabilizer chain (or base and strong generating set) of a group is stored in the data structure \(C\):

\[ C=(S,\Delta,T,C'). \]

The data members of this structure are, respectively, the generating set \(S\) of the current group, the basic orbit \(\Delta\), the corresponding transversal \(T\), and the stabilizer \(C'\) stored as a nested substructure. Of course, the stabilizer \(C'\) is also a structure of this kind. The whole group is actually stored in a layered structure, in which every layer describes one group of the stabilizer chain. The innermost layer is an empty structure representing \(G^{(k)}=\{e\}\).

In the pseudocode, the members of this data structure are accessed via \(C.generators\), \(C.orbit\), \(C.transversal\) and \(C.next\), respectively. The first element of the orbit, \(C.orbit[0]\), is by default the point \(\beta\) of the base, and the corresponding coset representative \(C.transversal[\beta]\) is by default the identity \(e\). Note that although array subscripts are used here to access the elements of the orbit and the transversal, they are not necessarily stored as arrays; this should be understood as meaning that they provide a way to access the first element of the orbit and to look up the corresponding coset representative given a point of the orbit. The concrete implementation details are discussed below.

Applications

After obtaining a base and strong generating set of a group, a series of queries about the group can be answered. Among them, the most basic ones, and the ones most frequently encountered in competitive programming, are querying the order of the group and querying whether a given permutation belongs to the given group.

Order of the group

If a base and strong generating set of the group \(G\) is known, then by Lagrange's theorem and the orbit–stabilizer theorem the order of the group \(G\) can be computed as

\[ |G|=\prod_{i=1}^k[G^{(i-1)}:G^{(i)}]=\prod_{i=1}^k[G^{(i-1)}:G^{(i-1)}_{\beta_i}]=\prod_{i=1}^k|T_i|. \]

So it suffices to multiply the sizes of all transversals \(T_i\) (or, equivalently, the lengths of the basic orbits \(\Delta_i\)) to obtain the order of the group \(G\).

Membership testing

Knowing a base and strong generating set of the group \(G\), one can also decide whether a given permutation \(h\) belongs to the group \(G\). This is called the membership testing problem.

This problem can be solved recursively. To decide whether \(h\in G^{(i-1)}\), first find the representative \(t\in T_i\) of the coset of \(G^{(i)}\) containing \(h\). If such a representative can be found, let \(h'=ht^{-1}\); then \(h=h't\), and \(h\in G^{(i-1)}\) is equivalent to \(h'\in G^{(i)}\), so the problem reduces to deciding whether \(h'\in G^{(i)}\). If no such \(t\) can be found, or the recursion has already reached \(G^{(k)}=\{e\}\) but \(h\neq e\), one can conclude that \(h\notin G\). In fact, this procedure not only decides whether \(h\in G\), but in the case \(h\in G\) it also expresses \(h\) as a product of a series of coset representatives \(t_k\cdots t_2t_1\), where \(t_i\in T_i\). For elements of the group \(G\), such a representation exists and is unique. This again proves that the formula above for the order of the group is correct.

Now we write this procedure as the following pseudocode:

\[ \begin{array}{l} \textbf{Algorithm }\textrm{MembershipTest}(C,h):\\ \textbf{Input. }\textrm{A stabilizer chain }C\textrm{ for a group }G\textrm{ and a permutation }h.\\ \textbf{Output. }\textrm{Whether }h\in G.\\ \textbf{Method.}\\ \begin{array}{ll} 1 & \textbf{while }C\textrm{ is not empty }\\ 2 & \qquad \beta \leftarrow C.orbit[0]\\ 3 & \qquad \delta \leftarrow \beta^h\\ 4 & \qquad \textbf{if }\delta\in C.orbit\textbf{ then}\\ 5 & \qquad \qquad t \leftarrow C.transversal[\delta]\\ 6 & \qquad \qquad h \leftarrow ht^{-1}\\ 7 & \qquad \textbf{else }\\ 8 & \qquad \qquad \textbf{return }\textrm{false}\\ 9 & \qquad \textbf{end if}\\ 10 & \qquad C \leftarrow C.next\\ 11 & \textbf{end while}\\ 12 & \textbf{return }h=e \end{array} \end{array} \]

As will be seen below, the membership testing problem is also an important component of the implementation of the Schreier–Sims algorithm discussed in this article.

Computing orbits, transversals and stabilizers

To implement the Schreier–Sims algorithm, the following subproblem must be solved first:3

  • Given a generating set \(S\) of the group \(G\) and a point \(\beta\), how to compute the orbit \(\beta^G\), the corresponding transversal \(T\), and a generating set of the stabilizer \(G_\beta\)?

This is the problem solved in this section.

Storing the orbit and the transversal

To obtain the orbit and the transversal, a direct search suffices. The pseudocode is as follows:

\[ \begin{array}{l} \textbf{Algorithm }\textrm{OrbitTransversal}(S,\beta):\\ \textbf{Input. }\textrm{A generating set }S\textrm{ for a group }G\textrm{ and a point }\beta.\\ \textbf{Output. }\textrm{The orbit }\Delta=\beta^G\textrm{ and the transversal }T.\\ \textbf{Method.}\\ \begin{array}{ll} 1 & \Delta \leftarrow [\beta]\\ 2 & T[\beta] \leftarrow e\\ 3 & \textbf{for }\delta\in\Delta\\ 4 & \qquad \textbf{for }s\in S\\ 5 & \qquad \qquad \gamma \leftarrow \delta^s\\ 6 & \qquad \qquad \textbf{if }\gamma\notin\Delta\textbf{ then}\\ 7 & \qquad \qquad \qquad\textrm{append }\gamma\textrm{ to }\Delta\\ 8 & \qquad \qquad \qquad T[\gamma] \leftarrow T[\delta]\cdot s\\ 9 & \qquad \qquad \textbf{end if}\\ 10 & \qquad \textbf{end for}\\ 11 & \textbf{end for}\\ 12 & \textbf{return }\Delta, T \end{array} \end{array} \]

In a concrete implementation, both breadth-first search and depth-first search can be used. The number of states visited by the search is \(|S||T|\); as long as the orbit and the transversal are stored sensibly, the time complexity is perfectly acceptable.

Since, in the context of permutation groups, an orbit is nothing but a set of at most \(n\) points, it can be stored as a Boolean array or an unordered set to perform lookups and insertions efficiently. Then both operations have time complexity \(O(1)\), and the total space usage is \(O(n)\). Of course, depending on the implementation of the transversal, the position of the first element may additionally need to be marked.

The question is which data structure to use to store the corresponding transversal \(T\).

Direct storage

The simplest method is, of course, to store every element \(t\) of the transversal \(T\) directly. A single permutation stored in one-line notation takes exactly \(n\) space, so the space complexity of storing such a transversal is \(O(|T|n)\). The advantage of this is that the time complexity of accessing a single coset representative is \(O(1)\); the price is that the time complexity of computing these coset representatives for the first time is \(O(|T|n)\).

Schreier tree

Another common approach is to implement a tree structure for storing the transversal. It is called a Schreier tree or a Schreier vector4. Its root is \(\beta\), and its vertices are the elements \(\delta\) of the orbit \(\Delta\). Every time a new vertex \(\gamma=\delta^s\) is obtained during the search, an edge is drawn from the old vertex \(\delta\) to the new vertex \(\gamma\), and the index (or a pointer) of the permutation \(s\) of the generating set \(S\) is recorded on the edge. Since the generating set is already stored, the extra space complexity of storing the transversal is \(O(|T|)\). When \(n\) is very large, this saves space effectively, and the complexity of the initial computation is \(O(|T|)\). The side effect, however, is that every time a coset representative is needed, the edges on the path from the vertex to the root must be traversed to recompute the coset representative, so the time complexity depends heavily on the depth of the Schreier tree. In the general case, the depth of the tree may reach the order of \(O(n)\).

In a concrete implementation, the time and space complexity of the algorithm must be weighed according to the actual situation. In the cases that may arise in competitive programming, \(n\) is usually not large, space is plentiful, and time complexity often becomes the bottleneck. As will be seen shortly, the most time-consuming step of the Schreier–Sims algorithm is exactly the one that needs to access coset representatives many times, so direct storage is often better. But in some application scenarios, \(n\) may be very large and storage space may be tighter, so it may be necessary to store the transversal as a Schreier tree. For this case, to avoid the Schreier tree becoming too deep, researchers have proposed many methods that rebuild a shallow Schreier tree when the depth of the tree becomes too large. Interested readers can consult the references at the end of the article.

In the pseudocode, this article does not distinguish between concrete implementations of the transversal, and only assumes that the data structure storing the transversal \(T\) implements the operations of accessing and modifying the corresponding coset representative \(T[\delta]\) given an orbit element \(\delta\in\Delta\).

Schreier's lemma

After obtaining the orbit \(\beta^G\) and the transversal \(T\), Schreier's lemma then provides a way to obtain a generating set of the stabilizer \(G_\beta\).

Schreier's lemma

Let the group \(G=\langle S\rangle\) have a subgroup \(H\le G\). Let \(T\) be a (right) transversal of the subgroup \(H\) with \(e\in T\)9, and denote by \(\overline g\) the representative \(t\in T\) of the coset containing \(g\in G\). Then the set

\[ U=\{ts(\overline{ts})^{-1}:t\in T,s\in S\} \]

is a generating set of the subgroup \(H\). Its elements are called Schreier generators of the subgroup \(H\).

Proof

First, by the definition of coset representatives, \(ts(\overline{ts})^{-1}\in H\) holds for all \(t\in T,s\in S\), hence \(\langle U\rangle\subseteq H\).

Conversely, for any \(h\in H\), since \(S\) is a generating set of \(G\ge H\), there necessarily exists a sequence \(s_i\in S\cup S^{-1}\) such that

\[ h=s_1s_2\cdots s_r \]

holds. Let \(t_1=e\) and recursively define \(t_{i+1}=\overline{t_is_i}\in T\); then we have

\[ \begin{aligned} h&=\left(t_1s_1t_2^{-1}\right)\left(t_2s_2t_3^{-1}\right)\cdots\left(t_rs_rt_{r+1}^{-1}\right)t_{r+1}. \end{aligned} \]

And for every \(i=1,2,\cdots,r\) we have \(t_is_it_{i+1}^{-1}=t_is_i(\overline{t_is_i})^{-1}\in U\cup U^{-1}\subseteq H\), hence \(t_{r+1}\in H\). But \(H\cap T=\{e\}\), so \(t_{r+1}=e\). This shows that any \(h\in H\) can be written as a product of a sequence of elements \(u_i=t_is_it_{i+1}^{-1}\in U\cup U^{-1}\), i.e. \(U\) generates \(H\).

Since the subgroup corresponding to the transversal \(T\) is exactly the stabilizer \(G_\beta\), after computing the transversal \(T\) and combining it with the generating set \(S\) of the group \(G\), one obtains a generating set of the stabilizer \(G_\beta\).

Algorithm

With a slight modification of the pseudocode above, a generating set of the corresponding stabilizer can be obtained at the same time as the orbit and the transversal are computed:

\[ \begin{array}{l} \textbf{Algorithm }\textrm{OrbitTransversalStabilizer}(S,\beta):\\ \textbf{Input. }\textrm{A generating set }S\textrm{ for a group }G\textrm{ and a point }\beta.\\ \textbf{Output. }\textrm{The orbit }\Delta=\beta^G\textrm{, the transversal }T\textrm{, and a}\\ \qquad\textrm{ generating set }S'\textrm{ for the stabilizer }G_\beta.\\ \textbf{Method.}\\ \begin{array}{ll} 1 & \Delta \leftarrow [\beta]\\ 2 & T[\beta] \leftarrow e\\ 3 & S' \leftarrow [e]\\ 4 & \textbf{for }\delta\in\Delta\\ 5 & \qquad \textbf{for }s\in S\\ 6 & \qquad \qquad \gamma \leftarrow \delta^s\\ 7 & \qquad \qquad \textbf{if }\gamma\notin\Delta\textbf{ then}\\ 8 & \qquad \qquad \qquad\textrm{append }\gamma\textrm{ to }\Delta\\ 9 & \qquad \qquad \qquad T[\gamma] \leftarrow T[\delta]\cdot s\\ 10 & \qquad \qquad \textbf{else} \\ 11 & \qquad \qquad \qquad \textrm{append }T[\delta]\cdot s\cdot T[\gamma]^{-1}\textrm{ to }S'\\ 12 & \qquad \qquad \textbf{end if}\\ 13 & \qquad \textbf{end for}\\ 14 & \textbf{end for}\\ 15 & \textbf{return }\Delta, T, S' \end{array} \end{array} \]

In the pseudocode, for each pair \((\delta,s)\), \(t_\delta st_{\delta^s}^{-1}\) is a new Schreier generator only when no new element of the orbit is produced; otherwise it is the identity \(e\). Therefore, the number of Schreier generators actually produced by the algorithm (not counting the initial identity) is at most

\[ |S||T|-(|T|-1) = (|S|-1)|T|+1 \]

In the general case this upper bound is tight5. But for the finite groups actually handled in practice, this bound is rather loose: most of the newly obtained Schreier generators are repetitions of previously obtained generators, or can be composed from previous generators.

Since the basic flow of the Schreier–Sims algorithm can be implemented as recursive calls of the above algorithm for computing orbits and stabilizers, at this point we have in fact already obtained a naive implementation of the Schreier–Sims algorithm. However, without sifting, the number of Schreier generators grows exponentially: applying \(|S^{(i)}|=O(|S^{(i-1)}||T_i|)\) repeatedly shows that the size of the generating set of the innermost stabilizer will reach \(O(|S||G|)\). This is obviously absurdly inefficient, since the innermost stabilizer is \(\{e\}\).

Sims's work provides a method to limit the growth rate of the number of Schreier generators, which guarantees that the size of the final strong generating set \(\bar S\) is \(O(n^2)\). In this way, a base and strong generating set can be computed in polynomial time.

Schreier–Sims algorithm

To solve the problem above, this section discusses an incremental implementation of the Schreier–Sims algorithm, which yields a strong generating set of size \(O(n^2)\).

Sifting

The core optimization of the Schreier–Sims algorithm over the naive algorithm above is very simple: it requires that, before any Schreier generator is added to the generating set of the stabilizer, it must first go through sifting. Sifting means first deciding whether the new Schreier generator already lies in the subgroup generated by the existing generators, and then adding only those generators that are not yet present. For this, it suffices to use the membership testing algorithm \(\textrm{MembershipTest}(C,h)\) from above.

But the precondition for doing so is that, for the Schreier generators already produced from the current group, the stabilizer chain (or base and strong generating set) of the group they generate has already been built. This means that every time a new Schreier generator is added to the generating set of the stabilizer, the inner stabilizer chain must be maintained dynamically, to be used for subsequent sifting. However, each insertion of a generator into the current layer may produce several Schreier generators and hence may update the inner structure several times; and each update of the inner structure may in turn trigger several updates of even deeper structures.

It seems that the exponential blow-up problem mentioned earlier still exists. In fact, it does not. Because sifting is done in advance, the structure of a layer is updated only when the generator to be added really enlarges that layer's structure. This shows that the number of updates of a single layer is actually equal to the number of times the group stored in that layer strictly grows. But the length of a chain of subgroups of a group of size \(|G|\) is at most \(\log_2|G|\), because Lagrange's theorem guarantees that each time the length of the subgroup chain increases by one, the size of the group at least doubles. This shows that a single layer is updated at most \(\log_2|G|\) times, so the size of the final strong generating set \(\bar S\) is \(O(|B|\log|G|)\).

This estimate can be improved further. Since the group \(G\) appearing here is known to be a subgroup of the symmetric group \(S_n\) of degree \(n\), the length of a subgroup chain of \(G\) cannot exceed the length of a subgroup chain of \(S_n\). It can be shown6 that the length of a strictly increasing chain of subgroups of \(S_n\) does not exceed \(3n/2\). This shows that the number of updates of a single layer is in fact \(O(n)\). Obviously, the size of the base does not exceed \(n\) either. Hence, the size of the final strong generating set \(\bar S\) is \(O(n^2)\).

The sifting method mentioned here was proposed by Sims and is also called the Sims filter. There is also a more sophisticated sifting method proposed by Jerrum, called the Jerrum filter, which guarantees that the size of the resulting strong generating set is \(O(n)\). Interested readers may study it on their own.

A small optimization of the sifting procedure is that the implementation of \(\textrm{MembershipTest}(C,h)\) does not output a Boolean value, but the final "siftee"7 \(h\) (i.e. lines \(8\) and \(12\) of the pseudocode are replaced by \(\textbf{return }h\)). If the "siftee" \(h\neq e\), the membership test has failed, and then the "siftee" \(h\) rather than the original \(h\) can be added directly to the current layer. This "siftee" \(h\) has already been stripped of the factors of several coset representatives, and hence moves fewer elements, which reduces the local amount of computation. This optimization does not change the analysis above.

Procedure

Now the concrete procedure of the Schreier–Sims algorithm can be described: first, initialize an empty structure \(C\) for storing the stabilizer chain of the group. Then add the generators of the generating set \(S\) to the structure \(C\) one by one; the final structure \(C\) is the stabilizer chain of the group \(\langle S\rangle\). The pseudocode is as follows:

\[ \begin{array}{l} \textbf{Algorithm }\textrm{SchreierSims}(S):\\ \textbf{Input. }\textrm{A generating set }S\textrm{ for a group }G.\\ \textbf{Output. }\textrm{The stabilizer chain }C\textrm{ for the group }G.\\ \textbf{Method.}\\ \begin{array}{ll} 1 & C \leftarrow []\\ 2 & \textbf{for }s\in S\\ 3 & \qquad C \leftarrow \textrm{Extend}(C,s)\\ 4 & \textbf{end for}\\ 5 & \textbf{return }C \end{array} \end{array} \]

The core of the algorithm is the step of adding a new generator \(s\) to the current \(C\), i.e. the subroutine \(\textrm{Extend}(C,s)\). As stated above, both before and after adding the permutation \(s\), \(C\) must be guaranteed to be a stabilizer chain. Thus, before adding the permutation \(s\), sifting can be done first. If \(s\) is found not to be in the existing group, the orbit, coset representatives and Schreier generators are computed incrementally. "Incrementally" here means that whatever has already been computed is not computed again. Only in this way can the correct complexity be guaranteed.

Consider how to turn \(\textrm{OrbitTransversalStabilizer}(S,\beta)\) into an incremental version. The state space searched by the algorithm is \(\Delta\times S\). After adding the new generator \(s\), the state space becomes \(\Delta'\times\left(S\cup\{s\}\right)\). The difference of the two is

\[ \left(\Delta\times\{s\}\right)\cup\left((\Delta'\setminus\Delta)\times \left(S\cup\{s\}\right)\right). \]

This means that when a new generator \(s\) is added, one first needs to compute the combinations of the new generator \(s\) with the old orbit and the corresponding coset representatives; if new orbit elements are obtained in this process, one then considers the combinations of these elements with all generators (new and old alike); the process is repeated until the orbit no longer grows.

The pseudocode for adding a permutation \(g\) to the structure \(C\) is as follows:

\[ \begin{array}{l} \textbf{Algorithm }\textrm{Extend}(C,g):\\ \textbf{Input. }\textrm{A stabilizer chain }C\textrm{ for the group generated by }S\textrm{ and a}\\ \qquad \textrm{permutation }g.\\ \textbf{Output. }\textrm{A stabilizer chain }C\textrm{ for the group generated by }S\cup\{g\}.\\ \textbf{Method.}\\ \begin{array}{ll} 1 & \textbf{if }\textrm{MembershipTest}(C,g)\textrm{ is passed}\textbf{ then}\\ 2 & \qquad \textbf{return }C\\ 3 & \textbf{end if}\\ 4 & \textbf{if }C\textrm{ is empty}\textbf{ then}\\ 5 & \qquad \beta \leftarrow \textrm{an element moved by }g\\ 6 & \qquad C.orbit[0] \leftarrow \beta \\ 7 & \qquad C.transversal[\beta] \leftarrow e\\ 8 & \textbf{end if}\\ 9 & \textrm{append }g\textrm{ to }C.generators\\ 10 & \Delta \leftarrow \textrm{a copy of }C.orbit Another implementation

The implementation above is already correct, but lines \(12\sim 19\) and \(23\sim 30\) are somewhat repetitive. Based on this, Knuth proposed in his paper a recursive implementation that is more concise. His approach is to regard the repeated part as an update of the transversal (and the orbit). Every update of the transversal has to be combined with all generators, and depending on whether a new coset representative is produced, one decides whether to call the subroutine itself recursively or the procedure for adding a generator. The pseudocode is as follows:

\[ \begin{array}{l} \textbf{Algorithm }\textrm{Extend}(C,g):\\ \textbf{Input. }\textrm{A stabilizer chain }C\textrm{ for the group generated by }S\textrm{ and a}\\ \qquad \textrm{permutation }g.\\ \textbf{Output. }\textrm{A stabilizer chain }C\textrm{ for the group generated by }S\cup\{g\}.\\ \textbf{Method.}\\ \begin{array}{ll} 1 & \textbf{if }\textrm{MembershipTest}(C,g)\textrm{ is passed}\textbf{ then}\\ 2 & \qquad \textbf{return }C\\ 3 & \textbf{end if}\\ 4 & \textbf{if }C\textrm{ is empty}\textbf{ then}\\ 5 & \qquad \beta \leftarrow \textrm{an element moved by }g\\ 6 & \qquad C.orbit[0] \leftarrow \beta \\ 7 & \qquad C.transversal[\beta] \leftarrow e\\ 8 & \textbf{end if}\\ 9 & \textrm{append }g\textrm{ to }C.generators\\ 10 & \textbf{for }t\in\textrm{a copy of }C.transversal\\ 11 & \qquad \textrm{ExtendTransversal}(C,t\cdot g)\\ 12 & \textbf{end for}\\ 13 & \textbf{return }C \end{array}\\ \\ \textbf{Sub-Algorithm }\textrm{ExtendTransversal}(C,t):\\ \textbf{Method.}\\ \begin{array}{ll} 1 & \beta \leftarrow C.orbit[0]\\ 2 & \gamma \leftarrow \beta^t\\ 3 & \textbf{if }\gamma\notin C.orbit\textbf{ then}\\ 4 & \qquad \textrm{append }\gamma\textrm{ to }C.orbit\\ 5 & \qquad C.transversal[\gamma] \leftarrow t\\ 6 & \qquad \textbf{for }s\in C.generators\\ 7 & \qquad \qquad \textrm{ExtendTransversal}(C,t\cdot s)\\ 8 & \qquad \textbf{end for}\\ 9 & \textbf{else}\\ 10 & \qquad s' \leftarrow t\cdot C.transversal[\gamma]^{-1}\\ 11 & \qquad C.next \leftarrow \textrm{Extend}(C.next,s')\\ 12 & \textbf{end if} \end{array} \end{array} \]

Comparing this pseudocode with that of the previous section shows that it is correct. Moreover, there is no difference in complexity between the two. Note that line \(10\) of \(\textrm{Extend}\) iterates over the transversal as it was when the loop was entered: the coset representatives newly produced during the loop have already been combined with all generators in the recursion of \(\textrm{ExtendTransversal}\) and should not be iterated over again.

Complexity

To analyze the complexity of the Schreier–Sims algorithm, some notation is needed. Let the length of the permutations be \(n\) and the size \(|S|\) of the generating set be \(m\). The length of the (nonredundant) base obtained is denoted \(|B|\). Moreover, in the final stabilizer \(G^{(i-1)}\) at the \(i\)-th layer from the outside in, the number of generators is denoted \(|S^{(i-1)}|\), and the size of the transversal (or the length of the orbit) is denoted \(|T_i|\). We now analyze the time complexity required by the incremental implementation of the Schreier–Sims algorithm above. The algorithm consists of two main parts: sifting, and the computation of orbits, transversals and Schreier generators.

Both the initially given generators and the Schreier generators obtained in the algorithm must be sifted, so the total number of executions of the sifting procedure is \(O(\sum_{i=1}^{|B|}|S^{(i-1)}||T_i|+|S|)\). A single sifting requires computing permutation products with \(O(|B|)\) coset representatives. Let the time to compute the product with a single coset representative be \(\tau\). When coset representatives are stored directly, \(\tau\in O(n)\); when they are stored in a Schreier tree, \(\tau\in O(n^2)\). The total time complexity of executing the sifting procedure is \(O(\tau|B|\sum_{i=1}^{|B|}|S^{(i-1)}||T_i|+\tau|B||S|)\).

As for the computation of orbits and related information, since the implementation is incremental, every pair \((\delta,s)\in\Delta_i\times S^{(i-1)}\) in the state space is computed at most once. For the computation of orbits and transversals, depending on the storage method, the time complexity of computing a single coset representative may be \(O(n)\) or \(O(1)\). But in any case, this does not exceed the complexity of computing the Schreier generators. With direct storage, it is \(O(n)\); with a Schreier tree, it is \(O(n^2)\). Comparing with the total time complexity of the sifting procedure, one finds that the time complexity of computing this information never exceeds the time complexity required for sifting. Therefore, the time complexity of the Schreier–Sims algorithm is exactly the \(O(\tau|B|\sum_{i=1}^{|B|}|S^{(i-1)}||T_i|+\tau|B||S|)\) obtained in the previous paragraph.

As for space complexity, the data structure finally obtained by the algorithm stores \(O(\sum_{i=1}^{|B|}|S^{(i-1)}|)\) generators and \(O(\sum_{i=1}^{|B|}|T_i|)\) coset representatives. With direct storage, both generators and coset representatives require \(O(n)\) space; with a Schreier tree, generators require \(O(n)\) space, while coset representatives require only \(O(1)\) space.

It was shown above that the length of a strictly increasing chain of subgroups of the symmetric group of degree \(n\) is \(O(n)\), which applies to both \(|B|\) and \(|S^{(i)}|\). Therefore, the Schreier–Sims algorithm implemented with direct storage of transversals has time complexity \(O(n^5+mn^2)\) and space complexity \(O(n^3)\). Of course, for the case \(\log|G|\in O(n)\), a better estimate is a time complexity8 of \(O(n^2\log^3|G|+mn\log|G|)\) and a space complexity of \(O(n^2\log|G|)\). For random generating sets, practical tests have found that the complexity of the algorithm is noticeably lower than \(\Theta(n^5)\), roughly \(\Theta(n^4)\).

Although, compared with direct storage, a Schreier tree introduces an extra factor of \(n\) into the time complexity, in the case where \(n\) is very large but the group itself is far smaller than the symmetric group of degree \(n\), its space complexity is \(O(n\log^2|G|)\), far smaller than the \(O(n^2\log|G|)\) of direct storage. But in competitive programming, it is hard to encounter such a situation where storing with a Schreier tree is better.

Reference implementation

Here we provide a reference implementation of the Schreier–Sims algorithm. Since \(n\) is small, the implementation directly fixes the base \(B=\{n,n-1,\cdots,1\}\) rather than choosing it through the algorithm. The advantage of doing this is that the permutations in the group at the \(k\)-th layer from the inside out (not counting the empty structure) only change the first \(k\) elements, which is convenient for subsequent computation. Another optimization in the code is that, when storing coset representatives, what is actually stored is their inverse permutations, which simplifies the operations on permutations.

Reference implementation 
#include <iostream>
#include <vector>

// A permutation.
class Permutation {
  std::vector<int> perm;

  void shrink() {
    int m = perm.size();
    for (; m && perm[m - 1] == m - 1; --m);
    perm.resize(m);
  }

 public:
  Permutation() {}

  Permutation(const std::vector<int>& vec) : perm(vec) { shrink(); }

  int operator[](int i) const { return i < perm.size() ? perm[i] : i; }

  bool empty() const { return perm.empty(); }

  // First LHS then RHS.
  Permutation operator*(const Permutation& rhs) const {
    Permutation res;
    res.perm.resize(std::max(perm.size(), rhs.perm.size()));
    for (int i = 0; i < res.perm.size(); ++i) {
      res.perm[i] = rhs[(*this)[i]];
    }
    res.shrink();
    return res;
  }

  // First LHS^{-1} then RHS.
  Permutation operator/(const Permutation& rhs) const {
    Permutation res;
    res.perm.resize(std::max(perm.size(), rhs.perm.size()));
    for (int i = 0; i < res.perm.size(); ++i) {
      res.perm[(*this)[i]] = rhs[i];
    }
    res.shrink();
    return res;
  }

  // Inverse.
  Permutation inv() const {
    Permutation res;
    res.perm.resize(perm.size());
    for (int i = 0; i < res.perm.size(); ++i) {
      res.perm[(*this)[i]] = i;
    }
    return res;
  }
};

// A stabilizer chain (a.k.a., BSGS) for a group.
class PermutationGroup {
  size_t n, k;
  std::vector<bool> orbit;               // Orbit of the n-th point.
  std::vector<Permutation> generators;   // Generators.
  std::vector<Permutation> transversal;  // Inverse of coset representatives.
  PermutationGroup* next;                // Stabilizer.

  // Sift a permutation.
  void sift(Permutation& h) const {
    if (!n) return;
    int i = h[n - 1];
    if (!orbit[i]) return;
    h = h * transversal[i];
    next->sift(h);
  }

  // Add one more element into the transversal.
  void extend_transversal(Permutation t) {
    int i = t[n - 1];
    if (!orbit[i]) {
      ++k;
      orbit[i] = true;
      transversal[i] = t.inv();
      for (const auto& s : generators) {
        extend_transversal(t * s);
      }
    } else {
      next->extend(t * transversal[i]);
    }
  }

 public:
  PermutationGroup(int n)
      : n(n), k(1), orbit(n), transversal(n), next(nullptr) {
    if (!n) return;
    // Initialize the current layer.
    orbit[n - 1] = true;
    next = new PermutationGroup(n - 1);
  }

  // Destructor.
  ~PermutationGroup() {
    if (next) delete next;
  }

  // Add one more permutation into the group.
  void extend(Permutation g) {
    sift(g);
    if (g.empty()) return;
    generators.emplace_back(g);
    for (int i = 0; i < n; ++i) {
      if (orbit[i]) {
        extend_transversal(transversal[i] / g);
      }
    }
  }

  // Check whether a permutation belongs to the group.
  bool membership_test(Permutation h) const {
    sift(h);
    return h.empty();
  }

  // Return the size of the group.
  long long size() const { return n ? next->size() * k : 1LL; }
};

int main() {
  int n, m;
  std::cin >> n >> m;
  PermutationGroup group(n);
  // Read permutations and insert them to the group.
  std::vector<int> vec(n);
  for (; m; --m) {
    for (int& x : vec) {
      std::cin >> x;
      --x;  // Index starting at 0.
    }
    group.extend(Permutation(vec));
  }
  // Output the size of the group.
  std::cout << group.size();
  return 0;
}
