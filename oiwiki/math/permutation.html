Permutacije i razmještaji (arrangements) pojmovi su koji se vrlo često pojavljuju u raznim vrstama zadataka.

Ovaj članak ne govori o broju varijacija

Tema ovog članka potpune su permutacije, a ne broj varijacija (razmještaja) iz kombinatorike. Za sadržaj o broju varijacija pogledajte Kombinatorika.

Dogovor

Ako nije drukčije rečeno, u ovom se članku uvijek govori o konačnim skupovima.

Definicija

Bijekcija (tj. obostrano jednoznačno preslikavanje) \(\sigma\) skupa \(X\) na samog sebe naziva se permutacija (permutation) skupa \(X\). Ako na skupu \(X\) postoji i relacija totalnog uređaja, tada se njegova permutacija često naziva i (potpuni) razmještaj (arrangement). Taj totalni uređaj naziva se prirodnim poretkom na skupu.

„Permutacija” i „razmještaj”

U kineskom kontekstu „permutacija” (置换) obično označava promjenu redoslijeda elemenata, a „razmještaj” (排列) obično označava slaganje elemenata u niz. Kad među elementima postoji prirodan poredak, ta su dva pojma jedno te isto: „razmještaj” se može shvatiti kao rezultat „permutacije”, a u odnosu na prirodan poredak elemenata redoslijed elemenata u „razmještaju” određuje „permutaciju”. Budući da se u ovom članku pri uporabi riječi „razmještaj” uvijek pretpostavlja da na skupu postoji prirodan poredak, ta se dva pojma u ovom članku ne razlikuju posebno.

Naravno, i elementi bez prirodnog poretka mogu se „razmještati”. Takvi se „razmještaji” često pojavljuju u zadacima kombinatornog prebrojavanja. To je izvan opsega ovog članka.

Neka je veličina skupa \(X\) jednaka \(n\); tada je broj svih permutacija skupa \(X\) jednak \(n!\). Posebno, \(0!=1\), tj. na praznom skupu postoji točno jedna permutacija – prazna permutacija.

Oznake

Permutacije se bave odnosima pridruživanja među elementima, a ne time što su elementi konkretno. Zato se, kad govorimo o skupu veličine \(n\), obično pretpostavlja da je riječ o skupu \(\{1,2,\cdots,n\}\); kad je na skupu potreban prirodan poredak, obično se pretpostavlja prirodan poredak na prirodnim brojevima.

Načini zapisa

Permutacije se mogu zapisati na više načina. Ovdje ćemo različite načine zapisa permutacija raspraviti na primjeru sljedeće permutacije.

\[ \sigma(1) = 2,\ \sigma(2) = 6,\ \sigma(3) = 5,\ \sigma(4) = 4,\ \sigma(5) = 3,\ \sigma(6) = 1. \]

Dvoredni zapis

Permutacija skupa \(X=\{x_1,x_2,\cdots,x_n\}\) može se zapisati kao

\[ \sigma=\begin{pmatrix}x_1&x_2&\cdots&x_n\\ x_{p_1}&x_{p_2}&\cdots&x_{p_n} \end{pmatrix}. \]

To znači da permutacija \(\sigma\) element \(x_i\) preslikava u \(x_{p_i}\). Ovdje, naravno, mora vrijediti \(X=\{x_{p_1},x_{p_2},\cdots,x_{p_n}\}\). U dvorednom zapisu permutacije redoslijed pojavljivanja elemenata u prvom retku nije važan; važno je pridruživanje između dvaju redaka.

Primjerice, prethodni se primjer u dvorednom zapisu može napisati kao

\[ \sigma= \begin{pmatrix} 1 & 2 & 3 & 4 & 5 & 6 \\ 2 & 6 & 5 & 4 & 3 & 1 \end{pmatrix}, \]

a može se, naravno, napisati i kao

\[ \sigma= \begin{pmatrix} 6 & 5 & 4 & 3 & 2 & 1 \\ 1 & 3 & 4 & 5 & 6 & 2 \end{pmatrix}. \]

Jednoredni zapis

Često na skupu \(X\) postoji prirodan poredak. Ako se u dvorednom zapisu prvi redak podrazumijevano piše u prirodnom poretku i izostavi, permutacija se može zapisati kao

\[ \sigma=\sigma(1)\sigma(2)\cdots\sigma(n). \]

To više nalikuje pojmu razmještaja u prirodnom jeziku. Zato se ta uređena n-torka ponekad naziva i „razmještaj”.

Prethodni se primjer u jednorednom zapisu može napisati kao

\[ \sigma=265431. \]

Takav se jednoredni zapis često koristi za uspoređivanje različitih razmještaja.

Zapis ciklusima

Postoji još kompaktniji način zapisa permutacija, koji se naziva zapisom permutacije ciklusima. On permutaciju prikazuje kao produkt niza disjunktnih ciklusa. U nastavku opisujemo korake kojima se zadana permutacija zapisuje ciklusima.

Za zadanu permutaciju \(\sigma\) zapis ciklusima dobiva se sljedećim koracima:

  1. Ako u \(X\) još postoji element koji nije zapisan, napišemo lijevu zagradu i zapišemo bilo koji takav element;
  2. Kad je posljednji zapisani element \(x\),
    • ako je \(\sigma(x)\) već prije zapisan, napišemo desnu zagradu i vratimo se na korak 1;
    • ako \(\sigma(x)\) još nije zapisan, zapišemo \(\sigma(x)\) i nastavimo s korakom 2;
  3. Ponavljamo gornje korake dok svi elementi skupa \(X\) ne budu zapisani.

Unutar svakog para zagrada nalazi se jedan ciklus. Broj elemenata u zagradama naziva se duljinom pripadnog ciklusa. U praksi se ciklusi duljine jedan često izostavljaju.

Prethodni se primjer zapisom ciklusima može napisati kao

\[ \sigma=(126)(35)(4)=(126)(35). \]

U identičnom preslikavanju svi ciklusi imaju duljinu jedan; ono se često zapisuje kao \((1)\), a ne izostavlja se u cijelosti.

Kompozicija

Kompozicija permutacija kompozicija je preslikavanja. Kompozicija permutacija često se naziva i množenjem permutacija.

Za zadane dvije permutacije

\[ \sigma=\begin{pmatrix}x_1&x_2&\cdots&x_n\\ x_{p_1}&x_{p_2}&\cdots&x_{p_n}\end{pmatrix},\ \pi=\begin{pmatrix}x_{p_1}&x_{p_2}&\cdots&x_{p_n}\\ x_{q_1}&x_{q_2}&\cdots&x_{q_n}\end{pmatrix}, \]

njihov je produkt \(\pi\circ\sigma\) jednak

\[ \pi\circ\sigma=\begin{pmatrix}x_1&x_2&\cdots&x_n\\ x_{q_1}&x_{q_2}&\cdots&x_{q_n}\end{pmatrix}. \]

Jednostavno rečeno, najprije se primijeni preslikavanje \(\sigma\), a zatim preslikavanje \(\pi\). Uočite da se u gornjem dvorednom zapisu redoslijed drugog retka unutarnjeg preslikavanja \(\sigma\) podudara s redoslijedom prvog retka vanjskog preslikavanja \(\pi\).

Budući da su permutacije \(\sigma\) i \(\pi\) u biti dva preslikavanja, vrijedi \((\pi\circ\sigma)(x)=\pi(\sigma(x))\). Redoslijed računanja kompozicije permutacija ide zdesna nalijevo. Množenje permutacija nije komutativno, pa računanje u pogrešnom redoslijedu može dovesti do pogrešnog rezultata.

Uzastopna višestruka kompozicija iste permutacije naziva se potencijom permutacije i može se ubrzano izračunati brzim potenciranjem.

Inverzna permutacija

Budući da je permutacija bijekcija, permutacija uvijek ima pripadnu inverznu permutaciju.

Za zadanu permutaciju

\[ \sigma=\begin{pmatrix}x_1&x_2&\cdots&x_n\\ x_{p_1}&x_{p_2}&\cdots&x_{p_n}\end{pmatrix}, \]

njezina je inverzna permutacija

\[ \sigma^{-1}=\begin{pmatrix}x_{p_1}&x_{p_2}&\cdots&x_{p_n}\\x_1&x_2&\cdots&x_n\end{pmatrix}. \]

U zapisu ciklusima dovoljno je invertirati svaki ciklus da bi se dobio inverz izvorne permutacije; a da bi se invertirao ciklus, dovoljno je obrnuti redoslijed zapisivanja elemenata. Primjerice, zapis ciklusima inverzne permutacije permutacije \(\sigma\) iz gornjeg primjera jest

\[ \sigma^{-1} = (621)(53) = (162)(35). \]

Za zadani razmještaj brojeva \(1\sim n\), on i niz sastavljen od položaja svakog elementa u tom razmještaju međusobno su inverzni razmještaji.

Ciklusi

Ciklus (cycle) sam je po sebi posebna permutacija. Svojstvo je ciklusa da se iz bilo koje točke \(x\) ciklusa uzastopnom primjenom permutacije \(\sigma\) može doći do bilo koje točke \(y\) ciklusa. Ciklus duljine \(k\) naziva se i \(k\)‑ciklus (\(k\)-cycle). Uzastopnom primjenom \(k\)‑ciklusa \(k\) puta dobiva se identično preslikavanje, tj. svaki se element vraća na svoj početni položaj.

Zapis permutacije ciklusima može se shvatiti kao zapisivanje permutacije u obliku produkta tih posebnih permutacija (tj. ciklusa), pa se zapis permutacije ciklusima može smatrati i rastavom permutacije na cikluse (cycle decomposition). Za svaku je permutaciju način rastava na produkt ciklusa, ne gledajući redoslijed, jedinstven. Ciklusi se mogu shvatiti kao osnovne jedinice od kojih se grade permutacije.

Rastav permutacije na cikluse ima jasno geometrijsko značenje. Ako svaki uređeni par \((x,\sigma(x))\) permutacije skupa \(X\) shvatimo kao brid usmjerenog grafa s vrhovima iz \(X\), ti su ciklusi upravo ciklusi (zatvoreni putovi) u tom grafu. Ako se permutacija \(\sigma\) može rastaviti na \(m\) ciklusa, to znači da pripadni usmjereni graf ima ukupno \(m\) ciklusa (uključujući petlje). Ti su ciklusi, naravno, međusobno disjunktni.

Fiksne točke

Elementi \(1\)‑ciklusa fiksne su točke (fixed point) permutacije. Za permutaciju \(\sigma\) skupa \(X\) skup fiksnih točaka permutacije \(\sigma\) obično se označava \(X^\sigma\), tj. \(X^\sigma=\{x\in X:\sigma(x)=x\}\).

Transpozicije

\(2\)‑ciklus naziva se i transpozicija (transposition). Drugim riječima, transpozicija je permutacija koja zamjenjuje položaje samo jednog para elemenata. Njezin je zapis ciklusima \((x_ix_j)\), što znači da zamjenjuje položaje elemenata \(x_i\) i \(x_j\).

Svaka se permutacija može zapisati kao produkt niza transpozicija. To je isto što i reći da se razmještaj u bilo kojem redoslijedu nizom operacija zamjene dvaju elemenata može vratiti u zadani uzlazni redoslijed. Upravo to rade algoritmi sortiranja temeljeni na zamjenama.

Štoviše, ispravnost algoritma bubble sort zapravo pokazuje da se svaka permutacija može zapisati kao produkt niza susjednih transpozicija. Susjedna transpozicija (adjacent transposition) ovdje je transpozicija koja zamjenjuje samo susjedne elemente.

Svojstva

U primjenama često treba obratiti pozornost na svojstva pojedine permutacije.

Parnost

Način rastava ciklusa na transpozicije nije jedinstven. Primjerice,

\[ (123)=(13)(12)=(12)(23)=(12)(13)(12)(13). \]

Međutim, kad se permutacija rastavlja na niz transpozicija, parnost broja potrebnih transpozicija je fiksna. Parnost broja transpozicija u rastavu permutacije naziva se i parnošću (parity) permutacije.

Permutacija koja se može rastaviti na produkt parnog broja transpozicija naziva se parnom permutacijom, a permutacija koja se može rastaviti na produkt neparnog broja transpozicija naziva se neparnom permutacijom. Za \(n\ge2\) među permutacijama \(n\) elemenata broj je neparnih i parnih permutacija jednak.

Predznak

Prema parnosti permutacije može se definirati i predznak (sign) permutacije, koji se označava \(\operatorname{sgn}\sigma\). Predznak parne permutacije definira se kao \(+1\), a predznak neparne permutacije kao \(-1\).

Predznak produkta permutacija jednak je produktu njihovih predznaka, tj.

\[ \operatorname{sgn}(\pi\circ\sigma)=\operatorname{sgn} \pi\cdot\operatorname{sgn}\sigma. \]

Drugim riječima, kompozicija dviju permutacija iste parnosti parna je permutacija, a kompozicija dviju permutacija različite parnosti neparna je permutacija. Taj je zaključak očit iz perspektive rastava na transpozicije.

Posebno, jedna transpozicija nužno mijenja parnost permutacije. To upravo objašnjava zašto je, iako način rastava na transpozicije nije jedinstven, parnost broja potrebnih transpozicija određena.

Predznak permutacije pojavljuje se u Leibnizovoj formuli za determinantu.

Red permutacije

Red (order) permutacije najmanji je pozitivan cijeli broj \(a\) koji zadovoljava sljedeći uvjet: nakon \(a\) ponavljanja te permutacije svi se elementi vraćaju na svoje početne položaje. Dakle

\[ \operatorname{ord}\sigma=\min\{a\in\mathbf N_+:\sigma^a=(1)\}. \]

Na konačnom skupu red je svake permutacije konačan. To znači da se, krenuvši od početnog redoslijeda, uzastopnim miješanjem zadanog niza prema fiksnom obrascu razmještaj u konačnom vremenu uvijek može vratiti u početno stanje.

Tip permutacije

Rastavimo li permutaciju \(n\) elemenata na cikluse, tip (cycle type) permutacije multiskup je duljina ciklusa u tom rastavu. Duljine tih ciklusa čine jednu particiju broja \(n\) na cijele brojeve. Ako u dobivenom rastavu ima ukupno \(\alpha_k\) ciklusa duljine \(k\), tip permutacije često se zapisuje kao

\[ 1^{\alpha_1}2^{\alpha_2}\cdots n^{\alpha_n}, \]

a ti eksponenti zadovoljavaju \(\sum_{k=1}^nk\alpha_k=n\).

Za zadani tip permutacije broj različitih permutacija jednak je

\[ \frac{n!}{1^{\alpha_1}2^{\alpha_2}\cdots n^{\alpha_n}\alpha_1!\alpha_2!\cdots\alpha_n!}. \]
Analiza

To je zato što se svaki razmještaj brojeva \(1\sim n\) prema tipu permutacije može podijeliti na odgovarajući rastav na cikluse. No redoslijed ciklusa jednake duljine ne utječe na permutaciju, pa ukupan broj treba podijeliti s \(\prod_k\alpha_k!\). Osim toga, unutar jednog ciklusa riječ je zapravo o kružnom razmještaju, pa ni izbor početne točke ne utječe na permutaciju, zbog čega treba podijeliti s \(\prod_kk^{\alpha_k}\). Tako se dobiva gornja formula.

Ako je zadan samo broj ciklusa \(k\) na koje se permutacija rastavlja, broj različitih permutacija jednak je Stirlingovu broju prve vrste \(\begin{bmatrix}n\\ k\end{bmatrix}\). Broj različitih tipova jednak je broju particija \(p_n\) broja \(n\).

Iz tipa permutacije lako se određuju svojstva poput reda i parnosti permutacije.

Budući da je red \(k\)‑ciklusa jednak \(k\), a različiti su ciklusi međusobno disjunktni, red permutacije \(\sigma\) jednak je

\[ \operatorname{lcm}\{k:\alpha_k>0\}. \]

Slično, budući da je parnost \(k\)‑ciklusa suprotna parnosti broja \(k\), parnost permutacije \(\sigma\) jednaka je parnosti broja

\[ \sum_k(k-1)\alpha_k=\sum_{k}k\alpha_k-\sum_{k}\alpha_k=n-c(\sigma) \]

Ovdje je \(c(\sigma)\) broj ciklusa (uključujući \(1\)‑cikluse, tj. fiksne točke).

Tip permutacije ima važnu ulogu u Pólyinu prebrojavanju.

O razmještajima

Ako skup \(X\) sam ima prirodan poredak, permutacija \(\sigma\) često se naziva razmještajem i zapisuje jednorednim zapisom

\[ \sigma(1)\sigma(2)\cdots\sigma(n) \]

Pazite da to ne pomiješate s ciklusima.

Broj inverzija

Ako u razmještaju neki veći broj stoji ispred nekog manjeg broja, kažemo da ta dva broja čine inverziju (inversion) ili obrnuti poredak. Uspoređivanje se ovdje provodi prema prirodnom poretku.

Ukupan broj inverzija koje se pojavljuju u razmještaju naziva se brojem inverzija tog razmještaja. Broj inverzija razmještaja najmanji je broj susjednih transpozicija potreban da se razmještaj vrati u uzlazno sortirani niz. Stoga se parnost broja inverzija razmještaja podudara s parnošću pripadne permutacije. To može poslužiti kao ekvivalentna definicija parnosti permutacije.

Za računanje broja inverzija može se upotrijebiti merge sort ili Fenwick tree; vremenska je složenost obaju \(O(n\log n)\). Objašnjenja obaju algoritama nalaze se u odgovarajućim poglavljima; ovdje dajemo njihove referentne implementacije.

Referentna implementacija 
#include <iostream>
#include <vector>

// Merge sort and count inversions.
long long merge_sort(std::vector<int>& nums, int b, int e) {
  // Return 0 when length <= 1.
  if (e - b <= 1) return 0;
  long long res = 0;
  int m = (b + e) / 2;
  // Merge_sort two halves.
  res += merge_sort(nums, b, m);
  res += merge_sort(nums, m, e);
  // Temporary vector to store sorted array.
  std::vector<int> tmp(e - b);
  int i = b, j = m, k = 0;
  while (i < m && j < e) {
    if (nums[j] < nums[i]) {
      tmp[k] = nums[j++];
      // In this case, all elements in [i,m) are larger than element j.
      res += m - i;
    } else {
      tmp[k] = nums[i++];
    }
    ++k;
  }
  // Deal with remaining elements.
  for (; i < m; ++i, ++k) {
    tmp[k] = nums[i];
  }
  for (; j < e; ++j, ++k) {
    tmp[k] = nums[j];
  }
  // Copy back to original vector.
  for (i = b, k = 0; i < e; ++i, ++k) {
    nums[i] = tmp[k];
  }
  return res;
}

int main() {
  int n;
  std::cin >> n;
  std::vector<int> nums(n);
  for (int& num : nums) {
    std::cin >> num;
  }
  std::cout << merge_sort(nums, 0, n);
  return 0;
}

#include <algorithm>
#include <iostream>
#include <unordered_map>
#include <vector>

// A simple BIT implementation.
class BIT {
  int n;
  std::vector<int> su;

 public:
  BIT(int n) : n(n), su(n + 1) {}

  // Add v to the x-th number.
  void add(int x, int v) {
    for (; x <= n; x += x & (-x)) {
      su[x] += v;
    }
  }

  // Get the cumulative sum till the x-th number.
  int query(int x) {
    int res = 0;
    for (; x; x &= x - 1) {
      res += su[x];
    }
    return res;
  }
};

// Count inversions.
long long solve(const std::vector<int>& nums) {
  // Discretization.
  std::vector<int> sorted(nums);
  std::sort(sorted.begin(), sorted.end());
  sorted.erase(std::unique(sorted.begin(), sorted.end()), sorted.end());
  std::unordered_map<int, int> ids;
  int m = sorted.size();
  for (int i = 0; i < m; ++i) {
    // Reverse the order.
    // Now a smaller id means a larger element.
    ids[sorted[i]] = m - i;
  }
  // Main part.
  BIT bit(m);
  long long res = 0;
  for (int num : nums) {
    int id = ids[num];
    // Get inversion pair (i,j) with j the current element.
    // Namely, count the number of elements larger than
    //     the current one but located before it.
    res += bit.query(id - 1);
    // Insert the current element to the BIT.
    bit.add(id, 1);
  }
  return res;
}

int main() {
  int n;
  std::cin >> n;
  std::vector<int> nums(n);
  for (int& num : nums) {
    std::cin >> num;
  }
  std::cout << solve(nums);
  return 0;
}

Poredak

Razmještaji se mogu uspoređivati. Budući da je svaki jednoredni zapis string, poredak razmještaja leksikografski je poredak tih stringova.

U zaglavlju <algorithm> standardne biblioteke C++-a mogu se upotrijebiti prev_permutation i next_permutation za pronalaženje prethodnog odnosno sljedećeg razmještaja trenutačnog razmještaja u leksikografskom poretku.

Rang

Ako razmještaje \(n\) elemenata ispišemo u leksikografskom poretku od najmanjeg do najvećeg, položaj nekog razmještaja u tom nizu njegov je rang. On uspostavlja bijekciju između razmještaja i pozitivnih cijelih brojeva i često se koristi za sažimanje stanja u zadacima vezanima za razmještaje.

U kineskoj natjecateljskoj zajednici taj se rang često naziva „Cantorovim razvojem” razmještaja, ali taj naziv nije sasvim precizan. Preciznije rečeno, Cantorov razvoj (Cantor expansion) ranga razmještaja odgovara Lehmerovu kodu (Lehmer code) tog razmještaja.

O „Cantorovu razvoju”

Kao što ime sugerira, Cantorov razvoj metoda je razvoja prirodnog broja u niz. Može se shvatiti kao posebna vrsta brojevnog sustava, koja se naziva i faktorijelni brojevni sustav. U tom sustavu različita mjesta imaju različite baze (radix). Primjerice, dekadski broj \(463_{10}\) u faktorijelnom se sustavu može zapisati kao

\[ 463_{10}=341010_{!}. \]

To znači sljedeće

\[ 463=3\times 5!+4\times 4!+1\times 3!+0\times 2!+1\times 1!+0\times 0!. \]

Cantor je proučavao ovakve sustave s miješanim bazama, pa se zapis prirodnog broja znamenkama u tom sustavu često naziva i Cantorovim razvojem prirodnog broja.

Primjer

Čitatelji koji nisu upoznati s načinom računanja ranga mogu kroz ovaj jednostavan primjer shvatiti osnovnu ideju algoritma u nastavku.

Izračunati rang razmještaja \(\sigma=452631\) znači izračunati koliko je razmještaja leksikografski manjih od \(\sigma\) i dodati jedan. Ideja je ovdje slična DP-u po znamenkama: raspravljamo mjesto po mjestu.

  • Izbor \(1\). mjesta mora biti manji nego u \(\sigma\), pa može biti samo iz \(\{1,2,3\}\), a preostalih \(5\) mjesta može se birati proizvoljno; ukupno \(3\times 5!\) mogućih razmještaja;
  • Ako i na \(1\). mjestu izaberemo \(4\), izbor \(2\). mjesta mora biti manji nego u \(\sigma\), pa može biti samo iz \(\{1,2,3\}\) (ovdje je \(4\) već izabrano), a preostala \(4\) mjesta mogu se birati proizvoljno; ukupno \(3\times 4!\) mogućih razmještaja;
  • Slično, kad se izbor prvih \(2\) mjesta podudara sa \(\sigma\), izbor \(3\). mjesta mora biti manji nego u \(\sigma\), pa može biti samo iz \(\{1\}\), a preostala \(3\) mjesta mogu se birati proizvoljno; ukupno \(1\times 3!\) mogućih razmještaja;
  • Kad se izbor prvih \(3\) mjesta podudara sa \(\sigma\), izbor \(4\). mjesta mora biti manji nego u \(\sigma\), pa može biti samo iz \(\{1,3\}\), a preostala \(2\) mjesta mogu se birati proizvoljno; ukupno \(2\times 2!\) mogućih razmještaja;
  • Kad se izbor prvih \(4\) mjesta podudara sa \(\sigma\), izbor \(5\). mjesta mora biti manji nego u \(\sigma\), pa može biti samo iz \(\{1\}\), a preostalo \(1\) mjesto može se birati proizvoljno; ukupno \(1\times 1!\) mogućih razmještaja;
  • Kad se izbor prvih \(5\) mjesta podudara sa \(\sigma\), izborom \(6\). mjesta ne može se dobiti razmještaj manji od \(\sigma\), pa je ukupno \(0\times 0!\) mogućih razmještaja.

Stoga je rang razmještaja \(\sigma\) jednak

\[ 1+3\times 5!+3\times 4!+1\times 3!+2\times 2!+1\times 1!+0\times 0!=444. \]

Za različite razmještaje ključno je odrediti koeficijente ispred faktorijela. Zapravo, ti su koeficijenti upravo broj elemenata koji stoje iza tog mjesta, a manji su od elementa na tom mjestu.

Iz primjera vidimo da se algoritam za računanje ranga zadanog razmještaja može podijeliti u dva koraka:

  1. Zadani razmještaj duljine \(n\) pretvorimo u njegov Lehmerov kod, tj. niz \(L_\sigma\) duljine \(n\) čiji je \(i\)-ti član

    \[ L_\sigma(i)=\#\{j>i:\sigma(j)<\sigma(i)\}, \]

    dakle broj elemenata u razmještaju koji stoje iza \(i\)-tog mjesta, a manji su od \(\sigma(i)\). On je jednak rangu zadanog elementa među još neiskorištenim elementima (umanjenom za jedan).

  2. Lehmerov kod shvatimo kao Cantorov razvoj prirodnog broja, izračunamo taj prirodni broj i dodamo jedan. Drugim riječima, konačni je rang jednak

    \[ \operatorname{rank}\sigma=1+L_\sigma(1)(n-1)!+L_\sigma(2)(n-2)!+\cdots+L_\sigma(n)0!. \]

Za rješavanje obratnog problema, tj. određivanje razmještaja iz zadanog ranga, dovoljno je gornji postupak provesti obrnutim redom. Zbroj brojeva u Lehmerovu kodu dobivenom u tom postupku upravo je broj inverzija razmještaja.

Pri programskoj implementaciji ključno je moći brzo izračunati „rang zadanog elementa među još neiskorištenim elementima” (pri računanju ranga) i „element zadanog ranga među još neiskorištenim elementima” (pri računanju razmještaja); sve se to može održavati strukturama podataka poput Fenwick treeja ili segment treeja. Vremenska složenost obiju operacija (izravne i obratne) jest \(O(n\log n)\).

Referentna implementacija 
#include <iostream>
#include <vector>

// A simple BIT implementation.
class BIT {
  int n;
  std::vector<int> su;

 public:
  BIT(int n) : n(n), su(n + 1) {}

  // Add v to the x-th number.
  void add(int x, int v) {
    for (; x <= n; x += x & (-x)) {
      su[x] += v;
    }
  }

  // Get the cumulative sum till the x-th number.
  int query(int x) {
    int res = 0;
    for (; x; x &= x - 1) {
      res += su[x];
    }
    return res;
  }
};

// Get the rank of a permutation of 1~n.
long long find_rank(const std::vector<int>& nums) {
  int n = nums.size();
  BIT bit(n);
  long long fac = 1;
  long long res = 0;
  // Reverse iteration.
  for (int i = n - 1; i >= 0; --i) {
    // Count the number of elements smaller than the current one.
    res += bit.query(nums[i] - 1) * fac;
    // Insert the current element into the BIT.
    bit.add(nums[i], 1);
    // Update the factorial.
    fac *= n - i;
  }
  return res + 1;
}

int main() {
  int n;
  std::cin >> n;
  std::vector<int> nums(n);
  for (int& num : nums) {
    std::cin >> num;
  }
  std::cout << find_rank(nums);
  return 0;
}

#include <cmath>
#include <iostream>
#include <vector>

// A simple BIT implementation.
class BIT {
  int n;
  std::vector<int> su;

 public:
  BIT(int n) : n(n), su(n + 1) {}

  // Fill the BIT with one.
  void fill() {
    for (int x = 1; x <= n; ++x) {
      su[x] += x & (-x);
    }
  }

  // Add v to the x-th number.
  void add(int x, int v) {
    for (; x <= n; x += x & (-x)) {
      su[x] += v;
    }
  }

  // Get the k-th smallest element.
  int find_kth(int k) {
    int ps = 0, x = 0;
    for (int i = log2(n); i >= 0; --i) {
      x += 1 << i;
      if (x >= n || ps + su[x] >= k) {
        x -= 1 << i;
      } else {
        ps += su[x];
      }
    }
    return x + 1;
  }
};

// Find the k-th permutation of 1~n.
std::vector<int> find_permutation(int n, long long k) {
  --k;
  // Expand rank to Lehmer code.
  std::vector<int> lehmer(n);
  for (int i = 1; i <= n; ++i) {
    lehmer[n - i] = k % i;
    k /= i;
  }
  BIT bit(n);
  // Set all values in BIT to one.
  bit.fill();
  std::vector<int> res(n);
  for (int i = 0; i < n; ++i) {
    // Find the lehmer[i]-th smallest unused element.
    res[i] = bit.find_kth(lehmer[i] + 1);
    // Remove it from the BIT.
    bit.add(res[i], -1);
  }
  return res;
}

int main() {
  int n;
  long long k;
  std::cin >> n >> k;
  auto res = find_permutation(n, k);
  for (int num : res) {
    std::cout << num << ' ';
  }
  return 0;
}

Permutations and arrangements are concepts that appear very frequently in all kinds of problems.

This article is not about the number of arrangements

The topic of this article is full permutations, not the number of arrangements (k-permutations) from combinatorics. For material on the number of arrangements, see Combinatorics.

Convention

Unless stated otherwise, this article always deals with finite sets.

Definition

A bijection (i.e. one-to-one correspondence) \(\sigma\) from a set \(X\) to itself is called a permutation of \(X\). If the set \(X\) also carries a total order, then a permutation of it is often also called a (full) arrangement. This total order is called the natural order on the set.

“Permutation” and “arrangement”

In the Chinese context, "permutation" (置换) usually refers to changing the order of elements, while "arrangement" (排列) usually refers to lining elements up in a row. When there is a natural order among the elements, these two concepts are one and the same: an "arrangement" can be viewed as the result of a "permutation", and relative to the natural order of the elements, the order of the elements in the "arrangement" specifies the "permutation". Since whenever this article uses the word "arrangement" it always assumes that a natural order exists on the set, this article does not specifically distinguish between the two concepts.

Of course, elements without a natural order can also be "arranged". Such "arrangements" often appear in combinatorial counting problems. That is beyond the scope of this article.

Let the size of the set \(X\) be \(n\); then the number of all permutations of \(X\) is \(n!\). In particular, \(0!=1\), i.e. there is exactly one permutation on the empty set, namely the empty permutation.

Notation

Permutations are about the correspondence between elements and do not care what the elements actually are. Hence, when discussing a set of size \(n\), it is usually assumed that the set in question is \(\{1,2,\cdots,n\}\); when a natural order on the set is needed, the natural order on the natural numbers is usually assumed.

Notations

There are several ways to write a permutation. Here we discuss the different notations for permutations using the following permutation as an example.

\[ \sigma(1) = 2,\ \sigma(2) = 6,\ \sigma(3) = 5,\ \sigma(4) = 4,\ \sigma(5) = 3,\ \sigma(6) = 1. \]

Two-line notation

A permutation of the set \(X=\{x_1,x_2,\cdots,x_n\}\) can be written as

\[ \sigma=\begin{pmatrix}x_1&x_2&\cdots&x_n\\ x_{p_1}&x_{p_2}&\cdots&x_{p_n} \end{pmatrix}. \]

It means that the permutation \(\sigma\) maps the element \(x_i\) to \(x_{p_i}\). Here, of course, we need \(X=\{x_{p_1},x_{p_2},\cdots,x_{p_n}\}\). In the two-line notation of a permutation, the order in which the elements appear in the first row does not matter; what matters is the correspondence between the two rows.

For example, the earlier example can be written in two-line notation as

\[ \sigma= \begin{pmatrix} 1 & 2 & 3 & 4 & 5 & 6 \\ 2 & 6 & 5 & 4 & 3 & 1 \end{pmatrix}, \]

and of course it can also be written as

\[ \sigma= \begin{pmatrix} 6 & 5 & 4 & 3 & 2 & 1 \\ 1 & 3 & 4 & 5 & 6 & 2 \end{pmatrix}. \]

One-line notation

Very often the set \(X\) has a natural order. If in the two-line notation the first row is written in the natural order by default and omitted, then the permutation can be written as

\[ \sigma=\sigma(1)\sigma(2)\cdots\sigma(n). \]

This is more like the concept of an arrangement in natural language. So this ordered tuple is sometimes also called an "arrangement".

The earlier example can be written in one-line notation as

\[ \sigma=265431. \]

This one-line notation is often used to compare different arrangements.

Cycle notation

There is an even more compact way to express a permutation, called the cycle notation of the permutation. It expresses the permutation as a product of a series of disjoint cycles. Below we describe the steps for writing a given permutation in cycle notation.

Given a permutation \(\sigma\), it can be written in cycle notation by the following steps:

  1. If there is still an element of \(X\) that has not been written down, write a left parenthesis and write down any such element;
  2. When the last element written down is \(x\),
    • if \(\sigma(x)\) has already been written down earlier, write a right parenthesis and return to step 1;
    • if \(\sigma(x)\) has not been written down yet, write down \(\sigma(x)\) and continue with step 2;
  3. Repeat the above steps until all elements of \(X\) have been written down.

Inside each pair of parentheses is one cycle. The number of elements inside the parentheses is called the length of the corresponding cycle. In practice, cycles of length one are often omitted.

The earlier example can be written in cycle notation as

\[ \sigma=(126)(35)(4)=(126)(35). \]

In the identity transformation all cycles have length one; it is often written as \((1)\) rather than omitted entirely.

Composition

The composition of permutations is the composition of maps. The composition of permutations is also often called the multiplication of permutations.

Given two permutations

\[ \sigma=\begin{pmatrix}x_1&x_2&\cdots&x_n\\ x_{p_1}&x_{p_2}&\cdots&x_{p_n}\end{pmatrix},\ \pi=\begin{pmatrix}x_{p_1}&x_{p_2}&\cdots&x_{p_n}\\ x_{q_1}&x_{q_2}&\cdots&x_{q_n}\end{pmatrix}, \]

their product \(\pi\circ\sigma\) is

\[ \pi\circ\sigma=\begin{pmatrix}x_1&x_2&\cdots&x_n\\ x_{q_1}&x_{q_2}&\cdots&x_{q_n}\end{pmatrix}. \]

Simply put, first apply the map \(\sigma\), then apply the map \(\pi\). Note that in the two-line notation above, the order of the second row of the inner map \(\sigma\) agrees with the order of the first row of the outer map \(\pi\).

Since the permutations \(\sigma\) and \(\pi\) are essentially two maps, \((\pi\circ\sigma)(x)=\pi(\sigma(x))\). The order of evaluation of the composition of permutations is from right to left. Multiplication of permutations is not commutative, so computing in the wrong order may lead to a wrong result.

Repeated composition of the same permutation is called a power of the permutation, and it can be computed quickly using binary exponentiation.

Inverse permutation

Since a permutation is a bijection, a permutation always has a corresponding inverse permutation.

Given the permutation

\[ \sigma=\begin{pmatrix}x_1&x_2&\cdots&x_n\\ x_{p_1}&x_{p_2}&\cdots&x_{p_n}\end{pmatrix}, \]

its inverse permutation is

\[ \sigma^{-1}=\begin{pmatrix}x_{p_1}&x_{p_2}&\cdots&x_{p_n}\\x_1&x_2&\cdots&x_n\end{pmatrix}. \]

In cycle notation, it suffices to invert each cycle to obtain the inverse of the original permutation; and to invert a cycle, it suffices to reverse the order in which the elements are written. For example, the cycle notation of the inverse of the permutation \(\sigma\) from the example above is

\[ \sigma^{-1} = (621)(53) = (162)(35). \]

Given an arrangement of \(1\sim n\), it and the sequence formed by the position of each element in that arrangement are inverse arrangements of each other.

Cycles

A cycle is itself a special permutation. The characteristic of a cycle is that, starting from any point \(x\) of the cycle, any point \(y\) of the cycle can be reached by repeatedly applying the permutation \(\sigma\). A cycle of length \(k\) is also called a \(k\)‑cycle (\(k\)-cycle). Applying a \(k\)‑cycle \(k\) times yields the identity transformation, i.e. every element returns to its original position.

The cycle notation of a permutation can be viewed as writing the permutation as a product of these special permutations (i.e. cycles), so the cycle notation of a permutation can also be viewed as the cycle decomposition of the permutation. For every permutation, the way it decomposes into a product of cycles is unique up to order. Cycles can be regarded as the basic building blocks of permutations.

The cycle decomposition of a permutation has a clear geometric meaning. If every ordered pair \((x,\sigma(x))\) of a permutation of the set \(X\) is regarded as an edge of a directed graph with vertex set \(X\), then these cycles are exactly the cycles (closed walks) of this graph. If the permutation \(\sigma\) can be decomposed into \(m\) cycles, this means that the corresponding directed graph has a total of \(m\) cycles (including self-loops). These cycles are naturally pairwise disjoint.

Fixed points

The elements of \(1\)‑cycles are the fixed points of the permutation. For a permutation \(\sigma\) of the set \(X\), the set of fixed points of \(\sigma\) is usually denoted \(X^\sigma\), i.e. \(X^\sigma=\{x\in X:\sigma(x)=x\}\).

Transpositions

A \(2\)‑cycle is also called a transposition. In other words, a transposition is a permutation that swaps the positions of only one pair of elements. Its cycle notation is \((x_ix_j)\), meaning that it swaps the positions of \(x_i\) and \(x_j\).

Every permutation can be written as a product of a series of transpositions. This amounts to saying that an arrangement in any order can be restored to a specified ascending order by a series of operations that swap two elements. This is exactly what swap-based sorting algorithms do.

Furthermore, the correctness of the bubble sort algorithm in fact shows that every permutation can be written as a product of a series of adjacent transpositions. Here an adjacent transposition is a transposition that swaps only adjacent elements.

Properties

In applications, one often needs to pay attention to the properties of a single permutation.

Parity

The way a cycle is decomposed into transpositions is not unique. For example,

\[ (123)=(13)(12)=(12)(23)=(12)(13)(12)(13). \]

However, when a permutation is decomposed into a series of transpositions, the parity of the number of transpositions needed is fixed. The parity of the number of transpositions in the decomposition of a permutation is also called the parity of the permutation.

A permutation that can be decomposed into a product of an even number of transpositions is called an even permutation, and one that can be decomposed into a product of an odd number of transpositions is called an odd permutation. For \(n\ge2\), the numbers of odd and even permutations of \(n\) elements are equal.

Sign

Based on the parity of a permutation, one can also define the sign of the permutation, denoted \(\operatorname{sgn}\sigma\). The sign of an even permutation is defined as \(+1\), and the sign of an odd permutation as \(-1\).

The sign of a product of permutations equals the product of their signs, i.e.

\[ \operatorname{sgn}(\pi\circ\sigma)=\operatorname{sgn} \pi\cdot\operatorname{sgn}\sigma. \]

In other words, the composition of two permutations of the same parity is an even permutation, and the composition of two permutations of different parity is an odd permutation. This conclusion is obvious from the point of view of the decomposition into transpositions.

In particular, a single transposition necessarily changes the parity of a permutation. This is exactly why, although the decomposition into transpositions is not unique, the parity of the number of transpositions needed is determined.

The sign of a permutation appears in the Leibniz formula for the determinant.

Order of a permutation

The order of a permutation is the smallest positive integer \(a\) satisfying the following condition: after repeating the permutation \(a\) times, all elements return to their original positions. That is,

\[ \operatorname{ord}\sigma=\min\{a\in\mathbf N_+:\sigma^a=(1)\}. \]

On a finite set, the order of every permutation is finite. This means that, starting from the initial order, as long as a given sequence is repeatedly shuffled according to a fixed pattern, the arrangement can always be restored to its original state in finite time.

Cycle type of a permutation

Decompose a permutation of \(n\) elements into cycles; the cycle type of the permutation is the multiset of the cycle lengths in the decomposition. These cycle lengths form an integer partition of \(n\). If the resulting decomposition contains \(\alpha_k\) cycles of length \(k\) in total, the cycle type of the permutation is often written as

\[ 1^{\alpha_1}2^{\alpha_2}\cdots n^{\alpha_n}, \]

and these exponents satisfy \(\sum_{k=1}^nk\alpha_k=n\).

Given the cycle type of a permutation, the number of distinct permutations is

\[ \frac{n!}{1^{\alpha_1}2^{\alpha_2}\cdots n^{\alpha_n}\alpha_1!\alpha_2!\cdots\alpha_n!}. \]
Analysis

This is because any arrangement of \(1\sim n\) can be split according to the cycle type into the corresponding cycle decomposition. However, the order among cycles of the same length does not affect the permutation, so the total must be divided by \(\prod_k\alpha_k!\). Moreover, within a single cycle we actually have a circular arrangement, and the choice of the starting point does not affect the permutation either, so we must divide by \(\prod_kk^{\alpha_k}\). This yields the formula above.

If only the number \(k\) of cycles into which the permutation decomposes is given, the number of distinct permutations is the Stirling number of the first kind \(\begin{bmatrix}n\\ k\end{bmatrix}\). The number of distinct cycle types is the partition number \(p_n\) of \(n\).

From the cycle type of a permutation, properties such as the order and parity of the permutation can be conveniently determined.

Since the order of a \(k\)‑cycle is \(k\) and distinct cycles are pairwise disjoint, the order of the permutation \(\sigma\) is

\[ \operatorname{lcm}\{k:\alpha_k>0\}. \]

Similarly, since the parity of a \(k\)‑cycle is opposite to the parity of \(k\), the parity of the permutation \(\sigma\) is the parity of

\[ \sum_k(k-1)\alpha_k=\sum_{k}k\alpha_k-\sum_{k}\alpha_k=n-c(\sigma) \]

Here, \(c(\sigma)\) is the number of cycles (including \(1\)‑cycles, i.e. fixed points).

The cycle type of a permutation plays an important role in Pólya counting.

Arrangements

If the set \(X\) itself has a natural order, the permutation \(\sigma\) is often called an arrangement and written in one-line notation

\[ \sigma(1)\sigma(2)\cdots\sigma(n) \]

Be careful not to confuse this with cycles.

Inversion number

In an arrangement, if some larger number comes before some smaller number, we say that these two numbers form an inversion. The comparison here is made under the natural order.

The total number of inversions appearing in an arrangement is called the inversion number of the arrangement. The inversion number of an arrangement is the minimum number of adjacent swaps needed to restore it to the sorted ascending sequence. Hence the parity of the inversion number of an arrangement coincides with the parity of the corresponding permutation. This can serve as an equivalent definition of the parity of a permutation.

To compute the inversion number, one can use merge sort or a Fenwick tree; the time complexity of both is \(O(n\log n)\). Explanations of both algorithms can be found in the corresponding chapters; here we give their reference implementations.

Reference implementation 
#include <iostream>
#include <vector>

// Merge sort and count inversions.
long long merge_sort(std::vector<int>& nums, int b, int e) {
  // Return 0 when length <= 1.
  if (e - b <= 1) return 0;
  long long res = 0;
  int m = (b + e) / 2;
  // Merge_sort two halves.
  res += merge_sort(nums, b, m);
  res += merge_sort(nums, m, e);
  // Temporary vector to store sorted array.
  std::vector<int> tmp(e - b);
  int i = b, j = m, k = 0;
  while (i < m && j < e) {
    if (nums[j] < nums[i]) {
      tmp[k] = nums[j++];
      // In this case, all elements in [i,m) are larger than element j.
      res += m - i;
    } else {
      tmp[k] = nums[i++];
    }
    ++k;
  }
  // Deal with remaining elements.
  for (; i < m; ++i, ++k) {
    tmp[k] = nums[i];
  }
  for (; j < e; ++j, ++k) {
    tmp[k] = nums[j];
  }
  // Copy back to original vector.
  for (i = b, k = 0; i < e; ++i, ++k) {
    nums[i] = tmp[k];
  }
  return res;
}

int main() {
  int n;
  std::cin >> n;
  std::vector<int> nums(n);
  for (int& num : nums) {
    std::cin >> num;
  }
  std::cout << merge_sort(nums, 0, n);
  return 0;
}

#include <algorithm>
#include <iostream>
#include <unordered_map>
#include <vector>

// A simple BIT implementation.
class BIT {
  int n;
  std::vector<int> su;

 public:
  BIT(int n) : n(n), su(n + 1) {}

  // Add v to the x-th number.
  void add(int x, int v) {
    for (; x <= n; x += x & (-x)) {
      su[x] += v;
    }
  }

  // Get the cumulative sum till the x-th number.
  int query(int x) {
    int res = 0;
    for (; x; x &= x - 1) {
      res += su[x];
    }
    return res;
  }
};

// Count inversions.
long long solve(const std::vector<int>& nums) {
  // Discretization.
  std::vector<int> sorted(nums);
  std::sort(sorted.begin(), sorted.end());
  sorted.erase(std::unique(sorted.begin(), sorted.end()), sorted.end());
  std::unordered_map<int, int> ids;
  int m = sorted.size();
  for (int i = 0; i < m; ++i) {
    // Reverse the order.
    // Now a smaller id means a larger element.
    ids[sorted[i]] = m - i;
  }
  // Main part.
  BIT bit(m);
  long long res = 0;
  for (int num : nums) {
    int id = ids[num];
    // Get inversion pair (i,j) with j the current element.
    // Namely, count the number of elements larger than
    //     the current one but located before it.
    res += bit.query(id - 1);
    // Insert the current element to the BIT.
    bit.add(id, 1);
  }
  return res;
}

int main() {
  int n;
  std::cin >> n;
  std::vector<int> nums(n);
  for (int& num : nums) {
    std::cin >> num;
  }
  std::cout << solve(nums);
  return 0;
}

Order

Arrangements can be compared. Since each one-line notation is a string, the order of arrangements is the lexicographic order on these strings.

In the C++ standard library header <algorithm>, prev_permutation and next_permutation can be used to find the previous and next arrangement of the current one in lexicographic order, respectively.

Rank

If the arrangements of \(n\) elements are listed in lexicographic order from smallest to largest, the position of a given arrangement in this sequence is the rank of that arrangement. It establishes a one-to-one correspondence between arrangements and positive integers, and is often used for state compression in arrangement-related problems.

In the Chinese competitive programming community, this rank is often called the "Cantor expansion" of the arrangement, but this name is not quite standard. More rigorously, the Cantor expansion of the rank of an arrangement corresponds to the Lehmer code of that arrangement.

About the “Cantor expansion”

As the name suggests, the Cantor expansion is a method of expanding a natural number into a sequence. It can be viewed as a special numeral system, also called the factorial number system. In this numeral system, different positions have different radices. For example, the decimal number \(463_{10}\) can be written in the factorial number system as

\[ 463_{10}=341010_{!}. \]

It means the following

\[ 463=3\times 5!+4\times 4!+1\times 3!+0\times 2!+1\times 1!+0\times 0!. \]

Cantor studied such mixed-radix numeral systems, so the digit representation of a natural number in this system is often also called the Cantor expansion of the natural number.

Example

Readers unfamiliar with how to compute the rank can use this simple example to understand the basic idea of the algorithm below.

To compute the rank of the arrangement \(\sigma=452631\) is to compute how many arrangements are lexicographically smaller than \(\sigma\), and add one. The idea here is similar to digit DP: we discuss position by position.

  • The choice for position \(1\) must be smaller than in \(\sigma\), so it can only come from \(\{1,2,3\}\), and the remaining \(5\) positions can be chosen arbitrarily; \(3\times 5!\) possible arrangements in total;
  • If position \(1\) is also chosen as \(4\), then the choice for position \(2\) must be smaller than in \(\sigma\), so it can only come from \(\{1,2,3\}\) (here \(4\) has already been chosen), and the remaining \(4\) positions can be chosen arbitrarily; \(3\times 4!\) possible arrangements in total;
  • Similarly, when the choices for the first \(2\) positions agree with \(\sigma\), the choice for position \(3\) must be smaller than in \(\sigma\), so it can only come from \(\{1\}\), and the remaining \(3\) positions can be chosen arbitrarily; \(1\times 3!\) possible arrangements in total;
  • When the choices for the first \(3\) positions agree with \(\sigma\), the choice for position \(4\) must be smaller than in \(\sigma\), so it can only come from \(\{1,3\}\), and the remaining \(2\) positions can be chosen arbitrarily; \(2\times 2!\) possible arrangements in total;
  • When the choices for the first \(4\) positions agree with \(\sigma\), the choice for position \(5\) must be smaller than in \(\sigma\), so it can only come from \(\{1\}\), and the remaining \(1\) position can be chosen arbitrarily; \(1\times 1!\) possible arrangements in total;
  • When the choices for the first \(5\) positions agree with \(\sigma\), the choice for position \(6\) cannot yield an arrangement smaller than \(\sigma\), so there are \(0\times 0!\) possible arrangements in total.

Therefore, the rank of the arrangement \(\sigma\) is

\[ 1+3\times 5!+3\times 4!+1\times 3!+2\times 2!+1\times 1!+0\times 0!=444. \]

For different arrangements, the key point is to determine the coefficients in front of the factorials. In fact, these coefficients are exactly the number of elements that come after that position but are smaller than the element at that position.

From the example we see that the algorithm for computing the rank of a given arrangement can be divided into two steps:

  1. Convert the given arrangement of length \(n\) into its Lehmer code, i.e. the sequence \(L_\sigma\) of length \(n\) whose \(i\)-th entry is

    \[ L_\sigma(i)=\#\{j>i:\sigma(j)<\sigma(i)\}, \]

    that is, the number of elements in the arrangement that come after position \(i\) but are smaller than \(\sigma(i)\). It equals the rank of the given element among the not-yet-used elements (minus one).

  2. Regard the Lehmer code as the Cantor expansion of a natural number, compute the original natural number, and add one. In other words, the final rank equals

    \[ \operatorname{rank}\sigma=1+L_\sigma(1)(n-1)!+L_\sigma(2)(n-2)!+\cdots+L_\sigma(n)0!. \]

To solve the inverse problem, i.e. to find the corresponding arrangement given its rank, simply run the above process in reverse. The sum of the numbers in the Lehmer code obtained in this process is exactly the inversion number of the arrangement.

In the programming implementation, the key is to be able to quickly compute "the rank of a given element among the not-yet-used elements" (when computing the rank) and "the element of a given rank among the not-yet-used elements" (when computing the arrangement); all of these can be maintained with data structures such as a Fenwick tree or a segment tree. The time complexity of both the forward and the inverse operation is \(O(n\log n)\).

Reference implementation 
#include <iostream>
#include <vector>

// A simple BIT implementation.
class BIT {
  int n;
  std::vector<int> su;

 public:
  BIT(int n) : n(n), su(n + 1) {}

  // Add v to the x-th number.
  void add(int x, int v) {
    for (; x <= n; x += x & (-x)) {
      su[x] += v;
    }
  }

  // Get the cumulative sum till the x-th number.
  int query(int x) {
    int res = 0;
    for (; x; x &= x - 1) {
      res += su[x];
    }
    return res;
  }
};

// Get the rank of a permutation of 1~n.
long long find_rank(const std::vector<int>& nums) {
  int n = nums.size();
  BIT bit(n);
  long long fac = 1;
  long long res = 0;
  // Reverse iteration.
  for (int i = n - 1; i >= 0; --i) {
    // Count the number of elements smaller than the current one.
    res += bit.query(nums[i] - 1) * fac;
    // Insert the current element into the BIT.
    bit.add(nums[i], 1);
    // Update the factorial.
    fac *= n - i;
  }
  return res + 1;
}

int main() {
  int n;
  std::cin >> n;
  std::vector<int> nums(n);
  for (int& num : nums) {
    std::cin >> num;
  }
  std::cout << find_rank(nums);
  return 0;
}

#include <cmath>
#include <iostream>
#include <vector>

// A simple BIT implementation.
class BIT {
  int n;
  std::vector<int> su;

 public:
  BIT(int n) : n(n), su(n + 1) {}

  // Fill the BIT with one.
  void fill() {
    for (int x = 1; x <= n; ++x) {
      su[x] += x & (-x);
    }
  }

  // Add v to the x-th number.
  void add(int x, int v) {
    for (; x <= n; x += x & (-x)) {
      su[x] += v;
    }
  }

  // Get the k-th smallest element.
  int find_kth(int k) {
    int ps = 0, x = 0;
    for (int i = log2(n); i >= 0; --i) {
      x += 1 << i;
      if (x >= n || ps + su[x] >= k) {
        x -= 1 << i;
      } else {
        ps += su[x];
      }
    }
    return x + 1;
  }
};

// Find the k-th permutation of 1~n.
std::vector<int> find_permutation(int n, long long k) {
  --k;
  // Expand rank to Lehmer code.
  std::vector<int> lehmer(n);
  for (int i = 1; i <= n; ++i) {
    lehmer[n - i] = k % i;
    k /= i;
  }
  BIT bit(n);
  // Set all values in BIT to one.
  bit.fill();
  std::vector<int> res(n);
  for (int i = 0; i < n; ++i) {
    // Find the lehmer[i]-th smallest unused element.
    res[i] = bit.find_kth(lehmer[i] + 1);
    // Remove it from the BIT.
    bit.add(res[i], -1);
  }
  return res;
}

int main() {
  int n;
  long long k;
  std::cin >> n >> k;
  auto res = find_permutation(n, k);
  for (int num : res) {
    std::cout << num << ' ';
  }
  return 0;
}
