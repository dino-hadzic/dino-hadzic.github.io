U kombinatorici je prebrojavanje grafova (graph enumeration) grana koja proučava probleme prebrojavanja grafova sa zadanim svojstvima. Funkcije izvodnice, Pólyin teorem prebrojavanja, simbolička metoda i OEIS najvažniji su matematički alati za rješavanje takvih problema. Problemi prebrojavanja grafova dijele se na dvije velike skupine: označene (labeled) i neoznačene (unlabeled). U većini slučajeva1 označena je inačica problema jednostavnija od odgovarajuće neoznačene, pa ćemo najprije promotriti prebrojavanje označenih struktura.

Označeni povezani grafovi

Primjer zadatka „POJ 1737” Connected Graph

Primjer zadatka „POJ 1737” Connected Graph

Sažetak zadatka: odredite broj označenih povezanih grafova s \(n\) vrhova (\(n \leq 50\)).

Ovakvi se problemi prvi put pojavljuju u seriji zadataka „男人八题” („Osam zadataka za muškarce”) Lou Tianchenga (楼教主). Neka je \(g_n\) broj označenih grafova s \(n\) vrhova, a \(c_n\) traženi niz. Graf s \(n\) vrhova ima najviše \(\binom{n}{2}\) bridova, svaki brid ima dva stanja (postoji ili ne postoji) i ta su stanja međusobno neovisna, pa je \(g_n = 2^{\binom{n}{2}}\). Fiksiramo jedan vrh i prebrojavamo po veličini komponente povezanosti u kojoj se nalazi: od preostalih \(n-1\) vrhova treba odabrati \(i-1\) vrhova koji s njim čine jednu komponentu povezanosti. Vrhovi izvan te komponente mogu biti povezani proizvoljno, pa vrijedi sljedeća rekurzivna relacija:

\[ \begin{align} \sum_{i=1}^{n} \binom{n-1}{i-1} c_i g_{n-i} &= g_n \\ c_n &= g_n - \sum_{i=1}^{n-1} \binom{n-1}{i-1} c_i g_{n-i} \end{align} \]

Prebacivanjem članova dobivamo rekurzivnu formulu za niz \(c_n\) složenosti \(O(n^2)\), čime se ovaj zadatak može riješiti.

Primjer zadatka „集训队作业 2013” 城市规划 (Zadaća reprezentacije 2013 – Urbanističko planiranje)

Sažetak zadatka: odredite broj označenih povezanih grafova s \(n\) vrhova (\(n \leq 130000\)).

Za probleme s nizovima i većim ograničenjima obično trebamo konstruirati funkcije izvodnice tih nizova kako bismo mogli primijeniti učinkovite algoritme za polinome.

Metoda 1: FFT metodom podijeli pa vladaj

Gornju rekurziju možemo promatrati kao oblik samokonvolucije, pa je možemo računati FFT-om metodom podijeli pa vladaj (divide-and-conquer FFT), složenosti \(O(n\log^2n)\).

Metoda 2: inverz polinoma

Raspišimo binomni koeficijent u gornjoj rekurziji i preuredimo je:

\[ \begin{align} \sum_{i=1}^{n} \binom{n-1}{i-1} c_i g_{n-i} &= g_n \\ \sum_{i=1}^{n} \frac{c_i}{(i-1)!} \frac{g_{n-i}}{(n-i)!} &= \frac{g_n}{(n-1)!} \end{align} \]

Konstruiramo polinome:

\[ \begin{align} C(x) &= \sum_{n=1} \frac{c_n}{(n-1)!} x^n \\ G(x) &= \sum_{n=0} \frac{g_n}{n!} x^n \\ H(x) &= \sum_{n=1} \frac{g_n}{(n-1)!} x^n \end{align} \]

Uvrštavanjem u gornju jednakost dobivamo \(CG = H\); dovoljno je izračunati inverz polinoma i zatim konvolucijom dobiti \(C(x)\).

Metoda 3: eksponencijal polinoma

Drugi je pristup iskoristiti kombinatorno značenje eksponencijala polinoma kod EGF-a. Neka su \(C(x)\) i \(G(x)\) redom EGF-ovi nizova označenih povezanih grafova i jednostavnih grafova; tada među njima vrijedi sljedeća veza:

\[ \begin{align} \exp(C(x)) &= G(x) \\ C(x) &= \ln(G(x)) \end{align} \]

Dovoljno je logaritmom polinoma izračunati \(C(x)\).

Problem povezanih grafova riješen je u prethodnim primjerima; razmotrimo Eulerove grafove. Uočimo da se sve gore navedene metode za prebrojavanje povezanih grafova mogu poopćiti na označene povezane grafove s proizvoljnim svojstvom. Primjerice, ako u rekurziji za povezane grafove \(g_n\) umjesto broja svih grafova označava broj grafova u kojima su stupnjevi svih vrhova parni, dobiveni \(c_n\) upravo je broj Eulerovih grafova.

Rekurzivni postupak iz POJ 1737 zapakirajmo u funkciju „povezivanja” (prijelaza na povezane strukture):

void ln(Int C[], Int G[]) {
  for (int i = 1; i <= n; ++i) {
    C[i] = G[i];
    for (int j = 1; j <= i - 1; ++j)
      C[i] -= binom[i - 1][j - 1] * C[j] * G[i - j];
  }
}

Prva se dva pitanja tada rješavaju bez poteškoća:

for (int i = 1; i <= n; ++i) G[i] = pow(2, binom[i][2]);
ln(C, G);
for (int i = 1; i <= n; ++i) G[i] = pow(2, binom[i - 1][2]);
ln(E, G);

Uočimo da je ovaj rekurzivni postupak povezivanja zapravo ekvivalentan računanju logaritma polinoma na odgovarajućem EGF-u. Analogno možemo napisati i funkciju obrnutog povezivanja, koja je ekvivalentna računanju eksponencijala polinoma na EGF-u.

void exp(Int G[], Int C[]) {
  for (int i = 1; i <= n; ++i) {
    G[i] = C[i];
    for (int j = 1; j <= i - 1; ++j)
      G[i] += binom[i - 1][j - 1] * C[j] * G[i - j];
  }
}

Razmotrimo sada prebrojavanje označenih bipartitnih grafova.

Neka \(b_n\) označava broj bipartitnih grafova s n vrhova, a \(g_n\) broj grafova s \(n\) vrhova čiji su vrhovi obojeni dvjema bojama tako da između vrhova iste boje nema bridova. Prebrojavanjem po broju vrhova jedne od boja dobivamo2:

\[ g_n = \sum_{i=0}^{n} \binom{n}{i}2^{i(n-i)} \]

Vezu između \(g_n\) i \(b_n\) uspostavit ćemo dvjema različitim metodama.

Metoda 1: dvostruko prebrojavanje

Neka \(c_{n, k}\) označava broj bipartitnih grafova s k komponenata povezanosti. Lako se dobiva sljedeća veza:

\[ \begin{align} b_n &= \sum_{i=1}^{n} c_{n, i} \\ g_n &= \sum_{i=1}^{n} c_{n, i} 2^i \end{align} \]

Usporedimo dva izraza za \(g_n\) i raspišimo:

\[ \begin{align} \sum_{i=0}^{n} \binom{n}{i}2^{i(n-i)} &= \sum_{i=1}^{n} c_{n, i} 2^i \\ c_{n, i} &= \sum_{i=0}{n-1} \binom{n-1}{i-1} c_{n, 1}c_{n-i,k-1} \end{align} \]

Odatle se lako dobiva rekurzivna relacija za \(b_n\) složenosti \(O(n^3)\); primjenom formule uključivanja-isključivanja može se dodatno optimizirati na \(O(n^2)\) i riješiti zadatak.

Metoda 2: rekurzija povezivanjem

Druga i treća metoda koriste povezane bipartitne grafove \(b1_n\) A001832 kao most između \(g_n\) i \(b_n\).

Uočimo da svaki povezani bipartitni graf ima točno dva različita bojenja, koja odgovaraju dvama različitim povezanim 2-obojenim grafovima, pa je niz dobiven povezivanjem niza \(g_n\) točno dvostruki \(b1_n\), a \(b_n\) se iz \(b1_n\) dobiva obrnutim povezivanjem.

Stoga:

for (int i = 1; i <= n; ++i) {
  G[i] = 0;
  for (int j = 0; j < i + 1; ++j) G[i] += binom[i][j] * pow(2, j * (i - j));
}
ln(B1, G);
for (int i = 1; i <= n; ++i) B1[i] /= 2;
exp(B, B1);

Oba rekurzivna postupka imaju složenost \(O(n^2)\), čime se zadatak može riješiti.

Metoda 3: eksponencijal polinoma

Uočimo da se gornji rekurzivni postupak može razumjeti i preko EGF-a.

Neka je \(G(x)\) EGF niza \(g_n\), \(B1(x)\) EGF niza \(b1_n\), a \(B(x)\) EGF niza \(b_n\). Primjenom pristupa iz druge metode dobivamo:

\[ \begin{align} G(x) &= \exp(2B1(x)) \\ B(x) &= \exp(B1(x)) \\ &= \exp(\frac{\ln{G(x)}}{2}) \\ &= \sqrt{G} \end{align} \]

Deriviranjem obiju strana jednakosti i usporedbom koeficijenata dobivamo rekurzivnu formulu koja se lako programira, čime se zadatak može riješiti. Uočimo da su druga i treća metoda u biti iste, a treća u općem slučaju daje bolju vremensku složenost.

\[ \begin{align} B_n^2 &= G \\ 2B_nB_n' &= G' \end{align} \]

Riddellova formula

Gornja upotreba eksponencijala EGF-a ponekad se naziva Riddellovom formulom za označene grafove (Riddell's formula for labeled graphs), a Eulerova transformacija funkcije izvodnice ponekad Riddellovom formulom za neoznačene grafove (Riddell's formula for unlabeled graphs). Potonja se prvi put pojavila u Eulerovu proučavanju particija brojeva; osim u prebrojavanju grafova, pojavljuje se i u problemu neograničenog ruksaka (unbounded knapsack).

Za zadani niz \(a_i\) i pripadnu OGF \(A(x)\) Eulerova transformacija od \(A(x)\) definira se kao:

\[ \begin{align} \mathcal{E}(A(x)) &= \prod_{i} (1-x^i)^{-a_i} \\ &= \exp (\sum_{i} \frac{A(x^i)}{i}) \end{align} \]

Neka su \(b_i\) koeficijenti od \(\mathcal{E}(A(x))\) i definirajmo pomoćni niz \(c_i = \sum_{d|n} d a_d\); tada vrijedi rekurzivna formula

\[ n b_n = c_n + \sum_{i=1}^{n-1} c_i b_{n-i} \]

Korijenska stabla

Označeni je slučaj riješen ranije u tekstu; razmotrimo neoznačena korijenska stabla. Neka je njihova OGF \(F(x)\). Primjenom Eulerove transformacije dobivamo:

\[ F(x) = x\mathcal{E}(F(x)) \]

Dovoljno je izdvojiti koeficijente.

Stabla bez korijena

Primijenimo uključivanje-isključivanje: od broja korijenskih stabala oduzmemo ona u kojima korijen nije centroid (težište), pri čemu razlikujemo slučajeve prema parnosti \(n\).

Kad je \(n\) neparan:

Nužno postoji podstablo veličine \(\geq \left\lceil \frac{n}{2}\right\rceil\); prebrojavanjem po veličini tog podstabla dobivamo:

\[ g_n = f_n - \sum_{i=\left\lceil\frac{n}{2}\right\rceil}^{n-1} f_i f_{n-i} \]

Kad je \(n\) paran:

Uočimo da se u slučaju s dva centroida gornjim postupkom oduzima samo jednom, pa treba dodatno oduzeti

\[ g_n = f_n - \sum_{i=\frac{n}{2}+1}^{n-1} f_i f_{n-i} - \binom{f_{\frac{n}{2}}}{2} \]

Neoznačeni jednostavni grafovi

Primjer zadatka „SGU 282. Isomorphism” Isomorphism

Primjer zadatka „SGU 282. Isomorphism” Isomorphism

Sažetak zadatka: odredite broj načina bojenja bridova neoznačenog potpunog grafa s n vrhova s m boja.

Uočimo da su za m = 2 traženi objekti upravo neoznačeni jednostavni grafovi A000088. Promotrimo Pólyin teorem prebrojavanja:

\[ \frac{1}{|G|}\sum_{g\in G} m^{c(g)} \]

U ovom je zadatku grupa permutacija \(G\) grupa permutacija bridova koju generira simetrična grupa reda \(n\) na vrhovima, ali gruba sila prolazi kroz \(O(n!)\) permutacija, što nije dovoljno za rješavanje zadatka.

Razvrstajmo permutacije prema njihovoj cikličkoj strukturi: svaka ciklička struktura odgovara jednoj particiji broja, a particije generiramo funkcijom dfs(). Problem se tako svodi na određivanje broja permutacija \(w(p)\) koje odgovaraju svakoj particiji \(p\) i broja ciklusa \(c(p)\) u svakoj klasi permutacija; odgovor je

\[ \frac{1}{|G|} \sum_{p \in P} w(p) m^{c(p)} \]

Promotrimo \(w(p)\): svaki dio particije odgovara jednoj cikličkoj permutaciji, a redoslijed dijelova iste veličine nije bitan, pa imamo:

\[ w(p) = \frac{n!}{\prod_{i}(p_i)\prod_{i}(q_i!)} \]

Ovdje \(q_i\) označava koliko se puta dio veličine \(i\) pojavljuje u \(p\).

Promotrimo \(c(p)\): broj ciklusa na skupu vrhova na koje \(p\) djeluje jednak je \(|p|\), ali zadatak traži bojenje bridova, pa treba promotriti permutaciju bridova koju generira permutacija vrhova.

Ako su oba vrha nekog brida u istom ciklusu veličine \(p_i\), broj ciklusa koje generiraju bridovi točno je \(\left\lfloor \frac{p_i}{2} \right\rfloor\).

Ako su vrhovi brida u dvama različitim ciklusima veličina \(p_i\) i \(p_j\), duljina je svakog ciklusa \(\operatorname{lcm}(p_i,p_j)\), pa je broj ciklusa koje generiraju bridovi točno \(\frac{p_i p_j}{\operatorname{lcm}(p_i,p_j)} = \gcd(p_i, p_j)\).

In combinatorics, graph enumeration is the branch that studies problems of counting graphs with given properties. Generating functions, the Pólya enumeration theorem, the symbolic method and the OEIS are the most important mathematical tools for solving such problems. Graph enumeration problems fall into two large classes: labeled and unlabeled. In most cases1 the labeled version of a problem is simpler than the corresponding unlabeled one, so we first look at counting labeled structures.

Labeled connected graphs

Example problem "POJ 1737" Connected Graph

Example problem “POJ 1737” Connected Graph

Problem summary: find the number of labeled connected graphs with \(n\) vertices (\(n \leq 50\)).

Problems of this kind first appeared in Lou Tiancheng's (楼教主) problem series “男人八题” (“Eight Problems for Men”). Let \(g_n\) be the number of labeled graphs with \(n\) vertices and \(c_n\) the sequence we are looking for. A graph with \(n\) vertices has at most \(\binom{n}{2}\) edges, each edge has two states (present or absent) and these states are independent, so \(g_n = 2^{\binom{n}{2}}\). Fix one vertex and enumerate the size of the connected component it belongs to: from the remaining \(n-1\) vertices we have to choose \(i-1\) vertices that form one connected component together with it. The vertices outside this component may be connected arbitrarily, so we get the following recurrence:

\[ \begin{align} \sum_{i=1}^{n} \binom{n-1}{i-1} c_i g_{n-i} &= g_n \\ c_n &= g_n - \sum_{i=1}^{n-1} \binom{n-1}{i-1} c_i g_{n-i} \end{align} \]

Rearranging the terms gives an \(O(n^2)\) recurrence for the sequence \(c_n\), which is enough to solve this problem.

Example problem "集训队作业 2013" 城市规划

Example problem “集训队作业 2013” 城市规划 (Team Selection Homework 2013 – Urban Planning)

Problem summary: find the number of labeled connected graphs with \(n\) vertices (\(n \leq 130000\)).

For sequence problems with larger constraints we usually need to construct the generating functions of these sequences so that efficient polynomial algorithms can be used.

Method 1: divide-and-conquer FFT

The recurrence above can be viewed as a kind of self-convolution, so it can be computed with divide-and-conquer FFT in \(O(n\log^2n)\).

Method 2: polynomial inverse

Expand the binomial coefficient in the recurrence above and rearrange:

\[ \begin{align} \sum_{i=1}^{n} \binom{n-1}{i-1} c_i g_{n-i} &= g_n \\ \sum_{i=1}^{n} \frac{c_i}{(i-1)!} \frac{g_{n-i}}{(n-i)!} &= \frac{g_n}{(n-1)!} \end{align} \]

Construct the polynomials:

\[ \begin{align} C(x) &= \sum_{n=1} \frac{c_n}{(n-1)!} x^n \\ G(x) &= \sum_{n=0} \frac{g_n}{n!} x^n \\ H(x) &= \sum_{n=1} \frac{g_n}{(n-1)!} x^n \end{align} \]

Substituting into the equation above gives \(CG = H\); it suffices to compute the polynomial inverse and then obtain \(C(x)\) by convolution.

Method 3: polynomial exp

Another approach is to use the combinatorial meaning of the polynomial exp of an EGF. Let \(C(x)\) and \(G(x)\) be the EGFs of the sequences of labeled connected graphs and of simple graphs, respectively; then they satisfy the following relation:

\[ \begin{align} \exp(C(x)) &= G(x) \\ C(x) &= \ln(G(x)) \end{align} \]

It suffices to compute \(C(x)\) with the polynomial logarithm.

Labeled Eulerian and bipartite graphs

Example problem "SPOJ KPGRAPHS" Counting Graphs

Example problem “SPOJ KPGRAPHS” Counting Graphs

Problem summary: find the number of labeled graphs with \(n\) vertices satisfying each of the following properties (\(n \leq 1000\)).

  • connected graphs A001187,
  • Eulerian graphs A033678,
  • bipartite graphs A047864.

This problem limits the code length, so polynomial templates cannot be used directly, but generating functions still help us with the analysis.

The connected-graph problem was solved in the previous examples; consider Eulerian graphs. Note that all of the methods for counting connected graphs above generalize to labeled connected graphs with an arbitrary property. For example, if in the recurrence for connected graphs we replace \(g_n\), the number of all graphs, by the number of graphs in which every vertex has even degree, the resulting \(c_n\) is exactly the number of Eulerian graphs.

Let us wrap the recurrence from POJ 1737 into a "connectification" function (transition to connected structures):

void ln(Int C[], Int G[]) {
  for (int i = 1; i <= n; ++i) {
    C[i] = G[i];
    for (int j = 1; j <= i - 1; ++j)
      C[i] -= binom[i - 1][j - 1] * C[j] * G[i - j];
  }
}

The first two questions are then solved easily:

for (int i = 1; i <= n; ++i) G[i] = pow(2, binom[i][2]);
ln(C, G);
for (int i = 1; i <= n; ++i) G[i] = pow(2, binom[i - 1][2]);
ln(E, G);

Note that this connectification recurrence is in fact equivalent to taking the polynomial logarithm of the corresponding EGF. Similarly we can write the inverse connectification function, which is equivalent to taking the polynomial exp of the EGF.

void exp(Int G[], Int C[]) {
  for (int i = 1; i <= n; ++i) {
    G[i] = C[i];
    for (int j = 1; j <= i - 1; ++j)
      G[i] += binom[i - 1][j - 1] * C[j] * G[i - j];
  }
}

Now let us discuss counting labeled bipartite graphs.

Let \(b_n\) denote the number of bipartite graphs with n vertices and \(g_n\) the number of graphs with \(n\) vertices whose vertices are colored with 2 colors so that there is no edge between vertices of the same color. Enumerating the number of vertices of one of the colors, we get2:

\[ g_n = \sum_{i=0}^{n} \binom{n}{i}2^{i(n-i)} \]

Next we establish the relation between \(g_n\) and \(b_n\) in two different ways.

Method 1: double counting

Let \(c_{n, k}\) denote the number of bipartite graphs with k connected components. It is not hard to obtain the following relation:

\[ \begin{align} b_n &= \sum_{i=1}^{n} c_{n, i} \\ g_n &= \sum_{i=1}^{n} c_{n, i} 2^i \end{align} \]

Comparing the two expressions for \(g_n\) and expanding gives:

\[ \begin{align} \sum_{i=0}^{n} \binom{n}{i}2^{i(n-i)} &= \sum_{i=1}^{n} c_{n, i} 2^i \\ c_{n, i} &= \sum_{i=0}{n-1} \binom{n-1}{i-1} c_{n, 1}c_{n-i,k-1} \end{align} \]

It is not hard to obtain a recurrence for \(b_n\) in \(O(n^3)\); using the inclusion–exclusion principle it can be further optimized to \(O(n^2)\), which solves this problem.

Method 2: connectification recurrence

Methods 2 and 3 both use connected bipartite graphs \(b1_n\) A001832 as the bridge between \(g_n\) and \(b_n\).

Note that every connected bipartite graph has exactly two different colorings, corresponding to two different connected 2-colored graphs, so applying connectification to \(g_n\) gives exactly twice the sequence \(b1_n\), while \(b_n\) is obtained from \(b1_n\) by inverse connectification.

Therefore:

for (int i = 1; i <= n; ++i) {
  G[i] = 0;
  for (int j = 0; j < i + 1; ++j) G[i] += binom[i][j] * pow(2, j * (i - j));
}
ln(B1, G);
for (int i = 1; i <= n; ++i) B1[i] /= 2;
exp(B, B1);

Both recurrences run in \(O(n^2)\), which solves this problem.

Method 3: polynomial exp

Note that the recurrence above can also be understood through EGFs.

Let \(G(x)\) be the EGF of \(g_n\), \(B1(x)\) the EGF of \(b1_n\) and \(B(x)\) the EGF of \(b_n\). Applying the approach of method 2, we have:

\[ \begin{align} G(x) &= \exp(2B1(x)) \\ B(x) &= \exp(B1(x)) \\ &= \exp(\frac{\ln{G(x)}}{2}) \\ &= \sqrt{G} \end{align} \]

Differentiating both sides and comparing coefficients yields a recurrence that is easy to code, which solves this problem. Note that methods 2 and 3 are essentially the same, and in general method 3 gives a better time complexity.

\[ \begin{align} B_n^2 &= G \\ 2B_nB_n' &= G' \end{align} \]

Riddell's formula

The use of the exp of an EGF described above is sometimes called Riddell's formula for labeled graphs, and the Euler transform of a generating function is sometimes called Riddell's formula for unlabeled graphs. The latter first appeared in Euler's study of integer partitions; besides graph enumeration problems, it also appears in the unbounded knapsack problem.

For a given sequence \(a_i\) with corresponding OGF \(A(x)\), the Euler transform of \(A(x)\) is defined as:

\[ \begin{align} \mathcal{E}(A(x)) &= \prod_{i} (1-x^i)^{-a_i} \\ &= \exp (\sum_{i} \frac{A(x^i)}{i}) \end{align} \]

Let \(b_i\) be the coefficients of \(\mathcal{E}(A(x))\) and define the auxiliary array \(c_i = \sum_{d|n} d a_d\); then we have the recurrence

\[ n b_n = c_n + \sum_{i=1}^{n-1} c_i b_{n-i} \]

Rooted trees

The labeled case was solved earlier in the text; now consider unlabeled rooted trees. Let their OGF be \(F(x)\). Applying the Euler transform, we get:

\[ F(x) = x\mathcal{E}(F(x)) \]

It suffices to extract the coefficients.

Unrooted trees

Use inclusion–exclusion: from the number of rooted trees subtract those in which the root is not the centroid, and treat the cases by the parity of \(n\).

When \(n\) is odd:

There necessarily exists a subtree of size \(\geq \left\lceil \frac{n}{2}\right\rceil\); enumerating the size of this subtree gives:

\[ g_n = f_n - \sum_{i=\left\lceil\frac{n}{2}\right\rceil}^{n-1} f_i f_{n-i} \]

When \(n\) is even:

Note that in the case of two centroids the procedure above subtracts only once, so we additionally have to subtract

\[ g_n = f_n - \sum_{i=\frac{n}{2}+1}^{n-1} f_i f_{n-i} - \binom{f_{\frac{n}{2}}}{2} \]

Problem summary: find the number of ways to color the edges of an unlabeled complete graph with n vertices using m colors.

Note that for m = 2 the objects in question are exactly the unlabeled simple graphs A000088. Consider the Pólya enumeration theorem:

\[ \frac{1}{|G|}\sum_{g\in G} m^{c(g)} \]

In this problem the permutation group \(G\) is the group of edge permutations generated by the symmetric group of order \(n\) on the vertices, but the brute-force approach enumerates \(O(n!)\) permutations, which is not enough to solve this problem.

Let us classify the permutations by their cycle structure: each cycle structure corresponds to an integer partition, and we generate the partitions with dfs(). The problem then reduces to finding, for each partition \(p\), the number of corresponding permutations \(w(p)\) and the number of cycles \(c(p)\) in each class of permutations; the answer is

\[ \frac{1}{|G|} \sum_{p \in P} w(p) m^{c(p)} \]

Consider \(w(p)\): each part of the partition corresponds to a cyclic permutation, and the order among parts of the same size does not matter, so we have:

\[ w(p) = \frac{n!}{\prod_{i}(p_i)\prod_{i}(q_i!)} \]

Here \(q_i\) denotes the number of times a part of size \(i\) appears in \(p\).

Consider \(c(p)\): the number of cycles on the vertex set acted on by \(p\) is \(|p|\), but the problem is about edge coloring, so we also have to consider the edge permutation generated by the vertex permutation.

If both endpoints of an edge lie in the same cycle of size \(p_i\), the number of cycles generated by the edges is exactly \(\left\lfloor \frac{p_i}{2} \right\rfloor\).

If the endpoints of an edge lie in two different cycles of sizes \(p_i\) and \(p_j\), the length of each cycle is \(\operatorname{lcm}(p_i,p_j)\), so the number of cycles generated by the edges is exactly \(\frac{p_i p_j}{\operatorname{lcm}(p_i,p_j)} = \gcd(p_i, p_j)\).

#include <iostream>
#include <vector>
using namespace std;

using LL = long long;
int MOD = int(1e9) + 7;

namespace NT {
void INC(int& a, int b) {
  a += b;
  if (a >= MOD) a -= MOD;
}

int sum(int a, int b) {
  a += b;
  if (a >= MOD) a -= MOD;
  return a;
}

void DEC(int& a, int b) {
  a -= b;
  if (a < 0) a += MOD;
}

int dff(int a, int b) {
  a -= b;
  if (a < 0) a += MOD;
  return a;
}

void MUL(int& a, int b) { a = (LL)a * b % MOD; }

int pdt(int a, int b) { return (LL)a * b % MOD; }

int _I(int b) {
  int a = MOD, x1 = 0, x2 = 1, q;
  while (1) {
    q = a / b, a %= b;
    if (!a) return x2;
    DEC(x1, pdt(q, x2));

    q = b / a, b %= a;
    if (!b) return x1;
    DEC(x2, pdt(q, x1));
  }
}

void DIV(int& a, int b) { MUL(a, _I(b)); }

int qtt(int a, int b) { return pdt(a, _I(b)); }

int pow(int a, LL b) {
  int c(1);
  while (b) {
    if (b & 1) MUL(c, a);
    MUL(a, a), b >>= 1;
  }
  return c;
}

template <class T>
T pow(T a, LL b) {
  T c(1);
  while (b) {
    if (b & 1) c *= a;
    a *= a, b >>= 1;
  }
  return c;
}

template <class T>
T pow(T a, int b) {
  return pow(a, (LL)b);
}

struct Int {
  int val;

  operator int() const { return val; }

  Int(int _val = 0) : val(_val) {
    val %= MOD;
    if (val < 0) val += MOD;
  }

  Int(LL _val) : val(_val) {
    _val %= MOD;
    if (_val < 0) _val += MOD;
    val = _val;
  }

  Int& operator+=(const int& rhs) {
    INC(val, rhs);
    return *this;
  }

  Int operator+(const int& rhs) const { return sum(val, rhs); }

  Int& operator-=(const int& rhs) {
    DEC(val, rhs);
    return *this;
  }

  Int operator-(const int& rhs) const { return dff(val, rhs); }

  Int& operator*=(const int& rhs) {
    MUL(val, rhs);
    return *this;
  }

  Int operator*(const int& rhs) const { return pdt(val, rhs); }

  Int& operator/=(const int& rhs) {
    DIV(val, rhs);
    return *this;
  }

  Int operator/(const int& rhs) const { return qtt(val, rhs); }

  Int operator-() const { return MOD - *this; }
};

}  // namespace NT

using namespace NT;

constexpr int N = int(5e1) + 9;
Int Fact[N];
vector<vector<int>> Partition;
vector<int> cur;
int n, m;

void gen(int n = ::n, int s = 1) {
  if (!n) {
    Partition.push_back(cur);
  } else if (n >= s) {
    cur.push_back(s);
    gen(n - s, s);
    cur.pop_back();
    gen(n, s + 1);
  }
}

Int w(const vector<int> P) {
  Int z = Fact[n];
  int c = 0, l = P.front();

  for (auto p : P) {
    z /= p;
    if (p != l) {
      z /= Fact[c];
      l = p;
      c = 1;
    } else {
      ++c;
    }
  }

  z /= Fact[c];
  return z;
}

int gcd(int x, int y) { return y ? gcd(y, x % y) : x; }

int c(const vector<int> P) {
  int z = 0;
  for (int i = 0; i < P.size(); ++i) {
    z += P[i] / 2;
    for (int j = 0; j < i; ++j) z += gcd(P[i], P[j]);
  }
  return z;
}

int main() {
  cin >> n >> m >> MOD;
  Fact[0] = 1;
  for (int i = 1; i <= n; ++i) Fact[i] = Fact[i - 1] * i;

  gen();

  Int res = 0;
  for (auto P : Partition) {
    res += w(P) * pow(m, c(P));
  }
  res /= Fact[n];
  cout << res << endl;
}
