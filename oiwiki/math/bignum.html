Definicija

Računanje s velikim brojevima (aritmetika proizvoljne preciznosti, Arbitrary-Precision Arithmetic), poznato i kao računanje s velikim cijelim brojevima (bignum), koristi određene algoritamske strukture kako bi podržalo operacije nad većim cijelim brojevima (brojevima koji premašuju ugrađene cjelobrojne tipove jezika).

Uvod

Zadaci s velikim brojevima sadrže mnogo sitnih detalja, a i implementacija ima brojne finese.

Zato ćemo danas zajedno napisati jednostavan kalkulator.

Zadatak

Ulaz: izraz oblika a <op> b.

  • a i b nenegativni su dekadski cijeli brojevi duljine najviše \(1000\);
  • <op> je jedan znak (+, -, * ili /) koji označava operaciju.
  • Brojevi i operator odvojeni su jednim razmakom.

Izlaz: rezultat operacije.

  • Za operacije +, - i * ispišite jedan redak s rezultatom;
  • Za operaciju / ispišite dva retka: kvocijent i ostatak.
  • Zajamčeno je da su svi rezultati nenegativni cijeli brojevi.

Pohrana

U uobičajenim implementacijama veliki brojevi prikazuju se stringovima, pri čemu svaki znak predstavlja jednu dekadsku znamenku. Stoga se može reći da je računanje s velikim brojevima zapravo posebna vrsta obrade stringova.

Kad se string pročita, najznačajnija znamenka nalazi se na početku stringa (na mjestu s malim indeksom). No uobičajeno je da se na mjestu s najmanjim indeksom pohrani najmanje značajna znamenka, tj. pohranjuje se obrnuti string. Razlog je to što se duljina broja može mijenjati, a želimo da znamenke iste težine uvijek ostanu poravnate (primjerice, da sve jedinice budu na indeksu [0], sve desetice na indeksu [1]…); istodobno, zbrajanje, oduzimanje i množenje obično počinju od jedinica (sjetite se pisanog računanja iz osnovne škole), što sve daje dovoljno razloga za „obrnutu pohranu”.

Tog ćemo se dogovora držati u nastavku. Definiramo konstantu LEN = 1004 kao najveću duljinu koju program može prihvatiti.

Iz toga nije teško napisati kôd za čitanje velikog broja:

void clear(int a[]) {
  for (int i = 0; i < LEN; ++i) a[i] = 0;
}

void read(int a[]) {
  static char s[LEN + 1];
  scanf("%s", s);

  clear(a);

  int len = strlen(s);
  // kao što je rečeno, obrćemo
  for (int i = 0; i < len; ++i) a[len - i - 1] = s[i] - '0';
  // s[i] - '0' je upravo znamenka koju s[i] predstavlja
  // nekima je možda bliže to shvatiti kao ord(s[i]) - ord('0')
}

Ispis također ide obrnutim redoslijedom od pohrane. Budući da ne želimo ispisivati vodeće nule, ovdje od najznačajnije znamenke tražimo prvu znamenku različitu od nule i od nje počinjemo ispis; uvjet zaustavljanja je i >= 1, a ne i >= 0, jer kad je cijeli broj jednak \(0\) ipak želimo ispisati jedan znak 0.

void print(int a[]) {
  int i;
  for (i = LEN - 1; i >= 1; --i)
    if (a[i] != 0) break;
  for (; i >= 0; --i) putchar(a[i] + '0');
  putchar('\n');
}

Četiri osnovne operacije

Četiri osnovne operacije razlikuju se po težini. Najjednostavnije su zbrajanje i oduzimanje velikih brojeva, zatim množenje velikog broja običnim brojem (obični int) i množenje dvaju velikih brojeva, a na kraju dijeljenje velikog broja velikim brojem.

Sve tražene funkcionalnosti implementirat ćemo redom.

Zbrajanje

Zbrajanje velikih brojeva zapravo je obično pisano zbrajanje.

Dakle, počevši od najmanje značajne znamenke, zbrajamo znamenke dvaju pribrojnika na odgovarajućim mjestima i provjeravamo je li zbroj dosegnuo ili premašio \(10\). Ako jest, obrađujemo prijenos: rezultat na sljedećem višem mjestu uvećamo za \(1\), a rezultat na trenutačnom mjestu umanjimo za \(10\).

void add(int a[], int b[], int c[]) {
  clear(c);

  // u implementacijama velikih brojeva najveća duljina niza LEN obično je malo veća od mogućeg ulaza,
  // a zatim se posljednjih nekoliko iteracija petlje preskoči; time se uštedi dosta obrade rubnih slučajeva
  // budući da stvarni ulaz ne prelazi 1000 znamenaka, ovdje je dovoljno ići do LEN - 1 = 1003
  for (int i = 0; i < LEN - 1; ++i) {
    // zbrojimo znamenke na odgovarajućem mjestu
    c[i] += a[i] + b[i];
    if (c[i] >= 10) {
      // prijenos
      c[i + 1] += 1;
      c[i] -= 10;
    }
  }
}

Oduzimanje

Oduzimanje velikih brojeva također je obično pisano oduzimanje.

Od jedinica nadalje oduzimamo znamenku po znamenku, a kad naiđemo na negativan rezultat, posuđujemo \(1\) s višeg mjesta. Cjelokupna je ideja potpuno ista kao kod zbrajanja.

void sub(int a[], int b[], int c[]) {
  clear(c);

  for (int i = 0; i < LEN - 1; ++i) {
    // oduzimamo znamenku po znamenku
    c[i] += a[i] - b[i];
    if (c[i] < 0) {
      // posudba
      c[i + 1] -= 1;
      c[i] += 10;
    }
  }
}

Zapravo, gornji kôd može obraditi samo slučaj kad je umanjenik \(a\) veći od ili jednak umanjitelju \(b\). Slučaj kad je umanjenik manji od umanjitelja, tj. \(a<b\), rješava se jednostavno.

\(a-b=-(b-a)\)

Da bismo izračunali \(b-a\), budući da je \(b>a\), možemo pozvati funkciju sub iz gornjeg koda kao sub(b,a,c). Da bismo dobili \(a-b\), dovoljno je ispred rezultata dodati znak minus.

Množenje

Veliki broj – obični broj

Množenje velikih brojeva također je obično pisano… čekajte, čekajte!

Razmotrimo prvo jednostavan slučaj: jedan od faktora običan je int. Postoji li jednostavan način da se to obradi?

Intuitivna je ideja jednostavno pomnožiti svaku znamenku broja \(a\) s \(b\). Brojčano je ta metoda ispravna, ali rezultat nije u skladu s dekadskim zapisom, pa ga treba ponovno urediti u uobičajeni oblik.

Uređivanje se također provodi od jedinica nadalje, obrađujući prijenos znamenku po znamenku prema višim mjestima. No ovdje prijenos može biti vrlo velik, čak znatno veći od \(9\), jer svaka znamenka nakon množenja može dosegnuti red veličine \(9b\). Zato se prijenos više ne može obraditi jednostavnom operacijom \(-10\), nego ga treba izračunati preko kvocijenta i ostatka pri dijeljenju s \(10\). Detalji su u komentarima koda, a možete pogledati i sliku u nastavku koja prikazuje postupak množenja velikog broja \(1337\) običnim brojem \(42\).

Naravno, upravo zbog toga ova metoda zahtijeva posebnu pozornost na raspon faktora \(b\). Ako je on istog reda veličine kao \(10^9\) (odnosno gornja granica odgovarajućeg cjelobrojnog tipa), množenje velikog broja običnim brojem treba koristiti s oprezom.

void mul_short(int a[], int b, int c[]) {
  clear(c);

  for (int i = 0; i < LEN - 1; ++i) {
    // i-tu znamenku broja a izravno pomnožimo faktorom i dodamo u rezultat
    c[i] += a[i] * b;

    if (c[i] >= 10) {
      // obrada prijenosa
      // c[i] / 10, tj. kvocijent dijeljenja, postaje iznos prijenosa
      c[i + 1] += c[i] / 10;
      // a c[i] % 10, tj. ostatak dijeljenja, postaje vrijednost koja ostaje na trenutačnom mjestu
      c[i] %= 10;
    }
  }
}

Veliki broj – veliki broj

Ako su oba faktora veliki brojevi, pisano množenje ponovno dolazi do izražaja.

Prisjetimo se da svaki korak pisanog množenja zapravo računa zbroj nekoliko članova \(a \times b_i \times 10^i\). Primjerice, pri računanju \(1337 \times 42\) računamo \(1337 \times 2 \times 10^0 + 1337 \times 4 \times 10^1\).

Stoga \(b\) možemo rastaviti na njegove znamenke, od kojih je svaka običan broj, svaku od njih pomnožiti s \(a\), a zatim ih pomaknuti ulijevo na odgovarajuća mjesta i zbrojiti – to je odgovor. Naravno, na kraju treba obraditi prijenos na isti način kao u prethodnom primjeru.

Primijetite da se ovaj postupak ne poklapa posve s pisanim množenjem: naš algoritam u svakom koraku množenja ne radi prijenos, nego sve rezultate zadržava na odgovarajućim mjestima i tek na kraju obrađuje prijenos zajedno, ali to ne utječe na rezultat.

void mul(int a[], int b[], int c[]) {
  clear(c);

  for (int i = 0; i < LEN - 1; ++i) {
    // ovdje izravno računamo i-tu znamenku rezultata (od najmanje značajne) i usput obrađujemo prijenos
    // i-ta iteracija u c[i] dodaje zbroj svih umnožaka a[p] * b[q] za koje je p + q = i
    // učinak je isti kao kad bismo proveli račun sa slike i na kraju zbrojili, samo je implementacija kraća
    for (int j = 0; j <= i; ++j) c[i] += a[j] * b[i - j];

    if (c[i] >= 10) {
      c[i + 1] += c[i] / 10;
      c[i] %= 10;
    }
  }
}

Dijeljenje

Jedan način implementacije dijeljenja velikih brojeva pisano je dugo dijeljenje.

Pisano dugo dijeljenje zapravo se može promatrati kao postupak uzastopnog oduzimanja. Primjerice, računanje desetica kvocijenta na gornjoj slici može se shvatiti ovako: od \(45\) tri puta oduzmemo \(12\) i rezultat postane manji od \(12\), dalje se ne može oduzimati, pa je ta znamenka \(3\).

Kako bismo smanjili suvišne operacije, unaprijed odredimo duljinu djeljenika \(l_a\) i duljinu djelitelja \(l_b\) te kvocijent računamo od indeksa \(l_a - l_b\) nadalje, od viših prema nižim znamenkama. To je isto kao kad pri ručnom računanju najznačajniju znamenku prvog množenja poravnamo s najznačajnijom znamenkom djeljenika.

Referentni program implementira funkciju greater_eq() koja provjerava može li se od djeljenika, kojemu je indeks last_dg najmanje značajna znamenka, još jednom oduzeti djelitelj tako da rezultat ostane nenegativan. Zatim za svaku znamenku kvocijenta uzastopno pozivamo greater_eq() i, kad je uvjet ispunjen, oduzimanjem velikih brojeva oduzmemo djelitelj od ostatka, čime simuliramo postupak pisanog dijeljenja.

// može li se od djeljenika a, kojemu je indeks last_dg najmanje značajna znamenka, još oduzeti djelitelj b tako da ostane nenegativan
// len je duljina djelitelja b, da se ne računa iznova
bool greater_eq(int a[], int b[], int last_dg, int len) {
  // preostali dio djeljenika može biti dulji od djelitelja, ali najviše za 1 znamenku, pa je ova provjera dovoljna
  if (a[last_dg + len] != 0) return true;
  // od najznačajnije do najmanje značajne znamenke, usporedba znamenku po znamenku
  for (int i = len - 1; i >= 0; --i) {
    if (a[last_dg + i] > b[i]) return true;
    if (a[last_dg + i] < b[i]) return false;
  }
  // slučaj jednakosti također je dopušten
  return true;
}

void div(int a[], int b[], int c[], int d[]) {
  clear(c);
  clear(d);

  int la, lb;
  for (la = LEN - 1; la > 0; --la)
    if (a[la - 1] != 0) break;
  for (lb = LEN - 1; lb > 0; --lb)
    if (b[lb - 1] != 0) break;
  if (lb == 0) {  // djelitelj ne smije biti nula
    puts("> <");
    return;
  }

  // c je kvocijent
  // d je preostali dio djeljenika, koji nakon završetka algoritma prirodno postaje ostatak
  for (int i = 0; i < la; ++i) d[i] = a[i];
  for (int i = la - lb; i >= 0; --i) {
    // računamo i-tu znamenku kvocijenta
    while (greater_eq(d, b, i, lb)) {
      // ako se može oduzeti, oduzmemo
      // ovaj je odsječak oduzimanje velikih brojeva
      for (int j = 0; j < lb; ++j) {
        d[i + j] -= b[j];
        if (d[i + j] < 0) {
          d[i + j + 1] -= 1;
          d[i + j] += 10;
        }
      }
      // ovu znamenku kvocijenta uvećamo za 1
      c[i] += 1;
      // vraćamo se na početak petlje i ponovno provjeravamo
    }
  }
}

    if (c[i] < 0) {
      c[i + 1] -= 1;
      c[i] += 10;
    }
  }
}

void mul(int a[], int b[], int c[]) {
  clear(c);

  for (int i = 0; i < LEN - 1; ++i) {
    for (int j = 0; j <= i; ++j) c[i] += a[j] * b[i - j];

    if (c[i] >= 10) {
      c[i + 1] += c[i] / 10;
      c[i] %= 10;
    }
  }
}

bool greater_eq(int a[], int b[], int last_dg, int len) {
  if (a[last_dg + len] != 0) return true;
  for (int i = len - 1; i >= 0; --i) {
    if (a[last_dg + i] > b[i]) return true;
    if (a[last_dg + i] < b[i]) return false;
  }
  return true;
}

void div(int a[], int b[], int c[], int d[]) {
  clear(c);
  clear(d);

  int la, lb;
  for (la = LEN - 1; la > 0; --la)
    if (a[la - 1] != 0) break;
  for (lb = LEN - 1; lb > 0; --lb)
    if (b[lb - 1] != 0) break;
  if (lb == 0) {
    puts("> <");
    return;
  }

  for (int i = 0; i < la; ++i) d[i] = a[i];
  for (int i = la - lb; i >= 0; --i) {
    while (greater_eq(d, b, i, lb)) {
      for (int j = 0; j < lb; ++j) {
        d[i + j] -= b[j];
        if (d[i + j] < 0) {
          d[i + j + 1] -= 1;
          d[i + j] += 10;
        }
      }
      c[i] += 1;
    }
  }
}

  read(a);

  char op[4];
  scanf("%s", op);

  read(b);

Pakiranje znamenaka

Uvod

U običnom zbrajanju, oduzimanju i množenju velikih brojeva brojeve koji sudjeluju u operaciji rastavljamo na pojedinačne znamenke i s njima računamo.

Primjerice, pri računanju \(8192\times 42\), ako slijedimo postupak množenja dvaju velikih brojeva, zapravo računamo \((8000+100+90+2)\times(40+2)\).

Kad broj ima mnogo znamenaka, i rastavljenih dijelova je mnogo, pa učinkovitost računanja s velikim brojevima opada.

Može li se to nekako optimizirati?

Primijetimo da način rastavljanja broja ne utječe na konačni rezultat, pa možemo spojiti više znamenaka u jednu cjelinu.

Postupak

Uzmimo ponovno gornji primjer: ako rastavljamo po dvije znamenke, možemo rastaviti kao \((8100+92)\times 42\).

Takvo rastavljanje ne utječe na konačni rezultat, ali budući da je rastavljenih brojeva manje, učinkovitost računanja raste.

Gledano iz perspektive brojevnih sustava, ovaj postupak znači da računamo u većoj bazi (gornje rastavljanje po dvije znamenke može se shvatiti kao računanje u bazi \(100\)), čime smanjujemo broj znamenaka koje sudjeluju u računu i povećavamo učinkovitost.

To je ideja pakiranja znamenaka (压位高精度, više znamenaka u jednoj ćeliji).

Učinkovito pisano dijeljenje s pakiranjem znamenaka

Kad koristimo pakiranje znamenaka, ako pri pogađanju znamenke kvocijenta i dalje koristimo gore opisanu metodu, broj pokušaja bit će vrlo velik, pa će i konstanta u složenosti biti ogromna. Primjerice, u bazi 10000 za svaku znamenku u prosjeku treba 5000 pokušaja, što je neprihvatljivo velika konstanta. Zato trebamo učinkovitiji način pogađanja kvocijenta.

Kao posrednik može poslužiti double. Pretpostavimo da djeljenik ima 4 znamenke, \(a_4,a_3,a_2,a_1\), a djelitelj 3 znamenke, \(b_3,b_2,b_1\); tada trebamo pogoditi samo jednu znamenku kvocijenta: u bazi \(base\) kvocijent procjenjujemo izrazom \(\dfrac{a_4 base + a_3}{b_3 + b_2 base^{-1} + (b_1+1)base^{-2}}\). Za više znamenaka, postupak za jednu znamenku jednostavno stavimo u petlju. Budući da djelitelj u procjeni sudjeluje s preciznošću od 3 znamenke, zajamčeno je da procijenjeni kvocijent q' i stvarni kvocijent q zadovoljavaju \(q-1 \le q' \le q\), pa su za svaku znamenku u najgorem slučaju potrebna samo dva pokušaja. Istodobno se zahtijeva da \(base^3\) bude unutar efektivne preciznosti tipa double, tj. \(base^3 < 2^{53}\), pa se pri primjeni ove metode preporučuje ne prelaziti bazu 32768; inače zbog nedovoljne preciznosti lako nastaju odstupanja koja dovode do pogrešaka.

Osim toga, budući da je procijenjeni kvocijent uvijek manji od ili jednak stvarnome, postoji prostor za daljnju optimizaciju. U velikoj većini slučajeva za svaku znamenku kvocijent procjenjujemo samo jednom; tada pri procjeni sljedeće znamenke dobiveni kvocijent zbog pogreške prethodne znamenke može biti veći od ili jednak base, ali to nije problem – dovoljno je na kraju odjednom obraditi prijenose. Na primjer, neka je baza 10 i računamo \(395081/9876\); koraci pogađanja kvocijenta su sljedeći:

  1. Prvo pogađanjem dobivamo \(3950/988=3\), pa je \(395081-(9876 \times 3 \times 10^1) = 98801\); u ovom se koraku pojavila pogreška, ali ne obraćamo pozornost na nju i nastavljamo sa sljedećim korakom.
  2. Za ostatak 98801 pogađanjem dobivamo \(9880/988=10\), pa je \(98801-(9876 \times 10 \times 10^0) = 41\), što je konačni ostatak.
  3. Zbrojimo rezultate pogađanja i obradimo prijenos: \(3 \times 10^1 + 10 \times 10^0 = 40\) točan je kvocijent.

Iako metoda izgleda jednostavno, u konkretnoj se implementaciji lako upada u zamke, pa u nastavku dajemo višestruko provjerenu implementaciju bez poznatih grešaka kao referencu; detalji na koje treba obratiti pozornost napisani su u komentarima.

// od ovog broja oduzima b pomnožen s mul i pomaknut ulijevo za offset; služi dijeljenju
BigIntSimple &sub_mul(const BigIntSimple &b, int mul, int offset) {
  if (mul == 0) return *this;
  int borrow = 0;
  // za razliku od oduzimanja, borrow može biti vrlo velik, pa se ne može pisati kao kod oduzimanja
  for (size_t i = 0; i < b.v.size(); ++i) {
    borrow += v[i + offset] - b.v[i] * mul - BIGINT_BASE + 1;
    v[i + offset] = borrow % BIGINT_BASE + BIGINT_BASE - 1;
    borrow /= BIGINT_BASE;
  }
  // ako još ima posudbe, nastavljamo obradu
  for (size_t i = b.v.size(); borrow; ++i) {
    borrow += v[i + offset] - BIGINT_BASE + 1;
    v[i + offset] = borrow % BIGINT_BASE + BIGINT_BASE - 1;
    borrow /= BIGINT_BASE;
  }
  return *this;
}

BigIntSimple div_mod(const BigIntSimple &b, BigIntSimple &r) const {
  BigIntSimple d;
  r = *this;
  if (absless(b)) return d;
  d.v.resize(v.size() - b.v.size() + 1);
  // unaprijed izračunamo recipročnu vrijednost najznačajnije tri znamenke djelitelja + 1; ako su najznačajnije tri znamenke a3,a2,a1,
  // onda je db recipročna vrijednost od a3+a2/base+(a1+1)/base^2, a na kraju množenjem procjenjujemo svaku znamenku kvocijenta
  // ova metoda radi unutar raspona int32 kad je BIGINT_BASE<=32768
  // ali čak i s int64 upotrebljiva je samo za BIGINT_BASE<=131072 (ograničeno preciznošću tipa double)
  // može se zajamčiti da procijenjeni rezultat q' i stvarni rezultat q zadovoljavaju q'<=q<=q'+1
  // pa je za svaku znamenku u prosjeku potreban samo jedan pokušaj, a prijenosi se poslije obrade odjednom
  // ako se želi koristiti veća baza, treba promijeniti način pogađanja kvocijenta
  double t = (b.get((unsigned)b.v.size() - 2) +
              (b.get((unsigned)b.v.size() - 3) + 1.0) / BIGINT_BASE);
  double db = 1.0 / (b.v.back() + t / BIGINT_BASE);
  for (size_t i = v.size() - 1, j = d.v.size() - 1; j <= v.size();) {
    int rm = r.get(i + 1) * BIGINT_BASE + r.get(i);
    int m = std::max((int)(db * rm), r.get(i + 1));
    r.sub_mul(b, m, j);
    d.v[j] += m;
    if (!r.get(i + 1))  // provjeravamo je li najznačajnija znamenka već 0, da izbjegnemo ekstremne slučajeve
      --i, --j;
  }
  r.trim();
  // ispravak najmanje značajne znamenke rezultata
  int carry = 0;
  while (!r.absless(b)) {
    r.subtract(b);
    ++carry;
  }
  // ispravak prijenosa na svakoj znamenki
  for (size_t i = 0; i < d.v.size(); ++i) {
    carry += d.v[i];
    d.v[i] = carry % BIGINT_BASE;
    carry /= BIGINT_BASE;
  }
  d.trim();
  d.sign = sign * b.sign;
  return d;
}

BigIntSimple operator/(const BigIntSimple &b) const {
  BigIntSimple r;
  return div_mod(b, r);
}

BigIntSimple operator%(const BigIntSimple &b) const {
  BigIntSimple r;
  div_mod(b, r);
  return r;
}

Karatsubino množenje

Označimo broj znamenaka velikog broja s \(n\); tada pisano množenje dvaju velikih brojeva zahtijeva \(O(n^2)\) vremena. U ovom odjeljku predstavljamo algoritam bolje vremenske složenosti, koji je predložio sovjetski (ruski) matematičar Anatolij Karacuba (Anatoly Karatsuba); riječ je o algoritmu tipa „podijeli pa vladaj”.

Promotrimo dva velika dekadska cijela broja \(x\) i \(y\), oba s \(n\) znamenaka (vodeće nule su dopuštene). Odaberimo proizvoljno \(0 < m < n\) i označimo

\[ \begin{aligned} x &= x_1 \cdot 10^m + x_0, \\ y &= y_1 \cdot 10^m + y_0, \\ x \cdot y &= z_2 \cdot 10^{2m} + z_1 \cdot 10^m + z_0, \end{aligned} \]

gdje je \(x_0, y_0, z_0, z_1 < 10^m\). Dobivamo

\[ \begin{aligned} z_2 &= x_1 \cdot y_1, \\ z_1 &= x_1 \cdot y_0 + x_0 \cdot y_1, \\ z_0 &= x_0 \cdot y_0. \end{aligned} \]

Uočavamo

\[ z_1 = (x_1 + x_0) \cdot (y_1 + y_0) - z_2 - z_0, \]

pa za izračun \(z_1\) treba izračunati samo \((x_1 + x_0) \cdot (y_1 + y_0)\) i od toga oduzeti \(z_0\) i \(z_2\).

Gornja je formula zapravo srž Karatsubina algoritma: ona problem množenja duljine \(n\) pretvara u \(3\) potproblema manje duljine. Ako stavimo \(m = \left\lceil \dfrac n 2 \right\rceil\) i označimo vrijeme koje Karatsubin algoritam troši na množenje dvaju \(n\)-znamenkastih brojeva s \(T(n)\), vrijedi \(T(n) = 3 \cdot T \left(\left\lceil \dfrac n 2 \right\rceil\right) + O(n)\), a iz master teorema slijedi \(T(n) = \Theta(n^{\log_2 3}) \approx \Theta(n^{1.585})\).

Cijeli se postupak može implementirati rekurzivno. Radi jasnoće, kôd u nastavku Karatsubinim algoritmom implementira množenje polinoma, a na kraju obrađuje sve prijenose.

int *karatsuba_polymul(int n, int *a, int *b) {
  if (n <= 32) {
    // za male veličine računamo izravno, da izbjegnemo gubitak učinkovitosti zbog daljnje rekurzije
    int *r = new int[n * 2 + 1]();
    for (int i = 0; i <= n; ++i)
      for (int j = 0; j <= n; ++j) r[i + j] += a[i] * b[j];
    return r;
  }

  int m = n / 2 + 1;
  int *r = new int[m * 4 + 1]();
  int *z0, *z1, *z2;

  z0 = karatsuba_polymul(m - 1, a, b);
  z2 = karatsuba_polymul(n - m, a + m, b + m);

  // računamo z1
  // privremena izmjena, nakon računanja vraćamo
  for (int i = 0; i + m <= n; ++i) a[i] += a[i + m];
  for (int i = 0; i + m <= n; ++i) b[i] += b[i + m];
  z1 = karatsuba_polymul(m - 1, a, b);
  for (int i = 0; i + m <= n; ++i) a[i] -= a[i + m];
  for (int i = 0; i + m <= n; ++i) b[i] -= b[i + m];
  for (int i = 0; i <= (m - 1) * 2; ++i) z1[i] -= z0[i];
  for (int i = 0; i <= (n - m) * 2; ++i) z1[i] -= z2[i];

  // rezultat dobivamo kombiniranjem z0, z1, z2
  for (int i = 0; i <= (m - 1) * 2; ++i) r[i] += z0[i];
  for (int i = 0; i <= (m - 1) * 2; ++i) r[i + m] += z1[i];
  for (int i = 0; i <= (n - m) * 2; ++i) r[i + m * 2] += z2[i];

  delete[] z0;
  delete[] z1;
  delete[] z2;
  return r;
}

void karatsuba_mul(int a[], int b[], int c[]) {
  int *r = karatsuba_polymul(LEN - 1, a, b);
  memcpy(c, r, sizeof(int) * LEN);
  for (int i = 0; i < LEN - 1; ++i)
    if (c[i] >= 10) {
      c[i + 1] += c[i] / 10;
      c[i] %= 10;
    }
  delete[] r;
}

No takva implementacija ima problem: u bazi \(b\) svaki koeficijent polinoma može dosegnuti red veličine \(n \cdot b^2\), što u implementaciji s pakiranjem znamenaka može uzrokovati prelijevanje cijelih brojeva; a ako prijenose obrađujemo tijekom množenja polinoma, rezultati \(x_1 + x_0\) i \(y_1 + y_0\) mogu dosegnuti \(2 \cdot b^m\), tj. dobiti jednu znamenku više (ako se pak računa u obliku \(x_1 - x_0\), nužno je posebno obraditi negativne brojeve). Stoga način implementacije treba odabrati prema konkretnoj primjeni.

Učinkovito množenje velikih brojeva pomoću polinoma

Ako veličina podataka dosegne \(10^{10^5}\) ili više, obično množenje velikih brojeva može prekoračiti vremensko ograničenje. U ovom odjeljku predstavljamo kako takvo množenje optimizirati pomoću polinoma.

\(n\)-znamenkasti dekadski cijeli broj \(a\) možemo promatrati kao polinom \(A=a_{0} 10^0+a_{1} 10^1+\cdots+a_{n-1} 10^{n-1}\) čiji su svi koeficijenti cijeli brojevi manji od \(10\). Tako smo množenje dvaju cijelih brojeva pretvorili u množenje dvaju polinoma.

Obično množenje polinoma i dalje ima vremensku složenost \(O(n^2)\), ali može se optimizirati algoritmima iz poglavlja o polinomima, kao što su brza Fourierova transformacija i brza teorijsko-brojevna transformacija; nakon optimizacije vremenska je složenost \(O(n\log n)\).

Definition

Arbitrary-precision arithmetic, also called big integer (bignum) arithmetic, uses certain algorithmic structures to support operations on larger integers (numbers whose magnitude exceeds the language's built-in integer types).

Introduction

Bignum problems contain many small details, and the implementation has many subtleties too.

So today let's implement a simple calculator together.

Task

Input: an expression of the form a <op> b.

  • a and b are non-negative decimal integers of length at most \(1000\);
  • <op> is a single character (+, -, * or /) denoting the operation.
  • The integers and the operator are separated by a single space.

Output: the result of the operation.

  • For the operations +, - and *, output one line with the result;
  • For the operation /, output two lines: the quotient and the remainder.
  • It is guaranteed that all results are non-negative integers.

Storage

In everyday implementations, big numbers are represented by strings, where each character represents one decimal digit. Therefore one can say that bignum arithmetic is really a special kind of string processing.

When the string is read in, the most significant digit is at the beginning of the string (at the position with the small index). However, by convention the position with the smallest index stores the least significant digit, i.e. the reversed string is stored. The reason is that the length of the number may change, but we want digits of the same weight to always stay aligned (for example, we want all the ones digits at index [0], all the tens digits at index [1]…); at the same time, addition, subtraction and multiplication generally start from the ones digit (recall long arithmetic from elementary school), all of which gives ample justification for "reversed storage".

We will follow this convention from now on. Define a constant LEN = 1004 as the maximum length the program can hold.

From this it is easy to write the code that reads a big number:

void clear(int a[]) {
  for (int i = 0; i < LEN; ++i) a[i] = 0;
}

void read(int a[]) {
  static char s[LEN + 1];
  scanf("%s", s);

  clear(a);

The four basic operations

The four basic operations differ in difficulty. The simplest are bignum addition and subtraction, followed by bignum–single-precision (ordinary int) multiplication and bignum–bignum multiplication, and finally bignum–bignum division.

We will implement all the required functionality in this order.

Addition

Bignum addition is really just long addition.

That is, starting from the least significant digit, add the digits of the two addends at the corresponding positions and check whether the sum reaches or exceeds \(10\). If it does, handle the carry: increase the result at the next higher position by \(1\) and decrease the result at the current position by \(10\).

void add(int a[], int b[], int c[]) {
  clear(c);

  // in bignum implementations, the maximum array length LEN is usually made a bit larger than the possible input
  // and the last few iterations of the loop are skipped; this saves a lot of handling of boundary cases
  // since the actual input does not exceed 1000 digits, looping up to LEN - 1 = 1003 here is sufficient
  for (int i = 0; i < LEN - 1; ++i) {
    // add the digits at the corresponding position
    c[i] += a[i] + b[i];
    if (c[i] >= 10) {
      // carry
      c[i + 1] += 1;
      c[i] -= 10;
    }
  }
}

Multiplication

Bignum – single precision

Bignum multiplication is really just long… wait, wait!

First consider a simple case: one of the factors is an ordinary int. Is there a simple way to handle this?

An intuitive idea is to directly multiply each digit of \(a\) by \(b\). Numerically this method is correct, but the result does not conform to decimal notation, so it needs to be rearranged into its normal form.

The rearrangement, too, proceeds from the ones digit upward, handling the carry digit by digit. But here the carry can be very large, even far larger than \(9\), because each digit after multiplication may reach the order of magnitude of \(9b\). So the carry here can no longer be handled by simply performing \(-10\); instead it must be computed via the quotient and remainder of division by \(10\). See the code comments for details, or refer to the figure below, which shows the process of multiplying the big number \(1337\) by the single-precision number \(42\).

Of course, for this very reason, the method requires special attention to the range of the factor \(b\). If it is of the same order of magnitude as \(10^9\) (or the upper bound of the corresponding integer type), bignum–single-precision multiplication should be used with caution.

void mul_short(int a[], int b, int c[]) {
  clear(c);

  for (int i = 0; i < LEN - 1; ++i) {
    // directly multiply the i-th digit of a by the factor and add it to the result
    c[i] += a[i] * b;

    if (c[i] >= 10) {
      // handle the carry
      // c[i] / 10, i.e. the quotient of the division, becomes the carry increment
      c[i + 1] += c[i] / 10;
      // and c[i] % 10, i.e. the remainder of the division, becomes the value left at the current position
      c[i] %= 10;
    }
  }
}

Bignum – bignum

If both factors are big numbers, long multiplication comes into its own again.

Recall that each step of long multiplication actually computes the sum of several terms \(a \times b_i \times 10^i\). For example, computing \(1337 \times 42\) computes \(1337 \times 2 \times 10^0 + 1337 \times 4 \times 10^1\).

So we can decompose \(b\) into all of its digits, each of which is a single-precision number, multiply each of them by \(a\), then shift them left to their respective positions and add them up to obtain the answer. Of course, at the end the carries also need to be handled in the same way as in the previous example.

Note that this process is not quite the same as long multiplication: our algorithm does not carry during each multiplication step but keeps all the results at their corresponding positions and handles the carries all at once at the end; this does not affect the result, however.

void mul(int a[], int b[], int c[]) {
  clear(c);

  for (int i = 0; i < LEN - 1; ++i) {
    // here we directly compute the i-th digit of the result (from least significant) and handle the carry along the way
    // the i-th iteration adds to c[i] the sum of all products a[p] * b[q] with p + q = i
    // the effect is the same as performing the computation in the figure above and summing at the end, just a shorter implementation
    for (int j = 0; j <= i; ++j) c[i] += a[j] * b[i - j];

    if (c[i] >= 10) {
      c[i + 1] += c[i] / 10;
      c[i] %= 10;
    }
  }
}

Division

One way to implement bignum division is long division.

Long division can actually be viewed as a process of repeated subtraction. For example, the computation of the tens digit of the quotient in the figure above can be understood as follows: after subtracting \(12\) from \(45\) three times, the result becomes smaller than \(12\) and no further subtraction is possible, so this digit is \(3\).

To reduce redundant operations, we determine in advance the length \(l_a\) of the dividend and the length \(l_b\) of the divisor, and compute the quotient starting from index \(l_a - l_b\), from the higher digits to the lower ones. This is the same as aligning the most significant digit of the first multiplication with the most significant digit of the dividend when computing by hand.

The reference program implements a function greater_eq() that checks whether the divisor can be subtracted once more from the dividend, with index last_dg as its least significant digit, while staying non-negative. Then, for each digit of the quotient, we repeatedly call greater_eq() and, when it holds, subtract the divisor from the remainder using bignum subtraction, thereby simulating the process of long division.

// whether the divisor b can be subtracted once more from the dividend a, with index last_dg as its least significant digit, while staying non-negative
// len is the length of the divisor b, to avoid recomputing it
bool greater_eq(int a[], int b[], int last_dg, int len) {
  // the remaining part of the dividend may be longer than the divisor, but by at most 1 digit, so this check suffices
  if (a[last_dg + len] != 0) return true;
  // from the most significant digit to the least significant, compare digit by digit
  for (int i = len - 1; i >= 0; --i) {
    if (a[last_dg + i] > b[i]) return true;
    if (a[last_dg + i] < b[i]) return false;
  }
  // the equal case is also feasible
  return true;
}

void div(int a[], int b[], int c[], int d[]) {
  clear(c);
  clear(d);

  int la, lb;
  for (la = LEN - 1; la > 0; --la)
    if (a[la - 1] != 0) break;
  for (lb = LEN - 1; lb > 0; --lb)
    if (b[lb - 1] != 0) break;
  if (lb == 0) {  // the divisor must not be zero
    puts("> <");
    return;
  }

  // c is the quotient
  // d is the remaining part of the dividend, which naturally becomes the remainder when the algorithm ends
  for (int i = 0; i < la; ++i) d[i] = a[i];
  for (int i = la - lb; i >= 0; --i) {
    // compute the i-th digit of the quotient
    while (greater_eq(d, b, i, lb)) {
      // if we can subtract, subtract
      // this section is a bignum subtraction
      for (int j = 0; j < lb; ++j) {
        d[i + j] -= b[j];
        if (d[i + j] < 0) {
          d[i + j + 1] -= 1;
          d[i + j] += 10;
        }
      }
      // increase this digit of the quotient by 1
      c[i] += 1;
      // go back to the beginning of the loop and check again
    }
  }
}

Digit packing

Introduction

In ordinary bignum addition, subtraction and multiplication, we split the numbers taking part in the operation into individual digits and compute with them.

For example, when computing \(8192\times 42\), if we follow the bignum–bignum multiplication procedure, what we actually compute is \((8000+100+90+2)\times(40+2)\).

When there are many digits, there are also many split-off pieces, and the efficiency of bignum arithmetic drops.

Is there any way to optimize this?

Note that the way the number is split does not affect the final result, so we can merge several digits together.

Procedure

Take the example above again: if we split off two digits at a time, we can split it as \((8100+92)\times 42\).

Such a split does not affect the final result, but since there are fewer split-off numbers, the computation becomes more efficient.

Viewed from the perspective of numeral systems, this process means computing in a larger base (splitting two digits at a time above can be regarded as computing in base \(100\)), thereby reducing the number of digits taking part in the computation and increasing efficiency.

This is the idea of digit packing (压位高精度, several digits per cell).

Below we give the code for bignum addition with digit packing to further illustrate how it is implemented:

Efficient long division with digit packing

When using digit packing, if we still use the method described above to find each quotient digit by trial, the number of trials will be very large and the constant factor enormous. For example, in base 10000 each digit needs on average 5000 trials, which is an unacceptably large constant. So we need a more efficient way of estimating the quotient.

We can use a double as an intermediary. Suppose the dividend has 4 digits, \(a_4,a_3,a_2,a_1\), and the divisor has 3 digits, \(b_3,b_2,b_1\); then we only need to estimate one quotient digit: in base \(base\), estimate the quotient with the expression \(\dfrac{a_4 base + a_3}{b_3 + b_2 base^{-1} + (b_1+1)base^{-2}}\). For the multi-digit case, just wrap the single-digit version in a loop. Since the divisor takes part in the estimate with 3 digits of precision, it is guaranteed that the estimated quotient q' and the actual quotient q satisfy \(q-1 \le q' \le q\), so each digit needs at most two trials even in the worst case. At the same time, however, \(base^3\) must be within the effective precision of a double, i.e. \(base^3 < 2^{53}\), so when applying this method it is recommended not to exceed base 32768; otherwise insufficient precision easily produces deviations that lead to errors.

Moreover, since the estimated quotient is always less than or equal to the actual quotient, there is room for further optimization. In the vast majority of cases each digit is estimated only once; then, when estimating the next digit, the quotient obtained may be greater than or equal to base due to the error in the previous digit, but that does not matter – it suffices to handle all the carries at once at the end. For example, suppose the base is 10 and we compute \(395081/9876\); the trial steps are as follows:

  1. First, the trial gives \(3950/988=3\), so \(395081-(9876 \times 3 \times 10^1) = 98801\); an error appeared in this step, but we ignore it and continue with the next step.
  2. For the remainder 98801, the trial gives \(9880/988=10\), so \(98801-(9876 \times 10 \times 10^0) = 41\), which is the final remainder.
  3. Add up the results of the trials and handle the carry: \(3 \times 10^1 + 10 \times 10^0 = 40\) is the exact quotient.

Although the method looks simple, it is easy to fall into pitfalls in the concrete implementation, so below we provide a thoroughly verified implementation with no known problems for reference; the details to watch out for are written in the comments.

Reference implementation of efficient long division with digit packing 
// full template and implementation: https://baobaobear.github.io/post/20210228-bigint1/
// subtract b multiplied by mul and shifted left by offset from this number; serves division
BigIntSimple &sub_mul(const BigIntSimple &b, int mul, int offset) {
  if (mul == 0) return *this;
  int borrow = 0;
  // unlike subtraction, borrow can be very large, so the subtraction style cannot be used
  for (size_t i = 0; i < b.v.size(); ++i) {
    borrow += v[i + offset] - b.v[i] * mul - BIGINT_BASE + 1;
    v[i + offset] = borrow % BIGINT_BASE + BIGINT_BASE - 1;
    borrow /= BIGINT_BASE;
  }
  // if there is still a borrow, keep processing
  for (size_t i = b.v.size(); borrow; ++i) {
    borrow += v[i + offset] - BIGINT_BASE + 1;
    v[i + offset] = borrow % BIGINT_BASE + BIGINT_BASE - 1;
    borrow /= BIGINT_BASE;
  }
  return *this;
}

BigIntSimple div_mod(const BigIntSimple &b, BigIntSimple &r) const {
  BigIntSimple d;
  r = *this;
  if (absless(b)) return d;
  d.v.resize(v.size() - b.v.size() + 1);
  // precompute the reciprocal of the divisor's top three digits + 1; if the top three digits are a3,a2,a1,
  // then db is the reciprocal of a3+a2/base+(a1+1)/base^2, and finally each quotient digit is estimated by multiplication
  // this method works within the int32 range when BIGINT_BASE<=32768
  // but even with int64 it is only usable for BIGINT_BASE<=131072 (limited by the precision of double)
  // it guarantees that the estimate q' and the actual result q satisfy q'<=q<=q'+1
  // so each digit needs only one trial on average, and the carries are handled all at once afterwards
  // if a larger base is to be used, a different trial scheme is needed
  double t = (b.get((unsigned)b.v.size() - 2) +
              (b.get((unsigned)b.v.size() - 3) + 1.0) / BIGINT_BASE);
  double db = 1.0 / (b.v.back() + t / BIGINT_BASE);
  for (size_t i = v.size() - 1, j = d.v.size() - 1; j <= v.size();) {
    int rm = r.get(i + 1) * BIGINT_BASE + r.get(i);
    int m = std::max((int)(db * rm), r.get(i + 1));
    r.sub_mul(b, m, j);
    d.v[j] += m;
    if (!r.get(i + 1))  // check whether the top digit is already 0, to avoid extreme cases
      --i, --j;
  }
  r.trim();
  // fix the lowest digit of the result
  int carry = 0;
  while (!r.absless(b)) {
    r.subtract(b);
    ++carry;
  }
  // fix the carry of every digit
  for (size_t i = 0; i < d.v.size(); ++i) {
    carry += d.v[i];
    d.v[i] = carry % BIGINT_BASE;
    carry /= BIGINT_BASE;
  }
  d.trim();
  d.sign = sign * b.sign;
  return d;
}

BigIntSimple operator/(const BigIntSimple &b) const {
  BigIntSimple r;
  return div_mod(b, r);
}

BigIntSimple operator%(const BigIntSimple &b) const {
  BigIntSimple r;
  div_mod(b, r);
  return r;
}

Karatsuba multiplication

Let \(n\) denote the number of digits of a big number; then bignum–bignum long multiplication takes \(O(n^2)\) time. This section introduces an algorithm with better time complexity, proposed by the Soviet (Russian) mathematician Anatoly Karatsuba; it is a divide-and-conquer algorithm.

Consider two big decimal integers \(x\) and \(y\), both with \(n\) digits (leading zeros allowed). Pick any \(0 < m < n\) and write

\[ \begin{aligned} x &= x_1 \cdot 10^m + x_0, \\ y &= y_1 \cdot 10^m + y_0, \\ x \cdot y &= z_2 \cdot 10^{2m} + z_1 \cdot 10^m + z_0, \end{aligned} \]

where \(x_0, y_0, z_0, z_1 < 10^m\). We get

\[ \begin{aligned} z_2 &= x_1 \cdot y_1, \\ z_1 &= x_1 \cdot y_0 + x_0 \cdot y_1, \\ z_0 &= x_0 \cdot y_0. \end{aligned} \]

Observe that

\[ z_1 = (x_1 + x_0) \cdot (y_1 + y_0) - z_2 - z_0, \]

so to compute \(z_1\) we only need to compute \((x_1 + x_0) \cdot (y_1 + y_0)\) and subtract \(z_0\) and \(z_2\) from it.

The formula above is in fact the core of Karatsuba's algorithm: it turns a multiplication problem of length \(n\) into \(3\) subproblems of smaller length. If we set \(m = \left\lceil \dfrac n 2 \right\rceil\) and denote the time Karatsuba's algorithm takes to multiply two \(n\)-digit integers by \(T(n)\), then \(T(n) = 3 \cdot T \left(\left\lceil \dfrac n 2 \right\rceil\right) + O(n)\), and by the master theorem \(T(n) = \Theta(n^{\log_2 3}) \approx \Theta(n^{1.585})\).

The whole process can be implemented recursively. For clarity, the code below implements polynomial multiplication via Karatsuba's algorithm and handles all the carries at the end.

karatsuba_mulc.cpp 
int *karatsuba_polymul(int n, int *a, int *b) {
  if (n <= 32) {
    // for small sizes compute directly, to avoid the efficiency loss of further recursion
    int *r = new int[n * 2 + 1]();
    for (int i = 0; i <= n; ++i)
      for (int j = 0; j <= n; ++j) r[i + j] += a[i] * b[j];
    return r;
  }

  int m = n / 2 + 1;
  int *r = new int[m * 4 + 1]();
  int *z0, *z1, *z2;

  z0 = karatsuba_polymul(m - 1, a, b);
  z2 = karatsuba_polymul(n - m, a + m, b + m);

  // compute z1
  // temporary modification, restored after the computation
  for (int i = 0; i + m <= n; ++i) a[i] += a[i + m];
  for (int i = 0; i + m <= n; ++i) b[i] += b[i + m];
  z1 = karatsuba_polymul(m - 1, a, b);
  for (int i = 0; i + m <= n; ++i) a[i] -= a[i + m];
  for (int i = 0; i + m <= n; ++i) b[i] -= b[i + m];
  for (int i = 0; i <= (m - 1) * 2; ++i) z1[i] -= z0[i];
  for (int i = 0; i <= (n - m) * 2; ++i) z1[i] -= z2[i];

  // combine z0, z1, z2 to obtain the result
  for (int i = 0; i <= (m - 1) * 2; ++i) r[i] += z0[i];
  for (int i = 0; i <= (m - 1) * 2; ++i) r[i + m] += z1[i];
  for (int i = 0; i <= (n - m) * 2; ++i) r[i + m * 2] += z2[i];

  delete[] z0;
  delete[] z1;
  delete[] z2;
  return r;
}

void karatsuba_mul(int a[], int b[], int c[]) {
  int *r = karatsuba_polymul(LEN - 1, a, b);
  memcpy(c, r, sizeof(int) * LEN);
  for (int i = 0; i < LEN - 1; ++i)
    if (c[i] >= 10) {
      c[i + 1] += c[i] / 10;
      c[i] %= 10;
    }
  delete[] r;
}

Therefore the implementation approach must be chosen according to the actual application scenario.

Efficient big integer multiplication based on polynomials

If the data size reaches \(10^{10^5}\) or more, ordinary bignum multiplication may exceed the time limit. This section introduces how to optimize such multiplication using polynomials.

An \(n\)-digit decimal integer \(a\) can be viewed as a polynomial \(A=a_{0} 10^0+a_{1} 10^1+\cdots+a_{n-1} 10^{n-1}\) whose coefficients are all integers less than \(10\). In this way we have turned the multiplication of two integers into the multiplication of two polynomials.

Ordinary polynomial multiplication still has time complexity \(O(n^2)\), but it can be optimized with algorithms from the polynomial chapter such as the fast Fourier transform and the number-theoretic transform; after optimization the time complexity is \(O(n\log n)\).

Big Big::operator*(const Big& T) const {
  Big res;
  int up;
  int te, tee;
  f(i, 0, len) {
    up = 0;
    f(j, 0, T.len) {
      te = a[i] * T.a[j] + res.a[i + j] + up;
      if (te > MAXN) {
        tee = te - te / (MAXN + 1) * (MAXN + 1);
        up = te / (MAXN + 1);
        res.a[i + j] = tee;
      } else {
        up = 0;
        res.a[i + j] = te;
      }
    }
    if (up) res.a[i + T.len] = up;
  }
  res.len = len + T.len;
  while (res.len > 1 && res.a[res.len - 1] == 0) --res.len;
  return res;
}

Big Big::operator/(const int& b) const {
  Big res;
  int down = 0;
  gd(i, len - 1, 0) {
    res.a[i] = (a[i] + down * (MAXN + 1)) / b;
    down = a[i] + down * (MAXN + 1) - res.a[i] * b;
  }
  res.len = len;
  while (res.len > 1 && res.a[res.len - 1] == 0) --res.len;
  return res;
}

int Big::operator%(const int& b) const {
  int d = 0;
  gd(i, len - 1, 0) d = (d * (MAXN + 1) % b + a[i]) % b;
  return d;
}

Big Big::operator^(const int& n) const {
  Big t(*this), res(1);
  int y = n;
  while (y) {
    if (y & 1) res = res * t;
    t = t * t;
    y >>= 1;
  }
  return res;
}

bool Big::operator<(const Big& T) const {
  int ln;
  if (len < T.len) return true;
  if (len == T.len) {
    ln = len - 1;
    while (ln >= 0 && a[ln] == T.a[ln]) --ln;
    if (ln >= 0 && a[ln] < T.a[ln]) return true;
    return false;
  }
  return false;
}
