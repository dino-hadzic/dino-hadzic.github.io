Bitovne operacije su unarne i binarne operacije nad binarnim zapisom cijelih brojeva, a dijele se na logičke operacije po bitovima i pomake. Bitovne operacije pripadaju najosnovnijim operacijama procesora i obično su vrlo brze.

Cijeli brojevi i nizovi bitova

Vidi i: Cjelobrojni tipovi, Komplementi

Niz fiksne duljine sastavljen samo od znakova 0 i 1 nazivamo nizom bitova. Krajnji lijevi bit nazivamo najvišim (najznačajnijim) bitom, a krajnji desni najnižim (najmanje značajnim) bitom.

Računala nizovima bitova prikazuju cijele brojeve iz određenog raspona. Nizova bitova duljine \(N\) ima samo \(2^N\), pa se mogu bijektivno pridružiti samo \(2^N\) cijelih brojeva. Takva pridruživanja dijele se na dvije vrste: s predznakom (signed) i bez predznaka (unsigned). Pridruživanje s predznakom znači da među pridruženim cijelim brojevima ima negativnih, a bez predznaka da su svi pridruženi cijeli brojevi nenegativni.

  • Kod pridruživanja bez predznaka binarni zapis cijelog broja možemo izravno uzeti kao niz bitova; ako je zapis prekratak, dopunjujemo ga nulama 0 na višim mjestima.

    Uz pridruživanje bez predznaka niz bitova duljine \(N\) može prikazati cijele brojeve iz \([0,2^N-1]\).

  • Kod pridruživanja s predznakom imamo dva pravila prikaza: jedinični komplement (ones' complement) i dvojni komplement (two's complement).

    Za nenegativne cijele brojeve pravilo prikaza isto je kao i bez predznaka. Za negativan cijeli broj uzmemo niz bitova njegova suprotnog broja i invertiramo ga po bitovima (tj. svaku 0 zamijenimo s 1, a svaku 1 s 0); rezultat nazivamo jediničnim komplementom. Ako jedinični komplement pretvorimo u cijeli broj prema pravilu bez predznaka, dodamo jedan, zatim ga prema pravilu bez predznaka pretvorimo natrag u niz bitova i odbacimo dio koji premašuje izvornu duljinu niza, dobiveni novi niz nazivamo dvojnim komplementom.

    Uz jedinični komplement niz bitova duljine \(N\) može prikazati cijele brojeve iz \([-2^{N-1}+1,2^{N-1}-1]\).

    Uz dvojni komplement niz bitova duljine \(N\) može prikazati cijele brojeve iz \([-2^{N-1},2^{N-1}-1]\).

Za primjer uzmimo nizove od \(3\) bita:

Niz bitova Bez predznaka S predznakom (jedinični komplement) S predznakom (dvojni komplement)
000 \(0\) \(0\) \(0\)
001 \(1\) \(1\) \(1\)
010 \(2\) \(2\) \(2\)

Vidimo da je najveći problem jediničnog komplementa pojava „negativnog broja” \(-0\), koji zapravo ne postoji, pa u pravilu koristimo samo dvojni komplement. Budući da pri prikazu cijelih brojeva s predznakom o predznaku odlučuje isključivo najviši bit niza, taj bit nazivamo bitom predznaka.

Pretvaranje niza bitova u cijeli broj također je jednostavno: za nenegativne brojeve nije potrebno ništa posebno, kod jediničnog komplementa inverzijom dobivamo suprotni broj, a kod dvojnog komplementa suprotni broj dobivamo inverzijom i dodavanjem jedinice.

Logičke operacije po bitovima

Logičke operacije po bitovima su operacije koje na niz bitova, bit po bit, primjenjuju neke Booleove funkcije. Formalno, za Booleovu funkciju \(f:\mathbf{B}^k\to \mathbf{B}\) operacija po bitovima jest funkcija oblika

\[ \begin{aligned} F:\left(\mathbf{B}^m\right)^k&\to \mathbf{B}^m\\ ((p_{1,1},\dots,p_{m,1}),\dots,(p_{1,k},\dots,p_{m,k}))&\mapsto (f(p_{1,1},\dots,p_{1,k}),\dots,f(p_{m,1},\dots,p_{m,k})) \end{aligned} \]

gdje je \(m\) duljina niza bitova. Kao i inače, u pravilu proučavamo samo unarne i binarne operacije po bitovima. Ako nije drukčije rečeno, operacije po bitovima u nastavku ograničene su na unarni i binarni slučaj.

Općenito, negaciju po bitovima (NOT), I po bitovima (AND), ILI po bitovima (OR) i isključivo ILI po bitovima (XOR) smatramo osnovnim operacijama po bitovima; sve ostale operacije po bitovima mogu se dobiti njihovim kombiniranjem.

Operacija po bitovima Matematička oznaka Pripadna Booleova funkcija Operator u C++-u Objašnjenje
negacija po bitovima (NOT) \(\operatorname{NOT}\) \(\lnot\) ~ \(0\) postaje \(1\), a \(1\) postaje \(0\)
I po bitovima (AND) \(\operatorname{AND}\) \(\land\) & rezultat je \(1\) samo ako su oba odgovarajuća bita \(1\)
ILI po bitovima (OR) \(\operatorname{OR}\) \(\lor\) | rezultat je \(1\) čim je barem jedan od dvaju odgovarajućih bitova \(1\)
isključivo ILI po bitovima (XOR) \(\oplus\), \(\operatorname{XOR}\) \(\oplus\) ^ rezultat je \(1\) samo ako su dva odgovarajuća bita različita
Upozorenje

Pazite na razliku između operacija po bitovima i Booleovih funkcija.

Na primjer:

  • \(\operatorname{NOT} 01010111=10101000\),
  • \(01010011 \operatorname{AND} 00110010=00010010\),
  • \(01010011 \operatorname{OR} 00110010=01110011\),
  • \(01010011 \operatorname{XOR} 00110010=01100001\).

Budući da se pri izvođenju gornjih četiriju operacija po bitovima računanje na pojedinim bitovima odvija neovisno, te četiri operacije izravno nasljeđuju svojstva pripadnih Booleovih funkcija.

Radi jednostavnosti, kad je duljina niza bitova poznata, operacije po bitovima možemo primjenjivati izravno na cijele brojeve, npr.:

\[ \begin{aligned} \operatorname{NOT} 5&=-6,\\ \operatorname{NOT} (-5)&=4,\\ 5 \operatorname{AND} 6 &=4,\\ 5 \operatorname{OR} 6 &=7,\\ 5 \operatorname{XOR} 6 &=3. \end{aligned} \]

Uz pretpostavku \(x,y\geq 0\) operacije po bitovima možemo zapisati i pomoću suma:

\[ \begin{aligned} \operatorname{NOT} x&=\sum_{n=0}^{\lfloor\log_{2}x\rfloor}2^n\left(\left(\left\lfloor\frac{x}{2^n}\right\rfloor\bmod 2+1\right)\bmod 2\right)\\ &=\sum_{n=0}^{\lfloor\log_{2}x\rfloor}\left(2^{\left\lfloor\log_{2}x\right\rfloor +1}-1-x\right)\\ x\operatorname{AND} y&=\sum_{n=0}^{\lfloor\log_{2}\max\{x,y\}\rfloor}2^n\left(\left\lfloor\frac{x}{2^n}\right\rfloor\bmod 2\right)\left(\left\lfloor{\frac{y}{2^n}}\right\rfloor\bmod 2\right)\\ x\operatorname{OR} y&=\sum_{n=0}^{\lfloor\log_{2}\max\{x,y\}\rfloor}2^n\left(\left(\left\lfloor\frac{x}{2^n}\right\rfloor\bmod 2\right)+\left(\left\lfloor{\frac{y}{2^n}}\right\rfloor\bmod 2\right)-\left(\left\lfloor\frac{x}{2^n}\right\rfloor\bmod 2\right)\left(\left\lfloor{\frac{y}{2^n}}\right\rfloor\bmod 2\right)\right)\\ x\operatorname{XOR} y&=\sum_{n=0}^{\lfloor\log_{2}\max\{x,y\}\rfloor}2^n\left(\left(\left(\left\lfloor\frac{x}{2^n}\right\rfloor\bmod 2\right)+\left(\left\lfloor{\frac{y}{2^n}}\right\rfloor\bmod 2\right)\right)\bmod 2\right)\\ &=\sum_{n=0}^{\lfloor\log_{2}\max\{x,y\}\rfloor}2^n\left(\left(\left\lfloor\frac{x}{2^n}\right\rfloor +\left\lfloor\frac{y}{2^n}\right\rfloor\right)\bmod 2\right) \end{aligned} \]

Kad ne postoji opasnost od zabune, u nastavku izostavljamo „po bitovima”.

Pomak bitova

Vidi i: Bitovni operatori u C++-u.

Pomak (shift) je binarna operacija koja niz bitova „pomiče ulijevo ili udesno bit po bit”; prvi je argument niz bitova, a drugi je u pravilu nenegativan cijeli broj. Pomicanje ulijevo zovemo lijevim pomakom, a udesno desnim pomakom. Prema načinu popunjavanja mjesta ispražnjenih pomicanjem pomake dijelimo na aritmetičke, logičke i kružne (rotacije). Pri tome

  • logički pomak ispražnjena mjesta popunjava nulama 0,
  • aritmetički desni pomak ispražnjena mjesta popunjava bitom predznaka, a aritmetički lijevi pomak jednak je logičkom lijevom pomaku,
  • kružni pomak ispražnjena mjesta popunjava bitovima koji su ispali.

Na primjer, za \(8\)-bitni niz 10 01 01 10:

Operacija Rezultat
aritmetički pomak ulijevo za \(2\) bita 01 01 10 00
aritmetički pomak udesno za \(2\) bita 11 10 01 01
logički pomak ulijevo za \(2\) bita 01 01 10 00
logički pomak udesno za \(2\) bita 00 10 01 01
kružni pomak ulijevo za \(2\) bita 01 01 10 10
kružni pomak udesno za \(2\) bita 10 10 01 01

U C++-u lijevi pomak zapisujemo kao a << b, a desni kao a >> b; koje se pravilo pomaka pri tome primjenjuje, vidi Bitovni operatori u C++-u.

Kružni pomak možemo implementirati sljedećim kodom:

Implementacija 
// From <https://stackoverflow.com/a/776523/224132>
#include <climits>
#include <cstdint>

uint32_t rotl32(uint32_t value, unsigned int count) {
  const unsigned int mask = CHAR_BIT * sizeof(value) - 1;
  count &= mask;
  return (value << count) | (value >> (-count & mask));
}

uint32_t rotr32(uint32_t value, unsigned int count) {
  const unsigned int mask = CHAR_BIT * sizeof(value) - 1;
  count &= mask;
  return (value >> count) | (value << (-count & mask));
}

Primjene bitovnih operacija

Bitovne operacije u pravilu imaju tri uloge:

  1. Učinkovito izvođenje nekih računskih operacija umjesto drugih, sporijih načina. Vidi Optimizacije pri prevođenju – smanjenje snage operacija.
  2. Prikaz skupova (često u DP-u s bitmaskama).
  3. Zadatak sam po sebi zahtijeva bitovne operacije.

Treba imati na umu da zamjena drugih operacija bitovnima često ne donosi veliko ubrzanje, a kod čini složenijim, pa to pri uporabi treba dobro odvagnuti.

Primjene vezane uz potencije broja 2

Budući da bitovne operacije rade nad binarnim zapisom, iz njih proizlaze mnoge primjene vezane uz cjelobrojne potencije broja 2.

Množenje (dijeljenje) broja nenegativnom cjelobrojnom potencijom broja 2:

int mulPowerOfTwo(int n, int m) {  // računa n*(2^m)
  return n << m;
}

int divPowerOfTwo(int n, int m) {  // računa n/(2^m)
  return n >> m;
}

def mulPowerOfTwo(n, m):  # računa n*(2^m)
    return n << m


def divPowerOfTwo(n, m):  # računa n/(2^m)
    return n >> m
Upozorenje

Dijeljenje kakvo obično pišemo zaokružuje prema \(0\), a desni pomak ovdje zaokružuje prema dolje (pazite na tu razliku); dakle, za brojeve veće ili jednake \(0\) oba su načina ekvivalentna, a za brojeve manje od \(0\) postoji razlika, npr. vrijednost -1 / 2 jest \(0\), a vrijednost -1 >> 1 jest \(-1\).

Apsolutna vrijednost

Na nekim je strojevima učinkovitije od n > 0 ? n : -n.

int Abs(int n) {
  return (n ^ (n >> 31)) - (n >> 31);
  /* n>>31 daje predznak od n: ako je n pozitivan, n>>31 je 0, ako je n negativan, n>>31 je -1
    ako je n pozitivan, n^0=n, broj se ne mijenja; ako je n negativan, imamo n^(-1)
    treba uzeti dvojne komplemente od n i -1 i napraviti XOR,
    rezultat je n s promijenjenim predznakom, jednak apsolutnoj vrijednosti od n umanjenoj za 1; oduzimanjem -1 dobiva se apsolutna vrijednost */
}

def Abs(n):
    return (n ^ (n >> 31)) - (n >> 31)
    """
    n>>31 daje predznak broja n: ako je n pozitivan, n>>31 je 0, ako je n negativan, n>>31 je -1
    ako je n pozitivan, n^0=n i broj se ne mijenja; ako je n negativan, imamo n^(-1)
    treba izračunati dvojni komplement brojeva n i -1 pa ih povezati operacijom XOR,
    rezultat je n s promijenjenim predznakom, jednak apsolutnoj vrijednosti n umanjenoj za 1; oduzimanjem -1 dobiva se apsolutna vrijednost
    """

Maksimum/minimum dvaju brojeva

Na nekim je strojevima učinkovitije od a > b ? a : b.

// ako je a >= b, (a - b) >> 31 je 0, inače je -1
int max(int a, int b) { return (b & ((a - b) >> 31)) | (a & (~(a - b) >> 31)); }

int min(int a, int b) { return (a & ((a - b) >> 31)) | (b & (~(a - b) >> 31)); }

# ako je a >= b, (a - b) >> 31 je 0, inače je -1
def max(a, b):
    return b & ((a - b) >> 31) | a & (~(a - b) >> 31)


def min(a, b):
    return a & ((a - b) >> 31) | b & (~(a - b) >> 31)

Provjera imaju li dva broja različita od nule isti predznak

bool isSameSign(int x, int y) {  // slučaj s 0 je iznimka
  return (x ^ y) >= 0;
}

# slučaj s 0 je iznimka
def isSameSign(x, y):
    return (x ^ y) >= 0

Zamjena dvaju brojeva

Metoda ima ograničenja

Ovim se načinom mogu zamijeniti samo dva cijela broja, pa je raspon primjene ograničen.

Za zamjenu u općem slučaju preporučuje se izravno pozvati funkciju std::swap iz biblioteke algorithm.

void swap(int& a, int& b) { a ^= b ^= a ^= b; }

Rad s pojedinim bitovima broja

Dohvaćanje određenog bita binarnog zapisa broja:

// dohvaća b-ti bit od a, najniži bit ima indeks 0
int getBit(int a, int b) { return (a >> b) & 1; }

# dohvaća b-ti bit od a, najniži bit ima indeks 0
def getBit(a, b):
    return (a >> b) & 1

Postavljanje određenog bita binarnog zapisa broja na \(0\):

// postavlja b-ti bit od a na 0, najniži bit ima indeks 0
int unsetBit(int a, int b) { return a & ~(1 << b); }

# postavlja b-ti bit od a na 0, najniži bit ima indeks 0
def unsetBit(a, b):
    return a & ~(1 << b)

Postavljanje određenog bita binarnog zapisa broja na \(1\):

// postavlja b-ti bit od a na 1, najniži bit ima indeks 0
int setBit(int a, int b) { return a | (1 << b); }

# postavlja b-ti bit od a na 1, najniži bit ima indeks 0
def setBit(a, b):
    return a | (1 << b)

Invertiranje određenog bita binarnog zapisa broja:

// invertira b-ti bit od a, najniži bit ima indeks 0
int flapBit(int a, int b) { return a ^ (1 << b); }

# invertira b-ti bit od a, najniži bit ima indeks 0
def flapBit(a, b):
    return a ^ (1 << b)

Ove operacije zapravo tretiraju \(32\)-bitnu cjelobrojnu varijablu kao Booleovo polje duljine \(32\).

Hammingova težina

Hammingova težina niza simbola jest broj simbola različitih od nul-simbola (zero-symbol, definiranog nad korištenom abecedom). Za binarni broj Hammingova težina jednaka je broju njegovih jedinica \(1\) (tj. popcount).

Hammingovu težinu broja možemo izračunati petljom: neprestano uklanjamo posljednji bit binarnog zapisa broja (tj. pomičemo ga udesno za \(1\) bit), održavamo varijablu s odgovorom i tijekom dijeljenja ažuriramo odgovor ovisno o tome je li najniži bit \(1\).

Kod je sljedeći:

// računa Hammingovu težinu od x
int popcount(int x) {
  int cnt = 0;
  while (x) {
    cnt += x & 1;
    x >>= 1;
  }
  return cnt;
}

Hammingovu težinu broja možemo izračunati i operacijom lowbit: od broja neprestano oduzimamo njegov lowbit1 dok broj ne postane \(0\).

Kod je sljedeći:

// računa Hammingovu težinu od x
int popcount(int x) {
  int cnt = 0;
  while (x) {
    cnt++;
    x -= x & -x;
  }
  return cnt;
}

Konstrukcija permutacije s rastućom Hammingovom težinom

U DP-u s bitmaskama nabrajanje stanja u poretku rastućeg popcounta ponekad omogućuje izbjegavanje ponovnog nabrajanja istih stanja. To je jedna od glavnih primjena konstrukcije permutacije s rastućom Hammingovom težinom.

U nastavku konkretno istražujemo kako u vremenu \(O(n)\) konstruirati permutaciju s rastućom Hammingovom težinom.

Znamo da je najmanji cijeli broj Hammingove težine \(n\) jednak \(2^n-1\). Ako za cijeli broj u konstantnom vremenu možemo konstruirati sljedbenika jednake Hammingove težine, onda nabrajanjem Hammingovih težina i neprestanim traženjem sljedećeg broja počevši od \(2^n-1\) u vremenu \(O(n)\) konstruiramo traženu permutaciju brojeva \(0\sim n\).

Sljedbenika broja \(x\) s jednakom Hammingovom težinom pronalazimo prema ovoj ideji, na primjeru \((10110)_2\):

  • Krajnju desnu jedinicu \(1\) broja \((10110)_2\) pomaknemo ulijevo; ako se ne može pomaknuti, pomaknemo jedinicu \(1\) lijevo od nje, i tako dalje. Dobivamo \((11010)_2\).

  • U dobivenom \((11010)_2\) sve jedinice \(1\) od izvornog položaja posljednje pomaknute jedinice \(1\) do najnižeg bita pomaknemo skroz udesno. Ovdje je posljednja pomaknuta jedinica \(1\) izvorno bila na trećem mjestu, pa posljednja tri bita \(010\) moraju postati \(001\) i dobivamo \((11001)_2\).

Taj se postupak može optimizirati bitovnim operacijama:

  int t = x + (x & -x);
  x = t | ((((t & -t) / (x & -x)) >> 1) - 1);
  • U prvom koraku broju \(x\) dodajemo njegov lowbit, što u binarnom zapisu znači da krajnji desni neprekinuti blok jedinica \(1\) broja \(x\) zamjenjujemo jednom jedinicom \(1\) lijevo od njega. Primjerice, maloprije spomenuti binarni broj \((10110)_2\) nakon dodavanja svojeg lowbit-a postaje \((11000)_2\). Time smo zapravo dobili prvu polovicu odgovora.
  • Zatim moramo nadopuniti jedinice \(1\) na kraju odgovora. lowbit od \(t\) jest položaj na koji je pomaknuta krajnja lijeva jedinica \(1\) krajnjeg desnog neprekinutog bloka jedinica \(1\) broja \(x\), a lowbit od \(x\) jest položaj krajnje desne jedinice \(1\) tog bloka broja \(x\). Opet na primjeru \((10110)_2\): \(t = (11000)_2\), \(\operatorname{lowbit}(t) = (01000)_2\), \(\operatorname{lowbit}(x)=(00010)_2\).
  • Dijeljenje koje slijedi najteži je dio ove bitovne tehnike za razumijevanje, ali i najvažniji. Neka se najviša jedinica \(1\) krajnjeg desnog neprekinutog bloka jedinica \(1\) izvornog broja nalazi na \(r\)-tom bitu (bitove brojimo od \(0\)), a najniža jedinica \(1\) na \(l\)-tom bitu; lowbit od \(t\) jednak je 1 << (r+1), lowbit od \(x\) jednak je 1 << l, a (((t&-t)/(x&-x))>>1) daje (1<<(r+1))/(1<<l)/2 = (1<<r)/(1<<l) = 1<<(r-l), što je u binarnom zapisu jedinica \(1\) iza koje slijedi \(r-l\) nula, a broj nula upravo je jednak broju uzastopnih jedinica \(1\) umanjenom za \(1\). Na našem primjeru: \(\frac{\operatorname{lowbit(t)/2}}{\operatorname{lowbit(x)}} = \frac{(00100)_2}{(00010)_2} = (00010)_2\). Oduzmemo li od tog broja \(1\), dobivamo upravo niže bitove koje treba nadopuniti, a OR s izvornim brojem daje odgovor.

Potpuni kod za nabrajanje permutacije brojeva \(0\sim n\) u poretku rastuće Hammingove težine stoga glasi:

  for (int i = 0; (1 << i) - 1 <= n; i++) {
    for (int x = (1 << i) - 1, t; x <= n; t = x + (x & -x),
             x = x ? (t | ((((t & -t) / (x & -x)) >> 1) - 1)) : (n + 1)) {
      // ovdje napišite operacije koje treba obaviti
    }
  }

Pri tome treba posebno obraditi \(0\), jer \(0\) nema sljedbenika iste Hammingove težine.

Srodne klase i funkcije u C++-u

Ugrađene funkcije GCC-a

GCC ima i nekoliko ugrađenih (built-in) funkcija za bitovne operacije:

  • int __builtin_ffs(int x): vraća položaj posljednje jedinice \(1\) na kraju binarnog zapisa od \(x\); položaji se broje od \(1\) (najniži bit ima broj \(1\)). Kad je \(x\) jednak \(0\), vraća \(0\).
  • int __builtin_clz(unsigned int x): vraća broj vodećih nula \(0\) u binarnom zapisu od \(x\). Kad je \(x\) jednak \(0\), rezultat nije definiran.
  • int __builtin_ctz(unsigned int x): vraća broj uzastopnih nula \(0\) na kraju binarnog zapisa od \(x\). Kad je \(x\) jednak \(0\), rezultat nije definiran.
  • int __builtin_clrsb(int x): kad je bit predznaka od \(x\) jednak \(0\), vraća broj vodećih nula \(0\) u binarnom zapisu od \(x\) umanjen za jedan; inače vraća broj vodećih jedinica \(1\) u binarnom zapisu od \(x\) umanjen za jedan.
  • int __builtin_popcount(unsigned int x): vraća broj jedinica \(1\) u binarnom zapisu od \(x\).
  • int __builtin_parity(unsigned int x): određuje parnost broja jedinica \(1\) u binarnom zapisu od \(x\).

Svim ovim funkcijama na kraj imena možemo dodati l ili ll (npr. __builtin_popcountll) kako bi tip argumenta postao (unsigned)long odnosno (unsigned)long long (povratna vrijednost i dalje je tipa int). Primjerice, ponekad želimo izračunati logaritam broja po bazi dva; ako zanemarimo poseban slučaj 0, to je jednako broju bitova binarnog zapisa tog broja -1, a broj bitova binarnog zapisa N-bitnog cijelog broja n može se izraziti kao N - __builtin_clz(n), pa N - 1 - __builtin_clz(n) daje logaritam od n po bazi dva.

Budući da su to ugrađene funkcije koje prevodilac snažno optimizira, izvršavaju se vrlo brzo (nekima je dovoljna čak samo jedna instrukcija).

Bit operations are unary and binary operations on the binary representation of integers; they fall into two classes, bitwise operations and shifts. Bit operations are among the most basic operations of a CPU and are usually very fast.

Integers and bit sequences

See also: Integer types, Complement representations

We call a fixed-length sequence consisting only of 0 and 1 a bit sequence. The leftmost bit is called the most significant bit and the rightmost bit the least significant bit.

Computers use bit sequences to represent integers in a certain range. There are only \(2^N\) bit sequences of length \(N\), so they can be put in one-to-one correspondence with only \(2^N\) integers. Such correspondences fall into two classes: signed and unsigned. Signed means that the corresponding integers include negative numbers; unsigned means that all corresponding integers are nonnegative.

  • For the unsigned correspondence we can directly take the binary representation of the integer as the bit sequence, padding with 0 in the high positions if it is too short.

    Under the unsigned correspondence, a bit sequence of length \(N\) can represent the integers in \([0,2^N-1]\).

  • For the signed correspondence we have two representation rules: ones' complement and two's complement.

    For nonnegative integers the representation rule is the same as the unsigned one. For a negative integer, we take the bit sequence of its opposite number and invert it bitwise (i.e., turn every 0 into 1 and every 1 into 0); the result is called the ones' complement. If we convert the ones' complement to an integer under the unsigned correspondence, add one, convert it back to a bit sequence under the unsigned correspondence and discard the part exceeding the original length of the sequence, the new sequence we obtain is called the two's complement.

    Under ones' complement, a bit sequence of length \(N\) can represent the integers in \([-2^{N-1}+1,2^{N-1}-1]\).

    Under two's complement, a bit sequence of length \(N\) can represent the integers in \([-2^{N-1},2^{N-1}-1]\).

Take bit sequences of length \(3\) as an example:

Bit sequence Unsigned integer Signed integer (ones' complement) Signed integer (two's complement)
000 \(0\) \(0\) \(0\)
001 \(1\) \(1\) \(1\)
010 \(2\) \(2\) \(2\)
011 \(3\) \(3\) \(3\)
100 \(4\) \(-3\) \(-4\)
101 \(5\) \(-2\) \(-3\)
110 \(6\) \(-1\) \(-2\)
111 \(7\) \(-0\) \(-1\)

We can see that the biggest problem of ones' complement is the appearance of \(-0\), a "negative number" that does not actually exist, so normally we only use two's complement. Since, when representing signed integers, the sign is determined solely by the most significant bit of the sequence, we call this bit the sign bit.

Converting a bit sequence to an integer is also easy: for nonnegative numbers nothing special is needed; for ones' complement, inverting gives the opposite number; for two's complement, inverting and adding one gives the opposite number.

Bitwise operations

Bitwise operations are operations that apply certain Boolean functions to a bit sequence bit by bit. Formally, for a Boolean function \(f:\mathbf{B}^k\to \mathbf{B}\), the bitwise operation is the function of the form

\[ \begin{aligned} F:\left(\mathbf{B}^m\right)^k&\to \mathbf{B}^m\\ ((p_{1,1},\dots,p_{m,1}),\dots,(p_{1,k},\dots,p_{m,k}))&\mapsto (f(p_{1,1},\dots,p_{1,k}),\dots,f(p_{m,1},\dots,p_{m,k})) \end{aligned} \]

where \(m\) is the length of the bit sequence. As usual, we generally study only unary and binary bitwise operations. Unless otherwise stated, the bitwise operations below are restricted to the unary and binary cases.

In general, we regard bitwise NOT, bitwise AND, bitwise OR and bitwise XOR as the basic bitwise operations; all other bitwise operations can be obtained by combining them.

Bitwise operation Mathematical notation Corresponding Boolean function C++ operator Explanation
bitwise NOT \(\operatorname{NOT}\) \(\lnot\) ~ \(0\) becomes \(1\), \(1\) becomes \(0\)
bitwise AND \(\operatorname{AND}\) \(\land\) & \(1\) only if both corresponding bits are \(1\)
bitwise OR \(\operatorname{OR}\) \(\lor\) | \(1\) as soon as at least one of the two corresponding bits is \(1\)
bitwise XOR \(\oplus\), \(\operatorname{XOR}\) \(\oplus\) ^ \(1\) only if the two corresponding bits differ
Warning

Be careful to distinguish bitwise operations from Boolean functions.

For example:

  • \(\operatorname{NOT} 01010111=10101000\),
  • \(01010011 \operatorname{AND} 00110010=00010010\),
  • \(01010011 \operatorname{OR} 00110010=01110011\),
  • \(01010011 \operatorname{XOR} 00110010=01100001\).

Since in the four bitwise operations above the computation on each bit is independent, these four operations directly inherit the properties of their corresponding Boolean functions.

For convenience, when the length of the bit sequence is known, we can also apply bitwise operations directly to integers, for example:

\[ \begin{aligned} \operatorname{NOT} 5&=-6,\\ \operatorname{NOT} (-5)&=4,\\ 5 \operatorname{AND} 6 &=4,\\ 5 \operatorname{OR} 6 &=7,\\ 5 \operatorname{XOR} 6 &=3. \end{aligned} \]

Assuming \(x,y\geq 0\), we can also express bitwise operations as sums:

\[ \begin{aligned} \operatorname{NOT} x&=\sum_{n=0}^{\lfloor\log_{2}x\rfloor}2^n\left(\left(\left\lfloor\frac{x}{2^n}\right\rfloor\bmod 2+1\right)\bmod 2\right)\\ &=\sum_{n=0}^{\lfloor\log_{2}x\rfloor}\left(2^{\left\lfloor\log_{2}x\right\rfloor +1}-1-x\right)\\ x\operatorname{AND} y&=\sum_{n=0}^{\lfloor\log_{2}\max\{x,y\}\rfloor}2^n\left(\left\lfloor\frac{x}{2^n}\right\rfloor\bmod 2\right)\left(\left\lfloor{\frac{y}{2^n}}\right\rfloor\bmod 2\right)\\ x\operatorname{OR} y&=\sum_{n=0}^{\lfloor\log_{2}\max\{x,y\}\rfloor}2^n\left(\left(\left\lfloor\frac{x}{2^n}\right\rfloor\bmod 2\right)+\left(\left\lfloor{\frac{y}{2^n}}\right\rfloor\bmod 2\right)-\left(\left\lfloor\frac{x}{2^n}\right\rfloor\bmod 2\right)\left(\left\lfloor{\frac{y}{2^n}}\right\rfloor\bmod 2\right)\right)\\ x\operatorname{XOR} y&=\sum_{n=0}^{\lfloor\log_{2}\max\{x,y\}\rfloor}2^n\left(\left(\left(\left\lfloor\frac{x}{2^n}\right\rfloor\bmod 2\right)+\left(\left\lfloor{\frac{y}{2^n}}\right\rfloor\bmod 2\right)\right)\bmod 2\right)\\ &=\sum_{n=0}^{\lfloor\log_{2}\max\{x,y\}\rfloor}2^n\left(\left(\left\lfloor\frac{x}{2^n}\right\rfloor +\left\lfloor\frac{y}{2^n}\right\rfloor\right)\bmod 2\right) \end{aligned} \]

When no ambiguity arises, "bitwise" is omitted below.

Bit shifts

See also: C++ bit operators.

A shift is a binary operation that "moves a bit sequence left or right bit by bit"; the first argument is the bit sequence and the second is usually a nonnegative integer. Moving left is called a left shift, moving right a right shift. According to how the vacated positions are filled, shifts are divided into arithmetic shifts, logical shifts and circular shifts (rotations). Here

  • a logical shift fills the vacated positions with 0,
  • an arithmetic right shift fills the vacated positions with the sign bit, and an arithmetic left shift is the same as a logical left shift,
  • a circular shift fills the vacated positions with the bits that were shifted out.

For example, for the \(8\)-bit sequence 10 01 01 10:

Operation Result
arithmetic left shift by \(2\) bits 01 01 10 00
arithmetic right shift by \(2\) bits 11 10 01 01
logical left shift by \(2\) bits 01 01 10 00
logical right shift by \(2\) bits 00 10 01 01
circular left shift by \(2\) bits 01 01 10 10
circular right shift by \(2\) bits 10 10 01 01

In C++, a << b denotes a left shift and a >> b a right shift; for which shift rule is applied, see C++ bit operators.

We can implement circular shifts with the following code:

Implementation 
// From <https://stackoverflow.com/a/776523/224132>
#include <climits>
#include <cstdint>

uint32_t rotl32(uint32_t value, unsigned int count) {
  const unsigned int mask = CHAR_BIT * sizeof(value) - 1;
  count &= mask;
  return (value << count) | (value >> (-count & mask));
}

uint32_t rotr32(uint32_t value, unsigned int count) {
  const unsigned int mask = CHAR_BIT * sizeof(value) - 1;
  count &= mask;
  return (value >> count) | (value << (-count & mask));
}

Applications of bit operations

Bit operations generally serve three purposes:

  1. Performing certain computations efficiently, replacing other, less efficient ways. See Compiler optimizations – strength reduction.
  2. Representing sets (commonly used in bitmask DP).
  3. The problem itself requires bit operations.

Note that replacing other operations with bit operations often does not bring much optimization and instead makes the code more complex, so use them judiciously.

Applications involving powers of 2

Since bit operations act on the binary representation, many applications related to integer powers of 2 can be derived.

Multiplying (dividing) a number by a nonnegative integer power of 2:

int mulPowerOfTwo(int n, int m) {  // compute n*(2^m)
  return n << m;
}

int divPowerOfTwo(int n, int m) {  // compute n/(2^m)
  return n >> m;
}

def mulPowerOfTwo(n, m):  # compute n*(2^m)
    return n << m


def divPowerOfTwo(n, m):  # compute n/(2^m)
    return n >> m
Warning

The division we usually write rounds toward \(0\), while the right shift here rounds down (note the difference); that is, the two methods are equivalent when the number is greater than or equal to \(0\) and differ when the number is less than \(0\). For example, the value of -1 / 2 is \(0\), while the value of -1 >> 1 is \(-1\).

Absolute value

On some machines this is more efficient than n > 0 ? n : -n.

int Abs(int n) {
  return (n ^ (n >> 31)) - (n >> 31);
  /* n>>31 gives the sign of n: if n is positive, n>>31 equals 0, if n is negative, n>>31 equals -1
    if n is positive, n^0=n, the number is unchanged; if n is negative we have n^(-1)
    we need the two's complements of n and -1 and then XOR them,
    the result is n with flipped sign, equal to the absolute value of n minus 1; subtracting -1 gives the absolute value */
}

def Abs(n):
    return (n ^ (n >> 31)) - (n >> 31)
    """
    n>>31 gives the sign of n: if n is positive, n>>31 equals 0; if n is negative, n>>31 equals -1
    if n is positive, n^0=n and the number is unchanged; if n is negative, we have n^(-1)
    we need the two's complement of n and -1 and then XOR them,
    the result is n with its sign flipped, equal to the absolute value of n minus 1; subtracting -1 gives the absolute value
    """

Checking whether two nonzero numbers have the same sign

bool isSameSign(int x, int y) {  // the case with 0 is an exception
  return (x ^ y) >= 0;
}

# the case with 0 is an exception
def isSameSign(x, y):
    return (x ^ y) >= 0

Manipulating the bits of a number

Getting a certain bit of the binary representation of a number:

// get bit b of a, the lowest bit has index 0
int getBit(int a, int b) { return (a >> b) & 1; }

# get bit b of a, the lowest bit has index 0
def getBit(a, b):
    return (a >> b) & 1

Setting a certain bit of the binary representation of a number to \(0\):

// set bit b of a to 0, the lowest bit has index 0
int unsetBit(int a, int b) { return a & ~(1 << b); }

# set bit b of a to 0, the lowest bit has index 0
def unsetBit(a, b):
    return a & ~(1 << b)

Setting a certain bit of the binary representation of a number to \(1\):

// set bit b of a to 1, the lowest bit has index 0
int setBit(int a, int b) { return a | (1 << b); }

# set bit b of a to 1, the lowest bit has index 0
def setBit(a, b):
    return a | (1 << b)

Flipping a certain bit of the binary representation of a number:

// flip bit b of a, the lowest bit has index 0
int flapBit(int a, int b) { return a ^ (1 << b); }

# flip bit b of a, the lowest bit has index 0
def flapBit(a, b):
    return a ^ (1 << b)

These operations effectively treat a \(32\)-bit integer variable as a Boolean array of length \(32\).

Hamming weight

The Hamming weight of a string of symbols is the number of symbols that differ from the zero-symbol (defined over the alphabet in use). For a binary number, its Hamming weight equals the number of \(1\)s in it (i.e., popcount).

The Hamming weight of a number can be computed with a loop: we repeatedly remove the last bit of the number's binary representation (i.e., shift it right by \(1\) bit), maintain an answer variable, and during the division update the answer according to whether the lowest bit is \(1\).

The code is as follows:

// compute the Hamming weight of x
int popcount(int x) {
  int cnt = 0;
  while (x) {
    cnt += x & 1;
    x >>= 1;
  }
  return cnt;
}

The Hamming weight of a number can also be computed with the lowbit operation: we repeatedly subtract its lowbit1 from the number until the number becomes \(0\).

The code is as follows:

// compute the Hamming weight of x
int popcount(int x) {
  int cnt = 0;
  while (x) {
    cnt++;
    x -= x & -x;
  }
  return cnt;
}

Constructing a permutation with increasing Hamming weight

In bitmask DP, enumerating in order of increasing popcount can sometimes avoid enumerating states repeatedly. This is a major use of constructing a permutation with increasing Hamming weight.

Below we explore concretely how to construct a permutation with increasing Hamming weight in \(O(n)\) time.

We know that the smallest integer with Hamming weight \(n\) is \(2^n-1\). As long as we can construct, in constant time, the successor of an integer with the same Hamming weight, we can enumerate the Hamming weights and, starting from \(2^n-1\), keep finding the next number, thus constructing the required permutation of \(0\sim n\) in \(O(n)\) time.

To find the successor of a number \(x\) with the same Hamming weight, the idea is as follows, taking \((10110)_2\) as an example:

  • Move the rightmost \(1\) of \((10110)_2\) to the left; if it cannot be moved, move the \(1\) to its left, and so on, obtaining \((11010)_2\).

  • In the resulting \((11010)_2\), move all the \(1\)s from the original position of the last moved \(1\) down to the lowest bit all the way to the right. Here the last moved \(1\) was originally in the third position, so the last three bits \(010\) must become \(001\), giving \((11001)_2\).

This process can be optimized with bit operations:

  int t = x + (x & -x);
  x = t | ((((t & -t) / (x & -x)) >> 1) - 1);
  • In the first step, we add to the number \(x\) its lowbit; in binary this amounts to replacing the rightmost contiguous block of \(1\)s of \(x\) with a single \(1\) to its left. For the binary number \((10110)_2\) just mentioned, after adding its lowbit it becomes \((11000)_2\). This actually gives the first half of our answer.
  • Next we need to fill in the trailing \(1\)s of the answer. The lowbit of \(t\) is the position to which the leftmost \(1\) of the rightmost contiguous block of \(1\)s of \(x\) has moved, while the lowbit of \(x\) is the position of the rightmost \(1\) of that block of \(x\). Again with \((10110)_2\) as the example, \(t = (11000)_2\), \(\operatorname{lowbit}(t) = (01000)_2\), \(\operatorname{lowbit}(x)=(00010)_2\).
  • The division that follows is the hardest part of this bit trick to understand, but also the most crucial. Suppose the highest \(1\) of the rightmost contiguous block of \(1\)s of the original number is at bit \(r\) (bits numbered from \(0\)) and the lowest \(1\) is at bit \(l\); the lowbit of \(t\) equals 1 << (r+1), the lowbit of \(x\) equals 1 << l, and (((t&-t)/(x&-x))>>1) yields (1<<(r+1))/(1<<l)/2 = (1<<r)/(1<<l) = 1<<(r-l), which in binary is a \(1\) followed by \(r-l\) zeros, where the number of zeros is exactly the number of consecutive \(1\)s minus \(1\). Taking our number as an example, \(\frac{\operatorname{lowbit(t)/2}}{\operatorname{lowbit(x)}} = \frac{(00100)_2}{(00010)_2} = (00010)_2\). Subtracting \(1\) from this number gives exactly the low bits we need to fill in, and OR-ing it with the original number gives the answer.

So the complete code for enumerating the permutation of \(0\sim n\) in order of increasing Hamming weight is:

  for (int i = 0; (1 << i) - 1 <= n; i++) {
    for (int x = (1 << i) - 1, t; x <= n; t = x + (x & -x),
             x = x ? (t | ((((t & -t) / (x & -x)) >> 1) - 1)) : (n + 1)) {
      // write the operations to perform here
    }
  }

Note the special handling of \(0\), since \(0\) has no successor with the same Hamming weight.

Related classes and functions in C++

GCC built-in functions

GCC also has some built-in functions for bit operations:

  • int __builtin_ffs(int x): returns the position of the last \(1\) at the end of the binary representation of \(x\), with positions numbered from \(1\) (the lowest bit is number \(1\)). Returns \(0\) when \(x\) is \(0\).
  • int __builtin_clz(unsigned int x): returns the number of leading \(0\)s in the binary representation of \(x\). The result is undefined when \(x\) is \(0\).
  • int __builtin_ctz(unsigned int x): returns the number of trailing consecutive \(0\)s in the binary representation of \(x\). The result is undefined when \(x\) is \(0\).
  • int __builtin_clrsb(int x): when the sign bit of \(x\) is \(0\), returns the number of leading \(0\)s in the binary representation of \(x\) minus one; otherwise returns the number of leading \(1\)s in the binary representation of \(x\) minus one.
  • int __builtin_popcount(unsigned int x): returns the number of \(1\)s in the binary representation of \(x\).
  • int __builtin_parity(unsigned int x): determines the parity of the number of \(1\)s in the binary representation of \(x\).

All of these functions can have l or ll appended to the function name (e.g., __builtin_popcountll) to change the argument type to (unsigned)long or (unsigned)long long (the return value is still of type int). For example, we sometimes want the base-two logarithm of a number; ignoring the special case 0, this equals the number of bits in the number's binary representation -1, and the number of bits in the binary representation of an N-bit integer n can be expressed as N - __builtin_clz(n), so N - 1 - __builtin_clz(n) gives the base-two logarithm of n.

Since these are built-in functions, highly optimized by the compiler, they run very fast (some need only a single instruction).
