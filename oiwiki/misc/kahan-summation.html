Uvod

Algoritam Kahanova zbrajanja (Kahan summation), poznat i kao kompenzirano zbrajanje ili zbrajanje s prijenosom, algoritam je za smanjenje pogreške pri akumuliranju zbroja niza brojeva s pomičnim zarezom konačne preciznosti. Postiže to uglavnom tako da u zasebnoj varijabli (obično nazvanoj \(c\)) akumulira pogrešku.

Algoritam je 1960-ih otkrio uglavnom William Kahan. Budući da je sličan algoritam neovisno predložio i Ivo Babuška, Kahanovo se zbrajanje naziva i Kahan–Babuškino zbrajanje.

Pogreška zaokruživanja

U računalnim programima realne brojeve moramo približno prikazivati konačnim brojem znamenaka; većina današnjih računala za taj približni prikaz koristi brojeve s pomičnim zarezom propisane standardom IEEE-754. Broj \(\frac{1}{3}\) ne možemo točno prikazati konačnim brojem znamenaka, pa se pri zapisu po IEEE-754 dio vrijednosti mora zaokružiti (odrezati, truncate). Ta je pogreška zaokruživanja (rounding off error) svojstvo računanja s pomičnim zarezom.

Pri zbrajanju brojeva s pomičnim zarezom vrijedi komutativnost (commutativity), ali ne i asocijativnost (associativity). Drugim riječima, \(a+b = b+a\), ali \((a+b)+c \neq a+(b+c)\). Zato pri zbrajanju niza brojeva s pomičnim zarezom možemo zbrajati jedan po jedan slijeva nadesno, a možemo ih i, zadržavajući izvorni redoslijed, grupirati u parove. Drugi je postupak razmjerno sporiji i treba više memorije, a često ga koriste posebne funkcije za zbrajanje u nekim jezicima, ali daje razmjerno točniji rezultat.

Da bismo dobili točniji rezultat zbrajanja brojeva s pomičnim zarezom, trebamo algoritam Kahanova zbrajanja.

Pri računanju \(S_{new}=S_{old}+a\) (\(a\) je jedan broj iz niza brojeva s pomičnim zarezom) definiramo vrijednost koja je stvarno dodana u \(S\) kao \(a_{eff}=S_{new}-S_{old}\); ako je \(a_{eff}\) veći od \(a\), došlo je do zaokruživanja prema gore, a ako je \(a_{eff}\) manji od \(a\), došlo je do zaokruživanja prema dolje. Pogreška zaokruživanja definira se kao \(E_{roundoff} = a_{eff} - a\). Vrijednost kojom se ta pogreška zaokruživanja ispravlja tada je \(a-a_{eff}\), tj. negativna vrijednost od \(E_{roundoff}\). Ako je \(c\) varijabla koja kompenzira izgubljene niže znamenke, dobivamo \(c_{new} = c_{old} + (a - a_{eff})\).

Postupak

Algoritam Kahanova zbrajanja pogrešku akumulira u zasebnoj varijabli. Kao što pokazuje referentni kod u nastavku, \(sum\) je konačni rezultat zbrajanja koji se vraća. \(c\) je varijabla koja kompenzira izgubljene niže znamenke (dio koji je odbačen) i nužna je varijabla algoritma Kahanova zbrajanja.

Budući da je \(sum\) velik, a \(y\) malen, niže se znamenke od \(y\) gube. \((t - sum)\) poništava viši dio od \(y\), a oduzimanjem \(y\) dobiva se negativna vrijednost (niži dio od \(y\)). Zato je algebarski \(c\) uvijek nula. U sljedećoj iteraciji izgubljeni se niži dio pribraja u \(y\).

Implementacija

Referentni kod 
float kahanSum(vector<float> nums) {
  float sum = 0.0f;
  float c = 0.0f;
  for (auto num : nums) {
    float y = num - c;
    float t = sum + y;
    c = (t - sum) - y;
    sum = t;
  }
  return sum;
}

Zadaci za vježbu

U OI-ju Kahanovo zbrajanje postoji uglavnom kao pomoćni alat koji rezultatu računanja daje manju pogrešku.

Primjer CodeForces Contest 800 Problem A. Voltage Keepsake

Postoji \(n\) uređaja koji se koriste istodobno. \(i\)-ti uređaj troši \(a_{i}\) jedinica energije u sekundi. Potrošnja je kontinuirana, tj. u \(\lambda\) sekundi uređaj potroši \(\lambda \times a_{i}\) jedinica energije. \(i\)-ti uređaj trenutačno ima pohranjeno \(b_{i}\) jedinica energije. Svi uređaji mogu pohraniti proizvoljnu količinu energije. Postoji jedan punjač koji se može priključiti na bilo koji pojedini uređaj. Punjač uređaju dodaje \(p\) jedinica energije u sekundi. Punjenje je kontinuirano, tj. ako je uređaj priključen \(\lambda\) sekundi, dobit će \(\lambda \times p\) jedinica energije. Uređaj koji se puni možemo promijeniti u bilo kojem trenutku (uključujući realne trenutke; vrijeme prebacivanja zanemarujemo). Odredite koliko se najdulje uređaji mogu koristiti prije nego što energija nekog od njih padne na \(0\) jedinica.

Primjer CodeForces Contest 504 Problem B. Misha and Permutations Summation

Zbroj dviju permutacija \(p\) i \(q\) brojeva \(0, 1, \cdots, (n - 1)\) definiran je kao \(Perm((Ord(p)+Ord(q))\bmod n!)\), gdje je \(Perm(x)\) \(x\)-ta permutacija brojeva \(0, 1, \cdots, (n-1)\) u leksikografskom poretku (brojeći od nule), a \(Ord(p)\) je broj permutacija koje su leksikografski manje od \(p\). Na primjer, \(Perm(0) = (0, 1, \cdots , n - 2, n - 1)\), \(Perm(n! - 1) = (n - 1, n-2,\cdots, 1,0))\). Misha ima dvije permutacije \(p\) i \(q\); odredite njihov zbroj.

Zbrajanje u programskim jezicima

Standardna biblioteka Pythona propisuje funkciju fsum za točno zaokruženo zbrajanje, kojom se može dobiti točan zbroj vrijednosti s pomičnim zarezom iz iterabilnog objekta; gubitak preciznosti izbjegava Shewchukovim algoritmom, prateći više međuzbrojeva.

U jeziku Julia zadana implementacija funkcije sum jest zbrajanje u parovima, radi visoke točnosti i dobrih performansi. Istodobno funkcija vanjske biblioteke sum_kbn nudi implementaciju Neumaierove varijante za slučajeve u kojima je potrebna veća točnost; vidi KahanSummation.jl.

Introduction

The Kahan summation algorithm, also known as compensated summation or carry summation, is an algorithm for reducing the error when accumulating the sum of a sequence of finite-precision floating-point numbers. It achieves this mainly by keeping a separate variable (commonly named \(c\)) that accumulates the error.

The algorithm was discovered mainly by William Kahan in the 1960s. Since Ivo Babuška independently proposed a similar algorithm, Kahan summation is also known as Kahan–Babuška summation.

Rounding error

In computer programs, we need to approximate real numbers with a finite number of digits; most of today's computers use the floating-point numbers specified by IEEE-754 as this approximation. Since we cannot represent \(\frac{1}{3}\) exactly with a finite number of digits, part of the value must be rounded off (truncated) when using the IEEE-754 representation. This rounding off error is a characteristic of floating-point computation.

In floating-point addition, commutativity holds, but associativity does not. That is, \(a+b = b+a\) but \((a+b)+c \neq a+(b+c)\). Therefore, when adding a sequence of floating-point numbers, we can either accumulate them one by one from left to right, or group them into pairs while keeping the original order. The second method is relatively slower and needs more memory, and it is often used by the dedicated summation functions of some languages, but its result is relatively more accurate.

To obtain a more accurate floating-point sum, we need the Kahan summation algorithm.

When computing \(S_{new}=S_{old}+a\) (\(a\) is one value of the floating-point sequence), define the value actually added to \(S\) as \(a_{eff}=S_{new}-S_{old}\); if \(a_{eff}\) is larger than \(a\), there was an upward rounding error, and if \(a_{eff}\) is smaller than \(a\), there was a downward rounding error. The rounding error is then defined as \(E_{roundoff} = a_{eff} - a\). The value used to correct this rounding error is \(a-a_{eff}\), i.e. the negative of \(E_{roundoff}\). Defining \(c\) as the variable that compensates for the lost low-order digits, we get \(c_{new} = c_{old} + (a - a_{eff})\).

Procedure

The Kahan summation algorithm accumulates the error in a separate variable. As shown in the reference code below, \(sum\) is the final accumulated result that is returned. \(c\) is the variable that compensates for the lost low-order digits (the part that was rounded off), and it is the essential variable of the Kahan summation algorithm.

Because \(sum\) is large and \(y\) is small, the low-order digits of \(y\) are lost. \((t - sum)\) cancels the high-order part of \(y\), and subtracting \(y\) recovers the negative value (the low-order part of \(y\)). Therefore, algebraically \(c\) is always zero. In the next iteration, the lost low-order part is added back into \(y\).

Exercises

In OI, Kahan summation exists mainly as an auxiliary tool that provides a computed result with a smaller error.

Example CodeForces Contest 800 Problem A. Voltage Keepsake

There are \(n\) devices used simultaneously. The \(i\)-th device uses \(a_{i}\) units of power per second. This usage is continuous, that is, in \(\lambda\) seconds the device will use \(\lambda \times a_{i}\) units of power. The \(i\)-th device currently has \(b_{i}\) units of power stored. All devices can store an arbitrary amount of power. There is a single charger that can be plugged into any single device. The charger adds \(p\) units of power per second to the device. This charging is continuous, that is, if the device is plugged in for \(\lambda\) seconds, it will gain \(\lambda \times p\) units of power. We can switch which device is being charged at any moment of time (including real moments; the time needed to switch is negligible). Find the maximum amount of time the devices can be used before one of them reaches \(0\) units of power.

Example CodeForces Contest 504 Problem B. Misha and Permutations Summation

Define the sum of two permutations \(p\) and \(q\) of the numbers \(0, 1, \cdots, (n - 1)\) as \(Perm((Ord(p)+Ord(q))\bmod n!)\), where \(Perm(x)\) is the \(x\)-th lexicographical permutation of the numbers \(0, 1, \cdots, (n-1)\) (counting from zero), and \(Ord(p)\) is the number of permutations lexicographically smaller than \(p\). For example, \(Perm(0) = (0, 1, \cdots , n - 2, n - 1)\), \(Perm(n! - 1) = (n - 1, n-2,\cdots, 1,0))\). Misha has two permutations \(p\) and \(q\); find their sum.

Summation in programming languages

Python's standard library specifies the correctly rounded summation function fsum, which can be used to return an accurate floating-point sum of the values in an iterable; it avoids loss of precision by tracking multiple intermediate partial sums using the Shewchuk algorithm.

In the Julia language, the default implementation of the sum function is pairwise summation, for high accuracy and good performance. Meanwhile, the external library function sum_kbn provides an implementation of the Neumaier variant for cases where higher accuracy is needed; see KahanSummation.jl.
