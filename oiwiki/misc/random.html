Pregled

Preduvjet za korištenje randomiziranih tehnika jest mogućnost brzog generiranja slučajnih brojeva. Ovaj članak predstavlja uobičajene metode generiranja slučajnih brojeva.

Slučajni i pseudoslučajni brojevi

Nema smisla reći da je jedan pojedinačni broj „slučajan”, pa u nastavku podrazumijevamo da govorimo o „nizu slučajnih brojeva”; čak i kad spominjemo „slučajni broj”, mislimo na „element niza slučajnih brojeva”.

Računski procesi današnjih računala deterministički su, pa je nemoguće samo pomoću algoritma generirati niz slučajnih brojeva koji bi bio uistinu nepredvidiv i neponovljiv.

Međutim, u velikoj većini slučajeva ne trebamo tako jaku slučajnost, nego nam je dovoljno da generirani niz statistički ima razna svojstva niza slučajnih brojeva (npr. uniformnu distribuciju, međusobnu nezavisnost itd.). Takav niz zovemo nizom pseudoslučajnih brojeva.

Primjeri primjene slučajnih i pseudoslučajnih brojeva u stvarnom životu i u algoritmima:

  • Pri uzorkovanju u anketama obično su dovoljni pseudoslučajni brojevi. Razlog je to što nas ionako zanimaju samo statistička svojstva.
  • U računalnoj sigurnosti često su potrebni jači slučajni brojevi (od upravo spomenutih pseudoslučajnih). Razlog je to što napadač može iskoristiti predvidivost.
  • Randomiziranim algoritmima koji se koriste u OI/ICPC-u gotovo uvijek su dovoljni pseudoslučajni brojevi. Razlog je to što ti algoritmi uvođenjem slučajnih brojeva obično unose vjerojatnost u analizu složenosti i time smanjuju složenost. To u biti i dalje koristi samo statistička svojstva slučajnih brojeva.
  • Neki randomizirani algoritmi (npr. Moserov algoritam) koriste svojstva slučajnih brojeva povezana s entropijom, pa moraju koristiti prave slučajne brojeve.

Metode generiranja slučajnih brojeva

rand

Služi za generiranje pseudoslučajnih brojeva; nedostatak mu je što je prilično spor. Za korištenje je potrebno #include<cstdlib>.

Poziv funkcije rand() vraća slučajan nenegativan cijeli broj iz [0,RAND_MAX], gdje je RAND_MAX makro iz standardne biblioteke; na Linuxu je RAND_MAX jednak \(2^{31}-1\). Veličinu generiranih brojeva možemo ograničiti uzimanjem ostatka.

Za korištenje rand() potrebno je sjeme (seed) slučajnih brojeva; funkcijom srand(seed) sjeme se može promijeniti u seed, a naravno može se i ne inicijalizirati.

Ako se isti program dvaput pokrene s istim seed, na istom računalu i s istim prevoditeljem, dobiveni slučajni rezultati bit će jednaki.

Jedna je mogućnost koristiti trenutno sistemsko vrijeme kao sjeme: srand(time(nullptr)).

Upozorenje

Na sustavu Windows raspon vrijednosti koje vraća rand() jest \(\left[0,2^{15}\right)\) (tj. RAND_MAX je jednak \(2^{15}-1\)); kad treba generirati brojeve koji nisu manji od \(2^{15}\), preporučuje se za veće slučajne brojeve koristiti (rand() << 15 | rand()).

O slučajnosti rand() i rand()%n:

  • Standard C/C++ ne propisuje ništa o kvaliteti slučajnih brojeva koje generira rand(), ni u kojem pogledu.
  • Implementacija rand() u GCC-u jamči osnovna svojstva poput uniformnosti distribucije, ali ima očite nedostatke poput kratkog perioda nižih bitova. (Primjerice, na autorovu računalu period niza koji generira rand()%2 iznosi otprilike \(2\cdot 10^6\).)
  • Čak i ako pretpostavimo da je rand() uniformno slučajan, rand()%n ne jamči uniformnost, jer se brojevi iz [0,n) mogu pojavljivati različit broj puta među 0%n,1%n,...,RAND_MAX%n. Za postupak koji strogo jamči uniformnost pogledajte Daniel Lemire, Fast Random Integer Generation in an Interval.

Predefinirani generatori slučajnih brojeva

Definirano je nekoliko posebnih popularnih algoritama. Ako nije drukčije navedeno, svi su definirani u zaglavlju <random>.

Upozorenje

Predefinirani generatori slučajnih brojeva dostupni su od standarda C++113.

Mersenne Twister

Mersenne Twister predložili su Matsumoto i Nishimura 1998. godine1; ime je dobio po tome što jedna njegova implementacija, MT19937, ima period duljine Mersenneova prostog broja \(M_{19937} = 2^{19937} - 1\).

Od C++11 predložak klase std::mersenne_twister_engine implementira generator slučajnih brojeva zasnovan na gornjoj metodi. Budući da je njegovo korištenje vrlo složeno, u praksi se obično koriste specijalizacije tog predloška: std::mt19937 i std::mt19937_64. Njihova je prednost visoka kvaliteta slučajnih brojeva i znatno veća brzina od rand().

mt19937 zasnovan je na 32-bitnom Mersenne Twisteru, koji su Matsumoto i Nishimura predložili 1998. godine1; to je klasa generatora slučajnih brojeva s istom ulogom kao rand(), a raspon slučajnih brojeva jednak je rasponu tipa unsigned int. Za korištenje jednostavno njime definiramo generator slučajnih brojeva: mt19937 myrand(seed); seed se može izostaviti, a tada se koristi zadano sjeme. Klasa preopterećuje operator(), pa kad treba generirati slučajan broj, dovoljno je pozvati myrand() i vraća se slučajan broj.

Sličan je generator mt19937_64, zasnovan na 64-bitnom Mersenne Twisteru koji su Matsumoto i Nishimura predložili 2000. godine; koristi se jednako kao mt19937, ali je raspon slučajnih brojeva proširen na raspon tipa unsigned long long.

Primjer koda 
#include <ctime>
#include <iostream>
#include <random>

using namespace std;

int main() {
  mt19937 myrand(SEED);  // zamijeni SEED bilo kojim cijelim brojem ili s time(nullptr)
  cout << myrand() << endl;
  return 0;
}

Linearni kongruentni generator slučajnih brojeva

Linearni kongruentni generator slučajnih brojeva (skraćeno LCG) predložili su Thomson i Rotenberg 1958. godine. Računa se prema sljedećoj formuli, gdje su \(A, C, M\) predefinirane konstante:

\[ s_i \equiv \begin{cases} \operatorname{seed} & i = 0 \\ s_{i-1} \times A + C & i \ge 1 \end{cases}\pmod{M} \]

Od C++11 predložak klase std::linear_congruential_engine implementira generator slučajnih brojeva zasnovan na gornjoj metodi, s parametrima predloška:

template <class UIntType, UIntType A, UIntType C, UIntType M>
class linear_congruential_engine;

Ovdje UIntType označava tip od \(s\), a slijede tri konstante.

Zatim su Lewis, Goodman i Miller 1969. predložili da se uzme \(A = 7^{5} = 16807\), \(C = 0\), \(M = 2^{31} - 1 = 2147483647\); tada algoritam postiže gotovo maksimalan period \(2^{31} - 2\) za taj modul (jer je \(16807\) primitivni korijen po tom modulu) i ima relativno dobra statistička svojstva.

Potom su 1988. Park i Miller LCG s tim parametrima prihvatili kao „minimalni standard”, upravo zato što je njegova implementacija iznimno jednostavna, razumljiva, učinkovita i relativno dobre kvalitete. Naposljetku su 1993. Park, Miller i Stockmeyer promijenili parametar \(A\) u \(48271\), što je postalo noviji „minimalni standard”. Obje inačice „minimalnog standarda” predefinirane su u C++11 kao specijalizacije linear_congruential_engine, redom minstd_rand0 i minstd_rand. Konkretno:

  • Za minstd_rand0 tip od \(s_i\) jest std::uint_fast32_t, \(A\) je \(16807\), \(C\) je \(0\), a \(M\) je \(2147483647\).

  • Za minstd_rand tip od \(s_i\) jest std::uint_fast32_t, \(A\) je \(48271\), \(C\) je \(0\), a \(M\) je \(2147483647\).

Korištenje je također jednostavno. Prvo definiramo std::minstd_rand myrand(seed);, gdje je seed sjeme, a ako se izostavi, zadana je vrijednost \(1\). Zatim pozivom myrand() dobivamo slučajan broj.

Ako treba prilagođeni generator slučajnih brojeva ovog oblika, a \(A, C, M\) nisu konstante, može se razmotriti i ručna implementacija. Ta je metoda jednostavna za implementaciju, ali generirani slučajni niz ima relativno kratak period (period je najviše \(M\), no u većini slučajeva kraći od \(M\)).

Referentna implementacija 
#include <iostream>
using namespace std;

struct myrand {
  int A, C, M, x;

  myrand(int A, int C, int M) {
    this->A = A;
    this->C = C;
    this->M = M;
    this->x = 0;
  }

  // generira sljedeći slučajni broj u slučajnom nizu
  int next() { return x = ((long long)A * x + C) % M; }
};

myrand rnd(3, 5, 97);  // inicijaliziraj generator slučajnih brojeva

int main() {
  int x = rnd.next();
  cout << x << endl;
  return 0;
}

Adapteri generatora slučajnih brojeva

Na temelju predefiniranih generatora slučajnih brojeva mogu se dodatnim omatanjem dobiti novi generatori slučajnih brojeva. Konkretna imena klasa i način korištenja potražite u popisu Pseudo-random number generation – Random number engine adaptors.

Sljedeći kod pomoću std::independent_bits_engine omata izlaz generatora std::minstd_rand.

#include <cstdint>
#include <iostream>
#include <random>

using std::cout;

int main() {
  std::independent_bits_engine<std::minstd_rand, 32, std::uint_fast32_t> rng;
  for (int i = 0; i < 10; ++i) {
    cout << rng() << " ";
  }
  return 0;
}

Nedeterministički generator uniformno distribuiranih slučajnih cijelih brojeva

random_device je hardverski zasnovan generator uniformno distribuiranih slučajnih brojeva koji može brzo generirati slučajne brojeve dok se ne iscrpi spremnik entropije. Klasa je definirana u C++11 i zahtijeva zaglavlje random. Budući da nakon iscrpljenja spremnika entropije performanse naglo padaju, preporučuje se ovom metodom generirati sjeme za pseudoslučajne generatore poput mt19937, a ne same slučajne brojeve.

random_device je nedeterministički generator uniformno slučajnih bitova, iako je implementaciji dopušteno da ga, ako nedeterminističko generiranje slučajnih brojeva nije podržano, ostvari pseudoslučajnim pogonom. Autor dosad nije primio izvještaje da evaluacijska računala NOIP-a ne podržavaju hardverski zasnovano generiranje uniformno distribuiranih slučajnih brojeva. Ipak, iz opreza, preporučuje se ovaj algoritam koristiti za generiranje sjemena slučajnih brojeva.

Referentni kod slijedi.

#include <iostream>
#include <map>
#include <random>
#include <string>

int main() {
  std::random_device rd;
  std::map<int, int> hist;
  std::uniform_int_distribution<int> dist(0, 9);
  for (int n = 0; n < 20000; ++n) {
    ++hist[dist(rd)];
  }
  for (auto p : hist) {
    std::cout << p.first << " : " << std::string(p.second / 100, '*') << '\n';
  }
  return 0;
}

Distribucije slučajnih brojeva

Ovdje su predstavljeni generatori slučajnih brojeva koji zahtijevaju da generirani slučajni brojevi slijede određenu distribuciju, npr. diskretnu uniformnu distribuciju, Bernoullijevu distribuciju, binomnu distribuciju, geometrijsku distribuciju, standardnu normalnu (Gaussovu) distribuciju.

Konkretna imena klasa potražite u popisu Pseudo-random number generation – Random number distributions.

Sljedeći program simulira kocku sa šest strana.

#include <iostream>
#include <random>
using std::cout;
using std::mt19937;

using std::uniform_int_distribution;
int main() {
  mt19937 gen(SEED);  // postavi sjeme standardnog mersenne_twister_engine
  uniform_int_distribution<> dis(1, 6);

  for (int n = 0; n < 10; ++n)
    // pomoću dis pretvori slučajni unsigned int koji daje gen u int iz [1, 6]
    cout << dis(gen) << ' ';
  cout << '\n';
  return 0;
}

Ostale metode implementacije

Ponekad trebamo implementirati vlastiti generator slučajnih brojeva. Slijede neke često korištene metode generiranja slučajnih brojeva.

Xorshift

Obitelj generatora slučajnih brojeva Xorshift predložio je George Marsaglia 2003. godine; zasniva se uglavnom na jednoj operaciji: XOR-u broja s njegovim pomakom. U algoritamskim natjecanjima često se koriste dvije inačice, xorshift32 i xorshift64:

#include <cstdint>

using u32 = std::uint32_t;
using u64 = std::uint64_t;

class xorshift32 {
 private:
  u32 x;

 public:
  xorshift32() : x(2463534242) {}

  explicit xorshift32(u32 s) : x(s) {}

  u32 operator()() {
    x ^= x << 13;
    x ^= x >> 17;
    x ^= x << 5;
    return x;
  }
};

class xorshift64 {
 private:
  u64 x;

 public:
  xorshift64() : x(88172645463325252) {}

  explicit xorshift64(u64 s) : x(s) {}

  u64 operator()() {
    x ^= x << 13;
    x ^= x >> 7;
    x ^= x << 17;
    return x;
  }
};

Način korištenja sličan je većini prethodno predstavljenih generatora slučajnih brojeva: prvo definiramo generator xorshift32 rng32(seed) ili xorshift64 rng64(seed), gdje je seed sjeme, a ako se izostavi, koristi se zadano sjeme; zatim pozivom rng32() ili rng64() dobivamo slučajan broj. Kad sjeme nije \(0\), ova dva generatora imaju period \(2^{32} - 1\) odnosno \(2^{64} - 1\); budući da je njihova implementacija iznimno jednostavna, često se natjecateljima daju zajedno sa sjemenom kako bi sami generirali velike ulazne podatke i time smanjili trošak ulaza/izlaza.

SplitMix

Obitelj generatora slučajnih brojeva SplitMix predložili su Steele, Lea i Flood 2014. godine, a primijenjena je u klasi java.util.SplittableRandom u Javi 8. U svijetu algoritamskih natjecanja najčešće se koristi inačica splitmix64:

#include <cstdint>

using u64 = std::uint64_t;

class splitmix64 {
 private:
  u64 x;

 public:
  splitmix64() : x(0) {}

  explicit splitmix64(u64 s) : x(s) {}

  u64 operator()() {
    u64 z = (x += 0x9e3779b97f4a7c15);
    z = (z ^ (z >> 30)) * 0xbf58476d1ce4e5b9;
    z = (z ^ (z >> 27)) * 0x94d049bb133111eb;
    return z ^ (z >> 31);
  }
};

Njezina je glavna upotreba ponovno hashiranje već izračunate hash-vrijednosti, kako netko pažljivo konstruiranim podacima ne bi srušio hash-tablicu i izazvao prekoračenje vremenskog ograničenja:

#include <cstdint>

using u64 = std::uint64_t;

struct MyHash {
  u64 mix64(u64 x) const {
    x = (x ^ (x >> 30)) * 0xbf58476d1ce4e5b9;
    x = (x ^ (x >> 27)) * 0x94d049bb133111eb;
    return x ^ (x >> 31);
  }

  size_t operator()(size_t x) const {
    // preporučuje se koristiti
    // std::chrono::steady_clock::now().time_since_epoch().count() iz biblioteke <chrono> kao
    // FIXED_RANDOM
    static const u64 FIXED_RANDOM = 0x9e3779b97f4a7c15;
    return mix64(x + FIXED_RANDOM);
  }
};

Može se koristiti i za generiranje slučajnih brojeva: prvo definiramo splitmix64 rng64(seed), gdje je seed sjeme, a ako se izostavi, koristi se zadano sjeme; zatim pozivom rng64() dobivamo slučajan broj. Tada je prilično očito da ova funkcija ima period \(2^{64}\) (jer su sve velike konstante neparne, pa \(x\) ima period \(2^{64}\), a sve kasnije operacije nad \(z\) potpuno su reverzibilne). To također znači da, čak i ako ne možete zapamtiti gornje velike parametre, možete jednostavno napisati nekoliko proizvoljnih dovoljno velikih neparnih brojeva u kombinaciji s XOR-om i pomakom udesno te postići sličan učinak.

Fibonaccijev generator slučajnih brojeva s kašnjenjem

Niz slučajnih brojeva \(\{R_i\}\) generira se sljedećom formulom (gdje je \(0 < j < k\)):

\[ R_i \equiv R_{i-j} \star R_{i-k} \bmod P \]

Ovdje se za \(P\) obično uzima potencija broja \(2\) (često \(2^{32}\) ili \(2^{64}\)), a \(\star\) označava binarni operator, koji može biti zbrajanje, oduzimanje, množenje ili XOR.

U usporedbi s tradicionalnim linearnim kongruentnim generatorima slučajnih brojeva ova metoda ima dulji period, ali na njezinu slučajnost znatno utječu početni uvjeti.

Referentna implementacija 
#include <iostream>
#include <random>
#include <vector>

using namespace std;

struct myrand {
  vector<unsigned int> vec;
  int l, j, k, cur;

  template <class URBG>
  myrand(int l, int j, int k, URBG &&rng) {
    this->l = l;
    this->j = j;
    this->k = k;
    cur = 0;
    for (int i = 0; i < l; i++) {
      vec.push_back(rng());  // prvih nekoliko elemenata slučajnog niza generiraj drugom metodom
    }
  }

  unsigned int next() {
    vec[cur] = vec[(cur - j + l) % l] * vec[(cur - k + l) % l];
    // tip unsigned se koristi da bi se automatski računalo modulo 2^32
    return vec[cur++];
  }
};

// posljednji argument može se zamijeniti drugim generatorom slučajnih brojeva, sjeme postavi sam
myrand rnd(11, 4, 7, mt19937(SEED));

int main() {
  unsigned int x = rnd.next();
  cout << x << endl;
  return 0;
}

Vrijedi spomenuti da je u C++11 std::subtract_with_carry_engine jedna od implementacija ove vrste generatora slučajnih brojeva, a std::ranlux24_base i std::ranlux48_base specijalizacije su tog predloška klase, dok se std::ranlux24 i std::ranlux48 dobivaju tako da se na prethodne primijeni adapter std::discard_block_engine. Međutim, danas se njihovo korištenje obično više ne preporučuje.

Randomizirani algoritmi

U nastavku predstavljamo neke randomizirane algoritme definirane u standardu C++ koji se oslanjaju na generiranje slučajnih brojeva.

random_shuffle

std::random_shuffle uveden je u C++98 i služi za slučajno miješanje zadanog niza. Za korištenje je potrebno #include<algorithm>; uobičajena je implementacija Fisher–Yatesov algoritam.

Pri korištenju dovoljno je predati pokazivače ili iteratore na početak i kraj zadanog raspona (zatvoren slijeva, otvoren zdesna): std::random_shuffle(first, last) ili std::random_shuffle(first, last, myrand).

Generator slučajnih brojeva koji se interno koristi zadano je rand(). Naravno, može se predati i prilagođeni generator slučajnih brojeva.

O slučajnosti random_shuffle:

  • Standard C++ zahtijeva da random_shuffle s jednakom vjerojatnošću slučajno odabere među svim mogućim permutacijama, ali zadana standardna biblioteka GCC-a2, libstdc++, to ne provodi strogo.
  • Jedan od uzroka nedostatka slučajnosti random_shuffle u GCC-u jest to što koristi izraz oblika rand()%n. Kao što je ranije rečeno, tako generirani brojevi nisu uniformno slučajni cijeli brojevi.
  • Drugi je uzrok ograničen raspon vrijednosti rand(). Ako duljina predanog raspona premašuje RAND_MAX, neke se permutacije ne mogu nikako dobiti4.
Upozorenje

random_shuffle zastario je (deprecated) u standardu C++14 i uklonjen u standardu C++17.

shuffle

std::shuffle uveden je u C++11 i ima istu ulogu kao random_shuffle. Za korištenje je potrebno #include<algorithm>.

Razlika je u tome što se obavezno mora koristiti prilagođeni generator slučajnih brojeva: std::shuffle(first, last, myrand).

Implementacija shuffle u GCC-u2 u skladu je sa zahtjevima standarda C++, tj. s jednakom vjerojatnošću slučajno odabire među svim mogućim permutacijama.

Slijedi generator ulaznih podataka napisan pomoću rand() i random_shuffle(). Generira male slučajne ulazne podatke za zadatak „ZJOI2012” 灾难 (Katastrofa).

#include <algorithm>
#include <cstdlib>
#include <iostream>
using std::cout;

using std::random_shuffle;

int a[100];

int main() {
  srand(SEED);
  int n = rand() % 99 + 1;
  for (int i = 1; i <= n; i++) a[i] = i;
  cout << n << '\n';
  for (int i = 1; i <= n; i++) {
    random_shuffle(a + 1, a + i);
    int cnt = rand() % i;
    for (int j = 1; j <= cnt; j++) cout << a[j] << ' ';
    cout << 0 << '\n';
  }
}

Slijedi isti generator ulaznih podataka napisan pomoću mt19937 i shuffle().

#include <algorithm>
#include <iostream>
#include <random>
using std::cout;
using std::mt19937;

using std::shuffle;

int a[100];

int main() {
  mt19937 rng(SEED);
  int n = rng() % 99 + 1;
  for (int i = 1; i <= n; i++) a[i] = i;
  cout << n << '\n';
  for (int i = 1; i <= n; i++) {
    shuffle(a + 1, a + i, rng);
    int cnt = rng() % i;
    for (int j = 1; j <= cnt; j++) cout << a[j] << ' ';
    cout << 0 << '\n';
  }
}

std::sample uveden je u C++17 i služi za slučajan odabir \(n\) elemenata iz niza; glavna razlika u odnosu na uzimanje prvih \(n\) elemenata nakon shuffle jest to što odabrani elementi u izlazu zadržavaju svoj relativni redoslijed. Uobičajena je implementacija uzorkovanje spremnikom (reservoir sampling).

Koristi se kao std::sample(first, last, dest, n, myrand), gdje [first, last) označava raspon iz kojeg se uzorkuje, [dest, dest + n) mjesto na koje se ispisuje, a myrand zadani generator slučajnih brojeva.

}

Overview

A prerequisite for using randomization techniques is being able to generate random numbers quickly. This article introduces common methods of generating random numbers.

Random and pseudorandom numbers

It is meaningless to say that a single number is "random", so in the following we always talk about a "random sequence"; even when we mention a "random number", we mean "an element of a random sequence".

The computations of today's computers are deterministic, so it is impossible to generate a truly unpredictable and unrepeatable random sequence using an algorithm alone.

However, in the vast majority of cases we do not need such strong randomness; it suffices that the generated sequence statistically has the various properties of a random sequence (such as uniform distribution, mutual independence, and so on). Such a sequence is called a pseudorandom sequence.

Examples of applications of random and pseudorandom numbers in real life and in algorithms:

  • Sampling surveys usually only need pseudorandom numbers. This is because we only care about statistical properties anyway.
  • Network security often needs stronger random numbers (than the pseudorandom numbers just mentioned). This is because an attacker may exploit predictability.
  • The randomized algorithms used in OI/ICPC almost always only need pseudorandom numbers. This is because these algorithms usually introduce random numbers in order to bring probability into the complexity analysis and thereby reduce the complexity. In essence this still only uses the statistical properties of random numbers.
  • Some randomized algorithms (for example Moser's algorithm) use entropy-related properties of random numbers and therefore must use true random numbers.

Methods of generating random numbers

rand

Used to generate pseudorandom numbers; its drawback is that it is rather slow. It requires #include<cstdlib>.

Calling the function rand() returns a random non-negative integer in [0,RAND_MAX], where RAND_MAX is a macro from the standard library; on Linux RAND_MAX equals \(2^{31}-1\). The size of the generated numbers can be limited by taking a remainder.

Using rand() requires a random seed; the function srand(seed) changes the random seed to seed, although not initializing it is also fine.

If the same program is run twice with the same seed, on the same machine and with the same compiler, the random results will be identical.

One option is to use the current system time as the random seed: srand(time(nullptr)).

Warning

On Windows the range of values returned by rand() is \(\left[0,2^{15}\right)\) (i.e. RAND_MAX equals \(2^{15}-1\)); when numbers not smaller than \(2^{15}\) need to be generated, it is recommended to use (rand() << 15 | rand()) to generate larger random numbers.

On the randomness of rand() and rand()%n:

  • The C/C++ standard makes no requirements whatsoever about the quality of the random numbers generated by rand().
  • The implementation of rand() used by GCC guarantees basic properties such as uniformity of the distribution, but has obvious flaws such as a short period of the low bits. (For example, on the author's machine, the period of the sequence generated by rand()%2 is about \(2\cdot 10^6\).)
  • Even assuming that rand() is uniformly random, rand()%n does not guarantee uniformity, because the numbers in [0,n) may appear a different number of times among 0%n,1%n,...,RAND_MAX%n. For a method that strictly guarantees uniformity, see Daniel Lemire, Fast Random Integer Generation in an Interval.

Predefined random number generators

Several special popular algorithms are defined. Unless stated otherwise, all are defined in the header <random>.

Warning

The predefined random number generators are available since the C++11 standard3.

Mersenne Twister

The Mersenne Twister was proposed by Matsumoto and Nishimura in 19981; it got its name because one of its implementations, MT19937, has a period as long as the Mersenne prime \(M_{19937} = 2^{19937} - 1\).

Since C++11, the class template std::mersenne_twister_engine implements a random number generator based on the method above. Since it is very complicated to use, in practice the specializations of this class template are usually used: std::mt19937 and std::mt19937_64. Their advantages are high-quality random numbers and much higher speed than rand().

mt19937 is based on the 32-bit Mersenne Twister proposed by Matsumoto and Nishimura in 19981; it is a random number generator class with the same role as rand(), and the range of the random numbers is the range of the type unsigned int. To use it, simply define a random number generator with it: mt19937 myrand(seed); seed may be omitted, in which case the default seed is used. It overloads operator(), so when a random number is needed, just call myrand() and a random number is returned.

Another similar generator is mt19937_64, based on the 64-bit Mersenne Twister proposed by Matsumoto and Nishimura in 2000; it is used in the same way as mt19937, but the range of random numbers is extended to the range of the type unsigned long long.

Sample code 
#include <ctime>
#include <iostream>
#include <random>

using namespace std;

int main() {
  mt19937 myrand(SEED);  // replace SEED with any integer or with time(nullptr)
  cout << myrand() << endl;
  return 0;
}

Linear congruential random number generator

The linear congruential random number generator (LCG for short) was proposed by Thomson and Rotenberg in 1958. It is computed by the following formula, where \(A, C, M\) are predefined constants:

\[ s_i \equiv \begin{cases} \operatorname{seed} & i = 0 \\ s_{i-1} \times A + C & i \ge 1 \end{cases}\pmod{M} \]

Since C++11, the class template std::linear_congruential_engine implements a random number generator based on the method above, with the following template parameters:

template <class UIntType, UIntType A, UIntType C, UIntType M>
class linear_congruential_engine;

Here UIntType denotes the type of \(s\), followed by the three constants.

Later, Lewis, Goodman, and Miller proposed in 1969 that with \(A = 7^{5} = 16807\), \(C = 0\), \(M = 2^{31} - 1 = 2147483647\), this algorithm reaches a nearly maximal period of \(2^{31} - 2\) for this modulus (because \(16807\) is a primitive root modulo it) and has relatively good statistical properties.

Then, in 1988, the LCG with these parameters was adopted by Park and Miller as the "minimal standard", simply because its implementation is extremely simple, understandable, efficient, and of relatively good quality. Finally, in 1993, Park, Miller, and Stockmeyer changed the parameter \(A\) to \(48271\), which became the newer "minimal standard". Both versions of the "minimal standard" are predefined in C++11 as specializations of linear_congruential_engine, namely minstd_rand0 and minstd_rand. Specifically:

  • For minstd_rand0, the type of \(s_i\) is std::uint_fast32_t, \(A\) is \(16807\), \(C\) is \(0\), and \(M\) is \(2147483647\).

  • For minstd_rand, the type of \(s_i\) is std::uint_fast32_t, \(A\) is \(48271\), \(C\) is \(0\), and \(M\) is \(2147483647\).

Usage is also simple. First define std::minstd_rand myrand(seed);, where seed is the seed, which defaults to \(1\) when omitted. Then call myrand() to obtain a random number.

If a custom random number generator of this form is needed and \(A, C, M\) are not constants, a hand-written implementation can also be considered. This method is easy to implement, but the generated random sequence has a relatively short period (the period is at most \(M\), but in most cases shorter than \(M\)).

Reference implementation 
#include <iostream>
using namespace std;

struct myrand {
  int A, C, M, x;

  myrand(int A, int C, int M) {
    this->A = A;
    this->C = C;
    this->M = M;
    this->x = 0;
  }

  // generate the next random number of the random sequence
  int next() { return x = ((long long)A * x + C) % M; }
};

myrand rnd(3, 5, 97);  // initialize a random number generator

int main() {
  int x = rnd.next();
  cout << x << endl;
  return 0;
}

Random number engine adaptors

On top of the predefined random number generators, new random number generators can be obtained by wrapping them again. For the specific class names and usage, see the list in Pseudo-random number generation – Random number engine adaptors.

The following code uses std::independent_bits_engine to wrap the output of std::minstd_rand.

#include <cstdint>
#include <iostream>
#include <random>

using std::cout;

int main() {
  std::independent_bits_engine<std::minstd_rand, 32, std::uint_fast32_t> rng;
  for (int i = 0; i < 10; ++i) {
    cout << rng() << " ";
  }
  return 0;
}

Non-deterministic uniformly distributed integer random number generator

random_device is a hardware-based uniformly distributed random number generator that can generate random numbers at high speed until the entropy pool is exhausted. The class is defined in C++11 and requires the random header. Since performance drops sharply once the entropy pool is exhausted, it is recommended to use this method to generate seeds for pseudorandom generators such as mt19937, rather than to generate the random numbers directly.

random_device is a non-deterministic uniform random bit generator, although if non-deterministic random number generation is not supported, implementations are allowed to realize it with a pseudorandom engine. So far the author has received no reports that the NOIP judging machines do not support hardware-based uniformly distributed random number generation. But to be conservative, it is recommended to use this algorithm to generate random seeds.

The reference code is as follows.

#include <iostream>
#include <map>
#include <random>
#include <string>

int main() {
  std::random_device rd;
  std::map<int, int> hist;
  std::uniform_int_distribution<int> dist(0, 9);
  for (int n = 0; n < 20000; ++n) {
    ++hist[dist(rd)];
  }
  for (auto p : hist) {
    std::cout << p.first << " : " << std::string(p.second / 100, '*') << '\n';
  }
  return 0;
}

Random number distributions

Introduced here are random number generators that require the generated random numbers to follow a certain distribution, such as the discrete uniform distribution, the Bernoulli distribution, the binomial distribution, the geometric distribution, and the standard normal (Gaussian) distribution.

For the specific class names, see the list in Pseudo-random number generation – Random number distributions.

The following program simulates a six-sided die.

#include <iostream>
#include <random>
using std::cout;
using std::mt19937;

using std::uniform_int_distribution;
int main() {
  mt19937 gen(SEED);  // seed the standard mersenne_twister_engine
  uniform_int_distribution<> dis(1, 6);

  for (int n = 0; n < 10; ++n)
    // use dis to transform the random unsigned int generated by gen into an int in [1, 6]
    cout << dis(gen) << ' ';
  cout << '\n';
  return 0;
}

Other implementation methods

Sometimes we need to implement our own random number generator. Below are some commonly used methods of generating random numbers.

Xorshift

The Xorshift family of random number generators was proposed by George Marsaglia in 2003; it is mainly based on a single operation: XORing a number with a shifted copy of itself. The versions commonly used in algorithm competitions are xorshift32 and xorshift64:

#include <cstdint>

using u32 = std::uint32_t;
using u64 = std::uint64_t;

class xorshift32 {
 private:
  u32 x;

 public:
  xorshift32() : x(2463534242) {}

  explicit xorshift32(u32 s) : x(s) {}

  u32 operator()() {
    x ^= x << 13;
    x ^= x >> 17;
    x ^= x << 5;
    return x;
  }
};

class xorshift64 {
 private:
  u64 x;

 public:
  xorshift64() : x(88172645463325252) {}

  explicit xorshift64(u64 s) : x(s) {}

  u64 operator()() {
    x ^= x << 13;
    x ^= x >> 7;
    x ^= x << 17;
    return x;
  }
};

Usage is similar to most of the random number generators introduced above: first define the random number generator xorshift32 rng32(seed) or xorshift64 rng64(seed), where seed is the seed, with the default seed used when omitted; then call rng32() or rng64() to obtain a random number. When the seed is not \(0\), these two random number generators have periods of \(2^{32} - 1\) and \(2^{64} - 1\) respectively; since their implementation is extremely simple, they are often handed out to contestants together with a seed to generate large test data, in order to reduce I/O overhead.

SplitMix

The SplitMix family of random number generators was proposed by Steele, Lea, and Flood in 2014 and is used in the java.util.SplittableRandom class of Java 8. The most commonly used version in the algorithm competition community is splitmix64:

#include <cstdint>

using u64 = std::uint64_t;

class splitmix64 {
 private:
  u64 x;

 public:
  splitmix64() : x(0) {}

  explicit splitmix64(u64 s) : x(s) {}

  u64 operator()() {
    u64 z = (x += 0x9e3779b97f4a7c15);
    z = (z ^ (z >> 30)) * 0xbf58476d1ce4e5b9;
    z = (z ^ (z >> 27)) * 0x94d049bb133111eb;
    return z ^ (z >> 31);
  }
};

Its main use is to re-hash an already computed hash value, in order to prevent someone from using carefully constructed data to make a hash table time out:

#include <cstdint>

using u64 = std::uint64_t;

struct MyHash {
  u64 mix64(u64 x) const {
    x = (x ^ (x >> 30)) * 0xbf58476d1ce4e5b9;
    x = (x ^ (x >> 27)) * 0x94d049bb133111eb;
    return x ^ (x >> 31);
  }

  size_t operator()(size_t x) const {
    // it is recommended to use
    // std::chrono::steady_clock::now().time_since_epoch().count() from the <chrono> library as
    // FIXED_RANDOM
    static const u64 FIXED_RANDOM = 0x9e3779b97f4a7c15;
    return mix64(x + FIXED_RANDOM);
  }
};

It can also be used to generate random numbers: first define splitmix64 rng64(seed), where seed is the seed, with the default seed used when omitted; then call rng64() to obtain a random number. It is then fairly obvious that this function has a period of \(2^{64}\) (because all the large constants are odd, \(x\) has a period of \(2^{64}\), and all subsequent operations on \(z\) are completely reversible). This also means that even if you cannot remember the large parameters above, you can simply write a few arbitrary sufficiently large odd numbers combined with XOR and right shifts to achieve a similar effect.

Lagged Fibonacci random number generator

The random sequence \(\{R_i\}\) is generated by the following formula (where \(0 < j < k\)):

\[ R_i \equiv R_{i-j} \star R_{i-k} \bmod P \]

Here \(P\) is usually a power of \(2\) (commonly \(2^{32}\) or \(2^{64}\)), and \(\star\) denotes a binary operator, which can be addition, subtraction, multiplication, or XOR.

Compared with the traditional linear congruential random number generators, this method has a longer period, but its randomness is strongly affected by the initial conditions.

Reference implementation 
#include <iostream>
#include <random>
#include <vector>

using namespace std;

struct myrand {
  vector<unsigned int> vec;
  int l, j, k, cur;

  template <class URBG>
  myrand(int l, int j, int k, URBG &&rng) {
    this->l = l;
    this->j = j;
    this->k = k;
    cur = 0;
    for (int i = 0; i < l; i++) {
      vec.push_back(rng());  // generate the first few elements of the random sequence by another method
    }
  }

  unsigned int next() {
    vec[cur] = vec[(cur - j + l) % l] * vec[(cur - k + l) % l];
    // the unsigned type is used so that the result is automatically taken modulo 2^32
    return vec[cur++];
  }
};

// the last argument can be replaced by another random number generator; set the seed yourself
myrand rnd(11, 4, 7, mt19937(SEED));

int main() {
  unsigned int x = rnd.next();
  cout << x << endl;
  return 0;
}

It is worth mentioning that in C++11, std::subtract_with_carry_engine is one implementation of this kind of random number generator, std::ranlux24_base and std::ranlux48_base are specializations of this class template, and std::ranlux24 and std::ranlux48 are obtained by applying the adaptor std::discard_block_engine on top of the former. However, their use is generally no longer recommended today.

Randomized algorithms

Below we introduce some randomized algorithms defined in the C++ standard that rely on random number generation.

random_shuffle

std::random_shuffle was introduced in C++98 and is used to randomly shuffle a given sequence. It requires #include<algorithm>; the common implementation is the Fisher–Yates algorithm.

To use it, pass pointers or iterators to the beginning and end of the given range (closed on the left, open on the right): std::random_shuffle(first, last) or std::random_shuffle(first, last, myrand).

The random number generator used internally defaults to rand(). Of course, a custom random number generator can also be passed.

On the randomness of random_shuffle:

  • The C++ standard requires random_shuffle to choose randomly among all possible permutations with equal probability, but GCC's2 default standard library libstdc++ does not strictly enforce this.
  • One reason for the randomness flaw of random_shuffle in GCC is that it uses an expression of the form rand()%n. As mentioned earlier, the numbers generated this way are not uniformly random integers.
  • The second reason is the limited range of rand(). If the length of the passed range exceeds RAND_MAX, some permutations cannot be produced at all4.
Warning

random_shuffle was deprecated in the C++14 standard and removed in the C++17 standard.

shuffle

std::shuffle was introduced in C++11 and has the same role as random_shuffle. It requires #include<algorithm>.

The difference is that a custom random number generator must be used: std::shuffle(first, last, myrand).

GCC's2 implementation of shuffle complies with the requirements of the C++ standard, i.e. it chooses randomly among all possible permutations with equal probability.

Below is a test data generator written with rand() and random_shuffle(). It generates small random test data for the problem "ZJOI2012" 灾难 (Disaster).

#include <algorithm>
#include <cstdlib>
#include <iostream>
using std::cout;

using std::random_shuffle;

int a[100];

int main() {
  srand(SEED);
  int n = rand() % 99 + 1;
  for (int i = 1; i <= n; i++) a[i] = i;
  cout << n << '\n';
  for (int i = 1; i <= n; i++) {
    random_shuffle(a + 1, a + i);
    int cnt = rand() % i;
    for (int j = 1; j <= cnt; j++) cout << a[j] << ' ';
    cout << 0 << '\n';
  }
}

sample

std::sample was introduced in C++17 and is used to randomly select \(n\) elements from a sequence; the main difference from taking the first \(n\) elements after shuffle is that the selected elements keep their relative order in the output. The common implementation is reservoir sampling.

It is used as std::sample(first, last, dest, n, myrand), where [first, last) denotes the range to sample from, [dest, dest + n) denotes where to output, and myrand is the given random number generator.

Below is an implementation that randomly picks 4 out of 11 uppercase letters.

#include <algorithm>
#include <iostream>
#include <iterator>
#include <random>
#include <string>
using std::back_inserter;
using std::copy;
using std::cout;
using std::mt19937;
using std::string;

using std::sample;

int main() {
  string in{"ABCDEFGHIJK"}, out;
  mt19937 rng{SEED};
  sample(in.begin(), in.end(), back_inserter(out), 4, rng);
  cout << "Four random letters out of " << in << ": " << out << '\n';
}
