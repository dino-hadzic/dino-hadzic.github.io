Tehnike optimizacije prostora (memorije) u algoritamskim natjecanjima nisu osobito česte, no ipak ih vrijedi razmotriti.

Informacijska entropija

Informacijska entropija opisuje donju granicu prostora potrebnog za pohranu podataka; ako je stvarno raspoloživi prostor manji od te granice, informacija se nužno gubi.

Definicija

Za slučajnu varijablu \(X\) informacijska entropija definira se kao

\[ H(X)=-\sum_{x}P(X=x)\log_2 P(X=x). \]

Baza logaritma u definiciji je \(2\) zato što svaki bit informacije pohranjene u računalu ima samo \(2\) moguće vrijednosti: \(0\) i \(1\).

Na primjer, neka \(X\) ima uniformnu distribuciju na \(\{1,2,\dots,n\}\); tada je njegova informacijska entropija

\[ H(X)=-\sum_{i=1}^n\frac{1}{n}\log_2\frac{1}{n}=\log_2 n, \]

pa nam za pohranu cijelog broja od \(1\) do \(n\) treba barem \(\log_2 n\) bitova.

Primjer zadatka

[WC2022] 猜词 (Pogađanje riječi)

Interaktivni zadatak: u ograničenom broju pokušaja trebate pogoditi riječ od 5 slova. Svaki pokušaj mora biti riječ koja postoji u zadanom rječniku. Ako pogodite, igra završava; nakon svakog pogrešnog pokušaja interaktor vraća koja su slova na ispravnom položaju te koja se slova pojavljuju u traženoj riječi, ali na pogrešnom položaju.

Rješenje

Vidi Rješavanje Wordlea pomoću teorije informacija - 3Blue1Brown.

Razmotrimo računanje informacijske entropije: očito, ako pri svakom pogađanju biramo riječ s visokom informacijskom entropijom, očekivani broj pokušaja bit će što manji.

Budući da je u ovom zadatku prije pogađanja zadano prvo slovo odgovora, za svako početno slovo možemo unaprijed izračunati optimalan pokušaj.

Osim toga, ako je preostalo malo riječi, možemo prednost dati riječima koje bi mogle biti odgovor, čime smanjujemo broj pokušaja.

Uobičajene tehnike

Izbjegavanje pohrane nepotrebnih podataka

Na primjer:

  • U perzistentnom segment treeu jedna izmjena stvara samo \(O(\log n)\) novih čvorova, pa ne moramo cijeli segment tree svake verzije pohraniti u potpunosti, nego je dovoljno zabilježiti nove čvorove.
  • Razmotrimo pohranu grafa: za rijetke grafove matrica susjedstva pohranjuje mnoštvo beskorisnih vrijednosti \(0\), pa se rijetki grafovi obično pohranjuju listama susjedstva.
  • Svaki element polja tipa bool zauzima jedan bajt; po potrebi ga možemo zamijeniti s std::vector<bool> ili bitsetom, u kojima svaki element zauzima samo jedan bit.
  • U DP-u za ruksak, kod 0-1 ruksaka svako računanje DP vrijednosti koristi samo podatke iz prethodnog računanja, pa prostor možemo optimizirati rolajućim poljem (rolling array) i pamtiti samo trenutačne DP vrijednosti.

Iskorištavanje svojstava podataka

Razmotrimo strukturu disjunktnih skupova (DSU) s kompresijom putova i heurističkim spajanjem (union by size); tradicionalno su potrebna dva polja: jedno za indeks roditelja, drugo za veličinu podstabla.

Uočimo:

  1. Uz kompresiju putova, za svako stablo u DSU-u trebamo pamtiti samo veličinu podstabla korijena.
  2. Roditelj korijena nužno je on sam.

Možemo iskoristiti svojstva predznačenih cijelih brojeva: negativnim brojevima označavamo korijene, a pozitivnima nekorijenske čvorove, pa nam je za DSU s kompresijom putova i heurističkim spajanjem dovoljno samo jedno polje.

Implementacija 
#include <cstdint>
#include <vector>
using i32 = int32_t;
using u32 = uint32_t;

class dsu {
  // p[i] < 0 znači da je i korijen, a veličina njegova podstabla je -p[i]
  // p[i] >= 0 znači da i nije korijen, a indeks njegova roditelja je p[i]
  std::vector<i32> p;

 public:
  // čvorovi su označeni od 0 do sz-1
  explicit dsu(u32 sz) : p(sz, -1) {}

  i32 find(u32 x) { return p[x] < 0 ? (i32)x : p[x] = find((u32)p[x]); }

  u32 size(u32 x) { return (u32)-p[(u32)find(x)]; }

  bool same_root(u32 x, u32 y) { return find(x) == find(y); }

  bool merge(u32 x, u32 y) {
    if ((x = (u32)find(x)) == (y = (u32)find(y))) return false;
    if (p[x] > p[y]) std::swap(x, y);  // heurističko spajanje (union by size)
    p[x] += p[y], p[y] = (i32)x;
    return true;
  }
};

Space optimization techniques are not very common in algorithm competitions, but they are still worth discussing.

Information entropy

Information entropy describes the lower bound on the space occupied by stored data; if the actually available space is below this bound, information is necessarily lost.

Definition

For a random variable \(X\), the information entropy is defined as

\[ H(X)=-\sum_{x}P(X=x)\log_2 P(X=x). \]

The base of the logarithm in the definition is \(2\) because each bit of information stored in a computer has only \(2\) possible values: \(0\) and \(1\).

For example, let \(X\) be uniformly distributed on \(\{1,2,\dots,n\}\); then its information entropy is

\[ H(X)=-\sum_{i=1}^n\frac{1}{n}\log_2\frac{1}{n}=\log_2 n, \]

so we need at least \(\log_2 n\) bits to store an integer from \(1\) to \(n\).

Example problem

[WC2022] 猜词 (Guess the Word)

An interactive problem: you need to guess a 5-letter word within a limited number of attempts. Each guess must be a word that exists in the given dictionary. If you guess correctly, the game ends; after each wrong guess, the interactor returns which letters are in the correct position, and which letters appear in the target word but in the wrong position.

Solution

See Solving Wordle using information theory - 3Blue1Brown.

Consider computing the information entropy: obviously, choosing a word with high information entropy at each guess makes the expected number of guesses as small as possible.

Since in this problem the first letter of the answer is given before guessing, we can precompute the optimal guess for each first letter.

In addition, if few words remain, we can prefer to output words that may be the answer, thereby reducing the number of guesses.

Common techniques

Avoid storing unnecessary data

For example:

  • In a persistent segment tree, a single modification creates only \(O(\log n)\) new nodes, so we do not need to store the complete segment tree of every version; it suffices to record the new nodes.
  • Consider graph storage: for sparse graphs, an adjacency matrix stores a large number of useless \(0\) values, so sparse graphs are usually stored with adjacency lists.
  • Each element of a bool array occupies one byte; when necessary, it can be replaced by std::vector<bool> or a bitset, where each element occupies only one bit.
  • In knapsack DP, for the 0-1 knapsack, each computation of DP values uses only the data from the previous computation, so we can optimize space with a rolling array and only record the current DP values.

Exploit properties of the data

Consider a disjoint set union (DSU) with path compression and union by size; the traditional approach needs two arrays, recording the parent index and the subtree size respectively.

Note that:

  1. After applying path compression, for a tree in the DSU we only need to record the subtree size of the root.
  2. The parent of a root is always itself.

We can use the properties of signed integers, representing roots by negative numbers and non-root nodes by positive numbers, so a single array suffices to implement a DSU with path compression and union by size.

Implementation 
#include <cstdint>
#include <vector>
using i32 = int32_t;
using u32 = uint32_t;

class dsu {
  // p[i] < 0 means i is a root and the size of its subtree is -p[i]
  // p[i] >= 0 means i is not a root and the index of its parent is p[i]
  std::vector<i32> p;

 public:
  // nodes are numbered from 0 to sz-1
  explicit dsu(u32 sz) : p(sz, -1) {}

  i32 find(u32 x) { return p[x] < 0 ? (i32)x : p[x] = find((u32)p[x]); }

  u32 size(u32 x) { return (u32)-p[(u32)find(x)]; }

  bool same_root(u32 x, u32 y) { return find(x) == find(y); }

  bool merge(u32 x, u32 y) {
    if ((x = (u32)find(x)) == (y = (u32)find(y))) return false;
    if (p[x] > p[y]) std::swap(x, y);  // union by size
    p[x] += p[y], p[y] = (i32)x;
    return true;
  }
};
