Ova stranica predstavlja CDQ podjelu (CDQ divide and conquer).

Uvod

CDQ podjela je ideja, a ne konkretan algoritam, slično kao dinamičko programiranje. Ta se ideja danas vrlo široko proširila i prema načelu rada i načinu pisanja grubo se dijeli na tri vrste:

  • rješavanje zadataka o parovima točaka;
  • optimizacija i prijelazi 1D dinamičkog programiranja;
  • pretvaranje nekih dinamičkih problema u statičke pomoću CDQ podjele.

Ideju CDQ podjele prva je još u srednjoj školi uredila i sažela Chen Danqi (陈丹琦), osvajačica zlatne medalje na IOI-ju 2008., pa je po njoj i dobila ime.1

Rješavanje zadataka o parovima točaka

Zadaci ovog tipa većinom nalikuju na „zadan je niz duljine \(n\), prebroji parove točaka \((i,j)\) s određenim svojstvima” ili „zadan je niz duljine \(n\), pronađi par točaka \((i,j)\) koji maksimizira vrijednost neke funkcije”.

Tijek algoritma kojim CDQ podjela rješava takve zadatke je sljedeći:

  1. pronađemo sredinu niza \(mid\);

  2. sve parove točaka \((i,j)\) podijelimo u 3 vrste:

    1. parove s \(1 \leq i \leq mid,1 \leq j \leq mid\);
    2. parove s \(1 \leq i \leq mid ,mid+1 \leq j \leq n\);
    3. parove s \(mid+1 \leq i \leq n,mid+1 \leq j \leq n\).

  3. niz \((1,n)\) razdvojimo na dva niza \((1,mid)\) i \((mid+1,n)\). Tada se parovi prve i treće vrste nalaze unutar tih dvaju nizova;

  4. rekurzivno obradimo te dvije vrste parova;

  5. smislimo način za obradu parova druge vrste.

Vidimo da je ideja CDQ podjele neprestano rekurzivno raspodjeljivati parove točaka na lijevi i desni interval.

U praksi obično koristimo funkciju solve(l,r) koja obrađuje parove s \(l \leq i \leq r,l \leq j \leq r\). Rekurzivni dio gornjeg tijeka algoritma ostvaruje se pozivima solve(l,mid) i solve(mid+1,r). Za preostale parove druge vrste treba dodatno osmisliti algoritam.

Primjeri zadataka

三维偏序 (Trodimenzionalni parcijalni uređaj)

Zadan je niz u kojem svaka točka ima tri svojstva \(a_i,b_i,c_i\). Odredite koliko parova točaka \((i,j)\) u tom nizu zadovoljava \(a_j \leq a_i\) i \(b_j \leq b_i\) i \(c_j \leq c_i\) i \(j \ne i\).

Ideja rješenja

Trodimenzionalni parcijalni uređaj klasičan je zadatak za CDQ podjelu.

Zadatak traži da prebrojimo parove točaka u nizu, pa pokušajmo s CDQ podjelom.

Najprije niz sortiramo po \(a\).

Pretpostavimo da smo već napisali solve(l,r) i da smo rekurzijom riješili solve(l,mid) i solve(mid+1,r). Sada moramo prebrojati koliko parova točaka \((i,j)\) s \(l \leq i \leq mid\), \(mid+1 \leq j \leq r\) još zadovoljava i ograničenja \(a_{i} \leq a_{j}\), \(b_{i} \leq b_{j}\), \(c_{i} \leq c_{j}\).

Nakon kratkog razmišljanja uočavamo da ograničenje \(a_{i} \leq a_{j}\) više ničemu ne služi: budući da je \(i\) manji od \(mid\), a \(j\) veći od \(mid\), \(i\) je sigurno manji od \(j\); a kako je niz već sortiran po \(a\), nužno vrijedi \(a_{i} \leq a_{j}\). Preostaju još dva ograničenja: \(b_{i} \leq b_{j}\) i \(c_{i} \leq c_{j}\). Prema njima možemo iterirati po \(j\) i odrediti koliko \(i\) zadovoljava uvjete.

Radi lakšeg iteriranja, sve točke u \((l,mid)\) i \((mid+1,r)\) sortiramo uzlazno po vrijednosti \(b\). Zatim redom prolazimo kroz svaki \(j\) i sve točke \(i\) s \(b_{i} \leq b_{j}\) ubacujemo u neku strukturu podataka (ovdje biramo Fenwick tree). Tada je dovoljno upitati koliko točaka u Fenwick treeju ima vrijednost \(c\) manju ili jednaku \(c_{j}\) i dobili smo koliko \(i\) se može valjano upariti s tom točkom \(j\).

Kad ubacujemo točku čija je vrijednost \(c\) jednaka \(x\), na poziciji \(x\) Fenwick treeja povećamo vrijednost za jedan, a upit koliko točaka u Fenwick treeju ima vrijednost manju od \(x\) zapravo je računanje prefiksne sume; ako smo unaprijed diskretizirali sve vrijednosti \(c\), složenost je ispravna.

Za svaki \(j\) moramo u Fenwick tree ubaciti sve točke \(i\) s \(b_{i} \leq b_{j}\). Budući da su svi \(i\) i \(j\) već unaprijed sortirani po vrijednosti \(b\), dovoljno je točke ubacivati u Fenwick tree tehnikom dvostrukih pokazivača (two pointers), čime broj umetanja u Fenwick tree pada s \(O(n^2)\) na \(O(n)\).

Ovakvim tijekom algoritma informacije o parovima druge vrste obradili smo u vremenu \(O(n\log n)\). Ukupna vremenska složenost algoritma tada je \(T(n)=T(\lfloor \frac{n}{2} \rfloor)+T(\lceil \frac{n}{2} \rceil)+O(n\log n)=O(n\log^2n)\).

Primjer koda 
#include <algorithm>
#include <iostream>

constexpr int MAXN = 1e5 + 10;
constexpr int MAXK = 2e5 + 10;

int n, k;

struct Element {
  int a, b, c;
  int cnt;
  int res;

  bool operator!=(Element other) const {
    if (a != other.a) return true;
    if (b != other.b) return true;
    if (c != other.c) return true;
    return false;
  }
};

Element e[MAXN];
Element ue[MAXN];
int m, t;
int res[MAXN];

struct BinaryIndexedTree {
  int node[MAXK];

  int lowbit(int x) { return x & -x; }

  void Add(int pos, int val) {
    while (pos <= k) {
      node[pos] += val;
      pos += lowbit(pos);
    }
    return;
  }

  int Ask(int pos) {
    int res = 0;
    while (pos) {
      res += node[pos];
      pos -= lowbit(pos);
    }
    return res;
  }
} BIT;

bool cmpA(Element x, Element y) {
  if (x.a != y.a) return x.a < y.a;
  if (x.b != y.b) return x.b < y.b;
  return x.c < y.c;
}

bool cmpB(Element x, Element y) {
  if (x.b != y.b) return x.b < y.b;
  return x.c < y.c;
}

void CDQ(int l, int r) {
  if (l == r) return;
  int mid = (l + r) / 2;
  CDQ(l, mid);
  CDQ(mid + 1, r);
  std::sort(ue + l, ue + mid + 1, cmpB);
  std::sort(ue + mid + 1, ue + r + 1, cmpB);
  int i = l;
  int j = mid + 1;
  while (j <= r) {
    while (i <= mid && ue[i].b <= ue[j].b) {
      BIT.Add(ue[i].c, ue[i].cnt);
      i++;
    }
    ue[j].res += BIT.Ask(ue[j].c);
    j++;
  }
  for (int k = l; k < i; k++) BIT.Add(ue[k].c, -ue[k].cnt);
  return;
}

using std::cin;
using std::cout;

int main() {
  cin.tie(nullptr)->sync_with_stdio(false);
  cin >> n >> k;
  for (int i = 1; i <= n; i++) cin >> e[i].a >> e[i].b >> e[i].c;
  std::sort(e + 1, e + n + 1, cmpA);
  for (int i = 1; i <= n; i++) {
    t++;
    if (e[i] != e[i + 1]) {
      m++;
      ue[m].a = e[i].a;
      ue[m].b = e[i].b;
      ue[m].c = e[i].c;
      ue[m].cnt = t;
      t = 0;
    }
  }
  CDQ(1, m);
  for (int i = 1; i <= m; i++) res[ue[i].res + ue[i].cnt - 1] += ue[i].cnt;
  for (int i = 0; i < n; i++) cout << res[i] << '\n';
  return 0;
}
CQOI2011 动态逆序对 (Dinamičke inverzije)

Za niz \(a\) broj inverzija definiran je kao broj elemenata skupa \(\{(i,j)| i < j \wedge a_i > a_j \}\).

Zadana je permutacija brojeva \(1\sim n\) iz koje se nekim redoslijedom redom briše \(m\) elemenata. Vaš je zadatak prije svakog brisanja elementa izračunati broj inverzija cijelog niza.

Primjer koda 
// Pažljivim izvodom dobije se izraz gotovo jednak trodimenzionalnom parcijalnom uređaju; u biti je to predložak za 3D parcijalni uređaj
#include <algorithm>
#include <iostream>
using namespace std;
using ll = long long;
int n;
int m;

struct treearray {
  int ta[200010];

  void ub(int& x) { x += x & (-x); }

  void db(int& x) { x -= x & (-x); }

  void c(int x, int t) {
    for (; x <= n + 1; ub(x)) ta[x] += t;
  }

  int sum(int x) {
    int r = 0;
    for (; x > 0; db(x)) r += ta[x];
    return r;
  }
} ta;

struct data_ {
  int val;
  int del;
  int ans;
} a[100010];

int rv[100010];
ll res;

// Definiramo dvije usporedbe
bool cmp1(const data_& a, const data_& b) { return a.val < b.val; }

bool cmp2(const data_& a, const data_& b) { return a.del < b.del; }

void solve(int l, int r) {  // Dolje je konkretan izraz, samo ga primijenimo
  if (r - l == 1) {
    return;
  }
  int mid = (l + r) / 2;
  solve(l, mid);
  solve(mid, r);
  int i = l + 1;
  int j = mid + 1;
  while (i <= mid) {
    while (a[i].val > a[j].val && j <= r) {
      ta.c(a[j].del, 1);
      j++;
    }
    a[i].ans += ta.sum(m + 1) - ta.sum(a[i].del);
    i++;
  }
  i = l + 1;
  j = mid + 1;
  while (i <= mid) {
    while (a[i].val > a[j].val && j <= r) {
      ta.c(a[j].del, -1);
      j++;
    }
    i++;
  }
  i = mid;
  j = r;
  while (j > mid) {
    while (a[j].val < a[i].val && i > l) {
      ta.c(a[i].del, 1);
      i--;
    }
    a[j].ans += ta.sum(m + 1) - ta.sum(a[j].del);
    j--;
  }
  i = mid;
  j = r;
  while (j > mid) {
    while (a[j].val < a[i].val && i > l) {
      ta.c(a[i].del, -1);
      i--;
    }
    j--;
  }
  sort(a + l + 1, a + r + 1, cmp1);
  return;
}

int main() {
  cin.tie(nullptr)->sync_with_stdio(false);
  cin >> n >> m;
  for (int i = 1; i <= n; i++) {
    cin >> a[i].val;
    rv[a[i].val] = i;
  }
  for (int i = 1; i <= m; i++) {
    int p;
    cin >> p;
    a[rv[p]].del = i;
  }
  for (int i = 1; i <= n; i++) {
    if (a[i].del == 0) a[i].del = m + 1;
  }
  for (int i = 1; i <= n; i++) {
    res += ta.sum(n + 1) - ta.sum(a[i].val);
    ta.c(a[i].val, 1);
  }
  for (int i = 1; i <= n; i++) {
    ta.c(a[i].val, -1);
  }
  solve(0, n);
  sort(a + 1, a + n + 1, cmp2);
  for (int i = 1; i <= m; i++) {
    cout << res << '\n';
    res -= a[i].ans;
  }
  return 0;
}

Optimizacija prijelaza 1D/1D dinamičkog programiranja CDQ podjelom

Povezani sadržaj: optimizacija DP-a CDQ podjelom

1D/1D dinamičko programiranje označava posebnu klasu DP zadataka kod kojih je DP polje jednodimenzionalno, a prijelaz je \(O(n)\). Ako su uvjeti povoljni, ponekad se CDQ podjelom njihova vremenska složenost može smanjiti s \(O(n^2)\) na \(O(n\log^2n)\).

Na primjer, zadan je niz u kojem svaki element ima dva svojstva \(a\), \(b\). Želimo izračunati vrijednost DP izraza čija je jednadžba prijelaza sljedeća:

\(dp_{i}=1+ \max_{j=1}^{i-1}dp_{j}[a_{j} < a_{i}][b_{j} < b_{i}]\)

To je DP jednadžba dvodimenzionalnog najduljeg rastućeg podniza, tj. samo točke \(j\) s \(j < i,a_{j} < a_{i},b_{j} < b_{i}\) mogu ažurirati DP vrijednost točke \(i\).

Izravan prijelaz očito je \(O(n^2)\). Slijedi objašnjenje kako se postupak prijelaza optimizira CDQ podjelom.

Primjećujemo da je i odnos prijelaza iz \(dp_{j}\) u \(dp_{i}\) odnos između parova točaka, pa ga obrađujemo na način sličan onome kojim CDQ podjela obrađuje odnose među parovima točaka.

Taj je postupak prijelaza prilično shematičan. Pretpostavimo da je interval koji trenutno obrađujemo \((l,r)\); tijek algoritma otprilike je sljedeći:

  1. ako je \(l=r\), dio \(\max\) vrijednosti \(dp_{r}\) već je izračunat, pa samo postavimo \(dp_{r} \gets dp_{r} + 1\) i vratimo se;
  2. rekurzivno pozovemo solve(l,mid);
  3. obradimo sve odnose prijelaza s \(l \leq j \leq mid\), \(mid+1 \leq i \leq r\);
  4. rekurzivno pozovemo solve(mid+1,r).

Treći korak radi se gotovo jednako kao kod CDQ podjele za trodimenzionalni parcijalni uređaj. Pri obradi odnosa prijelaza s \(l \leq j \leq mid\), \(mid+1 \leq i \leq r\) uočavamo da se više ne moramo brinuti o ograničenju \(j < i\). Stoga i dalje sve točke \(i\) i \(j\) najprije sortiramo po vrijednosti \(a\), zatim tehnikom dvostrukih pokazivača točke \(j\) ubacujemo u Fenwick tree i na kraju upitom za prefiksni maksimum ažuriramo \(dp_{i}\).

Dokaz ispravnosti postupka prijelaza

Najveća razlika između ovog načina pisanja CDQ-a i onoga za obradu odnosa među parovima točaka jest dio u kojem se obrađuju parovi s \(l \leq j \leq mid\), \(mid+1 \leq i \leq r\). Kod CDQ-a za odnose među parovima točaka taj se dio može staviti bilo gdje. No kad CDQ podjelom optimiziramo DP, taj postupak mora biti umetnut između \(solve(l,mid)\) i \(solve(mid+1,r)\). Razlog je to što su DP prijelazi uređeni i moraju zadovoljavati dva uvjeta, inače nisu ispravni:

  1. sve vrijednosti \(dp_{j}\) koje se koriste za izračun \(dp_{i}\) moraju već biti do kraja izračunate, ne smije postojati „poluproizvod”;

  2. sve vrijednosti \(dp_{j}\) koje se koriste za izračun \(dp_{i}\) moraju ažurirati \(dp_{i}\), ne smije postojati vrijednost \(dp_{j}\) koja ga nije ažurirala.

Ta su dva uvjeta kod \(O(n^2)\) grube sile vrlo lako zadovoljena, ali nakon primjene CDQ podjele redoslijed prijelaza očito je ispremiješan, pa je potrebno ispitati ispravnost prijelaza.

Rekurzivno stablo CDQ podjele prikazano je u nastavku.

Ako izvedemo upravo opisani algoritam, uzmimo za primjer točku \(8\): njezina DP vrijednost dovršava se u 3 funkcije, solve(1,8), solve(5,8), solve(7,8), a točke koje je ta tri puta ažuriraju redom su tri disjunktna intervala \((1,4)\), \((5,6)\), \((7,7)\); uzmimo zatim za primjer točku \(5\): njezina se DP vrijednost rješava u funkciji solve(1,4), a interval koji je ažurira je \((1,4)\). Pažljivim promatranjem uočavamo da se DP vrijednost točke \(i\) ažurira \(\log\) puta i da su intervali koji je ažuriraju upravo onih \(\log\) intervala na koje se \((1,i)\) rastavlja u segment treeju. Dakle, doista smo osigurali da je svaki valjani \(j\) ažurirao točku \(i\), pa je 2. uvjet zadovoljen.

Analizirajmo zatim tijek izvođenja našeg algoritma:

  1. prva funkcija koja završava je solve(1,1). Tada uočavamo da je vrijednost \(dp_{1}\) već izračunata;
  2. prva funkcija koja izvodi postupak prijelaza je solve(1,2). Tada uočavamo da je vrijednost \(dp_{2}\) već prenesena;
  3. druga funkcija koja završava je solve(2,2). Tada uočavamo da je vrijednost \(dp_{2}\) već izračunata;
  4. zatim završava solve(1,2) i sve vrijednosti \(dp\) na intervalu \((1,2)\) su izračunate;
  5. sljedeća funkcija koja izvodi postupak prijelaza je solve(1,4). Nakon tog prijelaza uočavamo da je vrijednost \(dp_{3}\) već prenesena;
  6. sljedeća funkcija koja završava je solve(3,3). Uočavamo da je dp vrijednost \(dp_{3}\) izračunata;
  7. sljedeći prijelaz koji se izvodi je solve(3,4). Tada je \(dp_{4}\) u solve(1,4) jednom preneseno iz \((1,2)\), a sada još i iz \((3,3)\), pa je i vrijednost \(dp_{4}\) prenesena;
  8. solve(4,4) završava, vrijednost \(dp_{4}\) je izračunata;
  9. solve(3,4) završava, vrijednosti na \((3,4)\) su izračunate;
  10. solve(1,4) završava, vrijednosti na \((1,4)\) su izračunate.
  11. …

Simulirajući tijek funkcija uočavamo jedno: svaki put kad solve(l,r) završi, sve DP vrijednosti na intervalu \((l,r)\) su do kraja izračunate. Budući da je svaki put kad izvodimo funkciju prijelaza solve(l,mid) već završio, svaki postupak prijelaza koji izvodimo je valjan, pa je 1. uvjet zadovoljen.

U upravo opisanom postupku uočili smo: ako rekurzivno stablo CDQ podjele promatramo kao segment tree, CDQ podjela je funkcija inorder obilaska tog segment treeja, pa smo zapravo sve DP vrijednosti obradili redom, samo je redoslijed prijelaza rastavljen; stoga je algoritam ispravan.

SDOI2011 拦截导弹 (Presretanje projektila)

Neka je država, radi obrane od raketnih napada neprijateljske države, razvila sustav za presretanje projektila. No taj sustav ima manu: iako njegov prvi projektil može doseći bilo koju visinu i presresti projektil bilo koje brzine, svaki sljedeći projektil ne smije biti viši od prethodnoga, a ni brzina leta projektila koji presreće ne smije biti veća od brzine prethodnoga. Jednog dana radar je zabilježio dolazak neprijateljskih projektila. Budući da je sustav još u probnoj fazi, postoji samo jedan komplet sustava, pa možda neće biti moguće presresti sve projektile.

Ako nije moguće presresti sve projektile, naravno da biramo plan koji državi nanosi najmanju štetu, tj. kojim se presreće najviše projektila. No planova s najvećim brojem presretnutih projektila može biti više; ako postoji više optimalnih planova, nasumično biramo jedan kao konačni plan akcije presretanja.

Naši špijuni već su pribavili visine i brzine svih neprijateljskih projektila. Vaš je zadatak izračunati, uz provođenje gore opisane odluke, vjerojatnost da svaki pojedini projektil bude presretnut.

Primjer koda 
// Zadatak s dvodimenzionalnim najduljim rastućim podnizom
// Da bismo utvrdili je li neki element u najduljem rastućem podnizu, CDQ možemo pokrenuti dvaput: unaprijed i unatrag
#include <algorithm>
#include <iomanip>
#include <iostream>
using namespace std;
using db = double;
constexpr int N = 1e6 + 10;

struct data_ {
  int h;
  int v;
  int p;
  int ma;
  db ca;
} a[2][N];

int n;
bool tr;

// Dolje su funkcije usporedbe
bool cmp1(const data_& a, const data_& b) {
  if (tr)
    return a.h > b.h;
  else
    return a.h < b.h;
}

bool cmp2(const data_& a, const data_& b) {
  if (tr)
    return a.v > b.v;
  else
    return a.v < b.v;
}

bool cmp3(const data_& a, const data_& b) {
  if (tr)
    return a.p < b.p;
  else
    return a.p > b.p;
}

bool cmp4(const data_& a, const data_& b) { return a.v == b.v; }

struct treearray {
  int ma[2 * N];
  db ca[2 * N];

  void c(int x, int t, db c) {
    for (; x <= n; x += x & (-x)) {
      if (ma[x] == t) {
        ca[x] += c;
      } else if (ma[x] < t) {
        ca[x] = c;
        ma[x] = t;
      }
    }
  }

  void d(int x) {
    for (; x <= n; x += x & (-x)) {
      ma[x] = 0;
      ca[x] = 0;
    }
  }

    for (; x > 0; x -= x & (-x)) {
      if (ma[x] == m) {
        c += ca[x];
      } else if (m < ma[x]) {
        c = ca[x];
        m = ma[x];
      }
    }
  }

}

Pretvaranje dinamičkih problema u statičke

U prva dva slučaja svrha CDQ podjele bila je prepoloviti niz i zatim rekurzivno obraditi odnose među parovima točaka kako bi se postigla dobra složenost. No u ovom odjeljku ne polovimo običan niz, nego vremenski niz.

Primjenjiva je na neke zadatke sa strukturama podataka tipa „treba podržati izmjene xxx i zatim upite xxx”. Takvi zadaci imaju dvije značajke:

  • ako upite obradimo offline, sve se operacije prirodno poredaju u niz po vremenu;
  • svaka je izmjena usko povezana s upitima koji dolaze nakon nje, a takvih odnosa „izmjena – upit” ima ukupno \(O(n^2)\).

CDQ podjelom možemo podijeliti taj niz operacija i obraditi odnose između izmjena i upita.

Slično CDQ podjeli za odnose među parovima točaka, pretpostavimo da je niz koji trenutno dijelimo \((l,r)\): najprije rekurzivno obradimo odnose izmjena – upit unutar \((l,mid)\) i \((mid,r)\), a zatim sve odnose izmjena – upit s \(l \leq i \leq mid\), \(mid+1 \leq j \leq r\), gdje je \(i\) izmjena, a \(j\) upit.

Uočimo: ako su pojedine izmjene međusobno neovisne, ne moramo voditi računa o vremenskom odnosu između \(l \leq i \leq mid\) i \(mid+1 \leq j \leq r\) te između solve(l,mid) i solve(mid+1,r) (npr. kod običnih zadataka sa zbrajanjem i oduzimanjem). No ako izmjene nisu neovisne (npr. operacije pridruživanja vrijednosti), izgled niza nakon izmjene može ovisiti o prethodnom nizu. Tada se korak obrade svih odnosa izmjena – upit koji prelaze preko mid mora smjestiti između solve(l,mid) i solve(mid+1,r). Razlog je isti kao kod optimizacije 1D/1D dinamičkog programiranja CDQ podjelom: samo podjela po inorder redoslijedu jamči da se svaka izmjena izvodi strogo po vremenskom redoslijedu.

Primjeri zadataka

Dodavanje na pravokutniku i zbroj pravokutnika

Održavajte dvodimenzionalno polje uz podršku dodavanja broja na pravokutno područje i upita o zbroju pravokutnog područja.

Ideja rješenja

Za inačicu ovog problema bez izmjena, tj. „zadano je dvodimenzionalno polje, više puta se pita zbroj pravokutnog područja”, postoji klasično rješenje pomoću sweep linea i segment treeja. Konkretno, svaki pravokutnik najprije rastavimo na dvije operacije, umetanje i brisanje, zatim svaki upit rastavimo na oblik razlike dvodimenzionalnih prefiksnih suma i na kraju sve obradimo offline. Međutim, izvorni zadatak ima izmjene, pa se to rješenje ne može izravno primijeniti.

Pokušajmo na njega primijeniti CDQ podjelu. Sve upite i izmjene obradimo offline. Te operacije tvore niz i postoji \(O(N^2)\) parova odnosa izmjena – upit. I dalje slijedimo uobičajeni tijek CDQ podjele: sve odnose dijelimo u tri vrste, na ovoj razini podjele obrađujemo samo odnose izmjena – upit koji prelaze preko \(mid\), a preostale odnose izmjena – upit rješavamo rekurzijom.

Uočavamo da su sve izmjene dovršene prije upita. Tada je izvorni problem ekvivalentan problemu „u ravnini se nalaze statični pravokutnici, neprestano se pita zbroj pravokutnog područja”.

Sweep lineom u vremenu \(O(n\log n)\) obradimo sve odnose izmjena – upit koji prelaze preko \(mid\), a ostaje još samo rekurzivno podijeliti odnose izmjena – upit na lijevoj i desnoj strani.

U ovako implementiranoj CDQ podjeli isti se upit obrađuje \(O(\log n)\) puta. No to nije problem, jer su izmjene koje svaki put doprinose tom upitu međusobno disjunktne. Vremenska složenost cijelog postupka je \(T(n)=T(\lfloor \frac{n}{2} \rfloor)+T(\lceil \frac{n}{2} \rceil)+ O(n\log n)=O(n\log^2n)\).

Promatrajući gornji tijek algoritma uočavamo da smo u početku znali riješiti samo statični problem dodavanja na pravokutniku i zbroja pravokutnika, ali jednostavnom primjenom CDQ podjele možemo offline riješiti i dinamički problem dodavanja na pravokutniku i zbroja pravokutnika. Bit pretvaranja dinamičkog problema u statički leži u tome što CDQ podjela svaki put obrađuje samo odnose izmjena i upita koji prelaze preko neke točke, pa tada moramo razmotriti samo jednostavan problem u kojem „su svi upiti nakon izmjena”. Upravo se zbog toga CDQ podjela naziva „alatom za pretvaranje dinamičkih problema u statičke”.

  1. Vrijednosti na intervalu \([l,r]\) postavi na \(x\);
  2. Odgovori koliko se različitih brojeva pojavljuje na intervalu \([l,r]\), tj. isti broj koji se pojavljuje više puta broji se samo jednom.

Ideja rješenja

Za svaku poziciju održavamo poziciju prve točke iste boje lijevo od nje, označimo je s \(pre_{i}\); time se brojanje boja na intervalu pretvara u klasičan problem brojanja točaka u ravnini (2D dominance counting).

struct treearray  // Fenwick tree
{
  int ta[N];

  void c(int x, int t) {
    for (; x <= n; x += x & (-x)) ta[x] += t;
  }

  void d(int x) {
    for (; x <= n; x += x & (-x)) ta[x] = 0;
  }

    int r = 0;
    for (; x; x -= x & (-x)) r += ta[x];
    return r;

  if (l1 == r1 || l2 == r2) return;
  int mid = (L + R) / 2;
  int mid1 = l1;
  while (mid1 != r1 && md[mid1 + 1].t <= mid) mid1++;
  int mid2 = l2;
  while (mid2 != r2 && qr[mid2 + 1].t <= mid) mid2++;
  solve(l1, mid1, l2, mid2, L, mid);
  solve(mid1, r1, mid2, r2, mid, R);

[HNOI2010] 城市建设 (Izgradnja gradova)

Država PS velika je zemlja s mnogo gradova. Kralj Louis razbija glavu oko izgradnje prometne infrastrukture među gradovima. Louis može graditi ceste između nekih gradova, a gradnja ceste između različitih gradova ima različitu cijenu.

Louis želi izgraditi najmanje cesta tako da svi gradovi u državi budu povezani. No zbog određenih čimbenika cijena gradnje ceste između gradova mijenja se s vremenom. Louis neprestano dobiva vijesti o promjeni cijene gradnje neke ceste. Želi nakon svake vijesti odmah znati najmanji ukupni trošak kojim se gradovi mogu povezati. Louis je odlučio zatražiti vašu pomoć za taj zadatak.

Zadatak u jednoj rečenici: zadan je graf uz podršku dinamičke izmjene težina bridova; nakon svake izmjene težine brida treba ispisati najmanju ukupnu cijenu minimalnog razapinjućeg stabla tog grafa.

Ideja rješenja

Zapravo postoji rješenje podjelom po segment treeju u kombinaciji s LCT-om, ali ta implementacija ima prevelik konstantni faktor i vjerojatno zahtijeva vješto optimiziranje konstanti da bi prošla ovaj zadatak, pa razmotrimo rješenje CDQ podjelom.

Za razliku od problema koje CDQ podjela obično rješava, ovdje pri primjeni CDQ podjele nemamo odnos izmjena – upit po kojem bismo dijelili, jer ne možemo zasebno razmatrati „kakav doprinos izmjena jednog brida ima na minimalno razapinjuće stablo cijelog grafa”. Čini se da tradicionalna ideja CDQ podjele ovdje ne radi baš dobro.

Iz prethodnih primjera vidi se da obična CDQ podjela ima posebnu vezu sa segment treejem: tijekom CDQ podjele zapravo implicitno gradimo segment tree (jer je rekurzivno stablo CDQ podjele upravo segment tree). Uobičajeni CDQ razmatra vezu između lijevog i desnog djeteta u segment treeju. A u ovom zadatku trebamo razmotriti odnos između roditelja i djeteta; drugim riječima, kad obrađujemo interval $solve(l,r)$, ako uspijemo veličinu grafa svesti na veličinu ovisnu o duljini intervala, problem je riješen.

Kako onda konkretno osmisliti algoritam?

Pretpostavimo da gradimo skup bridova minimalnog razapinjućeg stabla za interval \((l,r)\) i da već znamo skup bridova minimalnog razapinjućeg stabla njegova roditelja. Bridovima koji se mijenjaju unutar intervala \((l,r)\) pridružimo težine \(+ \infty\) odnosno \(-\infty\) te za svaku od tih dviju varijanti pokrenemo Kruskal i odredimo koji su bridovi u minimalnom razapinjućem stablu.

Za pojedini brid:

  • ako su svim izmijenjenim bridovima pridružene težine \(+\infty\), a brid se ne pojavljuje u minimalnom razapinjućem stablu, dokazano je da se ne može pojaviti u minimalnom razapinjućem stablu ni za jedan upit iz \((l,r)\). Zato u skup bridova za \((l,r)\) dodajemo samo bridove tog minimalnog razapinjućeg stabla;
  • ako su svim izmijenjenim bridovima pridružene težine \(-\infty\), a brid se pojavljuje u minimalnom razapinjućem stablu, dokazano je da će se sigurno pojaviti u minimalnom razapinjućem stablu na cijelom intervalu \((l,r)\). Tada pomoću union–finda (disjoint set union) sažmemo vrhove tih bridova u jedan i njihove težine dodamo odgovoru.

Tako smo konstruirali skup bridova za interval \((l,r)\). Minimalno razapinjuće stablo dobiveno iz tih bridova ekvivalentno je minimalnom razapinjućem stablu izvornog grafa.

Zašto je onda naša složenost ispravna?

Prvo, izmijenjeni bridovi sigurno ulaze u naš skup bridova, a njihov je broj reda \(O(len)\).

Zatim moramo dokazati da u skupu bridova neće biti previše neizmijenjenih bridova. Dodajemo samo bridove minimalnog razapinjućeg stabla u kojem sve izmijenjene težine iznose \(+\infty\), pa broj dodanih bridova ne premašuje broj vrhova trenutnog grafa.

Sada još samo treba dokazati da je broj vrhova grafa na svakoj razini rekurzije reda \(O(len)\) i time je pokazano da je i broj bridova grafa reda \(O(len)\).

Dokaz da je broj vrhova reda \(O(len)\) postaje vrlo jednostavan. Bridovi koje sažimamo pri svakom spuštanju u rekurziju su neizmijenjeni bridovi koji se pojavljuju u razapinjućem stablu s \(-\infty\); gledano obrnuto, odrezali smo sve izmijenjene bridove koji se pojavljuju u razapinjućem stablu s \(-\infty\). Očito odrežemo najviše \(len\) bridova, pa se cijeli graf raspada na najviše \(O(len)\) komponenata povezanosti, a time je broj vrhova novog grafa reda \(O(len)\). Time smo dokazali da je graf na kojem pokrećemo Kruskal svaki put reda \(O(len)\), pa je vremenska složenost svake razine \(O(n\log n)\).

Vremenska složenost je \(T(n)=T(\lfloor \frac{n}{2} \rfloor)+T(\lceil \frac{n}{2} \rceil)+ O(n\log n)=O(n\log^2n)\).

Implementacija može biti ponešto zahtjevna. Treba paziti da union–find ne smije koristiti kompresiju puta, jer inače ne bi podržavao vraćanje (rollback). Sažimanje vrhova također nije potrebno doista izvoditi; dovoljno je da se Kruskal na svakoj razini izravno izvodi u union–findu prethodne razine.

    int u = f(x);
    int v = f(y);

    if (size[u] < size[v]) swap(u, v);
    size[u] += size[v];
    fa[v] = u;
    opt o;
    o.u = u;
    o.v = v;
    st.push(o);
  }

    opt o = st.top();
    st.pop();
    fa[o.v] = o.v;
    size[o.u] -= size[o.v];
  }

    while (st.size() > tim) {

This page introduces CDQ divide and conquer.

Introduction

CDQ divide and conquer is an idea rather than a concrete algorithm, similar to dynamic programming. Nowadays this idea has been extended very widely, and by principle and style of implementation it is roughly divided into three categories:

  • solving problems about pairs of points;
  • optimization and transitions of 1D dynamic programming;
  • turning some dynamic problems into static ones by CDQ divide and conquer.

The idea of CDQ divide and conquer was first organized and summarized, while still in high school, by Chen Danqi (陈丹琦), an IOI 2008 gold medalist, and it is named after her.1

Solving problems about pairs of points

Most problems of this kind look like "given a sequence of length \(n\), count the pairs of points \((i,j)\) with certain properties" or "given a sequence of length \(n\), find a pair of points \((i,j)\) that maximizes the value of some function".

The algorithm by which CDQ divide and conquer solves such problems is as follows:

  1. find the midpoint \(mid\) of the sequence;

  2. divide all pairs of points \((i,j)\) into 3 categories:

    1. pairs with \(1 \leq i \leq mid,1 \leq j \leq mid\);
    2. pairs with \(1 \leq i \leq mid ,mid+1 \leq j \leq n\);
    3. pairs with \(mid+1 \leq i \leq n,mid+1 \leq j \leq n\).

  3. split the sequence \((1,n)\) into two sequences \((1,mid)\) and \((mid+1,n)\). Now the pairs of the first and the third category both lie inside these two sequences;

  4. handle these two categories of pairs recursively;

  5. find a way to handle the pairs of the second category.

As we can see, the idea of CDQ divide and conquer is to keep distributing the pairs of points recursively to the left and the right interval.

In practice we usually use a function solve(l,r) that handles the pairs with \(l \leq i \leq r,l \leq j \leq r\). The recursive part of the algorithm above is implemented by solve(l,mid) and solve(mid+1,r). For the remaining pairs of the second category an additional algorithm has to be designed.

Example problems

三维偏序 (3D Partial Order)

Given a sequence in which every point has three attributes \(a_i,b_i,c_i\), find how many pairs of points \((i,j)\) in this sequence satisfy \(a_j \leq a_i\) and \(b_j \leq b_i\) and \(c_j \leq c_i\) and \(j \ne i\).

Solution idea

The 3D partial order is the classic problem for CDQ divide and conquer.

The problem asks us to count pairs of points in a sequence, so let us try CDQ divide and conquer.

First sort the sequence by \(a\).

Suppose we have already written solve(l,r) and have handled solve(l,mid) and solve(mid+1,r) by recursion. What we have to do now is to count how many pairs of points \((i,j)\) with \(l \leq i \leq mid\), \(mid+1 \leq j \leq r\) also satisfy the constraints \(a_{i} \leq a_{j}\), \(b_{i} \leq b_{j}\), \(c_{i} \leq c_{j}\).

After a moment of thought we notice that the constraint \(a_{i} \leq a_{j}\) is no longer useful: since \(i\) is smaller than \(mid\) and \(j\) is larger than \(mid\), \(i\) is certainly smaller than \(j\); and as the sequence has already been sorted by \(a\), we necessarily have \(a_{i} \leq a_{j}\). Two constraints remain: \(b_{i} \leq b_{j}\) and \(c_{i} \leq c_{j}\). Based on them we can enumerate \(j\) and find how many \(i\) satisfy the conditions.

To make the enumeration convenient, we sort all points in \((l,mid)\) and \((mid+1,r)\) by the value of \(b\) in increasing order. Then we enumerate every \(j\) in turn and insert all points \(i\) with \(b_{i} \leq b_{j}\) into some data structure (here we choose a Fenwick tree). Now we only have to query how many points in the Fenwick tree have a \(c\) value less than or equal to \(c_{j}\), and we have found how many \(i\) can be validly matched with this point \(j\).

When we insert a point whose \(c\) value equals \(x\), we add one at position \(x\) of the Fenwick tree, and querying how many points in the Fenwick tree are smaller than \(x\) is actually computing a prefix sum; as long as we have discretized all \(c\) values beforehand, the complexity is right.

For every \(j\) we have to insert all points \(i\) with \(b_{i} \leq b_{j}\) into the Fenwick tree. Since all \(i\) and \(j\) have already been sorted by \(b\) beforehand, it suffices to insert the points into the Fenwick tree with the two pointers technique, and the number of insertions into the Fenwick tree drops from \(O(n^2)\) to \(O(n)\).

With this algorithm we have processed the information about the pairs of the second category in \(O(n\log n)\) time. The time complexity of the algorithm is then \(T(n)=T(\lfloor \frac{n}{2} \rfloor)+T(\lceil \frac{n}{2} \rceil)+O(n\log n)=O(n\log^2n)\).

#include <algorithm>
#include <iostream>

constexpr int MAXN = 1e5 + 10;
constexpr int MAXK = 2e5 + 10;

int n, k;

struct Element {
  int a, b, c;
  int cnt;
  int res;

  bool operator!=(Element other) const {
    if (a != other.a) return true;
    if (b != other.b) return true;
    if (c != other.c) return true;
    return false;
  }
};

Element e[MAXN];
Element ue[MAXN];
int m, t;
int res[MAXN];

struct BinaryIndexedTree {
  int node[MAXK];

  int lowbit(int x) { return x & -x; }

  void Add(int pos, int val) {
    while (pos <= k) {
      node[pos] += val;
      pos += lowbit(pos);
    }
    return;
  }

  int Ask(int pos) {
    int res = 0;
    while (pos) {
      res += node[pos];
      pos -= lowbit(pos);
    }
    return res;
  }
} BIT;

bool cmpA(Element x, Element y) {
  if (x.a != y.a) return x.a < y.a;
  if (x.b != y.b) return x.b < y.b;
  return x.c < y.c;
}

bool cmpB(Element x, Element y) {
  if (x.b != y.b) return x.b < y.b;
  return x.c < y.c;
}

void CDQ(int l, int r) {
  if (l == r) return;
  int mid = (l + r) / 2;
  CDQ(l, mid);
  CDQ(mid + 1, r);
  std::sort(ue + l, ue + mid + 1, cmpB);
  std::sort(ue + mid + 1, ue + r + 1, cmpB);
  int i = l;
  int j = mid + 1;
  while (j <= r) {
    while (i <= mid && ue[i].b <= ue[j].b) {
      BIT.Add(ue[i].c, ue[i].cnt);
      i++;
    }
    ue[j].res += BIT.Ask(ue[j].c);
    j++;
  }
  for (int k = l; k < i; k++) BIT.Add(ue[k].c, -ue[k].cnt);
  return;
}

using std::cout;

  cin.tie(nullptr)->sync_with_stdio(false);
  cin >> n >> k;
  for (int i = 1; i <= n; i++) cin >> e[i].a >> e[i].b >> e[i].c;
  std::sort(e + 1, e + n + 1, cmpA);
  for (int i = 1; i <= n; i++) {
    t++;
    if (e[i] != e[i + 1]) {
      m++;
      ue[m].a = e[i].a;
      ue[m].b = e[i].b;
      ue[m].c = e[i].c;
      ue[m].cnt = t;
      t = 0;
    }
  }
  CDQ(1, m);
  for (int i = 1; i <= m; i++) res[ue[i].res + ue[i].cnt - 1] += ue[i].cnt;
  for (int i = 0; i < n; i++) cout << res[i] << '\n';
  return 0;
}
CQOI2011 动态逆序对 (Dynamic Inversions)

For a sequence \(a\), its number of inversions is defined as the number of elements of the set \(\{(i,j)| i < j \wedge a_i > a_j \}\).

Given a permutation of \(1\sim n\), \(m\) elements are deleted one by one in some order. Your task is to count the number of inversions of the whole sequence before every deletion.

#include <iostream>

struct treearray {
  int ta[200010];

  void db(int& x) { x -= x & (-x); }

  void c(int x, int t) {
    for (; x <= n + 1; ub(x)) ta[x] += t;
  }

    int r = 0;
    for (; x > 0; db(x)) r += ta[x];
    return r;
  }

struct data_ {
  int val;
  int del;
  int ans;

  if (r - l == 1) {
    return;
  }

  solve(l, mid);
  solve(mid, r);
  int i = l + 1;
  int j = mid + 1;

    while (a[i].val > a[j].val && j <= r) {
      ta.c(a[j].del, 1);
      j++;
    }
    a[i].ans += ta.sum(m + 1) - ta.sum(a[i].del);
    i++;

  i = l + 1;
  j = mid + 1;

      j++;
    }
    i++;

CDQ divide and conquer optimization of 1D/1D dynamic programming transitions

Related content: CDQ divide and conquer optimization of DP

1D/1D dynamic programming refers to a specific class of DP problems whose characteristic is that the DP array is one-dimensional and the transition is \(O(n)\). If the conditions are good, their time complexity can sometimes be reduced from \(O(n^2)\) to \(O(n\log^2n)\) by CDQ divide and conquer.

For example, given a sequence in which every element has two attributes \(a\), \(b\), we want to compute the value of a DP expression whose transition equation is as follows:

\(dp_{i}=1+ \max_{j=1}^{i-1}dp_{j}[a_{j} < a_{i}][b_{j} < b_{i}]\)

This is the DP equation of a two-dimensional longest increasing subsequence, i.e. only points \(j\) with \(j < i,a_{j} < a_{i},b_{j} < b_{i}\) can update the DP value of point \(i\).

A direct transition is obviously \(O(n^2)\). What follows is an explanation of how to optimize the transition process with CDQ divide and conquer.

We notice that the transition relation from \(dp_{j}\) to \(dp_{i}\) is also a relation between pairs of points, so we handle it in a way similar to how CDQ divide and conquer handles relations between pairs of points.

This transition process is relatively formulaic. Suppose the interval currently being processed is \((l,r)\); the algorithm goes roughly as follows:

  1. if \(l=r\), the \(\max\) part of the value \(dp_{r}\) has already been computed, so we simply set \(dp_{r} \gets dp_{r} + 1\) and return;
  2. call solve(l,mid) recursively;
  3. handle all transition relations with \(l \leq j \leq mid\), \(mid+1 \leq i \leq r\);
  4. call solve(mid+1,r) recursively.

The third step is done almost the same way as CDQ divide and conquer for the 3D partial order. When handling the transition relations with \(l \leq j \leq mid\), \(mid+1 \leq i \leq r\), we find that we no longer need to care about the constraint \(j < i\). Therefore we again first sort all points \(i\) and \(j\) by the value of \(a\), then insert the points \(j\) into a Fenwick tree with the two pointers technique, and finally query the prefix maximum to update \(dp_{i}\).

Proof of correctness of the transition process

The biggest difference between this way of writing CDQ and the one for handling relations between pairs of points is the part that handles the pairs with \(l \leq j \leq mid\), \(mid+1 \leq i \leq r\). In the CDQ for relations between pairs of points this part can be placed anywhere. However, when optimizing DP with CDQ divide and conquer, this step must be sandwiched between \(solve(l,mid)\) and \(solve(mid+1,r)\). The reason is that DP transitions are ordered; they must satisfy two conditions, otherwise they are wrong:

  1. all values \(dp_{j}\) used to compute \(dp_{i}\) must already be fully computed; there must be no "half-finished product";

  2. all values \(dp_{j}\) used to compute \(dp_{i}\) must update \(dp_{i}\); there must be no value \(dp_{j}\) that has not updated it.

These two conditions are quite easy to satisfy in the \(O(n^2)\) brute force, but after applying CDQ divide and conquer the order of transitions is obviously scrambled, so it is necessary to examine the correctness of the transitions.

The recursion tree of CDQ divide and conquer is shown below.

If we run the algorithm just described, take point \(8\) as an example: its DP value is completed in the 3 functions solve(1,8), solve(5,8), solve(7,8), and the points used to update it those three times are the three disjoint intervals \((1,4)\), \((5,6)\), \((7,7)\); take point \(5\) as another example: its DP value is settled in the function solve(1,4), and the interval that updates it is \((1,4)\). Looking carefully, we find that the DP value of a point \(i\) is updated \(\log\) times, and the intervals that update it are exactly the \(\log\) intervals into which \((1,i)\) is split in a segment tree. Therefore we have indeed guaranteed that every valid \(j\) has updated point \(i\), so condition 2 is satisfied.

Next we analyze the execution flow of our algorithm:

  1. the first function to finish is solve(1,1). At this point we find that the value of \(dp_{1}\) has been computed;
  2. the first function to execute the transition process is solve(1,2). At this point we find that the value of \(dp_{2}\) has been transitioned;
  3. the second function to finish is solve(2,2). At this point we find that the value of \(dp_{2}\) has been computed;
  4. next solve(1,2) finishes, and all \(dp\) values on the interval \((1,2)\) have been computed;
  5. the next function to execute the transition process is solve(1,4). After this transition we find that the value of \(dp_{3}\) has been transitioned;
  6. the next function to finish is solve(3,3). We find that the dp value of \(dp_{3}\) has been computed;
  7. the next transition executed is solve(3,4). At this point \(dp_{4}\) was transitioned once from \((1,2)\) in solve(1,4) and is now transitioned from \((3,3)\) as well, so the value of \(dp_{4}\) has also been transitioned;
  8. solve(4,4) finishes, the value of \(dp_{4}\) is computed;
  9. solve(3,4) finishes, the values on \((3,4)\) are computed;
  10. solve(1,4) finishes, the values on \((1,4)\) are computed.
  11. …

By simulating the flow of the functions we notice one thing: every time solve(l,r) finishes, all DP values on the interval \((l,r)\) have been computed. Since every time we execute the transition function solve(l,mid) has already finished, every transition process we execute is valid, so condition 1 is satisfied.

In the process above we found that if we view the recursion tree of CDQ divide and conquer as a segment tree, then CDQ divide and conquer is the inorder traversal function of this segment tree; so we have effectively processed all DP values in order, only the order of transitions has been split up, and therefore the algorithm is correct.

Turning dynamic problems into static ones

In the first two cases the purpose of CDQ divide and conquer was to halve the sequence and then recursively handle the relations between pairs of points, in order to obtain a good complexity. In this section, however, what is halved is not an ordinary sequence but a sequence in time.

It applies to some data structure problems of the kind "support doing updates xxx and then doing queries xxx". Such problems have two characteristics:

  • if the queries are processed offline, all operations are naturally arranged in a sequence by time;
  • every update is closely related to the queries that come after it, and there are \(O(n^2)\) such "update – query" relations in total.

We can use CDQ divide and conquer on this sequence of operations to handle the relations between updates and queries.

Similar to CDQ divide and conquer for relations between pairs of points, suppose the sequence currently being divided is \((l,r)\): we first recursively handle the update – query relations within \((l,mid)\) and \((mid,r)\), and then handle all update – query relations with \(l \leq i \leq mid\), \(mid+1 \leq j \leq r\), where \(i\) is an update and \(j\) is a query.

Note that if the individual updates are independent of each other, we do not need to care about the time ordering between \(l \leq i \leq mid\) and \(mid+1 \leq j \leq r\), or between solve(l,mid) and solve(mid+1,r) (for example in ordinary addition/subtraction problems). But if the updates are not independent (for example assignment operations), what the sequence looks like after an update may depend on the previous sequence. In that case the step that handles all update – query relations crossing mid must be placed between solve(l,mid) and solve(mid+1,r). The reason is the same as for the CDQ divide and conquer optimization of 1D/1D dynamic programming: only dividing in inorder guarantees that every update is executed strictly in time order.

Example problems

Rectangle add, rectangle sum

Maintain a two-dimensional array, supporting adding a number to a rectangular region and querying the sum of a rectangular region.

Solution idea

For the version of this problem without updates, i.e. "given a two-dimensional array, query the sum of a rectangular region many times", there is a classic solution with a sweep line combined with a segment tree. Concretely, first split every rectangle into two operations, an insertion and a deletion, then split every query into the form of a difference of two-dimensional prefix sums, and finally process everything offline. However, the original problem has updates, so this solution cannot be applied directly.

Let us try to apply CDQ divide and conquer to it. We process all queries and updates offline. These operations form a sequence, and there are \(O(N^2)\) pairs of update – query relations. We still follow the general procedure of CDQ divide and conquer: divide all relations into three categories, handle only the update – query relations crossing \(mid\) at this level of the recursion, and solve the remaining update – query relations recursively.

We notice that all updates are completed before the queries. Then the original problem is equivalent to "there are some static rectangles in the plane; keep querying the sum of a rectangular region".

Use a sweep line to handle all update – query relations crossing \(mid\) in \(O(n\log n)\) time; what remains is to recursively divide and conquer the update – query relations on the left and on the right side.

In a CDQ divide and conquer implemented like this, the same query is processed \(O(\log n)\) times. But that does not matter, because the updates that contribute to this query each time are pairwise disjoint. The time complexity of the whole procedure is \(T(n)=T(\lfloor \frac{n}{2} \rfloor)+T(\lceil \frac{n}{2} \rceil)+ O(n\log n)=O(n\log^2n)\).

Looking at the algorithm above, we find that at the beginning we could only solve the static rectangle add, rectangle sum problem, but after simply applying CDQ divide and conquer we can solve a dynamic rectangle add, rectangle sum problem offline. The essence of turning a dynamic problem into a static one is that CDQ divide and conquer only handles the update and query relations crossing a certain point each time, so we only need to consider the simple problem in which "all queries come after the updates". It is precisely because of this that CDQ divide and conquer is called "a tool for turning dynamic problems into static ones".

[Ynoi2016] 镜中的昆虫 (Insects in the Mirror)

Maintain a sequence \(a_i\) of length \(n\) with \(m\) operations.

  1. Set the values on the interval \([l,r]\) to \(x\);
  2. Query how many distinct numbers appear on the interval \([l,r]\), i.e. the same number appearing several times counts only once.

Problem in one sentence: range assignment, range color counting.

Solution idea

For every position maintain the position of the first point of the same color to its left, denoted \(pre_{i}\); then range color counting is turned into a classic 2D dominance counting problem.

By viewing a contiguous segment of the same color as a single point, it can be proved that the total amount of change of \(pre\) is \(O(n+m)\), i.e. a single operation causes only \(O(1)\) changes of \(pre\) values; so we can use CDQ divide and conquer to solve the dynamic point add, rectangle sum problem.

The concrete changes of the array \(pre\) can be handled with std::set. This technique of maintaining contiguous intervals with a set is also called old driver tree.

[HNOI2010] 城市建设 (City Construction)

The country PS is a large country with many cities. King Louis racks his brains over the construction of transportation between the cities. Louis can build roads between certain cities, and building a road between different cities requires a different cost.

Louis wants to build the fewest roads so that all cities in the country are connected. However, due to certain factors, the cost of building a road between cities changes over time. Louis keeps receiving news that the construction cost of some road has changed. He wants to know, immediately after receiving each piece of news, the minimum total cost of connecting the cities. Louis has decided to ask you for help with this task.

Problem in one sentence: given a graph, support dynamic changes of edge weights, and after every change of an edge weight output the minimum total cost of the minimum spanning tree of this graph.

Solution idea

In fact there is a solution with segment tree divide and conquer combined with LCT that solves this problem, but this implementation has too large a constant factor and probably needs clever constant optimization to pass this problem, so let us consider solving it with CDQ divide and conquer.

Unlike the problems CDQ divide and conquer usually solves, here, when using CDQ divide and conquer, there is no update – query relation along which to divide, because we cannot separately consider "what contribution changing one edge makes to the minimum spanning tree of the whole graph". The traditional idea of CDQ divide and conquer does not seem to work very well.

From the previous examples we can see that ordinary CDQ divide and conquer has a special connection with segment trees: during CDQ divide and conquer we actually implicitly build a segment tree (because the recursion tree of CDQ divide and conquer is exactly a segment tree). Ordinary CDQ considers the relation between the left and the right child of the segment tree. For this problem, what we need to consider is the relation between a parent and its child; in other words, when we are at the interval $solve(l,r)$, if we can find a way to make the size of the graph a quantity related to the length of the interval, we can solve this problem.

So how do we design the algorithm concretely?

Suppose we are constructing the edge set of the minimum spanning tree for the interval \((l,r)\), and we already know the edge set of the minimum spanning tree of its parent. We assign the edges that change within the interval \((l,r)\) the weights \(+ \infty\) and \(-\infty\) respectively, run Kruskal once for each, and find which edges are in the minimum spanning tree.

For an edge:

  • if all modified edge weights are set to \(+\infty\) and it does not appear in the minimum spanning tree, it is proved that it cannot appear in the minimum spanning tree of any query in \((l,r)\). So we only add the tree edges of the minimum spanning tree to the edge set of \((l,r)\);
  • if all modified edge weights are set to \(-\infty\) and it appears in the minimum spanning tree, it is proved that it will certainly appear in the minimum spanning tree over the interval \((l,r)\). In that case we can use a disjoint set union to contract the vertices of these edges and add their weights to the answer.

In this way we have constructed the edge set of the interval \((l,r)\). The minimum spanning tree obtained from these edges is equivalent to the minimum spanning tree of the original graph.

So why is our complexity correct?

First, the modified edges are certainly added to our edge set, and their number is of order \(O(len)\).

Next we need to prove that the edge set will not contain too many unmodified edges. We only add the tree edges of the minimum spanning tree with all weights set to \(+\infty\), so the number of edges we add does not exceed the number of vertices of the current graph.

Now we only have to prove that the number of vertices of the graph at every level of the recursion is of order \(O(len)\), and then the number of edges of the graph is of order \(O(len)\) as well.

Proving that the number of vertices is \(O(len)\) becomes very simple. The edges we contract every time we recurse downward are the unmodified edges appearing in the \(-\infty\) spanning tree; thinking of it the other way around, we have cut all the modified edges appearing in the \(-\infty\) spanning tree. Obviously we cut at most \(len\) edges, so the whole graph splits into at most \(O(len)\) connected components, and thus the number of vertices of the new graph is of order \(O(len)\). So we have proved that the graph on which we run Kruskal is of order \(O(len)\) every time, and hence the time complexity of every level is \(O(n\log n)\).

The time complexity is \(T(n)=T(\lfloor \frac{n}{2} \rfloor)+T(\lceil \frac{n}{2} \rceil)+ O(n\log n)=O(n\log^2n)\).

The implementation may be somewhat difficult. Note that the disjoint set union cannot use path compression, otherwise it would not support rollback. It is also not necessary to actually perform the contraction; it suffices to run Kruskal at every level directly in the disjoint set union of the previous level.

bool book[50010];  // query
vector<edge> ve[30];
vector<moved> vq;
vector<edge> tr;
ll res[30];
int tim[30];

void pushdown(int dep)  // edge contraction
{
  tr.clear();  // a copy is needed here, otherwise the operations could not be rolled back
  for (int i = 0; i < ve[dep].size(); i++) {
    tr.push_back(ve[dep][i]);
  }
  sort(tr.begin(), tr.end());
  for (int i = 0; i < tr.size(); i++) {  // useless edges
    if (s1.f(tr[i].u) == s1.f(tr[i].v)) {
      tr[i].mrk = -1;
      continue;
    }
    s1.u(tr[i].u, tr[i].v);
  }
  s1.clear(0);
  res[dep + 1] = res[dep];
  for (int i = 0; i < vq.size(); i++) {
    s1.u(vq[i].u, vq[i].v);
  }
  vq.clear();
  for (int i = 0; i < tr.size(); i++) {  // mandatory edges
    if (tr[i].mrk == -1 || s1.f(tr[i].u) == s1.f(tr[i].v)) continue;
    tr[i].mrk = 1;
    s1.u(tr[i].u, tr[i].v);
    s.u(tr[i].u, tr[i].v);
    res[dep + 1] += tr[i].val;
  }
  s1.clear(0);
  ve[dep + 1].clear();
  for (int i = 0; i < tr.size(); i++) {  // contract edges
    if (tr[i].mrk != 0) continue;
    edge p;
    p.u = s.f(tr[i].u);
    p.v = s.f(tr[i].v);
    if (p.u == p.v) continue;
    p.val = tr[i].val;
    p.mrk = 0;
    ve[dep + 1].push_back(p);
  }
  return;
}

void solve(int l, int r, int dep) {
  tim[dep] = s.st.size();
  int mid = (l + r) / 2;
  if (r - l == 1) {  // termination condition
    edge p;
    p.u = s.f(e[q[r].num].u);
    p.v = s.f(e[q[r].num].v);
    p.val = q[r].val;
    e[q[r].num].val = q[r].val;
    p.mrk = 0;
    ve[dep].push_back(p);
    pushdown(dep);
    q[r].ans = res[dep + 1];
    s.clear(tim[dep - 1]);
    return;
  }
  for (int i = l + 1; i <= mid; i++) {
    book[q[i].num] = true;
  }
  for (int i = mid + 1; i <= r; i++) {  // dynamic -> static
    if (book[q[i].num]) continue;
    edge p;
    p.u = s.f(e[q[i].num].u);
    p.v = s.f(e[q[i].num].v);
    p.val = e[q[i].num].val;
    p.mrk = 0;
    ve[dep].push_back(p);
  }
  for (int i = l + 1; i <= mid; i++) {  // query -> dynamic
    moved p;
    p.u = s.f(e[q[i].num].u);
    p.v = s.f(e[q[i].num].v);
    vq.push_back(p);
  }
  pushdown(dep);  // what follows is the rollback
  for (int i = mid + 1; i <= r; i++) {
    if (book[q[i].num]) continue;
    ve[dep].pop_back();
  }
  for (int i = l + 1; i <= mid; i++) {
    book[q[i].num] = false;
  }
  solve(l, mid, dep + 1);
  for (int i = 0; i < ve[dep].size(); i++) {
    ve[dep][i].mrk = 0;
  }
  for (int i = mid + 1; i <= r; i++) {
    book[q[i].num] = true;
  }
  for (int i = l + 1; i <= mid; i++) {  // dynamic -> static
    if (book[q[i].num]) continue;
    edge p;
    p.u = s.f(e[q[i].num].u);
    p.v = s.f(e[q[i].num].v);
    p.val = e[q[i].num].val;
    p.mrk = 0;
    ve[dep].push_back(p);
  }
  for (int i = mid + 1; i <= r; i++) {  // query -> dynamic
    book[q[i].num] = false;
    moved p;
    p.u = s.f(e[q[i].num].u);
    p.v = s.f(e[q[i].num].v);
    vq.push_back(p);
  }
  pushdown(dep);
  solve(mid, r, dep + 1);
  s.clear(tim[dep - 1]);
  return;  // rewind time to the previous level
}

int main() {
  cin.tie(nullptr)->sync_with_stdio(false);
  cin >> n >> m >> ask;
  s.ih();
  s1.ih();
  for (int i = 1; i <= m; i++) {
    cin >> e[i].u >> e[i].v >> e[i].val;
  }
  for (int i = 1; i <= ask; i++) {
    cin >> q[i].num >> q[i].val;
  }
  for (int i = 1; i <= ask; i++) {  // initial dynamic edges
    book[q[i].num] = true;
    moved p;
    p.u = e[q[i].num].u;
    p.v = e[q[i].num].v;
    vq.push_back(p);
  }
  for (int i = 1; i <= m; i++) {  // initial static
    if (book[i]) continue;
    ve[1].push_back(e[i]);
  }
  for (int i = 1; i <= ask; i++) {
    book[q[i].num] = false;
  }
  solve(0, ask, 1);
  for (int i = 1; i <= ask; i++) {
    cout << q[i].ans << '\n';
  }
  return 0;
}
