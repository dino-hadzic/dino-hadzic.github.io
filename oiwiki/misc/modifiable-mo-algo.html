Provjerite da već vladate običnim Mo algoritmom. Ako ga još ne znate, prvo pročitajte prethodnu stranicu Običan Mo algoritam.

Značajke

Običan Mo algoritam ne podržava izmjene.

Možemo ga nasilu natjerati da podržava izmjene: kao u DP-u, možemo nasilu dodati jednu dimenziju, vremensku dimenziju, koja označava vrijeme ove operacije.

Vremenska dimenzija označava broj dosad primijenjenih izmjena.

Drugim riječima, upit \([l,r]\) pretvaramo u \([l,r,\text{time}]\).

Tada se naše koordinate mogu pomicati i po vremenskoj dimenziji, tj. \([l,r,\text{time}]\) ima jednu dimenziju više u kojoj se može pomaknuti i može prijeći u:

  • \([l-1,r,\text{time}]\)
  • \([l+1,r,\text{time}]\)
  • \([l,r-1,\text{time}]\)
  • \([l,r+1,\text{time}]\)
  • \([l,r,\text{time}-1]\)
  • \([l,r,\text{time}+1]\)

Takav je prijelaz također \(O(1)\), ali naše sortiranje ima jedan ključ više; dovoljno je malo doraditi.

Sortiranje i prijelazi mogu se izvesti slično običnom Mo algoritmu, čime se postiže \(O(n^{5/3})\).

Ovaj put sortiramo tako da je blok duljine \(n^{2/3}\) i blokova je \(n^{1/3}\); prvi je ključ blok u kojem se nalazi lijevi kraj, drugi ključ blok u kojem se nalazi desni kraj, a treći ključ vrijeme.

Optimalna duljina bloka i analiza vremenske složenosti

Neka je duljina niza \(n\), neka ima \(m\) upita i \(t\) izmjena.

Drugi ključ sortiranja u Mo algoritmu s izmjenama indeks je bloka u kojem se nalazi desni kraj, za razliku od običnog Mo algoritma.

Razmislite što bi bilo da desni kraj ne dijelimo na blokove:

  • Nesortirani desni krajevi za svaki bi se upit pomicali \(n\) puta.
  • Sortirani desni krajevi donijeli bi nesortirana vremena, pa bi se za svaki upit vrijeme pomicalo \(t\) puta.

U oba je slučaja vremenski trošak neprihvatljiv.

Analizirajmo sada vremensku složenost.

Neka je duljina bloka \(s\); tada ima \(\dfrac{n}{s}\) blokova. Za blokove \(i\) i \(j\) neka \(q_{i,j}\) označava broj upita čiji je lijevi kraj u bloku \(i\), a desni kraj u bloku \(j\).

Za svaku „grupu” upita \((i,j)\) kod kojih lijevi i desni kraj ne mijenjaju blok, krajevi se pri svakom pomaku pomiču \(O(s)\) puta, a vrijeme monotono raste: \(O(t)\).

Vrijeme promjene bloka lijevog i desnog kraja zanemarujemo.

Zapisano, to je:

\[ \begin{aligned} &\sum_{i=1}^{n/s}\sum_{j=i+1}^{n/s}(q_{i,j}\cdot s+t)\\ =&ms+\left(\dfrac{n}{s}\right)^2t\\ =&ms+\dfrac{n^2t}{s^2} \end{aligned} \]

Minimum tog izraza tražimo deriviranjem. Neka je \(f(s)=ms+\dfrac{n^2t}{s^2}\). Tada je \(f'(s)=m-\dfrac{2n^2t}{s^3}=0\).

Dobivamo \(s=\sqrt[3]{\dfrac{2n^2t}{m}}=\dfrac{2^{1/3}n^{2/3}t^{1/3}}{m^{1/3}}=s_0\).

Dakle, kad je duljina bloka \(\dfrac{n^{2/3}t^{1/3}}{m^{1/3}}\), dobiva se optimalna vremenska složenost \(O\left(n^{2/3}m^{2/3}t^{1/3}\right)\).

Često spominjana složenost \(O\left(n^{5/3}\right)\) upravo je vremenska složenost kad se \(n,m,t\) smatraju istim redom veličine.

U praksi se ipak preporučuje uzeti \(n^{2/3}\) za duljinu bloka.

Primjer

Primjer 「国家集训队」数颜色/维护队列 (Brojanje boja / održavanje reda)

Sažetak zadatka: zadan je niz i M operacija dviju vrsta:

  1. promijeni broj na nekom mjestu u nizu
  2. upitaj koliko različitih brojeva ima u intervalu \([l,r]\) (više jednakih brojeva računa se kao jedan)

Lako je uočiti da bismo bez operacije 1 (izmjene) zadatak lako riješili običnim Mo algoritmom.

No zadatak sadrži i izmjene pojedinih elemenata, pa koristimo Mo algoritam s izmjenama.

Postupak

Prvo razmotrimo pristup običnim Mo algoritmom:

  • Pri svakom proširenju intervala, za svaki dodani broj prebrojimo koliko se puta već pojavio; ako je prije dodavanja broj pojavljivanja te vrijednosti bio \(0\), riječ je o novoj vrijednosti i odgovor se uveća za \(1\). Zatim se broj pojavljivanja te vrijednosti uveća za \(1\).
  • Pri svakom smanjenju intervala, za svaki izbrisani broj prebrojimo koliko se puta pojavljuje nakon brisanja; ako je nakon brisanja broj pojavljivanja te vrijednosti \(0\), ta je vrijednost potpuno izbrisana iz trenutačnog intervala, tj. trenutačni interval ima jednu boju manje, pa se odgovor umanji za \(1\). Zatim se broj pojavljivanja te vrijednosti umanji za \(1\).

Razmotrimo sada izmjene:

  • Izmjena jednog elementa mijenja broj na nekom mjestu. Ako prelazimo s upita koji je prošao \(i\) izmjena na upit koji je prošao \(j\) izmjena i vrijedi \(i<j\), moramo nasilu primijeniti izmjene od \((i+1)\)-ve do \(j\)-te.
  • Ako je \(j<i\), moramo nasilu poništiti izmjene od \(i\)-te do \((j+1)\)-ve.

Kako nasilu primijeniti izmjenu? Pretpostavimo da izmjena mijenja boju na položaju \(pos\), da je izvorna boja na \(pos\) bila \(a\), a nakon izmjene je \(b\), i da je trenutačni interval Mo algoritma proširen na \([l,r]\).

  • Primjena izmjene: najprije provjerimo je li \(pos\) unutar intervala \([l,r]\). Ako jest, to je isto kao da iz intervala izbrišemo boju \(a\) i dodamo boju \(b\), a \(pos\)-ti element trenutačnog niza boja promijenimo u \(b\). Ako nije unutar intervala \([l,r]\), samo izravno promijenimo \(pos\)-ti element trenutačnog niza boja u \(b\).
  • Poništavanje izmjene: isto je kao primjena izmjene koja mijenja \(pos\)-ti element i boju \(b\) mijenja u boju \(a\).

Tako je ovaj zadatak lako riješen Mo algoritmom s izmjenama!

Implementacija

Referentni kôd 
#include <algorithm>
#include <cmath>
#include <iostream>
using namespace std;

long long qsize;

struct query {
  long long id, t, l, r;

  bool operator<(query b) const {
    if (l / qsize != b.l / qsize) {
      return l / qsize > b.l / qsize;
    } else if (r / qsize != b.r / qsize) {
      return r / qsize > b.r / qsize;
    } else {
      return t > b.t;
    }
  }
} q[150009];

struct operation {
  long long p, x;
} r[150009];

char op;
long long n, m, x, y, cur, qcnt, rcnt, mp[1500009], a[150009], ans[150009];

void add(long long x) {
  if (!mp[x]) {
    cur += 1;
  }
  mp[x] += 1;
}

void del(long long x) {
  mp[x] -= 1;
  if (!mp[x]) {
    cur -= 1;
  }
}

void process() {
  sort(q + 1, q + qcnt + 1);
  long long L = 1, R = 0, last = 0;
  for (long long i = 1; i <= qcnt; i++) {
    while (R < q[i].r) {
      add(a[++R]);
    }
    while (R > q[i].r) {
      del(a[R--]);
    }
    while (L > q[i].l) {
      add(a[--L]);
    }
    while (L < q[i].l) {
      del(a[L++]);
    }
    while (last < q[i].t) {
      last += 1;
      if (r[last].p >= L && r[last].p <= R) {
        add(r[last].x);
        del(a[r[last].p]);
      }
      swap(a[r[last].p], r[last].x);
    }
    while (last > q[i].t) {
      if (r[last].p >= L && r[last].p <= R) {
        add(r[last].x);
        del(a[r[last].p]);
      }
      swap(a[r[last].p], r[last].x);
      last -= 1;
    }
    ans[q[i].id] = cur;
  }
}

signed main() {
  cin.tie(nullptr);
  ios::sync_with_stdio(false);
  cin >> n >> m;
  qsize = pow(n, 2.0 / 3.0);
  for (long long i = 1; i <= n; i++) {
    cin >> a[i];
  }
  for (long long i = 1; i <= m; i++) {
    cin >> op >> x >> y;
    if (op == 'Q') {
      ++qcnt, q[qcnt] = {qcnt, rcnt, x, y};
    } else if (op == 'R') {
      r[++rcnt] = {x, y};
    }
  }
  process();
  for (long long i = 1; i <= qcnt; i++) {
    cout << ans[i] << '\n';
  }
}

Please make sure you already know ordinary Mo's algorithm. If you do not yet, first read the previous page Ordinary Mo's algorithm.

Characteristics

Ordinary Mo's algorithm cannot handle modifications.

We can force it to support modifications: just like in DP, we can forcibly add one more dimension, the time dimension, representing the time of this operation.

The time dimension represents the number of modifications applied so far.

That is, the query \([l,r]\) becomes \([l,r,\text{time}]\).

Then our coordinates can also move along the time dimension, i.e. \([l,r,\text{time}]\) has one more direction in which it can move, and it can become:

  • \([l-1,r,\text{time}]\)
  • \([l+1,r,\text{time}]\)
  • \([l,r-1,\text{time}]\)
  • \([l,r+1,\text{time}]\)
  • \([l,r,\text{time}-1]\)
  • \([l,r,\text{time}+1]\)

Such a transition is also \(O(1)\), but our sorting has one more key; a little more tinkering is all that is needed.

The sorting and transitions can be done in a way similar to ordinary Mo's algorithm, achieving \(O(n^{5/3})\).

This time we sort with blocks of size \(n^{2/3}\), giving \(n^{1/3}\) blocks; the first key is the block containing the left endpoint, the second key is the block containing the right endpoint, and the third key is the time.

Optimal block length and time complexity analysis

Let the sequence length be \(n\), with \(m\) queries and \(t\) modifications.

The second sorting key of Mo's algorithm with modifications is the index of the block containing the right endpoint, unlike ordinary Mo's algorithm.

Think about what happens if the right endpoint is not divided into blocks:

  • Unordered right endpoints would move \(n\) times for every query.
  • Ordered right endpoints would bring unordered times, so every query would move \(t\) times in time.

In either case, the time cost is unacceptable.

Now let us analyze the time complexity.

Let the block length be \(s\); then there are \(\dfrac{n}{s}\) blocks. For blocks \(i\) and \(j\), let \(q_{i,j}\) denote the number of queries whose left endpoint lies in block \(i\) and whose right endpoint lies in block \(j\).

For each "group" of queries \((i,j)\) in which neither endpoint changes block, the endpoints move \(O(s)\) times per step, and the time increases monotonically: \(O(t)\).

The time spent when the left and right endpoints change blocks is negligible.

Written out, this is:

\[ \begin{aligned} &\sum_{i=1}^{n/s}\sum_{j=i+1}^{n/s}(q_{i,j}\cdot s+t)\\ =&ms+\left(\dfrac{n}{s}\right)^2t\\ =&ms+\dfrac{n^2t}{s^2} \end{aligned} \]

We find the minimum of this expression by differentiation. Let \(f(s)=ms+\dfrac{n^2t}{s^2}\). Then \(f'(s)=m-\dfrac{2n^2t}{s^3}=0\).

We get \(s=\sqrt[3]{\dfrac{2n^2t}{m}}=\dfrac{2^{1/3}n^{2/3}t^{1/3}}{m^{1/3}}=s_0\).

That is, when the block length is \(\dfrac{n^{2/3}t^{1/3}}{m^{1/3}}\), we obtain the optimal time complexity \(O\left(n^{2/3}m^{2/3}t^{1/3}\right)\).

The commonly quoted \(O\left(n^{5/3}\right)\) is precisely the time complexity when \(n,m,t\) are treated as being of the same order of magnitude.

In practice it is still recommended to set the block length to \(n^{2/3}\).

Example problem

Example 「国家集训队」数颜色/维护队列 (Counting Colors / Maintaining a Queue)

Problem summary: you are given a sequence and M operations of two kinds:

  1. change the number at some position of the sequence
  2. query the number of distinct numbers in the range \([l,r]\) (several equal numbers count as one)

It is easy to see that without operation 1 (modification), we could easily solve this with ordinary Mo's algorithm.

But the problem also has point modifications, so we use Mo's algorithm with modifications.

Procedure

First consider the approach of ordinary Mo's algorithm:

  • Each time the range is extended, for every number added, count how many times it has already occurred; if the number of occurrences of this value before the addition was \(0\), it is a new value and the answer increases by \(1\). Then the number of occurrences of this value increases by \(1\).
  • Each time the range is shrunk, for every number deleted, count how many times it occurs after the deletion; if the number of occurrences of this value after the deletion is \(0\), this value has been completely removed from the current range, i.e. the current range has one color fewer, and the answer decreases by \(1\). Then the number of occurrences of this value decreases by \(1\).

Now consider the modifications:

  • A point modification changes the number at some position. If we move from a query that has gone through \(i\) modifications to a query that has gone through \(j\) modifications, and \(i<j\), we need to forcibly apply the \((i+1)\)-th to the \(j\)-th modifications.
  • If \(j<i\), we need to forcibly undo the \(i\)-th to the \((j+1)\)-th modifications.

How do we forcibly apply a modification? Suppose a modification changes the color at position \(pos\), the original color at \(pos\) was \(a\) and the color after the modification is \(b\), and suppose the current range of Mo's algorithm has been extended to \([l,r]\).

  • Applying the modification: we first check whether \(pos\) is inside the range \([l,r]\). If so, this amounts to deleting color \(a\) from the range and adding color \(b\), and changing the \(pos\)-th entry of the current color sequence to \(b\). If it is not inside the range \([l,r]\), we simply change the \(pos\)-th entry of the current color sequence to \(b\).
  • Undoing the modification: this is the same as applying a modification that changes the \(pos\)-th entry and turns color \(b\) into color \(a\).

Thus this problem is easily solved with Mo's algorithm with modifications!
