Oblik

Pretpostavimo \(n=m\). Tada, ako se za problem s upitima nad intervalima niza odgovor za \([l,r]\) može u \(O(1)\) proširiti na odgovor za \([l-1,r],[l+1,r],[l,r+1],[l,r-1]\) (tj. za intervale susjedne intervalu \([l,r]\)), odgovori na sve upite mogu se izračunati u složenosti \(O(n\sqrt{n})\).

Objašnjenje

Upiti se offline sortiraju, obrađuju redom, a odgovor se grubom silom prenosi s prethodnog intervala na sljedeći (dovoljno je pomicati se korak po korak).

Način sortiranja

Intervali \([l,r]\) sortiraju se uzlazno s indeksom bloka u kojem se nalazi \(l\) kao prvim ključem i \(r\) kao drugim ključem.

Implementacija

void move(int pos, int sign) {
  // ažuriraj nowAns
}

void solve() {
  BLOCK_SIZE = int(ceil(pow(n, 0.5)));
  sort(querys, querys + m);
  for (int i = 0; i < m; ++i) {
    const query &q = querys[i];
    while (l > q.l) move(--l, 1);
    while (r < q.r) move(++r, 1);
    while (l < q.l) move(l++, -1);
    while (r > q.r) move(r--, -1);
    ans[q.id] = nowAns;
  }
}

Analiza složenosti

Sljedeće razmatramo uz pretpostavku da su \(n\) i \(m\) istog reda veličine.

Prvi je korak podjela na blokove; vremenska složenost tog koraka je \(O(\sqrt{n}\cdot\sqrt{n}\log\sqrt{n}+n\log n)=O(n\log n)\).

Zatim dolazi srž Mo algoritma; u nastavku jednostavnom, srednjoškolskom metodom dokazujemo da je njegova vremenska složenost \(O(n\sqrt{n})\).

Dokaz

Dokaz: neka su najveće vrijednosti \(L\) u pojedinim blokovima \(\max_1,\max_2,\max_3, \cdots , \max_{\lceil\sqrt{n}\rceil}\).

Iz prvog sortiranja slijedi \(\max_1 \le \max_2 \le \cdots \le \max_{\lceil\sqrt{n}\rceil}\).

Očito je vremenska složenost izračuna prvog upita svakog bloka grubom silom \(O(n)\).

Razmotrimo najgori slučaj: u svakom je bloku najveća vrijednost \(R\) jednaka \(n\), a svaka operacija izmjene mora \(L\) promijeniti iz \(\max_{i - 1}\) u \(\max_i\) ili iz \(\max_i\) u \(\max_{i - 1}\).

Razmotrimo \(R\): budući da je \(R\) unutar bloka već sortiran, vremenska složenost svih njegovih izmjena unutar jednog bloka je \(O(n)\). Za sve blokove to je \(O(n\sqrt{n})\).

Ključna je analiza \(L\): budući da je vremenska složenost svake promjene \(O(\max_i-\max_{i-1})\), vremenska složenost unutar jednog bloka je \(O(\sqrt{n}\cdot(\max_i-\max_{i-1}))\).

Zbrojimo li vremenske složenosti \(L\) svih blokova, dobivamo:

Ukupna vremenska složenost za \(L\) je

\[ \begin{aligned} & O(\sqrt{n}(\max{}_1-1)+\sqrt{n}(\max{}_2-\max{}_1)+\sqrt{n}(\max{}_3-\max{}_2)+\cdots+\sqrt{n}(\max{}_{\lceil\sqrt{n}\rceil}-\max{}_{\lceil\sqrt{n}\rceil-1))} \\ = \phantom{} & O(\sqrt{n}\cdot(\max{}_1-1+\max{}_2-\max{}_1+\max{}_3-\max{}_2+\cdots+\max{}_{\lceil\sqrt{n}\rceil-1}-\max{}_{\lceil\sqrt{n}\rceil-2}+\max{}_{\lceil\sqrt{n}\rceil}-\max{}_{\lceil\sqrt{n}\rceil-1)}) \\ = \phantom{} & O(\sqrt{n}\cdot(\max{}_{\lceil\sqrt{n}\rceil}-1))\\ \end{aligned} \]

(teleskopski zbroj)

Prema zadatku je \(\max_{\lceil\sqrt{n}\rceil}\) najviše \(n\), pa je ukupna vremenska složenost za \(L\) u najgorem slučaju \(O(n\sqrt{n})\).

Zaključno, vremenska složenost Mo algoritma je \(O(n\sqrt{n})\).

Međutim, za druge vrijednosti \(m\), npr. \(m<n\), način podjele na blokove treba promijeniti da bi bio bolji.

Kako podijeliti na blokove?

Neka je duljina bloka \(S\). Tada je za proizvoljno mnogo upita unutar istog bloka ukupna udaljenost pomicanja \(n\), blokova je ukupno \(\displaystyle \frac{n}{S}\), pa je ukupan broj pomaka \(\displaystyle \frac{n^2}{S}\); pomaci mogu prelaziti preko blokova, pa treba dodati još složenost \(mS\), a ukupna je složenost \(\displaystyle O\left(\frac{n^2}{S}+mS\right)\). Želimo da ta vrijednost bude što manja, pa ta dva člana trebaju biti što bliže jednaka; vidimo da je optimalno uzeti \(S\) jednako \(\displaystyle \frac{n}{\sqrt{m}}\), a složenost je tada \(\displaystyle O\left(\frac{n^2}{\displaystyle \frac{n}{\sqrt{m}}}+m\left(\frac{n}{\sqrt{m}}\right)\right)=O(n\sqrt{m})\).

Zapravo, ako duljina bloka nije točno postavljena, vremenska složenost Mo algoritma znatno trpi. Primjerice, ako je \(m\) istog reda veličine kao \(\sqrt n\), a duljina bloka pogrešno postavljena na \(\sqrt n\), lako se konstruira skup podataka na kojem je vremenska složenost \(O(n \sqrt n)\) umjesto ispravne \(O(n^{5/4})\).

Mo algoritam izgleda vrlo „grubo”, uvelike zato što njegov način sortiranja po blokovima izgleda vrlo grubo. Došli bismo na pomisao da sve intervale sortiramo nekom naizgled profinjenijom metodom. Jedna je mogućnost da sve intervale \([l, r]\) promatramo kao točke \((l, r)\) u ravnini, nad svim točkama izgradimo Manhattan minimalno razapinjuće stablo i odgovore među upitima prenosimo duž bridova tog stabla. Čini se da to može poboljšati vremensku složenost Mo algoritma, ali gornja granica vremenske složenosti metode sortiranja upita po blokovima zapravo je već optimalna.

Pretpostavimo da su \(n, m\) istog reda veličine i da je \(n\) potpun kvadrat. Promotrimo intervale oblika \([a \sqrt n, b \sqrt n](1 \le a, b \le \sqrt n)\); takvih je intervala ukupno \(n\). Ako sve intervale promatramo kao točke u ravnini, Manhattan udaljenost dviju točaka upravo je cijena prijelaza između dvaju intervala, a najmanja Manhattan udaljenost između bilo kojih dvaju intervala je \(\sqrt n\), pa je vremenska složenost obrade svih upita najmanje \(O(n \sqrt n)\). Konstrukcija podataka u ostalim slučajevima je slična.

Mo algoritam ima još jedno svojstvo: kad je \(n\) nepromijenjen, što je \(m\) veći, prosječna cijena prijelaza po upitu je manja. I neki drugi offline algoritmi imaju isto svojstvo (npr. Tarjanov algoritam za LCA), ali kod Mo algoritma prosječna cijena prijelaza najizraženije ovisi o \(m\).

Primjer i kod

Primjer 「国家集训队」小 Z 的袜子 (Čarape malog Z-a)

Sažetak zadatka:

Zadan je niz \(\{c_i\}\) duljine \(n\). Zadano je \(m\) upita; u svakom su zadana dva broja \(l,r\) i među brojevima s indeksima od \(l\) do \(r\) nasumično se biraju dva različita; odredite vjerojatnost da su ta dva broja jednaka.

Postupak

Ideja: školski primjer Mo algoritma.

Intervali \([l,r]\) sortiraju se uzlazno s indeksom bloka u kojem se nalazi \(l\) kao prvim ključem i \(r\) kao drugim ključem.

Zatim se odgovori računaju počevši od prvog upita niza; prvi se upit izračuna izravno grubom silom, u složenosti \(O(n)\), a odgovori na kasnije upite dobivaju se na temelju prethodnog upita.

Konkretan postupak:

Za interval \([i,i]\), budući da ima samo jedan element, odgovor lako znamo. Zatim se korak po korak od trenutačnog intervala (s poznatim odgovorom) približavamo sljedećem intervalu.

Neka \(col[i]\) označava koliko se puta trenutačno pojavljuje boja \(i\), a \(ans\) koliko trenutačno ima mogućih parova (na koliko se načina može izabrati par čarapa iste boje). Zatim pri svakom pomaku ažuriramo odgovor: neka je trenutačna boja \(k\); ako se interval proširuje, \(ans\) se uveća za \(\dbinom{col[k]+1}{2}-\dbinom{col[k]}{2}\); ako se skraćuje, \(ans\) se umanji za \(\dbinom{col[k]}{2}-\dbinom{col[k]-1}{2}\). Odgovor na upit je \(\displaystyle \frac{ans}{\dbinom{r-l+1}{2}}\).

Tu postoji optimizacija: \(\displaystyle \dbinom{a}{2}=\frac{a (a-1)}{2}\).

Stoga je \(\displaystyle \dbinom{a+1}{2}-\dbinom{a}{2}=\frac{(a+1) a}{2}-\frac{a (a-1)}{2}=\frac{a}{2}\cdot (a+1-a+1)=\frac{a}{2}\cdot 2=a\).

Dakle \(\dbinom{col[k]+1}{2}-\dbinom{col[k]}{2}=col[k]\).

Ukupna složenost algoritma: \(O(n\sqrt{n} )\)

U kodu u nastavku deno označava nazivnik odgovora (denominator), nume brojnik (numerator), sqn veličinu bloka \(\sqrt{n}\), arr je ulazni niz, node je struktura koja pohranjuje upit, tab je niz upita (nakon sortiranja), a col je kao gore opisano.

Napomena: zbog ++l i --r položaj četiriju while-petlji za pomicanje intervala u kodu u nastavku vrlo je važan i njihov se međusobni redoslijed ne smije proizvoljno mijenjati.

Rasprava o redoslijedu četiriju petlji

Pomicanje intervala u Mo algoritmu ekvivalentno je dodavanju elemenata iz \([1,r]\) i brisanju elemenata iz \([1,l-1]\). Stoga:

  • U slučaju \(l\le r\) elementi iz \([1,l-1]\) jednom su dodani i jednom izbrisani, elementi iz \([l,r]\) dodani su jednom, a elementi iz \([r+1,+\infty)\) nisu dodani. Taj je interval valjan.
  • U slučaju \(l=r+1\) elementi iz \([1,r]\) jednom su dodani i jednom izbrisani, a elementi iz \([r+1,+\infty)\) nisu dodani. Taj interval tada predstavlja prazan interval.
  • U slučaju \(l>r+1\) elementi iz \([r+1,l-1]\) (taj interval nije prazan) jednom su izbrisani, ali nisu dodani, pa je broj dodavanja tih elemenata negativan.

Dakle, ako u nekom trenutku nastupi \(l>r+1\), postojat će element čiji je broj dodavanja negativan. U nekim zadacima to stvara probleme; primjerice, ako sve brojeve u intervalu održavamo u set-u, pojavit će se problem „brisanja elementa koji ne postoji u set-u”.

Četiri while-petlje u kodu mogu se poredati na ukupno \(4!=24\) načina. Bez smanjenja općenitosti neka prva petlja radi s lijevim krajem; tada postoji sljedećih \(12\) poredaka (ostalih je \(12\) simetrično). Tablica u nastavku navodi ispravnost tih 12 zapisa i daje kontraprimjere za pogrešne zapise.

Od svih 24 poredaka samo je 6 ispravnih, od kojih je za 2 dokaz razmjerno složen; ovdje dajemo dokaz samo za 4 od njih.

Zajedničko je obilježje tih 4 ispravna zapisa da prva dva koraka prvo proširuju interval (l-- ili r++), a druga ga dva koraka zatim sužavaju (l++ ili r--). Tako napisano, prva dva koraka proširuju interval i mogu održati \(l\le r+1\); nakon izvršenja prvih dvaju koraka sigurno vrijedi \(l\le l'\le r'\le r\), a izvršenje drugih dvaju koraka samo sužava interval na \([l',r']\), pa i dalje vrijedi \(l\le r+1\); stoga je takav zapis ispravan.

Implementacija

Referentni kôd 
#include <algorithm>
#include <cmath>
#include <iostream>
using namespace std;
constexpr int N = 50005;
int n, m, maxn;
int c[N];
long long sum;
int cnt[N];
long long ans1[N], ans2[N];

struct query {
  int l, r, id;

  bool operator<(const query &x) const {  // preopterećenje operatora <
    if (l / maxn != x.l / maxn) return l < x.l;
    return (l / maxn) & 1 ? r < x.r : r > x.r;
  }
} a[N];

void add(int i) {
  sum += cnt[i];
  cnt[i]++;
}

void del(int i) {
  cnt[i]--;
  sum -= cnt[i];
}

long long gcd(long long a, long long b) { return b ? gcd(b, a % b) : a; }

int main() {
  cin.tie(nullptr)->sync_with_stdio(false);
  cin >> n >> m;
  maxn = sqrt(n);
  for (int i = 1; i <= n; i++) cin >> c[i];
  for (int i = 0; i < m; i++) cin >> a[i].l >> a[i].r, a[i].id = i;
  sort(a, a + m);
  for (int i = 0, l = 1, r = 0; i < m; i++) {  // konkretna implementacija
    if (a[i].l == a[i].r) {
      ans1[a[i].id] = 0, ans2[a[i].id] = 1;
      continue;
    }
    while (l > a[i].l) add(c[--l]);
    while (r < a[i].r) add(c[++r]);
    while (l < a[i].l) del(c[l++]);
    while (r > a[i].r) del(c[r--]);
    ans1[a[i].id] = sum;
    ans2[a[i].id] = (long long)(r - l + 1) * (r - l) / 2;
  }
  for (int i = 0; i < m; i++) {
    if (ans1[i] != 0) {
      long long g = gcd(ans1[i], ans2[i]);
      ans1[i] /= g, ans2[i] /= g;
    } else
      ans2[i] = 1;
    cout << ans1[i] << '/' << ans2[i] << '\n';
  }
  return 0;
}

Optimizacija običnog Mo algoritma

Postupak

Pogledajmo sljedeći skup podataka

// neka je veličina bloka 2 (pretpostavka)
1 1
2 100
3 1
4 100

Ručnom simulacijom vidi se da se pokazivač r pomakne otprilike 300 puta; nakon što obradimo prvi blok, \(l = 2, r = 100\), i tada bi bila dovoljna dva pomaka pokazivača l da dobijemo odgovor na četvrti upit, ali mi umjesto toga pomičemo pokazivač r na 1 da dobijemo odgovor na treći upit i zatim ga pomičemo na 100 da dobijemo odgovor na četvrti upit, što je devedesetak pomaka pokazivača više. Kako to optimizirati? Tu upotrebljavamo parno-neparno sortiranje.

Što je parno-neparno sortiranje? Parno-neparno sortiranje znači da se za upite koji pripadaju neparnim blokovima r sortira uzlazno, a za upite koji pripadaju parnim blokovima r sortira silazno; tako naš pokazivač r, nakon što obradi upite neparnog bloka, na povratku obrađuje upite parnog bloka, a zatim se opet pomiče prema n obrađujući upite sljedećeg neparnog bloka, čime je optimiziran broj pomaka pokazivača r. U pravilu ta optimizacija ubrzava program za oko 30 %.

Implementacija

Kod za sortiranje:

// clang-format off
// ovdje postoji jedan mali detalj o kojem ćemo govoriti u nastavku
int unit; // veličina bloka
struct node {
  int l, r, id;
  bool operator < (const node &x) const {
    return l / unit == x.l / unit ? (r == x.r ? 0 : ((l / unit) & 1) ^ (r < x.r)) : l < x.l;
  }
};

struct node {
  int l, r, id;

  bool operator<(const node &x) const {
    if (l / unit != x.l / unit) return l < x.l;
    // pazite: u sljedećim dvama redcima ne smije se pisati manje (veće) ili jednako, inače nastaje greška (vidi mali detalj u nastavku)
    if ((l / unit) & 1) return r < x.r;
    return r > x.r;
  }
};
Mali detalj

Ako se sort upotrebljava za usporedbu dviju struktura, ne smije se dogoditi da su \(a < b\) i \(b < a\) istodobno istiniti, inače nastaje greška pri izvođenju; vidi Uobičajene greške.

Kod sažete inačice, ako nema posebne provjere r == x.r, kad l pripada istom neparnom bloku i r su jednaki, nastaje problem opisan u gornjem malom detalju (simulirajte sami ručno); kod raširene inačice isti problem nastaje ako se napiše manje (veće) ili jednako.

Form

Assume \(n=m\). Then, for a range query problem on a sequence, if the answer for \([l,r]\) can be extended in \(O(1)\) to the answer for \([l-1,r],[l+1,r],[l,r+1],[l,r-1]\) (i.e. the ranges adjacent to \([l,r]\)), the answers to all queries can be computed in \(O(n\sqrt{n})\).

Explanation

Sort the queries offline, process them in order, and transfer the answer from the previous range to the next one by brute force (just move step by step).

Sorting method

For a range \([l,r]\), sort in ascending order with the index of the block containing \(l\) as the first key and \(r\) as the second key.

Implementation

    while (l < q.l) move(l++, -1);
    while (r > q.r) move(r--, -1);
    ans[q.id] = nowAns;
  }
}

Complexity analysis

The following discussion assumes that \(n\) and \(m\) are of the same order of magnitude.

The first step is dividing into blocks; the time complexity of this step is \(O(\sqrt{n}\cdot\sqrt{n}\log\sqrt{n}+n\log n)=O(n\log n)\).

Next comes the essence of Mo's algorithm; below we use a simple, middle-school-level method to prove that its time complexity is \(O(n\sqrt{n})\).

Proof

Proof: let the maximum values of \(L\) in each block be \(\max_1,\max_2,\max_3, \cdots , \max_{\lceil\sqrt{n}\rceil}\).

From the first sort we know that \(\max_1 \le \max_2 \le \cdots \le \max_{\lceil\sqrt{n}\rceil}\).

Obviously, the time complexity of computing the first query of each block by brute force is \(O(n)\).

Consider the worst case: in every block the maximum value of \(R\) is \(n\), and every modification operation has to change \(L\) from \(\max_{i - 1}\) to \(\max_i\) or from \(\max_i\) to \(\max_{i - 1}\).

Consider \(R\): since \(R\) is already sorted within a block, the time complexity of all its modifications within one block is \(O(n)\). For all blocks this is \(O(n\sqrt{n})\).

The key is analyzing \(L\): since the time complexity of each change is \(O(\max_i-\max_{i-1})\), the time complexity within one block is \(O(\sqrt{n}\cdot(\max_i-\max_{i-1}))\).

Adding up the time complexities of \(L\) over all blocks, we get:

The total time complexity for \(L\) is

\[ \begin{aligned} & O(\sqrt{n}(\max{}_1-1)+\sqrt{n}(\max{}_2-\max{}_1)+\sqrt{n}(\max{}_3-\max{}_2)+\cdots+\sqrt{n}(\max{}_{\lceil\sqrt{n}\rceil}-\max{}_{\lceil\sqrt{n}\rceil-1))} \\ = \phantom{} & O(\sqrt{n}\cdot(\max{}_1-1+\max{}_2-\max{}_1+\max{}_3-\max{}_2+\cdots+\max{}_{\lceil\sqrt{n}\rceil-1}-\max{}_{\lceil\sqrt{n}\rceil-2}+\max{}_{\lceil\sqrt{n}\rceil}-\max{}_{\lceil\sqrt{n}\rceil-1)}) \\ = \phantom{} & O(\sqrt{n}\cdot(\max{}_{\lceil\sqrt{n}\rceil}-1))\\ \end{aligned} \]

(telescoping sum)

By the problem, \(\max_{\lceil\sqrt{n}\rceil}\) is at most \(n\), so the total time complexity for \(L\) in the worst case is \(O(n\sqrt{n})\).

In summary, the time complexity of Mo's algorithm is \(O(n\sqrt{n})\).

However, for other values of \(m\), such as \(m<n\), the way of dividing into blocks has to change in order to do better.

How should we divide into blocks?

Let the block length be \(S\). Then for any number of queries within the same block, the distance moved is \(n\); there are \(\displaystyle \frac{n}{S}\) blocks in total, so the total number of moves is \(\displaystyle \frac{n^2}{S}\); moves may cross blocks, so we also have to add a complexity of \(mS\), and the total complexity is \(\displaystyle O\left(\frac{n^2}{S}+mS\right)\). We want this value to be as small as possible, so the two terms should be as close to equal as possible; we find that taking \(S\) equal to \(\displaystyle \frac{n}{\sqrt{m}}\) is optimal, and the complexity is then \(\displaystyle O\left(\frac{n^2}{\displaystyle \frac{n}{\sqrt{m}}}+m\left(\frac{n}{\sqrt{m}}\right)\right)=O(n\sqrt{m})\).

In fact, if the block length is set inaccurately, the time complexity of Mo's algorithm suffers greatly. For example, if \(m\) is of the same order as \(\sqrt n\) and the block length is mistakenly set to \(\sqrt n\), it is easy to construct a test case where the time complexity is \(O(n \sqrt n)\) instead of the correct \(O(n^{5/4})\).

Mo's algorithm looks very brute-force, largely because its block-based sorting method looks very crude. One might think of sorting all ranges with a seemingly more refined method. One approach is to view every range \([l, r]\) as a point \((l, r)\) in the plane, build a Manhattan minimum spanning tree over all points, and transfer answers between queries along the edges of the Manhattan minimum spanning tree. This seems to improve the time complexity of Mo's algorithm, but in fact the upper bound on the time complexity of sorting the queries by blocks is already optimal.

Assume \(n, m\) are of the same order and \(n\) is a perfect square. Consider ranges of the form \([a \sqrt n, b \sqrt n](1 \le a, b \le \sqrt n)\); there are \(n\) such ranges in total. If all ranges are viewed as points in the plane, the Manhattan distance between two points is exactly the transfer cost between the two ranges, and the minimum Manhattan distance between any two ranges is \(\sqrt n\), so the time complexity of processing all queries is at least \(O(n \sqrt n)\). The construction of test data in other cases is similar.

Mo's algorithm has another characteristic: when \(n\) stays the same, the larger \(m\) is, the smaller the average transfer cost per query becomes. Some other offline algorithms share this characteristic (such as Tarjan's algorithm for LCA), but for Mo's algorithm the average transfer cost varies most noticeably with \(m\).

Example problem & code

Example 「国家集训队」小 Z 的袜子 (Little Z's Socks)

Problem summary:

There is a sequence \(\{c_i\}\) of length \(n\). Now \(m\) queries are given; each gives two numbers \(l,r\), and two different numbers are chosen at random among those with indices from \(l\) to \(r\); find the probability that the two numbers are equal.

Procedure

Idea: a template problem for Mo's algorithm.

For a range \([l,r]\), sort in ascending order with the index of the block containing \(l\) as the first key and \(r\) as the second key.

Then compute the answers starting from the first query of the sequence; the first query is computed directly by brute force, with complexity \(O(n)\), and the answers to the later queries are obtained based on the previous query.

Concrete procedure:

For a range \([i,i]\), since the range has only one element, we can easily know the answer. Then we move step by step from the current range (whose answer is known) toward the next range.

Let \(col[i]\) denote how many times color \(i\) currently occurs, and let \(ans\) denote how many feasible pairings there currently are (in how many ways a pair of socks of the same color can be chosen). Then update the answer at each move: let the current color be \(k\); if the range is being extended, add \(\dbinom{col[k]+1}{2}-\dbinom{col[k]}{2}\) to \(ans\); if it is being shrunk, subtract \(\dbinom{col[k]}{2}-\dbinom{col[k]-1}{2}\) from \(ans\). The answer to the query is \(\displaystyle \frac{ans}{\dbinom{r-l+1}{2}}\).

There is an optimization here: \(\displaystyle \dbinom{a}{2}=\frac{a (a-1)}{2}\).

Therefore \(\displaystyle \dbinom{a+1}{2}-\dbinom{a}{2}=\frac{(a+1) a}{2}-\frac{a (a-1)}{2}=\frac{a}{2}\cdot (a+1-a+1)=\frac{a}{2}\cdot 2=a\).

So \(\dbinom{col[k]+1}{2}-\dbinom{col[k]}{2}=col[k]\).

Total complexity of the algorithm: \(O(n\sqrt{n} )\)

In the code below, deno denotes the denominator of the answer, nume the numerator, sqn the block size \(\sqrt{n}\), arr is the input array, node is the struct storing a query, tab is the sequence of queries (after sorting), and col is as described above.

Note: because of ++l and --r, the positions of the 4 while loops that move the range in the code below are crucial, and their relative order must not be changed arbitrarily.

Discussion of the order of the four loops

The process of moving the range in Mo's algorithm is equivalent to adding the elements of \([1,r]\) and deleting the elements of \([1,l-1]\). Therefore:

  • In the case \(l\le r\), the elements of \([1,l-1]\) have been added once and deleted once, the elements of \([l,r]\) have been added once, and the elements of \([r+1,+\infty)\) have not been added. This range is a valid range.
  • In the case \(l=r+1\), the elements of \([1,r]\) have been added once and deleted once, and the elements of \([r+1,+\infty)\) have not been added. In this case the range represents an empty range.
  • In the case \(l>r+1\), the elements of \([r+1,l-1]\) (this range is nonempty) have been deleted once but not added, so the number of times these elements have been added is negative.

Therefore, if the situation \(l>r+1\) occurs at some moment, there will be an element whose number of additions is negative. This causes problems in some tasks; for example, if we maintain all numbers in the range with a set, the problem of "needing to delete an element that does not exist in the set" arises.

The four while loops in the code have \(4!=24\) possible orderings in total. Without loss of generality, let the first loop operate on the left endpoint; then there are the following \(12\) orderings (the other \(12\) are symmetric). The table below lists the correctness of these 12 variants and also gives counterexamples for the incorrect ones.

Loop order Correctness Counterexample or note
l--,l++,r--,r++ incorrect \(l<r<l'<r'\)
l--,l++,r++,r-- incorrect \(l<r<l'<r'\)
l--,r--,l++,r++ incorrect \(l<r<l'<r'\)
l--,r--,r++,l++ correct the proof is rather tedious
l--,r++,l++,r-- correct
l--,r++,r--,l++ correct
l++,l--,r--,r++ incorrect \(l<r<l'<r'\)
l++,l--,r++,r-- incorrect \(l<r<l'<r'\)
l++,r++,l--,r-- incorrect \(l<r<l'<r'\)
l++,r++,r--,l-- incorrect \(l<r<l'<r'\)
l++,r--,l--,r++ incorrect \(l<r<l'<r'\)
l++,r--,r++,l-- incorrect \(l<r<l'<r'\)

Of all 24 orderings only 6 are correct, and for 2 of them the proof is rather tedious; here we only give the proof for 4 of them.

The common feature of these 4 correct variants is that the first two steps first extend the range (l-- or r++), and the last two steps then shrink it (l++ or r--). Written this way, the first two steps extend the range and can maintain \(l\le r+1\); after executing the first two steps, \(l\le l'\le r'\le r\) certainly holds, and executing the last two steps only shrinks the range to \([l',r']\), so \(l\le r+1\) still holds; therefore this way of writing it is correct.

Implementation

Reference code 
#include <algorithm>
#include <cmath>
#include <iostream>
using namespace std;
constexpr int N = 50005;
int n, m, maxn;
int c[N];
long long sum;
int cnt[N];
long long ans1[N], ans2[N];

struct query {
  int l, r, id;

  bool operator<(const query &x) const {  // overload the < operator
    if (l / maxn != x.l / maxn) return l < x.l;
    return (l / maxn) & 1 ? r < x.r : r > x.r;
  }
} a[N];

void add(int i) {
  sum += cnt[i];
  cnt[i]++;
}

void del(int i) {
  cnt[i]--;
  sum -= cnt[i];
}

long long gcd(long long a, long long b) { return b ? gcd(b, a % b) : a; }

int main() {
  cin.tie(nullptr)->sync_with_stdio(false);
  cin >> n >> m;
  maxn = sqrt(n);
  for (int i = 1; i <= n; i++) cin >> c[i];
  for (int i = 0; i < m; i++) cin >> a[i].l >> a[i].r, a[i].id = i;
  sort(a, a + m);
  for (int i = 0, l = 1, r = 0; i < m; i++) {  // the actual implementation
    if (a[i].l == a[i].r) {
      ans1[a[i].id] = 0, ans2[a[i].id] = 1;
      continue;
    }
    while (l > a[i].l) add(c[--l]);
    while (r < a[i].r) add(c[++r]);
    while (l < a[i].l) del(c[l++]);
    while (r > a[i].r) del(c[r--]);
    ans1[a[i].id] = sum;
    ans2[a[i].id] = (long long)(r - l + 1) * (r - l) / 2;
  }
  for (int i = 0; i < m; i++) {
    if (ans1[i] != 0) {
      long long g = gcd(ans1[i], ans2[i]);
      ans1[i] /= g, ans2[i] /= g;
    } else
      ans2[i] = 1;
    cout << ans1[i] << '/' << ans2[i] << '\n';
  }
  return 0;
}

Optimization of ordinary Mo's algorithm

Procedure

Let us look at the following test data

// let the block size be 2 (assumption)
1 1
2 100
3 1
4 100

Simulating by hand, we find that the r pointer moves roughly 300 times; after we finish processing the first block, \(l = 2, r = 100\), and at that point only two moves of the l pointer would be needed to get the answer to the fourth query, but instead we move the r pointer to 1 to get the answer to the third query and then move it to 100 to get the answer to the fourth query, which is ninety-odd extra pointer moves. How do we optimize this? Here we use odd-even sorting.

What is odd-even sorting? Odd-even sorting means that for queries belonging to odd-numbered blocks, r is sorted in ascending order, and for queries belonging to even-numbered blocks, r is sorted in descending order; this way, after our r pointer finishes the queries of an odd block, it processes the queries of the even block on its way back, and then moves toward n again to process the queries of the next odd block, which optimizes the number of moves of the r pointer. In general, this optimization makes the program about 30% faster.

Implementation

Sorting code:

// clang-format off
// there is a small detail here that will be discussed below
int unit; // block size
struct node {
  int l, r, id;
  bool operator < (const node &x) const {
    return l / unit == x.l / unit ? (r == x.r ? 0 : ((l / unit) & 1) ^ (r < x.r)) : l < x.l;
  }
};

struct node {
  int l, r, id;

  bool operator<(const node &x) const {
    if (l / unit != x.l / unit) return l < x.l;
    // note: the following two lines must not use less-than (greater-than) or equal, otherwise an error occurs (see the small detail below)
    if ((l / unit) & 1) return r < x.r;
    return r > x.r;
  }
};
Small detail

If sort is used to compare two structs, it must not happen that \(a < b\) and \(b < a\) are both true at the same time, otherwise a runtime error occurs; see Common mistakes.

For the compressed version, without the special check r == x.r, when the l values belong to the same odd block and the r values are equal, the problem from the small detail above occurs (simulate it by hand yourself); for the expanded version, the same problem occurs if less-than (greater-than) or equal is written.
