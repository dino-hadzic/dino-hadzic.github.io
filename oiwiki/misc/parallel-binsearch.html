Uvod

Na natjecanjima iz informatike dio zadataka može se riješiti binarnim pretraživanjem. No kad takav zadatak ima više upita, a izravno binarno pretraživanje za svaki upit moglo bi dovesti do TLE-a, koristi se paralelno binarno pretraživanje (parallel binary search). Glavna je ideja paralelnog binarnog pretraživanja riješiti više upita zajedno. (Zato je ovo offline algoritam.)

Zadaci rješivi paralelnim binarnim pretraživanjem moraju zadovoljavati sljedeća svojstva1:

  1. odgovor na upit može se binarno pretraživati;
  2. doprinosi izmjena provjeri odgovora međusobno su neovisni, izmjene ne utječu jedna na drugu;
  3. ako izmjena doprinosi provjeri odgovora, doprinos je određena vrijednost neovisna o kriteriju provjere;
  4. doprinosi zadovoljavaju komutativnost i asocijativnost te su aditivni;
  5. zadatak dopušta offline algoritam.

Objašnjenje

Označimo s \([l,r]\) raspon vrijednosti odgovora, a s \([L,R]\) domenu odgovora. (Drugim riječima, pri računanju odgovora razmatraju se samo operacije i upiti s indeksima u intervalu \([L,R]\), a odgovori tih upita leže u \([l,r]\).)

  • Najprije sve operacije kronološkim redoslijedom spremimo u polje, a zatim započnemo podjelu.
  • Na svakoj razini podjele pomoću strukture podataka (najčešće Fenwick treeja) utvrdimo odnos između odgovora trenutnih upita i \(mid\).
  • Prema odnosu utvrđenog odgovora i \(mid\) (manji ili jednak \(mid\), odnosno veći od \(mid\)) niz operacija koji trenutno obrađujemo podijelimo na dva dijela, \(q1\) i \(q2\), i svaki rekurzivno obradimo.
  • Kad je \(l=r\), odgovor je pronađen; zabilježimo ga i vratimo se.

Valja uočiti da se tijekom paralelnog binarnog pretraživanja, ako je raspon vrijednosti koji trenutno obrađujemo \([l,r]\), upiti čiji konačni odgovor nije u \([l,r]\) obrađuju u nekom drugom trenutku.

Upit za globalno k-ti najmanji

Zadatak 1

U nizu brojeva pronađite \(k\)-ti najmanji broj.

Rješenje

Naravno, može se izravno sortirati. A binarnim pretraživanjem? Strukturom podataka možemo zabilježiti koliko brojeva ima u svakom rasponu vrijednosti, zatim binarnim pretraživanjem pogađati, a strukturom podataka provjeravati.

Zadatak 2

U nizu brojeva više puta pronađite \(k\)-ti najmanji broj.

Rješenje

Možemo za svaki upit provesti jedno binarno pretraživanje; ali možemo i sve upite zajedno binarno pretraživati.

Razmotrimo najprije bit binarnog pretraživanja: pretpostavimo da treba pogoditi broj iz \([l,r]\) i da nakon pogađanja saznamo je li pogodak prevelik, premalen ili točan. Naravno, možemo iterirati od \(l\) do \(r\), ali bolja je metoda binarno pretraživanje: pogodimo da je odgovor \(m = \lfloor\frac{l + r}{2}\rfloor\), zatim provjerimo ispravnost \(m\) i prilagodimo granice. Tako je složenost svakog upita \(O(\log n)\); ako je broj upita \(q\), vremenska složenost je \(O(q\log n)\).

Vratimo se sada: za sve trenutne upite možemo pretpostaviti da je odgovor na svaki od njih \(mid\), zatim redom za svaki upit provjeriti treba li odgovor biti manji ili jednak \(mid\) ili veći od \(mid\), podijeliti upite na dva dijela (ne veći/veći) i za svaki dio nastaviti binarno pretraživanje. Napomena: ako je odgovor na upit veći od \(mid\), prije nego što ga prebacimo na desnu stranu treba ažurirati njegov \(k\), tj. ako u trenutnom nizu ima \(t\) brojeva manjih ili jednakih \(mid\), tada nakon podjele upit u desnom intervalu zapravo traži \(k - t\)-ti najmanji broj. Ako za neki dio vrijedi \(l = r\), binarno pretraživanje tog dijela završava. Služeći se znanjem o segment treeju: cijeli interval \([1,n]\) u kojem odgovor može biti (uz pretpostavku da je već diskretiziran) svaki put dijelimo na nekoliko dijelova, takvih podjela ima ukupno \(O(\log n)\), a jedna podjela prolazi kroz cijeli niz operacija jednom. Ako obrada cijelog niza uz podršku odgovarajućih upita ima vremensku složenost \(O(T)\), vremenska složenost paralelnog binarnog pretraživanja je \(O(T\log n)\).

Primjer koda 
struct Query {
  int id, k;  // oznaka ovog upita, k ovog upita
};

int ans[N], a[N];  // ans[i] je odgovor na upit s oznakom i, a je izvorni niz
int val[N], cnt[N];  // nakon diskretizacije, odgovarajuće vrijednosti i njihov broj (pretpostavlja se da su već izračunati)

// vraća broj elemenata izvornog niza čija je vrijednost u [l,r]
int check(int l, int r) {
  int res = 0;
  for (int i = l; i <= r; i++) {
    res += cnt[i];
  }
  return res;
}

// paralelno binarno pretraživanje
void solve(int l, int r, vector<Query> q) {
  int m = (l + r) / 2;
  if (l == r) {
    for (unsigned i = 0; i < q.size(); i++) ans[q[i].id] = val[l];
    return;
  }
  vector<Query> q1, q2;
  int t = check(l, m);
  for (unsigned i = 0; i < q.size(); i++) {
    if (q[i].k <= t)
      q1.push_back(q[i]);
    else
      q[i].k -= t, q2.push_back(q[i]);
  }
  solve(l, m, q1), solve(m + 1, r, q2);
  return;
}

Upit za k-ti najmanji na intervalu

Zadatak 3

U nizu brojeva više puta pronađite \(k\)-ti najmanji broj na intervalu.

Rješenje

Kad se upiti odnose na zadani interval, binarno pretraživanje po prethodnoj metodi dovelo bi do eksplozije vremenske složenosti funkcije check. I dalje razmatramo odnos upita i sredine raspona vrijednosti \(m\): ako u intervalu upita ima \(t\) brojeva manjih ili jednakih \(m\), a traži se \(k\)-ti najmanji broj u intervalu, tada za \(k \leq t\) odgovor mora biti manji ili jednak \(m\); inače odgovor mora biti veći od \(m\). (Pazite na rubne slučajeve.) Ovdje treba bilježiti broj elemenata u intervalu manjih ili jednakih zadanom broju, tj. dodavanje u točki i zbroj na intervalu, što se brzo obrađuje Fenwick treejem. Radi učinkovitosti brojimo samo elemente niza čija je vrijednost u rasponu \([l,r]\), tj. prije daljnje rekurzije ne dijelimo samo upite, nego i trenutno obrađivane brojeve dijelimo na dvije polovice prema rasponu vrijednosti.

Primjer koda (ključni dio) 
struct Num {
  int p, x;
};  // broj na p-tom mjestu u nizu ima vrijednost x

struct Query {
  int l, r, k, id;
};  // upit s oznakom id koji traži k-ti najmanji broj u [l,r]

int ans[N];
void add(int p, int x);  // Fenwick tree, na poziciju p dodaj x
int query(int p);        // Fenwick tree, zbroj na [1,p]
void clear();            // Fenwick tree, isprazni

void solve(int l, int r, vector<Num> a, vector<Query> q)
// u a su brojevi zadanog niza čija je vrijednost u rasponu [l,r]
{
  int m = (l + r) / 2;
  if (l == r) {
    for (unsigned i = 0; i < q.size(); i++) ans[q[i].id] = l;
    return;
  }
  vector<Num> a1, a2;
  vector<Query> q1, q2;
  for (unsigned i = 0; i < a.size(); i++)
    if (a[i].x <= m)
      a1.push_back(a[i]), add(a[i].p, 1);
    else
      a2.push_back(a[i]);
  for (unsigned i = 0; i < q.size(); i++) {
    int t = query(q[i].r) - query(q[i].l - 1);
    if (q[i].k <= t)
      q1.push_back(q[i]);
    else
      q[i].k -= t, q2.push_back(q[i]);
  }
  clear();
  solve(l, m, a1, q1), solve(m + 1, r, a2, q2);
  return;
}

U nastavku dajemo natjecateljski stil implementacije paralelnog binarnog pretraživanja za zadatak 【模板】可持久化线段树 2 (Predložak: perzistentni segment tree 2).

Primjer koda 
#include <algorithm>
#include <iostream>
using namespace std;
constexpr int N = 200020;
int n, m;
int ans[N];
// BIT begin
int t[N];
int a[N];

int sum(int p) {
  int ans = 0;
  while (p) {
    ans += t[p];
    p -= p & (-p);
  }
  return ans;
}

void add(int p, int x) {
  while (p <= n) {
    t[p] += x;
    p += p & (-p);
  }
}

// BIT end
int tot = 0;

struct Query {
  int l, r, k, id, type;  // set values to -1 when they are not used!
} q[N * 2], q1[N * 2], q2[N * 2];

void solve(int l, int r, int ql, int qr) {
  if (ql > qr) return;
  if (l == r) {
    for (int i = ql; i <= qr; i++)
      if (q[i].type == 2) ans[q[i].id] = l;
    return;
  }
  int mid = (l + r) / 2, cnt1 = 0, cnt2 = 0;
  for (int i = ql; i <= qr; i++) {
    if (q[i].type == 1) {
      if (q[i].l <= mid) {
        add(q[i].id, 1);
        q1[++cnt1] = q[i];
      } else
        q2[++cnt2] = q[i];
    } else {
      int x = sum(q[i].r) - sum(q[i].l - 1);
      if (q[i].k <= x)
        q1[++cnt1] = q[i];
      else {
        q[i].k -= x;
        q2[++cnt2] = q[i];
      }
    }
  }
  // rollback changes
  for (int i = 1; i <= cnt1; i++)
    if (q1[i].type == 1) add(q1[i].id, -1);
  // move them to the main array
  for (int i = 1; i <= cnt1; i++) q[i + ql - 1] = q1[i];
  for (int i = 1; i <= cnt2; i++) q[i + cnt1 + ql - 1] = q2[i];
  solve(l, mid, ql, cnt1 + ql - 1);
  solve(mid + 1, r, cnt1 + ql, qr);
}

pair<int, int> b[N];
int toRaw[N];

int main() {
  cin.tie(nullptr)->sync_with_stdio(false);
  cin >> n >> m;
  // read and discrete input data
  for (int i = 1; i <= n; i++) {
    int x;
    cin >> x;
    b[i].first = x;
    b[i].second = i;
  }
  sort(b + 1, b + n + 1);
  int cnt = 0;
  for (int i = 1; i <= n; i++) {
    if (b[i].first != b[i - 1].first) cnt++;
    a[b[i].second] = cnt;
    toRaw[cnt] = b[i].first;
  }
  for (int i = 1; i <= n; i++) {
    q[++tot] = {a[i], -1, -1, i, 1};
  }
  for (int i = 1; i <= m; i++) {
    int l, r, k;
    cin >> l >> r >> k;
    q[++tot] = {l, r, k, i, 2};
  }
  solve(0, cnt + 1, 1, tot);
  for (int i = 1; i <= m; i++) cout << toRaw[ans[i]] << '\n';
}

K-ti najmanji na intervalu s izmjenama

Zadatak 4 (Dynamic Rankings)

Zadan je niz brojeva; treba podržati izmjenu u točki i upit za \(k\)-ti najmanji na intervalu.

Rješenje

Operaciju izmjene možemo shvatiti kao brisanje jednog broja iz izvornog niza i dodavanje drugog; radi jednostavnosti upite i izmjene zajednički nazivamo „operacijama”. Budući da kasnije operacije ovise o prethodnima, ne možemo kao u zadatku 3 odvojiti brojanje od obrade upita, pa sve operacije spremamo u jedno polje, oznakom razlikujemo tip i obrađujemo operacije redom. Radi lakše obrade Fenwick treejem, operaciju izmjene možemo rastaviti na operaciju brisanja i operaciju umetanja.

Optimizacije

  1. Uočimo da se pri svakom razvrstavanju operacija mijenja samo njihov redoslijed, pa možemo raditi izravno na izvornom polju. Konkretno, pri binarnom pretraživanju polja \(q, a\) u koja smo bilježili operacije zamijenimo jednim velikim globalnim poljem, a informacija koju bilježimo tijekom binarnog pretraživanja postaje \(L, R\), tj. koji se interval globalnog polja trenutno obrađuje. Trenutno razvrstavanje bilježimo u privremeno polje, a prije daljnje rekurzije podatke iz privremenog polja prepišemo natrag u izvorno polje.
  2. Pražnjenje Fenwick treeja pri svakom pozivu dovelo bi do eksplozije vremenske složenosti; umjesto toga pri svakoj upotrebi Fenwick treeja bilježimo trenutne pozicije izmjena (to je već ostvareno privremenim poljem iz točke 1) i nakon završetka operacije na istim pozicijama dodamo \(-1\), čime se brzo vraća na nulu.
  3. Početna inicijalizacija niza može se pojednostavniti na operacije umetanja.
Primjer koda (ključni dio) 
struct Opt {
  int x, y, k, type, id;
  // za upit: type = 1, x, y su lijeva i desna granica intervala, k znači da se traži k-ti najmanji
  // za izmjenu: type = 0, x je pozicija izmjene, y je vrijednost nakon izmjene,
  // k označava je li trenutna operacija umetanje (1) ili brisanje (-1), koristi se pri ažuriranju Fenwick treeja.
  // id pamti izvornu oznaku svake operacije, jer se tijekom binarnog pretraživanja redoslijed operacija ispremiješa
};

Opt q[N], q1[N], q2[N];
// q su sve operacije,
// tijekom binarnog pretraživanja operacije razvrstane ulijevo spremaju se u q1, a razvrstane udesno u q2.
int ans[N];
void add(int p, int x);
int query(int p);  // funkcije Fenwick treeja, značenje vidi u zadatku 3

void solve(int l, int r, int L, int R)
// trenutni raspon vrijednosti je [l,r], interval obrađivanih operacija je [L,R]
{
  if (l > r || L > R) return;
  int cnt1 = 0, cnt2 = 0, m = (l + r) / 2;
  // cnt1, cnt2 su redom broj operacija razvrstanih ulijevo i udesno
  if (l == r) {
    for (int i = L; i <= R; i++)
      if (q[i].type == 1) ans[q[i].id] = l;
    return;
  }
  for (int i = L; i <= R; i++)
    if (q[i].type == 1) {  // upit: razvrstaj
      int t = query(q[i].y) - query(q[i].x - 1);
      if (q[i].k <= t)
        q1[++cnt1] = q[i];
      else
        q[i].k -= t, q2[++cnt2] = q[i];
    } else
      // izmjena: ažuriraj Fenwick tree i razvrstaj
      if (q[i].y <= m)
        add(q[i].x, q[i].k), q1[++cnt1] = q[i];
      else
        q2[++cnt2] = q[i];
  for (int i = 1; i <= cnt1; i++)
    if (q1[i].type == 0) add(q1[i].x, -q1[i].k);  // isprazni Fenwick tree
  for (int i = 1; i <= cnt1; i++) q[L + i - 1] = q1[i];
  for (int i = 1; i <= cnt2; i++)
    q[L + cnt1 + i - 1] = q2[i];  // elemente privremenih polja spoji natrag u izvorno polje
  solve(l, m, L, L + cnt1 - 1), solve(m + 1, r, L + cnt1, R);
  return;
}

Optimizacija za statične nizove

Zadatak 5 (【模板】可持久化线段树 2 (Predložak: perzistentni segment tree 2))

Zadan je niz; upit za \(k\)-ti najmanji na intervalu.

Rješenje

I ugniježđena stabla (tree-in-tree) i paralelno binarno pretraživanje rješavaju problem \(k\)-tog najmanjeg na intervalu s izmjenama u složenosti \(O(n \log^2 n)\), ali statični problem \(k\)-tog najmanjeg na intervalu može se perzistentnim segment treejem riješiti u vremenskoj složenosti \(O(n \log n)\), dok gotovo sve implementacije statičnog \(k\)-tog najmanjeg na intervalu paralelnim binarnim pretraživanjem imaju vremensku složenost \(O(n \log^2 n)\) i pri velikim ograničenjima postoji rizik od TLE-a. (Ovdje se podrazumijeva da je raspon vrijednosti istog reda kao duljina niza; slučaj kad raspon vrijednosti i duljina niza nisu istog reda može se diskretizacijom svesti na slučaj istog reda.)

Optimizacije

  1. U svakoj rundi podjele, ako u trenutnom nizu ima \(t\) brojeva manjih ili jednakih \(mid\), upit nakon podjele u desnom intervalu zapravo traži \(k - t\)-ti najmanji broj, pa se upiti razvrstani u desni interval mijenjaju. Ako je izvorni raspon vrijednosti odgovora \([L,R]\), a raspon vrijednosti odgovora u nekoj podjeli \([l,r]\), tada je za upite koji sudjeluju u toj podjeli utjecaj svih vrijednosti iz \([L,l)\) na njih već ranije uklonjen.
  2. Budući da svaka runda podjele mora ovisiti samo o trenutnom rasponu vrijednosti odgovora \([l,r]\), Fenwick tree treba više puta puniti i prazniti.

Što ako podjela ne ovisi samo o trenutnom rasponu vrijednosti odgovora?

Odatle se dobiva optimizacija povezana s globalnim nizom: održavamo pokazivač \(pos\) koji prati \(mid\) (središte podjele) svake runde podjele, indekse svih elemenata \(\leq pos\) u Fenwick treeju postavimo na \(1\), a ostale pozicije Fenwick treeja na \(0\). Prije svake podjele pomaknemo \(pos\) i ažuriramo Fenwick tree. Broj pomaka pokazivača \(pos\) istog je reda kao \(n \log n\). Pri podjeli za svaki upit upitamo vrijednost odgovarajućeg intervala u Fenwick treeju; ako uvjet vrijedi, upit razvrstavamo u lijevi interval, inače u desni, i upite nije potrebno mijenjati.

Budući da pratimo središte podjele, \(pos\) mora točno ažurirati Fenwick tree. Prije paralelnog binarnog pretraživanja niz sortiramo po veličini elemenata i zabilježimo indekse elemenata, a pri pomicanju pokazivača u Fenwick treeju odgovarajuće mijenjamo te indekse. Na veliku većinu zadataka rješivih paralelnim binarnim pretraživanjem koji nemaju izmjene može se primijeniti ova optimizacija kako bi se znatno smanjio broj upotreba strukture podataka.

Budući da se uklanja mnogo operacija punjenja i pražnjenja Fenwick treeja, ova optimizacija u pravilu primjetno povećava učinkovitost paralelnog binarnog pretraživanja (iako je samo optimizacija konstante), a za statični problem \(k\)-tog najmanjeg na intervalu učinkovitost nije ništa lošija od perzistentnog segment treeja bolje vremenske složenosti. Vrijedi spomenuti da za statični problem \(k\)-tog najmanjeg na intervalu postoji i implementacija paralelnog binarnog pretraživanja vremenske složenosti \(O(n \log n)\).

Primjer koda (ključni dio) 
struct Query {
  int i, l, r, k;
};  // i-ti upit traži k-ti najmanji na intervalu [l,r]

Query s[200005], t1[200005], t2[200005];
int n, m, cnt, pos, p[200005], ans[200005];
pair<int, int> a[200005];

void add(int x, int y);  // Fenwick tree: na poziciju x dodaj y
int sum(int x);          // Fenwick tree: prefiksni zbroj [1,x]

// trenutno obrađivani upiti su [l,r], raspon vrijednosti odgovora je [ql,qr]
void overall_binary(int l, int r, int ql, int qr) {
  if (l > r) return;
  if (ql == qr) {
    for (int i = l; i <= r; i++) ans[s[i].i] = ql;
    return;
  }
  int cnt1 = 0, cnt2 = 0, mid = (ql + qr) >> 1;
  // prati središte podjele; smatramo da su vrijednosti [1,pos] već učitane u Fenwick tree
  while (pos <= n - 1 && a[pos + 1].first <= mid)
    add(a[pos + 1].second, 1), ++pos;
  while (pos >= 1 && a[pos].first > mid) add(a[pos].second, -1), --pos;

  for (int i = l; i <= r; i++) {
    int now = sum(s[i].r) - sum(s[i].l - 1);
    if (s[i].k <= now)
      t1[++cnt1] = s[i];
    else
      t2[++cnt2] = s[i];  // pazite: podatke upita ne treba mijenjati
  }
  for (int i = 1; i <= cnt1; i++) s[l + i - 1] = t1[i];
  for (int i = 1; i <= cnt2; i++) s[l + cnt1 + i - 1] = t2[i];

  overall_binary(l, l + cnt1 - 1, ql, mid);
  overall_binary(l + cnt1, r, mid + 1, qr);
}

int main() {
  scanf("%d%d", &n, &m);
  for (int i = 1; i <= n; i++) {
    scanf("%d", &a[i].first);
    a[i].second = i;
    p[++cnt] = a[i].first;
  }
  sort(a + 1, a + n + 1);  // sortiraj niz, diskretizacija
  sort(p + 1, p + n + 1);
  cnt = unique(p + 1, p + n + 1) - p - 1;
  for (int i = 1; i <= n; i++)
    a[i].first = lower_bound(p + 1, p + cnt + 1, a[i].first) - p;
  // učitavanje upita je izostavljeno
  overall_binary(1, m, 1, cnt);
  for (int i = 1; i <= n; i++) printf("%d\n", p[ans[i]]);
  return 0;
}

Prethodnik i sljedbenik na intervalu

Zadatak 6

U nizu brojeva više puta pronađite prethodnika broja \(k\) u intervalu (najveći broj strogo manji od \(k\)) ili sljedbenika (najmanji broj strogo veći od \(k\)); zajamčeno je da takav broj postoji.

Rješenje

Uzmimo prethodnika kao primjer: ovakvi se problemi strukturama podataka obično rješavaju tako da se najprije upita koliko u intervalu ima brojeva strogo manjih od \(k\) (neka ih je \(x\)), a zatim se upita \(x\)-ti najmanji broj u intervalu. Za sljedbenika se upita koliko u intervalu ima brojeva ne većih od \(k\) (neka ih je \(x\)), a zatim \(x+1\)-vi najmanji broj u intervalu.

Razmotrimo rješenje paralelnim binarnim pretraživanjem: paralelno binarno pretraživanje učinkovit je offline algoritam za \(k\)-ti najmanji na intervalu, a CDQ podjela može offline učinkovito izračunati rang unutar intervala. Najprije jednom pokrenemo CDQ podjelu da izračunamo rangove, a zatim paralelnim binarnim pretraživanjem dobijemo prethodnika i sljedbenika unutar intervala.

Ovaj se problem može riješiti i jednim offline prolazom CDQ podjele u kombinaciji sa segment treejem, ali je učinkovitost znatno manja od dvaju prolaza: CDQ podjela + paralelno binarno pretraživanje.

Konstrukcija monotonog niza

Zadatak 7 (Sequence)

Zadan je niz; svakom operacijom neki broj možemo povećati za \(+1\) ili smanjiti za \(−1\). Niz treba učiniti neopadajućim, a u izmijenjenom nizu smiju se pojaviti samo brojevi koji su postojali prije izmjena; ispišite najmanji broj operacija.

Rješenje

Ovakvi se zadaci mogu riješiti i dinamičkim programiranjem ili greedyjem s poništavanjem (regret greedy).

Uz uvjet minimalnog broja operacija sigurno postoji rješenje u kojem je svaki broj konačnog niza postojao u nizu prije izmjena; ta se tvrdnja može dokazati matematičkom indukcijom. Budući da zadatak ne traži podatke o konačnom nizu, problem se svodi na određivanje najmanjeg broja operacija.

Budući da konačni niz mora biti neopadajući, možemo upotrijebiti paralelno binarno pretraživanje. U svakoj rundi paralelnog binarnog pretraživanja određujemo raspon vrijednosti intervala \([l,r]\) konačnog niza, pri čemu je raspon vrijednosti odgovora \([ql,qr]\). Neka je \(mid=\lfloor\frac{ql + qr}{2}\rfloor\); na početku svake runde sve brojeve podrazumijevano razvrstamo u \([mid+1,qr]\) (broj onih koji idu u \([ql,mid]\) postavimo na \(0\)), a početnu cijenu postavimo na broj operacija potreban da se cijeli interval \([l,r]\) niza postavi na \(mid+1\). Redom prolazimo kroz brojeve \(i\) intervala \([l,r]\) i računamo ukupan broj operacija kojima se \([l,i]\) postavlja na \(mid\), a \([i+1,r]\) na \(mid+1\); ako je bolji od prethodnog broja operacija, ažuriramo najmanji broj operacija i broj elemenata koji idu u \([ql,mid]\).

Pri podjeli već je osigurano da se monotonost konačnog niza ne narušava, a budući da svaki put uzimamo najmanji broj operacija, za brojeve koji su na kraju razvrstani u lijevi interval vrijednost \(mid\) sigurno je bolja od \(mid+1\), pa je niz dobiven paralelnim binarnim pretraživanjem sigurno neopadajući i s najmanjim brojem operacija. Preostaje izračunati broj operacija i ispisati ga.

Primjer koda (ključni dio) 
int a[500005], ans[500005];  // a: izvorni niz, ans: konstruirani niz

void overall_binary(int l, int r, int ql, int qr) {
  if (l > r) return;
  if (ql == qr) {
    for (int i = l; i <= r; i++) ans[i] = ql;
    return;
  }
  int cnt = 0,
      mid = ql + ((qr - ql) >> 1);  // podrazumijevano na početku sve postavljamo na mid+1 i razvrstavamo u desni interval
  long long res = 0ll, sum = 0ll;
  for (int i = l; i <= r; i++) sum += abs(a[i] - (mid + 1));
  res = sum;
  for (int i = l; i <= r;
       i++) {  // pokušaj [l,i] s mid+1 promijeniti na mid i razvrstati u lijevi interval
    sum -= abs(a[i] - (mid + 1));
    sum += abs(a[i] - mid);
    if (sum < res) cnt = i - l + 1, res = sum;  // [l,i] s vrijednošću mid je bolje, ažuriraj
  }
  overall_binary(l, l + cnt - 1, ql, mid);
  overall_binary(l + cnt, r, mid + 1, qr);
}

Introduction

In informatics competitions some problems can be solved by binary search. But when such a problem has many queries and running a separate binary search for every query could lead to TLE, parallel binary search is used. The main idea of parallel binary search is to solve many queries together. (So this is an offline algorithm.)

Problems that can be solved by parallel binary search must satisfy the following properties1:

  1. the answer to a query can be binary searched;
  2. the contributions of the updates to checking an answer are independent of each other, updates do not affect each other's effect;
  3. if an update contributes to checking an answer, the contribution is a fixed value independent of the checking criterion;
  4. the contributions satisfy commutativity and associativity and are additive;
  5. the problem allows an offline algorithm.

Explanation

Denote by \([l,r]\) the value range of the answers and by \([L,R]\) the domain of the answers. (That is, when computing the answers only the operations and queries with indices in the interval \([L,R]\) are considered, and the answers to these queries lie in \([l,r]\).)

  • We first store all operations in an array in chronological order, and then start the divide and conquer.
  • At every level of the recursion we use a data structure (commonly a Fenwick tree) to determine the relation between the answers to the current queries and \(mid\).
  • According to the relation between the determined answer and \(mid\) (less than or equal to \(mid\), or greater than \(mid\)) we split the currently processed sequence of operations into two parts \(q1\) and \(q2\) and process each of them recursively.
  • When \(l=r\), the answer has been found; record it and return.

Note that during parallel binary search, if the value range currently processed is \([l,r]\), the queries whose final answer is not in \([l,r]\) are processed at some other time.

Let us start from ordinary binary search:

Querying the global k-th smallest

Problem 1

Find the \(k\)-th smallest number in a sequence.

Solution

Of course we can simply sort. What about binary search? We can use a data structure to record how many numbers there are in every value range, then guess by binary search and verify with the data structure.

Problem 2

Find the \(k\)-th smallest number in a sequence, many times.

Solution

We can run a binary search for every query; but we can also binary search all queries together.

First consider the essence of binary search: suppose we want to guess a number in \([l,r]\), and after guessing we learn whether the guess was too large, too small, or exactly right. Of course we could enumerate from \(l\) to \(r\), but a better method is binary search: guess that the answer is \(m = \lfloor\frac{l + r}{2}\rfloor\), then verify the correctness of \(m\) and adjust the bounds. This way the complexity of every query is \(O(\log n)\); if the number of queries is \(q\), the time complexity is \(O(q\log n)\).

Coming back, for all current queries we can guess that the answer to every query is \(mid\), then verify in turn whether the answer to each query should be less than or equal to \(mid\) or greater than \(mid\), split the queries into two parts (not greater/greater), and continue the binary search for each part. Note: if the answer to a query is greater than \(mid\), its \(k\) must be updated before moving it to the right side, i.e. if there are \(t\) numbers less than or equal to \(mid\) in the current sequence, then after the split the query actually asks for the \(k - t\)-th smallest number in the right interval. If a part has \(l = r\), the binary search of this part ends. Using knowledge about segment trees: each time we split the whole interval \([1,n]\) in which the answer may lie (assuming it has been discretized) into several parts; such splits are performed \(O(\log n)\) times in total, and one split runs over the whole sequence of operations once. If operating on the whole sequence while supporting the corresponding queries has time complexity \(O(T)\), the time complexity of parallel binary search is \(O(T\log n)\).

struct Query {
  int id, k;  // the id of this query, the k of this query
};

int ans[N], a[N];  // ans[i] is the answer to the query with id i, a is the original sequence
int val[N], cnt[N];  // after discretization, the corresponding values and their counts (assumed to be computed already)

// returns the number of elements of the original sequence whose value is in [l,r]
int check(int l, int r) {
  int res = 0;
  for (int i = l; i <= r; i++) {
    res += cnt[i];
  }
  return res;
}

// parallel binary search
void solve(int l, int r, vector<Query> q) {
  int m = (l + r) / 2;
  if (l == r) {
    for (unsigned i = 0; i < q.size(); i++) ans[q[i].id] = val[l];
    return;
  }
  vector<Query> q1, q2;
  int t = check(l, m);
  for (unsigned i = 0; i < q.size(); i++) {
    if (q[i].k <= t)
      q1.push_back(q[i]);
    else
      q[i].k -= t, q2.push_back(q[i]);
  }
  solve(l, m, q1), solve(m + 1, r, q2);
  return;
}

Querying the k-th smallest in a range

Problem 3

Find the \(k\)-th smallest number in a range of a sequence, many times.

Solution

When the queries involve a given range, binary searching by the previous method would make the time complexity of the check function explode. We still consider the relation between a query and the midpoint \(m\) of the value range: if there are \(t\) numbers less than or equal to \(m\) in the query range and the query asks for the \(k\)-th smallest number in the range, then when \(k \leq t\) the answer should be less than or equal to \(m\); otherwise the answer should be greater than \(m\). (Mind the boundary cases.) Here we have to record the number of elements in a range that are less than or equal to a given number, i.e. point add and range sum, which can be handled quickly with a Fenwick tree. To improve efficiency, we only count the numbers of the sequence whose value is in the value range \([l,r]\), i.e. before recursing further we not only split the queries but also split the currently processed numbers into two halves by value range.

Reference code (key part) 
struct Num {
  int p, x;
};  // the number at position p of the sequence has value x

struct Query {
  int l, r, k, id;
};  // a query with id id asking for the k-th smallest number in [l,r]

int ans[N];
void add(int p, int x);  // Fenwick tree, add x at position p
int query(int p);        // Fenwick tree, sum over [1,p]
void clear();            // Fenwick tree, clear

void solve(int l, int r, vector<Num> a, vector<Query> q)
// a contains the numbers of the given sequence whose value is in the value range [l,r]
{
  int m = (l + r) / 2;
  if (l == r) {
    for (unsigned i = 0; i < q.size(); i++) ans[q[i].id] = l;
    return;
  }
  vector<Num> a1, a2;
  vector<Query> q1, q2;
  for (unsigned i = 0; i < a.size(); i++)
    if (a[i].x <= m)
      a1.push_back(a[i]), add(a[i].p, 1);
    else
      a2.push_back(a[i]);
  for (unsigned i = 0; i < q.size(); i++) {
    int t = query(q[i].r) - query(q[i].l - 1);
    if (q[i].k <= t)
      q1.push_back(q[i]);
    else
      q[i].k -= t, q2.push_back(q[i]);
  }
  clear();
  solve(l, m, a1, q1), solve(m + 1, r, a2, q2);
  return;
}

  int l, r, k, id, type;  // set values to -1 when they are not used!

  if (ql > qr) return;
  if (l == r) {
    for (int i = ql; i <= qr; i++)
      if (q[i].type == 2) ans[q[i].id] = l;
    return;
  }
  int mid = (l + r) / 2, cnt1 = 0, cnt2 = 0;
  for (int i = ql; i <= qr; i++) {

      if (q[i].l <= mid) {
        add(q[i].id, 1);
        q1[++cnt1] = q[i];

      else {

        q2[++cnt2] = q[i];

  // rollback changes
  for (int i = 1; i <= cnt1; i++)
    if (q1[i].type == 1) add(q1[i].id, -1);

  for (int i = 1; i <= cnt1; i++) q[i + ql - 1] = q1[i];
  for (int i = 1; i <= cnt2; i++) q[i + cnt1 + ql - 1] = q2[i];
  solve(l, mid, ql, cnt1 + ql - 1);
  solve(mid + 1, r, cnt1 + ql, qr);
}

K-th smallest in a range with updates

Problem 4 (Dynamic Rankings)

Given a sequence, support point updates and range queries for the \(k\)-th smallest.

Solution

An update operation can be understood directly as deleting a number from the original sequence and adding another one; for convenience, queries and updates are collectively called "operations". Since later operations depend on earlier ones, we cannot separate the counting from the processing of the queries as in Problem 3, so we store all operations in one array, distinguish their types with a flag, and process the operations one by one. To make the handling with the Fenwick tree easier, an update operation can be split into an erase operation and an insert operation.

Optimizations

  1. Note that every time the operations are classified, only their order changes, so we can operate directly on the original array. Concretely, during the binary search we replace the arrays \(q, a\) that record the operations with one large global array, and the information recorded during the binary search becomes \(L, R\), i.e. which interval of the global array is currently being processed. We use temporary arrays to record the current classification, and before recursing further we write the information from the temporary arrays back to the original array.
  2. Clearing the Fenwick tree every time would make the time complexity explode; instead, every time the Fenwick tree is used we record the positions currently modified (this is already achieved by the temporary arrays mentioned in 1), and after the current operation is finished we add \(-1\) at the same positions to quickly reset it to zero.
  3. The initialization of the sequence at the beginning can be simplified to insert operations.
Reference code (key part) 
struct Opt {
  int x, y, k, type, id;
  // for a query: type = 1, x, y are the left and right endpoints of the range, k means the k-th smallest is asked
  // for an update: type = 0, x is the updated position, y is the value after the update,
  // k indicates whether the current operation is an insert (1) or an erase (-1), used when updating the Fenwick tree.
  // id records the original id of every operation, because the order of the operations gets scrambled during the binary search
};

Opt q[N], q1[N], q2[N];
// q holds all operations,
// during the binary search the operations classified to the left are stored in q1, those classified to the right in q2.
int ans[N];
void add(int p, int x);
int query(int p);  // Fenwick tree functions, see Problem 3 for their meaning

void solve(int l, int r, int L, int R)
// the current value range is [l,r], the interval of processed operations is [L,R]
{
  if (l > r || L > R) return;
  int cnt1 = 0, cnt2 = 0, m = (l + r) / 2;
  // cnt1, cnt2 are the numbers of operations classified to the left and to the right, respectively
  if (l == r) {
    for (int i = L; i <= R; i++)
      if (q[i].type == 1) ans[q[i].id] = l;
    return;
  }
  for (int i = L; i <= R; i++)
    if (q[i].type == 1) {  // it is a query: classify
      int t = query(q[i].y) - query(q[i].x - 1);
      if (q[i].k <= t)
        q1[++cnt1] = q[i];
      else
        q[i].k -= t, q2[++cnt2] = q[i];
    } else
      // it is an update: update the Fenwick tree & classify
      if (q[i].y <= m)
        add(q[i].x, q[i].k), q1[++cnt1] = q[i];
      else
        q2[++cnt2] = q[i];
  for (int i = 1; i <= cnt1; i++)
    if (q1[i].type == 0) add(q1[i].x, -q1[i].k);  // clear the Fenwick tree
  for (int i = 1; i <= cnt1; i++) q[L + i - 1] = q1[i];
  for (int i = 1; i <= cnt2; i++)
    q[L + cnt1 + i - 1] = q2[i];  // merge the elements of the temporary arrays back into the original array
  solve(l, m, L, L + cnt1 - 1), solve(m + 1, r, L + cnt1, R);
  return;
}

Optimization for static sequences

Problem 5 (【模板】可持久化线段树 2 (Template: Persistent Segment Tree 2))

Given a sequence, answer range queries for the \(k\)-th smallest.

Solution

Both tree-in-tree structures and parallel binary search solve the \(k\)-th smallest in a range with updates in \(O(n \log^2 n)\), but the static \(k\)-th smallest in a range can be solved with a persistent segment tree in \(O(n \log n)\) time, while almost all parallel binary search implementations of the static \(k\)-th smallest in a range have time complexity \(O(n \log^2 n)\) and risk TLE on large inputs. (Here it is assumed that the value range is of the same order as the length of the sequence; the case where the value range and the sequence length are not of the same order can be reduced to the same-order case by discretization.)

Optimizations

  1. In every round of splitting, if there are \(t\) numbers less than or equal to \(mid\) in the current sequence, then after the split a query actually asks for the \(k - t\)-th smallest number in the right interval, so the queries split into the right interval are modified. If the original value range of the answers is \([L,R]\) and the value range of the answers in some split is \([l,r]\), then for the queries participating in this split the influence of all values in \([L,l)\) on them has already been eliminated earlier.
  2. Since every round of splitting has to depend only on the current value range of the answers \([l,r]\), the Fenwick tree has to be loaded and cleared many times.

What if the split depends not only on the current value range of the answers?

From this we obtain an optimization related to the global sequence: maintain a pointer \(pos\) that tracks the \(mid\) (the center of the division) of every round of splitting, set the indices in the Fenwick tree corresponding to all elements \(\leq pos\) to \(1\), and the remaining positions of the Fenwick tree to \(0\). Before every split, move \(pos\) and update the Fenwick tree. The number of moves of the pointer \(pos\) is of the same order as \(n \log n\). During a split, for every query we query the value of the corresponding range in the Fenwick tree; if the condition holds, the query is split into the left interval, otherwise into the right one, and the queries do not need to be modified.

Since the center of the division is tracked, \(pos\) has to update the Fenwick tree precisely. Before the parallel binary search, sort the sequence by element value and record the index of every element; when the pointer moves, modify the corresponding indices in the Fenwick tree. For the vast majority of problems that can be solved by parallel binary search and have no updates, this optimization can be applied to greatly reduce the number of uses of the data structure.

Since many load and clear operations of the Fenwick tree are eliminated, applying this optimization usually improves the efficiency of parallel binary search noticeably (even though it is only a constant factor optimization), and for the static \(k\)-th smallest in a range the efficiency is no worse than that of the persistent segment tree with the better time complexity. It is worth noting that for the static \(k\)-th smallest in a range there also exists a parallel binary search implementation with time complexity \(O(n \log n)\).

void add(int x, int y);  // Fenwick tree: add y at position x
int sum(int x);          // Fenwick tree: prefix sum over [1,x]

// the currently processed queries are [l,r], the value range of the answers is [ql,qr]
void overall_binary(int l, int r, int ql, int qr) {
  if (l > r) return;
  if (ql == qr) {
    for (int i = l; i <= r; i++) ans[s[i].i] = ql;
    return;
  }
  int cnt1 = 0, cnt2 = 0, mid = (ql + qr) >> 1;
  // track the center of the division; the values [1,pos] are considered loaded into the Fenwick tree
  while (pos <= n - 1 && a[pos + 1].first <= mid)
    add(a[pos + 1].second, 1), ++pos;
  while (pos >= 1 && a[pos].first > mid) add(a[pos].second, -1), --pos;

  for (int i = l; i <= r; i++) {
    int now = sum(s[i].r) - sum(s[i].l - 1);
    if (s[i].k <= now)
      t1[++cnt1] = s[i];
    else
      t2[++cnt2] = s[i];  // note: the query information should not be modified
  }
  for (int i = 1; i <= cnt1; i++) s[l + i - 1] = t1[i];
  for (int i = 1; i <= cnt2; i++) s[l + cnt1 + i - 1] = t2[i];

  overall_binary(l, l + cnt1 - 1, ql, mid);
  overall_binary(l + cnt1, r, mid + 1, qr);
}

int main() {
  scanf("%d%d", &n, &m);
  for (int i = 1; i <= n; i++) {
    scanf("%d", &a[i].first);
    a[i].second = i;
    p[++cnt] = a[i].first;
  }
  sort(a + 1, a + n + 1);  // sort the sequence, discretization
  sort(p + 1, p + n + 1);
  cnt = unique(p + 1, p + n + 1) - p - 1;
  for (int i = 1; i <= n; i++)
    a[i].first = lower_bound(p + 1, p + cnt + 1, a[i].first) - p;
  // reading the queries is omitted
  overall_binary(1, m, 1, cnt);
  for (int i = 1; i <= n; i++) printf("%d\n", p[ans[i]]);
  return 0;
}

Predecessor and successor in a range

Problem 6

In a sequence, query many times the predecessor of \(k\) in a range (the largest number strictly less than \(k\)) or its successor (the smallest number strictly greater than \(k\)); it is guaranteed that such a number exists.

Solution

Take the predecessor as an example: the usual way to solve such problems with data structures is to first query how many numbers in the range are strictly less than \(k\) (let their count be \(x\)), and then query the \(x\)-th smallest number in the range. For the successor, query how many numbers in the range are not greater than \(k\) (count \(x\)), and then query the \(x+1\)-th smallest number in the range.

Consider solving this problem with parallel binary search: parallel binary search is an efficient offline algorithm for the \(k\)-th smallest in a range, while CDQ divide and conquer can efficiently compute ranks within a range offline. First run CDQ divide and conquer once to compute the ranks, and then parallel binary search gives the predecessor and successor within the range.

This problem can also be solved offline in one pass with CDQ divide and conquer combined with a segment tree, but the efficiency is far lower than the two passes of CDQ divide and conquer + parallel binary search.

Constructing a monotonic sequence

Problem 7 (Sequence)

Given a sequence, each operation can change some number by \(+1\) or \(−1\). The sequence has to be made non-decreasing, and only numbers that existed before the modifications may appear in the modified sequence; output the minimum number of operations.

Solution

Problems of this kind can also be solved with dynamic programming or regret greedy.

Under the condition of minimizing the number of operations, there always exists a solution in which every number of the final sequence existed in the sequence before the modifications; this claim can be proved by mathematical induction. Since the problem does not need information about the final sequence, the problem is reduced to finding the minimum number of operations.

Since the final sequence has to be non-decreasing, parallel binary search can be used. In every round of parallel binary search we determine the value range of the range \([l,r]\) of the final sequence, where the value range of the answers is \([ql,qr]\). Let \(mid=\lfloor\frac{ql + qr}{2}\rfloor\); at the start of every round all numbers are by default split into \([mid+1,qr]\) (the number of elements to be split into \([ql,mid]\) is set to \(0\)), and the initial cost is set to the number of operations needed to set the whole range \([l,r]\) of the sequence to \(mid+1\). Enumerate the numbers \(i\) in the range \([l,r]\) in turn and compute the total number of operations to set \([l,i]\) to \(mid\) and \([i+1,r]\) to \(mid+1\); if it is better than the previous number of operations, update the minimum number of operations and the number of elements to be split into \([ql,mid]\).

The split already guarantees that the monotonicity of the final sequence is not broken, and since the minimum number of operations is taken every time, for the numbers finally split into the left interval taking \(mid\) is certainly better than taking \(mid+1\), so the sequence obtained by parallel binary search is certainly non-decreasing with the minimum number of operations. It remains to compute the number of operations and output it.

Reference code (key part) 
int a[500005], ans[500005];  // a: original sequence, ans: constructed sequence

void overall_binary(int l, int r, int ql, int qr) {
  if (l > r) return;
  if (ql == qr) {
    for (int i = l; i <= r; i++) ans[i] = ql;
    return;
  }
  int cnt = 0,
      mid = ql + ((qr - ql) >> 1);  // by default start by filling everything with mid+1 and splitting all into the right interval
  long long res = 0ll, sum = 0ll;
  for (int i = l; i <= r; i++) sum += abs(a[i] - (mid + 1));
  res = sum;
  for (int i = l; i <= r;
       i++) {  // try changing [l,i] from mid+1 to mid and splitting it into the left interval
    sum -= abs(a[i] - (mid + 1));
    sum += abs(a[i] - mid);
    if (sum < res) cnt = i - l + 1, res = sum;  // taking mid on [l,i] is better, update
  }
  overall_binary(l, l + cnt - 1, ql, mid);
  overall_binary(l + cnt, r, mid + 1, qr);
}
