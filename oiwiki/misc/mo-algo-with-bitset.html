Bitset se često koristi za probleme odlučivanja i prebrojavanja koje je uobičajenim strukturama podataka teško održavati, a Mo algoritam (Mo's algorithm) može održavati informacije o intervalima koje je uobičajenim strukturama podataka teško održavati. Kombiniranjem jednog i drugog istodobno iskorištavamo prednosti obaju.

Primjer zadatka 「Ynoi2016」掉进兔子洞 (Pad u zečju rupu)

Ovaj zadatak točno odgovara gore opisanim obilježjima Mo algoritma uz bitset. Lako je dosjetiti se da za svaki interval možemo u zasebnom bitsetu pohraniti sve vrijednosti koje se u njemu pojavljuju; odgovor na jedan upit tada je zbroj duljina svih intervala umanjen za broj elemenata u presjeku triju bitseta \(\times 3\).

No kad bitset koristimo u Mo algoritmu, algoritam treba prilagoditi osobitostima bitseta:

  1. Bitset se ne snalazi dobro kad se ista vrijednost pojavi više puta. Možemo kao objekt koji umećemo u bitset uzeti zbroj diskretizirane vrijednosti trenutnog elementa i broja njegovih dosadašnjih pojavljivanja u trenutnom intervalu.
  2. Kad inače koristimo Mo algoritam, možda ne pazimo na redoslijed 4 načina pomicanja pokazivača, pa se tijekom pomicanja može dogoditi da lijevi kraj intervala bude desno od desnog kraja, tj. da duljina intervala bude negativna, zbog čega broj elemenata postaje negativan. U drugim situacijama to ne smeta, ali u ovom zadatku element koji umećemo u bitset ovisi o broju elemenata, pa moramo paziti na redoslijed 4 načina pomicanja pokazivača: naredbe koje lijevi pokazivač pomiču ulijevo i desni pokazivač udesno pišemo prve, kako u bitset ne bismo umetali negativne brojeve.
  3. Iako bitset troši malo memorije, ipak ne može podnijeti podatke veličine \(10 ^ 5 \times 10 ^ 5\). Zato upite moramo podijeliti na konstantan broj dijelova i obraditi ih zasebno, čime memorija postaje upravo dovoljna, a vremenska složenost ostaje nepromijenjena.
Referentni kôd 
#include <algorithm>
#include <bitset>
#include <cmath>
#include <cstring>
#include <iostream>
using namespace std;
constexpr int N = 100005, M = N / 3 + 10;
int n, m, maxn;
int a[N], ans[M], cnt[N];
bitset<N> sum[M], now;

struct query {
  int l, r, id;

  bool operator<(const query& x) const {
    if (l / maxn != x.l / maxn) return l < x.l;
    return (l / maxn) & 1 ? r < x.r : r > x.r;
  }
} q[M * 3];

void static_set() {
  static int tmp[N];
  memcpy(tmp, a, sizeof(a));
  sort(tmp + 1, tmp + n + 1);
  for (int i = 1; i <= n; i++)
    a[i] = lower_bound(tmp + 1, tmp + n + 1, a[i]) - tmp;
}

void add(int x) {
  now.set(x + cnt[x]);
  cnt[x]++;
}

void del(int x) {
  cnt[x]--;
  now.reset(x + cnt[x]);
}

void solve() {
  int cnt = 0, tot = 0;
  now.reset();
  for (tot = 0; tot < M - 5 && m; tot++) {
    m--;
    ans[tot] = 0;
    sum[tot].set();
    for (int j = 0; j < 3; j++) {
      cin >> q[cnt].l >> q[cnt].r;
      q[cnt].id = tot;
      ans[tot] += q[cnt].r - q[cnt].l + 1;
      cnt++;
    }
  }
  sort(q, q + cnt);
  for (int i = 0, l = 1, r = 0; i < cnt; i++) {
    while (l > q[i].l) add(a[--l]);
    while (r < q[i].r) add(a[++r]);
    while (l < q[i].l) del(a[l++]);
    while (r > q[i].r) del(a[r--]);
    sum[q[i].id] &= now;
  }
  for (int i = 0; i < tot; i++)
    cout << ans[i] - (int)sum[i].count() * 3 << '\n';
}

int main() {
  cin.tie(nullptr)->sync_with_stdio(false);
  cin >> n >> m;
  for (int i = 1; i <= n; i++) cin >> a[i];
  static_set();
  maxn = sqrt(n);
  solve();
  memset(cnt, 0, sizeof(cnt));
  solve();
  memset(cnt, 0, sizeof(cnt));
  solve();
  return 0;
}

Bitsets are often used for decision and counting problems that are hard to maintain with conventional data structures, while Mo's algorithm can maintain interval information that is hard to maintain with conventional data structures. Combining the two lets us exploit the advantages of both at the same time.

Example problem 「Ynoi2016」掉进兔子洞 (Falling into the Rabbit Hole)

This problem matches exactly the characteristics of Mo's algorithm with bitset mentioned above. It is easy to think of storing, in a separate bitset for each interval, all the values that appear in it; the answer to one query is then the sum of the lengths of all intervals minus the number of elements in the intersection of the three \(\times 3\).

However, using a bitset inside Mo's algorithm also requires adapting the algorithm to the characteristics of bitsets:

  1. A bitset cannot handle multiple occurrences of the same value well. We can take the discretized value of the current element plus the number of its occurrences so far in the current interval as the object inserted into the bitset.
  2. When we normally use Mo's algorithm, we may not pay attention to the order of the 4 ways of moving the pointers, so during the pointer moves the left endpoint of the interval may end up to the right of the right endpoint, i.e. the interval length becomes negative, making the number of elements negative. In other situations this has no effect, but in this problem the element inserted into the bitset depends on the number of elements, so we must pay attention to the order of the 4 ways of moving the pointers: write the statements that move the left pointer to the left and the right pointer to the right first, to avoid inserting negative numbers into the bitset.
  3. Although bitsets use little memory, they still cannot cope with a data size of \(10 ^ 5 \times 10 ^ 5\). So we need to split the queries into a constant number of parts and process them separately, which keeps the memory just sufficient while leaving the time complexity unchanged.
